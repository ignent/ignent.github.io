Android NDK 图像处理实战：Bitmap native 像素处理与 libyuv 转码

移动端很多高性能模块都会把核心逻辑放到 C++：音视频处理用 FFmpeg，图像处理用 OpenCV、libyuv，游戏引擎用 Cocos2d-x/Unreal，渲染用 OpenGL ES/Vulkan，AI 推理、加密压缩和安全对抗也经常在 native 层完成。

但小白一上来直接接 FFmpeg 或 OpenCV，很容易被构建脚本、ABI、动态库和大段 API 淹没。本文先做一个更容易复现的实战项目：Kotlin 把 Bitmap 和一段 NV21 图像数据传给 C++，C++ 在 native 层完成像素处理和格式转换，再把结果显示回 Android 页面。

我们会完成两个功能：

  1. 使用 Android NDK 的 jnigraphics 直接锁定 Bitmap 像素，把图片转成灰度图。
  2. 使用 libyuv 把 Android 常见的 NV21 数据转换成 RGBA，再写入 Bitmap 。

目标效果

运行后，页面上会显示两张图：第一张是 Kotlin 创建的彩色测试图，点击按钮后会被 C++ 原地转换为灰度图；第二张是 C++ 调用 libyuv::NV21ToARGB 生成的 RGBA 图，用来验证 YUV 到 RGB 的 native 转换链路。

2. 最终运行效果

页面上有两个按钮：

  • 灰度处理 ：调用 C++ 的 grayInPlace(bitmap) ，把已有 Bitmap 原地转灰度。
  • 生成 NV21 示例图 ：Kotlin 构造一段假的 NV21 数据，调用 C++ 的 nv21ToBitmap(nv21, width, height, output) ，由 libyuv 转成 RGBA 后显示。

预期日志：

I/NativeImageLab: grayInPlace width=240 height=160 stride=960
I/NativeImageLab: nv21ToBitmap width=240 height=160 ySize=38400

验证重点：

  • 第一张图点击后变成灰度，说明 C++ 能安全访问和修改 Bitmap 像素。
  • 第二张图出现由暗到亮的渐变色块，说明 NV21 到 RGBA 转换成功。
  • logcat 中能看到 NativeImageLab 日志，说明 native 库正确加载并执行。

7. Kotlin 与 JNI 边界

文件路径： app/src/main/java/com/example/nativeimage/NativeImageProcessor.kt

package com.example.nativeimage

import android.graphics.Bitmap

/**
 * NativeImageProcessor 是 Kotlin 调 C++ 的统一入口。
 *
 * object 表示 Kotlin 单例。native 方法最终会映射到 C++ 中的 JNI 函数。
 */
object NativeImageProcessor {

    init {
        // 加载 CMake 生成的 libnative-image.so。
        // 名字必须和 CMakeLists.txt 里的 add_library(native-image ...) 对应。
        System.loadLibrary("native-image")
    }

    /**
     * 把 ARGB_8888 Bitmap 原地转成灰度图。
     *
     * @param bitmap 必须是可变 Bitmap，并且格式应为 Bitmap.Config.ARGB_8888。
     * @return true 表示处理成功，false 表示格式不支持或 native 处理失败。
     */
    external fun grayInPlace(bitmap: Bitmap): Boolean

    /**
     * 把 NV21 数据转换为 ARGB_8888 Bitmap。
     *
     * @param nv21 输入 NV21 数据，大小必须是 width * height * 3 / 2。
     * @param width 图像宽度，建议为偶数。
     * @param height 图像高度，建议为偶数。
     * @param output 输出 Bitmap，必须是可变 ARGB_8888，尺寸必须等于 width x height。
     * @return true 表示转换成功。
     */
    external fun nv21ToBitmap(
        nv21: ByteArray,
        width: Int,
        height: Int,
        output: Bitmap
    ): Boolean
}

这份文件里最关键的是两点：

  • System.loadLibrary("native-image") 会加载 libnative-image.so 。
  • external fun 只声明方法签名，具体实现由 C++ JNI 函数提供。

8. 页面和测试数据

文件路径： app/src/main/java/com/example/nativeimage/MainActivity.kt

package com.example.nativeimage

import android.app.Activity
import android.graphics.Bitmap
import android.graphics.Canvas
import android.graphics.Color
import android.graphics.Paint
import android.os.Bundle
import android.view.ViewGroup
import android.widget.Button
import android.widget.ImageView
import android.widget.LinearLayout
import android.widget.TextView

class MainActivity : Activity() {

    // 示例图片宽高。这里用小图，方便快速验证，也避免日志和内存占用过大。
    private val imageWidth = 240
    private val imageHeight = 160

    // lateinit 表示稍后在 onCreate 中初始化。
    private lateinit var sourceBitmap: Bitmap
    private lateinit var grayImageView: ImageView
    private lateinit var yuvImageView: ImageView
    private lateinit var statusText: TextView

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 创建一张可变 ARGB_8888 测试图。
        sourceBitmap = createColorTestBitmap(imageWidth, imageHeight)

        grayImageView = ImageView(this).apply {
            // setImageBitmap 显示 Bitmap。后续 native 原地修改后，再次设置可刷新显示。
            setImageBitmap(sourceBitmap)
            adjustViewBounds = true
        }

        yuvImageView = ImageView(this).apply {
            adjustViewBounds = true
        }

        statusText = TextView(this).apply {
            text = "点击按钮运行 native 图像处理"
            textSize = 15f
            setTextColor(Color.DKGRAY)
        }

        val grayButton = Button(this).apply {
            text = "灰度处理"
            setOnClickListener {
                // 调用 C++ 修改 sourceBitmap 的像素。
                val ok = NativeImageProcessor.grayInPlace(sourceBitmap)

                // 重新设置图片，确保 ImageView 刷新。
                grayImageView.setImageBitmap(sourceBitmap)

                statusText.text = "grayInPlace: $ok"
            }
        }

        val yuvButton = Button(this).apply {
            text = "生成 NV21 示例图"
            setOnClickListener {
                // Kotlin 构造一段可预测的 NV21 数据。
                val nv21 = createFakeNv21(imageWidth, imageHeight)

                // 输出 Bitmap 必须可变，native 层会写入像素。
                val output = Bitmap.createBitmap(
                    imageWidth,
                    imageHeight,
                    Bitmap.Config.ARGB_8888
                )

                val ok = NativeImageProcessor.nv21ToBitmap(
                    nv21 = nv21,
                    width = imageWidth,
                    height = imageHeight,
                    output = output
                )

                yuvImageView.setImageBitmap(output)
                statusText.text = "nv21ToBitmap: $ok, input=${nv21.size} bytes"
            }
        }

        val root = LinearLayout(this).apply {
            orientation = LinearLayout.VERTICAL
            setPadding(24, 24, 24, 24)

            addView(statusText, matchWrap())
            addView(grayButton, matchWrap())
            addView(grayImageView, matchWrap())
            addView(yuvButton, matchWrap())
            addView(yuvImageView, matchWrap())
        }

        setContentView(root)
    }

    /**
     * 创建彩色测试图。
     *
     * 路径：MainActivity.kt
     * 作用：生成一张带红、绿、蓝渐变的 ARGB_8888 Bitmap，用来验证灰度处理。
     */
    private fun createColorTestBitmap(width: Int, height: Int): Bitmap {
        // true 表示 Bitmap 可变，native 层才能写像素。
        val bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888)

        val canvas = Canvas(bitmap)
        val paint = Paint(Paint.ANTI_ALIAS_FLAG)

        for (y in 0 until height) {
            for (x in 0 until width) {
                // r 随 x 从 0 到 255 变化。
                val r = x * 255 / (width - 1)

                // g 随 y 从 0 到 255 变化。
                val g = y * 255 / (height - 1)

                // b 使用 x+y 的混合值，方便观察灰度结果。
                val b = (x + y) * 255 / (width + height - 2)

                paint.color = Color.rgb(r, g, b)
                canvas.drawPoint(x.toFloat(), y.toFloat(), paint)
            }
        }

        return bitmap
    }

    /**
     * 创建一帧假的 NV21 数据。
     *
     * NV21 内存布局：
     * - 前 width * height 字节是 Y 平面，表示亮度。
     * - 后 width * height / 2 字节是交错 VU 平面，两个像素共享一组 V/U。
     *
     * 这个函数不是相机采集，只是构造一帧便于复现的测试数据。
     */
    private fun createFakeNv21(width: Int, height: Int): ByteArray {
        require(width % 2 == 0 && height % 2 == 0) {
            "NV21 示例要求 width 和 height 都是偶数"
        }

        val ySize = width * height
        val uvSize = ySize / 2
        val data = ByteArray(ySize + uvSize)

        // 填充 Y 平面：从左到右变亮，从上到下略微变暗。
        for (y in 0 until height) {
            for (x in 0 until width) {
                val luminance = 32 + (x * 180 / (width - 1)) - (y * 30 / (height - 1))
                data[y * width + x] = luminance.coerceIn(0, 255).toByte()
            }
        }

        // 填充 VU 平面：NV21 是 V、U、V、U 交错。
        // 这里让左半部分偏蓝，右半部分偏红，便于肉眼确认转换结果。
        var uvIndex = ySize
        for (y in 0 until height step 2) {
            for (x in 0 until width step 2) {
                val isLeft = x < width / 2

                val v = if (isLeft) 96 else 180
                val u = if (isLeft) 180 else 96

                data[uvIndex++] = v.toByte()
                data[uvIndex++] = u.toByte()
            }
        }

        return data
    }

    /**
     * 创建常用 LayoutParams。
     */
    private fun matchWrap(): LinearLayout.LayoutParams {
        return LinearLayout.LayoutParams(
            ViewGroup.LayoutParams.MATCH_PARENT,
            ViewGroup.LayoutParams.WRAP_CONTENT
        )
    }
}

这里没有使用 XML 布局，是为了让示例文件更少。正式项目中，你完全可以把页面改成 XML、Compose 或已有 UI 框架，JNI 调用方式不变。

9. CMake 配置

文件路径： app/src/main/cpp/CMakeLists.txt

# CMakeLists.txt
# 作用：构建 native-image.so，并把 libyuv 编译进当前 native 库。

cmake_minimum_required(VERSION 3.22.1)

# 声明当前 native 工程名称。
project(native_image_lab)

# Android 官方建议开启 position independent code，动态库需要它。
set(CMAKE_POSITION_INDEPENDENT_CODE ON)

# libyuv 源码目录。CMAKE_CURRENT_SOURCE_DIR 是 app/src/main/cpp。
# ../third_party/libyuv 对应 app/src/main/third_party/libyuv。
set(LIBYUV_DIR ${CMAKE_CURRENT_SOURCE_DIR}/../third_party/libyuv)

# 引入 libyuv 自带 CMakeLists.txt。
# 第二个参数是 libyuv 的构建输出目录。
add_subdirectory(${LIBYUV_DIR} ${CMAKE_CURRENT_BINARY_DIR}/libyuv)

# 构建本文自己的 JNI 动态库。
add_library(
    native-image
    SHARED
    native-image.cpp
)

# 让 native-image.cpp 能 include "libyuv.h"。
target_include_directories(
    native-image
    PRIVATE
    ${LIBYUV_DIR}/include
)

# 查找 Android 日志库。C++ 中会调用 __android_log_print。
find_library(log-lib log)

# 链接依赖库：
# - yuv：libyuv 目标名，来自 libyuv 的 CMakeLists.txt。
# - android：提供 AndroidBitmap_getInfo / lockPixels / unlockPixels。
# - log：提供 __android_log_print。
target_link_libraries(
    native-image
    PRIVATE
    yuv
    android
    ${log-lib}
)

libyuv CMake 目标名

多数 libyuv 源码版本会生成 yuv 目标。如果你固定的 commit 中目标名不同，执行构建时会看到 target_link_libraries 找不到目标。此时打开 third_party/libyuv/CMakeLists.txt ，确认实际 add_library(...) 的目标名。

10. C++ 核心源码

// native-image.cpp
// 作用：实现 Kotlin 中 NativeImageProcessor 声明的 external 方法。

#include <android/bitmap.h>
#include <android/log.h>
#include <jni.h>
#include <libyuv.h>

#include <algorithm>
#include <cstdint>

// 日志标签。adb logcat -s NativeImageLab 可以只看本文日志。
namespace {
constexpr const char* kLogTag = "NativeImageLab";

// 用宏减少日志调用样板代码。
#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, kLogTag, __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, kLogTag, __VA_ARGS__)

/**
 * 检查 Bitmap 是否是本文支持的 ARGB_8888。
 *
 * @param env JNI 环境指针，AndroidBitmap_getInfo 需要它。
 * @param bitmap Kotlin 传入的 Bitmap 对象。
 * @param info 输出 Bitmap 信息。
 * @return true 表示 Bitmap 可处理。
 */
bool GetArgb8888BitmapInfo(JNIEnv* env, jobject bitmap, AndroidBitmapInfo* info) {
    // AndroidBitmap_getInfo 会读取宽、高、stride、format 等信息。
    const int result = AndroidBitmap_getInfo(env, bitmap, info);
    if (result != ANDROID_BITMAP_RESULT_SUCCESS) {
        LOGE("AndroidBitmap_getInfo failed, result=%d", result);
        return false;
    }

    // 本文只处理 ARGB_8888。其他格式如 RGB_565、RGBA_F16 的字节布局不同。
    if (info->format != ANDROID_BITMAP_FORMAT_RGBA_8888) {
        LOGE("Unsupported bitmap format=%u, expected RGBA_8888", info->format);
        return false;
    }

    return true;
}

/**
 * 把整数限制在 0 到 255。
 *
 * 本文灰度计算使用整数，不会溢出到负数；保留这个函数是为了说明图像处理中
 * 常见的 clamp 思路。更复杂的卷积、亮度、对比度处理都需要 clamp。
 */
uint8_t ClampToByte(int value) {
    return static_cast<uint8_t>(std::clamp(value, 0, 255));
}
} // namespace

extern "C" JNIEXPORT jboolean JNICALL
Java_com_example_nativeimage_NativeImageProcessor_grayInPlace(
    JNIEnv* env,
    jobject /* thiz */,
    jobject bitmap
) {
    if (bitmap == nullptr) {
        LOGE("grayInPlace bitmap is null");
        return JNI_FALSE;
    }

    AndroidBitmapInfo info{};
    if (!GetArgb8888BitmapInfo(env, bitmap, &info)) {
        return JNI_FALSE;
    }

    void* pixels = nullptr;

    // lockPixels 会锁定 Bitmap 底层像素内存。成功后 pixels 指向第一行起始地址。
    const int lockResult = AndroidBitmap_lockPixels(env, bitmap, &pixels);
    if (lockResult != ANDROID_BITMAP_RESULT_SUCCESS || pixels == nullptr) {
        LOGE("AndroidBitmap_lockPixels failed, result=%d", lockResult);
        return JNI_FALSE;
    }

    LOGI(
        "grayInPlace width=%u height=%u stride=%u",
        info.width,
        info.height,
        info.stride
    );

    // AndroidBitmapInfo::stride 表示一行占用的字节数，不一定等于 width * 4。
    // 所以遍历每一行时必须使用 stride 移动到下一行。
    auto* base = static_cast<uint8_t*>(pixels);

    for (uint32_t y = 0; y < info.height; ++y) {
        // 当前行地址。
        auto* row = reinterpret_cast<uint32_t*>(base + y * info.stride);

        for (uint32_t x = 0; x < info.width; ++x) {
            // 直接按字节读取一个 4 字节像素。
            auto* px = reinterpret_cast<uint8_t*>(&row[x]);

            const uint8_t r = px[0];
            const uint8_t g = px[1];
            const uint8_t b = px[2];
            const uint8_t a = px[3];

            // 常用亮度近似：gray = 0.299R + 0.587G + 0.114B。
            // 用整数 77、150、29 近似 256 倍权重，最后右移 8 位。
            const uint8_t gray = ClampToByte((77 * r + 150 * g + 29 * b) >> 8);

            px[0] = gray;
            px[1] = gray;
            px[2] = gray;
            px[3] = a;
        }
    }

    // 成功或失败都要解锁。这里没有提前 return，所以直接解锁。
    AndroidBitmap_unlockPixels(env, bitmap);

    return JNI_TRUE;
}

extern "C" JNIEXPORT jboolean JNICALL
Java_com_example_nativeimage_NativeImageProcessor_nv21ToBitmap(
    JNIEnv* env,
    jobject /* thiz */,
    jbyteArray nv21,
    jint width,
    jint height,
    jobject output
) {
    if (nv21 == nullptr || output == nullptr) {
        LOGE("nv21ToBitmap input or output is null");
        return JNI_FALSE;
    }

    if (width <= 0 || height <= 0 || width % 2 != 0 || height % 2 != 0) {
        LOGE("Invalid size width=%d height=%d", width, height);
        return JNI_FALSE;
    }

    const jsize expectedSize = width * height * 3 / 2;
    const jsize actualSize = env->GetArrayLength(nv21);
    if (actualSize < expectedSize) {
        LOGE("NV21 data too small, actual=%d expected=%d", actualSize, expectedSize);
        return JNI_FALSE;
    }

    AndroidBitmapInfo info{};
    if (!GetArgb8888BitmapInfo(env, output, &info)) {
        return JNI_FALSE;
    }

    if (static_cast<jint>(info.width) != width || static_cast<jint>(info.height) != height) {
        LOGE(
            "Output bitmap size mismatch, bitmap=%ux%u input=%dx%d",
            info.width,
            info.height,
            width,
            height
        );
        return JNI_FALSE;
    }

    // GetByteArrayElements 可能复制，也可能直接固定 JVM 内存。
    // 无论哪种情况，后面都必须 ReleaseByteArrayElements。
    jboolean isCopy = JNI_FALSE;
    jbyte* nv21Bytes = env->GetByteArrayElements(nv21, &isCopy);
    if (nv21Bytes == nullptr) {
        LOGE("GetByteArrayElements failed");
        return JNI_FALSE;
    }

    void* outputPixels = nullptr;
    const int lockResult = AndroidBitmap_lockPixels(env, output, &outputPixels);
    if (lockResult != ANDROID_BITMAP_RESULT_SUCCESS || outputPixels == nullptr) {
        env->ReleaseByteArrayElements(nv21, nv21Bytes, JNI_ABORT);
        LOGE("AndroidBitmap_lockPixels failed, result=%d", lockResult);
        return JNI_FALSE;
    }

    const int ySize = width * height;

    // NV21 布局：YYYY... 后面接 VUVUVU...
    const auto* srcY = reinterpret_cast<const uint8_t*>(nv21Bytes);
    const auto* srcVU = srcY + ySize;

    // 输出 Bitmap 的一行字节数由 stride 决定。
    auto* dstArgb = static_cast<uint8_t*>(outputPixels);

    LOGI("nv21ToBitmap width=%d height=%d ySize=%d", width, height, ySize);

    // libyuv 的 NV21ToARGB 参数：
    // src_y / src_stride_y：Y 平面地址和行跨度。
    // src_vu / src_stride_vu：交错 VU 平面地址和行跨度。
    // dst_argb / dst_stride_argb：输出 ARGB 地址和行跨度。
    // width / height：图像尺寸。
    const int convertResult = libyuv::NV21ToARGB(
        srcY,
        width,
        srcVU,
        width,
        dstArgb,
        static_cast<int>(info.stride),
        width,
        height
    );

    AndroidBitmap_unlockPixels(env, output);

    // JNI_ABORT 表示不把 native 对 nv21Bytes 的修改复制回 Java。
    // 本文只读输入数据，所以使用 JNI_ABORT 更清晰。
    env->ReleaseByteArrayElements(nv21, nv21Bytes, JNI_ABORT);

    if (convertResult != 0) {
        LOGE("libyuv::NV21ToARGB failed, result=%d", convertResult);
        return JNI_FALSE;
    }

    return JNI_TRUE;
}

像素字节顺序提醒

Android Bitmap.Config.ARGB_8888 是 Java/Kotlin 层的颜色模型名称；NDK ANDROID_BITMAP_FORMAT_RGBA_8888 描述 native 访问时的像素格式。不同 API、库和 CPU 小端读写方式会让 “ARGB/RGBA/BGRA” 这些名字看起来容易混淆。

本文在灰度函数中按字节访问 px[0] 、 px[1] 、 px[2] 、 px[3] ，并且只做灰度处理，所以即使红蓝通道理解有偏差，视觉结果仍容易验证。正式做颜色精确处理时，请用小图写测试验证通道顺序。

12. 关键代码拆解

12.1 为什么 Bitmap 必须可变

Kotlin 中创建图片时使用：

val bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888)

这个 API 返回可变 Bitmap 。如果你从资源文件解码图片，默认可能是不可变的。不可变 Bitmap 在 native 层锁像素可能失败，或者修改后不会得到预期效果。

如果输入来自资源，可以复制成可变版本：

val mutable = decoded.copy(Bitmap.Config.ARGB_8888, true)

第二个参数 true 表示可变。

12.2 为什么遍历图片要用 stride

C++ 中这一行很关键：

auto* row = reinterpret_cast<uint32_t*>(base + y * info.stride);

stride 是一行像素占用的实际字节数。出于对齐和性能原因，它不一定等于 width * 4 。如果你写成：

base + y * width * 4

在某些设备、某些图片宽度下可能读写到错误位置，轻则花屏，重则 native 崩溃。

12.3 为什么 lock 和 unlock 必须成对

这两行是一组资源管理：

AndroidBitmap_lockPixels(env, bitmap, &pixels);
AndroidBitmap_unlockPixels(env, bitmap);

lockPixels 成功后，系统允许 native 访问底层像素。处理结束必须 unlockPixels 。如果中途提前 return ，要先解锁。本文在 nv21ToBitmap 中失败分支也手动释放了 jbyteArray ，避免资源悬挂。

正式项目可以用 RAII 封装锁：

class BitmapPixelsLock {
public:
    BitmapPixelsLock(JNIEnv* env, jobject bitmap) : env_(env), bitmap_(bitmap) {
        ok_ = AndroidBitmap_lockPixels(env_, bitmap_, &pixels_) == ANDROID_BITMAP_RESULT_SUCCESS;
    }

    ~BitmapPixelsLock() {
        if (ok_) {
            AndroidBitmap_unlockPixels(env_, bitmap_);
        }
    }

    bool ok() const { return ok_; }
    void* pixels() const { return pixels_; }

private:
    JNIEnv* env_ = nullptr;
    jobject bitmap_ = nullptr;
    void* pixels_ = nullptr;
    bool ok_ = false;
};

这段 RAII 代码在对象析构时自动解锁，适合复杂函数。本文主代码保持显式 lock/unlock，是为了让 JNI 流程更直观。

12.4 NV21 是什么

NV21 是 Android 相机预览里常见的 YUV 420 格式之一：

Y 平面： width * height 字节
VU 平面：width * height / 2 字节
总大小： width * height * 3 / 2 字节

对于 240 x 160 图片：

Y  大小 = 240 * 160 = 38400
VU 大小 = 38400 / 2 = 19200
总大小 = 57600

Y 表示亮度，U/V 表示色度。YUV 420 中，色度分辨率低于亮度分辨率，通常每 2 x 2 个像素共享一组色度数据。

12.5 为什么使用 libyuv

你当然可以自己写 NV21 到 RGB 的公式：

R = Y + 1.402 * (V - 128)
G = Y - 0.344136 * (U - 128) - 0.714136 * (V - 128)
B = Y + 1.772 * (U - 128)

但实际项目还要考虑：

  • 不同 YUV 格式：NV21、NV12、I420、YV12。
  • stride 不等于 width。
  • 裁剪、旋转、缩放、镜像。
  • ARM NEON、x86 SIMD 优化。

libyuv 已经覆盖这些常见需求，所以音视频和相机项目里经常使用它。本文只调用 NV21ToARGB ，先把最小链路跑通。

13. 常见错误和排查

13.1 No implementation found for native ...

原因通常是 JNI 函数名和 Kotlin 包名、类名、方法名不匹配。

本文 Kotlin 方法：

package com.example.nativeimage
object NativeImageProcessor {
    external fun grayInPlace(bitmap: Bitmap): Boolean
}

对应 C++ 函数名：

Java_com_example_nativeimage_NativeImageProcessor_grayInPlace

如果你修改包名或类名，C++ 函数名也要同步修改。大型项目更推荐使用 RegisterNatives 显式注册 native 方法，避免函数名过长。

13.2 java.lang.UnsatisfiedLinkError: dlopen failed

排查：

  1. System.loadLibrary("native-image") 是否和 CMake 的 add_library(native-image SHARED ...) 一致。
  2. target_link_libraries 是否遗漏 android 、 log 或 yuv 。
  3. libyuv 是否成功编译到当前 ABI。
  4. 设备 ABI 是否在 abiFilters 中，例如真机是 arm64-v8a ，模拟器通常是 x86_64 。

13.3 找不到 libyuv.h

检查：

target_include_directories(
    native-image
    PRIVATE
    ${LIBYUV_DIR}/include
)

以及源码中：

#include <libyuv.h>

如果你的 libyuv 目录结构不同，请确认 include/libyuv.h 是否存在。

13.4 target_link_libraries 找不到 yuv

打开 app/src/main/third_party/libyuv/CMakeLists.txt ，确认它创建的库目标名。常见目标名是 yuv 。如果你的版本使用其他名字，把本文的：

target_link_libraries(native-image PRIVATE yuv android ${log-lib})

改成实际目标名。

13.5 图片颜色异常

可能原因：

  • 输入并不是 NV21，而是 NV12、I420 或其他 YUV 格式。
  • width/height、stride 使用错误。
  • 输出 Bitmap 格式不是 ARGB_8888。
  • 对 ARGB/RGBA/BGRA 的内存顺序理解不一致。

排查方法：

  1. 先使用本文 createFakeNv21 的测试数据验证链路。
  2. 再接真实相机数据。
  3. 打印输入大小，确认是 width * height * 3 / 2 。
  4. 对 2 x 2 或 4 x 4 小图做固定输入，逐像素比较输出。

13.6 native 崩溃

常见原因：

  • 没有检查 AndroidBitmap_lockPixels 的返回值。
  • 忽略 stride ，按 width * 4 错误跳行。
  • jbyteArray 长度不足，却按完整 NV21 读取。
  • C++ 提前 return 前忘记释放数组或解锁 Bitmap。

排查建议：

adb logcat

如果看到 native backtrace，可以用 Android Studio 的 Analyze Stack Trace ，或者配置符号文件后用 ndk-stack 辅助定位。

14. 背后的原理

14.1 Bitmap native 处理的本质

Bitmap 在 Kotlin 层是对象，在 native 层可以通过 NDK 的 jnigraphics API 暂时拿到底层像素内存。拿到内存后，它和普通 C++ 数组非常像：你需要知道起始地址、每行跨度、宽高、像素格式，然后自己遍历处理。

这类处理适合：

  • 灰度、反色、阈值、亮度对比度调整。
  • 简单卷积，如模糊、锐化、边缘检测。
  • 把 Java/Kotlin 层频繁 per-pixel 操作移到 C++。
  • 和 OpenCV、libyuv、AI 推理前后处理衔接。

不适合：

  • 在 UI 线程处理超大图。
  • 每帧频繁跨 JNI 传很多小对象。
  • 依赖未公开像素布局或系统私有符号。

14.2 JNI 的性能边界

JNI 调用本身不是不能用，但不要把它当普通 Kotlin 函数高频细粒度调用。更好的方式是：

  • 一次传入整张图或整帧数据。
  • C++ 内部完成完整处理流程。
  • 只把最终结果或少量状态返回 Kotlin。

本文的 grayInPlace(bitmap) 和 nv21ToBitmap(...) 都是批量处理接口，符合这个原则。

14.3 和 OpenCV、FFmpeg、AI 推理的关系

这篇文章没有直接引入 OpenCV 或 FFmpeg，但链路是相通的：

  • OpenCV：可以把 Bitmap 像素复制或包装成 cv::Mat ，再调用滤波、边缘检测、特征提取等算法。
  • FFmpeg：解码得到的 YUV 帧可以先用 libswscale 或 libyuv 转成 RGBA，再交给渲染或 Bitmap。
  • AI 推理：相机 NV21/RGBA 帧通常要 resize、normalize、颜色通道转换，再输入 TFLite、ONNX Runtime、ncnn、MNN 等推理库。
  • OpenGL ES/Vulkan：实时预览更常走 GPU 纹理链路，而不是每帧写 Bitmap 。

先理解本文的 Bitmap、stride、YUV、JNI 边界，后面接这些库会顺很多。

15. 不要直接跨版本套用的点

  • 不要依赖 Android 私有 so、私有符号或未公开结构体字段。
  • 不要假设所有 Bitmap 都是 ARGB_8888。
  • 不要假设所有图片行跨度都是 width * 4 。
  • 不要假设相机输出一定是 NV21；Camera2 常见输出可能是 YUV_420_888 ，它有三个 plane，每个 plane 都有自己的 row stride 和 pixel stride。
  • 不要把 libyuv 主分支当稳定发布版本；请固定 commit。

16. 小结

本文完成了一个可复现的 Android NDK 图像处理项目：

  • Kotlin 使用 external fun 调 C++。
  • C++ 使用 AndroidBitmap_getInfo 、 AndroidBitmap_lockPixels 、 AndroidBitmap_unlockPixels 处理 Bitmap。
  • 灰度处理演示了 native 层逐像素读写。
  • libyuv::NV21ToARGB 演示了常见 YUV 到 RGBA 转换。
  • CMake 同时链接了 android 、 log 和第三方源码库 libyuv 。

继续扩展时，可以按这个顺序走：

  1. 给灰度处理加 NEON 或多线程。
  2. 接入真实 Camera2 YUV_420_888 数据。
  3. 增加 resize、rotate、mirror，模拟相机预处理。
  4. 把输出送给 OpenGL ES 纹理或 AI 推理输入。
  5. 再考虑 OpenCV、FFmpeg 等更大的 native 库。
