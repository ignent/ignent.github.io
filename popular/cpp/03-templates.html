C++ 模板：函数模板、类模板和 STL 模板容器

C++ 模板：函数模板、类模板和 STL 模板容器

C++ 模板最容易被讲成 “泛型编程” 的抽象概念，但真正写项目时，你会直接遇到这些问题：

  • 同一段边界检查逻辑， int 、 double 都想复用，是否要写两份函数？
  • 一个库存类想支持不同 ID 类型和数量类型，是否要为每种类型写一个类？
  • std::vector<int> 、 std::map<std::string, double> 为什么都能从同一个容器模板生成出不同类型？
  • 模板代码为什么经常放在头文件里？
  • 模板报错为什么看起来很长，应该从哪里排查？

本文用一个可以直接编译运行的 “小型库存统计” 项目，把函数模板、类模板和常用 STL 模板容器放进同一条业务流程中观察。程序会维护商品库存，按 SKU 调整库存，统计库存总数和库存金额，并找出低库存商品。

目标效果

复现完成后，你应该能看懂一条完整链路：用 std::vector 准备商品数据，用自定义类模板 Inventory<Id, Quantity> 管理库存，用 std::map 和 std::unordered_map 建索引，用函数模板复用统计和打印逻辑，最后通过 std::optional 表达 “可能查不到商品”。

1. 运行环境和前置条件

示例使用 C++20，只依赖 C++ 标准库。准备一个支持 C++20 的编译器和 CMake 即可。

推荐环境：

工具建议版本说明
C++ 编译器GCC 13+、Clang 17+ 或 MSVC 19.36+这些版本对本文用到的 C++20 concepts 、标准容器和常用库支持较完整
CMake3.20+用于跨平台生成构建文件
操作系统Linux、macOS、Windows 均可构建命令基本一致，Windows 建议使用 Visual Studio 开发者命令行

版本差异提醒：

  • 本文使用 C++20 的 std::signed_integral 、 std::totally_ordered 和自定义 concept。如果编译器没有启用 C++20，通常会出现 concepts 、 requires 或 std::signed_integral 相关报错。
  • 本文不使用 C++20 modules。模块在不同编译器、标准库和构建系统中的支持细节仍有差异，不建议把模块示例直接跨项目套用。
  • 本文不使用 std::format ，因为不同编译器和标准库版本曾经存在支持进度差异。为了便于复现，示例用 std::ostringstream 和 std::iomanip 格式化金额。
  • std::unordered_map 不保证遍历顺序。示例只把它当作 SKU 到 ID 的快速索引，不依赖它的输出顺序。

检查工具版本：

g++ --version
clang++ --version
cmake --version

只需要其中一个 C++ 编译器可用即可。Windows 使用 MSVC 时可运行：

cl
cmake --version

2. 最终目标和运行效果

我们会创建一个名为 template-inventory 的 C++20 小项目。程序运行后会完成这些操作：

  1. 用 std::vector<Product<int, int>> 准备初始商品。
  2. 用类模板 Inventory<int, int> 保存商品。
  3. 用 std::map<int, Product<int, int>> 按 ID 有序保存商品。
  4. 用 std::unordered_map<std::string, int> 建立 SKU 到商品 ID 的索引。
  5. 用函数模板调整数值边界、统计库存、打印指标。
  6. 用 std::optional<Product<int, int>> 表示 SKU 查询结果可能为空。

验证时重点看：

  • 商品列表按 id 从小到大输出，说明 std::map 的有序特性生效。
  • 未知 SKU 返回 false ，说明 std::unordered_map 查询失败时不会误改库存。
  • clamped discount 输出 0.20 ，说明函数模板 clamp_value 对 double 也能工作。
  • 低库存列表只输出 BOOK-CPP-20 ，说明类模板里的业务逻辑能正常筛选数据。

3. 项目结构

新建一个目录，例如 template-inventory ，文件结构如下：

template-inventory/
├── CMakeLists.txt
├── include/
│   └── template_inventory/
│       ├── algorithms.hpp
│       ├── inventory.hpp
│       └── report.hpp
└── src/
    ├── report.cpp
    └── main.cpp

各文件职责：

  • CMakeLists.txt ：声明项目名称、C++ 标准、可执行文件和头文件搜索路径。
  • include/template_inventory/algorithms.hpp ：定义通用函数模板，例如边界限制和字段累加。
  • include/template_inventory/inventory.hpp ：定义商品模型 Product 和库存类模板 Inventory 。
  • include/template_inventory/report.hpp ：声明报表函数，并定义依赖模板参数的输出函数模板。
  • src/report.cpp ：实现非模板函数，例如金额格式化。
  • src/main.cpp ：程序入口，负责准备数据、调用模板类和输出结果。

文件路径： CMakeLists.txt

# CMakeLists.txt
# 作用：配置 template-inventory 示例项目。放在项目根目录。

cmake_minimum_required(VERSION 3.20)

# project 声明项目名、版本和语言。
# LANGUAGES CXX 表示这是一个 C++ 项目。
project(template_inventory VERSION 1.0.0 LANGUAGES CXX)

# add_executable 生成一个名为 template_inventory 的可执行文件。
# 源文件只列 .cpp；头文件通过 include 路径被源文件包含。
add_executable(template_inventory
    src/main.cpp
    src/report.cpp
)

# CXX_STANDARD 20 要求使用 C++20。
# CXX_STANDARD_REQUIRED ON 表示编译器不支持 C++20 时直接失败。
# CXX_EXTENSIONS OFF 尽量关闭编译器私有扩展，让代码更接近标准 C++。
set_target_properties(template_inventory PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED ON
    CXX_EXTENSIONS OFF
)

# 把 include/ 加入当前目标的头文件搜索路径。
# 这样代码里才能写 #include "template_inventory/inventory.hpp"。
target_include_directories(template_inventory PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

注

CXX_STANDARD 是 CMake 的目标属性。本文把它设置在 template_inventory 这个目标上，而不是全局假设所有目标都使用同一个标准。实际项目有多个库或多个可执行文件时，按目标声明语言标准更容易排查构建问题。

5.1 通用算法模板

文件路径： include/template_inventory/algorithms.hpp

// include/template_inventory/algorithms.hpp
// 作用：定义可以被多个源文件复用的函数模板。
// 注意：模板定义通常需要放在头文件中，调用方才能完成实例化。

#ifndef TEMPLATE_INVENTORY_ALGORITHMS_HPP
#define TEMPLATE_INVENTORY_ALGORITHMS_HPP

#include <concepts>    // 使用 std::totally_ordered 约束可比较类型。
#include <iterator>    // 使用 std::begin 推导容器元素类型。
#include <stdexcept>   // 使用 std::invalid_argument 报告非法边界参数。
#include <type_traits> // 使用 std::decay_t 清理推导出的引用和 const。

namespace template_inventory {

// clamp_value 是一个函数模板。
// template <std::totally_ordered T> 表示 T 必须支持 <、>、== 等全序比较。
// int、double、std::string 等类型通常都满足这个约束。
template <std::totally_ordered T>
T clamp_value(const T& value, const T& low, const T& high) {
    // 如果上界比下界小，调用方传入的边界就是错误的。
    if (high < low) {
        throw std::invalid_argument("high must not be less than low");
    }

    // value 小于下界时返回下界。
    if (value < low) {
        return low;
    }

    // value 大于上界时返回上界。
    if (high < value) {
        return high;
    }

    // value 已经在 [low, high] 范围内，原样返回。
    return value;
}

// sum_projected 是一个函数模板。
// Container 表示任意可遍历容器，例如 std::vector<Product<int, int>>。
// Projection 表示一个可调用对象，例如 lambda，用来从元素中取出要累加的字段。
template <typename Container, typename Projection>
auto sum_projected(const Container& items, Projection projection) {
    // decltype(projection(*std::begin(items))) 推导 projection 返回值类型。
    // std::decay_t 去掉 const、引用等修饰，得到适合保存 total 的值类型。
    using Result = std::decay_t<decltype(projection(*std::begin(items)))>;

    // total 使用 Result{} 初始化，int 会变成 0，double 会变成 0.0。
    Result total{};

    // 遍历容器中的每个元素，把 projection(item) 的结果累加到 total。
    for (const auto& item : items) {
        total += projection(item);
    }

    // 返回累加结果。返回类型由编译器根据 total 自动推导。
    return total;
}

} // namespace template_inventory

#endif // TEMPLATE_INVENTORY_ALGORITHMS_HPP

5.2 商品模型和库存类模板

文件路径： include/template_inventory/inventory.hpp

// include/template_inventory/inventory.hpp
// 作用：定义商品模型 Product 和库存管理类模板 Inventory。
// Product 和 Inventory 都是模板，完整定义需要放在头文件中。

#ifndef TEMPLATE_INVENTORY_INVENTORY_HPP
#define TEMPLATE_INVENTORY_INVENTORY_HPP

#include "template_inventory/algorithms.hpp" // 使用 clamp_value 演示通用模板复用。

#include <concepts>      // 使用 std::signed_integral、std::totally_ordered 约束模板参数。
#include <limits>        // 使用 std::numeric_limits 获取整数类型最大值。
#include <map>           // 使用 std::map 按商品 ID 有序保存商品。
#include <optional>      // 使用 std::optional 表达“可能查到，也可能查不到”。
#include <string>        // 使用 std::string 保存 SKU、商品名等文本。
#include <unordered_map> // 使用 std::unordered_map 建立 SKU 到 ID 的快速索引。
#include <utility>       // 使用 std::move 移动商品对象，减少不必要拷贝。
#include <vector>        // 使用 std::vector 返回商品列表和筛选结果。

namespace template_inventory {

// Product 是一个类模板。这里使用 struct，是因为它只是简单数据模型。
// Id 表示商品 ID 类型，可以是 int、long long、std::string 等。
// Quantity 被限制为有符号整数，方便支持负数库存变更，例如 -8。
template <typename Id, std::signed_integral Quantity>
struct Product {
    Id id{};                  // 商品唯一 ID，用作 std::map 的 key。
    std::string sku;          // 库存单位编码，用作 std::unordered_map 的 key。
    std::string name;         // 商品名称，用于报表展示。
    Quantity stock{};         // 当前库存数量。
    Quantity warning_level{}; // 库存预警阈值，小于等于该值时提示低库存。
    double price{};           // 商品单价，用于计算库存金额。
};

// Inventory 是类模板。
// Id 表示商品 ID 类型；Quantity 表示库存数量类型。
// std::totally_ordered Id 要求 ID 可以排序，因为内部使用 std::map。
// std::signed_integral Quantity 要求 Quantity 是有符号整数类型。
template <std::totally_ordered Id, std::signed_integral Quantity>
class Inventory {
public:
    // ProductType 是当前 Inventory 实例所管理的具体商品类型。
    // Inventory<int, int> 中，ProductType 就是 Product<int, int>。
    using ProductType = Product<Id, Quantity>;

    // add_product 按值接收 product。
    // 调用方传左值时会复制，传右值时可以移动，函数内部统一用 std::move 存入容器。
    void add_product(ProductType product) {
        // 保存 id 和 sku 的副本，因为 product 稍后会被 std::move 移入 products_。
        const Id id = product.id;
        const std::string sku = product.sku;

        // products_ 是 std::map，按 id 有序保存商品。
        // insert_or_assign 表示 id 不存在就插入，id 已存在就覆盖。
        products_.insert_or_assign(id, std::move(product));

        // sku_index_ 是 std::unordered_map，用 SKU 快速找到商品 ID。
        sku_index_.insert_or_assign(sku, id);
    }

    // change_stock_by_sku 根据 SKU 调整库存。
    // delta 可以为正数或负数，例如 +15 表示入库，-8 表示出库。
    bool change_stock_by_sku(const std::string& sku, Quantity delta) {
        // 先从哈希表查 SKU。平均情况下 unordered_map 查询复杂度接近 O(1)。
        const auto sku_it = sku_index_.find(sku);

        // 找不到 SKU 时返回 false，让调用方知道没有修改任何数据。
        if (sku_it == sku_index_.end()) {
            return false;
        }

        // SKU 找到后，用对应 id 到 std::map 中定位商品记录。
        auto product_it = products_.find(sku_it->second);

        // 如果索引和商品表不一致，也返回 false。正常流程不应该发生。
        if (product_it == products_.end()) {
            return false;
        }

        // current 保存当前库存。业务上库存始终保持在 [0, max]。
        const Quantity current = product_it->second.stock;

        // max_stock 是当前 Quantity 类型能表示的最大库存值。
        const Quantity max_stock = std::numeric_limits<Quantity>::max();

        // next_stock 保存调整后的库存。
        Quantity next_stock = current;

        // delta 小于 0 表示出库。这里避免直接 current + delta 导致有符号整数下溢。
        if (delta < Quantity{0}) {
            // 如果减少量已经超过当前库存，就把库存归零。
            if (delta <= -current) {
                next_stock = Quantity{0};
            } else {
                next_stock = current + delta;
            }
        } else {
            // delta 大于等于 0 表示入库。这里避免直接 current + delta 导致有符号整数上溢。
            const Quantity distance_to_max = max_stock - current;

            if (delta > distance_to_max) {
                next_stock = max_stock;
            } else {
                next_stock = current + delta;
            }
        }

        // clamp_value 再做一次边界表达，让业务规则在代码里更直观。
        product_it->second.stock = clamp_value(next_stock, Quantity{0}, max_stock);

        // 返回 true 表示修改成功。
        return true;
    }

    // find_by_sku 根据 SKU 查询商品。
    // std::optional<ProductType> 有值表示查到了，std::nullopt 表示没查到。
    std::optional<ProductType> find_by_sku(const std::string& sku) const {
        // const 成员函数中只能通过 const 迭代器读取容器。
        const auto sku_it = sku_index_.find(sku);

        // SKU 不存在，返回空 optional。
        if (sku_it == sku_index_.end()) {
            return std::nullopt;
        }

        // 找到 SKU 对应的商品 ID。
        const auto product_it = products_.find(sku_it->second);

        // 商品表中没有该 ID，同样返回空 optional。
        if (product_it == products_.end()) {
            return std::nullopt;
        }

        // 返回商品副本。小示例里复制成本很低，也更容易理解。
        return product_it->second;
    }

    // list 返回所有商品的 vector 副本。
    // 由于 products_ 是 std::map，遍历结果会按 id 从小到大排列。
    std::vector<ProductType> list() const {
        // result 保存最终返回的商品列表。
        std::vector<ProductType> result;

        // reserve 预留空间，避免 push_back 过程中反复扩容。
        result.reserve(products_.size());

        // structured binding 把 map 的 key/value 拆成 id 和 product。
        for (const auto& [id, product] : products_) {
            // 当前函数只需要 product；id 由 map 的顺序负责。
            (void)id;

            // 把商品复制到 result 中。
            result.push_back(product);
        }

        // 返回 vector。现代编译器会使用移动或返回值优化降低开销。
        return result;
    }

    // low_stock_items 返回低库存商品列表。
    std::vector<ProductType> low_stock_items() const {
        // result 保存低库存商品。
        std::vector<ProductType> result;

        // 遍历所有商品，筛选 stock <= warning_level 的记录。
        for (const auto& [id, product] : products_) {
            (void)id;

            if (product.stock <= product.warning_level) {
                result.push_back(product);
            }
        }

        // 返回筛选结果。
        return result;
    }

private:
    // std::map 是有序关联容器模板。
    // key 是 Id，value 是 ProductType，适合稳定地按 ID 输出报表。
    std::map<Id, ProductType> products_;

    // std::unordered_map 是哈希关联容器模板。
    // key 是 std::string 类型 SKU，value 是 Id，适合快速按 SKU 查找。
    std::unordered_map<std::string, Id> sku_index_;
};

} // namespace template_inventory

#endif // TEMPLATE_INVENTORY_INVENTORY_HPP

5.3 报表输出头文件

文件路径： include/template_inventory/report.hpp

// include/template_inventory/report.hpp
// 作用：声明报表相关函数，并定义依赖模板参数的输出函数模板。

#ifndef TEMPLATE_INVENTORY_REPORT_HPP
#define TEMPLATE_INVENTORY_REPORT_HPP

#include "template_inventory/inventory.hpp" // 使用 Product 模板。

#include <concepts> // 使用 std::signed_integral 约束模板参数。
#include <iomanip>  // 使用 std::setw 控制输出宽度。
#include <iostream> // 使用 std::cout 打印报表。
#include <string>   // 使用 std::string 作为标签和格式化结果。

namespace template_inventory {

// StreamWritable 是一个自定义 concept。
// 它要求某个类型的值可以写入 std::ostream，例如 std::cout << value。
template <typename T>
concept StreamWritable = requires(std::ostream& output, const T& value) {
    output << value;
};

// format_money 是普通函数，不是模板。
// 这里只需要在头文件中声明，具体实现放在 src/report.cpp。
std::string format_money(double value);

// print_metric 是一个函数模板。
// T 只要能被 operator<< 输出到 std::cout，就可以传给这个函数。
template <StreamWritable T>
void print_metric(const std::string& label, const T& value) {
    // std::setw(18) 固定标签宽度，让输出对齐。
    std::cout << std::left << std::setw(18) << label << ": " << value << '\n';
}

// print_product 是函数模板，专门打印 Product<Id, Quantity>。
// Id 和 Quantity 的具体类型由传入的 product 自动推导。
template <StreamWritable Id, std::signed_integral Quantity>
void print_product(const Product<Id, Quantity>& product) {
    // 逐个输出商品字段，方便读者对照 Product 模板中的成员。
    std::cout << "id=" << product.id
              << " sku=" << product.sku
              << " name=" << product.name
              << " stock=" << product.stock
              << " warning=" << product.warning_level
              << " price=" << format_money(product.price);

    // 库存小于等于预警阈值时追加 [LOW] 标记。
    if (product.stock <= product.warning_level) {
        std::cout << " [LOW]";
    }

    // 每个商品占一行。
    std::cout << '\n';
}

} // namespace template_inventory

#endif // TEMPLATE_INVENTORY_REPORT_HPP

5.4 非模板函数实现文件

文件路径： src/report.cpp

// src/report.cpp
// 作用：实现报表相关的非模板函数。

#include "template_inventory/report.hpp"

#include <iomanip> // 使用 std::fixed、std::setprecision 控制金额格式。
#include <sstream> // 使用 std::ostringstream 生成字符串。

namespace template_inventory {

std::string format_money(double value) {
    // std::ostringstream 先把数字写入内存字符串流。
    std::ostringstream output;

    // std::fixed 表示固定小数格式，std::setprecision(2) 表示保留两位小数。
    output << std::fixed << std::setprecision(2) << value;

    // str() 取出格式化后的字符串。
    return output.str();
}

} // namespace template_inventory

5.5 程序入口

文件路径： src/main.cpp

// src/main.cpp
// 作用：组装示例数据，调用库存类模板和函数模板，观察运行结果。

#include "template_inventory/algorithms.hpp"
#include "template_inventory/inventory.hpp"
#include "template_inventory/report.hpp"

#include <iostream> // 使用 std::cout 打印流程标题。
#include <vector>   // 使用 std::vector 准备初始商品列表。

int main() {
    // using 声明把示例中要用的名字引入当前函数，避免每行都写命名空间前缀。
    using template_inventory::Inventory;
    using template_inventory::Product;
    using template_inventory::clamp_value;
    using template_inventory::format_money;
    using template_inventory::print_metric;
    using template_inventory::print_product;
    using template_inventory::sum_projected;

    // 创建一个具体类型：Inventory<int, int>。
    // 编译器会用 Id=int、Quantity=int 实例化 Inventory 类模板。
    Inventory<int, int> inventory;

    std::cout << "== build inventory ==\n";

    // std::vector 是顺序容器模板。
    // Product<int, int> 表示 Id 是 int、Quantity 也是 int 的具体商品类型。
    const std::vector<Product<int, int>> seed_products{
        {1001, "BOOK-CPP-20", "C++20 tutorial", 12, 5, 79.0},
        {1002, "KEY-MECH-87", "87-key keyboard", 4, 3, 299.0},
        {1003, "USB-CABLE-1M", "USB-C cable 1m", 30, 10, 19.9},
    };

    // 把初始商品逐个加入库存系统。
    for (const auto& product : seed_products) {
        inventory.add_product(product);
        std::cout << "added " << product.sku << '\n';
    }

    std::cout << "\n== adjust stock ==\n";

    // 出库 8 件，BOOK-CPP-20 库存会从 12 变成 4，并低于预警阈值 5。
    inventory.change_stock_by_sku("BOOK-CPP-20", -8);

    // 入库 15 件，USB-CABLE-1M 库存会从 30 变成 45。
    inventory.change_stock_by_sku("USB-CABLE-1M", 15);

    // 查询不存在的 SKU。函数返回 false，不会修改任何商品。
    const bool changed = inventory.change_stock_by_sku("UNKNOWN", 1);
    std::cout << "unknown sku changed: " << std::boolalpha << changed << "\n\n";

    std::cout << "== product list ==\n";

    // list 返回 std::vector<Product<int, int>>，便于后续遍历和统计。
    const auto products = inventory.list();

    // print_product 是函数模板，编译器会从 product 推导出 Id 和 Quantity。
    for (const auto& product : products) {
        print_product(product);
    }

    std::cout << "\n== metrics ==\n";

    // sum_projected 通过 lambda 取出 stock 字段，并把所有 stock 累加。
    const auto total_stock = sum_projected(
        products,
        [](const auto& product) {
            return product.stock;
        }
    );

    // 这里的 lambda 返回 double，因此 total_value 的类型也会推导为 double。
    const auto total_value = sum_projected(
        products,
        [](const auto& product) {
            return product.stock * product.price;
        }
    );

    // print_metric 可以打印 int。
    print_metric("total stock", total_stock);

    // print_metric 也可以打印 std::string。
    print_metric("total value", format_money(total_value));

    // clamp_value 也可以用于 double。0.28 会被限制到 [0.0, 0.20] 中的 0.20。
    print_metric("clamped discount", format_money(clamp_value(0.28, 0.0, 0.20)));

    std::cout << "\n== find by sku ==\n";

    // find_by_sku 返回 std::optional<Product<int, int>>。
    // if 语句会检查 optional 是否有值。
    if (const auto found = inventory.find_by_sku("KEY-MECH-87")) {
        // *found 取出 optional 内部保存的 Product。
        print_product(*found);
    }

    std::cout << "\n== low stock ==\n";

    // low_stock_items 返回低库存商品列表。
    for (const auto& product : inventory.low_stock_items()) {
        print_product(product);
    }

    // main 返回 0 表示程序正常结束。
    return 0;
}

7. 整体流程拆解

这个程序可以按五步理解：

  1. include/template_inventory/algorithms.hpp 提供通用函数模板： clamp_value 和 sum_projected 。
  2. include/template_inventory/inventory.hpp 提供商品模型 Product<Id, Quantity> 和库存类模板 Inventory<Id, Quantity> 。
  3. include/template_inventory/report.hpp 声明普通函数 format_money ，并定义输出函数模板 print_metric 、 print_product 。
  4. src/report.cpp 实现普通函数 format_money 。
  5. src/main.cpp 用 std::vector<Product<int, int>> 准备数据，调用库存类和函数模板输出报表。

这里最重要的一点是：模板本身不是一个具体函数或具体类。只有当你写出 Inventory<int, int> 、 Product<int, int> 、 clamp_value(0.28, 0.0, 0.20) 时，编译器才会根据实际类型生成可编译的具体代码。

8. 关键代码解释

8.1 函数模板：把相同算法用于不同类型

include/template_inventory/algorithms.hpp 中的 clamp_value 核心是这行：

template <std::totally_ordered T>
T clamp_value(const T& value, const T& low, const T& high)

含义如下：

  • template <...> 声明这是模板。
  • T 是模板参数，代表调用时才确定的类型。
  • std::totally_ordered T 是 C++20 concepts 写法，要求 T 能进行全序比较。
  • const T& 避免不必要复制，也保证函数内部不修改调用方传入的值。

调用 clamp_value(0.28, 0.0, 0.20) 时，三个实参都是 double ，编译器推导出 T = double ，生成一个类似 double clamp_value(const double&, const double&, const double&) 的函数。

在库存类中也可以看到同一个模板对 Quantity 类型生效：

product_it->second.stock = clamp_value(next_stock, Quantity{0}, max_stock);

如果 Inventory<int, int> 中 Quantity 是 int ，这里就会实例化 clamp_value<int> 。

注意

clamp_value(1, 0, 2.5) 通常无法通过模板实参推导，因为前两个参数像 int ，第三个参数像 double 。可以改成 clamp_value<double>(1, 0, 2.5) ，或把参数写成同一类型： clamp_value(1.0, 0.0, 2.5) 。

8.2 函数模板 + lambda：统计任意字段

sum_projected 的目标是：不关心容器里装的具体类型，只要求调用方告诉它 “从每个元素里取哪个值来累加”。

template <typename Container, typename Projection>
auto sum_projected(const Container& items, Projection projection)

在 main 中统计库存：

const auto total_stock = sum_projected(
    products,
    [](const auto& product) {
        return product.stock;
    }
);

这里发生了两层推导：

  • Container 被推导为 std::vector<Product<int, int>> 。
  • Projection 被推导为这个 lambda 的闭包类型。

统计金额时：

const auto total_value = sum_projected(
    products,
    [](const auto& product) {
        return product.stock * product.price;
    }
);

lambda 返回 double ，所以 sum_projected 内部的 Result 也是 double 。这就是模板常见的用途：算法只写一份，类型由调用点决定。

8.3 类模板：生成不同版本的数据结构

Product 是一个类模板：

template <typename Id, std::signed_integral Quantity>
struct Product {
    Id id{};
    std::string sku;
    std::string name;
    Quantity stock{};
    Quantity warning_level{};
    double price{};
};

当你写：

Product<int, int>

它表示：

  • Id = int
  • Quantity = int
  • id 的类型是 int
  • stock 和 warning_level 的类型也是 int

如果某个项目使用字符串作为商品 ID，也可以设计成：

Product<std::string, int>

但要注意：当前 Inventory 内部使用了 std::map<Id, ProductType> ，所以 Inventory 对 Id 增加了 std::totally_ordered 约束。 int 和 std::string 都可以满足常见排序需求；自定义 ID 类型则需要提供比较规则。

8.4 类模板内部使用 STL 模板容器

Inventory 的两个成员变量是本文理解 STL 模板容器的关键：

std::map<Id, ProductType> products_;
std::unordered_map<std::string, Id> sku_index_;

std::map<Id, ProductType> 的特点：

  • key 唯一。
  • 默认按 key 从小到大排序。
  • 查找、插入、删除通常是对数复杂度。
  • 适合需要稳定顺序输出的报表场景。

std::unordered_map<std::string, Id> 的特点：

  • key 唯一。
  • 内部基于哈希表组织数据。
  • 平均情况下查找、插入、删除接近常数复杂度。
  • 不保证遍历顺序。

所以示例里把二者分工：

  • products_ 负责保存完整商品，并提供稳定输出顺序。
  • sku_index_ 负责从 SKU 快速定位商品 ID。

8.5 optional：显式表达 “可能为空”

查询函数没有返回裸指针，也没有用特殊 ID 表示失败，而是返回：

std::optional<ProductType>

调用方必须显式检查：

if (const auto found = inventory.find_by_sku("KEY-MECH-87")) {
    print_product(*found);
}

这样写的好处是：函数签名已经告诉读者 “这个查询可能没有结果”。相比返回空字符串、 -1 或 nullptr ， std::optional 更适合表达值语义下的可选结果。

8.6 为什么 format_money 可以放进 .cpp

format_money 是普通函数：

std::string format_money(double value);

调用方只需要看到这条声明，就知道它接收 double 并返回 std::string 。函数体放在 src/report.cpp 中，编译完成后由链接器把调用点和实现连接起来。

但 print_metric 、 print_product 、 Inventory 都是模板。编译器在看到 print_product(Product<int, int>{...}) 或 Inventory<int, int> 时，需要完整模板定义来生成具体代码，所以它们留在头文件中。

9. 背后的模板原理

9.1 模板实例化

模板定义本身不是最终机器码。编译器会在使用点根据具体类型生成实例。

例如：

Inventory<int, int> inventory;

会触发 Inventory<Id, Quantity> 以 Id = int 、 Quantity = int 生成一个具体类。类似地：

clamp_value(0.28, 0.0, 0.20)

会生成 clamp_value<double> 。

这也是模板报错经常很长的原因：错误可能发生在模板定义中，但真正触发错误的是某个具体实例化点。

9.2 模板定义为什么常放头文件

普通函数可以在头文件声明、在 .cpp 文件实现，因为编译器编译调用方时只需要知道函数签名，链接器稍后会找到函数实现。

模板不同。编译器在实例化模板时通常需要看到完整定义。比如调用方写了：

Inventory<int, int> inventory;

编译器需要知道 Inventory 的成员函数具体怎么写，才能生成 Inventory<int, int> 的代码。因此模板类和模板函数经常直接放在头文件里。

如果你把模板定义放进 .cpp ，但没有显式实例化需要的类型，常见结果是链接时报 undefined reference 或 unresolved external symbol 。

注

显式实例化可以让部分模板实现留在 .cpp 中，但它要求你提前知道所有要支持的类型。入门和通用库场景下，先把模板定义放在头文件里更容易理解和维护。

9.3 concepts 让错误更靠近原因

传统模板常在函数体内部才暴露类型不匹配问题，错误信息可能很长。C++20 concepts 可以提前声明类型要求。

例如：

template <std::totally_ordered Id, std::signed_integral Quantity>
class Inventory;

这行代码明确要求：

  • Id 可以排序，因为 Inventory 内部要使用 std::map<Id, ProductType> 。
  • Quantity 是有符号整数，因为库存变更要支持 -8 这样的出库数量。

如果写：

Inventory<int, double> inventory;

编译器会直接提示 double 不满足 std::signed_integral ，比在函数体内部某个表达式报错更容易定位。

9.4 STL 容器本身就是类模板

常见 STL 容器基本都是模板：

std::vector<Product<int, int>>
std::map<int, Product<int, int>>
std::unordered_map<std::string, int>
std::optional<Product<int, int>>

尖括号里的类型参数决定了容器最终保存什么数据、如何比较、如何哈希、如何分配内存。学习模板不是只为了自己写泛型代码，也是为了更准确地理解标准库类型。

10. 常见错误和排查思路

10.1 std::signed_integral 或 std::totally_ordered 未定义

常见原因：

  • 没有 #include <concepts> 。
  • 编译器没有启用 C++20。
  • CMake 没有正确设置 CXX_STANDARD 20 。

排查方式：

cmake -S . -B build
cmake --build build --verbose

观察实际编译命令中是否包含 -std=c++20 、 /std:c++20 或等价选项。

10.2 找不到头文件 template_inventory/inventory.hpp

典型报错：

fatal error: template_inventory/inventory.hpp: No such file or directory

常见原因是忘记在 CMake 中配置头文件搜索路径。

确认 CMakeLists.txt 中存在：

target_include_directories(template_inventory PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

修改 CMake 后建议重新配置：

cmake -S . -B build
cmake --build build

10.3 模板函数放进 .cpp 后链接失败

典型报错：

undefined reference to `...`
unresolved external symbol ...

原因通常是：调用方只看到了模板声明，没有看到模板定义，编译器无法实例化对应类型。

解决思路：

  • 把模板定义放到头文件。
  • 或在 .cpp 中为明确需要的类型写显式实例化。

10.4 clamp_value(1, 0, 2.5) 无法编译

原因是函数模板参数 T 需要推导成一个确定类型，但实参里同时出现了 int 和 double 。

修复方式：

clamp_value(1.0, 0.0, 2.5);
clamp_value<double>(1, 0, 2.5);

10.5 print_metric 或 print_product 打印自定义类型失败

print_metric 内部使用：

std::cout << value;

print_product 内部也会打印 product.id 。因此被打印的类型必须支持输出流运算符 operator<< 。本文用 StreamWritable concept 把这个要求写在模板签名里，报错会比传统模板更靠近原因。

如果传入自定义 ID 类型，需要自己实现输出逻辑，或先转换成字符串。

10.6 std::unordered_map 输出顺序不稳定

std::unordered_map 是哈希容器，不保证遍历顺序。不同编译器、不同标准库版本、不同插入顺序下，遍历结果都可能不同。

如果需要稳定输出顺序，使用：

std::map<Key, Value>

如果只需要快速查找，不关心顺序，使用：

std::unordered_map<Key, Value>

10.7 Windows 下找不到可执行文件

Visual Studio 生成器通常是多配置生成器，可执行文件可能在：

build/Debug/template_inventory.exe
build/Release/template_inventory.exe

可以先查看构建输出，也可以显式指定配置：

cmake --build build --config Release
.\build\Release\template_inventory.exe

11. 小结

这篇文章用一个正式拆分结构的库存统计项目串起了三类知识：

  • 函数模板： clamp_value 、 sum_projected 、 print_metric 让同一段算法适配不同类型。
  • 类模板： Product<Id, Quantity> 和 Inventory<Id, Quantity> 让数据结构在类型层面可复用。
  • STL 模板容器： std::vector 、 std::map 、 std::unordered_map 、 std::optional 是日常 C++ 项目里最常见的模板类型。

拆分项目时可以记住一个实用规则：

  • 模板定义通常放头文件，因为调用方实例化模板时需要看到完整定义。
  • 普通函数可以头文件声明、 .cpp 实现，因为链接器能在后续阶段连接实现。
  • CMake 里要为目标配置 target_include_directories ，否则 include/ 下的头文件无法被找到。

入门阶段不要急着追求复杂模板技巧。先掌握三个判断标准更重要：

  1. 这段逻辑是否真的需要支持多种类型？
  2. 模板参数是否有清晰约束？
  3. 调用方能否从函数名、类型名和返回值看出行为？

能回答这三个问题，模板代码通常就不会变成难以维护的 “类型魔法”。
