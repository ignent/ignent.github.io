C++ 入门：基本语法、类型系统和函数

本文用三个可以直接编译运行的小项目，串起 C++ 入门时最容易混在一起的知识点：头文件和源文件、命名空间、 const 、引用、指针、值类型、 auto 、类型转换、函数重载、默认参数、函数指针和 lambda。

全文分为三部分：

  • 第一篇：用一个计数器项目理解头文件、源文件、命名空间、 const 、引用、指针和作用域。
  • 第二篇：用一个类型系统实验理解值类型、指针、引用、 auto 和类型转换。
  • 第三篇：用一个购物车计价项目理解函数重载、默认参数、 inline 、函数指针和 lambda。

第一篇：C++ 基本语法：从头文件、源文件到引用和指针

本文用一个可以直接编译运行的小项目串起 C++ 入门时最容易混在一起的几个知识点：

  • 头文件和源文件如何分工
  • 命名空间如何组织代码
  • const 如何限制修改
  • 引用和指针分别适合什么场景
  • 局部作用域、命名空间作用域、文件作用域有什么差异

最终程序会管理一个简单的 “计数器”，打印计数器状态，并演示通过引用修改对象、通过指针可选地访问对象、通过 const 防止误改数据。

目标效果

读完并复现后，你应该能理解一个 C++ 小项目为什么通常拆成 .hpp 和 .cpp ，也能说清 const Counter& 、 Counter* 、 static 变量和 namespace 分别在解决什么问题。

1. 最终项目结构

新建一个目录，例如 cpp-basic-syntax-demo ，文件结构如下：

cpp-basic-syntax-demo/
├── CMakeLists.txt
├── include/
│   └── demo/
│       └── counter.hpp
└── src/
    ├── counter.cpp
    └── main.cpp

各文件职责：

  • include/demo/counter.hpp ：声明对外可用的类型和函数。
  • src/counter.cpp ：实现头文件里声明的函数。
  • src/main.cpp ：程序入口，调用库代码并观察运行结果。
  • CMakeLists.txt ：告诉 CMake 如何编译这个小项目。

2. 关键配置文件

文件路径： CMakeLists.txt

# CMakeLists.txt
# 作用：描述项目如何构建。放在项目根目录。

cmake_minimum_required(VERSION 3.20)

# project 名字可以自行修改；LANGUAGES CXX 表示这是 C++ 项目。
project(cpp_basic_syntax_demo VERSION 1.0.0 LANGUAGES CXX)

# 生成一个名为 cpp_basic_syntax_demo 的可执行文件。
# 这里列出所有 .cpp 源文件，头文件通常不需要放进 add_executable。
add_executable(cpp_basic_syntax_demo
    src/main.cpp
    src/counter.cpp
)

# 要求使用 C++20。
# CXX_STANDARD_REQUIRED ON 表示如果编译器不支持 C++20，就直接失败。
set_target_properties(cpp_basic_syntax_demo PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED ON
    CXX_EXTENSIONS OFF
)

# 把 include/ 加入头文件搜索路径。
# 这样代码里才能写 #include "demo/counter.hpp"。
target_include_directories(cpp_basic_syntax_demo PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

注

CXX_EXTENSIONS OFF 会尽量避免启用编译器私有扩展，让示例更接近标准 C++。如果你在旧项目中看到 GNU 扩展写法，它们不一定能被 MSVC 或其他编译器接受。

3. 核心源码

3.1 头文件：声明项目对外能力

文件路径： include/demo/counter.hpp

// include/demo/counter.hpp
// 作用：声明 Counter 类型和相关函数，供其他 .cpp 文件 include。

#ifndef DEMO_COUNTER_HPP
#define DEMO_COUNTER_HPP

#include <string>

// namespace 用来把名字放进一个逻辑分组，避免和其他库的名字冲突。
namespace demo {

// Counter 是一个简单计数器。
// struct 的成员默认 public，适合用来演示小型数据结构。
struct Counter {
    std::string name; // 计数器名称
    int value;        // 当前计数值
};

// const int 表示 initial_value 在函数内部不能被重新赋值。
// 返回 Counter 表示创建一个新的计数器对象。
Counter make_counter(const std::string& name, const int initial_value);

// Counter& 是引用参数，函数可以直接修改调用者传入的对象。
// const int step 表示 step 本身在函数内部不能被修改。
void increase(Counter& counter, const int step);

// const Counter& 是只读引用：
// 1. 避免复制 Counter
// 2. 禁止函数内部修改 counter
std::string describe(const Counter& counter);

// Counter* 是指针参数，可以传入 nullptr 表示“没有对象”。
// 这个函数演示指针适合表达可选对象。
void reset_if_not_null(Counter* counter);

} // namespace demo

#endif // DEMO_COUNTER_HPP

头文件通常放 “声明”，告诉其他源文件：这里有哪些类型、函数、常量可以用。上面的 #ifndef 、 #define 、 #endif 是 include guard，用来防止同一个头文件被重复包含后造成重复定义。

提示

现代 C++ 项目里也经常看到 #pragma once 。它更短，但不是 ISO C++ 标准正式规定的语法；主流编译器基本都支持。为了最大限度保持可移植性，本文使用传统 include guard。

3.2 源文件：实现头文件声明的函数

文件路径： src/counter.cpp

// src/counter.cpp
// 作用：实现 include/demo/counter.hpp 中声明的函数。

#include "demo/counter.hpp"

#include <sstream>

namespace demo {

// unnamed namespace 中的名字只在当前 .cpp 文件可见。
// 它适合放“只给本文件内部使用”的辅助函数或常量。
namespace {

// kDefaultName 是文件内常量，不会暴露给其他源文件。
const char* const kDefaultName = "unnamed";

// normalize_name 是文件内辅助函数。
// const std::string& 避免复制字符串，并保证函数不修改参数。
std::string normalize_name(const std::string& name) {
    if (name.empty()) {
        return kDefaultName;
    }

    return name;
}

} // namespace

Counter make_counter(const std::string& name, const int initial_value) {
    // 局部变量 normalized 只在当前函数作用域内有效。
    const std::string normalized = normalize_name(name);

    // 使用聚合初始化创建 Counter。
    return Counter{
        .name = normalized,
        .value = initial_value,
    };
}

void increase(Counter& counter, const int step) {
    // counter 是引用，修改 counter.value 会影响调用者传入的对象。
    counter.value += step;
}

std::string describe(const Counter& counter) {
    // std::ostringstream 用来拼接字符串，避免手动管理字符数组。
    std::ostringstream output;
    output << "Counter{name=\"" << counter.name
           << "\", value=" << counter.value << "}";
    return output.str();
}

void reset_if_not_null(Counter* counter) {
    // 指针可能为空，解引用前必须检查。
    if (counter == nullptr) {
        return;
    }

    // -> 用于通过指针访问对象成员，等价于 (*counter).value。
    counter->value = 0;
}

} // namespace demo

这一份源文件展示了三个层次的作用域：

  • namespace demo ：命名空间作用域， demo::make_counter 等函数属于项目公开接口的一部分。
  • namespace { ... } ：匿名命名空间，里面的名字只在当前 counter.cpp 可见。
  • 函数内部：例如 normalized 、 output 是局部变量，离开函数后就不能访问。

3.3 主程序：调用并验证结果

文件路径： src/main.cpp

// src/main.cpp
// 作用：程序入口，演示头文件、命名空间、const、引用、指针和作用域。

#include "demo/counter.hpp"

#include <iostream>

// g_program_name 位于文件作用域。
// static 表示这个名字只在当前 main.cpp 文件可见。
static const char* const g_program_name = "cpp-basic-syntax-demo";

int main() {
    std::cout << "Program: " << g_program_name << '\n';

    // demo:: 表示访问 demo 命名空间里的名字。
    demo::Counter visits = demo::make_counter("visits", 10);

    // const 引用只能读取，不能修改。
    // 如果尝试写 readonly_visits.value = 99; 编译器会报错。
    const demo::Counter& readonly_visits = visits;

    std::cout << "Initial: "
              << demo::describe(readonly_visits) << '\n';

    // increase 接收 Counter&，会直接修改 visits。
    demo::increase(visits, 5);

    std::cout << "After increase: "
              << demo::describe(visits) << '\n';

    // Counter* 表示 visits_ptr 是指针，保存 Counter 对象的地址。
    // &visits 表示取得 visits 的地址。
    demo::Counter* visits_ptr = &visits;
    demo::reset_if_not_null(visits_ptr);

    std::cout << "After reset: "
              << demo::describe(visits) << '\n';

    // nullptr 表示空指针。reset_if_not_null 会安全地忽略它。
    demo::reset_if_not_null(nullptr);

    // 这个代码块创建了一个新的局部作用域。
    {
        const demo::Counter temporary = demo::make_counter("", 3);
        std::cout << "Temporary: "
                  << demo::describe(temporary) << '\n';
    }

    // temporary 在上面的代码块结束后已经离开作用域。
    // 如果在这里使用 temporary，编译器会报“未声明的标识符”。

    return 0;
}

main.cpp 是最适合观察语法效果的地方。你可以临时取消注释某些错误示例，例如给 readonly_visits.value 赋值，亲自看编译器如何阻止误用。

6. 按流程拆解这段程序

整体流程可以分成四步：

  1. main.cpp 通过 #include "demo/counter.hpp" 看到 Counter 和函数声明。
  2. 编译器分别编译 main.cpp 和 counter.cpp ，生成中间目标文件。
  3. 链接器把 main.cpp 中调用的 demo::make_counter 等符号，连接到 counter.cpp 里的函数实现。
  4. 程序运行时创建 Counter ，通过引用和指针修改同一个对象，然后打印结果。

所以头文件不是 “复制一份实现”，而是给不同源文件共享同一组声明。真正的函数体在 counter.cpp 中。

7. 关键语法逐段解释

7.1 头文件和源文件

counter.hpp 里写：

Counter make_counter(const std::string& name, const int initial_value);

这是函数声明，末尾是分号，没有函数体。它告诉编译器： demo 命名空间里有一个叫 make_counter 的函数，参数是什么，返回值是什么。

counter.cpp 里写：

Counter make_counter(const std::string& name, const int initial_value) {
    const std::string normalized = normalize_name(name);
    return Counter{
        .name = normalized,
        .value = initial_value,
    };
}

这是函数定义，包含函数体。一个普通函数通常只能在整个程序里定义一次，否则链接阶段会出现重复定义问题。

7.2 命名空间

示例把类型和函数放在 demo 里：

namespace demo {
struct Counter {
    std::string name;
    int value;
};
} // namespace demo

使用时写：

demo::Counter visits = demo::make_counter("visits", 10);

demo::Counter 的完整名字包含命名空间。这样即使别的库也有 Counter ，只要命名空间不同，就不会直接冲突。

入门阶段不建议在头文件里写 using namespace std; 。头文件会被很多源文件包含，把整个 std 命名空间导入出去容易污染使用者的命名空间。

7.3 const

本文出现了几种常见 const ：

const int initial_value
const std::string& name
const demo::Counter& readonly_visits
static const char* const g_program_name

它们含义不同：

写法含义
const int initial_value函数内部不能修改这个整数参数
const std::string& name通过引用读取字符串，不能修改原字符串
const demo::Counter& readonly_visits只读地访问 Counter 对象
const char* const p指针本身不能改，指向的字符内容也不应通过它修改

const 的价值不是 “让程序更高级”，而是让编译器帮你阻止误改。例如：

const demo::Counter& readonly_visits = visits;
readonly_visits.value = 99; // 编译错误：不能通过 const 引用修改对象

7.4 引用

increase 的参数是 Counter& ：

void increase(Counter& counter, const int step) {
    counter.value += step;
}

引用可以理解为某个对象的别名。调用：

demo::increase(visits, 5);

函数内部的 counter 指向的就是 visits 本体，所以修改 counter.value 会改变 visits.value 。

常见使用建议：

  • 需要修改调用者对象时，用非常量引用，例如 Counter& 。
  • 只读且对象可能比较大时，用常量引用，例如 const Counter& 。
  • 小整数、布尔值、枚举这类小对象通常直接按值传递即可。

7.5 * 和 & 的含义

* 和 & 在 C++ 里不是只有一个固定意思，它们的含义取决于所在位置。读代码时先看上下文，再判断它是在 “声明类型” 还是在 “操作对象”。

写法出现位置含义
Counter& counter类型声明中counter 是 Counter 对象的引用
Counter* counter类型声明中counter 是指向 Counter 对象的指针
&visits表达式中取得 visits 的地址
*visits_ptr表达式中访问 visits_ptr 指向的对象，也叫解引用

先看一个最小例子：

int value = 10;

int& ref = value;   // & 在类型里：ref 是 value 的引用，也就是别名
int* ptr = &value;  // * 在类型里：ptr 是指针；& 在表达式里：取得 value 的地址

ref = 20;           // 通过引用修改 value
*ptr = 30;          // * 在表达式里：解引用 ptr，再修改它指向的 value

执行完后， value 的值是 30 。 ref = 20 和 *ptr = 30 都修改了同一个变量，只是表达方式不同。

把它放回本文项目：

demo::Counter visits = demo::make_counter("visits", 10);

demo::Counter& visits_ref = visits; // 引用：visits_ref 是 visits 的别名
demo::Counter* visits_ptr = &visits; // 指针：visits_ptr 保存 visits 的地址

visits_ref.value = 15;  // 通过引用访问成员，用 .
visits_ptr->value = 0;  // 通过指针访问成员，用 ->

visits_ptr->value 等价于：

(*visits_ptr).value

这里必须加括号，因为成员访问运算符 . 的优先级高于解引用运算符 * 。如果写成 *visits_ptr.value ，编译器会先尝试访问 visits_ptr.value ，但 visits_ptr 是指针，不是对象。

快速判断

  • 类型& 名字 ：声明引用。
  • 类型* 名字 ：声明指针。
  • &变量 ：取变量地址。
  • *指针 ：访问指针指向的对象。

7.6 指针

reset_if_not_null 使用 Counter* ：

void reset_if_not_null(Counter* counter) {
    if (counter == nullptr) {
        return;
    }

    counter->value = 0;
}

指针和引用最大的区别之一是：指针可以为空。这个函数把 nullptr 当作合法输入，因此必须先检查：

demo::reset_if_not_null(nullptr);

如果没有空指针检查，直接写 counter->value = 0; ，传入 nullptr 时程序可能崩溃。

入门时可以先记住：

  • 必须有对象时，优先考虑引用。
  • “可能没有对象” 时，可以使用指针，并且先检查 nullptr 。
  • 涉及所有权和动态内存时，优先学习 std::unique_ptr 、 std::shared_ptr ，不要一开始就手写 new 和 delete 。

7.7 作用域

示例里有多种作用域：

namespace demo {
    // 命名空间作用域
}
namespace {
    // 当前 .cpp 文件内部可见
}
int main() {
    {
        const demo::Counter temporary = demo::make_counter("", 3);
    }
    // temporary 到这里已经不可见
}

作用域决定名字在哪里可见、什么时候失效。控制作用域能减少命名冲突，也能降低误用变量的概率。

在 main.cpp 中：

static const char* const g_program_name = "cpp-basic-syntax-demo";

这里的 static 用在文件作用域，表示 g_program_name 只在当前源文件可见。现代 C++ 中， .cpp 内部辅助名字也常用匿名命名空间表达文件内可见性。

8. 背后的编译原理

C++ 的传统构建大致分为三个阶段：

  1. 预处理：处理 #include 、 #define 、条件编译等。 #include "demo/counter.hpp" 会把头文件内容带入当前翻译单元。
  2. 编译：每个 .cpp 通常单独编译成目标文件。编译 main.cpp 时，编译器只需要看到函数声明，不需要看到函数实现。
  3. 链接：把多个目标文件和库合并成最终可执行文件。链接器负责找到 demo::make_counter 、 demo::increase 等函数定义。

这解释了两个常见现象：

  • 如果忘记把 src/counter.cpp 加入构建，编译可能通过，但链接会失败。
  • 如果函数声明和定义的参数不一致，编译或链接阶段会报错，因为调用方和实现方对同一个符号的理解不同。

9. 常见错误和排查思路

9.1 找不到头文件

错误类似：

fatal error: demo/counter.hpp: No such file or directory

排查：

  • 确认文件路径是 include/demo/counter.hpp 。
  • CMake 项目中确认有 target_include_directories(... include) 。
  • 手动编译时确认加了 -I include 或 MSVC 的 /I include 。

9.2 链接失败：undefined reference

错误类似：

undefined reference to `demo::make_counter(...)'

排查：

  • 确认编译命令包含 src/counter.cpp 。
  • CMake 中确认 add_executable 列出了 src/counter.cpp 。
  • 确认函数定义仍在 namespace demo 里面。

9.3 重复定义

错误类似：

multiple definition of `demo::increase(...)'

排查：

  • 不要把普通函数实现直接写进头文件后又被多个 .cpp 包含。
  • 如果确实要在头文件定义小函数，需要理解 inline 的规则后再使用。

9.4 试图修改 const 对象

错误类似：

assignment of member 'Counter::value' in read-only object

排查：

  • 看变量或参数是不是 const Counter& 。
  • 如果函数本来就应该修改对象，参数应设计为 Counter& 。
  • 如果函数只负责读取，不要为了绕过错误去移除 const ，先确认设计意图。

9.5 空指针崩溃

现象：

Segmentation fault

排查：

  • 检查有没有对可能为空的指针直接使用 -> 或 * 。
  • 先判断 counter == nullptr 。
  • 如果参数不允许为空，考虑改用引用，让接口表达 “必须传入对象”。

10. 可以继续练习的改造

你可以在当前项目上做三组练习：

  1. 给 Counter 增加 const int max_value ，限制最大计数值。

每次改完后重新构建并运行，观察输出是否符合预期。

4. 核心源码

文件路径： src/main.cpp

// src/main.cpp
// 作用：演示 C++20 中值类型、引用、指针、auto 和类型转换的基本行为。

#include <iomanip>
#include <iostream>
#include <sstream>
#include <string>
#include <string_view>
#include <type_traits>

// Item 是一个普通值类型。
// 它不管理外部资源，复制 Item 会得到一个独立的新对象。
struct Item {
    int id;       // 商品编号
    double price; // 商品价格，示例中用 double 方便演示数值转换
};

// 把 Item 格式化为字符串，便于稳定打印。
// const Item& 表示只读引用：不复制 Item，也不允许函数修改它。
std::string describe(const Item& item) {
    std::ostringstream output;
    output << std::fixed << std::setprecision(2);
    output << "Item{id=" << item.id << ", price=" << item.price << "}";
    return output.str();
}

// 打印对象地址。
// static_cast<const void*> 用于把对象指针转换为通用地址形式，便于输出。
void print_address(std::string_view label, const Item& item) {
    std::cout << label << static_cast<const void*>(&item) << '\n';
}

// 引用参数要求调用者必须传入一个有效 Item。
// 函数内部修改 item.price，会直接影响调用者传入的原对象。
void apply_discount(Item& item, const double amount) {
    item.price -= amount;
}

// 指针参数可以表达“可能没有对象”。
// 因为 item 可能是 nullptr，所以解引用前必须检查。
void add_fee_if_present(Item* item, const double fee) {
    if (item == nullptr) {
        std::cout << "pointer is null, skip update\n";
        return;
    }

    // item->price 等价于 (*item).price。
    item->price += fee;
}

int main() {
    std::cout << "== value type ==\n";

    // original 是一个 Item 对象。
    Item original{.id = 7, .price = 19.99};

    // copy 是 original 的副本。
    // 修改 copy.price 不会影响 original.price。
    Item copy = original;
    copy.price = 29.99;

    std::cout << "original: " << describe(original) << '\n';
    std::cout << "copy:     " << describe(copy) << '\n';
    print_address("original address: ", original);
    print_address("copy address:     ", copy);

    std::cout << "\n== reference ==\n";

    // reference 是 original 的引用，也就是别名。
    // 引用初始化后不能重新绑定到另一个对象。
    Item& reference = original;
    apply_discount(reference, 2.00);

    std::cout << "after discount: " << describe(original) << '\n';
    print_address("original address:  ", original);
    print_address("reference address: ", reference);

    std::cout << "\n== pointer ==\n";

    // nullptr 表示空指针。空指针不指向任何对象。
    Item* maybe_item = nullptr;
    add_fee_if_present(maybe_item, 2.01);

    // &original 取得 original 的地址。
    // item_ptr 保存这个地址，因此可以通过指针修改 original。
    Item* item_ptr = &original;
    add_fee_if_present(item_ptr, 2.01);
    std::cout << "after pointer update: " << describe(original) << '\n';

    std::cout << "\n== auto ==\n";

    // const_snapshot 是只读对象。
    const Item const_snapshot = original;

    // auto 默认按值推导，会复制对象，并丢弃顶层 const。
    auto auto_copy = const_snapshot;
    static_assert(std::is_same_v<decltype(auto_copy), Item>);
    auto_copy.price += 1.00;

    // auto& 保留引用语义，auto_ref 是 original 的别名。
    auto& auto_ref = original;
    static_assert(std::is_same_v<decltype(auto_ref), Item&>);

    // const auto& 适合只读访问，既不复制，也不允许修改。
    const auto& readonly_ref = original;
    static_assert(std::is_same_v<decltype(readonly_ref), const Item&>);

    // auto* 明确表达这里要推导一个指针类型。
    auto* auto_ptr = &original;
    static_assert(std::is_same_v<decltype(auto_ptr), Item*>);

    std::cout << std::fixed << std::setprecision(2);
    std::cout << "auto copy price: " << auto_copy.price << '\n';
    std::cout << "auto ref price: " << auto_ref.price << '\n';
    std::cout << "const auto& price: " << readonly_ref.price << '\n';
    std::cout << "auto* points to item id: " << auto_ptr->id << '\n';

    std::cout << "\n== conversion ==\n";

    const int total_cents = 1999;
    const int quantity = 3;

    // 整数除法会丢弃小数部分。
    const int integer_average_cents = total_cents / quantity;

    // static_cast<double> 明确告诉读者和编译器：
    // 这里希望先转换为 double，再做浮点除法。
    const double precise_average_cents =
        static_cast<double>(total_cents) / static_cast<double>(quantity);

    // int 转 double 是常见的数值转换，显式写出可读性更强。
    const double discount_rate = static_cast<double>(15) / 100.0;

    // double 转 int 会丢弃小数部分，这叫窄化转换。
    // 这里故意显式写 static_cast，提醒读者这是有损转换。
    const double raw_price = 19.99;
    const int narrowed_int = static_cast<int>(raw_price);

    std::cout << "integer average cents: " << integer_average_cents << '\n';
    std::cout << std::fixed << std::setprecision(2);
    std::cout << "precise average cents: " << precise_average_cents << '\n';
    std::cout << "discount rate: " << discount_rate << '\n';
    std::cout << "narrowed int: " << narrowed_int << '\n';

    return 0;
}

注意

本文所有可运行代码都避免依赖未定义行为。悬垂指针、悬垂引用、通过 const_cast 修改真正的常量对象、随意使用 reinterpret_cast 等做法会在后文解释风险，但不会让你复制运行。

6. 逐段解释关键代码

6.1 值类型：复制的是值，不是身份

这段代码创建了两个 Item 对象：

Item original{.id = 7, .price = 19.99};

Item copy = original;
copy.price = 29.99;

Item copy = original; 会复制 original 的成员值。复制完成后：

  • original.id 和 copy.id 都是 7 。
  • original.price 仍是 19.99 。
  • copy.price 被改成了 29.99 。
  • 两个对象位于不同地址。

所以 “值相同” 和 “同一个对象” 不是一回事。程序打印的地址可以帮助你观察这一点：

print_address("original address: ", original);
print_address("copy address:     ", copy);

如果你看到两个地址不同，就说明它们是两个独立对象。修改副本不会影响原对象。

注

本文的 Item 是简单值类型。对于持有文件句柄、网络连接、堆内存等资源的类型，复制行为需要额外设计。标准库里的 std::string 、 std::vector 已经封装好了资源管理；自己写资源类型时，要理解构造、析构、复制和移动语义。

6.2 引用：同一个对象的别名

这段代码创建了 original 的引用：

Item& reference = original;
apply_discount(reference, 2.00);

reference 不是新对象，它是 original 的别名。 apply_discount 的参数也是引用：

void apply_discount(Item& item, const double amount) {
    item.price -= amount;
}

调用后， item 、 reference 、 original 都指向同一个对象，所以 original.price 从 19.99 变为 17.99 。

引用有几个重要规则：

  • 引用声明时必须初始化。
  • 普通引用不能绑定到 nullptr 。
  • 引用初始化后不能重新绑定到另一个对象。
  • const Item& 可以只读绑定对象，常用于避免复制。

适合使用引用的场景：

场景写法说明
函数必须修改调用者对象Item&明确表达会修改原对象
函数只读取较大对象const Item&避免复制，禁止误改
小整数、布尔值、枚举按值传递复制成本低，语义简单

6.3 指针：保存地址，也可以为空

指针和引用都能间接访问对象，但指针多了一个关键状态：它可以为空。

Item* maybe_item = nullptr;
add_fee_if_present(maybe_item, 2.01);

函数内部必须先检查：

void add_fee_if_present(Item* item, const double fee) {
    if (item == nullptr) {
        std::cout << "pointer is null, skip update\n";
        return;
    }

    item->price += fee;
}

如果指针不为空，就可以通过 -> 访问对象成员：

Item* item_ptr = &original;
add_fee_if_present(item_ptr, 2.01);

这里的几个符号容易混：

写法出现位置含义
Item* item_ptr类型声明item_ptr 是指向 Item 的指针
&original表达式取得 original 的地址
*item_ptr表达式解引用，访问指针指向的对象
item_ptr->price表达式等价于 (*item_ptr).price

入门阶段可以先按这个规则选：

  • 参数必须有对象：优先用引用。
  • 参数可能没有对象：可以用指针，并检查 nullptr 。
  • 涉及所有权：优先学习 std::unique_ptr 、 std::shared_ptr ，不要一开始就手写 new 和 delete 。

6.4 auto ：看初始化表达式，也看你写没写 & 和 *

auto 不是 “没有类型”，而是让编译器根据初始化表达式推导类型。

const Item const_snapshot = original;

auto auto_copy = const_snapshot;
static_assert(std::is_same_v<decltype(auto_copy), Item>);

这里 auto_copy 的类型是 Item ，不是 const Item 。因为 auto 按值推导时会丢弃顶层 const ，并创建副本。

如果你希望保留引用语义，要写 auto& ：

auto& auto_ref = original;
static_assert(std::is_same_v<decltype(auto_ref), Item&>);

如果你希望只读访问并避免复制，写 const auto& ：

const auto& readonly_ref = original;
static_assert(std::is_same_v<decltype(readonly_ref), const Item&>);

如果初始化表达式是地址，可以写 auto* 明确表达指针：

auto* auto_ptr = &original;
static_assert(std::is_same_v<decltype(auto_ptr), Item*>);

提示

遇到 auto 时，不要只问 “编译器能不能推导”。更重要的是问：我想要复制、引用、只读引用，还是指针？把 & 、 const 、 * 写清楚，代码意图会明确很多。

6.5 类型转换：优先写出意图

这段代码展示了整数除法和浮点除法的差异：

const int total_cents = 1999;
const int quantity = 3;

const int integer_average_cents = total_cents / quantity;

const double precise_average_cents =
    static_cast<double>(total_cents) / static_cast<double>(quantity);

total_cents / quantity 两边都是 int ，结果也是整数，输出 666 。如果想保留小数，需要先把参与运算的值转成 double 。

static_cast<double>(total_cents) 的意义不是 “让代码更复杂”，而是明确告诉读者：这里就是要做数值类型转换。

再看窄化转换：

const double raw_price = 19.99;
const int narrowed_int = static_cast<int>(raw_price);

double 转 int 会丢弃小数部分，结果是 19 。这类转换可能丢信息，应该显式写出来，避免读者误以为没有损失。

C++ 里常见具名转换包括：

转换常见用途入门建议
static_cast<T>(value)数值转换、相关类型之间的明确转换常用，优先掌握
const_cast<T>(value)添加或移除 const / volatile谨慎，通常说明接口设计需要检查
reinterpret_cast<T>(value)重新解释底层位模式或地址高风险，不要跨平台照搬
dynamic_cast<T>(value)多态继承层次中的安全向下转换学到虚函数和继承后再深入

注意

不要用 C 风格强转 (T)value 代替所有转换。它可能退化成多种 C++ 转换的组合，读者很难看出你到底想做数值转换、移除 const ，还是重新解释地址。

7. 背后的原理

7.1 类型决定如何解释内存

对象在内存里是一段存储，但 C++ 不会只把它当成 “字节数组”。类型告诉编译器：

  • 这段存储有多大。
  • 哪些操作合法。
  • 如何调用构造、析构、复制和移动。
  • 表达式结果是值、引用还是指针。

Item 里有一个 int 和一个 double 。你不需要手动计算它占多少字节，也不应该假设它在所有平台上的布局完全一致。编译器可能为了对齐插入填充字节，所以教学代码里不要依赖结构体的二进制布局。

7.2 生命周期决定地址是否还有效

地址本身只是一个值。它是否还能安全使用，取决于指向对象的生命周期是否仍然存在。

错误示例，不要运行：

const Item* dangling = nullptr;

{
    Item local{.id = 1, .price = 9.99};
    dangling = &local;
}

// local 的生命周期已经结束。
// 这里再使用 dangling->price 是未定义行为。

上面的问题不是 “指针变量消失了”，而是它保存的地址指向了一个已经结束生命周期的对象。这类指针叫悬垂指针。

引用也有类似风险：

// 错误示例：不要这样返回局部变量的引用。
const Item& bad_reference() {
    Item local{.id = 1, .price = 9.99};
    return local;
}

local 在函数返回时销毁，返回它的引用会产生悬垂引用。编译器可能给出警告，但不要依赖警告兜底。

7.3 const 是类型的一部分

const Item& 和 Item& 是不同类型：

void read_item(const Item& item);
void update_item(Item& item);

前者表达 “只读访问”，后者表达 “会修改对象”。这不仅是文档，更是编译器能检查的约束。

const_cast 可以移除 const ，但这不代表你可以安全修改任何常量对象：

const Item item{.id = 1, .price = 9.99};

// 错误示例：移除 const 后修改真正的 const 对象，行为未定义。
Item& mutable_item = const_cast<Item&>(item);
mutable_item.price = 1.00;

如果你经常想用 const_cast ，通常应先检查函数签名和对象所有权设计，而不是把它当成常规工具。

7.4 reinterpret_cast 不是可移植序列化方案

reinterpret_cast 可以把一种指针或整数形式重新解释成另一种形式，但它不保证你得到的程序在不同平台、编译器、优化级别下都安全。

不要把下面这种思路当作通用方案：

// 错误方向：不要为了保存对象，就把对象地址或结构体内存随意重解释成字节协议。

如果你要做文件格式、网络协议或跨语言数据交换，应明确字段大小、字节序、对齐和版本，而不是直接依赖 C++ 对象在内存中的私有布局。

8. 常见错误和排查

8.1 忘记指定 C++20

错误可能类似：

error: expected primary-expression before '.' token

排查：

  • CMake 中确认 CXX_STANDARD 20 生效。
  • 手动编译时确认写了 -std=c++20 或 MSVC 的 /std:c++20 。
  • 如果编译器太旧，升级到 GCC 13+、Clang 17+ 或 MSVC 19.36+。

8.2 把副本当成原对象

现象：

auto auto_copy = const_snapshot;
auto_copy.price += 1.00;

你可能以为修改了 const_snapshot ，但实际上修改的是副本。

排查：

  • 如果需要修改原对象，使用 auto& 。
  • 如果只读且避免复制，使用 const auto& 。
  • 对关键代码可以临时打印地址确认是不是同一个对象。

8.3 空指针解引用

错误代码：

Item* item = nullptr;
item->price = 1.00;

可能现象：

Segmentation fault

排查：

  • 使用 -> 或 * 前检查 item == nullptr 。
  • 如果函数不接受空值，把参数改成 Item& 。
  • 如果指针表示所有权，优先考虑智能指针。

8.4 返回局部变量的引用或地址

错误代码：

const Item& make_bad_item() {
    Item item{.id = 1, .price = 9.99};
    return item;
}

排查：

  • 局部变量离开函数就销毁，不能返回它的引用或地址。
  • 如果要返回新对象，直接按值返回： Item make_item() 。
  • 现代 C++ 编译器会优化很多返回值复制，不要过早为了 “省复制” 返回悬垂引用。

8.5 窄化转换导致数据丢失

错误或风险代码：

double price = 19.99;
int cents = price;

排查：

  • 明确是否允许丢失小数。
  • 允许时写 static_cast<int>(price) ，让损失可见。
  • 金额计算不要轻易用浮点数作为最终存储格式，真实业务中通常会用整数分、定点数或专门的十进制库。

4. 核心源码

文件路径： src/main.cpp

// src/main.cpp
// 作用：演示 C++20 中的函数重载、默认参数、inline、函数指针和 lambda。

#include <algorithm>
#include <functional>
#include <iostream>
#include <sstream>
#include <string>

// Product 表示商品。
// price_cents 使用整数“分”保存金额，避免教学示例里出现浮点金额误差。
struct Product {
    std::string name; // 商品名称
    int price_cents;  // 商品单价，单位：分
};

// CartLine 表示购物车中的一行。
// product 保存商品信息，quantity 保存购买数量。
struct CartLine {
    Product product; // 当前行对应的商品
    int quantity;    // 购买数量
};

// inline 函数适合放小而稳定的工具逻辑。
// 如果这个函数未来被放进头文件并被多个 .cpp 包含，inline 可以避免普通函数多重定义。
// 注意：inline 不保证编译器一定把函数调用展开，它首先是一个链接和定义规则相关的说明。
inline int clamp_to_zero(const int value) {
    return std::max(value, 0);
}

// 第一个 format 重载：格式化 Product。
// const Product& 避免复制商品对象，也禁止函数内部修改商品。
std::string format(const Product& product) {
    std::ostringstream output;
    output << product.name << " costs " << product.price_cents << " cents";
    return output.str();
}

// 第二个 format 重载：格式化 CartLine。
// 函数名相同，但参数类型不同，因此构成函数重载。
std::string format(const CartLine& line) {
    std::ostringstream output;
    output << line.product.name << " x " << line.quantity;
    return output.str();
}

// 默认参数写在函数声明或定义的参数列表中。
// 调用 discount_price(price) 时，discount_percent 使用 10，min_price_cents 使用 0。
// 调用 discount_price(price, 20, 500) 时，会覆盖两个默认值。
int discount_price(
    const int price_cents,
    const int discount_percent = 10,
    const int min_price_cents = 0
) {
    const int discounted =
        price_cents * (100 - discount_percent) / 100;

    return std::max(discounted, min_price_cents);
}

// regular_total 是普通计价规则。
// 参数接收一行购物车数据，返回这一行的总价。
int regular_total(const CartLine& line) {
    return line.product.price_cents * line.quantity;
}

// member_total 是会员计价规则。
// 这里复用 discount_price，并显式传入 10% 折扣。
int member_total(const CartLine& line) {
    return discount_price(regular_total(line), 10);
}

// using 给函数指针类型起别名。
// PricingFunction 表示“指向某个函数的指针”，该函数接收 const CartLine&，返回 int。
using PricingFunction = int (*)(const CartLine& line);

// calculate_with_pointer 接收函数指针 rule。
// 调用者可以传 regular_total 或 member_total，函数内部不需要知道具体规则名。
int calculate_with_pointer(
    const CartLine& line,
    PricingFunction rule
) {
    if (rule == nullptr) {
        // 指针可以为空。这里返回 0，让示例保持可运行。
        // 真实项目中也可以选择抛异常、返回错误码，或改用引用/模板避免空规则。
        return 0;
    }

    return rule(line);
}

// std::function 可以保存普通函数、无捕获 lambda、有捕获 lambda 等可调用对象。
// 它比裸函数指针更灵活，适合需要捕获上下文的回调场景。
int calculate_with_callable(
    const CartLine& line,
    const std::function<int(const CartLine&)>& rule
) {
    return rule(line);
}

int main() {
    const Product book{
        .name = "Book",
        .price_cents = 1299,
    };

    const CartLine line{
        .product = book,
        .quantity = 3,
    };

    std::cout << "== product ==\n";

    // 编译器根据参数类型选择 format(const Product&)。
    std::cout << format(book) << '\n';

    // 编译器根据参数类型选择 format(const CartLine&)。
    std::cout << format(line) << '\n';

    std::cout << "\n== discount ==\n";

    // 只传入 price_cents，其余参数使用默认值：10% 折扣、最低价 0。
    std::cout << "10% off: "
              << discount_price(book.price_cents) << " cents\n";

    // 显式传入 discount_percent 和 min_price_cents，覆盖默认参数。
    std::cout << "20% off with floor: "
              << discount_price(book.price_cents, 20, 500) << " cents\n";

    std::cout << "\n== pricing rules ==\n";

    // 函数名 regular_total 在这里会转换为函数指针。
    const int regular =
        calculate_with_pointer(line, regular_total);

    // 同一个 calculate_with_pointer 可以换成 member_total 规则。
    const int member =
        calculate_with_pointer(line, member_total);

    // coupon_cents 是由当前购物车计算出来的运行时数据。
    // 普通函数指针不能捕获它。
    const int coupon_cents = line.quantity * 100;

    // lambda 可以捕获 coupon_cents。
    // [coupon_cents] 表示按值捕获，lambda 内部保存一份 coupon_cents 的副本。
    const auto coupon_rule = [coupon_cents](const CartLine& current_line) {
        return clamp_to_zero(regular_total(current_line) - coupon_cents);
    };

    const int coupon =
        calculate_with_callable(line, coupon_rule);

    // vip_rate 是另一个运行时参数，这里用购物车数量模拟配置计算。
    const int vip_rate = line.quantity + 12;

    // 这个 lambda 同时捕获 vip_rate 和 coupon_cents。
    // 它先计算会员价，再叠加一张优惠券。
    const auto vip_rule = [vip_rate, coupon_cents](const CartLine& current_line) {
        const int base = regular_total(current_line);
        const int discounted = discount_price(base, vip_rate);
        return clamp_to_zero(discounted - coupon_cents);
    };

    const int vip =
        calculate_with_callable(line, vip_rule);

    std::cout << "regular total: " << regular << " cents\n";
    std::cout << "member total:  " << member << " cents\n";
    std::cout << "coupon total:  " << coupon << " cents\n";
    std::cout << "vip total:     " << vip << " cents\n";

    return 0;
}

注意

本文示例没有使用编译器私有 API，也没有依赖标准库内部结构。不要把某个编译器生成的符号名、lambda 闭包对象布局、 std::function 内部存储策略当作稳定公开接口跨版本套用。

8. 逐段解释关键代码

8.1 函数重载：同名函数，不同参数

示例里有两个 format ：

std::string format(const Product& product) {
    std::ostringstream output;
    output << product.name << " costs " << product.price_cents << " cents";
    return output.str();
}

std::string format(const CartLine& line) {
    std::ostringstream output;
    output << line.product.name << " x " << line.quantity;
    return output.str();
}

它们函数名相同，但参数类型不同，因此构成重载。调用时：

std::cout << format(book) << '\n';
std::cout << format(line) << '\n';

编译器会根据实参类型选择候选函数：

  • book 是 Product ，匹配 format(const Product&) 。
  • line 是 CartLine ，匹配 format(const CartLine&) 。

重载时不能只改返回值类型：

// 错误示例：不要这样写。
// int parse(const std::string& text);
// double parse(const std::string& text);

因为调用 parse("12") 时，编译器不能只靠返回值判断你想调用哪个函数。C++ 的重载解析主要看函数名和参数列表。

8.2 默认参数：让常用调用更短

discount_price 的后两个参数有默认值：

int discount_price(
    const int price_cents,
    const int discount_percent = 10,
    const int min_price_cents = 0
) {
    const int discounted =
        price_cents * (100 - discount_percent) / 100;

    return std::max(discounted, min_price_cents);
}

因此可以这样调用：

discount_price(book.price_cents);          // 使用 10 和 0
discount_price(book.price_cents, 20, 500); // 使用 20 和 500

默认参数适合表达 “绝大多数调用都一样，少数调用需要覆盖” 的场景。它也有两个常见规则：

  • 默认参数通常只写在函数声明处。如果函数声明和定义分开，不要在两边重复写默认值。
  • 一旦某个参数有默认值，它右侧的参数通常也必须有默认值。

如果接口已经发布给很多调用者，修改默认参数要谨慎。默认参数是在调用点使用的，旧代码重新编译前可能仍按旧默认值生成调用逻辑。

8.3 inline：不是 “强制内联展开”

示例里的小工具函数：

inline int clamp_to_zero(const int value) {
    return std::max(value, 0);
}

很多人第一次看到 inline ，会把它理解成 “要求编译器把函数体展开到调用处”。这个理解不完整。

现代 C++ 中， inline 更重要的含义是：允许同一个函数定义出现在多个翻译单元中，只要这些定义完全一致。这就是为什么头文件里的小函数、类内定义的成员函数、模板函数经常和 inline 规则相关。

本文把 clamp_to_zero 放在 .cpp 里，严格说不需要 inline 。这里显式写出来，是为了方便你把它移动到头文件时理解规则：

// include/pricing.hpp
inline int clamp_to_zero(const int value) {
    return std::max(value, 0);
}

如果你把普通非 inline 函数定义放进头文件，然后这个头文件被多个 .cpp 包含，链接阶段很容易出现 multiple definition 。

注

编译器是否真的展开函数调用，取决于优化器判断、优化级别、函数复杂度和目标平台。不要把 inline 当成性能开关；先写清晰代码，再用性能分析工具定位瓶颈。

8.4 函数指针：把命名函数当作参数

先看类型别名：

using PricingFunction = int (*)(const CartLine& line);

它表示： PricingFunction 是一个函数指针类型，指向的函数必须满足两个条件：

  • 参数是 const CartLine& 。
  • 返回值是 int 。

所以 regular_total 和 member_total 都符合：

int regular_total(const CartLine& line) {
    return line.product.price_cents * line.quantity;
}

int member_total(const CartLine& line) {
    return discount_price(regular_total(line), 10);
}

接收函数指针的函数如下：

int calculate_with_pointer(
    const CartLine& line,
    PricingFunction rule
) {
    if (rule == nullptr) {
        return 0;
    }

    return rule(line);
}

调用时：

const int regular =
    calculate_with_pointer(line, regular_total);

const int member =
    calculate_with_pointer(line, member_total);

这里的 regular_total 和 member_total 不是立即执行，而是作为规则传入。 calculate_with_pointer 内部再通过 rule(line) 调用它们。

函数指针适合简单、明确、无状态的回调。它不能直接保存 “折扣率”“优惠券金额” 这类运行时状态。

8.5 lambda：就地创建可调用对象

当规则需要捕获运行时数据时，lambda 更自然：

const int coupon_cents = line.quantity * 100;

const auto coupon_rule = [coupon_cents](const CartLine& current_line) {
    return clamp_to_zero(regular_total(current_line) - coupon_cents);
};

这个 lambda 可以拆成四部分看：

部分示例含义
捕获列表[coupon_cents]把外部变量按值保存进 lambda
参数列表(const CartLine& current_line)调用 lambda 时需要传入的参数
函数体{ ... }具体执行逻辑
返回类型省略编译器根据 return 表达式推导为 int

再看 VIP 规则：

const int vip_rate = line.quantity + 12;

const auto vip_rule = [vip_rate, coupon_cents](const CartLine& current_line) {
    const int base = regular_total(current_line);
    const int discounted = discount_price(base, vip_rate);
    return clamp_to_zero(discounted - coupon_cents);
};

它同时捕获 vip_rate 和 coupon_cents 。这类 “临时规则” 如果用普通函数写，通常需要额外设计全局变量、上下文结构体或类；lambda 可以把逻辑和使用位置放得更近。

示例中的 calculate_with_callable 使用 std::function 接收它：

int calculate_with_callable(
    const CartLine& line,
    const std::function<int(const CartLine&)>& rule
) {
    return rule(line);
}

std::function<int(const CartLine&)> 表示：这里需要一个 “可以用 const CartLine& 调用，并返回 int 的东西”。普通函数、无捕获 lambda、有捕获 lambda 都可以放进去。

注意

lambda 的捕获方式会影响生命周期。 [coupon_cents] 是按值捕获，lambda 保存副本； [&coupon_cents] 是按引用捕获，要求被引用的变量在 lambda 调用时仍然活着。不要返回或保存一个引用捕获了局部变量的 lambda，除非你非常清楚对象生命周期。

9. 背后的原理

9.1 函数签名影响重载解析

编译器处理函数调用时，会先收集同名候选函数，再根据实参类型、转换成本、 const 限定等规则挑选最佳匹配。如果没有匹配，会报错；如果多个候选同样好，会报 “调用有歧义”。

例如：

void print(int value);
void print(double value);

print(1);   // 更匹配 int
print(1.5); // 更匹配 double

但下面这种调用可能让人困惑：

void print(long value);
void print(double value);

print(1); // 在某些重载组合下，可能需要仔细分析转换等级

写重载时要避免 “读者和编译器都要猜” 的接口。参数类型差异越清楚，调用越稳定。

9.2 默认参数属于调用接口

默认参数不会生成多个函数。下面这个函数仍然只有一个实现：

int discount_price(int price_cents, int discount_percent = 10);

调用：

discount_price(1000);

可以理解为编译器在调用点补上了默认值：

discount_price(1000, 10);

因此，默认参数更像接口的一部分，而不是函数体内部逻辑。函数声明分散在多个头文件或不同版本库中时，默认值不一致会造成维护问题。

9.3 函数指针只保存入口地址

函数指针保存的是某个函数的入口地址。它能表达 “稍后调用哪个函数”，但不能携带额外状态。

PricingFunction rule = regular_total;
const int total = rule(line);

这也是为什么有捕获 lambda 不能隐式转换成普通函数指针：它除了调用入口，还需要保存捕获的数据。无捕获 lambda 没有额外状态，在合适场景下可以转换为函数指针。

9.4 lambda 是编译器生成的闭包类型

每个 lambda 表达式都会生成一个独一无二的闭包类型。可以把它粗略理解成编译器帮你写了一个带 operator() 的小对象。

这段代码：

const int coupon_cents = 300;

const auto coupon_rule = [coupon_cents](const CartLine& current_line) {
    return regular_total(current_line) - coupon_cents;
};

可以类比为：

// 类比说明，不是编译器必须生成的真实源码。
struct CouponRule {
    int coupon_cents;

    int operator()(const CartLine& current_line) const {
        return regular_total(current_line) - coupon_cents;
    }
};

这只是帮助理解的模型，不是稳定 ABI 或标准要求的对象布局。不同编译器、优化级别和标准库实现都可能有不同细节。

10. 常见错误和排查思路

10.1 重载调用有歧义

错误可能类似：

error: call of overloaded 'print(int)' is ambiguous

排查：

  • 检查同名函数的参数类型是否过于接近。
  • 在调用点显式转换，例如 print(static_cast<long>(value)) 。
  • 重新设计函数名，让不同语义不要勉强挤进同一组重载。

10.2 默认参数重复定义

错误代码：

// pricing.hpp
int discount_price(int price_cents, int discount_percent = 10);

// pricing.cpp
int discount_price(int price_cents, int discount_percent = 10) {
    return price_cents * (100 - discount_percent) / 100;
}

可能报错：

error: default argument given for parameter

排查：

  • 如果声明和定义分开，默认参数通常只写在头文件声明中。
  • .cpp 文件里的定义保留参数名和类型，不重复写默认值。

10.3 把 inline 当成性能保证

现象：

  • 加了 inline ，程序并没有明显变快。
  • 或者没加 inline ，优化构建中函数仍然被编译器展开。

排查：

  • 先确认性能瓶颈是否真的在函数调用开销。
  • 使用优化参数，例如 GCC/Clang 的 -O2 ，再结合 profiler 观察。
  • 把 inline 主要理解为多翻译单元定义规则，不要把它当成强制优化指令。

10.4 函数指针类型不匹配

错误代码：

int wrong_rule(CartLine& line);
calculate_with_pointer(line, wrong_rule);

wrong_rule 接收 CartLine& ，而 PricingFunction 要求 const CartLine& ，类型不一致。

排查：

  • 对照 using PricingFunction = int (*)(const CartLine& line); 。
  • 确认返回值类型和参数类型完全匹配。
  • 如果规则需要捕获状态，改用 lambda 加 std::function ，或进一步学习模板参数。

10.5 lambda 引用捕获导致悬垂引用

错误方向：

std::function<int(const CartLine&)> make_bad_rule() {
    const int coupon_cents = 300;

    // 错误：按引用捕获局部变量。
    return [&coupon_cents](const CartLine& line) {
        return regular_total(line) - coupon_cents;
    };
}

coupon_cents 在函数返回后已经销毁，返回的 lambda 再访问它就是悬垂引用。

排查：

  • 需要把小的配置值保存到 lambda 中时，优先按值捕获： [coupon_cents] 。
  • 只有能保证被引用对象生命周期更长时，才使用引用捕获。
  • 对返回、异步执行、保存到容器里的 lambda，格外检查捕获列表。

12. 小结

可以把本文的重点压缩成一张表：

主题关键判断

默认参数适合常用参数值，属于调用接口，声明和定义分开时不要重复写
inline主要解决多翻译单元中的定义规则，不是强制性能开关
