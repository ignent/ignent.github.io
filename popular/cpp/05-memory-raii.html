C++ 内存管理：栈 / 堆、指针引用、RAII 与移动语义

C++ 的内存管理最容易被讲成一堆名词：栈、堆、指针、引用、生命周期、所有权、RAII、拷贝、移动。真正写项目时，问题通常更具体：

  • 一个对象到底什么时候创建，什么时候销毁？
  • new 出来的内存谁负责释放？
  • 为什么 nullptr 可以检查，悬垂指针却很危险？
  • const T* 、 T* const 、 const T& 到底分别限制了什么？
  • 一个管理堆内存的类为什么要写析构、拷贝构造、移动构造？
  • 头文件里应该放声明还是实现？什么时候可以用前向声明减少依赖？

本文用一个可以直接编译运行的小项目回答这些问题。示例会实现一个 Buffer 类：对象本身可以在栈上或堆上创建，内部使用 RAII 管理一段堆内存；程序会打印构造、析构、拷贝和移动日志，并演示指针、引用、 const 和头文件依赖的常见写法。

目标效果

复现完成后，你应该能看懂一条完整链路：创建栈对象和堆对象，观察对象生命周期，用引用表达 “必须存在的对象”，用指针表达 “可能为空的对象”，用 RAII 自动释放堆内存，再通过拷贝和移动看清所有权如何复制或转移。

1. 运行环境和前置条件

示例使用 C++20，只依赖 C++ 标准库。准备一个支持 C++20 的编译器和 CMake 即可。

推荐环境：

工具建议版本说明
C++ 编译器GCC 13+、Clang 17+ 或 MSVC 19.36+这些版本对本文用到的 C++20 常用语言和标准库能力支持较完整
CMake3.20+用于跨平台生成构建文件；本文使用的 CXX_STANDARD 20 在 CMake 3.12+ 已支持，3.20+ 与前文示例保持一致
操作系统Linux、macOS、Windows 均可构建命令基本一致，Windows 建议使用 Visual Studio 开发者命令行

版本差异提醒：

  • 本文使用 std::unique_ptr<int[]> 、 std::make_unique 、移动构造、 noexcept 和 nullptr ，这些能力从 C++11 起已经稳定；选择 C++20 是为了和本系列前文保持统一。
  • 本文不使用 C++20 modules。模块在不同编译器和构建系统中的细节仍有差异，入门阶段不要把本文的头文件拆分方式直接替换成 modules。
  • 本文不依赖对象二进制布局、虚表布局、栈帧地址或 ABI 细节。不同编译器输出的日志顺序通常一致，但析构日志附近的细节可能因优化、返回值优化和标准库实现略有差异。
  • 指针地址本身没有可移植业务意义，示例不会把地址值作为验证条件。

检查工具版本：

g++ --version
clang++ --version
cmake --version

只需要其中一个 C++ 编译器可用即可。Windows 使用 MSVC 时可运行：

cl
cmake --version

2. 最终目标和运行效果

我们会创建一个名为 memory-raii-lab 的 C++20 小项目。程序运行后会演示这些内容：

  1. Buffer stack_buffer(...) ：对象本身在当前作用域自动创建和销毁。
  2. std::make_unique<Buffer>(...) ：对象本身在堆上创建，由 std::unique_ptr 独占所有权并自动释放。
  3. Buffer 内部用 std::unique_ptr<int[]> 管理一段堆数组，不需要手写 delete[] 。
  4. Buffer& 表示函数必须拿到一个有效对象，并且可以修改它。
  5. const Buffer* 表示函数可能拿不到对象，因此必须检查 nullptr 。
  6. const int* 和 int* const 分别演示 “不能改指向的值” 和 “不能改指针本身”。
  7. 指针运算只在同一个数组范围内进行，避免越界和悬垂指针。
  8. 拷贝构造会复制堆数组，移动构造会转移堆数组所有权。
  9. include guard 和前向声明让头文件依赖更清楚。

预期输出会包含类似内容。析构日志的相邻位置可能因编译器和优化设置略有差异，验证时重点看关键行为是否出现：

验证时重点看：

  • 栈对象 stack_buffer 在 main 结束时自动析构。
  • 堆对象 heap_buffer 不需要手写 delete ， std::unique_ptr 会自动析构它。
  • inspect pointer: nullptr 说明指针可以表达 “没有对象”。
  • copy ctor 说明拷贝创建了独立副本。
  • move ctor 说明移动转移了内部堆数组的所有权。
  • copied after consume 变成 <moved-from> size=0 ，说明被移动后的对象仍然有效，但资源已经被转走。

3. 项目结构

新建一个目录，例如 memory-raii-lab ，文件结构如下：

memory-raii-lab/
├── CMakeLists.txt
├── include/
│   └── memory_raii/
│       ├── buffer.hpp
│       └── report.hpp
└── src/
    ├── buffer.cpp
    ├── main.cpp
    └── report.cpp

各文件职责：

  • CMakeLists.txt ：声明项目名称、C++ 标准、源文件和头文件搜索路径。
  • include/memory_raii/buffer.hpp ：声明 Buffer 类和它的公开接口。
  • include/memory_raii/report.hpp ：通过前向声明减少依赖，只声明报表函数。
  • src/buffer.cpp ：实现 Buffer 的构造、析构、拷贝、移动和数据访问。
  • src/report.cpp ：实现 describe_buffer ，把 Buffer 格式化成可读字符串。
  • src/main.cpp ：程序入口，集中演示栈 / 堆、指针 / 引用、RAII、拷贝 / 移动和 const 。

这个结构故意把类声明和函数实现分开。入门阶段这比单文件稍微麻烦一点，但它能更接近真实项目：头文件提供接口，源文件提供实现，调用方只依赖需要的声明。

4. 关键配置文件

文件路径： CMakeLists.txt

# CMakeLists.txt
# 作用：配置 memory-raii-lab 示例项目。放在项目根目录。

cmake_minimum_required(VERSION 3.20)

# project 声明项目名、版本和语言。
# LANGUAGES CXX 表示这是一个 C++ 项目。
project(memory_raii_lab VERSION 1.0.0 LANGUAGES CXX)

# add_executable 生成一个名为 memory_raii_lab 的可执行文件。
# 这里只列 .cpp 源文件；头文件通过 include 路径被源文件包含。
add_executable(memory_raii_lab
    src/main.cpp
    src/buffer.cpp
    src/report.cpp
)

# CXX_STANDARD 20 要求使用 C++20。
# CXX_STANDARD_REQUIRED ON 表示编译器不支持 C++20 时直接失败。
# CXX_EXTENSIONS OFF 尽量关闭编译器私有扩展，让示例更接近标准 C++。
set_target_properties(memory_raii_lab PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED ON
    CXX_EXTENSIONS OFF
)

# target_include_directories 把 include/ 加入当前目标的头文件搜索路径。
# 这样源文件里才能写 #include "memory_raii/buffer.hpp"。
target_include_directories(memory_raii_lab PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

# target_compile_options 给当前目标添加常用警告。
# GNU、Clang、AppleClang 使用 -Wall -Wextra -Wpedantic。
# MSVC 使用 /W4。
target_compile_options(memory_raii_lab PRIVATE
    $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra -Wpedantic>
    $<$<CXX_COMPILER_ID:MSVC>:/W4>
)

注

CMake 的 CXX_STANDARD 是 “请求某个 C++ 标准” 的目标属性。建议同时设置 CXX_STANDARD_REQUIRED ON ，否则在某些编译器上可能发生标准等级回退。教程项目通常应该让这类问题尽早暴露。

5. 核心源码

5.1 Buffer 头文件：声明拥有堆内存的类

文件路径： include/memory_raii/buffer.hpp

// include/memory_raii/buffer.hpp
// 作用：声明 Buffer 类。调用方 include 这个头文件后，就能创建和使用 Buffer。

#ifndef MEMORY_RAII_BUFFER_HPP
#define MEMORY_RAII_BUFFER_HPP

#include <cstddef> // 使用 std::size_t 表示数组长度和下标。
#include <memory>  // 使用 std::unique_ptr 管理堆数组所有权。
#include <string>  // 使用 std::string 保存 Buffer 名称。

namespace memory_raii {

// Buffer 表示一段拥有独占所有权的整数缓冲区。
// 对象负责在构造时准备资源，在析构时释放资源。
class Buffer {
public:
    // 构造函数：创建一个带名字、固定长度的 Buffer。
    // name 按值接收，函数内部可以通过 std::move 把字符串移动进成员变量。
    // size 表示缓冲区中 int 元素的数量。
    explicit Buffer(std::string name, std::size_t size);

    // 析构函数：对象生命周期结束时自动调用。
    // noexcept 表示析构过程不抛异常；析构函数通常都应该这样设计。
    ~Buffer() noexcept;

    // 拷贝构造函数：用一个已有 Buffer 创建新 Buffer。
    // 这里会分配新的堆数组，并复制每个元素。
    Buffer(const Buffer& other);

    // 拷贝赋值运算符：处理“已有对象 = 另一个对象”的场景。
    // 返回 Buffer& 可以支持 a = b = c 这样的链式赋值。
    Buffer& operator=(const Buffer& other);

    // 移动构造函数：从一个将亡值或显式 std::move 的对象接管资源。
    // noexcept 有助于标准容器在扩容时优先使用移动操作。
    Buffer(Buffer&& other) noexcept;

    // 移动赋值运算符：处理“已有对象 = 即将被移动的对象”的场景。
    Buffer& operator=(Buffer&& other) noexcept;

    // fill 把缓冲区填成 start、start + 1、start + 2 ...
    // 这个函数会修改对象，所以不能声明为 const。
    void fill(int start);

    // set 修改指定下标处的值。
    // index 是要写入的位置，value 是新值。
    void set(std::size_t index, int value);

    // at 读取指定下标处的值。
    // 函数末尾的 const 表示不会修改当前 Buffer。
    int at(std::size_t index) const;

    // size 返回元素数量。
    // noexcept 表示读取长度不会抛异常。
    std::size_t size() const noexcept;

    // name 返回名称的只读引用，避免复制字符串。
    const std::string& name() const noexcept;

    // rename 修改名称。
    // new_name 按值接收，方便调用方传入左值或右值字符串。
    void rename(std::string new_name);

    // data 返回原始指针，方便演示指针运算。
    // 返回 int* 的版本允许调用方修改元素。
    int* data() noexcept;

    // data 的 const 重载返回 const int*。
    // 调用方只能读取元素，不能通过这个指针修改元素。
    const int* data() const noexcept;

private:
    // check_index 统一检查下标范围。
    // 私有函数只给成员函数内部使用。
    void check_index(std::size_t index) const;

    std::string name_;             // Buffer 名称，用于日志和输出。
    std::size_t size_ = 0;         // 当前元素数量，0 表示没有元素。
    std::unique_ptr<int[]> data_;  // 独占拥有的堆数组，析构时自动 delete[]。
};

} // namespace memory_raii

#endif // MEMORY_RAII_BUFFER_HPP

这里使用传统 include guard：

#ifndef MEMORY_RAII_BUFFER_HPP
#define MEMORY_RAII_BUFFER_HPP
// 头文件内容
#endif

它的作用是防止同一个头文件在同一个翻译单元里被重复包含。 #pragma once 在主流编译器中也很常见，但它不是 ISO C++ 标准语法；写教程和跨平台基础库时，include guard 更保守。

5.2 报表头文件：用前向声明减少依赖

文件路径： include/memory_raii/report.hpp

// include/memory_raii/report.hpp
// 作用：声明报表函数。这个头文件只需要知道“存在一个 Buffer 类”。

#ifndef MEMORY_RAII_REPORT_HPP
#define MEMORY_RAII_REPORT_HPP

#include <string> // describe_buffer 返回 std::string，所以必须包含 <string>。

namespace memory_raii {

// 前向声明：告诉编译器 memory_raii 命名空间里有一个 Buffer 类。
// 这里不需要知道 Buffer 有哪些成员，因为函数参数只是 const Buffer&。
class Buffer;

// describe_buffer 把 Buffer 格式化成一行文本。
// const Buffer& 表示只读引用：不复制 Buffer，也不修改 Buffer。
std::string describe_buffer(const Buffer& buffer);

} // namespace memory_raii

#endif // MEMORY_RAII_REPORT_HPP

report.hpp 没有 #include "memory_raii/buffer.hpp" ，而是只写了 class Buffer; 。这就是前向声明。

前向声明适合这种场景：头文件只需要声明 “某个函数接收 Buffer& 、 Buffer* 、 const Buffer& ”，不需要访问 Buffer 的成员。真正实现函数时， report.cpp 必须包含 buffer.hpp ，因为实现里要调用 buffer.name() 、 buffer.size() 、 buffer.data() 。

5.3 Buffer 实现：用 RAII 管理堆数组

文件路径： src/buffer.cpp

// src/buffer.cpp
// 作用：实现 Buffer 的资源申请、释放、拷贝、移动和数据访问。

#include "memory_raii/buffer.hpp"

#include <algorithm>  // 使用 std::copy_n 复制数组元素。
#include <iostream>   // 使用 std::cout 打印生命周期日志。
#include <stdexcept>  // 使用 std::out_of_range 报告下标越界。
#include <utility>    // 使用 std::move 移动字符串和 unique_ptr。

namespace memory_raii {

namespace {

// allocate_ints 是当前 .cpp 内部使用的辅助函数。
// unnamed namespace 让它只在本文件可见，避免污染外部接口。
std::unique_ptr<int[]> allocate_ints(std::size_t size) {
    // size 为 0 时，不需要分配堆数组，返回空 unique_ptr。
    if (size == 0) {
        return nullptr;
    }

    // make_unique<int[]> 分配一段 int 数组，并交给 unique_ptr 独占管理。
    // 以后 unique_ptr 析构时会自动执行 delete[]。
    auto data = std::make_unique<int[]>(size);

    // 把数组初始化为 0，避免读取未初始化值。
    for (std::size_t index = 0; index < size; ++index) {
        data[index] = 0;
    }

    // 返回 unique_ptr 会发生移动，所有权从局部变量转交给调用方。
    return data;
}

} // namespace

Buffer::Buffer(std::string name, std::size_t size)
    : name_(std::move(name)), size_(size), data_(allocate_ints(size)) {
    std::cout << "[ctor] " << name_ << " size=" << size_ << '\n';
}

Buffer::~Buffer() noexcept {
    std::cout << "[dtor] " << name_ << " size=" << size_ << '\n';
}

Buffer::Buffer(const Buffer& other)
    : name_(other.name_ + "_copy"),
      size_(other.size_),
      data_(allocate_ints(other.size_)) {
    // 如果 other.size_ 为 0，data_ 为空，循环自然不会执行。
    for (std::size_t index = 0; index < size_; ++index) {
        data_[index] = other.data_[index];
    }

    std::cout << "[copy ctor] from " << other.name_
              << " to " << name_ << '\n';
}

Buffer& Buffer::operator=(const Buffer& other) {
    // 自赋值保护：处理 buffer = buffer; 这种情况。
    if (this == &other) {
        return *this;
    }

    // 先分配新资源并完成复制。
    // 如果这里抛异常，当前对象还没有被修改。
    auto copied_data = allocate_ints(other.size_);
    for (std::size_t index = 0; index < other.size_; ++index) {
        copied_data[index] = other.data_[index];
    }

    // 新资源准备好以后，再替换当前对象的状态。
    // 旧的 data_ 会在 unique_ptr 被赋新值时自动释放。
    name_ = other.name_ + "_assigned";
    size_ = other.size_;
    data_ = std::move(copied_data);

    std::cout << "[copy assign] from " << other.name_
              << " to " << name_ << '\n';
    return *this;
}

Buffer::Buffer(Buffer&& other) noexcept
    : name_(std::move(other.name_)),
      size_(other.size_),
      data_(std::move(other.data_)) {
    std::cout << "[move ctor] new object takes " << name_ << '\n';

    // 被移动后的对象仍然必须保持“可析构、可赋值”的有效状态。
    other.name_ = "<moved-from>";
    other.size_ = 0;
}

Buffer& Buffer::operator=(Buffer&& other) noexcept {
    // 自移动虽然少见，但写库代码时仍应让它保持安全。
    if (this == &other) {
        return *this;
    }

    // std::move 把 other 的字符串和堆数组所有权转移给当前对象。
    name_ = std::move(other.name_);
    size_ = other.size_;
    data_ = std::move(other.data_);

    std::cout << "[move assign] current object takes " << name_ << '\n';

    // 让来源对象处于有效但不再拥有资源的状态。
    other.name_ = "<moved-from>";
    other.size_ = 0;

    return *this;
}

void Buffer::fill(int start) {
    // 按下标写入 start、start + 1、start + 2 ...
    for (std::size_t index = 0; index < size_; ++index) {
        data_[index] = start + static_cast<int>(index);
    }
}

void Buffer::set(std::size_t index, int value) {
    // 先检查下标，避免写出数组边界。
    check_index(index);
    data_[index] = value;
}

int Buffer::at(std::size_t index) const {
    // const 成员函数可以读取成员，但不能修改成员。
    check_index(index);
    return data_[index];
}

std::size_t Buffer::size() const noexcept {
    return size_;
}

const std::string& Buffer::name() const noexcept {
    return name_;
}

void Buffer::rename(std::string new_name) {
    name_ = std::move(new_name);
}

int* Buffer::data() noexcept {
    return data_.get();
}

const int* Buffer::data() const noexcept {
    return data_.get();
}

void Buffer::check_index(std::size_t index) const {
    if (index >= size_) {
        throw std::out_of_range("Buffer index is out of range");
    }
}

} // namespace memory_raii

这段代码的关键点是： Buffer 拥有资源，但它没有直接保存裸指针 int* ，而是保存 std::unique_ptr<int[]> 。这样析构时不需要手写 delete[] ，拷贝和移动逻辑也更清楚。

注意

本文为了教学手写了拷贝构造和移动构造。真实项目里，如果可以直接用 std::vector<int> 表示动态数组，通常更推荐 std::vector<int> ，让标准库替你实现资源管理。这叫 “Rule of Zero”：能不手写析构、拷贝、移动，就不要手写。

5.4 报表实现：安全地做指针运算

文件路径： src/report.cpp

// src/report.cpp
// 作用：实现 describe_buffer，把 Buffer 内容转换成一行可读文本。

#include "memory_raii/report.hpp"

#include "memory_raii/buffer.hpp" // 实现函数时需要访问 Buffer 的成员函数。

#include <sstream> // 使用 std::ostringstream 拼接字符串。

namespace memory_raii {

std::string describe_buffer(const Buffer& buffer) {
    // ostringstream 适合把多个值逐步拼成一个 std::string。
    std::ostringstream output;

    // 读取 Buffer 的名称和长度。这里通过 const 引用读取，不会复制 Buffer。
    output << buffer.name() << " size=" << buffer.size() << " values=[";

    // data 返回数组首元素指针。
    // 因为 buffer 是 const Buffer&，这里调用的是 const int* data() const。
    const int* begin = buffer.data();

    // 指针运算只允许在同一个数组内部或末尾后一位进行。
    // begin + buffer.size() 表示“末尾后一位”，只能用于比较，不能解引用。
    const int* end = begin + buffer.size();

    // cursor 从 begin 走到 end，每次 ++cursor 前进一个 int 元素。
    for (const int* cursor = begin; cursor != end; ++cursor) {
        // cursor - begin 得到当前指针相对首元素的偏移量。
        if (cursor != begin) {
            output << ", ";
        }

        // *cursor 读取当前元素。这里没有越界，因为 cursor 始终小于 end。
        output << *cursor;
    }

    output << "]";
    return output.str();
}

} // namespace memory_raii

指针运算不是 “拿地址当整数随便加减”。在标准 C++ 中，安全前提是：参与运算的指针指向同一个数组中的元素，或者指向这个数组末尾后一位。 end 可以用于比较，但不能解引用。

5.5 程序入口：把内存、指针、引用、const、拷贝和移动串起来

文件路径： src/main.cpp

// src/main.cpp
// 作用：演示栈/堆、对象生命周期、所有权、指针、引用、const、RAII、拷贝和移动。

#include "memory_raii/buffer.hpp"
#include "memory_raii/report.hpp"

#include <iostream> // 使用 std::cout 输出验证信息。
#include <memory>   // 使用 std::make_unique 创建堆对象。
#include <utility>  // 使用 std::move 把左值显式转换成将亡值。

namespace {

// update_first_by_reference 使用非 const 引用接收 Buffer。
// 引用参数表达：调用方必须提供一个有效对象，函数内部会修改它。
void update_first_by_reference(memory_raii::Buffer& buffer) {
    // at(0) 读取第一个元素，set(0, ...) 写回第一个元素。
    const int old_value = buffer.at(0);
    buffer.set(0, old_value + 100);
}

// inspect_by_pointer 使用指针接收 Buffer。
// 指针参数表达：调用方可以传入 nullptr，函数必须先检查。
void inspect_by_pointer(const memory_raii::Buffer* buffer) {
    if (buffer == nullptr) {
        std::cout << "inspect pointer: nullptr\n";
        return;
    }

    // buffer 是指针，需要用 *buffer 得到它指向的对象。
    std::cout << "inspect pointer: "
              << memory_raii::describe_buffer(*buffer) << '\n';
}

// print_pointer_arithmetic 演示只在同一个数组范围内做指针运算。
void print_pointer_arithmetic(const memory_raii::Buffer& buffer) {
    const int* begin = buffer.data();
    const int* end = begin + buffer.size();

    for (const int* cursor = begin; cursor != end; ++cursor) {
        std::cout << "offset=" << (cursor - begin)
                  << " value=" << *cursor << '\n';
    }
}

// consume_buffer 接收右值引用 Buffer&&。
// 它表达：调用方同意这个函数“拿走”传入对象里的资源。
void consume_buffer(memory_raii::Buffer&& buffer) {
    std::cout << "[consume] rvalue reference received: "
              << buffer.name() << '\n';

    // 注意：buffer 虽然类型是 Buffer&&，但它有名字，所以在函数体内是左值。
    // 需要再次 std::move(buffer)，才会真正调用移动构造函数。
    memory_raii::Buffer local = std::move(buffer);

    // 移动后 local 拥有原来的堆数组，可以继续改名和读取。
    local.rename("consumed-buffer");
    std::cout << "inside consume: "
              << memory_raii::describe_buffer(local) << '\n';

    // 函数结束时 local 自动析构，内部堆数组也会自动释放。
}

} // namespace

int main() {
    using memory_raii::Buffer;
    using memory_raii::describe_buffer;

    std::cout << "== stack and heap ==\n";

    // stack_buffer 是自动存储期对象。
    // 它在当前作用域创建，在 main 返回前自动析构。
    Buffer stack_buffer("stack-buffer", 3);
    stack_buffer.fill(10);

    // heap_buffer 是 unique_ptr，独占管理一个堆上的 Buffer 对象。
    // make_unique 内部执行 new，unique_ptr 析构时自动执行 delete。
    auto heap_buffer = std::make_unique<Buffer>("heap-buffer", 2);
    heap_buffer->fill(40);

    std::cout << describe_buffer(stack_buffer) << '\n';
    std::cout << describe_buffer(*heap_buffer) << '\n';

    std::cout << "\n== reference, pointer and const ==\n";

    // 引用适合表达“必须存在，且函数要修改它”。
    update_first_by_reference(stack_buffer);
    std::cout << "after reference update: "
              << describe_buffer(stack_buffer) << '\n';

    // 指针适合表达“可能没有对象”。
    inspect_by_pointer(&stack_buffer);
    inspect_by_pointer(nullptr);

    // const Buffer& 是只读引用。
    // 通过 readonly 可以调用 const 成员函数 at、size、name、data。
    const Buffer& readonly = stack_buffer;
    std::cout << "const Buffer& first value=" << readonly.at(0) << '\n';

    // const int* 表示“指向 const int 的指针”。
    // 可以让 pointer_to_const 改指向，但不能通过它修改 *pointer_to_const。
    const int* pointer_to_const = stack_buffer.data();
    std::cout << "const int* points to value="
              << *pointer_to_const << '\n';

    // int* const 表示“const 指针，指向 int”。
    // const_pointer 必须初始化，之后不能改指向，但可以修改它指向的 int。
    int* const const_pointer = stack_buffer.data();
    *const_pointer = *const_pointer; // 这里不改变值，只演示它可以写入。
    std::cout << "int* const still points to first value="
              << *const_pointer << '\n';

    std::cout << "\n== pointer arithmetic ==\n";
    print_pointer_arithmetic(stack_buffer);

    std::cout << "\n== copy and move ==\n";

    // 拷贝构造：copied 拥有一份独立堆数组。
    Buffer copied = stack_buffer;
    std::cout << "copied: " << describe_buffer(copied) << '\n';

    // 拷贝赋值：assigned 原本已有资源，赋值后变成 copied 的副本。
    Buffer assigned("assigned", 1);
    assigned = copied;
    std::cout << "assigned: " << describe_buffer(assigned) << '\n';

    // std::move(copied) 不移动任何数据，它只是把 copied 转成将亡值表达式。
    // 真正的资源转移发生在 consume_buffer 内部的移动构造函数中。
    consume_buffer(std::move(copied));

    // 被移动后的对象仍然有效，可以析构、可以重新赋值，也可以查询状态。
    std::cout << "copied after consume: "
              << describe_buffer(copied) << '\n';

    std::cout << "\n== end of main ==\n";
    return 0;
}
为什么没有演示野指针和悬垂指针的 “运行效果”？

野指针和悬垂指针一旦被解引用，行为通常是未定义行为：它可能崩溃，也可能看起来能跑，也可能在别的地方埋下错误。教程不应该让读者把未定义行为当成可复现输出。

下面代码只用于识别错误形态，不要放进示例里运行：

int* wild;          // 错误：未初始化的野指针，值不确定。
// *wild = 1;       // 未定义行为。

int* dangling = nullptr;
{
    int local = 42;
    dangling = &local; // local 的生命周期只到这个作用域结束。
}
// std::cout << *dangling; // 错误：dangling 指向已经销毁的对象。

7. 按流程理解这段程序

7.1 整体流程

程序可以按这条线读：

  1. main.cpp 创建 stack_buffer ，它是栈上对象，离开 main 自动析构。
  2. main.cpp 创建 heap_buffer ，它是 std::unique_ptr<Buffer> 管理的堆对象，不需要手写 delete 。
  3. Buffer 构造函数分配内部堆数组，析构函数在对象生命周期结束时打印日志。
  4. update_first_by_reference 用 Buffer& 修改第一个元素。
  5. inspect_by_pointer 用 const Buffer* 接收可选对象，并显式处理 nullptr 。
  6. print_pointer_arithmetic 只在同一个数组 [begin, end) 范围内移动指针。
  7. Buffer copied = stack_buffer 触发拷贝构造，创建独立资源。
  8. assigned = copied 触发拷贝赋值，替换已有资源。
  9. consume_buffer(std::move(copied)) 触发右值引用和移动构造，资源从 copied 转移到局部对象。
  10. main 结束，局部对象按构造的相反顺序析构。

7.2 栈和堆不是 “快和慢” 这么简单

在示例里：

Buffer stack_buffer("stack-buffer", 3);

stack_buffer 这个对象本身是自动存储期对象。它的生命周期由作用域控制：进入作用域构造，离开作用域析构。

但 Buffer 内部还有：

std::unique_ptr<int[]> data_;

这个成员管理的是堆数组。也就是说，“对象在栈上” 并不代表它所有数据都在栈上。很多 C++ 对象本身在栈上，但内部拥有堆资源，例如 std::string 、 std::vector 、本文的 Buffer 。

堆对象示例是：

auto heap_buffer = std::make_unique<Buffer>("heap-buffer", 2);

这里 Buffer 对象本身在堆上，所有权由 std::unique_ptr<Buffer> 表达。不要写成：

Buffer* buffer = new Buffer("heap-buffer", 2);
// 中间任何 return 或 throw 都可能让 delete 被漏掉。
delete buffer;

入门阶段的默认规则可以很简单：

  • 能放在作用域里的对象，优先直接声明局部变量。
  • 需要动态生命周期或多态所有权时，优先用 std::unique_ptr 或 std::shared_ptr 表达所有权。
  • 不要用裸指针表达所有权转移。

7.3 RAII：把资源交给对象生命周期管理

RAII 的核心不是 “某个库”，而是一种写法：

  1. 构造函数获取资源。
  2. 对象保持资源可用。
  3. 析构函数释放资源。
  4. 作用域结束、异常退出、提前 return 时，已经构造成功的局部对象都会析构。

本文的资源获取在这里：

auto data = std::make_unique<int[]>(size);

释放动作没有出现在业务代码里，因为 std::unique_ptr<int[]> 的析构函数会自动释放数组。 Buffer 的析构函数只打印日志：

Buffer::~Buffer() noexcept {
    std::cout << "[dtor] " << name_ << " size=" << size_ << '\n';
}

真正释放内部数组的是成员 data_ 的析构。C++ 析构顺序是：先执行 Buffer::~Buffer() 的函数体，再按成员声明的相反顺序析构成员。因此 data_ 会在 Buffer 对象销毁过程中自动释放。

7.4 指针和引用的选择

示例里用引用修改对象：

void update_first_by_reference(memory_raii::Buffer& buffer)

Buffer& 的含义是：调用方必须提供一个有效对象。函数体里不用判断 nullptr ，并且函数名和参数类型都表达了 “会修改传入对象”。

示例里用指针表达可选对象：

void inspect_by_pointer(const memory_raii::Buffer* buffer)

const Buffer* 的含义是：可以没有对象，所以函数必须检查：

if (buffer == nullptr) {
    std::cout << "inspect pointer: nullptr\n";
    return;
}

一个实用判断：

  • 参数必须存在：用引用。
  • 参数可以为空：用指针或 std::optional 。
  • 函数要拥有对象：用值、 std::unique_ptr 或 std::shared_ptr ，不要用裸指针偷传所有权。

7.5 空指针、悬垂指针和野指针

三者不要混在一起：

名称典型形态能否安全检查主要风险
空指针Buffer* p = nullptr;可以用 p == nullptr 检查忘记检查后解引用
悬垂指针指向已经销毁的对象通常无法可靠检查读写已经失效的内存
野指针未初始化指针通常无法可靠检查指向不确定位置

正确写法是让指针尽量少活一会儿：

const int* begin = buffer.data();
const int* end = begin + buffer.size();

for (const int* cursor = begin; cursor != end; ++cursor) {
    std::cout << *cursor << '\n';
}

begin 、 end 、 cursor 都只在函数内部使用，不保存到全局变量，也不在 buffer 销毁后继续使用。

7.6 指针运算的安全边界

这一句是合法的：

const int* end = begin + buffer.size();

因为 end 指向同一个数组末尾后一位。末尾后一位可以用于比较：

cursor != end

但不能解引用：

// 错误：end 是末尾后一位，不是有效元素。
// std::cout << *end;

也不要把两个不同数组的指针相减：

// 错误：left 和 right 如果来自不同数组，left - right 没有可移植意义。
// auto distance = left - right;

如果你在真实项目里只是遍历容器，优先使用范围 for 、迭代器或 std::span 。本文使用原始指针运算，是为了把底层规则讲清楚。

7.7 拷贝语义：复制资源，而不是共享裸地址

拷贝构造函数是：

Buffer::Buffer(const Buffer& other)
    : name_(other.name_ + "_copy"),
      size_(other.size_),
      data_(allocate_ints(other.size_)) {
    for (std::size_t index = 0; index < size_; ++index) {
        data_[index] = other.data_[index];
    }
}

为什么不能直接复制 data_ 里的裸地址？因为两个对象如果指向同一段堆数组，就会出现两个严重问题：

  1. 一个对象修改数组，另一个对象也被影响，语义不清楚。
  2. 两个对象析构时都尝试释放同一段内存，会导致重复释放。

std::unique_ptr 从类型层面禁止拷贝，所以编译器会逼你想清楚：这个类到底要不要支持拷贝？本文选择支持拷贝，于是手写 “分配新数组并复制元素” 的深拷贝。

7.8 移动语义：转移所有权

移动构造函数是：

Buffer::Buffer(Buffer&& other) noexcept
    : name_(std::move(other.name_)),
      size_(other.size_),
      data_(std::move(other.data_)) {
    other.name_ = "<moved-from>";
    other.size_ = 0;
}

这里的重点是 std::move(other.data_) 。它把 other.data_ 管理的堆数组所有权转移给新对象。转移后， other.data_ 变为空，不再负责释放那段数组。

std::move 这个名字容易误导。它本身不移动内存，也不复制字节；它只是把一个表达式转换成 “可以被移动” 的值类别。真正执行移动逻辑的是移动构造函数或移动赋值运算符。

右值引用参数示例是：

void consume_buffer(memory_raii::Buffer&& buffer)

函数内部仍然要写：

memory_raii::Buffer local = std::move(buffer);

原因是： buffer 虽然类型是 Buffer&& ，但它有名字；有名字的变量表达式是左值。要触发移动构造，仍然需要 std::move(buffer) 。

7.9 const 正确性：读法从右往左更稳

示例里出现了三种常见写法。

第一种：

const int* pointer_to_const = stack_buffer.data();

它也可以写作：

int const* pointer_to_const = stack_buffer.data();

含义是：指针可以改指向，但不能通过这个指针修改它指向的 int 。

第二种：

int* const const_pointer = stack_buffer.data();

含义是：指针本身是 const，初始化后不能改指向；但它指向的是 int ，所以可以通过它修改元素。

第三种：

const Buffer& readonly = stack_buffer;

含义是： readonly 是一个只读引用，不能通过它调用非 const 成员函数，例如 fill 、 set 、 rename 。

对成员函数来说：

int at(std::size_t index) const;

末尾的 const 表示这个函数不会修改当前对象。这样 const Buffer& 才能调用它。

一个简单表格：

写法含义能否改指向能否改对象
const T* p指向 const T 的指针可以不可以通过 p 改
T* const p指向 T 的 const 指针不可以可以通过 p 改
const T& rT 的只读引用引用本来不能换绑不可以通过 r 改

7.10 头文件依赖：声明、定义和前向声明

buffer.hpp 中放的是类声明：

class Buffer {
public:
    explicit Buffer(std::string name, std::size_t size);
    ~Buffer() noexcept;
    Buffer(const Buffer& other);
    Buffer& operator=(const Buffer& other);
    Buffer(Buffer&& other) noexcept;
    Buffer& operator=(Buffer&& other) noexcept;
};

这些声明告诉调用方： Buffer 有哪些构造函数、成员函数和数据访问能力。函数体放在 buffer.cpp ，这样调用方不需要重新编译所有实现细节。

report.hpp 中只写：

class Buffer;
std::string describe_buffer(const Buffer& buffer);

这说明 “声明一个接收 const Buffer& 的函数” 不需要知道 Buffer 的完整定义。但 report.cpp 里要调用 buffer.name() ，所以必须包含完整定义：

#include "memory_raii/buffer.hpp"

常见判断规则：

  • 需要创建对象、访问成员、继承类、按值传参或按值返回：需要完整定义。
  • 只声明指针或引用参数：通常可以前向声明。
  • 头文件里用到了某个标准库类型作为成员，例如 std::string name_ ：必须包含对应头文件，不能只靠调用方碰巧包含。

8. 常见错误和排查思路

8.1 编译报找不到头文件

典型错误：

fatal error: memory_raii/buffer.hpp: No such file or directory

排查：

  • 确认文件路径是 include/memory_raii/buffer.hpp 。
  • 确认 CMake 中有 target_include_directories(memory_raii_lab PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/include) 。
  • 如果直接用命令行编译，确认带了 -I include 或 MSVC 的 /I include 。

8.2 链接时报 undefined reference 或 unresolved external symbol

典型原因是只编译了 src/main.cpp ，忘记编译 src/buffer.cpp 和 src/report.cpp 。

排查：

  • CMake 中确认 add_executable 列出了三个源文件。
  • 直接编译时确认命令包含：
src/main.cpp src/buffer.cpp src/report.cpp

8.3 std::move 后继续假设原对象还有原数据

示例中：

consume_buffer(std::move(copied));

之后 copied 仍然是一个有效对象，但它的内部数组已经被转移。你可以析构它、重新赋值给它、查询它的状态，但不要继续假设它还保存原来的数据。

排查原则：

  • 被移动后的对象只要求 “有效但状态未指定”。
  • 如果业务还需要原数据，就不要对它 std::move 。
  • 如果移动后要复用，先给它重新赋一个明确的新值。

8.4 指针越界没有立刻崩溃

错误示例：

const int* end = buffer.data() + buffer.size();
std::cout << *end << '\n'; // 错误：end 不能解引用。

这类错误不一定每次崩溃。它属于未定义行为，不能用 “我这里能跑” 来证明正确。

排查：

  • 遍历时使用 [begin, end) 半开区间。
  • 指针等于 end 时停止，不要解引用。
  • 可以开启 AddressSanitizer 辅助排查：
g++ -std=c++20 -fsanitize=address,undefined -fno-omit-frame-pointer \
  -I include \
  src/main.cpp src/buffer.cpp src/report.cpp \
  -o memory_raii_lab_asan

./memory_raii_lab_asan

MSVC 可在支持的版本中使用 AddressSanitizer 选项；不同 Visual Studio 版本和工程类型支持细节可能不同，按 Microsoft 文档调整。

8.5 把 const 当成 “绝对不可变”

const int* 只限制 “不能通过这个指针修改值”。如果同一个对象还有非 const 访问路径，值仍可能被改。

示例中：

const int* pointer_to_const = stack_buffer.data();
int* const const_pointer = stack_buffer.data();

pointer_to_const 不能写入，但 const_pointer 可以写入同一个首元素。 const 正确性的意义是让接口表达意图、让编译器阻止误用，不是给对象加物理锁。

9. 小结

这篇文章用一个 Buffer 小项目串起了 C++ 内存管理里最容易混淆的几组概念：

  • 栈对象由作用域管理生命周期；堆对象需要明确所有权，优先交给智能指针。
  • RAII 把资源申请和释放绑定到对象生命周期，减少泄漏和重复释放。
  • 引用适合表达 “必须存在”，指针适合表达 “可能为空”。
  • 空指针可以检查；悬垂指针和野指针通常无法可靠检查，应该通过设计避免。
  • 指针运算只能在同一个数组范围内安全进行。
  • 管理资源的类要认真处理拷贝和移动；能用标准库容器时优先遵守 Rule of Zero。
  • const T* 、 T* const 、 const T& 分别限制不同层面的修改。
  • 头文件里放接口声明，源文件里放实现；只需要指针或引用声明时，可以用前向声明降低依赖。
