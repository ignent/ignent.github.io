Android NDK JNI 实战：Kotlin 调 C++、C++ 回调 Kotlin 与常用 native 库

Android NDK 和 JNI 很容易被讲成一堆概念： JNIEnv 、 jobject 、 FindClass 、 AttachCurrentThread 、 GetStringUTFChars 。这些名字看起来吓人，但真正写项目时，它们解决的是几个很具体的问题：

  • Kotlin 怎么调用 C++ 函数？
  • C++ 怎么把结果返回给 Kotlin？
  • C++ 怎么访问 Kotlin 的 String 、 IntArray 、对象和回调接口？
  • native 线程想调用 Kotlin 方法时，为什么必须先附加到 JVM？
  • NDK 里的 log 、 android 、 jnigraphics 、AAudio、OpenSL ES、OpenGL ES、Vulkan 这些库在 CMake 里怎么链接？

本文用一个可以直接复现的小项目回答这些问题。项目会做三件事：

  1. Kotlin 调用 C++，传入 String 和 IntArray ，C++ 返回 Kotlin 数据类 NativeResult 。
  2. C++ 使用 libjnigraphics 直接修改 Bitmap 像素，把图片颜色反转。
  3. C++ 创建后台线程，先 AttachCurrentThread ，再通过 JNI 回调 Kotlin 接口方法。

目标效果

运行后，页面上会显示 native 汇总结果、常用 NDK 库探测信息、Bitmap 处理结果，以及 native 后台线程回调 Kotlin 的日志。logcat 中也能看到 C++ 侧通过 __android_log_print 打出的日志。

6.1 JNI 边界：NativeBridge.kt

文件路径： app/src/main/java/com/example/jnilab/NativeBridge.kt

// app/src/main/java/com/example/jnilab/NativeBridge.kt
// 作用：声明 Kotlin 调 C++ 的 native 方法，以及 C++ 回调 Kotlin 的接口。

package com.example.jnilab

import android.graphics.Bitmap

// NativeResult 是 C++ 返回给 Kotlin 的数据类。
// C++ 会通过 FindClass + GetMethodID("<init>") + NewObject 创建它。
data class NativeResult(
    val message: String, // C++ 生成的说明文本
    val sum: Int,        // C++ 从 IntArray 计算得到的和
)

// NativeCallback 是 C++ 回调 Kotlin 的接口。
// C++ 会通过 GetObjectClass + GetMethodID + CallVoidMethod 调用这两个方法。
interface NativeCallback {
    fun onNativeProgress(step: Int, message: String)
    fun onNativeError(message: String)
}

// object 表示单例。这里用它集中放 native 方法。
object NativeBridge {
    init {
        // System.loadLibrary("jnilab") 会加载 libjnilab.so。
        // 库名必须和 CMake add_library(jnilab SHARED ...) 中的 jnilab 对上。
        System.loadLibrary("jnilab")
    }

    // Kotlin 调 C++：
    // String 会以 jstring 传到 C++。
    // IntArray 会以 jintArray 传到 C++。
    // NativeResult 会以 jobject 从 C++ 返回。
    external fun summarize(name: String, scores: IntArray): NativeResult

    // Bitmap 会以 jobject 传到 C++。
    // C++ 使用 AndroidBitmap_getInfo / lockPixels / unlockPixels 修改像素。
    external fun invertBitmap(bitmap: Bitmap): Boolean

    // C++ 会启动 native 后台线程，并通过 callback 回调 Kotlin。
    external fun runCallbackDemo(callback: NativeCallback)

    // 返回 native 常用库的探测信息，验证 CMake 链接和头文件 include。
    external fun commonLibrarySummary(): String
}

6.2 页面和验证逻辑：MainActivity.kt

文件路径： app/src/main/java/com/example/jnilab/MainActivity.kt

// app/src/main/java/com/example/jnilab/MainActivity.kt
// 作用：构造一个最小页面，触发 JNI 调用，并把运行结果显示出来。

package com.example.jnilab

import android.app.Activity
import android.graphics.Bitmap
import android.graphics.Color
import android.os.Bundle
import android.view.ViewGroup
import android.widget.Button
import android.widget.ImageView
import android.widget.LinearLayout
import android.widget.ScrollView
import android.widget.TextView

class MainActivity : Activity() {
    // resultView 用来显示 Kotlin 和 C++ 之间来回调用的结果。
    private lateinit var resultView: TextView

    // imageView 用来显示被 native 代码修改过像素的 Bitmap。
    private lateinit var imageView: ImageView

    // demoBitmap 是一张运行时创建的小图片。
    // 本文不依赖任何图片资源，方便读者复制项目后直接运行。
    private lateinit var demoBitmap: Bitmap

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        demoBitmap = createDemoBitmap()

        resultView = TextView(this).apply {
            textSize = 15f
            setTextColor(Color.rgb(30, 30, 30))
            text = "点击按钮运行 JNI 示例"
        }

        imageView = ImageView(this).apply {
            setImageBitmap(demoBitmap)
            adjustViewBounds = true
            layoutParams = LinearLayout.LayoutParams(
                ViewGroup.LayoutParams.MATCH_PARENT,
                260,
            )
        }

        val runButton = Button(this).apply {
            text = "运行 JNI 示例"
            setOnClickListener { runJniDemo() }
        }

        val content = LinearLayout(this).apply {
            orientation = LinearLayout.VERTICAL
            setPadding(32, 32, 32, 32)
            addView(runButton)
            addView(imageView)
            addView(resultView)
        }

        val scrollView = ScrollView(this).apply {
            addView(content)
        }

        setContentView(scrollView)
    }

    private fun runJniDemo() {
        resultView.text = ""

        // 1. Kotlin 调 C++，传 String 和 IntArray，接收 NativeResult。
        val result = NativeBridge.summarize(
            name = "Android JNI",
            scores = intArrayOf(10, 20, 30),
        )
        appendLine("summarize: ${result.message}, sum=${result.sum}")

        // 2. 验证常用 NDK 库链接。
        appendLine("common libs: ${NativeBridge.commonLibrarySummary()}")

        // 3. 把 Bitmap 传给 C++，让 C++ 直接修改像素。
        val inverted = NativeBridge.invertBitmap(demoBitmap)
        imageView.setImageBitmap(demoBitmap)
        appendLine("invertBitmap: $inverted")

        // 4. 让 C++ 后台线程回调 Kotlin。
        NativeBridge.runCallbackDemo(object : NativeCallback {
            override fun onNativeProgress(step: Int, message: String) {
                // native 后台线程回调过来时，不在 Android 主线程。
                // 更新 UI 必须切回主线程。
                runOnUiThread {
                    appendLine("callback[$step]: $message")
                }
            }

            override fun onNativeError(message: String) {
                runOnUiThread {
                    appendLine("native error: $message")
                }
            }
        })
    }

    private fun appendLine(text: String) {
        // resultView.text 是 CharSequence，这里转成 String 再拼接，逻辑直观。
        resultView.text = resultView.text.toString() + text + "\n"
    }

    private fun createDemoBitmap(): Bitmap {
        val width = 160
        val height = 96

        // ARGB_8888 对应 native 侧 ANDROID_BITMAP_FORMAT_RGBA_8888。
        val bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888)

        for (y in 0 until height) {
            for (x in 0 until width) {
                val color = if (x < width / 2) {
                    Color.rgb(220, 70, 70)
                } else {
                    Color.rgb(60, 120, 230)
                }
                bitmap.setPixel(x, y, color)
            }
        }

        return bitmap
    }
}

7. CMake 配置

文件路径： app/src/main/cpp/CMakeLists.txt

# app/src/main/cpp/CMakeLists.txt
# 作用：构建 libjnilab.so，并链接 Android NDK 常用 native 库。

cmake_minimum_required(VERSION 3.22.1)

# project 声明 native 子项目名和语言。
project(jnilab LANGUAGES CXX)

# add_library 生成共享库 libjnilab.so。
# jnilab 这个名字要和 Kotlin 里的 System.loadLibrary("jnilab") 对应。
add_library(jnilab SHARED
    native-lib.cpp
)

# target_compile_features 要求当前目标使用 C++17。
target_compile_features(jnilab PRIVATE cxx_std_17)

# target_compile_options 打开常见编译警告。
target_compile_options(jnilab PRIVATE
    -Wall
    -Wextra
)

# target_link_libraries 链接 Android NDK 常用库。
# log: <android/log.h>，写 logcat。
# android: <android/trace.h>、NativeWindow、AssetManager 等 native Android API。
# jnigraphics: <android/bitmap.h>，访问 Java/Kotlin Bitmap 像素。
# aaudio: <aaudio/AAudio.h>，Android 低延迟音频 API，API 26+。
# OpenSLES: OpenSL ES 音频 API，较老项目常见，新项目可优先考虑 AAudio 或 Oboe。
# GLESv3/EGL: OpenGL ES 3.x 与 EGL。真正渲染前还需要创建 GL 上下文。
# vulkan: Vulkan loader。真正使用前还需要查询设备和扩展支持。
target_link_libraries(jnilab PRIVATE
    log
    android
    jnigraphics
    aaudio
    OpenSLES
    GLESv3
    EGL
    vulkan
)

不要无脑链接所有库

本文把常用库放在一起，是为了让你看清 CMake 写法。真实项目应该按需链接：只做日志就链接 log ，只处理 Bitmap 就加 jnigraphics 。OpenGL ES、Vulkan、音频库还涉及设备能力、上下文、权限、线程模型和生命周期，不能只靠链接库完成业务功能。

8. C++ 核心源码

文件路径： app/src/main/cpp/native-lib.cpp

下面是完整源码。它覆盖本文关心的 JNI 细节：类型映射、字符串转换、数组转换、局部引用、全局引用、线程附加、异常检查和性能注意点。

// app/src/main/cpp/native-lib.cpp
// 作用：实现 Kotlin 声明的 native 方法，演示 JNI 和 Android NDK 常用库。

#include <GLES3/gl3.h>          // OpenGL ES 3.x 常量和函数声明。
#include <SLES/OpenSLES.h>      // OpenSL ES 常量和函数声明。
#include <aaudio/AAudio.h>      // AAudio 常量和函数声明，API 26+。
#include <android/bitmap.h>     // AndroidBitmap_getInfo / lockPixels / unlockPixels。
#include <android/log.h>        // __android_log_print 写 logcat。
#include <android/trace.h>      // ATrace_beginSection / ATrace_endSection。
#include <jni.h>                // JNI 基础类型和函数。
#include <vulkan/vulkan.h>      // Vulkan loader API。

#include <chrono>               // std::chrono::milliseconds。
#include <cstdint>              // uint8_t。
#include <sstream>              // std::ostringstream。
#include <string>               // std::string。
#include <thread>               // std::thread。

namespace {

// TAG 是 logcat 过滤标签。
// adb logcat -s JniNdkLab 可以只看本文示例输出。
constexpr const char* TAG = "JniNdkLab";

// g_vm 保存 JavaVM 指针。
// JNIEnv 不能跨线程保存，但 JavaVM 可以跨线程保存，用于后续 GetEnv / AttachCurrentThread。
JavaVM* g_vm = nullptr;

// LocalRef 是一个很小的 RAII 包装器。
// 作用：函数中提前 return 时，也能自动 DeleteLocalRef，避免局部引用过多。
template <typename T>
class LocalRef {
public:
    LocalRef(JNIEnv* env, T ref) : env_(env), ref_(ref) {}

    ~LocalRef() {
        reset();
    }

    LocalRef(const LocalRef&) = delete;
    LocalRef& operator=(const LocalRef&) = delete;

    T get() const {
        return ref_;
    }

    T release() {
        T temp = ref_;
        ref_ = nullptr;
        return temp;
    }

    void reset(T next = nullptr) {
        if (ref_ != nullptr) {
            env_->DeleteLocalRef(ref_);
        }
        ref_ = next;
    }

private:
    JNIEnv* env_;
    T ref_;
};

// UtfChars 负责 GetStringUTFChars / ReleaseStringUTFChars 成对出现。
// 注意：JNI 的 UTF 字符串是 modified UTF-8，不完全等同标准 UTF-8。
class UtfChars {
public:
    UtfChars(JNIEnv* env, jstring value) : env_(env), value_(value), chars_(nullptr) {
        if (value_ != nullptr) {
            chars_ = env_->GetStringUTFChars(value_, nullptr);
        }
    }

    ~UtfChars() {
        if (chars_ != nullptr) {
            env_->ReleaseStringUTFChars(value_, chars_);
        }
    }

    UtfChars(const UtfChars&) = delete;
    UtfChars& operator=(const UtfChars&) = delete;

    const char* c_str() const {
        return chars_ == nullptr ? "" : chars_;
    }

    bool ok() const {
        return value_ == nullptr || chars_ != nullptr;
    }

private:
    JNIEnv* env_;
    jstring value_;
    const char* chars_;
};

// IntArrayElements 负责 GetIntArrayElements / ReleaseIntArrayElements 成对出现。
// releaseMode 使用 JNI_ABORT，表示 native 侧只读，不把修改写回 Kotlin IntArray。
class IntArrayElements {
public:
    IntArrayElements(JNIEnv* env, jintArray array)
        : env_(env), array_(array), data_(nullptr), length_(0) {
        if (array_ != nullptr) {
            length_ = env_->GetArrayLength(array_);
            data_ = env_->GetIntArrayElements(array_, nullptr);
        }
    }

    ~IntArrayElements() {
        if (data_ != nullptr) {
            env_->ReleaseIntArrayElements(array_, data_, JNI_ABORT);
        }
    }

    IntArrayElements(const IntArrayElements&) = delete;
    IntArrayElements& operator=(const IntArrayElements&) = delete;

    const jint* data() const {
        return data_;
    }

    jsize length() const {
        return length_;
    }

    bool ok() const {
        return array_ == nullptr || length_ == 0 || data_ != nullptr;
    }

private:
    JNIEnv* env_;
    jintArray array_;
    jint* data_;
    jsize length_;
};

// throwIllegalArgument 把 native 参数错误转换成 Java/Kotlin IllegalArgumentException。
void throwIllegalArgument(JNIEnv* env, const char* message) {
    jclass clazz = env->FindClass("java/lang/IllegalArgumentException");
    if (clazz != nullptr) {
        env->ThrowNew(clazz, message);
        env->DeleteLocalRef(clazz);
    }
}

// hasException 用于关键 JNI 调用后检查是否已经有 Java 异常挂起。
// JNI 中异常挂起后，不能继续当作普通成功路径执行。
bool hasException(JNIEnv* env, const char* where) {
    if (!env->ExceptionCheck()) {
        return false;
    }

    __android_log_print(ANDROID_LOG_ERROR, TAG, "JNI exception at %s", where);
    return true;
}

// buildNativeResult 演示 C++ 调 Kotlin 构造函数：
// FindClass -> GetMethodID -> NewStringUTF -> NewObject。
jobject buildNativeResult(JNIEnv* env, const std::string& message, jint sum) {
    LocalRef<jclass> resultClass(
        env,
        env->FindClass("com/example/jnilab/NativeResult")
    );
    if (resultClass.get() == nullptr || hasException(env, "FindClass NativeResult")) {
        return nullptr;
    }

    jmethodID constructor = env->GetMethodID(
        resultClass.get(),
        "<init>",
        "(Ljava/lang/String;I)V"
    );
    if (constructor == nullptr || hasException(env, "GetMethodID NativeResult.<init>")) {
        return nullptr;
    }

    LocalRef<jstring> javaMessage(env, env->NewStringUTF(message.c_str()));
    if (javaMessage.get() == nullptr || hasException(env, "NewStringUTF result message")) {
        return nullptr;
    }

    jobject result = env->NewObject(
        resultClass.get(),
        constructor,
        javaMessage.get(),
        sum
    );
    if (result == nullptr || hasException(env, "NewObject NativeResult")) {
        return nullptr;
    }

    // result 是要返回给 Kotlin 的局部引用，不能在这里 DeleteLocalRef。
    return result;
}

// attachCurrentThreadIfNeeded 用 JavaVM 获取当前线程的 JNIEnv。
// 如果当前线程不是 JVM 管理线程，就调用 AttachCurrentThread。
JNIEnv* attachCurrentThreadIfNeeded(bool* didAttach) {
    *didAttach = false;

    JNIEnv* env = nullptr;
    const jint getEnvResult = g_vm->GetEnv(
        reinterpret_cast<void**>(&env),
        JNI_VERSION_1_6
    );

    if (getEnvResult == JNI_OK) {
        return env;
    }

    if (getEnvResult != JNI_EDETACHED) {
        return nullptr;
    }

    if (g_vm->AttachCurrentThread(&env, nullptr) != JNI_OK) {
        return nullptr;
    }

    *didAttach = true;
    return env;
}

// callErrorCallback 在 native 后台线程中调用 Kotlin onNativeError。
void callErrorCallback(JNIEnv* env, jobject callback, jmethodID errorMethod, const char* message) {
    LocalRef<jstring> javaMessage(env, env->NewStringUTF(message));
    if (javaMessage.get() == nullptr || env->ExceptionCheck()) {
        env->ExceptionClear();
        return;
    }

    env->CallVoidMethod(callback, errorMethod, javaMessage.get());
    if (env->ExceptionCheck()) {
        env->ExceptionDescribe();
        env->ExceptionClear();
    }
}

} // namespace

// JNI_OnLoad 在 libjnilab.so 被 System.loadLibrary 加载时执行。
// 返回 JNI_VERSION_1_6 表示当前库使用 JNI 1.6。
JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void*) {
    g_vm = vm;
    return JNI_VERSION_1_6;
}

extern "C" JNIEXPORT jobject JNICALL
Java_com_example_jnilab_NativeBridge_summarize(
    JNIEnv* env,
    jobject /* thisObject */,
    jstring name,
    jintArray scores
) {
    if (name == nullptr) {
        throwIllegalArgument(env, "name must not be null");
        return nullptr;
    }

    if (scores == nullptr) {
        throwIllegalArgument(env, "scores must not be null");
        return nullptr;
    }

    // jstring -> const char*。UtfChars 析构时会自动 ReleaseStringUTFChars。
    UtfChars nativeName(env, name);
    if (!nativeName.ok() || hasException(env, "GetStringUTFChars name")) {
        return nullptr;
    }

    // jintArray -> jint*。IntArrayElements 析构时会自动 ReleaseIntArrayElements。
    IntArrayElements nativeScores(env, scores);
    if (!nativeScores.ok() || hasException(env, "GetIntArrayElements scores")) {
        return nullptr;
    }

    jint sum = 0;
    for (jsize index = 0; index < nativeScores.length(); ++index) {
        sum += nativeScores.data()[index];
    }

    __android_log_print(
        ANDROID_LOG_INFO,
        TAG,
        "summarize name=%s sum=%d",
        nativeName.c_str(),
        sum
    );

    std::string message = "hello from C++: ";
    message += nativeName.c_str();

    return buildNativeResult(env, message, sum);
}

extern "C" JNIEXPORT jboolean JNICALL
Java_com_example_jnilab_NativeBridge_invertBitmap(
    JNIEnv* env,
    jobject /* thisObject */,
    jobject bitmap
) {
    if (bitmap == nullptr) {
        throwIllegalArgument(env, "bitmap must not be null");
        return JNI_FALSE;
    }

    AndroidBitmapInfo info{};
    int status = AndroidBitmap_getInfo(env, bitmap, &info);
    if (status != ANDROID_BITMAP_RESULT_SUCCESS) {
        __android_log_print(ANDROID_LOG_ERROR, TAG, "AndroidBitmap_getInfo failed: %d", status);
        return JNI_FALSE;
    }

    if (info.format != ANDROID_BITMAP_FORMAT_RGBA_8888) {
        __android_log_print(ANDROID_LOG_ERROR, TAG, "Only RGBA_8888 bitmap is supported");
        return JNI_FALSE;
    }

    void* pixels = nullptr;
    status = AndroidBitmap_lockPixels(env, bitmap, &pixels);
    if (status != ANDROID_BITMAP_RESULT_SUCCESS || pixels == nullptr) {
        __android_log_print(ANDROID_LOG_ERROR, TAG, "AndroidBitmap_lockPixels failed: %d", status);
        return JNI_FALSE;
    }

    // info.stride 是每一行占用的字节数，不一定等于 width * 4。
    // 所以遍历像素时必须按 stride 找到每一行起点。
    for (uint32_t y = 0; y < info.height; ++y) {
        auto* row = static_cast<uint8_t*>(pixels) + y * info.stride;
        for (uint32_t x = 0; x < info.width; ++x) {
            uint8_t* px = row + x * 4;

            // RGBA_8888 每个像素 4 字节。这里只反转颜色通道，保留 alpha。
            px[0] = static_cast<uint8_t>(255 - px[0]);
            px[1] = static_cast<uint8_t>(255 - px[1]);
            px[2] = static_cast<uint8_t>(255 - px[2]);
        }
    }

    AndroidBitmap_unlockPixels(env, bitmap);

    __android_log_print(
        ANDROID_LOG_INFO,
        TAG,
        "Bitmap inverted: %ux%u stride=%u",
        info.width,
        info.height,
        info.stride
    );

    return JNI_TRUE;
}

extern "C" JNIEXPORT void JNICALL
Java_com_example_jnilab_NativeBridge_runCallbackDemo(
    JNIEnv* env,
    jobject /* thisObject */,
    jobject callback
) {
    if (callback == nullptr) {
        throwIllegalArgument(env, "callback must not be null");
        return;
    }

    LocalRef<jclass> callbackClass(env, env->GetObjectClass(callback));
    if (callbackClass.get() == nullptr || hasException(env, "GetObjectClass callback")) {
        return;
    }

    jmethodID progressMethod = env->GetMethodID(
        callbackClass.get(),
        "onNativeProgress",
        "(ILjava/lang/String;)V"
    );
    if (progressMethod == nullptr || hasException(env, "GetMethodID onNativeProgress")) {
        return;
    }

    jmethodID errorMethod = env->GetMethodID(
        callbackClass.get(),
        "onNativeError",
        "(Ljava/lang/String;)V"
    );
    if (errorMethod == nullptr || hasException(env, "GetMethodID onNativeError")) {
        return;
    }

    // callback 是 native 方法参数，默认只是局部引用。
    // native 方法返回后局部引用失效，所以后台线程必须持有全局引用。
    jobject globalCallback = env->NewGlobalRef(callback);
    if (globalCallback == nullptr || hasException(env, "NewGlobalRef callback")) {
        return;
    }

    __android_log_print(ANDROID_LOG_INFO, TAG, "Native worker started");

    std::thread([globalCallback, progressMethod, errorMethod]() {
        bool didAttach = false;
        JNIEnv* threadEnv = attachCurrentThreadIfNeeded(&didAttach);
        if (threadEnv == nullptr) {
            return;
        }

        for (jint step = 1; step <= 3; ++step) {
            std::this_thread::sleep_for(std::chrono::milliseconds(250));

            std::ostringstream oss;
            oss << "native worker step " << step;

            LocalRef<jstring> message(
                threadEnv,
                threadEnv->NewStringUTF(oss.str().c_str())
            );
            if (message.get() == nullptr || threadEnv->ExceptionCheck()) {
                threadEnv->ExceptionDescribe();
                threadEnv->ExceptionClear();
                callErrorCallback(threadEnv, globalCallback, errorMethod, "failed to allocate message");
                break;
            }

            threadEnv->CallVoidMethod(
                globalCallback,
                progressMethod,
                step,
                message.get()
            );

            if (threadEnv->ExceptionCheck()) {
                // callback 抛异常时，native 线程没有直接的 Kotlin 调用栈接住它。
                // 这里打印并清理，再通过 onNativeError 报告。
                threadEnv->ExceptionDescribe();
                threadEnv->ExceptionClear();
                callErrorCallback(threadEnv, globalCallback, errorMethod, "callback threw an exception");
                break;
            }
        }

        threadEnv->DeleteGlobalRef(globalCallback);

        if (didAttach) {
            g_vm->DetachCurrentThread();
        }
    }).detach();
}

10. 关键代码拆解

10.1 Kotlin 调 C++：native 方法和 System.loadLibrary

Kotlin 侧声明：

object NativeBridge {
    init {
        System.loadLibrary("jnilab")
    }

    external fun summarize(name: String, scores: IntArray): NativeResult
}

对应 C++ 函数名：

Java_com_example_jnilab_NativeBridge_summarize

命名规则可以按这段理解：

Java_包名_类名_方法名

所以：

com.example.jnilab.NativeBridge.summarize

会变成：

Java_com_example_jnilab_NativeBridge_summarize

注

本文使用 “按名字导出” 的 JNI 写法，便于初学者看懂映射关系。真实项目也常用 RegisterNatives 动态注册 native 方法，它更适合大型项目和混淆场景，但入门阶段会多一层映射表。

10.2 JNI 类型映射

本文用到的类型映射如下：

Kotlin / Java 类型C++ JNI 类型本文出现位置
Stringjstringsummarize(name: String, ...)
IntjintNativeResult.sum 、callback step
IntArrayjintArrayscores: IntArray
BitmapjobjectinvertBitmap(bitmap: Bitmap)
Kotlin 数据类对象jobjectNativeResult 返回值
Java/Kotlin 类jclassFindClass("com/example/jnilab/NativeResult")

jobject 是对象引用的通用类型， jstring 、 jarray 、 jclass 都属于 JNI 引用类型。不要把它们当 C++ 普通指针长期保存。native 方法参数默认是局部引用，只在当前 native 方法和当前线程中有效。

10.3 字符串转换

C++ 中读取 Kotlin String ：

UtfChars nativeName(env, name);

UtfChars 内部做了两件事：

chars_ = env_->GetStringUTFChars(value_, nullptr);
env_->ReleaseStringUTFChars(value_, chars_);

要点：

  • GetStringUTFChars 可能复制，也可能返回虚拟机内部缓冲，调用者不能假设具体实现。
  • 只要成功获取，就必须调用 ReleaseStringUTFChars 。
  • JNI 的 UTF 字符串是 modified UTF-8。大多数普通文本没问题，但如果你要严格处理完整 Unicode 编码规则，需要进一步确认编码策略。

10.4 数组转换

C++ 中读取 Kotlin IntArray ：

IntArrayElements nativeScores(env, scores);

内部对应：

length_ = env_->GetArrayLength(array_);
data_ = env_->GetIntArrayElements(array_, nullptr);
env_->ReleaseIntArrayElements(array_, data_, JNI_ABORT);

ReleaseIntArrayElements 的最后一个参数很重要：

模式含义
0把 native 修改提交回 Java/Kotlin，并释放缓冲
JNI_COMMIT提交修改，但不释放缓冲
JNI_ABORT不提交修改，直接释放缓冲

本文只是读取分数求和，所以使用 JNI_ABORT 。

10.5 C++ 创建 Kotlin 对象

本文返回 NativeResult ：

LocalRef<jclass> resultClass(
    env,
    env->FindClass("com/example/jnilab/NativeResult")
);

jmethodID constructor = env->GetMethodID(
    resultClass.get(),
    "<init>",
    "(Ljava/lang/String;I)V"
);

jobject result = env->NewObject(
    resultClass.get(),
    constructor,
    javaMessage.get(),
    sum
);

这段代码的关键是方法签名：

(Ljava/lang/String;I)V

可以拆成：

(参数列表)返回值

其中：

  • Ljava/lang/String; 表示 Java/Kotlin 的 String 。
  • I 表示 int 。
  • V 表示返回 void 。
  • 构造函数 <init> 总是返回 V 。

所以 NativeResult(message: String, sum: Int) 的构造函数签名就是：

(Ljava/lang/String;I)V

10.6 局部引用和全局引用

native 方法参数和大多数 JNI 函数返回值都是局部引用，例如：

jobject callback
jclass callbackClass
jstring message

局部引用的特点：

  • 只在当前 native 方法中有效。
  • 只在创建它的线程中有效。
  • native 方法返回后自动失效。
  • 循环中大量创建局部引用时，建议手动 DeleteLocalRef 。

本文用 LocalRef 自动删除局部引用：

LocalRef<jstring> message(threadEnv, threadEnv->NewStringUTF("..."));

后台线程需要在 native 方法返回后继续使用 Kotlin 回调对象，所以必须创建全局引用：

jobject globalCallback = env->NewGlobalRef(callback);

用完后必须释放：

threadEnv->DeleteGlobalRef(globalCallback);

全局引用不是缓存万能药

全局引用会阻止对象被垃圾回收。长期持有 Activity、View、Context 这类对象，很容易造成内存泄漏。真实项目中要结合生命周期释放，必要时只保存 Application Context 或弱全局引用。

10.7 native 线程调用 Kotlin：AttachCurrentThread

Kotlin 调 native 时，当前线程已经有 JNIEnv* 。但 C++ 自己创建的线程没有。

本文后台线程里先做：

JNIEnv* threadEnv = attachCurrentThreadIfNeeded(&didAttach);

内部逻辑：

g_vm->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6);
g_vm->AttachCurrentThread(&env, nullptr);

线程结束前：

g_vm->DetachCurrentThread();

要点：

  • JNIEnv* 是线程相关的，不能从一个线程传给另一个线程使用。
  • JavaVM* 可以跨线程保存，用它获取当前线程的 JNIEnv* 。
  • native 创建的线程要调用 Java/Kotlin 前必须 AttachCurrentThread 。
  • 由 native 附加的线程退出前要 DetachCurrentThread 。

10.8 JNI 异常处理

JNI 调用失败时，常见行为是 “返回空值，并挂起一个 Java 异常”。例如：

jclass clazz = env->FindClass("bad/ClassName");

如果找不到类， clazz == nullptr ，同时会挂起 ClassNotFoundException 或相关异常。此时不要继续按成功路径调用后续 JNI API。

本文用：

if (resultClass.get() == nullptr || hasException(env, "FindClass NativeResult")) {
    return nullptr;
}

回调线程中如果 Kotlin callback 抛异常，native 线程没有普通 Kotlin 调用栈接住它，所以本文会：

threadEnv->ExceptionDescribe();
threadEnv->ExceptionClear();
callErrorCallback(threadEnv, globalCallback, errorMethod, "callback threw an exception");

真实项目中可以选择：

  • 在 native 边界直接返回错误码。
  • 抛 Java/Kotlin 异常给调用者。
  • 通过 callback、Flow、Channel 或状态对象报告错误。

不要忽略 ExceptionCheck 后继续执行成功路径。

12. JNI 性能原则

JNI 调用不是不能用，但不要把它当普通函数调用无限细分。

更推荐：

  • 一次传入 IntArray 、 ByteArray 、 DirectByteBuffer 或业务对象，让 native 批量处理。
  • native 侧处理完一批数据后，再一次性返回结果。
  • 缓存稳定的 jclass 、 jmethodID 、 jfieldID ，但要注意类加载器和生命周期。
  • 图片、音频、视频这类大数据尽量减少 Kotlin/C++ 来回拷贝。

不推荐：

  • 在渲染循环里每个像素都跨 JNI 调一次。
  • 在音频回调里频繁创建 String 、对象或抛异常。
  • 把 JNIEnv* 缓存在全局变量给多个线程共用。
  • 长期持有 Activity 的全局引用。

本文 summarize(name, scores) 一次传入整个 IntArray ，就是 “批量传数据” 的小例子。

13. 常见错误和排查

13.1 java.lang.UnsatisfiedLinkError: couldn't find libjnilab.so

常见原因：

  • System.loadLibrary("jnilab") 和 add_library(jnilab SHARED ...) 名字不一致。
  • CMake 没有参与构建，检查 externalNativeBuild.cmake.path 。
  • APK 没有打入 so，执行 unzip -l app-debug.apk | grep libjnilab.so 。

13.2 No implementation found for native ...

常见原因：

  • C++ 函数名和 Kotlin 包名、类名、方法名不匹配。
  • Kotlin 方法参数改了，但 C++ 函数签名没改。
  • 忘记写 extern "C" ，导致 C++ 名字被改编。

排查方式：

nm -D app/build/intermediates/merged_native_libs/debug/out/lib/arm64-v8a/libjnilab.so | grep summarize

如果看不到 Java_com_example_jnilab_NativeBridge_summarize ，说明导出符号不对。

13.3 FindClass 找不到自己的 Kotlin 类

在 Kotlin 直接调用 native 的线程里， FindClass("com/example/...") 通常能找到应用类。

但 native 自己创建的线程里， FindClass 可能使用系统类加载器，找不到应用类。本文在后台线程里没有用 FindClass 找应用类，而是在 native 方法还没返回时先拿到：

jclass callbackClass = env->GetObjectClass(callback);
jmethodID progressMethod = env->GetMethodID(...);

然后在线程里只使用 jmethodID 和 globalCallback 。

如果真实项目需要在 native 线程里创建应用类对象，常见做法是在 Kotlin 层传入 ClassLoader 或工厂对象，由 native 通过这个对象间接创建。

13.4 native 线程回调后崩溃

优先检查：

  • 是否调用了 AttachCurrentThread 。
  • 是否把其他线程的 JNIEnv* 拿来用了。
  • callback 是否是全局引用。
  • 线程结束前是否 DetachCurrentThread 。
  • callback 内部是否直接更新 UI。UI 更新必须切回主线程。

13.5 Bitmap 处理返回 false

本文只支持：

Bitmap.Config.ARGB_8888

如果你传入 RGB_565 、硬件 Bitmap 或其他配置， info.format 可能不是 ANDROID_BITMAP_FORMAT_RGBA_8888 。解决方式：

val mutableBitmap = source.copy(Bitmap.Config.ARGB_8888, true)

再传给 native。

13.6 链接 aaudio、vulkan 或 GLES 报错

排查顺序：

  1. minSdk 是否满足库的 API level 要求。AAudio 需要 API 26+，Vulkan 需要 API 24+。
  2. SDK Manager 是否安装了指定 NDK。
  3. target_link_libraries 中库名是否写对，例如 OpenSLES 、 GLESv3 、 vulkan 。
  4. 如果只是普通 JNI 项目，不需要图形或音频库，就先删掉无关链接项。

13.7 JNI 字符串中文乱码

GetStringUTFChars 使用 modified UTF-8。一般日志、英文、常见中文传递通常可用，但如果你要处理严格 UTF-8 字节协议、emoji、二进制数据，不要把 String 当字节容器。更稳妥的方式是：

  • Kotlin 侧明确使用 ByteArray ，例如 text.encodeToByteArray() 。
  • C++ 侧用 jbyteArray 读取原始字节。
  • 明确约定编码，例如 UTF-8。

14. 背后的原理

JNI 可以理解成 “虚拟机提供给 native 代码的一张函数表”。 JNIEnv* 不是普通业务对象，而是当前线程访问 JVM 的入口。通过它，C++ 可以：

  • 创建 Java/Kotlin 对象。
  • 调用 Java/Kotlin 方法。
  • 读取和写入字段。
  • 处理字符串和数组。
  • 检查和抛出 Java 异常。

Android 上 Kotlin 最终也运行在 ART 虚拟机上，所以 native 层看到的是 Java/JVM 层面的类名、方法签名和对象引用。Kotlin 的高级语法会编译成 JVM 字节码，例如：

  • data class NativeResult(val message: String, val sum: Int) 会有 JVM 构造函数。
  • object NativeBridge 会生成一个单例类。
  • interface NativeCallback 会生成普通 JVM 接口。

这也是为什么 C++ 里写的是：

FindClass("com/example/jnilab/NativeResult")
GetMethodID(..., "<init>", "(Ljava/lang/String;I)V")
CallVoidMethod(...)

而不是直接写 Kotlin 源码里的语法。

不要依赖非公开接口

本文使用的都是公开 NDK/JNI API。不要在项目中调用 Android 系统私有符号、私有 so 或未公开结构体字段。Android 版本、厂商 ROM 和 ABI 差异都可能让这些做法在升级后崩溃。

15. 小结

这篇教程完成了一个最小但完整的 JNI 链路：

  • Kotlin 使用 external fun 和 System.loadLibrary 调 C++。
  • C++ 用 jstring 、 jintArray 、 jobject 、 jclass 处理 Kotlin 传入的数据。
  • 字符串用 GetStringUTFChars / ReleaseStringUTFChars 成对管理。
  • 数组用 GetIntArrayElements / ReleaseIntArrayElements 成对管理。
  • 局部引用只在当前 native 方法和线程有效，跨线程或跨方法保存对象要用全局引用。
  • native 线程调用 Kotlin 前必须 AttachCurrentThread ，退出前要 DetachCurrentThread 。
  • JNI 异常要用 ExceptionCheck 检查，不要挂着异常继续走成功路径。
  • 性能上要减少频繁跨语言调用，尽量批量传数据。

如果你继续扩展这个示例，建议按业务方向拆：

  • 图片处理：继续深入 jnigraphics 、 Bitmap 格式、SIMD、线程池。
  • 音频处理：优先看 AAudio 或 Oboe，理解实时音频线程限制。
  • 图形渲染：先建立 EGL/OpenGL ES 或 Vulkan 基础项目，再接入 JNI 数据传递。
  • 大型 native 项目：考虑 RegisterNatives 、统一错误码、native 生命周期管理和崩溃符号上传。
