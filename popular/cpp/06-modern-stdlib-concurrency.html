C++ 现代标准库实战：智能指针、容器、算法、Lambda 与多线程

学完基础语法、类、模板、异常和 RAII 之后，很多人会卡在一个更实际的问题上：这些标准库能力到底怎么一起用？

本文用一个可以直接运行的小项目串起来：

  • 智能指针： std::unique_ptr 、 std::shared_ptr 、 std::weak_ptr
  • 容器： std::vector 、 std::string 、 std::map 、 std::unordered_map
  • 算法： std::sort 、 std::find_if 、 std::transform
  • Lambda：普通回调、异步任务回调、JNI 边界封装思路
  • 移动语义：把字符串、任务对象和回调结果移动到目标位置，减少不必要拷贝
  • 现代工具类型： std::optional 、 std::variant 、 std::function
  • 多线程： std::thread 、 std::mutex 、 std::atomic 、 std::condition_variable

我们要实现的是一个 “任务管理 + 后台处理队列” 的控制台程序。主线程负责创建和查询任务；后台线程负责逐个处理任务；处理完成后通过 Lambda 回调把结果交给一个结果收集器。

目标效果

复现完成后，你应该能看懂一条完整链路：任务先存入 TaskStore ，用容器和算法完成排序、查找、转换；再用 std::unique_ptr 把任务提交给后台队列；后台线程通过条件变量等待任务；任务完成后通过 std::function 保存的 Lambda 回调通知结果对象；回调里用 std::weak_ptr 避免异步对象被意外延长生命周期。

1. 运行环境、版本和前置条件

本地可运行示例使用 C++20，只依赖 C++ 标准库和 CMake。

工具建议版本说明
C++ 编译器GCC 13+、Clang 17+ 或 MSVC 19.36+示例用到 std::optional 、 std::variant 、 std::function 、线程库和 C++20 编译模式；这些编译器版本更容易复现一致行为
CMake3.20+用于生成跨平台构建文件；本文使用 CXX_STANDARD 20 和 Threads::Threads
操作系统Linux、macOS、Windows 均可Windows 建议使用 Visual Studio Developer PowerShell 或 Developer Command Prompt

检查版本：

g++ --version
clang++ --version
cmake --version

只需要其中一个 C++ 编译器可用即可。Windows 使用 MSVC 时可以运行：

cl
cmake --version

版本差异提醒

std::optional 、 std::variant 从 C++17 起可用； std::thread 、 std::mutex 、 std::condition_variable 、 std::unique_ptr 、 std::shared_ptr 从 C++11 起已经稳定。本文统一使用 C++20，是为了和现代项目的编译配置保持一致。

C++20 还提供了 std::jthread 和 std::stop_token ，可以简化线程退出逻辑。但本文故意使用 std::thread + std::atomic + std::condition_variable ，因为这几个工具是理解 C++ 多线程代码时最常见的基础组合。

2. 最终运行效果

项目运行后会输出四段信息：

  1. 使用 std::vector 保存任务，并用 std::sort 得到按分组和名称排序的视图。
  2. 使用 std::find_if 查找任务，用 std::optional 表达 “可能找不到”。
  3. 使用 std::transform 提取任务名称。
  4. 使用后台队列异步处理任务，通过 Lambda 回调输出结果。

预期输出如下。不同标准库实现的线程调度细节可能略有差异，但本文的队列只有一个工作线程，因此回调顺序通常保持一致：

#2 [math] sum scores payload=values=[10, 20, 30]
#1 [text] normalize title note="uses std::transform" payload=text="hello modern c++"

== find_if + optional ==
#2 [math] sum scores note="found by std::find_if" payload=values=[10, 20, 30]
task #42 not found

== transform names ==
- normalize title
- sum scores
- jni callback name

== map/unordered_map stats ==
group jni -> 1 task(s)
group math -> 1 task(s)
group text -> 1 task(s)
unordered id index size=3

== async queue with smart pointers ==
[callback] #3 jni callback name -> upper=ONNATIVEDONE
[callback] #2 sum scores -> sum=60
[callback] #1 normalize title -> upper=HELLO MODERN C++
[callback] #100 move-only async text -> upper=MOVE ME ONCE

验证重点：

  • task #42 not found 说明 std::optional 正在表达 “查找失败”。
  • group ... 的输出按 key 排序，因为统计信息存在 std::map 中。
  • unordered id index size=3 说明快速 ID 索引用 std::unordered_map 保存。
  • [callback] 行来自后台线程处理后的回调。
  • sink expired=true 说明外部 std::shared_ptr 释放后， std::weak_ptr 不会继续拥有对象。

3. 项目结构

新建一个目录，例如 modern-cpp-stdlib-lab ，文件结构如下：

modern-cpp-stdlib-lab/
├── CMakeLists.txt
└── src/
    └── main.cpp

文件职责：

  • CMakeLists.txt ：声明 C++ 标准、可执行文件、线程库和编译警告。
  • src/main.cpp ：完整示例源码，包含任务模型、任务仓库、后台队列、回调对象和程序入口。

本文把核心代码放在一个 main.cpp 中，目的是降低复现成本。真实项目可以继续拆成 task.hpp 、 task_store.hpp 、 task_queue.hpp 等文件，但拆分方式不影响本文讲解的标准库用法。

4. 关键配置文件

文件路径： CMakeLists.txt

# CMakeLists.txt
# 作用：配置 modern-cpp-stdlib-lab 示例项目。该文件放在项目根目录。

cmake_minimum_required(VERSION 3.20)

# project 声明项目名、版本和语言。
# LANGUAGES CXX 表示只启用 C++ 编译器。
project(modern_cpp_stdlib_lab VERSION 1.0.0 LANGUAGES CXX)

# find_package(Threads REQUIRED) 查找当前平台的线程库配置。
# Linux 上通常会补上 pthread 相关链接选项；Windows/MSVC 上会使用对应平台能力。
find_package(Threads REQUIRED)

# add_executable 生成名为 modern_cpp_stdlib_lab 的可执行文件。
# 当前示例只有一个源文件：src/main.cpp。
add_executable(modern_cpp_stdlib_lab
    src/main.cpp
)

# CXX_STANDARD 20 要求用 C++20 编译。
# CXX_STANDARD_REQUIRED ON 表示编译器不支持 C++20 时直接失败。
# CXX_EXTENSIONS OFF 尽量关闭编译器私有扩展，让代码更接近标准 C++。
set_target_properties(modern_cpp_stdlib_lab PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED ON
    CXX_EXTENSIONS OFF
)

# Threads::Threads 是 CMake 提供的跨平台线程库目标。
# 这样比手写 -pthread 更适合 Windows、macOS 和 Linux 的统一构建。
target_link_libraries(modern_cpp_stdlib_lab PRIVATE
    Threads::Threads
)

# target_compile_options 为当前目标打开常用警告。
# GNU、Clang、AppleClang 使用 -Wall -Wextra -Wpedantic。
# MSVC 使用 /W4。
target_compile_options(modern_cpp_stdlib_lab PRIVATE
    $<$<CXX_COMPILER_ID:GNU,Clang,AppleClang>:-Wall -Wextra -Wpedantic>
    $<$<CXX_COMPILER_ID:MSVC>:/W4>
)

注

Threads::Threads 是 CMake 的导入目标，不是一个源码文件。它会根据平台补充合适的编译或链接选项。手写 -pthread 在 Linux 上常见，但放到跨平台教程里不够稳妥。

5. 核心源码

文件路径： src/main.cpp

下面是完整源码。代码较长，但没有省略本地可运行部分；每个区域都加了注释，读者可以直接复制到对应文件中编译。

// src/main.cpp
// 作用：用一个任务管理和后台队列示例串联现代 C++ 标准库常用能力。

#include <algorithm>           // 使用 std::sort、std::find_if、std::transform。
#include <atomic>              // 使用 std::atomic 保存跨线程计数和停止标记。
#include <chrono>              // 使用 60ms 这样的时间字面量。
#include <condition_variable>  // 使用 std::condition_variable 等待新任务。
#include <cctype>              // 使用 std::toupper 转换字符大小写。
#include <functional>          // 使用 std::function 保存回调，使用 std::reference_wrapper。
#include <iostream>            // 使用 std::cout 输出验证信息。
#include <iterator>            // 使用 std::back_inserter 配合 std::transform。
#include <map>                 // 使用 std::map 保存按 key 排序的分组统计。
#include <memory>              // 使用 std::unique_ptr、std::shared_ptr、std::weak_ptr。
#include <mutex>               // 使用 std::mutex、std::lock_guard、std::unique_lock。
#include <numeric>             // 使用 std::accumulate 计算整数和。
#include <optional>            // 使用 std::optional 表达“可能没有结果”。
#include <sstream>             // 使用 std::ostringstream 拼接列表文本。
#include <stdexcept>           // 使用 std::runtime_error 报告非法提交。
#include <string>              // 使用 std::string 保存任务名、分组和文本。
#include <thread>              // 使用 std::thread 创建后台工作线程。
#include <unordered_map>       // 使用 std::unordered_map 保存 ID 到下标的快速索引。
#include <utility>             // 使用 std::move 转移资源。
#include <variant>             // 使用 std::variant 保存不同类型的任务载荷。
#include <vector>              // 使用 std::vector 保存任务列表、结果列表和等待队列。

// 允许写 60ms。这个命名空间只在示例文件内部使用，避免放到头文件中污染调用方。
using namespace std::chrono_literals;

// TextPayload 表示“文本处理任务”的输入数据。
// 这里只有一个 std::string，后面会把它转成大写。
struct TextPayload {
    std::string text;
};

// SumPayload 表示“求和任务”的输入数据。
// std::vector<int> 用来保存一组整数。
struct SumPayload {
    std::vector<int> values;
};

// TaskPayload 是一个“只能是其中一种”的联合类型。
// 当前任务载荷要么是 TextPayload，要么是 SumPayload。
using TaskPayload = std::variant<TextPayload, SumPayload>;

// Task 是主线程和后台线程都要处理的任务对象。
struct Task {
    int id{};                         // 任务 ID，由 TaskStore 分配。
    std::string name;                 // 任务名称，方便排序和查找。
    std::string group;                // 任务分组，用于 std::map 统计。
    TaskPayload payload;              // 具体输入数据，由 std::variant 保存。
    std::optional<std::string> note;  // 可选备注；没有备注时就是 std::nullopt。
};

// TaskResult 是后台线程处理完一个任务后产生的结果。
struct TaskResult {
    int id{};             // 对应原任务 ID。
    std::string name;     // 对应原任务名称。
    std::string output;   // 处理结果文本。
};

// uppercase_copy 接收一个 std::string 副本，并在副本上就地转换。
// 参数按值传入，调用方传右值时可以移动进来，传左值时会复制一份。
std::string uppercase_copy(std::string text) {
    // std::transform 把输入区间逐个转换到输出区间。
    // 这里输入和输出都是 text 自己，所以是原地修改副本。
    std::transform(text.begin(), text.end(), text.begin(), [](unsigned char ch) {
        // std::toupper 接收 unsigned char 范围内的值更安全，避免 char 为负时出现未定义行为。
        return static_cast<char>(std::toupper(ch));
    });
    return text;
}

// PayloadPreview 是 std::visit 使用的访问器，用于把 TaskPayload 转成可读预览。
struct PayloadPreview {
    // 当 variant 当前保存 TextPayload 时，std::visit 会调用这个重载。
    std::string operator()(const TextPayload& payload) const {
        return "text=\"" + payload.text + "\"";
    }

    // 当 variant 当前保存 SumPayload 时，std::visit 会调用这个重载。
    std::string operator()(const SumPayload& payload) const {
        std::ostringstream out;
        out << "values=[";
        for (std::size_t i = 0; i < payload.values.size(); ++i) {
            if (i > 0) {
                out << ", ";
            }
            out << payload.values[i];
        }
        out << "]";
        return out.str();
    }
};

// PayloadExecutor 是真正执行任务的访问器。
struct PayloadExecutor {
    // 文本任务：把文本转成大写。
    std::string operator()(const TextPayload& payload) const {
        return "upper=" + uppercase_copy(payload.text);
    }

    // 求和任务：把 vector<int> 中的所有数字相加。
    std::string operator()(const SumPayload& payload) const {
        const int sum = std::accumulate(payload.values.begin(), payload.values.end(), 0);
        return "sum=" + std::to_string(sum);
    }
};

// payload_preview 对外隐藏 std::visit 的写法，让打印逻辑更清楚。
std::string payload_preview(const TaskPayload& payload) {
    return std::visit(PayloadPreview{}, payload);
}

// execute_task 执行一个任务，并返回统一的 TaskResult。
TaskResult execute_task(const Task& task) {
    return TaskResult{task.id, task.name, std::visit(PayloadExecutor{}, task.payload)};
}

// TaskStore 负责保存任务、查找任务和生成排序视图。
class TaskStore {
public:
    // addTask 使用按值参数接收 name、group、payload、note。
    // 这样调用方传临时对象时可以触发移动，调用方传左值时语义也清楚：需要保存一份。
    int addTask(std::string name,
                std::string group,
                TaskPayload payload,
                std::optional<std::string> note = std::nullopt) {
        const int id = next_id_++;

        // push_back 把新任务放进 vector。
        // std::move 表示把局部参数里的资源转移到 Task 中，避免再拷贝一遍字符串或 vector。
        tasks_.push_back(Task{id, std::move(name), std::move(group), std::move(payload), std::move(note)});

        // unordered_map 保存任务 ID 到 vector 下标的映射，便于 O(1) 平均复杂度查找。
        index_[id] = tasks_.size() - 1;

        // map 会按 group 字典序保存 key，所以打印统计时天然有序。
        ++group_count_[tasks_.back().group];

        return id;
    }

    // findById 返回 optional<reference_wrapper<Task>>。
    // std::optional 不能直接保存引用，所以用 std::reference_wrapper 包一层。
    std::optional<std::reference_wrapper<Task>> findById(int id) {
        const auto pos = index_.find(id);
        if (pos == index_.end()) {
            return std::nullopt;
        }
        return std::ref(tasks_.at(pos->second));
    }

    // findByName 用 std::find_if 查找第一个名称包含 keyword 的任务。
    std::optional<std::reference_wrapper<Task>> findByName(const std::string& keyword) {
        const auto it = std::find_if(tasks_.begin(), tasks_.end(), [&](const Task& task) {
            return task.name.find(keyword) != std::string::npos;
        });

        if (it == tasks_.end()) {
            return std::nullopt;
        }
        return std::ref(*it);
    }

    // sortedByGroupAndName 返回“指针视图”，而不是复制整个任务列表。
    // vector<const Task*> 只保存任务地址，排序时移动的是指针，成本比复制 Task 小。
    std::vector<const Task*> sortedByGroupAndName() const {
        std::vector<const Task*> view;
        view.reserve(tasks_.size());

        // std::transform 把 vector<Task> 转成 vector<const Task*>。
        std::transform(tasks_.begin(), tasks_.end(), std::back_inserter(view), [](const Task& task) {
            return &task;
        });

        // std::sort 使用 Lambda 定义排序规则：先按 group，再按 name。
        std::sort(view.begin(), view.end(), [](const Task* left, const Task* right) {
            if (left->group != right->group) {
                return left->group < right->group;
            }
            return left->name < right->name;
        });

        return view;
    }

    // names 提取所有任务名，演示 std::transform 的另一个常见用途。
    std::vector<std::string> names() const {
        std::vector<std::string> result;
        result.reserve(tasks_.size());

        std::transform(tasks_.begin(), tasks_.end(), std::back_inserter(result), [](const Task& task) {
            return task.name;
        });

        return result;
    }

    // printGroupStats 同时展示 std::map 和 std::unordered_map 的用途。
    void printGroupStats() const {
        for (const auto& [group, count] : group_count_) {
            std::cout << "group " << group << " -> " << count << " task(s)\n";
        }
        std::cout << "unordered id index size=" << index_.size() << "\n";
    }

    // size 返回当前保存的任务数量。
    std::size_t size() const {
        return tasks_.size();
    }

private:
    std::vector<Task> tasks_;                    // 保存任务本体，适合顺序遍历。
    std::unordered_map<int, std::size_t> index_; // ID 到 vector 下标的快速索引。
    std::map<std::string, int> group_count_;     // 分组统计，按 key 自动排序。
    int next_id_{1};                             // 下一个任务 ID，从 1 开始递增。
};

// EventSink 保存后台处理结果。
// 它会被 shared_ptr 管理，再通过 weak_ptr 捕获到异步回调里。
class EventSink {
public:
    // onResult 可能被后台线程调用，所以必须用 mutex 保护 history_ 和输出。
    void onResult(TaskResult result) {
        std::lock_guard<std::mutex> lock(mutex_);
        std::cout << "[callback] #" << result.id << " " << result.name << " -> " << result.output << "\n";
        history_.push_back(std::move(result));
    }

    // size 也要加锁，因为另一个线程可能正在写 history_。
    std::size_t size() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return history_.size();
    }

private:
    mutable std::mutex mutex_;          // mutable 允许 const 成员函数 size() 内部加锁。
    std::vector<TaskResult> history_;   // 保存所有回调结果。
};

// TaskQueue 是一个最小后台队列。
// 主线程 submit 任务；工作线程 run 等待任务并执行。
class TaskQueue {
public:
    // Callback 是一个类型别名，表示“接收 TaskResult、没有返回值”的回调。
    // std::function 可以保存 Lambda、函数指针、函数对象等可调用对象。
    using Callback = std::function<void(TaskResult)>;

    // 构造函数保存回调，并启动后台线程。
    explicit TaskQueue(Callback callback)
        : callback_(std::move(callback)), worker_(&TaskQueue::run, this) {}

    // 析构时停止后台线程，避免线程还在运行时对象已经被销毁。
    ~TaskQueue() {
        stop();
    }

    // 队列持有线程、互斥锁和任务所有权，复制语义容易出错，因此显式禁用复制。
    TaskQueue(const TaskQueue&) = delete;
    TaskQueue& operator=(const TaskQueue&) = delete;

    // submit 接收 unique_ptr<Task>，表示队列独占这个任务对象。
    void submit(std::unique_ptr<Task> task) {
        if (!task) {
            return;
        }

        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stopped_.load()) {
                throw std::runtime_error("cannot submit to stopped queue");
            }

            // std::unique_ptr 不能复制，只能移动。
            // 这行表示把任务所有权从调用方转移到 jobs_。
            jobs_.push_back(std::move(task));
        }

        // 修改共享队列后通知后台线程：现在可能有任务了。
        cv_.notify_one();
    }

    // processed 返回已经处理完成的任务数量。
    // relaxed 顺序足够用于“统计数字”，不用于保护其他内存访问。
    std::size_t processed() const {
        return processed_.load(std::memory_order_relaxed);
    }

    // stop 请求线程退出，并等待线程结束。
    void stop() {
        stopped_.store(true);
        cv_.notify_all();
        if (worker_.joinable()) {
            worker_.join();
        }
    }

private:
    // run 在后台线程中执行。
    void run() {
        while (true) {
            std::unique_ptr<Task> task;

            {
                // unique_lock 可以配合 condition_variable 等待；lock_guard 不能用于 wait。
                std::unique_lock<std::mutex> lock(mutex_);

                // 条件变量可能出现虚假唤醒，所以必须用谓词重新检查条件。
                cv_.wait(lock, [this] {
                    return stopped_.load() || !jobs_.empty();
                });

                // 已经请求停止，并且没有剩余任务，线程可以退出。
                if (stopped_.load() && jobs_.empty()) {
                    return;
                }

                // 从队列取出一个任务，所有权转移到局部变量 task。
                task = std::move(jobs_.front());

                // 为了演示 std::vector，这里用 erase 删除首元素。
                // 生产环境的高频队列更适合用 std::deque 或 std::queue。
                jobs_.erase(jobs_.begin());
            }

            // 模拟耗时操作。真实项目里这里可能是解析、网络请求、图片处理等。
            std::this_thread::sleep_for(60ms);

            // 执行任务，并通过回调把结果发出去。
            callback_(execute_task(*task));

            // 原子计数递增，主线程可以用它观察进度。
            processed_.fetch_add(1, std::memory_order_relaxed);
        }
    }

    Callback callback_;                         // 保存回调函数。
    std::vector<std::unique_ptr<Task>> jobs_;   // 等待处理的任务，队列独占每个任务。
    mutable std::mutex mutex_;                  // 保护 jobs_。
    std::condition_variable cv_;                // 没任务时让工作线程睡眠。
    std::atomic<bool> stopped_{false};          // 停止标记，跨线程读写。
    std::atomic<std::size_t> processed_{0};     // 已处理任务数量。
    std::thread worker_;                        // 后台工作线程。
};

// print_task_line 负责用统一格式打印任务。
void print_task_line(const Task& task) {
    std::cout << "#" << task.id << " [" << task.group << "] " << task.name;

    if (task.note.has_value()) {
        std::cout << " note=\"" << *task.note << "\"";
    }

    std::cout << " payload=" << payload_preview(task.payload) << "\n";
}

int main() {
    TaskStore store;

    // 三个任务会被移动进 TaskStore。
    // TextPayload 和 SumPayload 会自动转换成 TaskPayload，也就是 std::variant。
    store.addTask("normalize title", "text", TextPayload{"hello modern c++"}, "uses std::transform");
    store.addTask("sum scores", "math", SumPayload{{10, 20, 30}});
    store.addTask("jni callback name", "jni", TextPayload{"onNativeDone"}, "boundary naming demo");

    std::cout << "== sorted task view ==\n";
    for (const Task* task : store.sortedByGroupAndName()) {
        print_task_line(*task);
    }

    std::cout << "\n== find_if + optional ==\n";
    if (auto task = store.findByName("sum")) {
        // optional 有值时，通过 reference_wrapper::get() 拿到原 Task。
        task->get().note = "found by std::find_if";
        print_task_line(task->get());
    }

    if (auto missing = store.findById(42)) {
        print_task_line(missing->get());
    } else {
        std::cout << "task #42 not found\n";
    }

    std::cout << "\n== transform names ==\n";
    for (const std::string& name : store.names()) {
        std::cout << "- " << name << "\n";
    }

    std::cout << "\n== map/unordered_map stats ==\n";
    store.printGroupStats();

    std::cout << "\n== async queue with smart pointers ==\n";

    // shared_ptr 表示主线程拥有 EventSink。
    // 如果还有其他模块也要共享结果对象，也可以复制这个 shared_ptr。
    auto sink = std::make_shared<EventSink>();

    // weak_ptr 不增加引用计数，不会延长 EventSink 生命周期。
    // 异步回调常用 weak_ptr 防止“回调把界面对象/业务对象一直留住”。
    std::weak_ptr<EventSink> weak_sink = sink;

    // Lambda 捕获 weak_ptr。回调发生时先 lock，确认对象还活着再使用。
    TaskQueue queue([weak_sink](TaskResult result) {
        if (auto locked = weak_sink.lock()) {
            locked->onResult(std::move(result));
        }
    });

    // 这里从 store 中复制一份任务快照提交给后台队列。
    // 队列用 unique_ptr 独占任务对象，因此提交后调用方不能再访问这份后台任务。
    for (const Task* task : store.sortedByGroupAndName()) {
        queue.submit(std::make_unique<Task>(*task));
    }

    // 这个任务直接创建给后台队列，Task 临时对象会被移动进 unique_ptr 管理的对象中。
    queue.submit(std::make_unique<Task>(
        Task{100, "move-only async text", "text", TextPayload{"move me once"}, "created directly for worker"}));

    // 简单等待所有任务处理完成。
    // 真实项目通常会用更明确的关闭协议或 future/promise 返回结果。
    while (queue.processed() < store.size() + 1) {
        std::this_thread::sleep_for(20ms);
    }

    // 主动停止队列。即使不写这一行，析构函数也会调用 stop。
    queue.stop();

    std::cout << "processed=" << queue.processed() << "\n";
    std::cout << "history size=" << sink->size() << "\n";

    // 释放最后一个 shared_ptr 后，weak_ptr 会过期。
    sink.reset();
    std::cout << "sink expired=" << std::boolalpha << weak_sink.expired() << "\n";
}

7. 逐段拆解关键代码

7.1 std::variant ：一个任务只保存一种载荷

struct TextPayload {
    std::string text;
};

struct SumPayload {
    std::vector<int> values;
};

using TaskPayload = std::variant<TextPayload, SumPayload>;

这里有两种任务输入：

  • TextPayload ：保存文本，后面会转大写。
  • SumPayload ：保存整数列表，后面会求和。

std::variant<TextPayload, SumPayload> 表示 “当前值只能是这两种之一”。它比手写 void* 、基类指针或一堆 type 字段更安全，因为编译器知道所有可能类型，访问时必须用 std::visit 或 std::get 处理。

本文用 std::visit(PayloadExecutor{}, task.payload) 执行任务：

struct PayloadExecutor {
    std::string operator()(const TextPayload& payload) const {
        return "upper=" + uppercase_copy(payload.text);
    }

    std::string operator()(const SumPayload& payload) const {
        const int sum = std::accumulate(payload.values.begin(), payload.values.end(), 0);
        return "sum=" + std::to_string(sum);
    }
};

PayloadExecutor 像一个函数对象，针对不同载荷类型提供不同的 operator() 重载。 std::visit 会根据 variant 当前保存的真实类型选择对应重载。

7.2 std::optional ：把 “可能没有” 写进类型里

std::optional<std::reference_wrapper<Task>> findById(int id) {
    const auto pos = index_.find(id);
    if (pos == index_.end()) {
        return std::nullopt;
    }
    return std::ref(tasks_.at(pos->second));
}

findById 可能找到任务，也可能找不到任务。它没有返回裸指针，而是返回 std::optional ：

  • 有值：表示找到了任务。
  • std::nullopt ：表示没有找到。

这里还有一个细节： std::optional<T&> 不合法，所以示例用 std::reference_wrapper<Task> 包住引用。调用方拿到结果后需要写 task->get() 取出原对象。

使用方式：

if (auto missing = store.findById(42)) {
    print_task_line(missing->get());
} else {
    std::cout << "task #42 not found\n";
}

这种写法比返回特殊 ID、空字符串或异常更直观：函数签名已经告诉读者 “找不到是正常情况”。

7.3 std::vector 、 std::map 、 std::unordered_map 各管一件事

std::vector<Task> tasks_;
std::unordered_map<int, std::size_t> index_;
std::map<std::string, int> group_count_;

三个容器分别负责不同目标：

容器在示例中的用途适合原因
std::vector<Task>保存任务本体连续存储，遍历快，适合任务列表
std::unordered_map<int, std::size_t>保存 ID 到 vector 下标的索引平均 O (1) 查找，适合按 ID 快速定位
std::map<std::string, int>保存分组统计key 自动有序，打印统计时不需要额外排序

容器失效提醒

std::vector 扩容时会移动内部元素，之前保存的元素指针、引用、迭代器可能失效。本文的 index_ 保存的是下标，不是 Task* ，因此扩容不会让索引直接悬空。

不过，如果后续给 TaskStore 增加 “删除任务” 或 “重排 tasks_” 功能，就必须同步更新 index_ ，否则下标会指向错误任务。

7.4 std::sort 和 std::transform ：不要手写常见循环

排序视图：

std::vector<const Task*> sortedByGroupAndName() const {
    std::vector<const Task*> view;
    view.reserve(tasks_.size());

    std::transform(tasks_.begin(), tasks_.end(), std::back_inserter(view), [](const Task& task) {
        return &task;
    });

    std::sort(view.begin(), view.end(), [](const Task* left, const Task* right) {
        if (left->group != right->group) {
            return left->group < right->group;
        }
        return left->name < right->name;
    });

    return view;
}

这里没有复制 Task ，而是创建 vector<const Task*> ：

  1. std::transform 把 Task 转成 const Task* 。
  2. std::sort 只移动指针，排序成本较低。
  3. 原始 tasks_ 顺序不变。

提取任务名：

std::vector<std::string> names() const {
    std::vector<std::string> result;
    result.reserve(tasks_.size());

    std::transform(tasks_.begin(), tasks_.end(), std::back_inserter(result), [](const Task& task) {
        return task.name;
    });

    return result;
}

std::transform 的语义是 “把 A 转成 B”。读代码的人一眼能看出这里不是过滤、不是统计，而是在做映射。

7.5 std::find_if ：把查找条件写在 Lambda 里

std::optional<std::reference_wrapper<Task>> findByName(const std::string& keyword) {
    const auto it = std::find_if(tasks_.begin(), tasks_.end(), [&](const Task& task) {
        return task.name.find(keyword) != std::string::npos;
    });

    if (it == tasks_.end()) {
        return std::nullopt;
    }
    return std::ref(*it);
}

std::find_if 接收一个谓词，也就是返回 bool 的可调用对象。这里的 Lambda：

[&](const Task& task) {
    return task.name.find(keyword) != std::string::npos;
}

含义是：

  • [&] ：按引用捕获外部变量，这里用到 keyword 。
  • (const Task& task) ：每次检查一个任务，不复制任务。
  • return ... ：名称里包含关键字就返回 true 。

对于小示例， [&] 很方便；在复杂异步代码中建议显式捕获需要的变量，例如 [keyword] 或 [weak_sink] ，这样更容易看清生命周期。

7.6 std::unique_ptr ：把后台任务所有权交给队列

void submit(std::unique_ptr<Task> task) {
    if (!task) {
        return;
    }

    {
        std::lock_guard<std::mutex> lock(mutex_);
        if (stopped_.load()) {
            throw std::runtime_error("cannot submit to stopped queue");
        }

        jobs_.push_back(std::move(task));
    }

    cv_.notify_one();
}

std::unique_ptr<Task> 表示队列独占任务对象。调用方这样提交：

queue.submit(std::make_unique<Task>(*task));

提交后，后台队列拥有那份任务对象。由于 unique_ptr 不能复制，错误的所有权共享会在编译期暴露出来。

jobs_.push_back(std::move(task)) 是关键：

  • 不写 std::move ：编译失败，因为 unique_ptr 禁止复制。
  • 写了 std::move ：把所有权从局部参数 task 转移到 jobs_ 。

注

本文为了演示 std::vector ，等待队列用的是 std::vector<std::unique_ptr<Task>> ，并通过 erase(jobs_.begin()) 取走首元素。这个操作会移动后续元素，复杂度是 O (n)。高频生产队列更常用 std::deque 、 std::queue 、无锁队列或现成线程池。

7.7 std::shared_ptr 和 std::weak_ptr ：异步回调不要随便延长生命周期

主线程创建结果收集器：

auto sink = std::make_shared<EventSink>();
std::weak_ptr<EventSink> weak_sink = sink;

然后把 weak_ptr 捕获进回调：

TaskQueue queue([weak_sink](TaskResult result) {
    if (auto locked = weak_sink.lock()) {
        locked->onResult(std::move(result));
    }
});

为什么不用 shared_ptr 直接捕获？

TaskQueue queue([sink](TaskResult result) {
    sink->onResult(std::move(result));
});

这段代码也能运行，但回调会持有一份 shared_ptr ，导致 EventSink 至少活到队列销毁。对于桌面 UI、Android 页面、游戏场景对象等生命周期明确的对象，这可能造成 “界面已经关闭，后台回调还把对象留住” 的问题。

weak_ptr 的用法更稳：

  • 对象还活着： weak_sink.lock() 得到临时 shared_ptr ，安全调用。
  • 对象已经销毁： lock() 返回空，回调直接跳过。

注意

std::shared_ptr 的引用计数操作是线程安全的，但它不会自动保护被管理对象本身。多个线程同时读写 EventSink::history_ 仍然需要 std::mutex 。

7.8 std::function 和 Lambda：把回调作为对象保存

队列里定义了一个回调类型：

using Callback = std::function<void(TaskResult)>;

意思是：保存任意一个 “接收 TaskResult 、返回 void ” 的可调用对象。

构造队列时传入 Lambda：

TaskQueue queue([weak_sink](TaskResult result) {
    if (auto locked = weak_sink.lock()) {
        locked->onResult(std::move(result));
    }
});

std::function 的优点是接口简单，调用方可以传：

  • 普通函数
  • 捕获变量的 Lambda
  • 函数对象
  • std::bind 生成的对象

代价是它做了类型擦除，可能有一次间接调用和小对象优化以外的分配成本。绝大多数业务回调可以接受这个成本；极端性能热点可以考虑模板参数或 auto 泛型接口。

7.9 多线程： thread + mutex + condition_variable + atomic

后台线程启动：

explicit TaskQueue(Callback callback)
    : callback_(std::move(callback)), worker_(&TaskQueue::run, this) {}

worker_(&TaskQueue::run, this) 表示开一个线程执行当前对象的 run() 成员函数。

等待任务：

cv_.wait(lock, [this] {
    return stopped_.load() || !jobs_.empty();
});

这里有三个关键点：

  1. std::condition_variable 必须配合 std::unique_lock<std::mutex> 使用。
  2. 等待要带谓词，因为条件变量可能虚假唤醒。
  3. 谓词里检查两个条件：收到停止请求，或者队列里有任务。

停止线程：

void stop() {
    stopped_.store(true);
    cv_.notify_all();
    if (worker_.joinable()) {
        worker_.join();
    }
}

std::atomic<bool> stopped_ 用来跨线程传递停止信号。 join() 表示等待后台线程真正退出。不要让一个仍然 joinable 的 std::thread 对象进入析构，否则程序会调用 std::terminate 。

计数器：

processed_.fetch_add(1, std::memory_order_relaxed);

这里的原子计数只用于展示处理进度，不用于保护 jobs_ 或 history_ ，所以 memory_order_relaxed 足够。共享容器仍然由互斥锁保护。

8. 移动语义到底减少了哪些拷贝

本文有几处移动语义值得单独看。

8.1 添加任务时移动参数

tasks_.push_back(Task{id, std::move(name), std::move(group), std::move(payload), std::move(note)});

addTask 的参数是按值接收的：

int addTask(std::string name,
            std::string group,
            TaskPayload payload,
            std::optional<std::string> note = std::nullopt)

这种写法适合 “函数要保存一份数据” 的场景：

  • 调用方传临时对象：参数可以直接从临时对象移动构造。
  • 调用方传左值：参数先复制一份，再移动进容器，语义清楚。

如果改成 const std::string& ，最后放进 Task 时仍然需要复制。对需要保存的数据来说，按值接收再移动是一种常见、易读的写法。

8.2 提交任务时移动 unique_ptr

jobs_.push_back(std::move(task));

unique_ptr 的 “不可复制” 是它的价值：任务所有权只能有一个拥有者。提交前拥有者是调用方，提交后拥有者是队列。

8.3 回调结果移动进历史记录

history_.push_back(std::move(result));

TaskResult 里有 std::string 。移动 TaskResult 时，字符串内部资源可以被转移到 history_ ，通常不需要重新分配和复制字符内容。

注

移动不是 “对象消失”。被移动后的对象仍然有效，但值处于可析构、可重新赋值的状态。不要依赖被移动对象原来的内容。

9. Lambda 和 JNI 封装：把平台边界收窄

本地示例里的任务名 jni callback name 只是为了引出一个常见场景：Android 项目里，C++ 后台任务完成后，经常需要回调 Java/Kotlin。

本文的本地可运行项目不依赖 Android，也不要求读者配置 NDK。下面只给出 JNI 边界封装的关键代码，帮助你理解 Lambda、 std::function 、 shared_ptr 、 weak_ptr 在 JNI 场景中的组合方式。

JNI 小节的假设条件

下面代码不是本文本地 CMake 项目的一部分。它假设你已经有一个 Android NDK 工程，并把前面的 TaskQueue 、 TaskResult 等核心 C++ 代码编译进 native target。

示例假设环境为：JDK 17、Android Gradle Plugin 8.7.3、Gradle 8.9、Android NDK r27c（ 27.2.12479018 ）、CMake 3.22.1。不同 Android Gradle Plugin 和 NDK 版本的 Gradle DSL、默认 STL、CMake 集成细节可能变化；JNI 的核心规则来自公开 JNI 规范和 Android 官方 JNI 文档。

Java 侧定义一个回调接口，文件路径示例： app/src/main/java/com/example/moderncpp/NativeTaskCallback.java

package com.example.moderncpp;

// NativeTaskCallback 是 Java/Kotlin 层接收 native 结果的接口。
public interface NativeTaskCallback {
    // id 是 native 任务 ID，message 是 native 处理结果。
    void onDone(int id, String message);
}

C++ 侧可以把 Java 回调对象包装成 std::function<void(TaskResult)> 。下面只保留关键边界代码，省略 Gradle、Activity、错误 UI 等内容。

文件路径示例： app/src/main/cpp/native_bridge.cpp

// app/src/main/cpp/native_bridge.cpp
// 作用：演示如何把 Java 回调对象包装成 C++ std::function。

#include <jni.h>

#include <functional>
#include <memory>
#include <string>
#include <utility>

// 假设 TaskResult 来自你的公共 C++ 代码。
struct TaskResult {
    int id{};
    std::string name;
    std::string output;
};

// AttachedEnv 用 RAII 管理“当前线程是否临时 attach 到 JVM”。
struct AttachedEnv {
    JavaVM* vm{};
    JNIEnv* env{};
    bool attached{};

    ~AttachedEnv() {
        if (attached && vm != nullptr) {
            vm->DetachCurrentThread();
        }
    }
};

// JavaCallback 持有 Java 回调对象的全局引用。
// enable_shared_from_this 允许成员函数安全创建 weak_ptr。
class JavaCallback : public std::enable_shared_from_this<JavaCallback> {
public:
    // 只通过 create 创建 JavaCallback，确保 shared_from_this() 有 shared_ptr 控制块可用。
    static std::shared_ptr<JavaCallback> create(JNIEnv* env, jobject callback) {
        JavaVM* vm = nullptr;
        env->GetJavaVM(&vm);
        return std::shared_ptr<JavaCallback>(new JavaCallback(vm, env, callback));
    }

    ~JavaCallback() {
        AttachedEnv attached_env = attach();
        if (attached_env.env != nullptr) {
            attached_env.env->DeleteGlobalRef(callback_);
            attached_env.env->DeleteGlobalRef(callback_class_);
        }
    }

    std::function<void(TaskResult)> toFunction() {
        std::weak_ptr<JavaCallback> weak_self = shared_from_this();

        return [weak_self](TaskResult result) {
            if (auto self = weak_self.lock()) {
                self->emit(result);
            }
        };
    }

private:
    JavaCallback(JavaVM* vm, JNIEnv* env, jobject callback) : vm_(vm) {
        callback_ = env->NewGlobalRef(callback);

        jclass local_class = env->GetObjectClass(callback);
        callback_class_ = static_cast<jclass>(env->NewGlobalRef(local_class));
        env->DeleteLocalRef(local_class);

        on_done_ = env->GetMethodID(callback_class_, "onDone", "(ILjava/lang/String;)V");
    }

    AttachedEnv attach() const {
        if (vm_ == nullptr) {
            return AttachedEnv{};
        }

        JNIEnv* env = nullptr;

        if (vm_->GetEnv(reinterpret_cast<void**>(&env), JNI_VERSION_1_6) == JNI_OK) {
            return AttachedEnv{vm_, env, false};
        }

        if (vm_->AttachCurrentThread(&env, nullptr) == JNI_OK) {
            return AttachedEnv{vm_, env, true};
        }

        return AttachedEnv{vm_, nullptr, false};
    }

    void emit(const TaskResult& result) {
        AttachedEnv attached_env = attach();
        JNIEnv* env = attached_env.env;
        if (env == nullptr || on_done_ == nullptr) {
            return;
        }

        jstring message = env->NewStringUTF(result.output.c_str());
        env->CallVoidMethod(callback_, on_done_, static_cast<jint>(result.id), message);
        env->DeleteLocalRef(message);
    }

    JavaVM* vm_{};
    jobject callback_{};
    jclass callback_class_{};
    jmethodID on_done_{};
};

这段 JNI 封装体现了几个规则：

  • JNIEnv* 只适合当前线程使用，跨线程回调前要通过 JavaVM 获取或 attach 当前线程。
  • Java 对象如果要跨出当前 JNI 调用作用域，需要 NewGlobalRef ；不用时必须 DeleteGlobalRef 。
  • C++ 异步回调里捕获 weak_ptr ，避免 native 任务队列把 Java 回调包装对象永久留住。
  • 不要依赖 Android Runtime 的内部结构、对象布局、 jmethodID 的内部表示或非公开 NDK API；跨版本只使用公开 JNI/NDK 接口。

如果你要把本文的本地示例迁移到 Android，建议把核心任务逻辑放在平台无关的 C++ 文件里，把 JNI 代码限制在很薄的一层。这样 C++ 单元测试仍然可以在本地跑，Android 层只负责参数转换和异常 / 回调边界。

10. 常见错误和排查思路

10.1 undefined reference to pthread_create

Linux 上如果手写编译命令，忘记加线程链接选项可能出现这个错误。本文 CMake 使用了：

find_package(Threads REQUIRED)
target_link_libraries(modern_cpp_stdlib_lab PRIVATE Threads::Threads)

如果你不用 CMake，而是直接使用 g++ ，可以尝试：

g++ -std=c++20 -Wall -Wextra -Wpedantic -pthread src/main.cpp -o modern_cpp_stdlib_lab

10.2 std::optional 或 std::variant 找不到

通常是编译标准不够。确认 CMake 中有：

set_target_properties(modern_cpp_stdlib_lab PROPERTIES
    CXX_STANDARD 20
    CXX_STANDARD_REQUIRED ON
)

如果你直接编译，确认命令中有：

-std=c++20

最低也要 C++17 才能使用 std::optional 和 std::variant 。

10.3 程序退出时崩溃或直接终止

检查是否有 std::thread 没有 join() 或 detach() 。本文在 TaskQueue::stop() 中调用：

if (worker_.joinable()) {
    worker_.join();
}

并且析构函数会调用 stop() 。真实项目中还要避免在工作线程自己内部调用 join() 自己。

10.4 回调里访问已经销毁的对象

不要在异步 Lambda 里裸捕获对象指针：

// 危险：owner 销毁后，回调还可能使用悬垂指针。
[owner](TaskResult result) {
    owner->onResult(std::move(result));
}

更稳的方式是捕获 std::weak_ptr ：

[weak_sink](TaskResult result) {
    if (auto locked = weak_sink.lock()) {
        locked->onResult(std::move(result));
    }
}

10.5 多线程下偶发输出错乱或数据不一致

检查共享数据是否都被锁保护。本文中：

  • TaskQueue::jobs_ 由 TaskQueue::mutex_ 保护。
  • EventSink::history_ 由 EventSink::mutex_ 保护。
  • processed_ 是 std::atomic<std::size_t> ，不需要再加锁。

不要以为用了 shared_ptr 就自动线程安全。 shared_ptr 保护的是控制块引用计数，不保护你对象内部的数据结构。

10.6 JNI 回调没有触发或直接崩溃

按顺序检查：

  1. Java 包名、类名、native 方法名是否和 JNI 导出函数匹配；更推荐在复杂项目里用 RegisterNatives 明确注册。
  2. GetMethodID 的签名是否正确，例如 (ILjava/lang/String;)V 表示参数是 int 和 String ，返回 void 。
  3. 跨线程调用 Java 前是否通过 JavaVM::AttachCurrentThread 获取当前线程的 JNIEnv* 。
  4. 跨 JNI 调用长期保存 Java 对象时是否使用了 NewGlobalRef 。
  5. 不再使用全局引用时是否调用了 DeleteGlobalRef 。

11. 小结

这个示例把一组常见现代 C++ 能力放在同一条业务链路里：

  • std::vector 保存任务， std::unordered_map 做快速索引， std::map 做有序统计。
  • std::sort 、 std::find_if 、 std::transform 让排序、查找、映射的意图更直接。
  • std::variant 表达多种任务载荷， std::optional 表达查找可能失败， std::function 表达回调。
  • std::unique_ptr 表达独占任务所有权， std::shared_ptr 表达共享结果对象， std::weak_ptr 用于异步回调中的生命周期检查。
  • std::thread 执行后台任务， std::mutex 保护共享容器， std::condition_variable 让线程等待任务， std::atomic 保存简单跨线程状态。

入门阶段不要急着把这些工具背成概念表。更有效的方式是像本文这样，把每个工具放回具体问题里：谁拥有对象？有没有可能失败？任务会不会跨线程？回调对象可能先销毁吗？这些问题想清楚，标准库类型的选择通常也会变清楚。
