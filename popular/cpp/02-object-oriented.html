C++ 面向对象：类、生命周期、继承和多态

C++ 面向对象：类、生命周期、继承和多态

C++ 的面向对象不是只背 “封装、继承、多态”。真正写代码时，更常遇到的问题是：

  • 对象什么时候构造，什么时候析构？
  • 拷贝构造和移动构造分别在什么场景发生？
  • 基类指针为什么能调用派生类重写后的函数？
  • 基类析构函数为什么经常要写成 virtual ？
  • override 、 virtual 、 std::unique_ptr 在项目里分别解决什么问题？

本文用一个可以直接编译运行的小项目，把这些问题放到同一段代码中观察。示例会实现一个 “通知系统”：不同通知渠道都继承自同一个基类，调用方只面向基类接口发送消息；消息内容对象会打印构造、拷贝、移动和析构日志，方便观察生命周期。

目标效果

复现完成后，应该能看懂一条完整链路：创建消息对象，触发拷贝或移动，把不同派生类对象放进同一个容器，通过基类指针调用虚函数，最后按正确顺序析构对象。

2. 最终目标和运行效果

创建一个名为 oop-lab 的 C++20 小项目。程序运行后会演示四件事：

  1. Message 类如何通过构造函数初始化对象，通过析构函数释放资源。
  2. 拷贝构造如何创建独立副本，移动构造如何转移资源所有权。
  3. EmailChannel 和 SmsChannel 如何继承 NotificationChannel 。
  4. std::vector<std::unique_ptr<NotificationChannel>> 如何保存不同派生类对象，并通过虚函数实现运行时多态。

预期输出中会包含类似内容。不同编译器和优化级别可能让局部对象析构日志的相邻位置略有差异，但主要顺序和关键字段应一致：

== object lifecycle ==
[Message ctor] id=1 text="server started"
[Message copy ctor] from id=1 to id=2
[Message move ctor] from id=1 to id=3
original after move: Message{id=1, text="<moved>"}
copy: Message{id=2, text="server started (copied)"}
moved: Message{id=3, text="server started"}

== polymorphism ==
[Channel ctor] name=email
[EmailChannel ctor] smtp_host=smtp.example.com
[Channel ctor] name=sms
[SmsChannel ctor] country_code=+86
[Message ctor] id=4 text="deployment finished"
EmailChannel(email) -> ops@example.com via smtp.example.com: deployment finished
SmsChannel(sms) -> +8613800000000 [+86]: deployment finished

== virtual destructor ==
[EmailChannel dtor] smtp_host=smtp.example.com
[Channel dtor] name=email
[SmsChannel dtor] country_code=+86
[Channel dtor] name=sms

验证时重点看：

  • Message copy ctor 说明发生了拷贝构造。
  • Message move ctor 说明发生了移动构造。
  • original after move 的文本变成 <moved> ，说明资源所有权已经被转移。
  • 同一个 channels 容器里既能保存 EmailChannel ，也能保存 SmsChannel 。
  • 删除派生类对象时，派生类析构函数和基类析构函数都被调用。

5. 核心源码

文件路径： src/main.cpp

// src/main.cpp
// 作用：演示 C++20 中的类、构造/析构、拷贝构造、移动构造、继承、多态和虚函数。

#include <iostream>
#include <memory>
#include <string>
#include <utility>
#include <vector>

// Message 表示一条通知消息。
// 这个类故意手写资源管理代码，用来演示拷贝构造、移动构造和析构。
// 真实项目里，普通文本更推荐直接使用 std::string，让标准库负责资源管理。
class Message {
public:
    // 构造函数：创建一个 Message，并为 text_ 分配独立字符串资源。
    explicit Message(std::string content)
        : id_(next_id()), text_(new std::string(std::move(content))) {
        std::cout << "[Message ctor] id=" << id_
                  << " text=\"" << text() << "\"\n";
    }

    // 拷贝构造函数：用另一个 Message 创建当前对象。
    // 这里必须深拷贝字符串，否则两个对象会指向同一块动态内存。
    Message(const Message& other)
        : id_(next_id()), text_(new std::string(other.text())) {
        std::cout << "[Message copy ctor] from id=" << other.id_
                  << " to id=" << id_ << '\n';
    }

    // 移动构造函数：从临时对象或即将不再使用的对象中接管资源。
    // noexcept 告诉标准容器：移动这个对象不会抛异常，有助于容器优先选择移动。
    Message(Message&& other) noexcept
        : id_(next_id()), text_(other.text_) {
        other.text_ = nullptr;
        std::cout << "[Message move ctor] from id=" << other.id_
                  << " to id=" << id_ << '\n';
    }

    // 拷贝赋值运算符：处理“已存在对象 = 另一个对象”的场景。
    Message& operator=(const Message& other) {
        if (this == &other) {
            return *this;
        }

        // 先构造新资源，再替换旧资源，避免中途失败后对象处于半更新状态。
        std::string* copied = new std::string(other.text());
        delete text_;
        text_ = copied;

        std::cout << "[Message copy assign] from id=" << other.id_
                  << " to id=" << id_ << '\n';
        return *this;
    }

    // 移动赋值运算符：释放当前资源，再接管 other 的资源。
    Message& operator=(Message&& other) noexcept {
        if (this == &other) {
            return *this;
        }

        delete text_;
        text_ = other.text_;
        other.text_ = nullptr;

        std::cout << "[Message move assign] from id=" << other.id_
                  << " to id=" << id_ << '\n';
        return *this;
    }

    // 析构函数：对象生命周期结束时自动调用，用来释放构造时申请的资源。
    ~Message() {
        std::cout << "[Message dtor] id=" << id_
                  << " text=\"" << text() << "\"\n";
        delete text_;
    }

    // const 成员函数：承诺不修改当前 Message 对象。
    const std::string& text() const {
        static const std::string moved_text = "<moved>";

        if (text_ == nullptr) {
            return moved_text;
        }

        return *text_;
    }

    // 普通成员函数：可以修改对象状态。
    void append_suffix(const std::string& suffix) {
        if (text_ != nullptr) {
            *text_ += suffix;
        }
    }

    // describe 用于稳定打印对象状态。
    std::string describe() const {
        return "Message{id=" + std::to_string(id_)
            + ", text=\"" + text() + "\"}";
    }

private:
    // static 局部变量在第一次执行到这里时初始化，之后在整个程序生命周期内保留。
    static int next_id() {
        static int current = 0;
        return ++current;
    }

    int id_;            // 每个 Message 的编号，便于观察构造和析构顺序。
    std::string* text_; // 手写拥有权指针，专门用于演示拷贝和移动。
};

// NotificationChannel 是通知渠道基类。
// 它定义所有渠道都应该具备的公共接口：name() 和 send(...)。
class NotificationChannel {
public:
    explicit NotificationChannel(std::string name)
        : name_(std::move(name)) {
        std::cout << "[Channel ctor] name=" << name_ << '\n';
    }

    // 基类打算被继承并通过基类指针删除时，析构函数应为 virtual。
    // 否则 delete 基类指针时可能不会调用派生类析构函数。
    virtual ~NotificationChannel() {
        std::cout << "[Channel dtor] name=" << name_ << '\n';
    }

    // 禁止拷贝：通知渠道通常代表一个外部连接或配置，不希望被无意复制。
    NotificationChannel(const NotificationChannel&) = delete;
    NotificationChannel& operator=(const NotificationChannel&) = delete;

    // 允许默认移动：如果未来需要把渠道对象转移到别处，可以保留移动能力。
    NotificationChannel(NotificationChannel&&) noexcept = default;
    NotificationChannel& operator=(NotificationChannel&&) noexcept = default;

    // 普通虚函数：派生类可以重写，也可以使用基类默认实现。
    virtual std::string name() const {
        return name_;
    }

    // 纯虚函数：基类只规定接口，不提供默认发送实现。
    // 因为存在纯虚函数，NotificationChannel 是抽象类，不能直接创建对象。
    virtual void send(const Message& message, const std::string& receiver) const = 0;

protected:
    // protected 成员函数只允许基类和派生类使用。
    // 它把公共的日志前缀逻辑收在基类中，避免派生类重复拼接。
    std::string prefix() const {
        return name() + "(" + name_ + ")";
    }

private:
    std::string name_; // 渠道内部名称。
};

// EmailChannel 继承 NotificationChannel，实现邮件发送渠道。
class EmailChannel final : public NotificationChannel {
public:
    EmailChannel(std::string name, std::string smtp_host)
        : NotificationChannel(std::move(name)),
          smtp_host_(std::move(smtp_host)) {
        std::cout << "[EmailChannel ctor] smtp_host=" << smtp_host_ << '\n';
    }

    ~EmailChannel() override {
        std::cout << "[EmailChannel dtor] smtp_host=" << smtp_host_ << '\n';
    }

    // override 要求编译器检查：这个函数必须真的重写了基类虚函数。
    std::string name() const override {
        return "EmailChannel";
    }

    void send(const Message& message, const std::string& receiver) const override {
        std::cout << prefix() << " -> " << receiver
                  << " via " << smtp_host_
                  << ": " << message.text() << '\n';
    }

private:
    std::string smtp_host_; // 邮件服务器地址。
};

// SmsChannel 继承 NotificationChannel，实现短信发送渠道。
class SmsChannel final : public NotificationChannel {
public:
    SmsChannel(std::string name, std::string country_code)
        : NotificationChannel(std::move(name)),
          country_code_(std::move(country_code)) {
        std::cout << "[SmsChannel ctor] country_code=" << country_code_ << '\n';
    }

    ~SmsChannel() override {
        std::cout << "[SmsChannel dtor] country_code=" << country_code_ << '\n';
    }

    std::string name() const override {
        return "SmsChannel";
    }

    void send(const Message& message, const std::string& receiver) const override {
        std::cout << prefix() << " -> " << receiver
                  << " [" << country_code_ << "]"
                  << ": " << message.text() << '\n';
    }

private:
    std::string country_code_; // 短信国家或地区代码。
};

// broadcast 只依赖 NotificationChannel 基类接口。
// 它不需要知道传入的是 EmailChannel 还是 SmsChannel。
void broadcast(
    const std::vector<std::unique_ptr<NotificationChannel>>& channels,
    const Message& message
) {
    for (const auto& channel : channels) {
        // channel 是 std::unique_ptr<NotificationChannel>。
        // send 是虚函数，这里会根据真实对象类型调用派生类实现。
        channel->send(message, channel->name() == "EmailChannel"
            ? "ops@example.com"
            : "+8613800000000");
    }
}

int main() {
    std::cout << "== object lifecycle ==\n";

    Message original("server started");

    // copy 通过拷贝构造得到独立副本。
    Message copy = original;
    copy.append_suffix(" (copied)");

    // moved 通过移动构造接管 original 的内部字符串资源。
    Message moved = std::move(original);

    std::cout << "original after move: " << original.describe() << '\n';
    std::cout << "copy: " << copy.describe() << '\n';
    std::cout << "moved: " << moved.describe() << '\n';

    std::cout << "\n== polymorphism ==\n";

    std::vector<std::unique_ptr<NotificationChannel>> channels;

    // make_unique 创建派生类对象，并把所有权交给 unique_ptr。
    // 容器中保存的是基类指针，因此可以放入不同派生类。
    channels.push_back(std::make_unique<EmailChannel>(
        "email",
        "smtp.example.com"
    ));
    channels.push_back(std::make_unique<SmsChannel>(
        "sms",
        "+86"
    ));

    Message notification("deployment finished");
    broadcast(channels, notification);

    std::cout << "\n== virtual destructor ==\n";

    // reset 会立刻释放 unique_ptr 管理的对象。
    // unique_ptr 会通过基类指针删除对象；因为基类析构函数是 virtual，
    // 所以派生类析构函数会先执行，然后再执行基类析构函数。
    channels[0].reset();
    channels[1].reset();

    return 0;
}

为什么示例手写 new 和 delete

这份代码手写了 std::string* text_ ，是为了让拷贝构造、移动构造和析构的职责变得可见。真实业务代码里，不要为了 “面向对象” 而手写裸指针资源管理。优先使用 std::string 、 std::vector 、 std::unique_ptr 、 std::shared_ptr 等 RAII 类型。

8. 按流程拆解程序

整体流程可以分成五步：

  1. 创建 Message original ，调用普通构造函数。
  2. 用 Message copy = original; 创建副本，调用拷贝构造函数。
  3. 用 Message moved = std::move(original); 创建新对象，调用移动构造函数。
  4. 创建 EmailChannel 和 SmsChannel ，用 std::unique_ptr<NotificationChannel> 保存到同一个容器。
  5. 调用 broadcast ，通过基类指针触发虚函数分派，程序结束时按正确顺序析构对象。

这条链路覆盖了面向对象最常见的两个维度：

  • 对象生命周期：构造、拷贝、移动、析构。
  • 对象行为抽象：基类定义接口，派生类提供具体实现，调用方只依赖基类。

9. 关键代码逐段解释

9.1 类：把数据和行为放在一起

Message 是一个类：

class Message {
public:
    explicit Message(std::string content);
    const std::string& text() const;
    void append_suffix(const std::string& suffix);

private:
    int id_;
    std::string* text_;
};

类把两类东西放在一起：

  • 数据成员：例如 id_ 、 text_ 。
  • 成员函数：例如 text() 、 append_suffix(...) 、析构函数。

public 和 private 控制访问权限：

访问控制含义
public类外部可以调用，构成这个类的公开接口
private只允许类内部访问，用来隐藏实现细节
protected允许类内部和派生类访问，常用于基类给派生类提供辅助能力

这个示例里，外部代码不能直接访问 text_ ，只能通过 text() 读取，通过 append_suffix(...) 修改。这样类可以保证内部资源始终按自己的规则管理。

9.2 构造函数：保证对象一创建就可用

构造函数写法如下：

explicit Message(std::string content)
    : id_(next_id()), text_(new std::string(std::move(content))) {
    std::cout << "[Message ctor] id=" << id_
              << " text=\"" << text() << "\"\n";
}

重点有三个：

  • 构造函数名字和类名相同，没有返回类型。
  • : id_(...), text_(...) 是成员初始化列表，优先用它初始化成员。
  • explicit 避免某些意外的隐式转换，例如把字符串参数悄悄转换成 Message 。

构造函数的目标不是 “执行一些代码”，而是让对象从出生开始就处于可用状态。这里的 Message 一创建就有编号和文本资源。

9.3 析构函数：对象结束时自动清理

析构函数写法如下：

~Message() {
    std::cout << "[Message dtor] id=" << id_
              << " text=\"" << text() << "\"\n";
    delete text_;
}

析构函数在对象生命周期结束时自动调用：

  • 局部变量离开作用域时调用。
  • 容器销毁元素时调用。
  • delete 某个动态对象时调用。
  • std::unique_ptr 被销毁时，会自动 delete 它管理的对象。

这就是 RAII 的核心：资源在构造时获取，在析构时释放。真实项目中，把资源交给标准库对象管理，能显著减少手写 delete 的错误。

9.4 拷贝构造：创建独立副本

拷贝构造函数如下：

Message(const Message& other)
    : id_(next_id()), text_(new std::string(other.text())) {
    std::cout << "[Message copy ctor] from id=" << other.id_
              << " to id=" << id_ << '\n';
}

调用场景：

Message copy = original;

因为 Message 内部有 std::string* ，所以不能只复制指针地址。如果两个对象指向同一个字符串，两个析构函数都会 delete 同一块内存，程序行为会出错。

所以这里要做深拷贝：

text_(new std::string(other.text()))

它分配一块新字符串，把 other 的文本内容复制进去。这样 copy 和 original 管理的是两份独立资源。

9.5 移动构造：转移资源所有权

移动构造函数如下：

Message(Message&& other) noexcept
    : id_(next_id()), text_(other.text_) {
    other.text_ = nullptr;
    std::cout << "[Message move ctor] from id=" << other.id_
              << " to id=" << id_ << '\n';
}

调用场景：

Message moved = std::move(original);

std::move(original) 本身不移动任何字节，它只是把 original 转换成 “可以被移动” 的右值表达式。真正的资源转移发生在移动构造函数里：

text_(other.text_);
other.text_ = nullptr;

这两行的意思是：

  1. 新对象 moved 接管原来 original 指向的字符串。
  2. 把 original.text_ 置空，避免两个对象同时释放同一块内存。

被移动后的对象仍然必须能安全析构、能被重新赋值，但它的业务值通常不应该再被依赖。示例用 <moved> 明确显示这个状态。

9.6 拷贝赋值和移动赋值

构造处理 “新对象从谁而来”，赋值处理 “已存在对象变成谁”。

拷贝赋值：

Message& operator=(const Message& other);

移动赋值：

Message& operator=(Message&& other) noexcept;

它们都返回 Message& ，是为了支持连续赋值这类表达式：

a = b = c;

如果一个类手写了析构函数、拷贝构造、拷贝赋值、移动构造或移动赋值，通常要一起考虑它们之间是否一致。这就是常说的 Rule of Five。

Rule of Zero

在业务代码中，更推荐 Rule of Zero：不要手写析构、拷贝、移动，让成员对象自己管理资源。例如把 std::string* text_ 改成 std::string text_ 后， Message 可以删除大部分手写生命周期代码。

9.7 继承：复用接口，而不是复制代码

基类：

class NotificationChannel {
public:
    virtual ~NotificationChannel();
    virtual std::string name() const;
    virtual void send(const Message& message, const std::string& receiver) const = 0;
};

派生类：

class EmailChannel final : public NotificationChannel {
public:
    std::string name() const override;
    void send(const Message& message, const std::string& receiver) const override;
};

public NotificationChannel 表示公有继承。可以理解为： EmailChannel 是一种 NotificationChannel 。因此 EmailChannel* 或 std::unique_ptr<EmailChannel> 可以在合适场景下转成基类指针使用。

本文的继承主要用来表达统一接口：

NotificationChannel
├── EmailChannel
└── SmsChannel

调用方只知道 “这是一个通知渠道”，不需要知道它是邮件还是短信。

9.8 纯虚函数和抽象类

send 后面的 = 0 表示纯虚函数：

virtual void send(const Message& message, const std::string& receiver) const = 0;

包含纯虚函数的类是抽象类，不能直接实例化：

NotificationChannel channel("base"); // 编译错误

它的作用是定义接口：所有具体通知渠道都必须实现 send(...) 。如果派生类忘记实现，派生类也会保持抽象，不能创建对象。

9.9 虚函数和运行时多态

broadcast 函数只依赖基类：

void broadcast(
    const std::vector<std::unique_ptr<NotificationChannel>>& channels,
    const Message& message
) {
    for (const auto& channel : channels) {
        channel->send(message, channel->name() == "EmailChannel"
            ? "ops@example.com"
            : "+8613800000000");
    }
}

channel 的静态类型是：

std::unique_ptr<NotificationChannel>

但它指向的真实对象可能是：

EmailChannel
SmsChannel

因为 send(...) 是虚函数，所以调用：

channel->send(...);

会在运行时根据真实对象类型分派到对应实现。这就是运行时多态。

9.10 override 和 final

派生类里写：

void send(const Message& message, const std::string& receiver) const override;

override 会让编译器检查：这个函数确实重写了基类中的某个虚函数。如果你把参数写错，编译器会直接报错。

例如误写成：

void send(Message& message, const std::string& receiver) const override;

这里少了 const Message& ，签名不同。因为有 override ，编译器能及时发现问题。

final 表示这个类不能再被继承：

class EmailChannel final : public NotificationChannel

示例中加 final 是为了表达：邮件渠道和短信渠道就是叶子类型，不再设计更细的派生类。

9.11 为什么基类析构函数要是 virtual

容器类型是：

std::vector<std::unique_ptr<NotificationChannel>> channels;

它保存的是基类指针。实际对象可能是 EmailChannel 或 SmsChannel 。

调用 channels[0].reset() 或程序结束清理容器时， std::unique_ptr<NotificationChannel> 会通过基类指针删除对象：

delete base_pointer;

如果基类析构函数不是 virtual ，通过基类指针删除派生类对象时，派生类析构函数可能不会正确执行。示例里的基类写成：

virtual ~NotificationChannel() {
    std::cout << "[Channel dtor] name=" << name_ << '\n';
}

这样删除时会先调用派生类析构函数，再调用基类析构函数：

[EmailChannel dtor] smtp_host=smtp.example.com
[Channel dtor] name=email

经验规则：只要一个类打算作为多态基类使用，就把析构函数写成 virtual 。

9.12 std::unique_ptr 表达独占所有权

创建渠道对象：

channels.push_back(std::make_unique<EmailChannel>(
    "email",
    "smtp.example.com"
));

这里有三层含义：

  • std::make_unique<EmailChannel>(...) 创建一个 EmailChannel 对象。
  • 返回的 std::unique_ptr<EmailChannel> 独占这个对象的所有权。
  • 放进 std::vector<std::unique_ptr<NotificationChannel>> 后，容器负责持有这些对象。

std::unique_ptr 不能被复制，只能移动。这正好表达 “同一时间只有一个所有者” 的语义，避免多个地方都以为自己应该释放同一个对象。

10. 背后的原理

10.1 对象生命周期由作用域和所有权决定

局部对象：

Message notification("deployment finished");

离开所在作用域时自动析构。

动态对象：

std::make_unique<EmailChannel>("email", "smtp.example.com");

由 std::unique_ptr 管理。 unique_ptr 被销毁时自动释放对象。

容器对象：

std::vector<std::unique_ptr<NotificationChannel>> channels;

离开作用域时先销毁容器，容器再销毁内部元素，元素中的 unique_ptr 再删除各自管理的渠道对象。

10.2 拷贝和移动是两种不同的对象转移策略

拷贝的语义是 “复制一份等价内容”：

Message copy = original;

拷贝后两个对象都应该能独立使用和独立析构。

移动的语义是 “把资源从一个对象转移到另一个对象”：

Message moved = std::move(original);

移动通常比深拷贝更便宜，尤其是对象内部持有堆内存、文件句柄、网络连接等资源时。但被移动对象只能保证处于有效但未指定的状态，不要继续依赖它原来的业务值。

10.3 多态依赖虚函数，而不是变量名

这行代码：

channel->send(message, receiver);

能调用到不同派生类实现，关键不在 channel 这个变量名，而在两个条件：

  1. 通过基类指针或引用调用。
  2. 被调用的函数是 virtual 。

如果 send 不是虚函数，那么通过 NotificationChannel* 调用时会绑定到基类版本。本文中 send 是纯虚函数，基类没有默认实现，所以派生类必须提供实现。

10.4 不要依赖虚表布局细节

很多资料会用 “虚表”“虚指针” 解释虚函数分派，这有助于理解性能和底层模型。但 C++ 标准并不要求所有编译器用完全相同的虚表布局。

本文只依赖稳定公开的语言规则：

  • virtual 启用动态分派。
  • override 检查重写关系。
  • 多态基类应使用虚析构函数。
  • 通过基类指针或引用调用虚函数时，会根据真实对象类型选择实现。

不要在普通业务代码中根据某个编译器的虚表内存布局做偏移访问。这属于实现细节，跨编译器、跨平台、跨版本都可能失效。

11. 常见错误和排查思路

11.1 忘记把基类析构函数写成 virtual

问题代码：

class Base {
public:
    ~Base() = default;
};

如果通过 Base* 删除 Derived 对象，派生类资源可能没有正确释放。

排查：

  • 只要类中有虚函数，通常就应该检查析构函数是否为 virtual 。
  • 多态基类可写成 virtual ~Base() = default; 。

11.2 重写函数签名写错

错误类似：

marked 'override', but does not override

排查：

  • 检查函数名、参数类型、 const 限定、引用限定是否和基类一致。
  • 保留 override ，不要为了消除报错把它删掉。这个报错通常正是在帮你发现 bug。

11.3 抽象类不能实例化

错误类似：

cannot declare variable 'channel' to be of abstract type

排查：

  • 检查类里是否有纯虚函数没有实现。
  • 如果你需要创建对象，应创建具体派生类，例如 EmailChannel 。
  • 如果你只想表达接口，应使用指针或引用，例如 NotificationChannel& 、 std::unique_ptr<NotificationChannel> 。

11.4 拷贝含裸指针的对象导致重复释放

问题代码：

class BadMessage {
public:
    explicit BadMessage(std::string text)
        : text_(new std::string(std::move(text))) {}

    ~BadMessage() {
        delete text_;
    }

private:
    std::string* text_;
};

这个类没有手写拷贝构造，编译器可能生成默认拷贝构造：直接复制 text_ 指针地址。两个对象析构时会重复 delete 。

排查：

  • 含有拥有权裸指针的类必须认真设计拷贝、移动和析构。
  • 更推荐把成员改成 std::string text_; 或 std::unique_ptr<std::string> text_; 。
  • 优先遵循 Rule of Zero，让标准库类型管理资源。

11.5 移动后继续依赖原对象业务值

问题代码：

Message moved = std::move(original);
std::cout << original.text() << '\n';

示例里 original.text() 会返回 <moved> ，但真实标准库类型被移动后的内容不一定是某个固定值。它只保证对象仍然有效，可以析构或重新赋值。

排查：

  • 移动后不要继续依赖原对象的业务内容。
  • 如果还要使用原对象，先给它重新赋值。

11.6 忘记包含头文件

错误类似：

'unique_ptr' is not a member of 'std'
'vector' is not a member of 'std'

排查：

  • std::unique_ptr 和 std::make_unique 需要 #include <memory> 。
  • std::vector 需要 #include <vector> 。
  • std::move 需要 #include <utility> 。
  • std::string 需要 #include <string> 。

12. 可以继续练习的改造

你可以在当前项目上做四组练习：

  1. 增加 WebhookChannel ，继承 NotificationChannel ，实现自己的 send(...) 。
  2. 把 Message 的 std::string* text_ 改成 std::string text_ ，删除手写析构、拷贝和移动函数，体会 Rule of Zero。
  3. 删除 NotificationChannel 析构函数前的 virtual ，观察编译器警告和运行输出，再恢复正确写法。
  4. 故意把 SmsChannel::send 的参数改错，同时保留 override ，观察编译器如何报错。

每次修改后重新编译运行，用输出验证你对对象生命周期和虚函数分派的判断。

13. 小结

主题关键点
类用公开接口隐藏内部数据和实现细节
构造函数让对象一创建就处于可用状态
析构函数在对象生命周期结束时释放资源
拷贝构造创建独立副本，资源拥有者通常需要深拷贝
移动构造转移资源所有权，被移动对象仍要能安全析构
继承用基类表达统一接口，用派生类提供具体行为
虚函数通过基类指针或引用调用时实现运行时多态
虚析构函数多态基类通过基类指针删除对象时必须重视
override让编译器检查派生类是否真的重写了虚函数
std::unique_ptr表达独占所有权，避免手动 delete

继续学习时，可以把本文的单文件示例拆成多文件项目：把 Message 、 NotificationChannel 、 EmailChannel 、 SmsChannel 的声明放进头文件，把成员函数实现放进源文件。这样能进一步练习类声明、成员函数定义、头文件依赖和链接错误排查。
