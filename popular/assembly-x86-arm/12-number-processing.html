数字处理

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的整数数字处理。

前面章节经常用退出码观察数字，但真实程序更多时候需要：

  • 把整数转成十进制字符串并输出。
  • 把 ASCII 字符串里的数字解析成整数。
  • 处理正负号、进制、余数和溢出。
  • 在寄存器和内存之间移动不同宽度的数字。

重点讲两个最实用的方向：

整数 -> 十进制 ASCII 字符串
十进制 ASCII 字符串 -> 整数

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的整数指令基本相同；差异主要在入口、链接方式和输出方式。

1. 一张表先建立全局印象

操作x86-64 LinuxAArch64 LinuxmacOS arm64
无符号除法div divisorudiv dst, dividend, divisor同 AArch64
有符号除法idiv divisorsdiv dst, dividend, divisor同 AArch64
余数div/idiv 后在 %rdx常用 msub rem, q, divisor, dividend同 AArch64
乘以 10imul $10, reg, regmul 或 add/lsl 组合同 AArch64
字符转数字sub $'0', reg8sub wN, wN, #'0'同 AArch64
数字转字符add $'0', reg8add wN, wN, #'0'同 AArch64
输出write syscallwrite syscall调用 libSystem _write
退出exit syscallexit syscallmain 返回

两个关键差异：

  • x86-64 的 div/idiv 使用隐式寄存器，结果固定放在 %rax/%rdx 。
  • AArch64 的 udiv/sdiv 只给商，余数需要手动计算。

2. 整数转十进制字符串的思路

把 12345 转成 "12345\n" ，最常见的方法是反复除以 10 ：

12345 / 10 = 1234 余 5  -> '5'
1234  / 10 = 123  余 4  -> '4'
123   / 10 = 12   余 3  -> '3'
12    / 10 = 1    余 2  -> '2'
1     / 10 = 0    余 1  -> '1'

余数出现的顺序是 5, 4, 3, 2, 1 ，和最终字符串相反。所以常见写法是：

1. 准备一个缓冲区
2. 指针先指向缓冲区末尾
3. 每得到一位数字，就从后往前写
4. 最后 write(pointer, length)

数字位转 ASCII 字符只需要加 '0' ：

5 + '0' = '5'

因为 ASCII 中 '0' 到 '9' 是连续编码。

3. 三个平台示例：输出数字 12345

目标输出：

12345

3.1 x86-64 Linux

文件名： number-x86-64.s

.section .bss
.lcomm buf, 32                              # 32 字节缓冲区，足够放 64 位整数的十进制文本

.section .text
.global _start
_start:
    # 目标：把整数 12345 转成 ASCII 字符串并输出。
    #
    # rax = 当前要转换的数
    # rbx = 除数 10
    # rcx = 输出长度
    # rsi = 当前写入位置，从缓冲区末尾往前移动

    mov $12345, %rax                         # rax = 要转换的整数
    mov $10, %rbx                            # rbx = 10，用于十进制除法

    lea buf + 31(%rip), %rsi                 # rsi 指向缓冲区最后一个字节
    movb $10, (%rsi)                         # 最后放一个换行符 '\n'
    mov $1, %rcx                             # rcx = 当前字符串长度，先包含换行符

convert_loop:
    # x86-64 div 使用隐式被除数 rdx:rax。
    # 做 64 位无符号除法前，要把 rdx 清零。
    xor %rdx, %rdx                           # rdx = 0，准备 rdx:rax / rbx
    div %rbx                                 # rax = 商，rdx = 余数

    # 余数一定在 0..9 之间。
    # dl 是 rdx 的低 8 位，加上 '0' 就得到 ASCII 数字字符。
    add $'0', %dl                            # dl = '0' + 余数

    dec %rsi                                 # 写入位置向前移动 1 字节
    mov %dl, (%rsi)                          # 保存这一位数字
    inc %rcx                                 # 字符串长度 + 1

    test %rax, %rax                          # 商是否为 0？
    jnz convert_loop                         # 商不为 0，继续处理下一位

    # write(1, rsi, rcx)
    mov $1, %rax                             # rax = 1，Linux x86-64 write
    mov $1, %rdi                             # rdi = 1，stdout
    mov %rcx, %rdx                           # rdx = 字符串长度
    syscall

    # exit(0)
    mov $60, %rax                            # rax = 60，Linux x86-64 exit
    xor %rdi, %rdi                           # rdi = 0
    syscall

编译运行：

as --64 number-x86-64.s -o number-x86-64.o
ld number-x86-64.o -o number-x86-64
./number-x86-64

预期输出：

12345

3.2 AArch64 Linux

文件名： number-aarch64.s

.section .bss
.balign 8
buf:
    .skip 32                                // 32 字节缓冲区

.section .text
.global _start
_start:
    // 目标：把整数 12345 转成 ASCII 字符串并输出。
    //
    // x0 = 当前要转换的数
    // x1 = 当前写入位置
    // x3 = 输出长度
    // x4 = 除数 10

    mov x0, #12345                           // x0 = 要转换的整数
    mov x4, #10                              // x4 = 10

    adrp x1, buf                             // x1 = buf 所在页
    add x1, x1, :lo12:buf                    // x1 = buf 的完整地址
    add x1, x1, #31                          // x1 指向缓冲区最后一个字节

    mov w2, #10                              // w2 = '\n'
    strb w2, [x1]                            // 最后放一个换行符
    mov x3, #1                               // x3 = 当前字符串长度，先包含换行符

convert_loop:
    // udiv 只得到商，不会自动给余数。
    // q = x0 / 10
    // rem = x0 - q * 10
    udiv x5, x0, x4                          // x5 = 商
    msub x6, x5, x4, x0                      // x6 = x0 - x5 * x4，也就是余数

    add w6, w6, #'0'                         // w6 = ASCII 数字字符
    sub x1, x1, #1                           // 写入位置向前移动 1 字节
    strb w6, [x1]                            // 保存这一位数字
    add x3, x3, #1                           // 字符串长度 + 1

    mov x0, x5                               // x0 = 商
    cbnz x0, convert_loop                    // 商不为 0，继续处理下一位

    // write(1, x1, x3)
    mov x0, #1                               // x0 = 1，stdout
    mov x2, x3                               // x2 = 字符串长度
    mov x8, #64                              // x8 = 64，Linux AArch64 write
    svc #0

    // exit(0)
    mov x0, #0                               // x0 = 0
    mov x8, #93                              // x8 = 93，Linux AArch64 exit
    svc #0

编译运行：

as number-aarch64.s -o number-aarch64.o
ld number-aarch64.o -o number-aarch64
./number-aarch64

预期输出：

12345

3.3 macOS arm64

文件名： number-macos-arm64.s

.data
buf:
    .space 32                                // 32 字节缓冲区

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _write，所以先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    mov x0, #12345                           // x0 = 要转换的整数
    mov x4, #10                              // x4 = 10

    adrp x1, buf@PAGE                        // x1 = buf 所在页
    add x1, x1, buf@PAGEOFF                  // x1 = buf 的完整地址
    add x1, x1, #31                          // x1 指向缓冲区最后一个字节

    mov w2, #10                              // w2 = '\n'
    strb w2, [x1]                            // 最后放一个换行符
    mov x3, #1                               // x3 = 当前字符串长度

convert_loop:
    udiv x5, x0, x4                          // x5 = 商
    msub x6, x5, x4, x0                      // x6 = 余数

    add w6, w6, #'0'                         // w6 = ASCII 数字字符
    sub x1, x1, #1                           // 写入位置向前移动
    strb w6, [x1]                            // 保存数字字符
    add x3, x3, #1                           // 长度 + 1

    mov x0, x5                               // x0 = 商
    cbnz x0, convert_loop                    // 商不为 0 就继续

    // 调用 libSystem 的 write(1, x1, x3)。
    mov x0, #1                               // x0 = stdout
    mov x2, x3                               // x2 = 字符串长度
    bl _write

    // main 返回 0。
    mov x0, #0
    ldp x29, x30, [sp], #16
    ret

编译运行：

clang number-macos-arm64.s -o number-macos-arm64
./number-macos-arm64

预期输出：

12345

4. 处理数字 0

上面的转换循环适合正整数。如果输入是 0 ，反复除以 10 的循环也能写，但很多程序会先特殊处理：

if (value == 0) {
    output "0\n"
}

x86-64：

test %rax, %rax
jz value_is_zero

AArch64/macOS arm64：

cbz x0, value_is_zero

原因很简单： 0 没有 “更高位” 可以继续除，直接输出 '0' 最清楚。

5. 处理负数

处理有符号十进制输出时，常见步骤是：

1. 判断数字是否小于 0
2. 如果是负数，先输出 '-'
3. 把绝对值转成十进制
4. 再输出数字部分

x86-64 判断负数：

cmp $0, %rax
jl negative

AArch64/macOS arm64 判断负数：

cmp x0, #0
b.lt negative

取负：

neg %rax            # x86-64
neg x0, x0          // AArch64/macOS arm64

注意一个边界：最小有符号整数不能用同样宽度的正数表示。例如 64 位的 -9223372036854775808 取绝对值会溢出。入门阶段可以先避开这个极端值，真实库函数需要专门处理。

6. ASCII 字符串转整数

把 "123" 转成整数的思路是：

value = 0

读到 '1':
    value = value * 10 + 1 = 1

读到 '2':
    value = value * 10 + 2 = 12

读到 '3':
    value = value * 10 + 3 = 123

字符转数字只需要减 '0' ：

'7' - '0' = 7

7. 示例片段：解析 "123"

7.1 x86-64

.section .rodata
digits:
    .ascii "123"
digits_len = . - digits

.section .text
    lea digits(%rip), %rsi                  # rsi = 当前字符地址
    mov $digits_len, %rcx                   # rcx = 剩余字符数
    xor %rax, %rax                          # rax = value = 0

parse_loop:
    movzbq (%rsi), %rbx                     # rbx = 当前 ASCII 字符
    sub $'0', %rbx                          # rbx = 当前数字 0..9

    imul $10, %rax, %rax                    # value *= 10
    add %rbx, %rax                          # value += digit

    inc %rsi                                # 指向下一个字符
    dec %rcx                                # 剩余字符数 - 1
    jnz parse_loop

循环结束后， %rax = 123 。

7.2 AArch64/macOS arm64

    // 假设 x1 指向字符串，x2 是长度。
    mov x0, #0                              // x0 = value = 0
    mov x4, #10                             // x4 = 10

parse_loop:
    ldrb w3, [x1], #1                       // w3 = *x1，然后 x1++
    sub w3, w3, #'0'                        // w3 = 当前数字 0..9

    mul x0, x0, x4                          // value *= 10
    add x0, x0, x3                          // value += digit

    subs x2, x2, #1                         // 长度 - 1，并更新 NZCV
    b.ne parse_loop

循环结束后， x0 = 123 。

8. 验证字符是不是数字

解析外部输入时，不能假设每个字符都是数字。应该检查：

'0' <= ch <= '9'

x86-64：

cmp $'0', %al
jb not_digit

cmp $'9', %al
ja not_digit

AArch64/macOS arm64：

cmp w3, #'0'
b.lo not_digit

cmp w3, #'9'
b.hi not_digit

这里用无符号条件 jb/ja 、 b.lo/b.hi ，因为 ASCII 字节天然是 0..255 的无符号值。

9. 常见进制处理

十进制每次乘除 10 。其他进制只是基数不同：

进制解析时输出时
二进制value = value * 2 + digit反复除以 2 或移位取 bit
八进制value = value * 8 + digit反复除以 8
十进制value = value * 10 + digit反复除以 10
十六进制value = value * 16 + digit反复除以 16

如果基数是 2 的幂，可以用移位替代乘法：

shl $4, %rax        # x86-64：value *= 16
lsl x0, x0, #4      // AArch64：value *= 16

十六进制数字字符需要额外处理：

0..9 -> '0'..'9'
10..15 -> 'a'..'f'

10. 溢出问题

解析数字时， value = value * 10 + digit 可能溢出。

例如 64 位无符号整数最大值是：

18446744073709551615

如果继续乘以 10 或加数字，就会超过 64 位。

入门示例通常先忽略溢出；真实程序应该在乘法和加法之前检查：

如果 value > UINT64_MAX / 10，乘以 10 一定溢出
如果 value == UINT64_MAX / 10 且 digit > UINT64_MAX % 10，加 digit 会溢出

x86-64 的 mul/imul 、 add 会更新标志位；AArch64 可以用 adds 、 umulh 等指令辅助检测。后续写健壮解析器时再深入。

11. 常见错误

11.1 x86-64 除法前忘记清理 %rdx

div %rbx

div 用的是 %rdx:%rax 这个组合被除数。做普通 64 位无符号除法前通常要写：

xor %rdx, %rdx
div %rbx

否则 %rdx 里的旧值会参与除法，结果可能错误，甚至触发除法异常。

11.2 AArch64 以为 udiv 会给余数

udiv x5, x0, x4

这只得到商。余数常用 msub ：

msub x6, x5, x4, x0     // x6 = x0 - x5 * x4

11.3 写数字时顺序反了

如果直接把每次除法得到的余数从前往后写：

12345 -> 5 4 3 2 1

结果会变成 "54321" 。所以常见做法是从缓冲区末尾往前写，或者先写入临时栈再反转。

11.4 把字符数字和整数数字混淆

字符 '7' 的 ASCII 编码不是整数 7 ，而是 55 。要转换：

sub $'0', %al       # x86-64：字符 -> 数字
add $'0', %al       # x86-64：数字 -> 字符
sub w0, w0, #'0'    // AArch64：字符 -> 数字
add w0, w0, #'0'    // AArch64：数字 -> 字符

11.5 忘记字符串长度

write 不看 \0 ， write 只看长度。整数转字符串时，必须准确维护长度：

数字位数 + 换行符长度

否则会输出多余字节，或者少输出一部分。
