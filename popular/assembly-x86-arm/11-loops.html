循环结构

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的循环结构。

高级语言里的循环通常写成：

sum = 0;

for (i = 1; i <= 10; i++) {
    sum += i;
}

汇编里没有 for 、 while 这些关键字。循环本质上是：

1. 设置初始值
2. 比较循环条件
3. 条件不成立就跳出
4. 执行循环体
5. 更新计数器或指针
6. 跳回条件检查位置

也就是说，循环就是 “条件判断 + 跳转 + 状态更新”。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的循环相关指令基本相同；差异主要在入口、链接方式和系统调用 / 退出方式。

最常见的循环模板：

# x86-64 AT&T
loop_start:
    cmp $10, %rax
    jg loop_done
    # body
    add $1, %rax
    jmp loop_start
loop_done:
// AArch64/macOS arm64
loop_start:
    cmp x0, #10
    b.gt loop_done
    // body
    add x0, x0, #1
    b loop_start
loop_done:

x86-64 条件跳转写成 jg 、 jle 、 jne 这种形式；AArch64 条件跳转写成 b.gt 、 b.le 、 b.ne 这种形式。

2. 循环和条件判断的关系

高级语言里的 while ：

while (i <= 10) {
    sum += i;
    i++;
}

可以拆成汇编视角：

loop_start:
    如果 i > 10，跳出循环
    sum += i
    i++
    跳回 loop_start

loop_done:
    循环结束后的代码

关键点是：

  • 循环顶部通常有一次比较。
  • 条件失败时跳到循环外。
  • 循环体最后通常会更新计数器。
  • 更新之后用无条件跳转回到循环顶部。

如果忘记更新计数器，就会进入死循环：

loop_start:
    cmp $10, %rax
    jg loop_done
    # 忘了 add $1, %rax
    jmp loop_start

3. 三个平台示例：计算 1 到 10 的和

目标逻辑：

sum = 0;
i = 1;

while (i <= 10) {
    sum += i;
    i++;
}

return sum;

计算结果：

1 + 2 + 3 + ... + 10 = 55

预期退出码是 55 。

3.1 x86-64 Linux

文件名： loop-x86-64.s

.section .text
.global _start
_start:
    # 目标：
    # sum = 0;
    # for (i = 1; i <= 10; i++) sum += i;
    # 最终 sum = 55。
    #
    # 这里用：
    # rax 保存 i
    # rbx 保存 sum

    mov $1, %rax                             # rax = i = 1
    mov $0, %rbx                             # rbx = sum = 0

loop_start:
    # 判断循环条件 i <= 10。
    #
    # cmp $10, %rax 表示临时计算 rax - 10。
    # 如果 rax > 10，说明 i 已经超过上界，跳出循环。
    cmp $10, %rax                            # 比较 i 和 10
    jg loop_done                             # 如果 i > 10，跳到 loop_done

    # 循环体：sum += i
    add %rax, %rbx                           # rbx = rbx + rax

    # 更新计数器：i++
    add $1, %rax                             # rax = rax + 1

    # 无条件跳回循环顶部，继续检查条件。
    jmp loop_start

loop_done:
    # exit(sum)
    mov %rbx, %rdi                           # rdi = 55，退出码
    mov $60, %rax                            # rax = 60，Linux x86-64 exit
    syscall

编译运行：

as --64 loop-x86-64.s -o loop-x86-64.o
ld loop-x86-64.o -o loop-x86-64
./loop-x86-64
echo $?

预期输出：

55

3.2 AArch64 Linux

文件名： loop-aarch64.s

.section .text
.global _start
_start:
    // 目标：
    // sum = 0;
    // for (i = 1; i <= 10; i++) sum += i;
    // 最终 sum = 55。
    //
    // 这里用：
    // x0 保存 i
    // x1 保存 sum

    mov x0, #1                               // x0 = i = 1
    mov x1, #0                               // x1 = sum = 0

loop_start:
    // 判断循环条件 i <= 10。
    //
    // cmp x0, #10 表示临时计算 x0 - 10。
    // 如果 x0 > 10，说明 i 已经超过上界，跳出循环。
    cmp x0, #10                              // 比较 i 和 10
    b.gt loop_done                           // 如果 i > 10，跳到 loop_done

    // 循环体：sum += i
    add x1, x1, x0                           // x1 = x1 + x0

    // 更新计数器：i++
    add x0, x0, #1                           // x0 = x0 + 1

    // 无条件跳回循环顶部，继续检查条件。
    b loop_start

loop_done:
    // exit(sum)
    mov x0, x1                               // x0 = 55，退出码
    mov x8, #93                              // x8 = 93，Linux AArch64 exit
    svc #0

编译运行：

as loop-aarch64.s -o loop-aarch64.o
ld loop-aarch64.o -o loop-aarch64
./loop-aarch64
echo $?

预期输出：

55

3.3 macOS arm64

文件名： loop-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 目标：
    // sum = 0;
    // for (i = 1; i <= 10; i++) sum += i;
    // 最终 main 返回 55。

    mov x0, #1                               // x0 = i = 1
    mov x1, #0                               // x1 = sum = 0

loop_start:
    cmp x0, #10                              // 比较 i 和 10
    b.gt loop_done                           // 如果 i > 10，跳出循环

    add x1, x1, x0                           // sum += i
    add x0, x0, #1                           // i++
    b loop_start                             // 继续循环

loop_done:
    // main 的返回值放在 x0/w0。
    // echo $? 会看到低 8 位，也就是 55。
    mov x0, x1                               // x0 = sum = 55
    ret

编译运行：

clang loop-macos-arm64.s -o loop-macos-arm64
./loop-macos-arm64
echo $?

预期输出：

55

4. while 循环模板

while 的特点是：先判断条件，再决定是否执行循环体。

高级语言：

while (condition) {
    body;
}

汇编结构：

loop_start:
    如果 condition 不成立，跳到 loop_done
    body
    跳回 loop_start

loop_done:

x86-64：

loop_start:
    cmp $10, %rax
    jg loop_done

    # body

    add $1, %rax
    jmp loop_start

loop_done:

AArch64/macOS arm64：

loop_start:
    cmp x0, #10
    b.gt loop_done

    // body

    add x0, x0, #1
    b loop_start

loop_done:

这种结构适合 “循环体可能一次都不执行” 的场景。例如数组长度为 0 时，遍历循环应该直接结束。

5. do while 循环模板

do while 的特点是：先执行一次循环体，再判断是否继续。

高级语言：

do {
    body;
} while (condition);

汇编结构：

loop_start:
    body
    如果 condition 成立，跳回 loop_start

例子：至少执行一次，把 i 从 1 加到 3 。

x86-64：

mov $1, %rax        # i = 1
mov $0, %rbx        # sum = 0

loop_start:
    add %rax, %rbx  # sum += i
    add $1, %rax    # i++

    cmp $3, %rax    # 判断 i <= 3
    jle loop_start  # 如果 i <= 3，继续循环

AArch64/macOS arm64：

mov x0, #1          // i = 1
mov x1, #0          // sum = 0

loop_start:
    add x1, x1, x0  // sum += i
    add x0, x0, #1  // i++

    cmp x0, #3      // 判断 i <= 3
    b.le loop_start // 如果 i <= 3，继续循环

注意：如果初始条件本来就不成立， do while 仍然会执行一次。这和 while 不一样。

6. for 循环模板

for 循环只是把初始化、条件、更新写在同一行：

for (init; condition; update) {
    body;
}

拆开后和 while 很像：

init

loop_start:
    如果 condition 不成立，跳到 loop_done
    body
    update
    跳回 loop_start

loop_done:

以 for (i = 1; i <= 10; i++) 为例：

x86-64：

mov $1, %rax        # init: i = 1

loop_start:
    cmp $10, %rax   # condition: i <= 10
    jg loop_done

    # body

    add $1, %rax    # update: i++
    jmp loop_start

loop_done:

AArch64/macOS arm64：

mov x0, #1          // init: i = 1

loop_start:
    cmp x0, #10     // condition: i <= 10
    b.gt loop_done

    // body

    add x0, x0, #1  // update: i++
    b loop_start

loop_done:

把高级语言循环翻译成汇编时，可以先把 for 改写成 while ，再翻译成标签和跳转。

7. 倒计数循环

很多底层代码喜欢倒计数：

count = 10;
sum = 0;

while (count != 0) {
    sum += count;
    count--;
}

结果仍然是：

10 + 9 + 8 + ... + 1 = 55

倒计数的好处是判断是否结束很简单：计数器减到 0 就停。

7.1 x86-64： sub 或 dec + jnz

mov $10, %rcx       # rcx = count = 10
mov $0, %rax        # rax = sum = 0

loop_start:
    add %rcx, %rax  # sum += count

    # dec 会把 rcx 减 1，并更新 ZF/SF/OF 等标志位。
    # 如果 rcx 减完后不是 0，jnz 会跳回 loop_start。
    dec %rcx
    jnz loop_start

也可以写得更直白：

sub $1, %rcx
cmp $0, %rcx
jne loop_start

入门阶段推荐先写 sub/cmp/jcc ，理解清楚之后再使用 dec/jnz 这种压缩写法。

7.2 AArch64/macOS arm64： subs + b.ne

mov x1, #10         // x1 = count = 10
mov x0, #0          // x0 = sum = 0

loop_start:
    add x0, x0, x1  // sum += count

    // subs 会把 x1 减 1，并更新 NZCV。
    // 如果减完后不是 0，b.ne 会跳回 loop_start。
    subs x1, x1, #1
    b.ne loop_start

如果不想更新 NZCV ，也可以用 sub + cbnz ：

sub x1, x1, #1
cbnz x1, loop_start

cbnz 只检查寄存器是否非零，不修改条件标志。

8. 三个平台示例：倒计数求和

这一节把倒计数循环写成完整程序。

目标逻辑：

count = 10;
sum = 0;

while (count != 0) {
    sum += count;
    count--;
}

return sum;

预期退出码是 55 。

8.1 x86-64 Linux

文件名： countdown-x86-64.s

.section .text
.global _start
_start:
    # 目标：计算 10 + 9 + ... + 1 = 55。
    #
    # rcx 保存 count。
    # rax 保存 sum。

    mov $10, %rcx                            # rcx = count = 10
    mov $0, %rax                             # rax = sum = 0

count_loop:
    add %rcx, %rax                           # sum += count

    # count--
    # dec 会更新 ZF。如果 rcx 减到 0，ZF=1。
    dec %rcx                                 # rcx = rcx - 1
    jnz count_loop                           # 如果 rcx != 0，继续循环

count_done:
    # exit(sum)
    mov %rax, %rdi                           # rdi = 55，退出码
    mov $60, %rax                            # rax = 60，Linux x86-64 exit
    syscall

编译运行：

as --64 countdown-x86-64.s -o countdown-x86-64.o
ld countdown-x86-64.o -o countdown-x86-64
./countdown-x86-64
echo $?

预期输出：

55

8.2 AArch64 Linux

文件名： countdown-aarch64.s

.section .text
.global _start
_start:
    // 目标：计算 10 + 9 + ... + 1 = 55。
    //
    // x1 保存 count。
    // x0 保存 sum，最后也作为退出码。

    mov x1, #10                              // x1 = count = 10
    mov x0, #0                               // x0 = sum = 0

count_loop:
    add x0, x0, x1                           // sum += count

    // count--
    // subs 会更新 NZCV。如果 x1 减到 0，Z=1。
    subs x1, x1, #1                          // x1 = x1 - 1，并更新标志位
    b.ne count_loop                          // 如果 x1 != 0，继续循环

count_done:
    // exit(sum)
    mov x8, #93                              // x8 = 93，Linux AArch64 exit
    svc #0

编译运行：

as countdown-aarch64.s -o countdown-aarch64.o
ld countdown-aarch64.o -o countdown-aarch64
./countdown-aarch64
echo $?

预期输出：

55

8.3 macOS arm64

文件名： countdown-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 目标：计算 10 + 9 + ... + 1 = 55。

    mov x1, #10                              // x1 = count = 10
    mov x0, #0                               // x0 = sum = 0

count_loop:
    add x0, x0, x1                           // sum += count
    subs x1, x1, #1                          // count--，并更新 NZCV
    b.ne count_loop                          // count != 0 时继续循环

count_done:
    // main 返回值放在 x0/w0。
    ret

编译运行：

clang countdown-macos-arm64.s -o countdown-macos-arm64
./countdown-macos-arm64
echo $?

预期输出：

55

9. 计算阶乘：循环体里做乘法

再看一个稍微真实一点的循环：计算 5! 。

高级语言：

n = 5;
result = 1;

while (n > 1) {
    result *= n;
    n--;
}

return result;

计算过程：

5 * 4 * 3 * 2 * 1 = 120

预期退出码是 120 。

9.1 x86-64

mov $5, %rax        # rax = n = 5
mov $1, %rbx        # rbx = result = 1

fact_loop:
    cmp $1, %rax    # 判断 n > 1
    jle fact_done   # 如果 n <= 1，结束循环

    imul %rax, %rbx # result *= n
    sub $1, %rax    # n--
    jmp fact_loop

fact_done:

9.2 AArch64/macOS arm64

mov x0, #5          // x0 = n = 5
mov x1, #1          // x1 = result = 1

fact_loop:
    cmp x0, #1      // 判断 n > 1
    b.le fact_done  // 如果 n <= 1，结束循环

    mul x1, x1, x0  // result *= n
    sub x0, x0, #1  // n--
    b fact_loop

fact_done:

这里的 n 是普通小整数，所以用有符号条件 jle/b.le 很容易理解。如果处理的是数组长度、字节数这类天然非负的值，通常应该考虑无符号条件。

10. break 和 continue

break 和 continue 本质上也是跳转。

10.1 break

高级语言：

while (1) {
    if (x == 5) {
        break;
    }
    x++;
}

汇编思路：

loop_start:
    如果 x == 5，跳到 loop_done
    x++
    跳回 loop_start

loop_done:

x86-64：

loop_start:
    cmp $5, %rax
    je loop_done    # break

    add $1, %rax
    jmp loop_start

loop_done:

AArch64/macOS arm64：

loop_start:
    cmp x0, #5
    b.eq loop_done  // break

    add x0, x0, #1
    b loop_start

loop_done:

10.2 continue

高级语言：

for (i = 0; i < 10; i++) {
    if (i == 5) {
        continue;
    }
    sum += i;
}

continue 的目标不是循环外，而是 “更新计数器的位置”。

汇编思路：

loop_start:
    如果 i >= 10，跳到 loop_done
    如果 i == 5，跳到 loop_update
    sum += i

loop_update:
    i++
    跳回 loop_start

loop_done:

x86-64：

loop_start:
    cmp $10, %rax
    jge loop_done

    cmp $5, %rax
    je loop_update  # continue

    add %rax, %rbx  # sum += i

loop_update:
    add $1, %rax
    jmp loop_start

loop_done:

AArch64/macOS arm64：

loop_start:
    cmp x0, #10
    b.ge loop_done

    cmp x0, #5
    b.eq loop_update // continue

    add x1, x1, x0   // sum += i

loop_update:
    add x0, x0, #1
    b loop_start

loop_done:

这个结构能避免一个常见错误： continue 直接跳回 loop_start ，却忘了先执行 i++ ，导致 i == 5 时死循环。

11. x86-64 的 loop 指令

x86 有一条名字就叫 loop 的指令：

mov $10, %rcx       # rcx = 10
mov $0, %rax        # rax = sum = 0

loop_start:
    add %rcx, %rax  # sum += rcx
    loop loop_start # rcx--；如果 rcx != 0，跳回 loop_start

这段代码也会得到：

10 + 9 + ... + 1 = 55

loop label 做两件事：

1. 把计数寄存器减 1
2. 如果减完后不为 0，就跳到 label

在 64 位代码里，通常使用 %rcx 作为计数寄存器。注意两个坑：

  • loop 的计数寄存器是固定的，不如 dec/jnz 灵活。
  • 如果初始 %rcx 是 0 ， loop 会先减 1，再判断是否为 0，可能变成一个非常长的循环。

所以现代 x86-64 代码里更常见的是：

dec %rcx
jnz loop_start

或者更直白的：

sub $1, %rcx
cmp $0, %rcx
jne loop_start

入门阶段认识 loop 就好，真正写代码时优先使用 cmp/jcc 或 dec/jnz 这种更清晰的结构。

12. 指针式循环

遍历连续内存时，循环变量不一定是 i = 0, 1, 2... ，也可以是指针。

高级语言：

p = array;
end = array + 4;
sum = 0;

while (p != end) {
    sum += *p;
    p++;
}

假设数组里有 4 个 64 位整数：

1, 2, 3, 4

结果是 10 。

12.1 x86-64 思路

    lea array(%rip), %rsi      # rsi = p = &array[0]
    lea array_end(%rip), %rdx  # rdx = end
    mov $0, %rax               # rax = sum

loop_start:
    cmp %rdx, %rsi             # 比较 p 和 end
    je loop_done               # 如果 p == end，结束

    add (%rsi), %rax           # sum += *p
    add $8, %rsi               # p++，因为每个元素 8 字节
    jmp loop_start

loop_done:

12.2 AArch64/macOS arm64 思路

    adr x1, array                  // x1 = p = &array[0]
    adr x2, array_end              // x2 = end
    mov x0, #0                     // x0 = sum

loop_start:
    cmp x1, x2                    // 比较 p 和 end
    b.eq loop_done                // 如果 p == end，结束

    ldr x3, [x1], #8              // x3 = *p，然后 p += 8
    add x0, x0, x3                // sum += x3
    b loop_start

loop_done:

ldr x3, [x1], #8 是后索引寻址：先从 [x1] 读取，再把 x1 加 8 。如果认为这个写法一开始不直观，也可以拆成两条：

ldr x3, [x1]
add x1, x1, #8

这里用 adr 是为了演示 “标签离当前代码比较近” 的入门场景。更复杂的全局符号取地址通常会用 adrp/add 或平台相关的重定位写法，数组章节会继续展开。

数组会在后面的章节详细讲。本节只先建立循环和指针移动的直觉。

13. signed 和 unsigned 循环边界

循环边界经常涉及大小比较。

如果 i 是普通有符号整数：

while (i < limit)

可以用 signed 条件：

cmp %rbx, %rax
jl loop_body        # x86-64 signed i < limit
cmp x0, x1
b.lt loop_body      // AArch64 signed i < limit

如果 i 和 length 表示数组下标、字节数、内存大小，通常应该当作无符号数：

cmp %rbx, %rax
jb loop_body        # x86-64 unsigned i < length
cmp x0, x1
b.lo loop_body      // AArch64 unsigned i < length

一个危险例子：

i = -1
length = 10

按 signed 看：

-1 < 10 成立

按 unsigned 看：

0xffffffffffffffff < 10 不成立

如果在数组访问里把 -1 当 signed 下标放进循环，就可能访问到错误地址。写循环边界时，一定先想清楚数据的含义。

14. 常见错误

14.1 忘记更新计数器

loop_start:
    cmp $10, %rax
    jg loop_done

    add %rax, %rbx
    jmp loop_start     # 错误：rax 没有变化

修正：

loop_start:
    cmp $10, %rax
    jg loop_done

    add %rax, %rbx
    add $1, %rax       # i++
    jmp loop_start

14.2 边界条件写错，少循环一次或多循环一次

i <= 10 和 i < 10 不一样：

cmp $10, %rax
jg done        # i > 10 时结束，表示循环条件是 i <= 10
cmp $10, %rax
jge done       # i >= 10 时结束，表示循环条件是 i < 10

AArch64/macOS arm64 同理：

cmp x0, #10
b.gt done      // i <= 10
cmp x0, #10
b.ge done      // i < 10

14.3 比较后插入会改标志位的指令

x86-64：

cmp $10, %rax
add $1, %rbx        # add 修改了 RFLAGS
jg loop_done        # 这里已经不是 cmp 的判断结果

AArch64：

cmp x0, #10
subs x1, x1, #1     // subs 修改了 NZCV
b.gt loop_done      // 这里已经不是 cmp 的判断结果

把比较和对应的条件跳转放近一点：

cmp $10, %rax
jg loop_done
cmp x0, #10
b.gt loop_done

14.4 倒计数循环没有处理初始值为 0

下面这种写法假设计数器一开始不是 0 ：

count_loop:
    # body
    dec %rcx
    jnz count_loop

如果 count = 0 时也可能进入这里，就会出错。更稳妥的结构是先检查：

test %rcx, %rcx
jz count_done

count_loop:
    # body
    dec %rcx
    jnz count_loop

count_done:

AArch64：

cbz x1, count_done

count_loop:
    // body
    subs x1, x1, #1
    b.ne count_loop

count_done:

14.5 把 continue 跳错位置

如果 continue 直接跳回循环顶部，可能跳过更新语句：

cmp $5, %rax
je loop_start       # 风险：如果 loop_start 前没有 i++，可能死循环

更常见的做法是跳到更新标签：

cmp $5, %rax
je loop_update

这样 i++ 仍然会执行。

14.6 把退出码当完整输出

退出码通常只保留低 8 位。比如 300 会显示成：

300 mod 256 = 44

所以示例选择 55 、 120 这类可以直接用 echo $? 观察的结果。

15. 小练习

  1. 把 loop-* 示例改成计算 1 + 2 + ... + 20 。注意结果 210 仍然能通过退出码观察。
  2. 把倒计数示例改成从 5 加到 1 ，确认退出码是 15 。
  3. 写一个循环计算 5! ，确认退出码是 120 。
  4. 写一个循环只累加 1 到 10 中的偶数，预期结果是 30 。
  5. 写一个带 continue 的循环：累加 0 到 9 ，但跳过 5 ，预期结果是 40 。
  6. 故意把 i <= 10 改成 i < 10 ，观察 55 变成多少，并解释少加了哪一项。
