逻辑指令

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的逻辑指令。

逻辑指令处理的是二进制位：

AND  按位与：两个位都是 1，结果才是 1
OR   按位或：任意一个位是 1，结果就是 1
XOR  按位异或：两个位不同，结果是 1
NOT  按位取反：0 变 1，1 变 0

逻辑指令常用于：

  • 清零寄存器。
  • 设置、清除、切换某些 flag 位。
  • 测试某一位是否为 1。
  • 提取字段、对齐地址、处理权限掩码。
  • 做简单的乘除 2 的幂，例如左移和右移。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的逻辑 / 移位指令基本相同；差异主要在入口、链接方式和系统调用。

1. 一张表先建立全局印象

按位与and src, dstand dst, src1, src2/#imm同 AArch64
按位或or src, dstorr dst, src1, src2/#imm同 AArch64
按位异或xor src, dsteor dst, src1, src2/#imm同 AArch64
按位取反not dstmvn dst, src同 AArch64

左移shl 或 sallsl同 AArch64

右旋rorror同 AArch64
清零寄存器xor %eax, %eaxmov x0, xzr 或 eor x0, x0, x0同 AArch64
标志位and/or/xor/test 会更新 RFLAGS普通 and/orr/eor 不更新； ands/tst 更新 NZCV同 AArch64

两个命名差异：

  • x86-64 写 or ，AArch64 写 orr 。
  • x86-64 写 xor ，AArch64 写 eor 。

两个操作数顺序差异：

# x86-64 AT&T：rax = rax & 0xf0
and $0xf0, %rax

// AArch64：x0 = x0 & x1
and x0, x0, x1

x86-64 目标通常在最后；AArch64 目标通常在最前。

2. 位运算先看 8 位例子

以下用 8 位二进制数做直觉演示：

0b10101010 = 0xaa = 170
0b11110000 = 0xf0 = 240
0b00000101 = 0x05 = 5
0b00001111 = 0x0f = 15

计算目标：

((0b10101010 & 0b11110000) | 0b00000101) ^ 0b00001111

第一步 AND:
  10101010
& 11110000
= 10100000

第二步 OR:
  10100000
| 00000101
= 10100101

第三步 XOR:
  10100101
^ 00001111
= 10101010

最终结果 0b10101010 = 170

退出码能显示 0 到 255 之间的值，所以 170 很适合用 echo $? 验证。

3. 三个平台示例：AND、OR、XOR

3.1 x86-64 Linux

文件名： logic-x86-64.s

.section .text
.global _start
_start:
    # 目标：
    # ((0b10101010 & 0b11110000) | 0b00000101) ^ 0b00001111 = 170
    #
    # x86-64 AT&T 语法：
    # and $mask, %rax  表示 rax = rax & mask
    # or  $mask, %rax  表示 rax = rax | mask
    # xor $mask, %rax  表示 rax = rax ^ mask

    mov $0b10101010, %rax                   # rax = 0xaa
    and $0b11110000, %rax                   # rax = 0xa0
    or  $0b00000101, %rax                   # rax = 0xa5
    xor $0b00001111, %rax                   # rax = 0xaa = 170

    # exit(rax)
    mov %rax, %rdi                          # rdi = 170，退出码
    mov $60, %rax                           # rax = 60，Linux x86-64 exit 系统调用号
    syscall

编译运行：

as --64 logic-x86-64.s -o logic-x86-64.o
ld logic-x86-64.o -o logic-x86-64
./logic-x86-64
echo $?

预期输出：

170

3.2 AArch64 Linux

文件名： logic-aarch64.s

.section .text
.global _start
_start:
    // 目标：
    // ((0b10101010 & 0b11110000) | 0b00000101) ^ 0b00001111 = 170
    //
    // AArch64 逻辑指令：
    // and x0, x0, x1  表示 x0 = x0 & x1
    // orr x0, x0, x1  表示 x0 = x0 | x1
    // eor x0, x0, x1  表示 x0 = x0 ^ x1

    mov x0, #0b10101010                     // x0 = 0xaa

    mov x1, #0b11110000                     // x1 = 0xf0
    and x0, x0, x1                          // x0 = 0xa0

    // AArch64 的逻辑立即数不是任意 bit pattern 都能直接编码。
    // 为了让示例稳定可汇编，这里把掩码先放进 x1。
    mov x1, #0b00000101                     // x1 = 0x05
    orr x0, x0, x1                          // x0 = 0xa5

    mov x1, #0b00001111                     // x1 = 0x0f
    eor x0, x0, x1                          // x0 = 0xaa = 170

    // exit(x0)
    mov x8, #93                             // x8 = 93，Linux AArch64 exit 系统调用号
    svc #0

编译运行：

as logic-aarch64.s -o logic-aarch64.o
ld logic-aarch64.o -o logic-aarch64
./logic-aarch64
echo $?

预期输出：

170

3.3 macOS arm64

文件名： logic-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 目标：
    // ((0b10101010 & 0b11110000) | 0b00000101) ^ 0b00001111 = 170

    mov x0, #0b10101010                     // x0 = 0xaa

    mov x1, #0b11110000                     // x1 = 0xf0
    and x0, x0, x1                          // x0 = 0xa0

    mov x1, #0b00000101                     // x1 = 0x05
    orr x0, x0, x1                          // x0 = 0xa5

    mov x1, #0b00001111                     // x1 = 0x0f
    eor x0, x0, x1                          // x0 = 0xaa = 170

    // main 返回值放在 x0/w0。
    // echo $? 会看到低 8 位，也就是 170。
    ret

编译运行：

clang logic-macos-arm64.s -o logic-macos-arm64
./logic-macos-arm64
echo $?

预期输出：

170

4. AND：保留某些位

AND 常用于 “只保留需要保留的位”。

例如只保留低 4 位：

value = 0b10101101
mask  = 0b00001111

value & mask = 0b00001101

x86-64：

and $0x0f, %rax

AArch64/macOS arm64：

and x0, x0, #0x0f

如果某个立即数不能被 AArch64 逻辑立即数格式编码，就先放到寄存器：

mov x1, #5
and x0, x0, x1

常见用途：

  • 提取低 8 位： value & 0xff 。
  • 判断是否按 16 字节对齐： addr & 0x0f 是否为 0。
  • 清除高位，只保留某个字段。

5. OR：设置某些位

OR 常用于 “把某些位强制设为 1”。

value = 0b10100000
mask  = 0b00000101

value | mask = 0b10100101

x86-64：

or $0x05, %rax

AArch64/macOS arm64：

orr x0, x0, x1

常见用途：

  • 添加权限 flag。
  • 设置状态位。
  • 把多个 bit flag 合并成一个值。

例如：

.equ FLAG_READ,  1 << 0
.equ FLAG_WRITE, 1 << 1
.equ FLAG_EXEC,  1 << 2

FLAG_READ | FLAG_EXEC 的值就是 0b101 。

6. XOR：切换位，也能清零

XOR 的规则是：相同为 0，不同为 1。

value = 0b10100101
mask  = 0b00001111

value ^ mask = 0b10101010

同一个位和 1 异或会翻转，和 0 异或保持不变。因此 XOR 常用于切换位：

xor $0x01, %rax        # x86-64：切换最低位
mov x1, #1
eor x0, x0, x1         // AArch64：切换最低位

清零寄存器也常用 XOR：

xor %eax, %eax         # x86-64：eax = 0，同时清空 rax 高 32 位

AArch64 有零寄存器，所以清零更直观：

mov x0, xzr            // x0 = 0
eor x0, x0, x0         // 也可以得到 0

x86-64 里 xor %eax, %eax 很常见，因为编码短、执行快，并且写 32 位寄存器会清空对应 64 位寄存器的高 32 位。

7. NOT、MVN、BIC：取反和清除位

x86-64 的 not 会把每一位取反：

mov $0b00001111, %rax
not %rax              # rax 的每一位都翻转

注意： not 不更新标志位。

AArch64 的按位取反常写 mvn ：

mvn x0, x1            // x0 = ~x1

mvn 实际上是 orn x0, xzr, x1 的别名，也就是：

x0 = xzr | ~x1 = ~x1

清除某些位时，AArch64 有专门的 bic ：

bic x0, x0, x1        // x0 = x0 & ~x1

x86-64 通常写成 and 配合反掩码：

and $~0x0f, %rax      # 清除低 4 位

或者先构造反掩码到寄存器。

8. TEST 和 TST：只测试，不保存结果

有时只需要知道某一位是不是 1，不想修改原来的值。

x86-64 用 test ：

test $0x04, %rax      # 计算 rax & 0x04，只更新标志位，不保存结果
jz bit_is_zero        # 如果结果为 0，说明这一位没设置

AArch64 用 tst ：

tst x0, #0x04         // 计算 x0 & 0x04，只更新 NZCV，不保存结果
b.eq bit_is_zero      // Z=1，说明结果为 0

如果掩码不能作为 AArch64 逻辑立即数直接编码，就先放进寄存器：

mov x1, #5
tst x0, x1

test/tst 的常见用途：

  • 判断 flag 是否存在。
  • 判断某个数是奇数还是偶数。
  • 判断地址是否对齐。

例如判断奇偶：

test $1, %rax         # x86-64：最低位为 0 表示偶数
tst x0, #1            // AArch64：最低位为 0 表示偶数

条件跳转会在下一章详细讲。先记住： test/tst 是 “不保存结果的 AND”。

9. 移位：左移、逻辑右移、算术右移

移位也是位操作。

9.1 左移

左移一位，相当于在不溢出的情况下乘以 2：

0b00010001 << 1 = 0b00100010
17 << 1 = 34

x86-64：

shl $1, %rax
sal $1, %rax          # sal 和 shl 对左移来说基本同义

AArch64/macOS arm64：

lsl x0, x0, #1

9.2 逻辑右移

逻辑右移高位补 0，适合无符号数：

0b10000000 >> 1 = 0b01000000

x86-64：

shr $1, %rax

AArch64/macOS arm64：

lsr x0, x0, #1

9.3 算术右移

算术右移会保留符号位，适合有符号数：

sar $1, %rax          # x86-64
asr x0, x0, #1        // AArch64

对于正数， shr 和 sar 看起来一样；对于最高位为 1 的负数，这些值差别很大。

10. 三个平台示例：移位和置位

目标计算：

value = 0b00010001      # 17
value = value << 1      # 34
value = value | 1       # 35
value = value >> 1      # 17

10.1 x86-64 Linux

文件名： shift-x86-64.s

.section .text
.global _start
_start:
    # 目标：通过左移、置位、右移，最终得到 17。

    mov $0b00010001, %rax                   # rax = 17
    shl $1, %rax                            # rax = 34
    or  $1, %rax                            # rax = 35，设置最低位
    shr $1, %rax                            # rax = 17，逻辑右移

    # exit(rax)
    mov %rax, %rdi
    mov $60, %rax
    syscall

运行：

as --64 shift-x86-64.s -o shift-x86-64.o
ld shift-x86-64.o -o shift-x86-64
./shift-x86-64
echo $?

预期输出：

17

10.2 AArch64 Linux

文件名： shift-aarch64.s

.section .text
.global _start
_start:
    // 目标：通过左移、置位、右移，最终得到 17。

    mov x0, #0b00010001                     // x0 = 17
    lsl x0, x0, #1                          // x0 = 34

    mov x1, #1                              // x1 = 掩码 1
    orr x0, x0, x1                          // x0 = 35，设置最低位

    lsr x0, x0, #1                          // x0 = 17，逻辑右移

    // exit(x0)
    mov x8, #93
    svc #0

运行：

as shift-aarch64.s -o shift-aarch64.o
ld shift-aarch64.o -o shift-aarch64
./shift-aarch64
echo $?

预期输出：

17

10.3 macOS arm64

文件名： shift-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 目标：通过左移、置位、右移，最终得到 17。

    mov x0, #0b00010001                     // x0 = 17
    lsl x0, x0, #1                          // x0 = 34

    mov x1, #1                              // x1 = 掩码 1
    orr x0, x0, x1                          // x0 = 35

    lsr x0, x0, #1                          // x0 = 17
    ret

运行：

clang shift-macos-arm64.s -o shift-macos-arm64
./shift-macos-arm64
echo $?

预期输出：

17

11. 旋转：移出去的位从另一边回来

普通移位会丢掉移出去的位。旋转会把移出去的位从另一端放回来。

右旋 1 位：

10000001 ror 1 = 11000000

x86-64：

ror $1, %rax
rol $1, %rax

AArch64/macOS arm64：

ror x0, x0, #1

旋转在哈希、加密、校验和、位混合里很常见。入门阶段先知道旋转和普通移位不同：旋转不丢位，只换位置。

12. 标志位差异

x86-64 的 and/or/xor/test 会更新标志位：

  • 根据结果设置 ZF 、 SF 、 PF 。
  • 清除 CF 和 OF 。
  • not 不更新标志位。

例子：

test $1, %rax       # 根据 rax & 1 设置 ZF
jz even             # ZF=1 表示最低位是 0，也就是偶数

AArch64 普通逻辑指令不更新 NZCV ：

and x0, x0, x1      // 不更新 NZCV
orr x0, x0, x1      // 不更新 NZCV
eor x0, x0, x1      // 不更新 NZCV

要更新标志，用带 s 的版本或 tst ：

ands x0, x0, x1     // 保存结果，并更新 NZCV
tst x0, x1          // 不保存结果，只更新 NZCV

这个差异非常重要。下一章写条件判断时，如果需要根据逻辑运算结果跳转，AArch64 上要明确选择 ands/tst ，不能默认指望 and 改标志。

13. 逻辑立即数限制

x86-64 的逻辑指令通常可以接受常见整数立即数：

and $0x12345678, %rax
or  $5, %rax
xor $0xff, %rax

AArch64 的逻辑立即数有特殊编码规则，不是任意 bit pattern 都能直接写在 and/orr/eor/tst 后面。比如某些汇编器会拒绝：

orr x0, x0, #5      // 可能报错：不是可编码的 logical immediate

稳妥写法是先放进寄存器：

mov x1, #5
orr x0, x0, x1

不要把这个理解成 AArch64 不能做 OR 5 ，当然能做；只是这个 5 不一定能作为该指令的立即数字段直接编码。

14. 常见坑

14.1 把 ORR 写成 OR

x86-64：

or $1, %rax

AArch64/macOS arm64：

orr x0, x0, x1

AArch64 指令名是 orr ，不是 or 。

14.2 AArch64 用 and 后期待标志位更新

and x0, x0, x1
b.eq zero           // 错误思路：and 不更新 NZCV

要写：

ands x0, x0, x1
b.eq zero

或者：

tst x0, x1
b.eq zero

14.3 混淆逻辑右移和算术右移

无符号数右移通常用逻辑右移：

shr $1, %rax        # x86-64
lsr x0, x0, #1      // AArch64

有符号数右移通常用算术右移：

sar $1, %rax        # x86-64
asr x0, x0, #1      // AArch64

对最高位为 1 的数，结果会不同。

14.4 忘记退出码只看低 8 位

如果逻辑结果大于 255 ， echo $? 只会显示低 8 位。比如：

0x1aa 的低 8 位是 0xaa，也就是 170

所以示例都让最终结果保持在 0 到 255 。

14.5 not 会翻转所有位

如果 %rax = 0x0f ：

not %rax

结果不是 0xf0 ，而是：

0xfffffffffffffff0

因为 64 位寄存器里的所有位都被翻转。想只翻转低 8 位，应该用 XOR 掩码：

xor $0xff, %rax

15. 小练习

  1. 把 logic-* 示例里的最后一个 XOR 掩码从 0x0f 改成 0xff ，观察退出码。
  2. 写一个程序用 and 保留低 4 位，让 0xab 变成 0x0b ，退出码应为 11 。
  3. 写一个程序用 xor 切换最低位，让 42 变成 43 。
  4. 把 shift-* 示例中的 lsr/shr 改成右移 2 位，计算新的退出码。
  5. 用 test/tst 判断 0b1010 的最低位是否为 0，为下一章条件判断做准备。
