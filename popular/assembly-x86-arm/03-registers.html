寄存器

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的寄存器。

寄存器可以先理解成 CPU 内部的一小组 “超快变量”。汇编代码几乎每天都在做三件事：

  1. 把立即数、地址或内存中的值放进寄存器。
  2. 用寄存器做计算、比较、跳转、调用函数。
  3. 按 ABI 约定把参数、返回值、系统调用号放到指定寄存器。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的很多寄存器名字相同，但 可执行文件格式、符号命名、系统调用接口、平台保留寄存器 不完全相同。不要把 Linux AArch64 示例原样搬到 macOS。

初学阶段最重要的是把两类约定分清：

  • 函数调用约定：调用自定义函数或 C 库函数时，参数和返回值放在哪些寄存器。
  • 系统调用约定：直接进入 Linux 内核时，系统调用号和参数放在哪些寄存器。

x86-64 Linux 上，这两套约定很像但不是完全一样：C 函数第 4 个参数用 rcx ，Linux syscall 第 4 个参数用 r10 。AArch64 Linux 上，C 函数和 syscall 都用 x0 起步传参数，但 syscall 号放在 x8 。

2. x86-64 寄存器名字怎么读

x86-64 的通用寄存器有 16 个。GAS AT&T 语法里寄存器前面带 % ：

64 位32 位16 位低 8 位常见用途
%rax%eax%ax%al返回值、临时值、syscall 号
%rbx%ebx%bx%bl被调用者保存，常当长期变量
%rcx%ecx%cx%clC 函数第 4 参数、计数、移位次数
%rdx%edx%dx%dlC 函数第 3 参数、返回值扩展
%rsi%esi%si%silC 函数第 2 参数，字符串源指针
%rdi%edi%di%dilC 函数第 1 参数，字符串目标指针
%rbp%ebp%bp%bpl帧指针，或普通 callee-saved 寄存器
%rsp%esp%sp%spl栈指针，不要随便当普通变量
%r8 - %r15%r8d - %r15d%r8w - %r15w%r8b - %r15b扩展通用寄存器

两个非常实用的规则：

  • 写入 32 位寄存器会把对应 64 位寄存器的高 32 位清零。例如 mov $7, %eax 会让 %rax 变成 7 。
  • 写入 8 位或 16 位寄存器通常不会清空高位。例如写 %al 只改 %rax 的最低 8 位。

下面用退出码演示 “写 %eax 会清空 %rax 高 32 位”。

文件名： width-x86.s

.section .text
.global _start
_start:
    # 1. 先把 rax 设成全 1。
    #    在二进制里，-1 的 64 位补码就是 0xffffffffffffffff。
    mov $-1, %rax

    # 2. 写 eax，而不是写 rax。
    #    x86-64 规定：写 32 位子寄存器会把高 32 位清零。
    #    所以这条指令执行后，rax 不是 0xffffffff00000007，
    #    而是 0x0000000000000007。
    mov $7, %eax

    # 3. exit(status) 的第 1 个参数放在 rdi。
    #    这里把刚才算出的 rax 复制给 rdi，作为退出码。
    mov %rax, %rdi

    # 4. Linux x86-64 syscall：
    #    rax = 系统调用号，60 表示 exit
    #    rdi = 第 1 参数，也就是 status
    mov $60, %rax
    syscall

运行：

as --64 width-x86.s -o width-x86.o
ld width-x86.o -o width-x86
./width-x86
echo $?

预期输出：

7

这个例子看起来简单，但这个例子解释了很多反汇编里常见的写法：编译器经常用 mov %eax 、 xor %eax, %eax 来得到一个干净的 64 位值。

3. AArch64 的 x 、 w 、 sp 、 xzr

AArch64 的通用整数寄存器通常写成：

  • x0 - x30 ：64 位视图。
  • w0 - w30 ：同一批寄存器的低 32 位视图。
  • sp ：栈指针，不能在所有指令里都当普通寄存器使用。
  • xzr/wzr ：零寄存器，读出来永远是 0，写进去的值会被丢弃。

常见角色如下：

寄存器ABI 角色初学者记法
x0 - x7参数 / 返回值寄存器，caller-saved函数前 8 个整数或指针参数
x8间接返回值位置；Linux syscall 号也放这里Linux syscall 时特别重要
x9 - x15caller-saved 临时寄存器临时变量，用完就走
x16 - x17ip0/ip1 ，链接器和跳板代码也可能使用跨函数调用时不要指望这些寄存器保留
x18platform register跨平台手写汇编尽量别用；Apple 平台保留
x19 - x28callee-saved函数用了就要恢复
x29/fpframe pointer帧指针
x30/lrlink registerbl 写返回地址， ret 默认跳回这里
spstack pointer栈顶位置，要求 16 字节对齐

AArch64 也有 “写 32 位视图会清空高 32 位” 的规则。

文件名： width-aarch64.s

.section .text
.global _start
_start:
    // 1. x0 是 64 位寄存器。这里把 x0 设成 -1。
    //    64 位补码形式是 0xffffffffffffffff。
    mov x0, #-1

    // 2. 写 w0，也就是 x0 的低 32 位视图。
    //    AArch64 规定：写 w0 会把 x0 的高 32 位清零。
    //    执行后 x0 = 0x0000000000000007。
    mov w0, #7

    // 3. Linux AArch64 exit(status)：
    //    x8 = 系统调用号，93 表示 exit
    //    x0 = 第 1 参数 status
    mov x8, #93
    svc #0

运行：

as width-aarch64.s -o width-aarch64.o
ld width-aarch64.o -o width-aarch64
./width-aarch64
echo $?

预期输出：

7

4. macOS arm64 的寄存器特别点

macOS arm64 使用 AArch64 指令集，但 Apple ABI 有平台自身规则。入门时先记住三点：

  1. x0 - x7 仍然是 C 函数参数 / 返回值寄存器。
  2. x18 是 Apple 平台保留寄存器，手写汇编不要用保存临时值。
  3. macOS 汇编里 C 符号通常带前导下划线： main 写成 _main ， write 写成 _write 。

下面是 macOS 版的 32 位写入清高位示例。该示例不直接调用 Linux 那种 svc #0 syscall，而是从 _main 返回，让 C 运行时处理进程退出。

文件名： width-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 1. x0 是 main 的返回值寄存器。
    //    这里先把 x0 设成 -1。
    mov x0, #-1

    // 2. 写 w0 会清空 x0 的高 32 位。
    //    所以 x0 变成 7。
    mov w0, #7

    // 3. main 返回时，C 运行时会把 w0/x0 里的值当作退出状态。
    //    这里没有调用其他函数，所以 x30 仍保存着 C 运行时给 main 的返回地址。
    ret

运行：

clang width-macos-arm64.s -o width-macos-arm64
./width-macos-arm64
echo $?

预期输出：

7

注意：进程退出码通常只显示低 8 位，所以示例都选择 0 - 255 之间的小数。

5. 函数调用：参数放哪里

先看最常用的整数 / 指针参数。假设需要写一个函数：

long add3(long a, long b, long c) {
    return a + b + c;
}

三种环境的寄存器分配如下：

参数 / 返回值x86-64 Linux C ABIAArch64 Linux C ABImacOS arm64 C ABI
第 1 参数 a%rdix0x0
第 2 参数 b%rsix1x1
第 3 参数 c%rdxx2x2
第 4 参数%rcxx3x3
第 5 参数%r8x4x4
第 6 参数%r9x5x5
第 7 参数栈上x6x6
第 8 参数栈上x7x7
返回值%raxx0x0

x86-64 的 C ABI 只有前 6 个整数 / 指针参数放寄存器；AArch64/macOS arm64 有前 8 个。

6. x86-64 Linux：用寄存器调用自定义函数

文件名： call-x86.s

.section .text
.global _start
_start:
    # 目标：调用 add3(2, 3, 4)，返回 9，然后用 9 作为退出码。
    #
    # System V AMD64 ABI 的整数/指针参数寄存器：
    # 第 1 参数 -> rdi
    # 第 2 参数 -> rsi
    # 第 3 参数 -> rdx
    # 返回值   -> rax
    mov $2, %rdi                  # a = 2
    mov $3, %rsi                  # b = 3
    mov $4, %rdx                  # c = 4

    # call 会做两件事：
    # 1. 把下一条指令的地址压入栈，作为返回地址。
    # 2. 跳到 add3。
    call add3

    # add3 返回后，rax = 9。
    # exit(status) 的第 1 参数要放进 rdi。
    mov %rax, %rdi

    # Linux x86-64 syscall：
    # rax = 60 表示 exit
    # rdi = status
    mov $60, %rax
    syscall

add3:
    # add3 进入时：
    # rdi = a
    # rsi = b
    # rdx = c
    #
    # 这里没有调用别的函数，也没有使用 callee-saved 寄存器，
    # 所以不需要建立栈帧。
    mov %rdi, %rax                # rax = a，rax 也是返回值寄存器
    add %rsi, %rax                # rax = a + b
    add %rdx, %rax                # rax = a + b + c

    # ret 会从栈顶弹出 call 保存的返回地址，并跳回那里。
    ret

运行：

as --64 call-x86.s -o call-x86.o
ld call-x86.o -o call-x86
./call-x86
echo $?

预期输出：

9

这个例子展示了 x86-64 的两个核心点：

  • call / ret 的返回地址主要通过栈传递。
  • 函数参数和返回值通过 ABI 指定的寄存器传递。

7. AArch64 Linux： bl 、 x30/lr 和 ret

文件名： call-aarch64.s

.section .text
.global _start
_start:
    // 目标：调用 add3(2, 3, 4)，返回 9，然后用 9 作为退出码。
    //
    // AAPCS64 的整数/指针参数寄存器：
    // 第 1 参数 -> x0
    // 第 2 参数 -> x1
    // 第 3 参数 -> x2
    // 返回值   -> x0
    mov x0, #2                    // a = 2
    mov x1, #3                    // b = 3
    mov x2, #4                    // c = 4

    // bl = branch with link。
    // 会把下一条指令的地址写入 x30/lr，然后跳到 add3。
    bl add3

    // add3 返回后，x0 = 9。
    // Linux AArch64 exit(status) 正好也用 x0 传第 1 参数。
    mov x8, #93                   // x8 = 93，exit 系统调用号
    svc #0                        // 进入 Linux 内核

add3:
    // add3 进入时：
    // x0 = a
    // x1 = b
    // x2 = c
    //
    // 返回值也放在 x0，所以可以直接累加到 x0。
    add x0, x0, x1                // x0 = a + b
    add x0, x0, x2                // x0 = a + b + c

    // ret 默认跳回 x30/lr 保存的地址。
    ret

运行：

as call-aarch64.s -o call-aarch64.o
ld call-aarch64.o -o call-aarch64
./call-aarch64
echo $?

预期输出：

9

AArch64 和 x86-64 最大的直观差异之一就是返回地址：

  • x86-64： call 把返回地址压到栈上， ret 从栈上取回。
  • AArch64： bl 把返回地址写进 x30/lr ， ret 默认跳回 x30 。

如果 AArch64 函数内部还要继续 bl 调用别的函数，新的 bl 会覆盖 x30 ，所以非叶子函数通常要先保存 x30 。

8. macOS arm64：调用函数前先保存 x30

macOS 版本也用 x0 、 x1 、 x2 传前三个参数。但 _main 需要调用 _add3 ，所以必须保存 x30 。否则 bl _add3 会覆盖 C 运行时放在 x30 里的返回地址， _main 最后就不知道该回哪里。

文件名： call-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 建立最小栈帧。
    //
    // stp = store pair，一次存两个 64 位寄存器。
    // [sp, #-16]! 表示：
    // 1. sp = sp - 16，给栈帧腾出 16 字节。
    // 2. 把 x29 和 x30 存到新的 sp 指向的位置。
    //
    // 保存 x29：旧帧指针。
    // 保存 x30：_main 返回到 C 运行时所需的返回地址。
    stp x29, x30, [sp, #-16]!

    // 让 x29 指向当前栈帧。Apple 平台很重视有效的 frame record，
    // 这样调试器和崩溃日志更容易还原调用栈。
    mov x29, sp

    // 调用 _add3(2, 3, 4)。
    mov x0, #2                    // 第 1 参数 a = 2
    mov x1, #3                    // 第 2 参数 b = 3
    mov x2, #4                    // 第 3 参数 c = 4
    bl _add3                      // 返回后 x0 = 9

    // 恢复 _main 进入时保存的 x29 和 x30。
    // [sp], #16 表示：
    // 1. 从 sp 指向的位置读回 x29、x30。
    // 2. sp = sp + 16，释放刚才的栈帧。
    ldp x29, x30, [sp], #16

    // x0 仍然是 9。main 返回后，C 运行时把作为进程退出码。
    ret

.p2align 2
_add3:
    // _add3 进入时：
    // x0 = a
    // x1 = b
    // x2 = c
    add x0, x0, x1                // x0 = a + b
    add x0, x0, x2                // x0 = a + b + c
    ret                           // 返回到 _main 中 bl _add3 的下一条指令

运行：

clang call-macos-arm64.s -o call-macos-arm64
./call-macos-arm64
echo $?

预期输出：

9

这段代码也是 macOS arm64 入门里最值得反复看的一段：

  • _main 是非叶子函数，因为该函数调用了 _add3 。
  • 非叶子函数必须保护返回所需的 x30 。
  • sp 始终按 16 字节对齐移动。
  • _add3 是叶子函数，因为该函数不调用别的函数，所以可以直接 ret 。

9. caller-saved 和 callee-saved

函数调用时，寄存器分成两类：

  • caller-saved：调用者想保留就由调用者保存。被调用函数可以随便改。
  • callee-saved：被调用函数如果要改，返回前必须恢复。

这不是 CPU 自动完成的魔法，而是 ABI 约定。手写汇编时要手动遵守。

9.1 x86-64 Linux 常用保存规则

类型寄存器
caller-saved%rax 、 %rcx 、 %rdx 、 %rsi 、 %rdi 、 %r8 、 %r9 、 %r10 、 %r11
callee-saved%rbx 、 %rbp 、 %rsp 、 %r12 、 %r13 、 %r14 、 %r15

如果函数里要使用 %rbx 保存长期变量，应该像这样保存和恢复：

use_rbx:
    push %rbx                     # rbx 是 callee-saved，先保存调用者的 rbx

    mov $100, %rbx                # 函数内部可以安全使用 rbx
    mov %rbx, %rax                # 返回值放 rax

    pop %rbx                      # 返回前恢复调用者的 rbx
    ret

9.2 AArch64 Linux 和 macOS arm64 常用保存规则

类型寄存器
caller-savedx0 - x17 ，其中 x16/x17 还可能被链接器跳板使用
平台相关x18 ，跨平台手写汇编尽量别用；Apple 平台保留
callee-savedx19 - x29 ，以及 sp
返回地址x30/lr ，如果函数内部还要 bl ，通常要保存

如果函数里要使用 x19 保存长期变量，可以这样写：

use_x19:
    // x19 是 callee-saved。
    // AArch64 栈指针要保持 16 字节对齐，所以即使只保存一个寄存器，
    // 也常常一次分配 16 字节。
    str x19, [sp, #-16]!          // sp -= 16; 把 x19 存到栈上

    mov x19, #100                 // 函数内部使用 x19
    mov x0, x19                   // 返回值放 x0

    ldr x19, [sp], #16            // 恢复 x19; sp += 16
    ret

如果这个函数还会调用别的函数，就要同时考虑 x30 ：

non_leaf:
    // 保存 x29 和 x30，建立常见的栈帧。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    // 这里可以安全 bl 调用别的函数，因为旧 x30 已经保存在栈上。
    bl other_function

    // 恢复返回到调用者所需的 x29/x30。
    ldp x29, x30, [sp], #16
    ret

10. 系统调用：Linux 和 macOS 不一样

系统调用是用户程序进入内核的接口。系统调用也使用寄存器传参，但不一定等于 C 函数 ABI。

10.1 Linux x86-64 syscall 寄存器

内容寄存器
系统调用号%rax
第 1 参数%rdi
第 2 参数%rsi
第 3 参数%rdx
第 4 参数%r10
第 5 参数%r8
第 6 参数%r9
返回值%rax
会被 syscall 破坏%rcx 、 %r11

文件名： syscall-x86.s

.section .rodata
msg:
    .ascii "x86 syscall registers\n"
msg_len = . - msg

.section .text
.global _start
_start:
    # write(fd, buf, count)
    #
    # Linux x86-64 syscall 约定：
    # rax = syscall number
    # rdi = arg1
    # rsi = arg2
    # rdx = arg3
    mov $1, %rax                  # 1 = write
    mov $1, %rdi                  # fd = 1，标准输出
    lea msg(%rip), %rsi           # buf = msg 的地址
    mov $msg_len, %rdx            # count = 字符串长度
    syscall

    # exit(0)
    mov $60, %rax                 # 60 = exit
    xor %rdi, %rdi                # status = 0
    syscall

运行：

as --64 syscall-x86.s -o syscall-x86.o
ld syscall-x86.o -o syscall-x86
./syscall-x86

预期输出：

x86 syscall registers

注意第 4 个参数：C 函数第 4 参数是 %rcx ，但 Linux x86-64 syscall 第 4 参数是 %r10 。这是初学者很容易踩到的差异。

文件名： syscall-aarch64.s

.section .rodata
msg:
    .ascii "AArch64 syscall registers\n"
msg_len = . - msg

.section .text
.global _start
_start:
    // write(fd, buf, count)
    //
    // Linux AArch64 syscall 约定：
    // x8 = syscall number
    // x0 = arg1
    // x1 = arg2
    // x2 = arg3
    mov x8, #64                   // 64 = write
    mov x0, #1                    // fd = 1，标准输出
    adr x1, msg                   // buf = msg 的地址
    mov x2, #msg_len              // count = 字符串长度
    svc #0

    // exit(0)
    mov x8, #93                   // 93 = exit
    mov x0, #0                    // status = 0
    svc #0

运行：

as syscall-aarch64.s -o syscall-aarch64.o
ld syscall-aarch64.o -o syscall-aarch64
./syscall-aarch64

预期输出：

AArch64 syscall registers

x8 在这里非常关键：该指令不是第 9 个参数，而是 Linux AArch64 的系统调用号寄存器。

10.3 macOS arm64：入门阶段调用 libSystem

macOS arm64 不要照搬 Linux AArch64 的 x8 = 64; svc #0 。入门阶段更推荐从 _main 开始，用 clang 链接，然后调用 libSystem 提供的 _write 。

文件名： write-macos-arm64.s

.section __TEXT,__const
msg:
    .ascii "macOS arm64 function registers\n"
msg_len = . - msg

.text
.globl _main
.p2align 2
_main:
    // _main 要调用 _write，所以这是非叶子函数。
    // 先保存 x29/x30，避免 bl _write 覆盖返回到 C 运行时的地址。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    // ssize_t write(int fd, const void *buf, size_t count)
    //
    // macOS arm64 调 C 函数时：
    // x0 = 第 1 参数 fd
    // x1 = 第 2 参数 buf
    // x2 = 第 3 参数 count
    mov x0, #1                    // fd = 1，标准输出

    // 在 Mach-O/Apple 汇编中，取全局标签地址常用 PAGE/PAGEOFF 重定位。
    // adrp 先取 msg 所在页的地址。
    // add 再加上 msg 在页内的偏移。
    adrp x1, msg@PAGE
    add x1, x1, msg@PAGEOFF       // x1 = msg 的完整地址

    mov x2, #msg_len              // x2 = 字符串长度
    bl _write                     // 调用 libSystem 的 write

    // main 的返回值放 w0。这里不把 _write 的返回值当退出码，
    // 而是明确返回 0，表示程序成功。
    mov w0, #0

    // 恢复帧指针和返回地址，然后回到 C 运行时。
    ldp x29, x30, [sp], #16
    ret

运行：

clang write-macos-arm64.s -o write-macos-arm64
./write-macos-arm64
echo $?

预期输出：

macOS arm64 function registers
0

这段代码里的 _write 是 C 函数调用，不是裸系统调用。所以使用的是 x0 、 x1 、 x2 这套函数参数约定，而不是 Linux syscall 号那套规则。

11. 条件标志寄存器

比较和条件跳转离不开标志寄存器。

11.1 x86-64 的 rflags

x86-64 的 cmp 本质上做减法但不保存结果，只更新标志位：

cmp $5, %rax      # 根据 rax - 5 设置标志位
je equal          # 如果 ZF = 1，也就是相等，就跳转
jl less           # 有符号比较：如果 rax < 5，就跳转

常见标志：

标志含义常见用途
ZFzero flag，结果为 0判断相等
SFsign flag，结果最高位为 1有符号数正负
CFcarry flag，无符号进位 / 借位无符号比较
OFoverflow flag，有符号溢出有符号比较

很多 x86 算术指令会隐式更新标志位。例如 add 、 sub 、 inc 、 dec 都会影响后续条件跳转。

11.2 AArch64 的 NZCV

AArch64 的标志寄存器通常叫 NZCV ：

标志含义
Nnegative，结果最高位为 1
Zzero，结果为 0
Ccarry，无符号进位 / 借位相关
Voverflow，有符号溢出

AArch64 的一个好处是：是否更新标志通常写在指令名上。

cmp x0, #5        // 实际类似 subs xzr, x0, #5，只更新 NZCV，不保存结果
b.eq equal        // Z = 1 时跳转
b.lt less         // 有符号比较：x0 < 5 时跳转

add x0, x0, #1    // 普通加法，不更新 NZCV
adds x0, x0, #1   // 加法并更新 NZCV

macOS arm64 使用同一套 AArch64 条件标志和条件跳转指令。

本系列前期主要用整数寄存器，但很快会在反汇编里看到浮点和 SIMD 寄存器。

12.1 x86-64

14. 常见坑

14.1 把 C 函数 ABI 和 Linux syscall ABI 混在一起

x86-64 Linux 上：

# C 函数第 4 参数
mov value, %rcx

# Linux syscall 第 4 参数
mov value, %r10

两者不是同一个寄存器。直接写 syscall 时，要按 Linux 内核接口来。

14.2 在 macOS arm64 上使用 x18

标准 AAPCS64 说 x18 是平台寄存器，具体用途由平台决定。Apple 平台保留 x18 ，所以手写 macOS/iOS arm64 汇编时不要把 x18 当普通临时寄存器。

更稳妥的选择：

// 临时值优先用 x9-x15。
mov x9, #123
mov x10, #456

14.3 AArch64 非叶子函数忘记保存 x30

错误思路：

bad:
    bl other_function             // 覆盖 x30
    ret                           // ret 使用被覆盖后的 x30，可能回不到调用者

正确思路：

good:
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    bl other_function

    ldp x29, x30, [sp], #16
    ret

14.4 用了 callee-saved 寄存器却不恢复

如果 x86-64 函数改了 %rbx ，返回前要恢复。如果 AArch64 函数改了 x19 - x28 ，返回前也要恢复。否则调用者可能在函数返回后读到被破坏的值。

14.5 以为条件标志能跨函数调用保存

不要指望 cmp 之后调用一个函数，再回来继续用之前的标志位。

cmp $0, %rax
call helper
je label          # 这里不可靠，helper 可能已经改了标志位

更稳妥的写法是：需要跳转时，比较和条件跳转尽量靠近。

14.6 把 sp 当普通寄存器乱改

栈指针不是普通临时变量。函数调用、局部变量、返回地址、调试回溯都依赖栈指针。修改 sp/rsp 时要保证：

  • 分配多少，释放多少。
  • AArch64/macOS arm64 的 sp 保持 16 字节对齐。
  • 调用 C 函数前遵守平台 ABI 的栈对齐要求。

15. 小练习

  1. 把 call-x86.s 、 call-aarch64.s 、 call-macos-arm64.s 里的参数 2, 3, 4 改成 10, 20, 30 ，重新运行，确认退出码变成 60 。
  2. 在 x86-64 的 add3 里故意使用 %rbx ，先不保存，再用 push %rbx / pop %rbx 修复。思考为什么 ABI 要区分 caller-saved 和 callee-saved。
  3. 在 AArch64 的 _main 里去掉保存 x30 的 stp/ldp ，观察程序是否崩溃或返回异常。然后恢复保存逻辑。
  4. 用 objdump -d call-x86 或 llvm-objdump -d call-macos-arm64 观察 call 、 bl 、 ret 最终反汇编长什么样。
  5. 把 mov w0, #7 改成 mov x0, #7 ，确认退出码仍是 7 。再思考两者对高 32 位的差别。
