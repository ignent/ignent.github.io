数组

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的数组访问。

汇编里没有高级语言意义上的 “数组类型”。数组就是一段连续内存，由程序员明确指定：

起始地址
元素大小
元素个数

访问 array[i] 的核心公式是：

元素地址 = 数组起始地址 + i * 元素大小

如果元素是 8 字节整数：

array[i] 地址 = base + i * 8

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的数组加载 / 存储指令基本相同；差异主要在全局符号取地址、入口、链接方式和退出方式。

1. 一张表先建立全局印象

操作x86-64 LinuxAArch64 LinuxmacOS arm64
定义 64 位数组.quad 1, 2, 3.quad 1, 2, 3.quad 1, 2, 3
取数组地址lea arr(%rip), %regadrp/add :lo12:adrp/add @PAGEOFF
访问 64 位元素(%base,%idx,8)[base, index, lsl #3]同 AArch64
访问 32 位元素(%base,%idx,4)[base, index, lsl #2]同 AArch64
指针后移add $8, %regadd xN, xN, #8 或后索引同 AArch64
读取 1 字节movzbq (%reg), %raxldrb wN, [xM]同 AArch64
读取 8 字节mov (%reg), %raxldr xN, [xM]同 AArch64

两个常见访问方式：

索引方式：base + i * elem_size
指针方式：p 从 array 开始，每次 p += elem_size

2. 数组在内存里长什么样

定义 4 个 64 位整数：

numbers:
    .quad 10, 20, 30, 40

如果 numbers 起始地址是 base ，那么：

元素地址值
numbers[0]base + 0 * 810
numbers[1]base + 1 * 820
numbers[2]base + 2 * 830
numbers[3]base + 3 * 840

元素大小决定缩放因子：

元素定义元素大小缩放
.byte1 字节i * 1
.word2 字节i * 2
.long4 字节i * 4
.quad8 字节i * 8

3. 三个平台示例：数组求和

目标逻辑：

numbers = {10, 20, 30, 40};
sum = 0;

for (i = 0; i < 4; i++) {
    sum += numbers[i];
}

return sum;

预期退出码：

10 + 20 + 30 + 40 = 100

3.1 x86-64 Linux

文件名： array-x86-64.s

.section .data
numbers:
    .quad 10, 20, 30, 40
numbers_len = 4

.section .text
.global _start
_start:
    # rbx = numbers 的起始地址
    # rcx = i
    # rax = sum

    lea numbers(%rip), %rbx                  # rbx = &numbers[0]
    xor %rcx, %rcx                           # rcx = i = 0
    xor %rax, %rax                           # rax = sum = 0

loop_start:
    cmp $numbers_len, %rcx                   # i < numbers_len ?
    jge loop_done                            # 如果 i >= len，结束

    # numbers[i] 的地址是 rbx + rcx * 8。
    # 因为每个 .quad 元素是 8 字节。
    add (%rbx, %rcx, 8), %rax                # sum += numbers[i]

    inc %rcx                                 # i++
    jmp loop_start

loop_done:
    # exit(sum)
    mov %rax, %rdi                           # rdi = 100
    mov $60, %rax                            # Linux x86-64 exit
    syscall

编译运行：

as --64 array-x86-64.s -o array-x86-64.o
ld array-x86-64.o -o array-x86-64
./array-x86-64
echo $?

预期输出：

100

3.2 AArch64 Linux

文件名： array-aarch64.s

.section .data
numbers:
    .quad 10, 20, 30, 40
.equ numbers_len, 4

.section .text
.global _start
_start:
    // x1 = numbers 的起始地址
    // x2 = i
    // x0 = sum

    adrp x1, numbers                         // x1 = numbers 所在页
    add x1, x1, :lo12:numbers                // x1 = &numbers[0]

    mov x2, #0                               // x2 = i = 0
    mov x0, #0                               // x0 = sum = 0

loop_start:
    cmp x2, #numbers_len                     // i < numbers_len ?
    b.ge loop_done                           // 如果 i >= len，结束

    // [x1, x2, lsl #3] 表示地址 x1 + x2 * 8。
    // #3 是因为左移 3 位等于乘以 8。
    ldr x3, [x1, x2, lsl #3]                 // x3 = numbers[i]
    add x0, x0, x3                           // sum += x3

    add x2, x2, #1                           // i++
    b loop_start

loop_done:
    // exit(sum)
    mov x8, #93                              // Linux AArch64 exit
    svc #0

编译运行：

as array-aarch64.s -o array-aarch64.o
ld array-aarch64.o -o array-aarch64
./array-aarch64
echo $?

预期输出：

100

3.3 macOS arm64

文件名： array-macos-arm64.s

.data
numbers:
    .quad 10, 20, 30, 40
.equ numbers_len, 4

.text
.globl _main
.p2align 2
_main:
    // x1 = numbers 的起始地址
    // x2 = i
    // x0 = sum

    adrp x1, numbers@PAGE
    add x1, x1, numbers@PAGEOFF              // x1 = &numbers[0]

    mov x2, #0                               // x2 = i = 0
    mov x0, #0                               // x0 = sum = 0

loop_start:
    cmp x2, #numbers_len                     // i < numbers_len ?
    b.ge loop_done

    ldr x3, [x1, x2, lsl #3]                 // x3 = numbers[i]
    add x0, x0, x3                           // sum += x3

    add x2, x2, #1                           // i++
    b loop_start

loop_done:
    // main 返回值放在 x0/w0。
    ret

编译运行：

clang array-macos-arm64.s -o array-macos-arm64
./array-macos-arm64
echo $?

预期输出：

100

4. 索引寻址

4.1 x86-64：base + index * scale

x86-64 的典型内存地址形式是：

displacement(base, index, scale)

例如：

mov (%rbx, %rcx, 8), %rax

含义是：

rax = *(rbx + rcx * 8)

scale 只能是 1 、 2 、 4 、 8 ，刚好适合常见元素宽度。

4.2 AArch64：base + index << shift

AArch64 常见写法：

ldr x3, [x1, x2, lsl #3]

含义是：

x3 = *(x1 + (x2 << 3))

x2 << 3 等价于 x2 * 8 。

如果访问 32 位整数数组：

ldr w3, [x1, x2, lsl #2]    // x1 + x2 * 4

如果访问字节数组：

ldrb w3, [x1, x2]           // x1 + x2 * 1

5. 指针遍历

索引不是唯一方式。也可以让指针一路向后走：

p = numbers;
end = numbers + len;

while (p != end) {
    sum += *p;
    p++;
}

x86-64：

lea numbers(%rip), %rsi
lea numbers_end(%rip), %rdx
xor %rax, %rax

loop_start:
    cmp %rdx, %rsi
    je loop_done

    add (%rsi), %rax
    add $8, %rsi
    jmp loop_start

loop_done:

AArch64/macOS arm64：

// x1 = p, x2 = end, x0 = sum
loop_start:
    cmp x1, x2
    b.eq loop_done

    ldr x3, [x1], #8     // x3 = *p，然后 p += 8
    add x0, x0, x3
    b loop_start

loop_done:

指针遍历适合顺序扫描；索引寻址适合需要经常访问 array[i] 、 array[j] 的场景。

6. 查找最大值

目标逻辑：

max = numbers[0];
for (i = 1; i < len; i++) {
    if (numbers[i] > max) {
        max = numbers[i];
    }
}

x86-64：

lea numbers(%rip), %rbx
mov (%rbx), %rax          # max = numbers[0]
mov $1, %rcx              # i = 1

loop_start:
    cmp $numbers_len, %rcx
    jge loop_done

    mov (%rbx, %rcx, 8), %rdx
    cmp %rax, %rdx        # 比较 numbers[i] 和 max
    jle skip_update

    mov %rdx, %rax        # max = numbers[i]

skip_update:
    inc %rcx
    jmp loop_start

loop_done:

AArch64/macOS arm64：

// x1 = numbers，x0 = max，x2 = i
ldr x0, [x1]              // max = numbers[0]
mov x2, #1                // i = 1

loop_start:
    cmp x2, #numbers_len
    b.ge loop_done

    ldr x3, [x1, x2, lsl #3]
    cmp x3, x0
    b.le skip_update

    mov x0, x3            // max = numbers[i]

skip_update:
    add x2, x2, #1
    b loop_start

loop_done:

如果数组元素是无符号数，比较条件要改成 jbe/ja 或 b.ls/b.hi 这一组。

7. 修改数组元素

数组放在 .data 中才能修改：

.section .data
numbers:
    .quad 1, 2, 3, 4

把 numbers[2] 改成 99 。

x86-64：

lea numbers(%rip), %rbx
movq $99, 16(%rbx)        # 2 * 8 = 16

AArch64/macOS arm64：

mov x3, #99
str x3, [x1, #16]         // 2 * 8 = 16

不要修改 .rodata 或 macOS 的只读段里的数据。只读段通常没有写权限，写入会崩溃。

8. 字节数组

字符串可以看作字节数组。

bytes:
    .byte 1, 2, 3, 4, 5

x86-64 读取 bytes[i] ：

movzbq (%rbx, %rcx, 1), %rax

AArch64 读取 bytes[i] ：

ldrb w3, [x1, x2]

字节读取时通常要零扩展，因为通常不希望寄存器高位残留旧值。

9. 二维数组直觉

C 语言的二维数组按行连续存放：

int a[2][3] = {
    {1, 2, 3},
    {4, 5, 6},
};

内存里是：

1, 2, 3, 4, 5, 6

访问 a[row][col] ：

地址 = base + (row * 列数 + col) * 元素大小

如果是 64 位整数，列数是 3 ：

地址 = base + (row * 3 + col) * 8

x86-64/AArch64 都可以先算出 row * 3 + col ，再按一维数组访问。

10. 常见错误

10.1 元素大小乘错

.quad 是 8 字节，不是 4 字节：

add (%rbx, %rcx, 8), %rax

AArch64：

ldr x3, [x1, x2, lsl #3]

如果把缩放写成 4，就会读到元素中间，结果完全错误。

10.2 越界访问

数组不会自动检查边界：

numbers[4]

对于长度为 4 的数组已经越界。汇编会照样访问那块地址，可能读到别的数据，也可能崩溃。

10.3 把字节加载当成 64 位加载

字符串要用字节加载：

movzbq (%rsi), %rax    # x86-64
ldrb w0, [x1]          // AArch64

如果用 64 位加载，会一次读 8 个字节。

10.4 修改只读数组

放在 .rodata 或 __TEXT,__cstring 里的内容通常只读。要修改数组，应放在 .data 或 .bss 。

10.5 macOS 取地址重定位写错

Linux AArch64：

adrp x1, numbers
add x1, x1, :lo12:numbers

macOS arm64：

adrp x1, numbers@PAGE
add x1, x1, numbers@PAGEOFF
