LSPosed Native Hook：JNI 方法参数动态解析与调用堆栈追踪

ZIP2026/6/15...大约 12 分钟XposedLSPosedNative HookJNI动态分析堆栈追踪

方案概述

在 Android Native 层逆向分析中，我们经常需要：

  1. 动态获取 JNI 方法的参数信息：某个 Native 方法被调用时，传入了哪些参数？参数类型是什么？
  2. 追踪方法的调用堆栈：这个方法是从哪里被调用的？完整的调用链路是什么？

本文介绍两种核心技术：

  • 使用 JNI 反射 + 可变参数动态解析方法参数
  • 使用 backtrace 和 dladdr 追踪调用堆栈

这些技术在分析加密算法、追踪敏感数据流向时非常有用。

技术原理

1. JNI 方法参数动态解析

问题背景

当我们 Hook 一个 JNI 函数（如 GetStringUTFChars ）时，通常只能获取固定的参数（如 jstring str ），但无法知道：

  • 调用者是哪个 Java 方法？
  • 该 Java 方法的参数列表是什么？
  • 参数的具体值是什么？

解决方案

通过 JNI 反射机制 + C++ 可变参数（va_list），我们可以：

  1. 使用 env->ToReflectedMethod() 将 jmethodID 转换为 Java 反射的 Method 对象
  2. 调用 Method.getParameterCount() 获取参数个数
  3. 调用 Method.getParameterTypes() 获取参数类型数组
  4. 使用 va_list 逐个读取传入的实际参数值

2. 调用堆栈追踪

方案对比

方法实现方式优点缺点
__builtin_return_address(n)GCC 内建函数开销小，简单只能获取有限层数（通常 < 10 层）
backtrace()GNU libc 函数可获取完整调用链需要 API Level 33+，性能开销较大
dladdr()动态链接库 API可解析函数符号和模块信息只能获取单个地址信息

本文采用 backtrace() + backtrace_symbols() 方案，获取完整的调用堆栈。

核心函数 1：动态解析方法参数

#include <jni.h>
#include <sstream>
#include <android/log.h>

// 从 jobject 获取类名（重载版本）
std::string get_class_name(JNIEnv *env, jobject obj) {
    jclass jclazz = env->FindClass("java/lang/Class");
    jmethodID class_getName_method = env->GetMethodID(jclazz, "getName", "()Ljava/lang/String;");
    
    auto class_name = (jstring) env->CallObjectMethod(obj, class_getName_method);
    auto class_name_cstr = env->GetStringUTFChars(class_name, nullptr);
    
    std::string result(class_name_cstr);
    
    // 释放资源
    env->ReleaseStringUTFChars(class_name, class_name_cstr);
    env->DeleteLocalRef(class_name);
    env->DeleteLocalRef(jclazz);
    
    return result;
}

// 动态解析并打印方法参数
static void show_args(JNIEnv *env, jobject obj, jmethodID jmethodId, bool isStatic, ...) {
    if (obj == nullptr || jmethodId == nullptr) { 
        return; 
    }
    
    // 1. 获取方法对应的 Class 对象
    jclass obj_class = env->GetObjectClass(obj);
    
    // 2. 将 jmethodID 转换为 Java 反射的 Method 对象
    jobject obj_method = env->ToReflectedMethod(obj_class, jmethodId, isStatic);
    jclass method_class = env->GetObjectClass(obj_method);
    
    // 3. 获取参数个数
    jmethodID getParameterCount_method_id = env->GetMethodID(
        method_class, "getParameterCount", "()I"
    );
    jint args_count = env->CallIntMethod(obj_method, getParameterCount_method_id);
    
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", "Args Count: %d", args_count);
    
    if (args_count == 0) { 
        __android_log_print(ANDROID_LOG_DEBUG, "0X->", "No Args");
        return;
    }
    
    // 4. 获取参数类型数组
    jmethodID getParameterTypes_method_id = env->GetMethodID(
        method_class, "getParameterTypes", "()[Ljava/lang/Class;"
    );
    auto args_types = (jobjectArray) env->CallObjectMethod(
        obj_method, getParameterTypes_method_id
    );
    
    // 5. 使用可变参数列表读取实际参数值
    va_list args;
    va_start(args, isStatic);  // 从 isStatic 后开始读取
    
    std::stringstream ss;
    
    for (int i = 0; i < args_count; ++i) {
        auto arg_obj = env->GetObjectArrayElement(args_types, i);
        if (arg_obj == nullptr) { continue; }
        
        // 获取参数类型的类名
        auto class_name = get_class_name(env, arg_obj);
        if (class_name.empty()) { continue; }
        
        // 根据类型读取对应的参数值
        if (class_name == "boolean" || class_name == "java.lang.Boolean") {
            // 注意：va_arg 对于小于 int 的类型会提升为 int
            jboolean arg = va_arg(args, int);
            ss << class_name << "(" << (arg == JNI_TRUE ? "true" : "false") << ")\n";
        }
        // 可以扩展其他类型：int, long, String, Object 等
    }
    
    va_end(args);
    
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", "args: %s", ss.str().c_str());
}

关键技术点解析

1. ToReflectedMethod() - 桥接 JNI 和 Java 反射
jobject env->ToReflectedMethod(jclass cls, jmethodID methodID, jboolean isStatic)
  • 作用：将 Native 层的 jmethodID 转换为 Java 层的 java.lang.reflect.Method 对象
  • 为什么需要： jmethodID 只是一个 Native 指针，无法直接获取方法的元数据（参数类型、返回值等）
  • 转换后可调用的 Java 方法：
    • Method.getParameterCount() - 获取参数个数
    • Method.getParameterTypes() - 获取参数类型数组
    • Method.getName() - 获取方法名
2. 可变参数 va_list 的使用
void show_args(JNIEnv *env, jobject obj, jmethodID jmethodId, bool isStatic, ...) {
    va_list args;
    va_start(args, isStatic);  // 从最后一个固定参数开始
    
    for (int i = 0; i < args_count; ++i) {
        jboolean arg = va_arg(args, int);  // 读取下一个参数
    }
    
    va_end(args);  // 清理
}

注意事项：

  • va_arg 的第二个参数是期望的类型
  • boolean 类型会被提升为 int ，所以用 va_arg(args, int) 而非 jboolean
  • 必须按顺序读取，不能跳过或回退
  • 必须事先知道参数个数和类型（通过反射获取）
3. 类型映射表
Java 类型JNI 类型va_arg 类型原因
booleanjbooleanintC 可变参数提升规则
bytejbyteint小于 int 的整数提升
intjintjint直接对应
longjlongjlong直接对应

核心函数 2：调用堆栈追踪

#include <execinfo.h>

static void get_stacktrace() {
    int nptrs;
    void *buffer[100];  // 存储最多 100 个栈帧地址
    char **strings;
    
    // 1. 获取当前调用栈的所有返回地址
    nptrs = backtrace(buffer, 100);
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", "backtrace() has %d address", nptrs);
    
    // 2. 将地址转换为符号字符串
    strings = backtrace_symbols(buffer, nptrs);
    
    if (strings == nullptr) {
        __android_log_print(ANDROID_LOG_DEBUG, "0X->", "has empty backtrace");
        return;
    }
    
    // 3. 打印所有栈帧
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", "Call stacks\n");
    for (int i = 0; i < nptrs; ++i) {
        __android_log_print(ANDROID_LOG_DEBUG, "0X->", "#%d: %s\n", i, strings[i]);
    }
    
    // 4. 释放内存
    free(strings);
}

函数说明

backtrace() - 获取调用栈地址
int backtrace(void **buffer, int size);
  • 参数：
    • buffer : 存储返回地址的数组
    • size : 数组大小（最多获取多少层）
  • 返回值：实际获取的栈帧数量
  • 原理：遍历栈帧的 Frame Pointer (FP) 链，提取每一层的返回地址
backtrace_symbols() - 地址符号化
char **backtrace_symbols(void *const *buffer, int size);
  • 作用：将内存地址转换为可读的字符串（函数名、模块名、偏移）
  • 返回格式示例：
    /system/lib64/libc.so(__epoll_pwait+92)
/apex/com.android.art/lib64/libart.so(art::JNI::CallStaticVoidMethod+123)
  • 注意：返回的字符串数组需要调用 free() 释放
dladdr() - 获取单个地址的详细信息
#include <dlfcn.h>

Dl_info info;
if (dladdr((void *) __builtin_return_address(0), &info)) {
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", 
        "Module: %s\nFunction: %s\nAddress: %p",
        info.dli_fname,   // 模块路径
        info.dli_sname,   // 符号名称
        info.dli_saddr    // 符号地址
    );
}

核心函数 3：Hook JNI 函数并追踪调用

const char *(*original_GetStringUTFChars)(JNIEnv *, jstring, jboolean *);

const char *hook_GetStringUTFChars(JNIEnv *env, jstring str, jboolean *isCopy) {
    // 1. 获取调用者信息
    Dl_info info;
    dladdr((void *) __builtin_return_address(0), &info);
    
    // 2. 调用原始函数获取字符串
    const char *ret = original_GetStringUTFChars(env, str, isCopy);
    
    // 3. 过滤特定模块（例如只关注某个 so）
    if (std::string(info.dli_fname).ends_with("libexercise16.so")) {
        // 4. 打印调用堆栈
        get_stacktrace();
        
        // 5. 打印字符串内容和调用模块
        __android_log_print(ANDROID_LOG_DEBUG, "0X->", 
            "hook_GetStringUTFChars: %s, called from: %s", 
            ret, info.dli_fname
        );
    }
    
    return ret;
}

// 安装 Hook
extern "C" JNIEXPORT void JNICALL
Java_com_xposed_NativeLib_initNative(JNIEnv *env, jclass clazz) {
    DobbyHook(
        (void *) env->functions->GetStringUTFChars, 
        (void *) hook_GetStringUTFChars,
        (void **) &original_GetStringUTFChars
    );
}

技术要点解析

1. env->functions->GetStringUTFChars - Hook JNI 函数表
struct JNINativeInterface {
    // ... 其他 JNI 函数 ...
    const char* (*GetStringUTFChars)(JNIEnv*, jstring, jboolean*);
    // ...
};

// env->functions 是指向 JNINativeInterface 的指针
// 可以直接 Hook 函数表中的函数指针

为什么 Hook 函数表而不是符号：

  • JNI 函数通过函数表调度，而非直接调用符号
  • Hook 函数表可以拦截所有通过 JNIEnv 的调用
  • 不需要查找符号地址，直接使用 env->functions->FunctionName
2. __builtin_return_address(0) - 获取调用者地址
void *caller = __builtin_return_address(0);  // 直接调用者
void *caller2 = __builtin_return_address(1); // 上上层调用者
  • 返回值：当前函数被调用时的返回地址（即调用者的下一条指令地址）
  • 用途：结合 dladdr() 可以确定调用来自哪个模块的哪个函数
  • 限制：参数必须是编译期常量，通常最多支持到 __builtin_return_address(10)

实战案例：追踪加密密钥

场景描述

某 App 的 Native 层有一个加密函数，通过 GetStringUTFChars 获取密钥字符串。我们需要：

  1. 找出密钥的值
  2. 确定调用来自哪个模块
  3. 获取完整的调用堆栈

实现代码

const char *hook_GetStringUTFChars(JNIEnv *env, jstring str, jboolean *isCopy) {
    // 1. 获取调用者信息
    Dl_info info;
    dladdr((void *) __builtin_return_address(0), &info);
    
    // 2. 获取字符串内容
    const char *ret = original_GetStringUTFChars(env, str, isCopy);
    
    // 3. 过滤目标模块（假设加密逻辑在 libencrypt.so）
    if (std::string(info.dli_fname).ends_with("libencrypt.so")) {
        // 4. 打印密钥
        __android_log_print(ANDROID_LOG_WARN, "0X->", 
            "[KEY FOUND] %s", ret
        );
        
        // 5. 打印调用堆栈
        get_stacktrace();
    }
    
    return ret;
}

extern "C"
JNIEXPORT void JNICALL
Java_com_xposed_NativeLib_initNative(JNIEnv *env, jclass clazz) {
    // Hook JNI 函数表
    DobbyHook(
        (void *) env->functions->GetStringUTFChars, 
        (void *) hook_GetStringUTFChars,
        (void **) &original_GetStringUTFChars
    );
}

完整的类型解析实现

static void show_args(JNIEnv *env, jobject obj, jmethodID jmethodId, bool isStatic, ...) {
    // ... 前置代码同上 ...
    
    va_list args;
    va_start(args, isStatic);
    std::stringstream ss;
    
    for (int i = 0; i < args_count; ++i) {
        auto arg_obj = env->GetObjectArrayElement(args_types, i);
        auto class_name = get_class_name(env, arg_obj);
        
        if (class_name == "boolean" || class_name == "java.lang.Boolean") {
            jboolean arg = va_arg(args, int);
            ss << "boolean(" << (arg ? "true" : "false") << ")\n";
        }
        else if (class_name == "int" || class_name == "java.lang.Integer") {
            jint arg = va_arg(args, jint);
            ss << "int(" << arg << ")\n";
        }
        else if (class_name == "long" || class_name == "java.lang.Long") {
            jlong arg = va_arg(args, jlong);
            ss << "long(" << arg << ")\n";
        }
        else if (class_name == "java.lang.String") {
            jstring arg = va_arg(args, jstring);
            const char *str = env->GetStringUTFChars(arg, nullptr);
            ss << "String(\"" << str << "\")\n";
            env->ReleaseStringUTFChars(arg, str);
        }
        else if (class_name.starts_with("[")) {
            // 数组类型
            jobject arg = va_arg(args, jobject);
            jarray jarr = (jarray) arg;
            jint len = env->GetArrayLength(jarr);
            ss << "Array[" << len << "]\n";
        }
        else {
            // 其他对象类型
            jobject arg = va_arg(args, jobject);
            ss << class_name << "@" << arg << "\n";
        }
    }
    
    va_end(args);
    __android_log_print(ANDROID_LOG_DEBUG, "0X->", "args:\n%s", ss.str().c_str());
}

常见问题与注意事项

1. backtrace() 在 API < 33 上不可用

错误信息：

undefined reference to `backtrace'

解决方案：

  • 方案 A：设置 minSdk = 33 （推荐）
  • 方案 B：使用 __builtin_return_address(n) 替代（最多 10 层）
  • 方案 C：手动实现栈回溯（通过 FP 寄存器遍历栈帧，复杂度高）

方案 B 示例代码：

static void get_stacktrace_builtin() {
    for (int i = 0; i < 10; ++i) {
        void *addr = nullptr;
        switch (i) {
            case 0: addr = __builtin_return_address(0); break;
            case 1: addr = __builtin_return_address(1); break;
            case 2: addr = __builtin_return_address(2); break;
            // ... 最多到 9
            default: return;
        }
        if (!addr) break;
        
        Dl_info info;
        if (dladdr(addr, &info)) {
            __android_log_print(ANDROID_LOG_DEBUG, "0X->", 
                "#%d: %s (%s+%ld)", 
                i, 
                info.dli_fname,
                info.dli_sname ? info.dli_sname : "???",
                (long)addr - (long)info.dli_saddr
            );
        }
    }
}

错误示例：

jboolean arg = va_arg(args, jboolean);  // ❌ 可能崩溃

正确写法：

jboolean arg = va_arg(args, int);  // ✅ 必须用 int

3. 内存泄漏风险

问题代码：

strings = backtrace_symbols(buffer, nptrs);
// 忘记 free(strings) - 内存泄漏

正确做法：

strings = backtrace_symbols(buffer, nptrs);
if (strings) {
    // 使用 strings...
    free(strings);  // ✅ 必须释放
}

4. ToReflectedMethod 的性能开销

  • 每次调用都会创建新的 Java Method 对象
  • 频繁调用会触发 GC
  • 优化建议：缓存 Method 对象或 jmethodID
static std::unordered_map<jmethodID, jobject> method_cache;

jobject get_cached_method(JNIEnv *env, jclass clazz, jmethodID id) {
    if (method_cache.find(id) == method_cache.end()) {
        jobject method = env->ToReflectedMethod(clazz, id, true);
        method_cache[id] = env->NewGlobalRef(method);  // 全局引用
    }
    return method_cache[id];
}

5. 堆栈符号解析不完整

现象：

D/0X->: #3: /data/app/.../lib/arm64/libencrypt.so(+0x12ab4)

符号名为空，只显示偏移。

原因：

  • so 被 strip 移除了符号表
  • 使用了 inline 或静态函数

解决方案：

  • 使用 IDA/Ghidra 根据偏移查找函数

调试技巧

1. 实时查看 Logcat

adb logcat -s "0X->"

2. 过滤特定模块的调用

if (std::string(info.dli_fname).find("target.so") != std::string::npos) {
    // 只分析 target.so 的调用
}

3. 条件断点（通过日志模拟）

static int call_count = 0;
if (++call_count == 100) {  // 只在第 100 次调用时打印
    get_stacktrace();
}

4. 导出堆栈到文件

#include <fstream>

void save_stacktrace(const char *filepath) {
    void *buffer[100];
    int nptrs = backtrace(buffer, 100);
    char **strings = backtrace_symbols(buffer, nptrs);
    
    std::ofstream file(filepath, std::ios::app);
    for (int i = 0; i < nptrs; ++i) {
        file << strings[i] << "\n";
    }
    file.close();
    free(strings);
}

// 使用
save_stacktrace("/sdcard/Download/stacktrace.txt");

总结

本文介绍了两种强大的 Native 动态分析技术：

  1. JNI 方法参数解析：

    • 使用 ToReflectedMethod 将 jmethodID 转换为 Java 反射对象
    • 通过 getParameterTypes() 获取参数类型
    • 使用 va_list 配合类型判断读取实际参数值

  2. 调用堆栈追踪：

    • 使用 backtrace() 获取完整调用链（需要 API 33+）
    • 使用 dladdr() 解析单个地址的模块和符号信息
    • 使用 __builtin_return_address() 作为低版本替代方案

这些技术组合可以实现：

  • 加密算法的密钥和参数追踪
  • 敏感 API 的调用来源分析
  • 数据流向的完整链路还原
  • 混淆代码的动态行为理解

通过实际代码示例和日志输出，读者可以直接复现并应用到自己的逆向分析项目中。
