XposedHelpers 常用方法

de.robv.android.xposed.XposedHelpers 。

总原则：

  • findClass* ：找类
  • findMethod* / findAndHookMethod ：找方法、Hook 方法
  • findConstructor* / findAndHookConstructor ：找构造函数、Hook 构造函数
  • findField* / set*Field ：找字段、改字段

官方 API 文档：

  • https://api.xposed.info/reference/de/robv/android/xposed/XposedHelpers.html

1. 方法 Hook

findAndHookMethod

作用：

  • 按 “类 + 方法名 + 参数类型” 定位目标方法
  • 找到后直接挂上 Hook

最常用，也是实际开发里最常见的方法。

最小示例：

XposedHelpers.findAndHookMethod(
        "com.example.Target",
        lpparam.classLoader,
        "check",
        String.class,
        new XC_MethodHook() {
            @Override
            protected void beforeHookedMethod(MethodHookParam param) {
            }

            @Override
            protected void afterHookedMethod(MethodHookParam param) {
            }
        }
);

要点：

  • 最后一个参数必须是 XC_MethodHook 或 XC_MethodReplacement
  • 前面的参数是方法参数类型
  • 目标类如果是应用自己的类，通常用 lpparam.classLoader
  • 它内部本质上是 “先找方法，再调用 XposedBridge.hookMethod(...) ”

适合场景：

  • 已经知道类名、方法名、参数列表
  • 目标明确，想一步到位直接 Hook

注意：

  • 它要求方法是 “在这个类里声明或重写” 的方法
  • 不要误以为它会自动处理所有继承链

findMethodExact

作用：

  • 精确查找一个方法
  • 只返回 Method
  • 不会自动 Hook

最小示例：

Method method = XposedHelpers.findMethodExact(
        "com.example.Target",
        lpparam.classLoader,
        "check",
        String.class
);

适合场景：

  • 只想先拿到 Method
  • 后面准备自己决定怎么处理

和 findAndHookMethod 的区别：

  • findMethodExact 只 “找”
  • findAndHookMethod 是 “找 + Hook”

findMethodExactIfExists

作用：

  • 和 findMethodExact 一样，也是精确查找
  • 但目标不存在时不抛异常，而是返回 null

最小示例：

Method method = XposedHelpers.findMethodExactIfExists(
        "com.example.Target",
        lpparam.classLoader,
        "check",
        String.class
);

if (method != null) {
    // 再决定后续处理
}

适合场景：

  • 目标方法在不同版本里可能有，也可能没有
  • 不想因为一次找不到就直接异常退出

findMethodsByExactParameters

作用：

  • 按 “返回值类型 + 参数类型” 查找方法
  • 返回的是 Method[]

最小示例：

Method[] methods = XposedHelpers.findMethodsByExactParameters(
        targetClass,
        boolean.class,
        String.class,
        int.class
);

适合场景：

  • 方法名混淆了
  • 但知道返回值和参数签名

注意：

  • 返回值可能不止一个
  • 通常还要自己再筛选方法名、修饰符或调用位置

2. 构造函数 Hook

findAndHookConstructor

作用：

  • 精确找到构造函数
  • 直接对构造函数挂 Hook

最小示例：

XposedHelpers.findAndHookConstructor(
        "com.example.Target",
        lpparam.classLoader,
        String.class,
        int.class,
        new XC_MethodHook() {
            @Override
            protected void afterHookedMethod(MethodHookParam param) {
            }
        }
);

适合场景：

  • 想在对象创建时拿到参数或改实例状态

和方法 Hook 的区别：

  • 构造函数没有方法名
  • 只写类名、参数类型和回调

findConstructorExact

作用：

  • 精确查找构造函数
  • 返回 Constructor
  • 不自动 Hook

最小示例：

Constructor<?> constructor = XposedHelpers.findConstructorExact(
        "com.example.Target",
        lpparam.classLoader,
        String.class,
        int.class
);

适合场景：

  • 先拿到构造函数对象，后面自己处理

findConstructorExactIfExists

作用：

  • 和 findConstructorExact 一样
  • 但找不到时返回 null

最小示例：

Constructor<?> constructor = XposedHelpers.findConstructorExactIfExists(
        "com.example.Target",
        lpparam.classLoader,
        String.class,
        int.class
);

适合场景：

  • 不同版本构造参数不完全一样
  • 要先试探目标是否存在

findConstructorBestMatch

作用：

  • 按 “最接近” 的参数类型找构造函数
  • 不要求像 Exact 那样完全严格一致

最小示例：

Constructor<?> constructor = XposedHelpers.findConstructorBestMatch(
        targetClass,
        String.class,
        int.class
);

适合场景：

  • 不能 100% 确认精确签名
  • 或者手里只有参数对象，想让它尽量自动匹配

注意：

  • 它比 Exact 更宽松
  • 也因此更容易因为重载太多而匹配到不想要的构造函数
  • 能用 Exact 时，优先 Exact

3. 类的查找

findClass

作用：

  • 用类名和 ClassLoader 找到 Class<?>

最小示例：

Class<?> targetClass = XposedHelpers.findClass(
        "com.example.Target",
        lpparam.classLoader
);

适合场景：

  • 后面要继续找方法、字段、构造函数
  • 想先把类对象拿到手

要点：

  • 应用自身类一般用 lpparam.classLoader
  • 系统框架类有时可以传 null
  • 内部类常见写法：
    com.example.Outer$Inner

findClassIfExists

作用：

  • 和 findClass 一样
  • 但找不到时返回 null ，不直接抛错

最小示例：

Class<?> targetClass = XposedHelpers.findClassIfExists(
        "com.example.Target",
        lpparam.classLoader
);

if (targetClass == null) {
    return;
}

适合场景：

  • 混淆版本或多版本兼容
  • 目标类可能不存在

4. 字段的查找与设置

findField

作用：

  • 按字段名查找字段
  • 返回 Field

最小示例：

Field field = XposedHelpers.findField(targetClass, "token");

适合场景：

  • 字段名稳定
  • 明确知道字段就叫这个名字

findFieldIfExists

作用：

  • 和 findField 一样
  • 但找不到时返回 null

最小示例：

Field field = XposedHelpers.findFieldIfExists(targetClass, "token");
if (field == null) {
    return;
}

适合场景：

  • 字段名可能变化
  • 不想因为某个版本没有这个字段而直接报错

findFirstFieldByExactType

作用：

  • 不按字段名
  • 而是按 “字段类型” 找类里第一个匹配字段

最小示例：

Field field = XposedHelpers.findFirstFieldByExactType(
        targetClass,
        String.class
);

适合场景：

  • 字段名被混淆了
  • 但知道这个类里有一个唯一的 String / Map / List 字段

注意：

  • 如果同类型字段有多个，它只会拿到 “第一个”
  • 所以这个方法适合 “类型很有辨识度” 的场景，不适合盲用

5. 设置字段值

这些 set*Field 都是 “修改对象实例字段” 的方法。

共同点：

  • 第一个参数是对象实例 obj
  • 第二个参数是字段名 fieldName
  • 第三个参数是要写入的值

也就是说，它们针对的是：

  • param.thisObject
  • 或已经拿到的某个对象实例

不是：

  • 单独传一个 Class<?>

setObjectField

作用：

  • 给对象字段写入引用类型值

示例：

XposedHelpers.setObjectField(param.thisObject, "token", "fake_token");

适合：

  • String
  • List
  • Map
  • 自定义对象

setBooleanField

作用：

  • 改 boolean 字段

示例：

XposedHelpers.setBooleanField(param.thisObject, "isVip", true);

setByteField

作用：

  • 改 byte 字段

示例：

XposedHelpers.setByteField(param.thisObject, "flag", (byte) 1);

setCharField

作用：

  • 改 char 字段

示例：

XposedHelpers.setCharField(param.thisObject, "grade", 'A');

setDoubleField

作用：

  • 改 double 字段

示例：

XposedHelpers.setDoubleField(param.thisObject, "price", 0.0d);

setFloatField

作用：

  • 改 float 字段

示例：

XposedHelpers.setFloatField(param.thisObject, "ratio", 1.0f);

setIntField

作用：

  • 改 int 字段

示例：

XposedHelpers.setIntField(param.thisObject, "count", 999);

setLongField

作用：

  • 改 long 字段

示例：

XposedHelpers.setLongField(param.thisObject, "expireTime", Long.MAX_VALUE);

setShortField

作用：

  • 改 short 字段

示例：

XposedHelpers.setShortField(param.thisObject, "level", (short) 10);

注意：

  • 这些方法是实例字段版本
  • 如果改的是静态字段，要用对应的 setStatic*Field
  • 这里没有展开静态字段方法，但官方文档里有

6. 最容易混淆的几组区别

findAndHookMethod vs findMethodExact

  • findAndHookMethod ：直接找并 Hook
  • findMethodExact ：只找方法，不 Hook

findMethodExact vs findMethodExactIfExists

  • findMethodExact ：找不到会报错
  • findMethodExactIfExists ：找不到返回 null

findConstructorExact vs findConstructorBestMatch

  • Exact ：签名必须精确一致
  • BestMatch ：尽量匹配，宽松但更容易误中

findClass vs findClassIfExists

  • findClass ：找不到直接异常
  • findClassIfExists ：找不到返回 null

findField vs findFirstFieldByExactType

  • findField ：按字段名找
  • findFirstFieldByExactType ：按字段类型找

7. 实战里怎么选

如果已经明确知道目标结构，优先：

  • 类： findClass
  • 方法： findAndHookMethod 或 findMethodExact
  • 构造函数： findAndHookConstructor 或 findConstructorExact
  • 字段： findField

如果在做多版本兼容或混淆适配，可以：

  • 类： findClassIfExists
  • 方法： findMethodExactIfExists
  • 构造函数： findConstructorExactIfExists
  • 字段： findFieldIfExists / findFirstFieldByExactType

总结：

  • Exact 追求准确
  • IfExists 追求稳妥
  • BestMatch 追求宽松匹配
  • findAndHook* 追求一步到位
