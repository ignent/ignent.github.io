  1. Application.attach(Context)
  2. Activity.onCreate(Bundle)
  3. CryptoHook.hook(lpparam)

入口类：

  • app/src/main/assets/xposed_init
com.xposed.HookEntry

默认作用域：

  • app/src/main/res/values/arrays.xml
<resources>
    <string-array name="xposedscope">
        <item>com.name.app</item>
    </string-array>
</resources>

这表示按工程默认配置，模块是打算作用在 com.name.app 上。

1. 入口流程： HookEntry

文件：

  • app/src/main/java/com/xposed/HookEntry.java

当前 handleLoadPackage(...) 里的实际逻辑是：

XposedHelpers.findAndHookMethod(Application.class, "attach", Context.class, new XC_MethodHook() {
    @Override
    protected void afterHookedMethod(MethodHookParam param) throws Throwable {
        Log.d(TAG, "[Application]: " + Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_DOWNLOADS));
        FileLogger.startRecord(Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_DOWNLOADS), lpparam);
    }
});

XposedHelpers.findAndHookMethod(Activity.class, "onCreate", Bundle.class, new XC_MethodHook() {
    @Override
    protected void afterHookedMethod(MethodHookParam param) throws Throwable {
        if (param.thisObject instanceof Activity) {
            Activity activity = (Activity) param.thisObject;
            initPermissions(activity);
        }
    }
});

CryptoHook.hook(lpparam);

按执行顺序理解，可以拆成 3 段：

1.1 先给 Application.attach(...) 挂 Hook

作用：

  • 目标进程的 Application 完成 attach 后，调用 FileLogger.startRecord(...)
  • 记录目录固定取 Environment.DIRECTORY_DOWNLOADS

这一步不是 “开始抓加密数据”，而是先把日志落地。

1.2 再给 Activity.onCreate(...) 挂 Hook

作用：

  • 每次目标进程里有 Activity 执行 onCreate(...)
  • 就调用 initPermissions(activity)

initPermissions(...) 里实际申请的是：

activity.requestPermissions(new String[]{
        "android.permission.READ_PHONE_STATE",
        "android.permission.READ_MEDIA_IMAGES",
        "android.permission.READ_MEDIA_VIDEO",
        "android.permission.READ_MEDIA_AUDIO",
        "android.permission.READ_EXTERNAL_STORAGE",
        "android.permission.WRITE_EXTERNAL_STORAGE",},
        0);

按当前代码，它没有判断 Android 版本，也没有先检查权限是否已经授予，而是直接发起权限请求。

1.3 CryptoHook

作用：

  • CryptoHook.hook(lpparam) 在 handleLoadPackage(...) 里直接执行
  • 里面会继续注册一批和摘要、Base64、对称加密、密钥派生、非对称密钥生成、签名相关的 Hook

2. 日志入口： Application.attach + FileLogger

2.1 为什么要 Hook Application.attach

当前代码把日志初始化放在：

Application.class, "attach", Context.class

这意味着：

  • 只要目标进程完成了 Application.attach(...)
  • 文件日志线程就会尝试启动

实际调用：

FileLogger.startRecord(
        Environment.getExternalStoragePublicDirectory(Environment.DIRECTORY_DOWNLOADS),
        lpparam
);

2.2 日志文件会写到哪里

文件：

  • app/src/main/java/com/xposed/utils/FileLogger.java

startRecord(...) 里会这样处理目录和文件：

File dir = new File(baseDir, "file_log");
String processName = lpparam.processName;
processName = processName.replace(":", "_");
File filename = new File(dir, processName + ".txt");

所以按当前代码，日志路径格式是：

/sdcard/Download/file_log/<processName>.txt

如果进程名里有 : ，会替换成 _ 。

2.3 FileLogger 做了什么

FileLogger 当前实现的关键点有 4 个：

  1. 用 LinkedBlockingDeque<>(2048) 做异步日志队列
  2. startRecord(...) 只在 syncLogThread == null 时真正启动一次
  3. 每条日志写入后会额外补 3 个换行，做分隔
  4. 如果已有日志文件超过 2 * 1024 * 1024 ，会尝试只保留尾部约 2MB 内容

对应代码里最关键的判断是：

if (syncLogThread != null) {
    return;
}

这表示同一个进程里，如果日志线程已经启动，后续再次进入 Application.attach(...) 不会重复起线程。

2.4 commons-io

app/build.gradle.kts 新增：

compileOnly("commons-io:commons-io:+")

它是给 FileLogger 用的，因为 FileLogger 里调用了：

  • org.apache.commons.io.FileUtils
  • org.apache.commons.io.IOUtils

3. 核心 Hook： CryptoHook

文件：

  • app/src/main/java/com/xposed/hook/CryptoHook.java

入口方法很直接：

public static void hook(XC_LoadPackage.LoadPackageParam lpparam) {
    hash();
    base64();
    crypto(lpparam);
}

也就是分 3 组：

  1. hash()
  2. base64()
  3. crypto(lpparam)

4. hash() ：摘要算法相关 Hook

4.1 Hook 哪些方法

  1. MessageDigest.getInstance(String)
  2. MessageDigest.update(byte[])
  3. MessageDigest.update(byte[], int, int)
  4. MessageDigest.digest(byte[])
  5. MessageDigest.digest()

4.2 各自记录什么

getInstance(String) ：

FileLogger.outLog(TAG, "[Hash Name]: " + param.args[0]);

作用：

  • 记录摘要算法名，例如 MD5 、 SHA-1 、 SHA-256

update(byte[]) ：

FileLogger.outLog(TAG, "[Hash Content]: " + param.args[0]);

update(byte[], int, int) ：

FileLogger.outLog(TAG, "[Hash Content]: " + bytesToHexString((byte[]) param.args[0]));

digest(byte[]) ：

FileLogger.outLog(TAG, "[Hash Content]: " + bytesToHexString((byte[]) param.args[0]));
FileLogger.outLog(TAG, "[Hash Result]: " + bytesToHexString((byte[]) param.getResult()));

digest() ：

FileLogger.outLog(TAG, "[Hash Result]: " + bytesToHexString((byte[]) param.getResult()));

4.3 预期效果

目标应用用 MessageDigest 做摘要，当前日志里能看到：

  • 算法名
  • 一部分输入内容
  • 摘要结果

但边界也很明确：

  • 只有走 MessageDigest 这些被 Hook 的重载，才会有日志
  • update(byte[]) 这条日志没有做十六进制格式化
  • update(byte[], int, int) 记录的是整个数组，不是切片后的那一段

5. base64() ：Base64 编码相关 Hook

5.1 Hook 了哪些方法

当前代码有两段：

  1. android.util.Base64.encodeToString(byte[], int)
  2. java.util.Base64.Encoder.encodeToString(byte[])

第二段只有在：

Build.VERSION.SDK_INT >= Build.VERSION_CODES.O

时才会安装。

5.2 记录内容

两段逻辑都一样，都会记录：

FileLogger.outLog(TAG, "[Base64 encodeToString]: " + bytesToHexString((byte[]) param.args[0]));
FileLogger.outLog(TAG, "[Base64 encodeToString R]: " + param.getResult());

作用：

  • 把输入字节转成十六进制
  • 把 Base64 编码结果原样记录

5.3 预期效果

效果：

  • 如果目标应用把字节数组编码成 Base64 字符串，日志里能看到输入和输出

6. crypto(lpparam) ：加密、密钥、签名相关 Hook

这组内容最多，可以按对象类型拆开看。

6.1 SecretKeySpec ：记录对称密钥

Hook：

SecretKeySpec(byte[], String)

日志：

FileLogger.outLog(TAG, "[Crypto Key]: " + param.args[1] + ":" + bytesToHexString((byte[]) param.args[0]));

作用：

  • 记录算法名
  • 记录构造 SecretKeySpec 时传入的原始 key 字节

6.2 IvParameterSpec ：记录 IV

Hook：

IvParameterSpec(byte[])

日志：

FileLogger.outLog(TAG, "[Crypto IV]: " + bytesToHexString((byte[]) param.args[0]));

作用：

  • 记录初始化向量

6.3 Cipher.getInstance(String) ：记录算法 / 模式 / 填充

Hook：

Cipher.getInstance(String)

日志：

FileLogger.outLog(TAG, "[Cipher Name]: " + param.args[0]);

作用：

  • 记录例如 AES/CBC/PKCS5Padding 这种 transformation 字符串

6.4 Cipher.getIV() ：记录运行期 IV

Hook：

Cipher.getIV()

日志：

FileLogger.outLog(TAG, "[Crypto IV]: " + bytesToHexString((byte[]) param.getResult()));

作用：

  • 记录 Cipher 返回的 IV

6.5 Cipher.doFinal(byte[]) ：记录输入和结果

Hook：

Cipher.doFinal(byte[])

日志：

FileLogger.outLog(TAG, "[Crypto Content]: " + bytesToHexString((byte[]) param.args[0]));
FileLogger.outLog(TAG, "[Crypto Result]: " + bytesToHexString((byte[]) param.getResult()));

作用：

  • 记录 doFinal(byte[]) 的输入
  • 记录执行后的返回值

6.6 KeyPairGenerator.getInstance(...) ：动态补 Hook

这里分两种重载：

  1. KeyPairGenerator.getInstance(String)
  2. KeyPairGenerator.getInstance(String, String)

第二种会先记录：

FileLogger.outLog(TAG, "[KeyPairGenerator]: " + param.args[0] + ":" + param.args[1]);

然后两种重载都会取到返回的 KeyPairGenerator 实例，再做两件事：

  1. XposedBridge.hookAllMethods(keyPairGenerator.getClass(), "initialize", ...)
  2. 对返回实例真实类名的 generateKeyPair 再挂 Hook

对应代码：

KeyPairGenerator keyPairGenerator = (KeyPairGenerator) param.getResult();
String name = keyPairGenerator.getClass().getName();

以及：

XposedHelpers.findAndHookMethod(
        name,
        lpparam.classLoader,
        "generateKeyPair",
        new XC_MethodHook() { ... });

generateKeyPair 的日志会记录：

FileLogger.outLog(TAG, "[KeyPair Public]: " + bytesToHexString(result.getPublic().getEncoded()));
FileLogger.outLog(TAG, "[KeyPair Private]: " + bytesToHexString(result.getPrivate().getEncoded()));

作用：

  • 记录公钥编码
  • 记录私钥编码

6.7 这段动态 Hook 的实现边界

代码里声明了：

private final static Set<String> hookList = new HashSet<>();

并且判断时用了：

if (!hookList.contains(name)) {
    ...
}

含义：

  • 代码有 “想避免重复 Hook 同一个实现类” 的意图
  • 但当前实现里没有把已经处理过的类名放进 hookList

6.8 SecretKeyFactory 和 PBEKeySpec

Hook：

  1. SecretKeyFactory.getInstance(String)
  2. PBEKeySpec(char[], byte[], int, int)

日志分别是：

FileLogger.outLog(TAG, "[SecretKeyFactory]: " + param.args[0]);

和：

FileLogger.outLog(TAG, "[PBEKeySpec Key]: " + String.valueOf((char[]) param.args[0]));
FileLogger.outLog(TAG, "[PBEKeySpec Salt]: " + bytesToHexString((byte[]) param.args[1]));

作用：

  • 记录派生算法名
  • 记录口令字符数组
  • 记录 salt

6.9 Signature ：记录签名算法与调用点

当前代码 Hook 了：

  1. Signature.getInstance(String, String)
  2. hookAllMethods(Signature.class, "initSign", ...)
  3. hookAllMethods(Signature.class, "update", ...)
  4. hookAllMethods(Signature.class, "sign", ...)

getInstance(String, String) 会记录两个参数：

FileLogger.outLog(TAG, "[Signature]: " + param.args[0]);
FileLogger.outLog(TAG, "[Signature]: " + param.args[1]);

initSign / update / sign 这 3 组 hookAllMethods(...) 记录：

FileLogger.outLog(TAG, "[Signature]: " + param.method.toString());

作用：

  • 记录调用到的是哪一个重载方法
