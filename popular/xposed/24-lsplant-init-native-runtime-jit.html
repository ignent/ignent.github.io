LSPlant InitNative运行时初始化

LSPlant InitNative 运行时初始化：符号解析、Hook 管理与 JIT 保护

概述

上一篇已经从工程构建、 InitConfig 、 InitJNI 和编译期符号 DSL 读到 LSPlant 的初始化入口。本文继续往下走，只盯住 InitNative(env, info) 这一段，回答一个更贴近实战的问题：

LSPlant 在真正 Hook Java 方法前，为什么要提前解析和 hook 这么多 ART 内部函数？

本文最终要达到的效果是：

读者能在 LSPlant 源码中定位 InitNative 的每个模块
读者能运行测试 APK，确认 LSPTest.initHooker() 返回 true
读者能从 logcat 看到 ArtMethod 偏移、Runtime 实例、trampoline 等初始化日志
读者能解释类初始化、JIT 编译、JIT cache 回收、debuggable instrumentation 为什么会影响 Hook

从执行链路看， InitNative 不是一个普通 “准备函数”。它做了三类事：

  1. 解析 ART 私有结构和符号，例如 ArtMethod 大小、quick entry offset、 Runtime::instance_ 。
  2. 对 ART 关键路径打保护性 inline hook，例如 ClassLinker::FixupStaticTrampolines 、 Jit::AddCompileTask 。
  3. 建立 Hook 后的状态管理，例如 target/backup 记录、JIT movement 记录、deoptimize 记录。

注意

本文讨论的 ArtMethod 、 ClassLinker 、 JitCodeCache 、 JniIdManager 、 libart.so mangled symbol 都不是 Android SDK 稳定公开接口。不同 Android 版本、厂商 ROM、ABI、编译器和 ART 优化策略都可能改变行为。请把本文当作源码阅读和实验复现指南，不要把私有偏移或符号名跨版本硬套到生产环境。

测试入口：提供 inline hook 和符号解析

文件： test/src/main/jni/test.cpp

#include <jni.h>
#include <dobby.h>
#include <sys/mman.h>
#include <string_view>
#include <xdl.h>

#include "logging.h"

// 测试模块通过 C++ module 使用 LSPlant 对外 API。
import lsplant;

// 下面这些宏用于把目标地址所在内存页改成 RWX，
// 方便 Dobby 修改函数入口指令。
#define _uintval(p) reinterpret_cast<uintptr_t>(p)
#define _ptr(p) reinterpret_cast<void *>(p)
#define _align_up(x, n) (((x) + ((n) - 1)) & ~((n) - 1))
#define _align_down(x, n) ((x) & -(n))
#define _page_size 4096
#define _page_align(n) _align_up(static_cast<uintptr_t>(n), _page_size)
#define _ptr_align(x) _ptr(_align_down(reinterpret_cast<uintptr_t>(x), _page_size))
#define _make_rwx(p, n) \
    ::mprotect( \
        _ptr_align(p), \
        _page_align(_uintval(p) + n) != _page_align(_uintval(p)) \
            ? _page_align(n) + _page_size \
            : _page_align(n), \
        PROT_READ | PROT_WRITE | PROT_EXEC)

// Java 层 LSPTest.initHooker() 会返回这个变量，
// 用来确认 lsplant::Init 是否成功。
bool init_result;

// xDL 先查动态符号表，再查调试符号表。
// LSPlant 需要的很多 ART 内部符号不保证出现在 .dynsym。
void *find_symbol(void *handle, const char *symbol_name) {
    void *addr = xdl_sym(handle, symbol_name, nullptr);
    if (addr == nullptr) {
        addr = xdl_dsym(handle, symbol_name, nullptr);
    }
    return addr;
}

// InitInfo.inline_hooker：
// target 是 ART 内部原函数，hooker 是 LSPlant 提供的替换函数。
// 返回 origin_call，后续替换函数可以通过它调用原始逻辑。
void *InlineHooker(void *target, void *hooker) {
    _make_rwx(target, _page_size);

    void *origin_call = nullptr;
    if (DobbyHook(target, hooker, &origin_call) == RS_SUCCESS) {
        return origin_call;
    }
    return nullptr;
}

// InitInfo.inline_unhooker：
// 撤销之前对 ART 内部函数打上的 inline hook。
bool InlineUnhooker(void *func) {
    return DobbyDestroy(func) == RT_SUCCESS;
}

extern "C"
JNIEXPORT jboolean JNICALL
Java_org_lsposed_lsplant_LSPTest_initHooker(JNIEnv *, jclass) {
    return init_result;
}

extern "C"
JNIEXPORT jobject JNICALL
Java_org_lsposed_lsplant_Hooker_doHook(
    JNIEnv *env,
    jobject thiz,
    jobject target,
    jobject callback

    // thiz 是 Java 层 Hooker 对象。
    // LSPlant 会把它放进生成 stub 类的 static field 中，
    // 目标方法调用进入 stub 后再回调 thiz.callback(Object[] args)。
    return lsplant::Hook(env, target, thiz, callback);
}

extern "C"
JNIEXPORT jboolean JNICALL
Java_org_lsposed_lsplant_Hooker_doUnhook(JNIEnv *env, jobject, jobject target) {
    return lsplant::UnHook(env, target);
}

JNIEXPORT jint JNICALL
JNI_OnLoad(JavaVM *vm, void *) {
    JNIEnv *env = nullptr;
    if (vm->GetEnv(reinterpret_cast<void **>(&env), JNI_VERSION_1_6) != JNI_OK) {
        return JNI_ERR;
    }

    // 打开当前进程中已经加载的 libart.so。
    static void *handle = xdl_open("libart.so", XDL_DEFAULT);

    lsplant::InitInfo initInfo{
        // 由测试模块决定使用 Dobby 做 inline hook。
        .inline_hooker = InlineHooker,
        .inline_unhooker = InlineUnhooker,

        // 精确符号解析：用于完整 mangled name。
        .art_symbol_resolver = [](std::string_view symbol) -> void * {
            return find_symbol(handle, symbol.data());
        },

        // 前缀符号解析：某些 Android 版本上的 mangled name 参数类型不同，
        // LSPlant 可以要求按前缀匹配。
        .art_symbol_prefix_resolver = [](std::string_view symbol) -> void * {
            return find_symbol(handle, symbol.data());
        },
    };

    init_result = lsplant::Init(env, initInfo);
    return JNI_VERSION_1_6;
}

这里最重要的不是 Dobby 或 xDL 本身，而是接口边界：

  • LSPlant 不内置 inline hook 框架，调用方通过 InitInfo.inline_hooker 提供。
  • LSPlant 不内置 libart 符号扫描器，调用方通过 InitInfo.art_symbol_resolver 提供。
  • InitNative 后续所有 handler(...) 都依赖这几个函数。

注意

_make_rwx 会把目标页改成可读、可写、可执行。真实项目要尽量避免长时间 RWX 映射，尤其在启用 SELinux、W^X、内存完整性策略或安全审计的场景中，应评估 inline hook 框架的实现方式和风险。

InitInfo：初始化依赖的能力清单

文件： lsplant/src/main/jni/include/lsplant.hpp

namespace lsplant {
inline namespace v2 {

struct InitInfo {
    // inline hook 函数：
    // target 是要被替换的 ART 内部函数；
    // hooker 是 LSPlant 生成/提供的替换函数；
    // 返回值是原函数备份入口，失败返回 null。
    using InlineHookFunType = std::function<void *(void *target, void *hooker)>;

    // 撤销 inline hook 的函数。
    using InlineUnhookFunType = std::function<bool(void *func)>;

    // 精确解析 libart.so 内部符号。
    using ArtSymbolResolver = std::function<void *(std::string_view symbol_name)>;

    // 按前缀解析 libart.so 内部符号。
    // 头文件注释说它可以为空，但当前 Init() 实现会把它作为必填项检查。
    using ArtSymbolPrefixResolver = std::function<void *(std::string_view symbol_prefix)>;

    // 可选：调用方提供可执行内存分配器，用于存放 LSPlant trampoline。
    using MemoryAllocator = std::function<void *(std::span<const uint8_t> data)>;

    // 可选：调用方提供可执行内存回收器。
    using MemoryRecycler = std::function<void(void *memory)>;

    InlineHookFunType inline_hooker;
    InlineUnhookFunType inline_unhooker;
    ArtSymbolResolver art_symbol_resolver;
    ArtSymbolPrefixResolver art_symbol_prefix_resolver;

    // Hook 时动态生成的 stub class、field、method 配置。
    std::string_view generated_class_name = "LSPHooker_";
    std::string_view generated_source_name = "LSP";
    std::string_view generated_field_name = "hooker";
    std::string_view generated_method_name = "{target}";

    MemoryAllocator executable_memory_allocator;
    MemoryRecycler executable_memory_recycler;
};

bool Init(JNIEnv *env, const InitInfo &info);
jobject Hook(JNIEnv *env, jobject target_method, jobject hooker_object, jobject callback_method);
bool UnHook(JNIEnv *env, jobject target_method);

}  // namespace v2
}  // namespace lsplant

InitInfo 可以理解为 InitNative 的工具箱：没有符号解析器，就拿不到 ART 内部函数；没有 inline hooker，就无法拦截 ClassLinker 、 Jit 、 Instrumentation 等关键路径。

Init：三段式入口和一次性初始化

文件： lsplant/src/main/jni/lsplant.cc

bool Init(JNIEnv *env, const InitInfo &info) {
    // 当前实现要求四个基础能力都非空。
    // 注意：这包括 art_symbol_prefix_resolver。
    if (!info.inline_hooker ||
        !info.inline_unhooker ||
        !info.art_symbol_resolver ||
        !info.art_symbol_prefix_resolver) {
        return false;
    }

    // static 局部变量让初始化主体只执行一次。
    // 第一次成功则后续直接返回 true；第一次失败则后续也返回 false。
    bool static kInit =
        InitConfig(info) &&
        InitJNI(env) &&
        InitNative(env, info);

    return kInit;
}

HookHandler：符号解析和 Hook 管理的共同入口

文件： lsplant/src/main/jni/include/utils/hook_helper.hpp

下面代码保留 HookHandler 的核心逻辑，省略了 FixedString 、 Function 、 Field 、 Hooker 的完整模板定义。前一篇已经解释过 "_sym" 和 .as<>() 的编译期字符串机制；本文只看 handler 如何工作。

struct HookHandler {
    // 保存调用方传入的 InitInfo。
    // 后续解析符号、inline hook、inline unhook 都会用到它。
    HookHandler(const InitInfo &info) : info_(info) {}

    template <typename T>
    bool operator()(T &&arg) const {
        // 默认精确匹配符号。
        return handle(std::forward<T>(arg), false);
    }

    template <typename T1, typename T2, typename... U>
    bool operator()(T1 &&arg1, T2 &&arg2, U &&...args) const {
        if constexpr (std::is_same_v<T2, bool>) {
            // 写法示例：handler(GetMethodShortyL_, true, GetMethodShorty_)
            // true 表示前一个符号允许按前缀匹配。
            return handle(std::forward<T1>(arg1), std::forward<T2>(arg2)) ||
                   this->operator()(std::forward<U>(args)...);
        } else {
            // 多个候选符号按顺序尝试，任意一个成功即可。
            return handle(std::forward<T1>(arg1), false) ||
                   this->operator()(std::forward<T2>(arg2), std::forward<U>(args)...);
        }
    }

    template <FixedString Sym, typename... Us, template <FixedString, typename...> typename T>
        requires(requires { T<Sym, Us...>::replace_; })
    bool unhook(const T<Sym, Us...> &hooker) const {
        // 如果这个对象是 Hooker，并且之前记录了原始地址，
        // 就交给调用方提供的 inline_unhooker 撤销 hook。
        if (hooker.address_ && info_.inline_unhooker && info_.inline_unhooker(hooker.address_)) {
            hooker = nullptr;
            hooker.address_ = nullptr;
            return true;
        }
        return false;
    }

private:
    bool operator()() const { return false; }

    template <FixedString Sym, typename... Us, template <FixedString, typename...> typename T>
        requires(!requires { T<Sym, Us...>::replace_; })
    bool handle(const T<Sym, Us...> &target, bool match_prefix) const {
        // 普通 Function/Field：只解析符号并保存地址。
        return target = dlsym<Sym>(match_prefix);
    }

    template <FixedString Sym, typename... Us, template <FixedString, typename...> typename T>
        requires(requires { T<Sym, Us...>::replace_; })
    bool handle(const T<Sym, Us...> &hooker, bool match_prefix) const {
        // Hooker：先解析原函数地址，再调用 inline_hooker，
        // 返回值会被保存为 backup 函数入口。
        return hooker = hook(
            hooker.address_ = dlsym<Sym>(match_prefix),
            reinterpret_cast<void *>(hooker.replace_)
        );
    }

    template <FixedString Sym>
    void *dlsym(bool match_prefix = false) const {
        // 优先精确匹配。
        if (auto match = info_.art_symbol_resolver(Sym.data)) {
            return match;
        }

        // 需要时再按前缀匹配。
        if (match_prefix && info_.art_symbol_prefix_resolver) {
            return info_.art_symbol_prefix_resolver(Sym.data);
        }
        return nullptr;
    }

    void *hook(void *original, void *replace) const {
        if (original) {
            return info_.inline_hooker(original, replace);
        }
        return nullptr;
    }

    const InitInfo &info_;
};

这解释了为什么很多模块的 Init 看起来像声明式代码：

handler(RegisterNativeClassLinker_, RegisterNative_, RegisterNativeFast_, RegisterNativeThread_);

这行不是简单 “查找四个函数”。如果变量是 .hook->*[] 生成的 Hooker， handler 会：

  1. 解析 ART 原函数地址。
  2. 调用 inline_hooker(original, replace) 。
  3. 把返回的原始入口保存为 backup。
  4. 后续替换函数里通过 backup(...) 调回原逻辑。

InitNative：模块初始化顺序

文件： lsplant/src/main/jni/lsplant.cc

bool InitNative(JNIEnv *env, const HookHandler &handler) {
    // 1. 先解析 ArtMethod 布局。
    // 后续几乎所有模块都依赖 ArtMethod::GetEntryPoint()/SetEntryPoint()。
    if (!ArtMethod::Init(env, handler)) {
        LOGE("Failed to init art method");
        return false;
    }

    // 2. 根据真实 entrypoint offset 更新 trampoline 机器码模板。
    UpdateTrampoline(ArtMethod::GetEntryPointOffset());

    // 3. 获取当前 ART Thread。
    if (!Thread::Init(handler)) {
        LOGE("Failed to init thread");
        return false;
    }

    // 4. mirror::Class：类状态、ClassDef、静态方法初始化保护。
    if (!Class::Init(handler)) {
        LOGE("Failed to init mirror class");
        return false;
    }

    // 5. Runtime：全局 runtime 实例和 debuggable 状态。
    if (!Runtime::Init(handler)) {
        LOGE("Failed to init runtime");
        return false;
    }

    // 6. ClassLinker：解释器入口、native 注册、静态 trampoline 修复。
    if (!ClassLinker::Init(env, handler)) {
        LOGE("Failed to init class linker");
        return false;
    }

    // 7. 并发控制：暂停线程和 GC critical section。
    if (!ScopedSuspendAll::Init(handler)) {
        LOGE("Failed to init scoped suspend all");
        return false;
    }
    if (!ScopedGCCriticalSection::Init(handler)) {
        LOGE("Failed to init scoped gc critical section");
        return false;
    }

    // 8. JIT code cache 和 JIT 编译任务保护。
    if (!JitCodeCache::Init(handler)) {
        LOGE("Failed to init jit code cache");
        return false;
    }
    if (!Jit::Init(handler)) {
        LOGE("Failed to init jit");
        return false;
    }

    // 9. DexFile：老版本动态 Dex 加载、setTrusted。
    if (!DexFile::Init(env, handler)) {
        LOGE("Failed to init dex file");
        return false;
    }

    // 10. Debuggable instrumentation 场景下保护方法入口。
    if (!Instrumentation::Init(env, handler)) {
        LOGE("Failed to init instrumentation");
        return false;
    }

    // 11. Android 11+ debugger / jmethodID 编码保护。
    if (!JniIdManager::Init(env, handler)) {
        LOGE("Failed to init jni id manager");
        return false;
    }

    // 12. 必须放最后：
    // 如果当前 runtime 是 Java debuggable，临时改成非 debuggable，
    // 规避某些 ART 内联路径覆盖 hooked entrypoint。
    if (IsJavaDebuggable(env)) {
        Runtime::Current()->SetJavaDebuggable(
            Runtime::RuntimeDebugState::kNonJavaDebuggable
        );
    }

    return true;
}

这段顺序不能随意换。比如：

  • 没有 ArtMethod::Init ，trampoline 不知道 quick entry offset。
  • 没有 Runtime::Init ，debuggable guard 不能切换 runtime 状态。
  • 没有 ClassLinker::Init ，deoptimize 和静态方法初始化保护都不完整。
  • 没有 Jit/JitCodeCache/Instrumentation ，后续 ART 可能再次把方法入口改掉。

trampoline：从模板到可执行跳板

文件： lsplant/src/main/jni/lsplant.cc

下面只展示 ARM64 主线。源码还包含 ARM、x86、x86_64、riscv64 模板。

consteval inline auto GetTrampoline() {
    if constexpr (is_arch_v<Arch::kAArch64>) {
        return std::make_tuple(
            // ARM64 指令模板：
            // 1. 从当前 PC 附近加载 hook ArtMethod*
            // 2. 从 hook ArtMethod + quick entry offset 读取真正入口
            // 3. 跳到 hook stub 的 quick entry
            // 4. 末尾 8 字节是待写入的 ArtMethod* 占位区
            "\x60\x00\x00\x58"
            "\x10\x00\x40\xf8"
            "\x00\x02\x1f\xd6"
            "\x78\x56\x34\x12"
            "\x78\x56\x34\x12"_uarr,

            // entry_point_offset 表示“quick entry offset 这个立即数”
            // 在模板里的 bit 位置。
            uint8_t{44u},

            // art_method_offset 表示模板里存放 ArtMethod* 的字节偏移。
            uintptr_t{12u}
        );
    }
}

auto [trampoline, entry_point_offset, art_method_offset] = GetTrampoline();

ArtMethod::Init 算出真实 quick entry offset 后， UpdateTrampoline 会把这个 offset 写入模板：

inline void UpdateTrampoline(uint8_t offset) {
    // entry_point_offset 不是字节偏移，而是 bit 偏移。
    // 这里把 ArtMethod quick entry 字段偏移写进机器码模板。
    trampoline[entry_point_offset / CHAR_BIT] |=
        offset << (entry_point_offset % CHAR_BIT);

    trampoline[entry_point_offset / CHAR_BIT + 1] |=
        offset >> (CHAR_BIT - entry_point_offset % CHAR_BIT);
}

生成具体 trampoline 时，LSPlant 会把 hook 方法的 ArtMethod* 写进模板，并复制到可执行内存：

void *GenerateTrampolineFor(art::ArtMethod *hook) {
    // 每个被 hook 的目标方法都会得到一份 trampoline 数据。
    auto data = trampoline;

    // 把 hook ArtMethod* 写进模板末尾占位区。
    *reinterpret_cast<ArtMethod **>(data.data() + art_method_offset) = hook;

    // 如果调用方提供了可执行内存分配器，优先使用调用方实现。
    if (executable_memory_allocator) {
        if (auto *memory = static_cast<char *>(executable_memory_allocator(data))) {
            __builtin___clear_cache(memory, memory + data.size());
            LOGV("memory allocated from user: %p", memory);
            return memory;
        }
    }

    // 如果没有调用方自定义分配器，进入源码默认分配逻辑：
    // 1. Android 10+ 优先尝试 memfd 双映射；
    // 2. 否则尝试 ashmem 双映射；
    // 3. 最后 fallback 到 RWX mmap；
    // 4. 一页内按 kTrampolineSize 切分多个 trampoline slot；
    // 5. 用 atomic + atomic_flag 管理 trampoline_pool。
    static const size_t kTrampolineNumPerPage = kPageSize / kTrampolineSize;
    unsigned count;
    uintptr_t address;

    while (true) {
        // trampoline_pool 同时编码“当前页地址”和“页内已用 slot 数”。
        auto tl = Trampoline{
            .address = trampoline_pool.fetch_add(1, std::memory_order_release)
        };
        count = kPageSize == 16384 ? tl.count16k : tl.count4k;
        address = tl.address & ~kPageMask;

        if (address == 0 || count >= kTrampolineNumPerPage) {
            if (trampoline_lock.test_and_set(std::memory_order_acq_rel)) {
                trampoline_lock.wait(true, std::memory_order_acquire);
                continue;
            }

            // AllocateMemory() 内部按 memfd -> ashmem -> mmap 顺序尝试。
            address = reinterpret_cast<uintptr_t>(AllocateMemory());
            if (!address) {
                trampoline_lock.clear(std::memory_order_release);
                trampoline_lock.notify_all();
                return nullptr;
            }

            count = 0;
            tl.address = address;
            kPageSize == 16384 ? tl.count16k = count + 1 : tl.count4k = count + 1;
            trampoline_pool.store(tl.address, std::memory_order_release);
            trampoline_lock.clear(std::memory_order_release);
            trampoline_lock.notify_all();
        }

        // 最终地址 = 页起始地址 + 页内 slot 偏移。
        address = address + count * kTrampolineSize;
        break;
    }

    auto *address_ptr = reinterpret_cast<char *>(address);

    // 双映射区域中，RX 页和 RW 页相邻；写入时要写 RW 映射。
    if (dual_regions.contains(__builtin_align_down(address_ptr, kPageSize))) {
        std::memcpy(address_ptr + kPageSize, data.data(), data.size());
    } else {
        std::memcpy(address_ptr, data.data(), data.size());
    }

    // 写入指令后清理 icache，确保 CPU 执行到最新内容。
    __builtin___clear_cache(address_ptr, reinterpret_cast<char *>(address + data.size()));

    return address_ptr;
}

class ArtMethod {
public:
    static bool Init(JNIEnv *env, const HookHandler handler) {
        auto sdk_int = GetAndroidApiLevel();

        // Android 8.0+ 反射方法父类是 Executable；
        // Android 6.0/7.x 使用 AbstractMethod；
        // Android 5.x 还有 java.lang.reflect.ArtMethod。
        ScopedLocalRef<jclass> executable{env, nullptr};
        if (sdk_int >= kSdkOreo) {
            executable = JNI_FindClass(env, "java/lang/reflect/Executable");
        } else if (sdk_int >= kSdkMarshmallow) {
            executable = JNI_FindClass(env, "java/lang/reflect/AbstractMethod");
        } else {
            executable = JNI_FindClass(env, "java/lang/reflect/ArtMethod");
        }
        if (!executable) {
            LOGE("Failed to find Executable/AbstractMethod/ArtMethod");
            return false;
        }

        // Android 6.0+ 的反射对象里有 long artMethod 字段。
        // 后续 FromReflectedMethod() 会优先读这个字段拿 ArtMethod*。
        if (sdk_int >= kSdkMarshmallow) {
            if (art_method_field = JNI_GetFieldID(env, executable, "artMethod", "J");
                !art_method_field) {
                LOGE("Failed to find artMethod field");
                return false;
            }
        }

        // 用 Throwable 的两个构造器估算 ArtMethod 结构大小：
        // 同一个类的 method array 中相邻 ArtMethod 地址差值就是 size。
        auto throwable = JNI_FindClass(env, "java/lang/Throwable");
        auto clazz = JNI_FindClass(env, "java/lang/Class");
        jmethodID get_declared_constructors =
            JNI_GetMethodID(
                env,
                clazz,
                "getDeclaredConstructors",
                "()[Ljava/lang/reflect/Constructor;"
            );

        const auto constructors =
            JNI_Cast<jobjectArray>(
                JNI_CallObjectMethod(env, throwable, get_declared_constructors)
            );
        if (constructors.size() < 2) {
            LOGE("Throwable has less than 2 constructors");
            return false;
        }

        auto *first = FromReflectedMethod(env, constructors[0].get());
        auto *second = FromReflectedMethod(env, constructors[1].get());
        art_method_size =
            reinterpret_cast<uintptr_t>(second) - reinterpret_cast<uintptr_t>(first);

        LOGD("ArtMethod size: %zu", art_method_size);

        // 现代 ART 中 quick entry 通常在 ArtMethod 末尾。
        // data 字段通常位于 quick entry 前一个指针大小。
        entry_point_offset = art_method_size - kPointerSize;
        data_offset = entry_point_offset - kPointerSize;

        // Android 6.0+ 可以从反射对象的 accessFlags 字段取真实 flags，
        // 再在 ArtMethod 内存中扫描出 access flags 偏移。
        if (sdk_int >= kSdkMarshmallow) {
            if (auto access_flags_field = JNI_GetFieldID(env, executable, "accessFlags", "I");
                access_flags_field) {
                uint32_t real_flags = JNI_GetIntField(env, constructors[0], access_flags_field);
                for (size_t i = 0; i < art_method_size; i += sizeof(uint32_t)) {
                    if (*reinterpret_cast<uint32_t *>(
                            reinterpret_cast<uintptr_t>(first) + i
                        ) == real_flags) {
                        access_flags_offset = i;
                        break;
                    }
                }
            }

            // 扫描失败时 fallback 到常见偏移 4。
            if (access_flags_offset == 0) {
                LOGW("Failed to find accessFlags field. Fallback to 4.");
                access_flags_offset = 4U;
            }
        }

        LOGD("ArtMethod::declaring_class offset: %zu", declaring_class_offset);
        LOGD("ArtMethod::entrypoint offset: %zu", entry_point_offset);
        LOGD("ArtMethod::data offset: %zu", data_offset);
        LOGD("ArtMethod::access_flags offset: %zu", access_flags_offset);

        // access flag 常量会随 Android 版本改变。
        if (sdk_int < kSdkR) {
            kAccPreCompiled = 0;
        } else if (sdk_int >= kSdkS) {
            kAccPreCompiled = 0x00800000;
        }
        if (sdk_int < kSdkQ) kAccFastInterpreterToInterpreterInvoke = 0;
        if (sdk_int < kSdkOreo) kAccIntrinsic = 0;

        // Android 9+ 尝试解析 ArtMethod::SetNotIntrinsic。
        // 如果解析失败，后续会用硬编码 kAccIntrinsic 清 flag。
        if (sdk_int >= kSdkPie && !handler(SetNotIntrinsic_)) {
            LOGW("Failed to find SetNotIntrinsic, use hard-coded kAccIntrinsic instead");
        }

        // Hook stub 生成时需要 method shorty。
        // 不同版本符号可能是 art::GetMethodShorty 或 art::L15GetMethodShorty。
        if (!handler(GetMethodShortyL_, true, GetMethodShorty_)) {
            LOGE("Failed to find GetMethodShorty");
            return false;
        }

        // PrettyMethod 只用于日志，失败不会阻止初始化。
        handler(PrettyMethod_, PrettyMethodStatic_, PrettyMethodMirror_);

        // Android 6.0 及更早版本还需要解释器桥相关兼容处理。
        // 源码中包括 AbstractMethodError 探测、GetQuickFrameInfo hook、
        // artInterpreterToCompiledCodeBridge 解析等分支，本文省略细节。

        return true;
    }

    static size_t GetEntryPointOffset() {
        return entry_point_offset;
    }

private:
    inline static jfieldID art_method_field = nullptr;
    inline static size_t art_method_size = 0;
    inline static size_t entry_point_offset = 0;
    inline static size_t data_offset = 0;
    inline static size_t access_flags_offset = 0;
    inline static size_t declaring_class_offset = 0;
};

inline void RecordHooked(
    art::ArtMethod *target,
    const art::dex::ClassDef *class_def,
    jobject reflected_backup,
    art::ArtMethod *backup
) {
    // 记录 class_def -> target，用于类初始化时恢复静态方法入口。
    hooked_classes_.lazy_emplace_l(
        class_def,
        [&target](auto &it) { it.second.emplace(target); },
        [&class_def, &target](const auto &ctor) {
            ctor(class_def, phmap::flat_hash_set<art::ArtMethod *>{target});
        }
    );

    // 双向记录：
    // target -> backup
    // backup -> target
    hooked_methods_.insert({
        std::make_pair(target, std::make_pair(reflected_backup, backup)),
        std::make_pair(backup, std::make_pair(nullptr, target))
    });
}

bool DoHook(ArtMethod *target, ArtMethod *hook, ArtMethod *backup) {
    // 避免 Hook 修改 ArtMethod 时和 GC/debugger 关键区冲突。
    ScopedGCCriticalSection section(
        art::Thread::Current(),
        art::gc::kGcCauseDebugger,
        art::gc::kCollectorTypeDebugger
    );

    // 暂停其他线程，避免并发执行到正在修改的 ArtMethod。
    ScopedSuspendAll suspend("LSPlant Hook", false);

    if (auto *entrypoint = GenerateTrampolineFor(hook); !entrypoint) {
        LOGE("Failed to generate trampoline");
        return false;
    } else {
        // intrinsic 方法可能被 ART 特殊处理，先去掉 intrinsic 标记。
        target->SetNonIntrinsic();

        // 把 target 复制到 backup。
        target->BackupTo(backup);

        // 禁止 target 后续继续被编译。
        target->SetNonCompilable();

        // 核心动作：target quick entry 指向 LSPlant trampoline。
        target->SetEntryPoint(entrypoint);

        return true;
    }
}

这也是为什么 “线程管理与并发控制初始化” 不是装饰性代码。没有它们，Hook 修改入口时可能和其他线程执行、GC、debugger、JIT metadata 更新撞在一起。

Class 初始化：保护未初始化类的静态方法

文件： lsplant/src/main/jni/art/mirror/class.cxx

class Class {
private:
    // mirror::Class::GetClassDef() 用于把 Class 映射到 dex::ClassDef。
    inline static auto GetClassDef_ =
        "_ZN3art6mirror5Class11GetClassDefEv"_sym
            .as<const dex::ClassDef *(Class::*)()>;

    using BackupMethods = phmap::flat_hash_map<art::ArtMethod *, void *>;

    // self -> class_def -> (method -> old_entrypoint)
    // 类初始化期间临时保存被 ART 覆盖前的 LSPlant entrypoint。
    inline static phmap::flat_hash_map<
        const art::Thread *,
        phmap::flat_hash_map<const dex::ClassDef *, BackupMethods>
    > backup_methods_;

    inline static std::mutex backup_methods_lock_;
    inline static uint8_t initialized_status = 0;

    static void BackupClassMethods(const dex::ClassDef *class_def, art::Thread *self) {
        BackupMethods out;
        if (!class_def) return;

        // 如果该 class_def 里有已 hook 的静态方法，
        // 在类状态切到 initialized 前先保存它们当前的 entrypoint。
        hooked_classes_.if_contains(class_def, [&out](const auto &it) {
            for (auto method : it.second) {
                if (method->IsStatic()) {
                    LOGV("Backup hooked method %p because of initialization", method);
                    out.emplace(method, method->GetEntryPoint());
                }
            }
        });

        // deoptimized 静态方法也要记录，后续恢复解释器入口。
        deoptimized_classes_.if_contains(class_def, [&out](const auto &it) {
            for (auto method : it.second) {
                if (method->IsStatic()) {
                    LOGV("Backup deoptimized method %p because of initialization", method);
                    out.emplace(method, method->GetEntryPoint());
                }
            }
        });

        if (!out.empty()) {
            std::unique_lock lk(backup_methods_lock_);
            backup_methods_[self].emplace(class_def, std::move(out));
        }
    }

    // Android 8.0+ 其中一种 SetStatus 签名。
    inline static auto SetClassStatus_ =
        "_ZN3art6mirror5Class9SetStatusENS_6HandleIS1_EENS_11ClassStatusEPNS_6ThreadE"_sym
            .hook->*[]<Backup auto backup>(
                TrivialHandle<Class> h,
                uint8_t new_status,
                Thread *self
            ) static -> void {
                if (new_status == initialized_status) {
                    BackupClassMethods(GetClassDef_(h.Get()), self);
                }
                return backup(h, new_status, self);
            };

public:
    static bool Init(const HookHandler &handler) {
        if (!handler(GetClassDef_)) {
            return false;
        }

        int sdk_int = GetAndroidApiLevel();

        // Android 8.0 前后 Class::SetStatus 签名不同，
        // 源码中提供 SetStatus_、TrivialSetStatus_、ClassSetStatus_ 等候选。
        if (sdk_int < kSdkOreo) {
            if (!handler(SetStatus_, ClassSetStatus_)) {
                return false;
            }
        } else {
            if (!handler(SetClassStatus_, TrivialSetStatus_)) {
                return false;
            }
        }

        // ClassStatus::kInitialized 的枚举值随 Android 版本变化。
        if (sdk_int >= kSdkR) {
            initialized_status = 15;
        } else if (sdk_int >= kSdkPie) {
            initialized_status = 14;
        } else if (sdk_int == kSdkOreoMr1) {
            initialized_status = 11;
        } else {
            initialized_status = 10;
        }

        return true;
    }

    const dex::ClassDef *GetClassDef() {
        return GetClassDef_(this);
    }

    static auto PopBackup(const dex::ClassDef *class_def, art::Thread *self) {
        // ClassLinker 修复静态 trampoline 后会调用 PopBackup，
        // 取出之前 BackupClassMethods 保存的旧 entrypoint。
        BackupMethods methods;
        if (!backup_methods_.size()) return methods;

        std::unique_lock lk(backup_methods_lock_);
        // 源码这里按 class_def 或 self 两种路径合并记录。
        // 为聚焦主线，省略 map 遍历细节。
        return methods;
    }
};

为什么要做这一层？因为 Hook 未初始化类的静态方法时，类初始化阶段 ART 可能会执行 FixupStaticTrampolines ，把静态方法入口重新修正为它认为正确的入口。LSPlant 先在 Class::SetStatus 即将进入 initialized 时备份入口，再让 ClassLinker 初始化后恢复。

public:

    };

private:
    // Runtime::instance_ 是 ART 全局 runtime 指针。
    inline static auto instance_ =
        "_ZN3art7Runtime9instance_E"_sym.as<Runtime *>;

    // Android 8.0+ 相关 debuggable 设置函数。
    inline static auto SetJavaDebuggable_ =
        "_ZN3art7Runtime17SetJavaDebuggableEb"_sym
            .as<void (Runtime::*)(bool)>;

    inline static auto SetRuntimeDebugState_ =
        "_ZN3art7Runtime20SetRuntimeDebugStateENS0_17RuntimeDebugStateE"_sym
            .as<void (Runtime::*)(RuntimeDebugState)>;

    inline static size_t debug_state_offset = 0U;

public:
    inline static Runtime *Current() {
        return *instance_;
    }

    void SetJavaDebuggable(RuntimeDebugState value) {
        if (SetJavaDebuggable_) {
            // 老接口只接收 bool。
            SetJavaDebuggable_(this, value != RuntimeDebugState::kNonJavaDebuggable);
        } else if (debug_state_offset > 0) {
            // 如果没有 SetJavaDebuggable_，就直接写 Runtime 内部 debug_state 字段。
            *reinterpret_cast<RuntimeDebugState *>(
                reinterpret_cast<uintptr_t>(*instance_) + debug_state_offset
            ) = value;
        }
    }

    static bool Init(const HookHandler &handler) {
        int sdk_int = GetAndroidApiLevel();

        if (!handler(instance_) || !*instance_) {
            return false;
        }
        LOGD("runtime instance = %p", *instance_);

        if (sdk_int >= kSdkOreo) {
            if (!handler(SetJavaDebuggable_, SetRuntimeDebugState_)) {
                return false;
            }
        }

        if (SetRuntimeDebugState_) {
            // 用一块假 Runtime 内存调用 SetRuntimeDebugState_，
            // 再扫描哪个偏移被写成 kJavaDebuggable，
            // 以此推导 Runtime::debug_state_ 的偏移。
            static constexpr size_t kLargeEnoughSizeForRuntime = 4096;
            std::array<uint8_t, kLargeEnoughSizeForRuntime> code;
            code.fill(uint8_t{0});

            auto *const fake_runtime = reinterpret_cast<Runtime *>(code.data());
            SetRuntimeDebugState_(fake_runtime, RuntimeDebugState::kJavaDebuggable);

            for (size_t i = 0; i < kLargeEnoughSizeForRuntime; ++i) {
                if (*reinterpret_cast<RuntimeDebugState *>(
                        reinterpret_cast<uintptr_t>(fake_runtime) + i
                    ) == RuntimeDebugState::kJavaDebuggable) {
                    LOGD("found debug_state at offset %zu", i);
                    debug_state_offset = i;
                    break;
                }
            }

            if (debug_state_offset == 0) {
                LOGE("failed to find debug_state");
                return false;
            }
        }
        return true;
    }
};

ClassLinker 初始化：解释器入口、native 注册和静态 trampoline

文件： lsplant/src/main/jni/art/runtime/class_linker.cxx

ClassLinker 是 InitNative 里最复杂的模块之一，主要管四件事：

  1. 解析或推导 art_quick_to_interpreter_bridge 。
  2. deoptimize 时把方法入口设到解释器。
  3. 类初始化后恢复被覆盖的静态方法 trampoline。
  4. native 方法注册时把 target/backup 关系传播正确。

    static void RestoreBackup(const dex::ClassDef *class_def, art::Thread *self) {
        // 从 Class::BackupClassMethods 保存的记录中取出旧入口。
        auto methods = mirror::Class::PopBackup(class_def, self);

        for (const auto &[art_method, old_trampoline] : methods) {
            auto new_trampoline = art_method->GetEntryPoint();

            // 恢复 target 方法上的 LSPlant trampoline。
            art_method->SetEntryPoint(old_trampoline);

            auto deoptimized = IsDeoptimized(art_method);
            auto backup_method = IsHooked(art_method);

            if (backup_method) {
                // 如果 ART 在类初始化过程中给 target 生成了新入口，
                // 且这个方法不是 deoptimized，就把新入口传播给 backup。
                if (!deoptimized && new_trampoline != old_trampoline) {
                    LOGV("propagate entrypoint for orig %p backup %p", art_method, backup_method);
                    backup_method->SetEntryPoint(new_trampoline);
                }
            } else if (deoptimized) {
                // deoptimized 方法如果又被 ART 改回非解释器入口，就重新 deoptimize。
                if (new_trampoline != &art_quick_to_interpreter_bridge_ &&
                    !art_method->IsNative()) {
                    LOGV("re-deoptimize for %p", art_method);
                    SetEntryPointsToInterpreter(art_method);
                }
            }
        }
    }

                backup(thiz, self);
            };

    inline static auto DoCollection_ =
        "_ZN3art3jit12JitCodeCache12DoCollectionEPNS_6ThreadE"_sym
            .hook->*[]<MemBackup auto backup>(
                JitCodeCache *thiz,
                Thread *self
            ) static -> void {
                MoveObsoleteMethods(thiz);
                backup(thiz, self);
            };

public:
    static bool Init(const HookHandler &handler) {
        auto sdk_int = GetAndroidApiLevel();

        if (sdk_int >= kSdkOreo) {
            if (!handler(MoveObsoleteMethod_)) {
                return false;
            }
        }

        if (sdk_int >= kSdkNougat) {
            if (!handler(GarbageCollectCache_, DoCollection_)) {
                return false;
            }
        }

        return true;
    }
};

这里的核心问题是：JIT 不只会生成机器码，还会维护代码缓存和 obsolete method。Hook 之后 target/backup 的入口和 data 关系被 LSPlant 改写，如果 JIT cache 回收时不迁移记录，backup 调原方法或 target 保持 trampoline 都可能出问题。

                size_t size,

                uint32_t location_checksum,
                void *mem_map,
                const void *oat_dex_file,
                std::string *error_msg
            )>;

    // Android 9+ 可以尝试调用内部 DexFile_setTrusted，
    // 让动态 Dex 绕过部分 hidden API 限制。
    inline static auto DexFile_setTrusted_ =
        "_ZN3artL18DexFile_setTrustedEP7_JNIEnvP7_jclassP8_jobject"_sym
            .as<void(JNIEnv *env, jclass clazz, jobject j_cookie)>;

public:
    static const DexFile *OpenMemory(
        const uint8_t *dex_file,
        size_t size,
        std::string location,
        std::string *error_msg
    ) {
        if (OpenMemory_) {
            return OpenMemory_(
                dex_file,
                size,
                location,
                reinterpret_cast<const Header *>(dex_file)->checksum_,
                nullptr,
                nullptr,
                error_msg
            ).release();
        }

        // 源码还有 OpenMemoryRaw_ 和 OpenMemoryWithoutOdex_ fallback，
        // 用于不同 Android 版本的函数签名差异。
        if (error_msg) *error_msg = "null sym";
        return nullptr;
    }

    jobject ToJavaDexFile(JNIEnv *env) const {
        // 在 Android 8.0 前，LSPlant 手动构造 dalvik.system.DexFile 对象，
        // 并填充 mCookie/mInternalCookie/mFileName。
        auto *java_dex_file = env->AllocObject(dex_file_class);
        auto cookie = JNI_NewLongArray(env, dex_file_start_index + 1);
        cookie[dex_file_start_index] = reinterpret_cast<jlong>(this);
        cookie.commit();
        JNI_SetObjectField(env, java_dex_file, cookie_field, cookie);
        JNI_SetObjectField(env, java_dex_file, file_name_field, JNI_NewStringUTF(env, ""));
        return java_dex_file;
    }

    static bool SetTrusted(JNIEnv *env, jobject cookie) {
        if (!DexFile_setTrusted_) return false;
        DexFile_setTrusted_(env, nullptr, cookie);
        return true;
    }

    static bool Init(JNIEnv *env, const HookHandler &handler) {
        auto sdk_int = GetAndroidApiLevel();

        if (sdk_int >= kSdkPie) {
            if (!handler(DexFile_setTrusted_, true)) {
                LOGW("DexFile.setTrusted not found, MakeDexFileTrusted will not work.");
            }
        }

        // Android 8.0+ InitJNI 已缓存 DexFile(ByteBuffer) 构造函数，
        // 这里不需要再走 OpenMemory。
        if (sdk_int >= kSdkOreo) {
            return true;
        }

        if (!handler(OpenMemory_, OpenMemoryRaw_, OpenMemoryWithoutOdex_)) {
            LOGE("Failed to find OpenMemory");
            return false;
        }

        dex_file_class = JNI_NewGlobalRef(env, JNI_FindClass(env, "dalvik/system/DexFile"));
        if (!dex_file_class) return false;

        // 不同 Android 版本 mCookie 类型不同：
        // Android 6.0+ 通常是 Object，Android 5.x 是 long。
        if (sdk_int >= kSdkMarshmallow) {
            cookie_field = JNI_GetFieldID(env, dex_file_class, "mCookie", "Ljava/lang/Object;");
        } else {
            cookie_field = JNI_GetFieldID(env, dex_file_class, "mCookie", "J");
            dex_file_start_index = -1;
        }

        file_name_field = JNI_GetFieldID(env, dex_file_class, "mFileName", "Ljava/lang/String;");

        if (sdk_int >= kSdkNougat) {
            internal_cookie_field =
                JNI_GetFieldID(env, dex_file_class, "mInternalCookie", "Ljava/lang/Object;");
            dex_file_start_index = 1u;
        }

        return cookie_field && file_name_field;
    }
};

DexFile::Init 和 InitJNI 是配套的：

  • Android 8.0+：优先用 Java 层 DexFile(ByteBuffer) 构造函数。
  • Android 8.0 前：通过 ART 内部 DexFile::OpenMemory 和手动 Java DexFile 包装实现动态 Dex 加载。
  • Android 9+：尝试解析 DexFile_setTrusted ，用于 MakeDexFileTrusted() 。

这些都是为了后续 BuildDex() 生成 hook stub 后能把它加载成 Java class。

class Instrumentation {
    inline static ArtMethod *MaybeUseBackupMethod(
        ArtMethod *art_method,
        const void *quick_code
    ) {
        // 如果 ART 想更新已 hook target 的 code，
        // 并且 quick_code 不是当前 target entrypoint，
        // 就把更新传播到 backup，避免覆盖 target trampoline。
        if (auto backup = IsHooked(art_method);
            backup && art_method->GetEntryPoint() != quick_code) {
            LOGD("Propagate update method code %p for hooked method %p to its backup",
                 quick_code,
                 art_method);
            return backup;
        }
        return art_method;
    }

    inline static auto InitializeMethodsCode_ =
        "_ZN3art15instrumentation15Instrumentation21InitializeMethodsCodeEPNS_9ArtMethodEPKv"_sym
            .hook->*[]<MemBackup auto backup>(
                Instrumentation *thiz,
                ArtMethod *art_method,
                const void *quick_code
            ) static -> void {
                if (IsDeoptimized(art_method)) {
                    LOGV("skip update entrypoint on deoptimized method %s",
                         art_method->PrettyMethod(true).c_str());
                    return;
                }
                backup(thiz, MaybeUseBackupMethod(art_method, quick_code), quick_code);
            };

public:
    static bool Init(JNIEnv *env, const HookHandler &handler) {
        // 非 Java debuggable 通常不需要 hook instrumentation。
        if (!IsJavaDebuggable(env)) {
            return true;
        }

        int sdk_int = GetAndroidApiLevel();
        if (sdk_int >= kSdkPie) {
            if (!handler(
                    ReinitializeMethodsCode_,
                    InitializeMethodsCode_,
                    UpdateMethodsCodeToInterpreterEntryPoint_
                )) {
                return false;
            }
        }
        return true;
    }
};

class JniIdManager {
    inline static auto EncodeGenericId_ =
        ("_ZN3art3jni12JniIdManager15EncodeGenericIdINS_9ArtMethodEEEjNS_16ReflectiveHandleIT_EE"_sym |
         "_ZN3art3jni12JniIdManager15EncodeGenericIdINS_9ArtMethodEEEmNS_16ReflectiveHandleIT_EE"_sym)
            .hook->*[]<MemBackup auto backup>(
                JniIdManager *thiz,
                ReflectiveHandle<ArtMethod> method
            ) static -> uintptr_t {
                // 如果 debugger 或 JNI ID 管理器正在为 backup 编码，
                // 改成 target，避免 debugger attach 时崩溃或映射错乱。
                if (auto *target = IsBackup(method.Get())) {
                    LOGD("get generic id for %s", method.Get()->PrettyMethod().c_str());
                    method.Set(target);
                }
                return backup(thiz, method);
            };

public:
    static bool Init(JNIEnv *env, const HookHandler &handler) {
        int sdk_int = GetAndroidApiLevel();

        if (sdk_int >= kSdkR) {
            if (IsJavaDebuggable(env) && !handler(EncodeGenericId_)) {
                LOGW("Failed to hook EncodeGenericId, attaching debugger may crash the process");
            }
        }
        return true;
    }
};

这两个模块都只在特定场景下生效：

  • 非 debuggable 应用通常不会走 Instrumentation::Init 的 hook 分支。
  • Android 11+ 且 Java debuggable 时才尝试 hook JniIdManager::EncodeGenericId 。

这也解释了为什么同一套 Hook 在 debug/release、是否连接 debugger、是否开启 method tracing 时表现可能不同。

原理分析

为什么不是只改一次 entrypoint

最直观的 Hook 做法是：

target->SetEntryPoint(trampoline)

但 ART 不是静态系统。下面这些时机都可能重新处理方法入口：

  • 类第一次初始化， ClassLinker 修复静态方法 trampoline。
  • JIT 编译或优化编译，方法可能获得新的 quick code。
  • JIT code cache 回收，obsolete method 和 data 指针可能迁移。
  • debuggable、method tracing、debugger attach， Instrumentation 可能把入口改成解释器或 instrumentation stub。
  • native 方法注册或反注册， ArtMethod::data 和 entrypoint 可能变化。
  • deoptimize 时，方法入口被切到 art_quick_to_interpreter_bridge 。

因此 LSPlant 的策略是：

Hook 当下：
  改 target quick entry 为 LSPlant trampoline
  复制 target 到 backup
  记录 target <-> backup

Hook 之后：
  在 ART 可能重写入口的位置打保护性 hook
  target 上保持 trampoline
  原始/新生成的真实入口尽量传播给 backup
  deoptimized 方法保持解释器入口

这也是 InitNative 看起来 “很重” 的原因。

target、hook、backup 三者的关系

一次 Hook 完成后，三个 ArtMethod 的角色是：

角色来源entrypoint作用
target被 Hook 的原始方法LSPlant trampoline普通 Java 调用进入这里
hook运行时生成的 hook stub methodART 为 stub 生成 / 解释的入口接收原方法参数，调用 hooker_object.callback(Object[])
backup运行时生成的 backup stub method，随后复制 target 内容原方法入口或后续传播的新入口replacement 里反射调用原始逻辑

关键代码在 DoHook() ：

target->SetNonIntrinsic();
target->BackupTo(backup);
target->SetNonCompilable();
target->SetEntryPoint(entrypoint);

顺序也有意义：

  1. 先取消 intrinsic，避免特殊内建优化绕开普通入口。
  2. 再复制 target 到 backup，让 backup 保留原始逻辑。
  3. 再禁止 target 编译，降低后续 JIT 干扰。
  4. 最后把 target 入口改成 trampoline。

trampoline 为什么保存 ArtMethod 指针

LSPlant 的 trampoline 不是一个固定跳转地址，而是嵌入了 hook ArtMethod* 。

这样做有两个好处：

  1. 同一份模板可以给不同 hook 方法复用，只需要填不同 ArtMethod* 。
  2. trampoline 每次执行时从 hook ArtMethod 读取当前 quick entry，能适应 hook stub 后续被解释执行或 JIT 编译后的入口变化。

也就是说，target 总是进入 LSPlant trampoline，而 trampoline 再动态追踪 hook stub 的真实入口。

为什么要处理 Java debuggable

Java debuggable 会改变 ART 对方法入口的处理方式。调试、方法追踪、解释执行、 Instrumentation 都可能参与进来。

LSPlant 的处理分两层：

  • 初始化最后，如果 IsJavaDebuggable(env) 为真，把 runtime 状态设置成 kNonJavaDebuggable 。
  • 在 Instrumentation::Init 和 JniIdManager::Init 里，只有 debuggable 时才尝试 hook 相关函数，保护 entrypoint 和 debugger/JNI ID 映射。

这并不表示 “debuggable 一定不能 hook”，而是表示 debuggable 场景变量更多，必须额外保护。

版本差异为什么这么多

ART 是系统内部实现，Android 版本变化会带来：

  • 类名变化： Executable 、 AbstractMethod 、 ArtMethod 。
  • 字段变化： artMethod 、 accessFlags 、 mCookie 、 mInternalCookie 。
  • 符号变化：同一函数 mangled name 参数类型不同，甚至被内联或移除。
  • access flag 常量变化： kAccPreCompiled 、 kAccIntrinsic 等值和可用性不同。
  • ClassStatus 枚举值变化： initialized_status 在不同版本不是同一个数字。
  • JIT 编译任务枚举变化： CompilationKind::kOptimized 取值需要探测。

所以 LSPlant 很少写死 “某 Android 版本一定是某个结构体布局”，而是尽量运行时探测：

  • 用两个构造器地址差估算 ArtMethod size。
  • 扫描内存定位 accessFlags 。
  • 通过调用 SetRuntimeDebugState_ 到假 runtime 上寻找 debug_state_offset 。
  • 多个符号候选按顺序尝试。
  • 对某些符号允许 prefix resolver。

常见错误与排查

LSPTest.initHooker() 返回 false

可能原因：

  • InitInfo.inline_hooker 、 inline_unhooker 、 art_symbol_resolver 、 art_symbol_prefix_resolver 有空值。
  • xDL 没打开 libart.so ，或符号解析器只能查 .dynsym ，查不到 .symtab 。
  • 当前 Android 版本或厂商 ROM 的 ART 符号和源码适配不匹配。
  • Dobby hook ART 内部函数失败。
  • ArtMethod::Init 探测字段失败。

排查方式：

adb logcat -s LSPlant:D LSPlant-test:D '*:S'

优先查这些日志：

Failed to find Executable/AbstractMethod/ArtMethod
Failed to find artMethod field
Failed to find GetMethodShorty
Failed to init art method
Failed to init class linker
Failed to init jit code cache
Failed to init instrumentation

如果日志停在 Failed to find xxx ，说明问题大概率在符号解析器或版本兼容。

art_symbol_prefix_resolver 为空导致 Init 失败

InitInfo 头文件注释里写 prefix resolver “May be null”，但当前 Init() 实现是：

if (!info.inline_hooker ||
    !info.inline_unhooker ||
    !info.art_symbol_resolver ||
    !info.art_symbol_prefix_resolver) {
    return false;
}

所以当前源码中它实际是必填项。即使你的 resolver 只是简单复用精确查找，也要传入：

.art_symbol_prefix_resolver = [](std::string_view symbol) -> void * {
    return find_symbol(handle, symbol.data());
},

Failed to find GetMethodShorty

GetMethodShorty 用于从 Java 反射方法拿 shorty，后续 BuildDex() 需要它生成签名兼容的 hook stub。

排查点：

  • xdl_sym 和 xdl_dsym 是否都调用了。
  • 是否真的打开了当前进程的 libart.so 。
  • 当前 ROM 是否 stripped 掉了 LSPlant 需要的符号。
  • art_symbol_prefix_resolver 是否可用。

Hook 未初始化类的静态方法失效

现象：

Hooker.hook(staticMethod) 返回非空
类初始化前后结果不一致
第一次调用有效，后续被恢复成原始逻辑

优先检查：

  • Class::Init 是否成功 hook Class::SetStatus 。
  • ClassLinker::Init 是否成功 hook FixupStaticTrampolines 或 visible initialized callback。
  • logcat 是否出现 Backup hooked method because of initialization 、 propagate entrypoint 、 re-deoptimize 。

这类问题常见于 ClassLinker 符号变化或被内联。

Hook 后短方法仍然走原逻辑

可能原因是调用方已经被 JIT/AOT 内联。LSPlant hook 的是被调用方法的入口；如果调用者方法里已经内联了被调用方法，就不会再经过 target entrypoint。

处理方式：

  • 换一个更外层或更稳定的 Hook 点。
  • 对调用者执行 lsplant::Deoptimize(env, caller_method) 。
  • 重新安装应用或清理 profile，让 ART 重新走解释执行 / 编译路径。

IllegalAccessError: Illegal class access

如果自带测试中出现类似：

java.lang.IllegalAccessError:
  Illegal class access: UnitTest attempting to access Hooker$MethodCallback

说明 native 初始化通常已经通过，错误发生在 Java 测试代码访问权限阶段。可以检查：

  • Hooker.MethodCallback 是否是测试进程可访问的 public 类型。
  • app APK 和 androidTest APK 是否处于不同 classloader。
  • replacement 方法签名是否和测试代码中反射获取的一致。

如果只是验证 InitNative ，可以先只看 t00_init 是否通过。

连接 debugger 后崩溃

可能原因：

  • debuggable 应用触发了 Instrumentation 或 JniIdManager 相关路径。
  • JniIdManager::EncodeGenericId 符号没有 hook 成功。
  • ART 想更新已 hook 方法的 entrypoint，但没有传播到 backup。

排查点：

Failed to hook EncodeGenericId, attaching debugger may crash the process
Propagate update method code ...
skip update entrypoint on deoptimized method ...

如果目标是稳定验证 Hook，建议先使用非 debuggable 测试包，减少变量。

总结

InitNative 可以用一句话概括：

在真正 Hook Java 方法前，LSPlant 先把 ART 后续可能影响 method entrypoint 的路径都接入管理。

主线是：

ArtMethod
  -> 找到可改的 quick entry

Trampoline
  -> 让 target 调到 hook stub

Thread / ScopedSuspendAll / ScopedGCCriticalSection
  -> 让入口修改尽量避开并发和 GC 风险

Class / ClassLinker
  -> 防止类初始化、静态 trampoline、native 注册覆盖 Hook 状态

Runtime / Instrumentation / JniIdManager
  -> 处理 debuggable、debugger、method code 更新

JIT / JitCodeCache
  -> 处理编译、优化和代码缓存回收

DexFile
  -> 支撑运行时生成和加载 hook stub

适用场景：

  • 研究 ART 方法入口 Hook。
  • 实现 Xposed 风格 Java 方法替换。
  • 需要 backup 调回原方法的 native hook 框架。
  • 需要理解 JIT、deoptimize、debuggable 对 Hook 稳定性的影响。

可扩展方向：

  • 替换 Dobby 为其他 inline hook 框架，只要实现 InitInfo.inline_hooker/unhooker 。
  • 替换 xDL 为自研 ELF 符号解析器，只要能查 .dynsym 和 .symtab 。
  • 自定义 executable memory allocator，统一管理 trampoline 内存。
  • 为特定 ROM 增加符号候选、prefix resolver 或版本分支。
  • 在测试层补充不同 Android 版本、debuggable 状态、JIT 热点场景的回归用例。
