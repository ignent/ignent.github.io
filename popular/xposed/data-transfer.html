Xposed 跨进程数据传递：自定义系统服务方案

ZIP2026/6/12...大约 9 分钟XposedLSPosedIPCAIDL

方案概述

在 Xposed Hook 中，经常需要在不同进程间传递数据。传统方案使用广播（BroadcastReceiver），但存在安全性和时效性问题。本文介绍一种基于 自定义系统服务 的跨进程数据传递方案，通过劫持系统 ServiceManager 实现高效、安全的进程间通信。

核心思路

  1. 在 system_server 进程中注入自定义服务管理器 XServiceManager
  2. 劫持现有系统服务（如 clipboard ）的 Binder 对象，将其包装为代理
  3. 通过特定的 transaction code 区分系统调用和自定义服务调用
  4. 客户端通过 XServiceManager.getService() 获取自定义服务
  5. 使用 AIDL 定义服务接口，实现类型安全的跨进程通信

对比广播方案

广播方案：

// 发送方
Intent intent = new Intent("0x_crypto_config");
intent.putExtra("crypto_name", "AES");
context.sendBroadcast(intent);

// 接收方
BroadcastReceiver receiver = new BroadcastReceiver() {
    public void onReceive(Context context, Intent intent) {
        String name = intent.getStringExtra("crypto_name");
    }
};

问题：

  • 需要声明权限，可能被其他应用拦截或监听
  • 异步通知，无法获取返回值
  • 需要序列化数据到 Intent

自定义服务方案：

  • 直接通过 Binder 通信，无需 Intent 序列化
  • 支持同步调用和返回值
  • 基于 AIDL，类型安全
  • 服务注册在系统层，不易被检测

实现步骤

1. 定义 AIDL 接口

文件路径： app/src/main/aidl/com/xposed/ICustomService.aidl

package com.xposed;

interface ICustomService {
    String getCryptoName();
    void setCryptoName(String name);
}

AIDL 编译后会生成对应的 Java 接口和 Stub 类，用于 Binder 通信。

2. 实现服务类

文件路径： app/src/main/java/com/xposed/aidl/CustomService.java

public class CustomService extends ICustomService.Stub {
    private static String _name = "default";

    @Override
    public String getCryptoName() throws RemoteException {
        return _name;
    }

    @Override
    public void setCryptoName(String name) throws RemoteException {
        _name = name;
    }
}
  • 继承 ICustomService.Stub 实现 Binder 服务端
  • 使用静态变量 _name 存储跨进程共享的数据
  • 实现 getter 和 setter 方法

3. 核心：XServiceManager

文件路径： app/src/main/java/com/xposed/utils/XServiceManager.java

3.1 关键常量

private static final String DELEGATE_SERVICE = "clipboard";  // 劫持的系统服务
private static final String DESCRIPTOR = XServiceManager.class.getName();
private static final int TRANSACTION_getService = ('_' << 24) | ('Y' << 16) | ('R' << 8) | 'X';
  • DELEGATE_SERVICE ：选择 clipboard 服务作为劫持目标（该服务几乎所有应用都会访问）
  • DESCRIPTOR ：自定义服务的描述符，用于 Binder 通信
  • TRANSACTION_getService ：自定义 transaction code（ _YRX 的 ASCII 编码），值为 0x5F595258 ，用于区分自定义服务调用

3.2 初始化方法： initForSystemServer()

调用时机：在 HookEntry.handleLoadPackage() 中，当检测到 packageName 为 "android" 时调用（即 system_server 进程）

if ("android".equals(lpparam.packageName)) {
    XServiceManager.initForSystemServer();
    XServiceManager.addService("0x_crypto", new CustomService());
}

核心逻辑：

  1. 检查进程：
if (!isSystemServerProcess()) return;

通过 UID 和进程名双重检查，确保只在 system_server 进程中执行。

  1. 获取原始 ServiceManager：
Class<?> ServiceManagerClass = Class.forName("android.os.ServiceManager");
Method getIServiceManagerMethod = ServiceManagerClass.getDeclaredMethod("getIServiceManager");
final Object serviceManager = getIServiceManagerMethod.invoke(null);
  1. 创建动态代理：
Field sServiceManagerField = ServiceManagerClass.getDeclaredField("sServiceManager");
Class<?> IServiceManagerClass = sServiceManagerField.getType();
Object serviceManagerDelegate = Proxy.newProxyInstance(
    IServiceManagerClass.getClassLoader(),
    new Class[]{IServiceManagerClass},
    (proxy, method, args) -> {
        // 拦截逻辑
    }
);
sServiceManagerField.set(null, serviceManagerDelegate);

使用 Java 动态代理（Proxy）包装原始 ServiceManager，拦截所有方法调用。

  1. 拦截 addService 方法：
if ("addService".equals(methodName) && DELEGATE_SERVICE.equals(args[0])) {
    IBinder clipboardService = (IBinder) args[1];
    IBinder xServiceManagerService = new XServiceManagerService();
    args[1] = new BinderDelegateService(clipboardService, xServiceManagerService);
    // 创建所有注册的自定义服务
}

当系统注册 clipboard 服务时：

  • 获取原始 clipboard 的 IBinder
  • 创建 XServiceManagerService （自定义服务管理器）
  • 用 BinderDelegateService 包装两者
  • 替换掉原始 clipboard 服务

3.3 Binder 代理： BinderDelegateService

private static final class BinderDelegateService extends Binder {
    private final IBinder systemService;    // 原始 clipboard 服务
    private final IBinder customService;    // 自定义服务管理器

    @Override
    protected boolean onTransact(int code, Parcel data, Parcel reply, int flags) {
        if (code == TRANSACTION_getService) {
            return customService.transact(code, data, reply, flags);
        }
        return systemService.transact(code, data, reply, flags);
    }
}

工作原理：

  • 所有对 clipboard 服务的调用都会经过这个代理
  • 如果 transaction code 是 TRANSACTION_getService （ 0x5F595258 ），转发给自定义服务管理器
  • 否则，转发给原始 clipboard 服务
  • 对正常使用 clipboard 的应用完全透明

3.4 自定义服务管理器： XServiceManagerService

private static final class XServiceManagerService extends Binder {
    @Override
    protected boolean onTransact(int code, Parcel data, Parcel reply, int flags) {
        switch (code) {
            case INTERFACE_TRANSACTION: {
                reply.writeString(DESCRIPTOR);
                return true;
            }
            case TRANSACTION_getService: {
                data.enforceInterface(DESCRIPTOR);
                String name = data.readString();
                reply.writeNoException();
                IBinder binder = getServiceInternal(name);  // 从缓存获取服务
                reply.writeStrongBinder(binder);
                return true;
            }
        }
    }
}

负责处理自定义服务的查询请求，从 sCache 中返回注册的服务。

3.5 注册服务： addService()

public static void addService(String name, IBinder service) {
    if (!isSystemServerProcess()) return;
    sCache.put(name, service);
}

在 system_server 进程中，将自定义服务存入 HashMap 缓存。

3.6 获取服务： getService()

调用侧代码（任意进程）：

IBinder binder = XServiceManager.getService("0x_crypto");
ICustomService service = ICustomService.Stub.asInterface(binder);
String name = service.getCryptoName();

实现逻辑：

public static IBinder getService(String name) {
    // 1. 获取系统的 clipboard 服务（实际是我们的代理）
    Class<?> ServiceManagerClass = Class.forName("android.os.ServiceManager");
    Method checkService = ServiceManagerClass.getMethod("checkService", String.class);
    IBinder delegateService = (IBinder) checkService.invoke(null, DELEGATE_SERVICE);
    
    // 2. 构造自定义 Parcel 数据
    Parcel _data = Parcel.obtain();
    Parcel _reply = Parcel.obtain();
    _data.writeInterfaceToken(DESCRIPTOR);
    _data.writeString(name);
    
    // 3. 通过特定 transaction code 调用
    delegateService.transact(TRANSACTION_getService, _data, _reply, 0);
    
    // 4. 读取返回的 IBinder
    _reply.readException();
    return _reply.readStrongBinder();
}

流程图：

客户端                      代理 Binder                system_server
  |                            |                            |
  | getService("0x_crypto")    |                            |
  |--------------------------->|                            |
  | (code=0x5F595258)         |                            |
  |                            |  转发到 XServiceManagerService
  |                            |--------------------------->|
  |                            |                            | 从 sCache 查找
  |                            |      返回 CustomService    |
  |                            |<---------------------------|
  | 返回 IBinder              |                            |
  |<---------------------------|                            |

4. Hook 入口整合

文件路径： app/src/main/java/com/xposed/HookEntry.java

@Override
public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) throws Throwable {
    // 在 system_server 中注册服务
    if ("android".equals(lpparam.packageName)) {
        Log.d(TAG, "Hooking system_server, initializing XServiceManager");
        XServiceManager.initForSystemServer();
        XServiceManager.addService("0x_crypto", new CustomService());
        Log.d(TAG, "Registered 0x_crypto service");
    }

    // 在所有应用中注入 CryptoHook
    CryptoHook.hook(lpparam);
}

注意：

  • 只在 packageName == "android" 时初始化 XServiceManager
  • 所有应用都会执行 CryptoHook.hook() ，可以访问自定义服务

5. 使用示例：在 Hook 中访问服务

文件路径： app/src/main/java/com/xposed/hook/CryptoHook.java

XposedHelpers.findAndHookMethod(
    Base64.class,
    "encodeToString",
    byte[].class,
    int.class,
    new XC_MethodHook() {
        @Override
        protected void afterHookedMethod(MethodHookParam param) throws Throwable {
            // 获取自定义服务
            IBinder binder = XServiceManager.getService("0x_crypto");
            if (binder != null) {
                ICustomService service = ICustomService.Stub.asInterface(binder);
                String cryptoName = service.getCryptoName();
                Log.d(TAG, "Current crypto name: " + cryptoName);
            }
            
            Log.d(TAG, "[Base64 encodeToString]: " + bytesToHexString((byte[]) param.args[0]));
            Log.d(TAG, "[Base64 encodeToString R]: " + param.getResult());
        }
    }
);

效果：

  • 在任意应用的 Base64 编码时，都可以从 system_server 获取配置
  • 无需广播，直接同步调用
  • 支持双向通信（读取和设置）

6. UI 端配置服务

文件路径： app/src/main/java/com/xposed/MainActivity.java

@Override
public void onClick(View v) {
    IBinder binder = XServiceManager.getService("0x_crypto");
    if (binder != null) {
        ICustomService service = ICustomService.Stub.asInterface(binder);
        try {
            service.setCryptoName("Base64");  // 设置配置
            Log.d(TAG, "set success!");
        } catch (RemoteException e) {
            Log.e(TAG, "RemoteException: " + e.getMessage(), e);
        }
    }
}

点击按钮后，配置会立即写入 system_server，其他应用的 Hook 可以实时读取。

关键细节

1. Transaction Code 的设计

private static final int TRANSACTION_getService = ('_' << 24) | ('Y' << 16) | ('R' << 8) | 'X';

计算结果为 0x5F595258 ，转换为字符是 _YRX 。这个值：

  • 足够特殊，不会与系统服务的 transaction code 冲突
  • 系统服务的 transaction code 通常从 1 开始递增
  • 这是一个 4 字节的自定义标识

2. 为什么劫持 clipboard 服务？

  1. 广泛使用：几乎所有应用都会访问剪贴板，服务会被初始化
  2. 初始化时机：在 system_server 启动早期就会注册
  3. 调用频率：不会太高，不影响性能
  4. 兼容性：Android 各版本都存在

3. 进程检查的双重保险

private static boolean isSystemServerProcess() {
    if (Process.myUid() != Process.SYSTEM_UID) {
        return false;
    }
    try (BufferedReader r = new BufferedReader(new FileReader("/proc/self/cmdline"))) {
        String processName = r.readLine().trim();
        return "system_server".equals(processName);
    }
}
  • 检查 UID 是否为 1000 （SYSTEM_UID）
  • 检查进程名是否为 system_server
  • 避免在错误进程中注入，导致崩溃

4. 延迟注册机制： registerService()

public static <T extends Binder> void registerService(String name, ServiceFetcher<T> serviceFetcher) {
    SERVICE_FETCHERS.put(name, serviceFetcher);
}

如果某个自定义服务需要依赖系统 Context 或其他核心服务，可以使用 registerService() 注册一个工厂方法。当 clipboard 服务创建时，会自动调用工厂方法创建实例：

if ("addService".equals(methodName) && DELEGATE_SERVICE.equals(args[0])) {
    Context systemContext = ...; // 获取系统 Context
    for (Map.Entry<String, ServiceFetcher<?>> entry : SERVICE_FETCHERS.entrySet()) {
        Binder service = entry.getValue().createService(systemContext);
        addService(entry.getKey(), service);
    }
}

应用场景

场景 1：动态配置 Hook 行为

传统方式需要修改 SharedPreferences 或配置文件，应用需要重启。使用自定义服务：

// UI 端
service.setCryptoName("AES-GCM");

// Hook 端
String algorithm = service.getCryptoName();
if ("AES-GCM".equals(algorithm)) {
    // 针对性处理
}

场景 2：跨应用数据共享

多个应用的 Hook 都可以访问同一个服务，实现数据共享：

// 应用 A 的 Hook
service.setCryptoName("SHA256:detected");

// 应用 B 的 Hook
String status = service.getCryptoName();
if (status.startsWith("SHA256:")) {
    // 同步状态
}

场景 3：Hook 数据回传

传统方式需要写文件或发广播，使用服务可以直接回传：

// Hook 端
service.setCryptoName("key=" + hexKey + ",iv=" + hexIv);

// UI 端
String data = service.getCryptoName();
String[] parts = data.split(",");
// 实时显示 Hook 到的数据

注意事项

1. 线程安全

CustomService 中的静态变量 _name 会被多个进程并发访问，如果需要复杂数据结构，应该使用线程安全的容器：

private static final ConcurrentHashMap<String, String> _data = new ConcurrentHashMap<>();

2. 数据大小限制

Binder 通信有 1MB 的 transaction 限制，不适合传输大量数据。如需传输文件，应使用共享内存或文件路径。

3. 服务生命周期

自定义服务随 system_server 启动，在系统运行期间一直存活。重启 system_server 会导致数据丢失，需要持久化的数据应写入文件。

4. 安全性

虽然比广播安全，但任何知道服务名和 transaction code 的应用都可以访问。如需加密，可以在 AIDL 接口中实现：

interface ICustomService {
    String getData(String key, String signature);
}

5. 兼容性测试

不同 Android 版本的 ServiceManager 实现可能有差异，建议在以下版本测试：

  • Android 8.0（API 26）：首次引入 Treble
  • Android 10（API 29）：隐私和权限大改
  • Android 12（API 31）：限制反射访问
  • Android 13+（API 33+）：最新安全策略

总结

自定义系统服务方案通过劫持系统 ServiceManager，实现了高效、安全的跨进程数据传递。核心技术点：

  1. 动态代理拦截：使用 Java Proxy 包装 ServiceManager
  2. Binder 代理模式：通过 transaction code 区分调用
  3. 服务注入时机：在 clipboard 注册时插入自定义服务
  4. AIDL 接口定义：类型安全的跨进程通信

相比传统广播方案，该方案在性能、安全性、实时性上都有显著优势，适用于需要频繁跨进程通信的 Xposed 模块。
