LSPosed Native Hook：JNI 函数与偏移地址拦截

ZIP2026/6/12...大约 9 分钟XposedLSPosedNative HookJNI

方案概述

在逆向 Android 应用时，除了 Java 层的加密逻辑，很多核心算法都实现在 Native 层（.so 库）。LSPosed 提供了 Native Hook 能力，可以拦截 JNI 函数和 Native 函数的调用。

本文介绍如何使用 LSPosed 的 Native API 实现：

  1. JNI 导出函数 Hook：拦截 Java_ 开头的 JNI 函数
  2. 偏移地址 Hook：拦截未导出的 Native 函数（通过 IDA 分析的偏移地址）
  3. 动态库加载监听：在目标 .so 加载时自动注入 Hook

核心流程

实现步骤

1. 定义 Native API 接口

文件路径： app/src/main/cpp/hook.h

#ifndef XSSXPOSEDTEMPLATE_HOOK_H
#define XSSXPOSEDTEMPLATE_HOOK_H

#include <cstdint>

// Hook 函数指针类型
typedef int (*HookFunType)(void *func, void *replace, void **backup);

// Unhook 函数指针类型
typedef int (*UnhookFunType)(void *func);

// 动态库加载回调类型
typedef void (*NativeOnModuleLoaded)(const char *name, void *handle);

// LSPosed Native API 入口结构体
typedef struct {
    uint32_t version;           // API 版本号
    HookFunType hook_func;      // Hook 函数
    UnhookFunType unhook_func;  // Unhook 函数
} NativeAPIEntries;

// 初始化函数类型
typedef NativeOnModuleLoaded (*NativeInit)(const NativeAPIEntries *entries);

#endif //XSSXPOSEDTEMPLATE_HOOK_H

1.1 结构体说明

NativeAPIEntries：

  • version ：API 版本号（LSPosed 提供）
  • hook_func ：LSPosed 提供的 Native Hook 函数
  • unhook_func ：LSPosed 提供的 Unhook 函数

HookFunType 函数签名：

int hook_func(void *func, void *replace, void **backup);
  • func ：目标函数地址
  • replace ：替换函数地址
  • backup ：保存原函数地址的指针（用于调用原函数）
  • 返回值： 0 表示成功，非 0 表示失败

2. 实现 Native Hook 逻辑

文件路径： app/src/main/cpp/native-lib.cpp

2.1 全局变量定义

#include <jni.h>
#include <string>
#include <dlfcn.h>
#include <android/log.h>

#include "hook.h"

// LSPosed 提供的 Hook 函数
static HookFunType hook_func = nullptr;

// 备份原始 JNI 函数
jboolean (*backup)(JNIEnv *env, jclass clazz);

// 备份原始 Native 函数
void (*sub_func)(const uint8_t *data, size_t len, uint8_t *out);

2.2 JNI 函数替换实现

jboolean replace_backup(JNIEnv *env, jclass clazz) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "replace_backup: ");
    return backup(env, clazz);
}

工作原理：

  1. 当目标应用调用原始 JNI 函数时，会先进入 replace_backup
  2. 在这里可以记录日志、修改参数
  3. 通过 backup 调用原始函数
  4. 可以修改返回值后再返回给调用方

2.3 Native 函数替换实现

void sub_func_hook(const uint8_t *data, size_t len, uint8_t *out) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "sub_func_hook: %s, %d", data, len);
    sub_func(data, len, out);
}

作用：

  • 拦截未导出的 Native 函数（通过偏移地址定位）
  • 记录函数输入参数
  • 调用原始函数完成计算

2.4 获取 .so 基地址

void *get_module_base(const char *module_name) {
    FILE *fp = fopen("/proc/self/maps", "r");
    if (fp == nullptr) {
        return nullptr;
    }
    char line[512];
    void *base = nullptr;
    while (fgets(line, sizeof(line), fp)) {
        if (strstr(line, module_name)) {
            char *start_str = strtok(line, "-");
            if (start_str) {
                base = (void *) strtoul(start_str, nullptr, 16);
                break;
            }
        }
    }
    fclose(fp);
    return base;
}

实现原理：

/proc/self/maps 文件记录了进程的内存映射，格式如下：

7b8e4000-7b8e5000 r--p 00000000 fe:08 1234  /data/app/com.example/lib/arm64/libexercise15.so
7b8e5000-7b8e6000 r-xp 00001000 fe:08 1234  /data/app/com.example/lib/arm64/libexercise15.so
7b8e6000-7b8e7000 rw-p 00002000 fe:08 1234  /data/app/com.example/lib/arm64/libexercise15.so
  • 第一列：内存地址范围（ start-end ）
  • 最后一列：文件路径

逻辑步骤：

  1. 逐行读取 /proc/self/maps
  2. 查找包含目标 .so 名称的行
  3. 解析第一个地址（起始地址）
  4. 转换为十六进制数值返回

2.5 动态库加载回调

void on_library_loaded(const char *name, void *handle) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded: %s", name);

    if (std::string(name).ends_with("libexercise15.so")) {
        // 1. Hook JNI 导出函数
        void *target = dlsym(handle, "Java_com_challenge_exercise_Exercise15Lib_check2");
        __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded target: %p", target);
        int ret = hook_func(target, (void *) replace_backup, (void **) &backup);
        __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded ret: %d", ret);

        // 2. 获取 .so 基地址
        const char *last_slash = strchr(name, '/');
        const char *short_name = last_slash ? last_slash + 1 : name;
        void *base_address = get_module_base(short_name);
        if (!base_address) {
            base_address = get_module_base(name);
        }
        __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded base_address: %p",
                            base_address);

        // 3. Hook 偏移地址
        void *target_addr = (void *) ((uintptr_t) base_address + 0xA64);
        if (target_addr) {
            ret = hook_func(target_addr, (void *) sub_func_hook, (void **) &sub_func);
            __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded ret: %d", ret);
        }
    }
}

核心逻辑分解：

第一步：Hook JNI 导出函数
void *target = dlsym(handle, "Java_com_challenge_exercise_Exercise15Lib_check2");
int ret = hook_func(target, (void *) replace_backup, (void **) &backup);
  • dlsym(handle, symbol) ：从动态库中获取符号地址
  • JNI 函数命名规则： Java_包名_类名_方法名 （包名中的 . 替换为 _ ）
  • hook_func 安装 Hook
第二步：获取基地址
const char *last_slash = strchr(name, '/');
const char *short_name = last_slash ? last_slash + 1 : name;
void *base_address = get_module_base(short_name);
  • name 可能是完整路径： /data/app/.../lib/arm64/libexercise15.so
  • 提取短名称： libexercise15.so
  • 从 /proc/self/maps 查找基地址
第三步：Hook 偏移地址
void *target_addr = (void *) ((uintptr_t) base_address + 0xA64);
ret = hook_func(target_addr, (void *) sub_func_hook, (void **) &sub_func);
  • 0xA64 ：通过 IDA Pro 或 Ghidra 分析得到的函数偏移
  • base_address + 偏移 ：计算函数的运行时绝对地址
  • 安装 Hook

2.6 模块初始化函数

extern "C" [[gnu::visibility("default")]] [[gnu::used]]
jint JNI_OnLoad(JavaVM *jvm, void *) {
    JNIEnv *env = nullptr;
    return JNI_VERSION_1_6;
}

extern "C" [[gnu::visibility("default")]] [[gnu::used]]
NativeOnModuleLoaded native_init(const NativeAPIEntries *entries) {
    hook_func = entries->hook_func;
    return on_library_loaded;
}

native_init 函数说明：

  • 函数名固定：LSPosed 会查找名为 native_init 的符号
  • 可见性声明： [[gnu::visibility("default")]] 确保函数导出
  • 防止优化： [[gnu::used]] 防止编译器优化掉未被调用的函数
  • 参数： NativeAPIEntries *entries 由 LSPosed 框架传入
  • 返回值：返回动态库加载回调函数

执行流程：

LSPosed 框架
  ↓ 加载 libxposed.so
  ↓ 调用 native_init(entries)
  ↓ 保存 hook_func
  ↓ 返回 on_library_loaded
  ↓ 目标应用加载 libexercise15.so
  ↓ 触发 on_library_loaded("libexercise15.so", handle)

5. Java 层加载 Native 库

文件路径： app/src/main/java/com/xposed/HookEntry.java

public class HookEntry implements IXposedHookZygoteInit, IXposedHookLoadPackage {
    private final static String TAG = "0X->";

    @Override
    public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) throws Throwable {
        System.loadLibrary("xposed");
    }

    @Override
    public void initZygote(StartupParam startupParam) throws Throwable {
        // 可以为空
    }
}

注意：

  • System.loadLibrary("xposed") 对应的是 libxposed.so
  • 这个调用会触发 JNI_OnLoad

  • 设置 false 避免重复提取
  • 加快应用启动速度

如何获取 Hook 目标

1. 获取 JNI 函数名

方法一：使用 nm 命令

nm -D libexercise15.so | grep Java_

输出示例：

00001a20 T Java_com_challenge_exercise_Exercise15Lib_check2

方法二：使用 IDA Pro

  1. 打开 .so 文件
  2. 查看 Exports 窗口（View → Open Subviews → Exports）
  3. 搜索 Java_ 开头的函数

2. 获取 Native 函数偏移

使用 IDA Pro 或 Ghidra：

  1. 反编译 .so 文件
  2. 定位目标函数（通过字符串引用、交叉引用等）
  3. 记录函数起始地址的偏移

示例（IDA Pro）：

.text:0000000000000A64 sub_A64:
.text:0000000000000A64    STP   X29, X30, [SP, #-0x10]!
.text:0000000000000A68    MOV   X29, SP

函数偏移为 0xA64 。

重要提示：

  • 偏移地址是相对于 .so 基地址的
  • 不同架构（arm/arm64/x86）的偏移不同
  • 需要根据目标设备选择正确的 .so 文件

3. 确定函数签名

通过 IDA Pro 的反编译结果确定函数参数和返回值：

void __fastcall sub_A64(const uint8_t *data, size_t len, uint8_t *out)
{
  // 函数体
}

然后在 C++ 中声明相同签名的函数指针：

void (*sub_func)(const uint8_t *data, size_t len, uint8_t *out);

高级技巧

1. 修改函数返回值

jboolean replace_backup(JNIEnv *env, jclass clazz) {
    jboolean result = backup(env, clazz);
    __android_log_print(ANDROID_LOG_INFO, "0X->", "原始返回值: %d", result);
    return JNI_TRUE;  // 强制返回 true
}

2. 修改函数参数

void sub_func_hook(const uint8_t *data, size_t len, uint8_t *out) {
    // 修改输入数据
    uint8_t modified_data[] = "hacked";
    sub_func(modified_data, sizeof(modified_data), out);
}

3. 跳过原函数执行

jboolean replace_backup(JNIEnv *env, jclass clazz) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "跳过原函数");
    return JNI_FALSE;  // 不调用 backup，直接返回
}

4. 多函数 Hook

void on_library_loaded(const char *name, void *handle) {
    if (std::string(name).ends_with("libexample.so")) {
        // Hook 多个函数
        void *func1 = dlsym(handle, "Java_..._method1");
        hook_func(func1, (void *) replace_func1, (void **) &backup_func1);
        
        void *func2 = dlsym(handle, "Java_..._method2");
        hook_func(func2, (void *) replace_func2, (void **) &backup_func2);
    }
}

5. 条件 Hook

void sub_func_hook(const uint8_t *data, size_t len, uint8_t *out) {
    if (strstr((const char *)data, "password")) {
        __android_log_print(ANDROID_LOG_INFO, "0X->", "检测到敏感数据");
        // 特殊处理
    }
    sub_func(data, len, out);
}

注意事项

1. 架构匹配

确保 Native 库支持目标设备的架构：

app/src/main/
├── jniLibs/
│   ├── arm64-v8a/
│   │   └── libxposed.so
│   ├── armeabi-v7a/
│   │   └── libxposed.so
│   └── x86_64/
│       └── libxposed.so

2. ASLR（地址空间布局随机化）

  • Android 默认启用 ASLR
  • 每次应用启动时，.so 的基地址会变化
  • 必须动态计算： 基地址 + 偏移 ，不能硬编码绝对地址

3. 函数签名匹配

替换函数和原函数的签名必须完全一致：

// 错误示例
jboolean backup(JNIEnv *env, jclass clazz);
void replace_backup() { ... }  // 签名不匹配，会崩溃

// 正确示例
jboolean replace_backup(JNIEnv *env, jclass clazz) { ... }

4. 符号可见性

extern "C" [[gnu::visibility("default")]] [[gnu::used]]
  • 不加这些属性，函数可能不会被导出
  • LSPosed 无法找到 native_init 符号

5. 日志输出

#include <android/log.h>

__android_log_print(ANDROID_LOG_INFO, "TAG", "消息: %s", str);
  • 使用 Android 日志系统，不要用 printf
  • 通过 adb logcat 查看输出

6. 内存安全

void sub_func_hook(const uint8_t *data, size_t len, uint8_t *out) {
    // 检查指针有效性
    if (!data || !out) {
        return;
    }
    sub_func(data, len, out);
}

7. 多进程支持

如果目标应用有多个进程，每个进程都会触发 on_library_loaded ：

void on_library_loaded(const char *name, void *handle) {
    // 检查当前进程
    char process_name[256];
    get_process_name(process_name, sizeof(process_name));
    
    if (strcmp(process_name, "com.example:main") == 0) {
        // 只在主进程 Hook
    }
}

调试技巧

1. 检查 Hook 是否生效

int ret = hook_func(target, (void *) replace_backup, (void **) &backup);
if (ret == 0) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "Hook 成功");
} else {
    __android_log_print(ANDROID_LOG_ERROR, "0X->", "Hook 失败: %d", ret);
}

2. 验证地址有效性

void *target = dlsym(handle, "Java_..._method");
if (target) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "函数地址: %p", target);
} else {
    __android_log_print(ANDROID_LOG_ERROR, "0X->", "未找到符号");
}

3. 输出调用栈

#include <unwind.h>

_Unwind_Backtrace([](struct _Unwind_Context* context, void* arg) -> _Unwind_Reason_Code {
    uintptr_t pc = _Unwind_GetIP(context);
    __android_log_print(ANDROID_LOG_INFO, "0X->", "栈帧: 0x%lx", pc);
    return _URC_NO_REASON;
}, nullptr);

总结

LSPosed Native Hook 通过以下机制实现 Native 层拦截：

  1. 模块初始化： native_init 获取 LSPosed 提供的 Hook API
  2. 动态库监听： on_library_loaded 在目标 .so 加载时触发
  3. 符号解析： dlsym 获取 JNI 导出函数地址
  4. 基地址计算：解析 /proc/self/maps 获取 .so 基地址
  5. 偏移计算： 基地址 + IDA偏移 得到运行时绝对地址
  6. 安装 Hook： hook_func 替换目标函数

核心优势：

  • 无需修改 APK，通过 LSPosed 动态注入
  • 支持 JNI 导出函数和未导出函数
  • 可拦截、修改参数和返回值
  • 适用于加密算法逆向、反调试绕过
