YukiHookAPI 入门配置

ZIP2026/6/17...大约 13 分钟Xposed, YukiHookAPI, DexKit, 生命周期, Hook

YukiHookAPI 完整实战：从入口配置到高级 Hook

概述

基于 YukiHookAPI 的综合小案例。

技术覆盖

  • 模块入口配置： @InjectYukiHookWithXposed 注解自动生成
  • 生命周期监听：监控 Application 的完整生命周期
  • DexKit 混淆查找：通过方法签名特征定位混淆类
  • Activity Hook：拦截所有 Activity 的 onCreate 方法
  • 跨进程数据通信：模块与宿主应用的数据交换
  • 配置存储：SharedPreferences 跨进程访问
  • 错误处理：完整的失败回调链

项目结构

YukiHookTemplate/
├── App.kt                    # 模块的 Application
├── HookEntry.kt              # Xposed 入口
├── MainModuleActivity.kt     # 模块管理界面
└── MainActivity.kt           # 原生界面（含 JNI）

第一部分：模块入口配置

1.1 HookEntry 类结构

package com.zilo.template

import com.highcapable.yukihookapi.YukiHookAPI
import com.highcapable.yukihookapi.annotation.xposed.InjectYukiHookWithXposed
import com.highcapable.yukihookapi.hook.factory.configs
import com.highcapable.yukihookapi.hook.log.YLog
import com.highcapable.yukihookapi.hook.xposed.proxy.IYukiHookXposedInit
import com.template.BuildConfig
import org.luckypray.dexkit.DexKitBridge

@InjectYukiHookWithXposed
class HookEntry : IYukiHookXposedInit {

    public final val tag: String = "0X->"

    companion object {
        init {
            System.loadLibrary("dexkit")
        }
    }

    override fun onInit() = configs {
        isDebug = BuildConfig.DEBUG
        debugLog {
            tag = "0X->"
            isRecord = true
        }
    }

    override fun onHook() = YukiHookAPI.encase {
        loadApp(name = "com.zilo.challenge") {
            // Hook 逻辑在这里展开
        }
    }
}

1.2 核心注解：@InjectYukiHookWithXposed

作用：这是 YukiHookAPI 最重要的注解，它会在编译时自动生成 Xposed 入口代码。

工作原理：

编译时
    ↓
KSP (Kotlin Symbol Processing) 扫描注解
    ↓
自动生成 HookEntry_YukiHookXposedInit.kt
    ↓
生成文件位置：build/generated/ksp/debug/kotlin/
    ↓
实现 IXposedHookLoadPackage 接口

生成的代码示例：

// 自动生成的文件：HookEntry_YukiHookXposedInit.kt
class HookEntry_YukiHookXposedInit : IXposedHookLoadPackage {
    override fun handleLoadPackage(lpparam: LoadPackageParam) {
        YukiHookAPI.encase(lpparam) {
            // 调用你的 HookEntry.onHook()
        }
    }
}

2.1 示例代码

override fun onHook() = YukiHookAPI.encase {
    loadApp(name = "com.zilo.challenge") {
        onAppLifecycle(isOnFailureThrowToApp = false) {
            attachBaseContext { baseContext, hasCalledSuper ->
                YLog.debug(msg = "attachBaseContext: $hasCalledSuper")
            }
            
            onCreate {
                YLog.debug(msg = "onCreate: $this")
            }
            
            onTerminate {
                YLog.debug(msg = "onTerminate: $this")
            }
            
            onLowMemory {
                YLog.debug(msg = "onLowMemory: $this")
            }
            
            onTrimMemory { self, level ->
                if (level == ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
                    YLog.debug(msg = "onTrimMemory: TRIM_MEMORY_UI_HIDDEN: $level")
                }
                YLog.debug(msg = "onTrimMemory: $level")
            }
            
            onConfigurationChanged { self, config ->
                YLog.debug(msg = "onConfigurationChanged: $config")
            }
        }
    }
}

2.2 loadApp 指定目标应用

loadApp(name = "com.zilo.challenge") {
    // 仅在目标应用中执行
}

作用：

  • 过滤包名，避免在其他应用中执行
  • 支持多个 loadApp 块 Hook 不同应用
  • 支持使用 loadZygote Hook 系统框架

2.3 attachBaseContext 详解

attachBaseContext { baseContext, hasCalledSuper ->
    YLog.debug(msg = "attachBaseContext: $hasCalledSuper")
}

参数说明：

  • baseContext ：传入的 Context 对象
  • hasCalledSuper ：是否已执行 super.attachBaseContext(base)

执行流程：

// Application 原始方法
protected void attachBaseContext(Context base) {
    // ← 第一次回调：hasCalledSuper = false
    super.attachBaseContext(base);
    // ← 第二次回调：hasCalledSuper = true
    // 应用自定义逻辑
}

实际应用：

attachBaseContext { baseContext, hasCalledSuper ->
    if (hasCalledSuper) {
        // Context 已初始化完成
        val apkPath = baseContext.applicationInfo.sourceDir
        YLog.debug(msg = "APK 路径: $apkPath")
        
        // 初始化 DexKit
        initDexKit(apkPath)
    }
}

2.4 onCreate 详解

onCreate {
    YLog.debug(msg = "onCreate: $this")
}

特点：

  • 通过 this 获取 Application 实例
  • 此时应用已完全初始化
  • 最常用的 Hook 时机

实际应用：

onCreate {
    val app = this as Application
    YLog.debug(msg = "包名: ${app.packageName}")
    YLog.debug(msg = "版本: ${app.packageManager.getPackageInfo(app.packageName, 0).versionName}")

}

2.5 onTrimMemory 详解

onTrimMemory { self, level ->
    if (level == ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN) {
        YLog.debug(msg = "onTrimMemory: TRIM_MEMORY_UI_HIDDEN: $level")
    }
    YLog.debug(msg = "onTrimMemory: $level")
}

内存级别对照表：

常量值含义应对策略
TRIM_MEMORY_UI_HIDDEN20UI 隐藏（切到后台）暂停非关键 Hook
TRIM_MEMORY_RUNNING_MODERATE5运行中，内存适中继续正常运行
TRIM_MEMORY_RUNNING_LOW10运行中，内存较低释放部分缓存
TRIM_MEMORY_RUNNING_CRITICAL15运行中，内存严重不足释放所有缓存
TRIM_MEMORY_BACKGROUND40在后台，可能被回收保存状态
TRIM_MEMORY_COMPLETE80在后台，优先回收清理所有资源

判断应用是否切到后台：

var isInBackground = false

onTrimMemory { self, level ->
    when (level) {
        ComponentCallbacks2.TRIM_MEMORY_UI_HIDDEN -> {
            isInBackground = true
            YLog.debug(msg = "用户离开应用")
        }
    }
}

onConfigurationChanged { self, config ->
    YLog.debug(msg = "onConfigurationChanged: $config")

Configuration 包含的信息：

  • 屏幕方向（横屏 / 竖屏）
  • 屏幕尺寸和密度
  • 语言和地区
  • 夜间模式

实际应用：

onConfigurationChanged { self, config ->

工作原理：

模块进程                        宿主应用进程
    ↓                              ↓
dataChannel.put()           dataChannel.wait()
    ↓                              ↓
    通过 ContentProvider 传输
    ↓                              ↓
发送成功                      触发回调

4.3 DataChannel vs SharedPreferences

特性DataChannelSharedPreferences
实时性高（主动推送）低（需要轮询）
数据类型丰富（任意 Serializable）有限（基本类型）
生命周期临时（内存中）持久（文件存储）
适用场景实时控制、事件通知配置存储、状态保存

第五部分：DexKit 混淆类查找

5.1 示例代码

loadApp(name = "com.zilo.challenge") {
    DexKitBridge.create(appInfo.sourceDir).use {
        // 通过方法签名查找类
        val classData = it.findClass {
            excludePackages(
                "androidx.constraintlayout",
                "com.google.common.primitives",
                "org.bouncycastle.crypto"
            )
            matcher {
                methods {
                    add {
                        paramTypes("int", "int")
                    }
                    add {
                        paramTypes("int", "int", "int")
                    }
                    add {
                        paramTypes("int", "int", "int", "int", "int", "int")
                    }
                }
            }
        }.singleOrNull() ?: error("This returned result is null or not unique")
        
        YLog.debug(msg = "class name: ${classData.name}", tag = tag)
        
        // 查找类中的特定方法
        val signMethod = classData.findMethod {
            matcher {
                paramTypes("byte[]")
                returnType = "java.lang.String"
            }
        }.singleOrNull() ?: error("This returned result is null or not unique")
        
        YLog.debug(msg = "method name: ${signMethod.name}", tag = tag)
        
        // Hook 找到的方法
        classData.name.toClass()
            .resolve()
            .firstMethod {
                name = signMethod.name
                parameters(ByteArray::class)
                returnType = String::class
            }.hook {
                after {
                    YLog.debug(msg = "参数: ${args[0]}", tag = tag)
                    YLog.debug(msg = "返回值: $result", tag = tag)
                }
            }
    }
}

5.2 查找策略解析

排除无关包

excludePackages(
    "androidx.constraintlayout",
    "com.google.common.primitives",
    "org.bouncycastle.crypto"
)

作用：

  • 提高查找速度（减少扫描范围）
  • 避免误匹配系统库或第三方库
  • 降低内存消耗

方法签名匹配

matcher {
    methods {
        add { paramTypes("int", "int") }
        add { paramTypes("int", "int", "int") }
        add { paramTypes("int", "int", "int", "int", "int", "int") }
    }
}

匹配逻辑：

  • 查找同时包含这三个方法签名的类
  • 这是一种强特征匹配，精准度高
  • 适用于加密、签名等工具类

为什么选择这些签名？

这些方法签名通常对应：

  • encrypt(int key, int mode) - 加密方法
  • sign(int userId, int timestamp, int nonce) - 签名方法
  • generateToken(int a, int b, int c, int d, int e, int f) - 生成令牌

5.3 查找特定方法

val signMethod = classData.findMethod {
    matcher {
        paramTypes("byte[]")
        returnType = "java.lang.String"
    }
}.singleOrNull() ?: error("This returned result is null or not unique")

特征：

  • 参数： byte[] （字节数组，通常是待签名数据）
  • 返回： String （签名结果，通常是 Base64 或十六进制）

典型应用场景：

// 目标方法示例
fun sign(data: ByteArray): String {
    // 对数据进行签名
    return Base64.encodeToString(...)
}

5.4 动态 Hook 找到的方法

classData.name.toClass()
    .resolve()
    .firstMethod {
        name = signMethod.name
        parameters(ByteArray::class)
        returnType = String::class
    }.hook {
        after {
            YLog.debug(msg = "参数: ${args[0]}", tag = tag)
            YLog.debug(msg = "返回值: $result", tag = tag)
        }
    }

关键技术点：

  1. toClass()：将类名字符串转换为 Class 对象
  2. resolve()：KavaRef 的反射辅助方法
  3. firstMethod{}：YukiHookAPI 的方法查找 DSL
  4. hook{}：执行 Hook 操作

Activity::class.resolve().firstMethod {
    name = "onCreate"

6.3 before vs after

.hook {
    before {
        // 在原方法执行前
        // 可以修改参数、阻止方法执行
        throw Exception("阻止方法执行")
    }
    after {
        // 在原方法执行后
        // 可以修改返回值、读取结果
        YLog.debug(msg = "方法执行完成")
    }
}

注意事项：

  • before 中抛出异常会阻止原方法执行
  • after 中抛出异常不影响原方法，但会传递给调用方
  • 两者可以同时使用

第七部分：错误处理机制

7.1 完整的错误处理链

Activity::class.resolve().firstMethod {
    name = "onCreate"
    parameters(Bundle::class)
}.hook {
    after {
        YLog.debug(msg = "hook onCreate success", tag = tag)
    }
}.result {
    onHookingFailure {
        YLog.debug(msg = "onHookingFailure: $it", tag = tag)
    }
    onConductFailure { param, throwable ->
        YLog.debug(msg = "onConductFailure: $throwable", tag = tag)
        param.throwable
    }
    onAllFailure {
        YLog.debug(msg = "onAllFailure: $it", tag = tag)
    }
}

7.2 三种失败类型

onHookingFailure

触发时机：Hook 注入失败

常见原因：

  • 目标方法不存在
  • 参数类型不匹配
  • 类加载器问题

示例：

.result {
    onHookingFailure {
        YLog.error(msg = "Hook 失败: $it")
        // 尝试降级方案
        tryAlternativeMethod()
    }
}

onConductFailure

触发时机：Hook 代码执行时抛出异常

常见原因：

  • before / after 代码逻辑错误
  • 空指针异常
  • 类型转换失败

示例：

.result {
    onConductFailure { param, throwable ->
        YLog.error(msg = "执行失败: ${throwable.message}")
        
        // 决定是否向外抛出异常
        if (throwable is NullPointerException) {
            // 吞掉空指针异常
            null
        } else {
            // 向外抛出
            param.throwable
        }
    }
}

onAllFailure

触发时机：任何类型的失败

作用：统一处理所有错误

示例：

.result {
    onAllFailure {
        YLog.error(msg = "Hook 失败（统一处理）: $it")
        reportToAnalytics(it)
    }
}

7.3 错误处理最佳实践

实践 1：渐进式降级

// 尝试 Hook 方法 A
"MethodA".toMethod().hook {
    after { /* ... */ }
}.result {
    onHookingFailure {
        // 失败后尝试 Hook 方法 B
        "MethodB".toMethod().hook {
            after { /* ... */ }
        }.result {
            onHookingFailure {
                YLog.error(msg = "所有方法都失败")
            }
        }
    }
}

实践 2：安全的类型转换

.hook {
    after {
        val result = this.result
        when (result) {
            is String -> YLog.debug(msg = "字符串: $result")
            is Int -> YLog.debug(msg = "整数: $result")
            else -> YLog.debug(msg = "未知类型: ${result?.javaClass}")
        }
    }
}

实践 3：异常日志详细记录

.result {
    onConductFailure { param, throwable ->
        YLog.error(msg = """
            执行失败详情:
            - 方法: ${param.member.name}
            - 异常类型: ${throwable.javaClass.simpleName}
            - 异常消息: ${throwable.message}
            - 堆栈: ${throwable.stackTraceToString()}
        """.trimIndent())
        param.throwable
    }
}

isModuleActiveBoolean模块是否激活
Executor.nameString框架名称（LSPosed/EdXposed）
Executor.apiLevelInt框架 API 级别
isTaiChiModuleActiveBoolean是否在太极中激活

8.3 实际应用

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    
    if (!YukiHookAPI.Status.isModuleActive) {
        // 显示未激活提示
        showNotActiveDialog()
    } else {
        // 显示正常界面
        showNormalUI()
    }
}

第十一部分：常见问题与解决方案

Q1：模块未激活怎么办？

检查步骤：

  1. 确认 LSPosed 已安装

    adb shell su -c "ls /data/adb/modules/"

  2. 确认模块已勾选

    • 打开 LSPosed 管理器
    • 找到你的模块
    • 勾选目标应用

  3. 重启目标应用

    adb shell am force-stop com.zilo.challenge
adb shell am start com.zilo.challenge/.MainActivity

  4. 查看模块状态

    YukiHookAPI.Status.isModuleActive  // 应返回 true

Q2：DexKit 查找返回 null？

可能原因：

  1. 特征不够精准

    // ❌ 特征太宽泛
it.findClass {
    matcher {
        methods {
            add { paramTypes("java.lang.String") }
        }
    }
}

// ✅ 增加多个特征
it.findClass {
    excludePackages("androidx", "com.google")
    matcher {
        methods {
            add { paramTypes("int", "int") }
            add { paramTypes("byte[]") }
        }
        fields {
            add { type = "android.content.Context" }
        }
    }
}

  2. 包名被排除

    • 检查 excludePackages 是否过滤了目标类
    • 减少排除范围

  3. 目标类根本不存在

    • 使用 jadx 反编译 APK 确认
    • 检查方法签名是否正确

Q3：Hook 后应用崩溃？

调试方法：

  1. 查看崩溃日志

    adb logcat | grep -E "FATAL|AndroidRuntime"

  2. 使用错误处理

    .hook {
    after {
        try {
            // 你的代码
        } catch (e: Exception) {
            YLog.error(msg = "错误: ${e.message}")
        }
    }
}

  3. 检查类型转换

    // ❌ 危险的转换
val result = this.result as String

// ✅ 安全的转换
val result = this.result?.toString() ?: "default"

Q4：SharedPreferences 读取不到？

检查清单：

  1. Provider 是否配置

    • 查看 AndroidManifest.xml
    • 确认 multiprocess="true"

  2. 名称是否一致

    // 模块侧
prefs(name = "zilo_prefs")

// 宿主侧
prefs(name = "zilo_prefs")  // 必须相同

  3. 权限问题

    <provider
    android:exported="true"  <!-- 必须为 true -->
    android:multiprocess="true" />

Q5：DataChannel 接收不到数据？

调试步骤：

  1. 确认监听已注册

    dataChannel.wait<String>(key = "zilo_config") {
    YLog.debug(msg = "收到: $it")
}

  2. 发送测试数据

    dataChannel(packageName = "com.zilo.challenge").put(
    key = "zilo_config",
    value = "test"
)

  3. 检查包名是否正确

    • 使用 adb shell pm list packages 确认包名
