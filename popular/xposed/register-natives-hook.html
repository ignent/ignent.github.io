LSPosed Native Hook：监控 JNI 动态注册

ZIP2026/6/14...大约 10 分钟XposedLSPosedNative HookJNIRegisterNatives

方案概述

在 Android 逆向中，很多应用为了增加分析难度，不使用静态的 Java_ 命名规则来导出 JNI 函数，而是通过 动态注册（ RegisterNatives ）的方式绑定 Java 方法和 Native 函数。这使得静态分析工具（如 IDA）无法直接从导出函数名看出 Java 方法对应的 Native 实现。

本文介绍如何通过 Hook Android Runtime 的 RegisterNatives 函数，实时监控所有 Native 方法的动态注册过程，获取：

  • Java 类名和方法名
  • 方法签名
  • Native 函数指针
  • 函数所在的 .so 模块
  • 函数在模块中的偏移地址

JNI 方法注册方式对比

静态注册（常规方式）

// Java 层
public class MainActivity {
    public native String getEncryptedData();
}
// Native 层 - 函数名固定，可直接在 IDA 中搜索
extern "C" JNIEXPORT jstring JNICALL
Java_com_example_MainActivity_getEncryptedData(JNIEnv *env, jobject thiz) {
    return env->NewStringUTF("encrypted");
}

特点：函数名遵循 Java_包名_类名_方法名 规则，导出符号可见。

动态注册（反静态分析）

// Java 层 - 相同
public class MainActivity {
    public native String getEncryptedData();
}
// Native 层 - 函数名任意，不可见
static jstring my_custom_func(JNIEnv *env, jobject thiz) {
    return env->NewStringUTF("encrypted");
}

// JNI_OnLoad 中动态绑定
jint JNI_OnLoad(JavaVM *vm, void *reserved) {
    JNIEnv *env;
    vm->GetEnv((void **)&env, JNI_VERSION_1_6);
    
    jclass clazz = env->FindClass("com/example/MainActivity");
    JNINativeMethod methods[] = {
        {"getEncryptedData", "()Ljava/lang/String;", (void *)my_custom_func}
    };
    env->RegisterNatives(clazz, methods, 1); // 动态注册
    return JNI_VERSION_1_6;
}

特点：函数名任意，不导出符号，静态分析无法直接关联。

2. 创建 Native 初始化接口

3. 在 Xposed 入口调用初始化

文件路径： app/src/main/java/com/xposed/HookEntry.java

public class HookEntry implements IXposedHookLoadPackage, IXposedHookZygoteInit {
    
    @Override
    public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) throws Throwable {
        System.loadLibrary("xposed");  // 加载 Native 模块
        NativeLib.initNative();        // 初始化 RegisterNatives Hook
    }
    
    @Override
    public void initZygote(StartupParam startupParam) throws Throwable {
        // Zygote 初始化逻辑
    }
}

调用时机：

  • handleLoadPackage 在目标应用进程启动时被调用
  • 此时目标应用的 .so 库可能还未加载
  • Hook 会在 RegisterNatives 被调用时生效（通常在 JNI_OnLoad 中）

4. 实现 Native Hook 逻辑

文件路径： app/src/main/cpp/native-lib.cpp

4.1 定义全局变量和工具函数

#include <jni.h>
#include <android/log.h>
#include <string>
#include <dlfcn.h>
#include "include/dobby.h"
#include "xdl.h"

// 保存原始 RegisterNatives 函数指针
jint (*original_RegisterNatives)(JNIEnv *, jclass, const JNINativeMethod *, jint);

// 缓存 Class.getName() 方法 ID
static jmethodID class_getName_method = nullptr;

4.2 获取类名

std::string get_class_name(JNIEnv *env, jclass clazz) {
    // 首次调用时查找 getName 方法
    if (!class_getName_method) {
        jclass jclazz = env->FindClass("java/lang/Class");
        class_getName_method = env->GetMethodID(jclazz, "getName", "()Ljava/lang/String;");
        env->DeleteLocalRef(jclazz);
    }
    
    // 调用 Class.getName() 获取类名
    jstring name_jstr = (jstring) env->CallObjectMethod(clazz, class_getName_method);
    if (!name_jstr) {
        return "Unknown";
    }
    
    const char *name_str = env->GetStringUTFChars(name_jstr, nullptr);
    std::string result(name_str);
    env->ReleaseStringUTFChars(name_jstr, name_str);
    env->DeleteLocalRef(name_jstr);
    
    return result;
}

原理说明：

  • jclass 是一个 Java 的 Class 对象引用
  • 通过反射调用 Class.getName() 方法获取类的全限定名
  • 结果格式： com.example.MainActivity

4.3 获取模块信息

std::pair<std::string, uintptr_t> get_module_info(void *address) {
    Dl_info info;
    if (dladdr(address, &info)) {
        return {info.dli_fname, reinterpret_cast<uintptr_t>(info.dli_fbase)};
    }
    return {"", 0};
}

dladdr 函数说明：

  • 通过地址查询其所属的动态库信息
  • dli_fname ：模块路径（如 /data/app/.../lib/arm64/libxxx.so ）
  • dli_fbase ：模块加载的基地址

返回值：

  • first ：模块路径
  • second ：模块基地址（用于计算偏移）

4.4 Hook RegisterNatives 函数

jint hook_RegisterNatives(JNIEnv *env, jclass clazz, 
                          const JNINativeMethod *methods, jint nMethods) {
    // 获取注册的 Java 类名
    std::string class_name = get_class_name(env, clazz);
    __android_log_print(ANDROID_LOG_INFO, "0X->", "RegisterNatives: %s", class_name.c_str());
    
    // 遍历所有注册的方法
    for (int i = 0; i < nMethods; ++i) {
        const auto &method = methods[i];
        
        // 获取函数指针所属的模块信息
        auto [module_name, module_address] = get_module_info((void *)method.fnPtr);
        
        // 构建日志信息
        std::string log_str = "name: " + std::string(method.name) +
                              ", signature: " + std::string(method.signature) +
                              ", fnPtr: " + std::to_string((uintptr_t)method.fnPtr) +
                              ", module: " + module_name;
        
        // 计算偏移量（地址 - 基地址）
        if (module_address) {
            uintptr_t offset = (uintptr_t)method.fnPtr - module_address;
            log_str += ", offset: 0x" + std::to_string(offset);
        }
        
        __android_log_print(ANDROID_LOG_INFO, "0X->", "%s", log_str.c_str());
    }
    
    // 调用原始 RegisterNatives，让注册正常进行
    return original_RegisterNatives(env, clazz, methods, nMethods);
}

关键数据结构 JNINativeMethod：

typedef struct {
    const char *name;       // Java 方法名
    const char *signature;  // 方法签名（参数和返回值类型）
    void *fnPtr;            // Native 函数指针
} JNINativeMethod;

输出示例：

RegisterNatives: com.example.CryptoHelper
name: encrypt, signature: ([B)[B, fnPtr: 140234567890, module: /data/app/.../libcrypto.so, offset: 0x1234
name: decrypt, signature: ([B)[B, fnPtr: 140234568000, module: /data/app/.../libcrypto.so, offset: 0x1290

4.5 查找并 Hook RegisterNatives

void *find_symbol(void *handle, const char *sym_name) {
    // 先尝试从动态符号表查找
    void *addr = xdl_sym(handle, sym_name, nullptr);
    if (addr == nullptr) {
        // 如果找不到，尝试从调试符号表查找
        addr = xdl_dsym(handle, sym_name, nullptr);
    }
    return addr;
}

extern "C"
JNIEXPORT void JNICALL
Java_com_xposed_NativeLib_initNative(JNIEnv *env, jclass clazz) {
    // 打开 libart.so（Android Runtime 库）
    void *handle = xdl_open("libart.so", XDL_DEFAULT);
    
    // RegisterNatives 有两个重载版本（模板参数不同）
    // 版本1：JNI<true>::RegisterNatives
    const char *symbol1 = "_ZN3art3JNIILb1EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi";
    void *addr1 = find_symbol(handle, symbol1);
    
    if (addr1) {
        __android_log_print(ANDROID_LOG_INFO, "0X->", "Found RegisterNatives<true>: %p", addr1);
        DobbyHook(addr1, (void *)hook_RegisterNatives, (void **)&original_RegisterNatives);
    }
    
    // 版本2：JNI<false>::RegisterNatives
    const char *symbol2 = "_ZN3art3JNIILb0EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi";
    void *addr2 = find_symbol(handle, symbol2);
    
    if (addr2) {
        __android_log_print(ANDROID_LOG_INFO, "0X->", "Found RegisterNatives<false>: %p", addr2);
        DobbyHook(addr2, (void *)hook_RegisterNatives, (void **)&original_RegisterNatives);
    }
}

符号名解析：

_ZN3art3JNIILb1EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi

使用 c++filt 解析：

c++filt _ZN3art3JNIILb1EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi
# 输出：art::JNI<true>::RegisterNatives(_JNIEnv*, _jclass*, JNINativeMethod const*, int)

为什么有两个版本：

  • JNI<true> ：带检查的版本（常用）
  • JNI<false> ：无检查的版本（性能优化）
  • 两个都 Hook 可以确保覆盖所有调用

5. LSPosed 框架集成

文件路径： app/src/main/cpp/native-lib.cpp （补充）

// LSPosed 提供的 Hook 函数（可选，用于 Hook 其他函数）
static HookFunType hook_func = nullptr;

// LSPosed 动态库加载回调
void on_library_loaded(const char *name, void *handle) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded: %s", name);
    
    // 可以在这里监听特定 .so 加载后进行其他 Hook
    // 例如：if (std::string(name).ends_with("libxxx.so")) { ... }
}

// LSPosed 初始化入口
extern "C" [[gnu::visibility("default")]] [[gnu::used]]
NativeOnModuleLoaded native_init(const NativeAPIEntries *entries) {
    hook_func = entries->hook_func;
    return on_library_loaded;
}

// JNI_OnLoad（标准 JNI 入口）
extern "C" [[gnu::visibility("default")]] [[gnu::used]]
jint JNI_OnLoad(JavaVM *jvm, void *) {
    return JNI_VERSION_1_6;
}

两个入口说明：

  • JNI_OnLoad ：标准 JNI 库加载入口
  • native_init ：LSPosed 框架特定入口，返回动态库加载回调

技术要点

1. C++ 名称修饰（Name Mangling）

C++ 编译器会对函数名进行修饰以支持重载和命名空间：

// 源代码
namespace art {
    template<bool kEnableIndexIds>
    class JNI {
        static jint RegisterNatives(JNIEnv* env, jclass c, 
                                    const JNINativeMethod* methods, jint nMethods);
    };
}

// 编译后的符号（Mangled Name）
_ZN3art3JNIILb1EE15RegisterNativesEP7_JNIEnvP7_jclassPK15JNINativeMethodi

查找符号的方法：

  1. 使用 readelf -s libart.so | grep RegisterNatives 查找
  2. 使用 nm -D libart.so | grep RegisterNatives 查找
  3. 使用 IDA 打开 libart.so，搜索 RegisterNatives

2. xDL vs dlsym

特性dlsymxdl_sym / xdl_dsym
查找导出符号✅✅
查找未导出符号❌✅
查找静态库符号❌✅
性能快稍慢（完整扫描）

xdl_sym：查找动态符号表（ .dynsym ）
xdl_dsym：查找调试符号表（ .symtab ，可能被 strip）

3. JNI 方法签名

方法签名用于描述参数和返回值类型：

Java 类型签名示例
voidV()V
booleanZ(Z)V
byteB([B)[B
intI(II)I
longJ(J)J
StringLjava/lang/String;(Ljava/lang/String;)Ljava/lang/String;
byte[][B([B)[B
Object[][Ljava/lang/Object;([Ljava/lang/Object;)V

示例：

public String encrypt(String data, int key) { ... }

签名： (Ljava/lang/String;I)Ljava/lang/String;

4. 偏移量计算

函数偏移 = 函数地址 - 模块基地址

为什么需要偏移：

  • 模块每次加载的基地址可能不同（ASLR）
  • 偏移量是固定的，可以在 IDA 中直接定位
  • 其他设备上可以通过 基地址 + 偏移 复现

常见问题

1. 找不到 RegisterNatives 符号

原因：

  • Android 版本不同，符号名可能不同
  • libart.so 被 strip，符号表被移除

解决方案：

# 从设备提取 libart.so
adb pull /apex/com.android.art/lib64/libart.so

# 查找 RegisterNatives 的符号
readelf -s libart.so | grep RegisterNatives

# 或者使用 IDA 打开，在 Exports 中搜索

2. Hook 后应用崩溃

可能原因：

  • Hook 函数的签名与原函数不匹配
  • 未正确调用原始函数
  • 在 Hook 函数中使用了不安全的 JNI 操作

调试方法：

# 查看崩溃日志
adb logcat | grep "FATAL"

# 查看 tombstone
adb shell ls /data/tombstones/
adb pull /data/tombstones/tombstone_xx

3. 日志中没有输出

检查项：

  1. LSPosed 模块是否正确启用
  2. 目标应用是否勾选
  3. 目标应用是否重启
  4. 目标应用是否真的使用了动态注册（有些应用只用静态注册）

验证方法：

# 确认模块已加载
adb logcat | grep "LSPosed"

# 确认 initNative 被调用
adb logcat | grep "initNative"

2. 过滤特定类或方法

jint hook_RegisterNatives(JNIEnv *env, jclass clazz, 
                          const JNINativeMethod *methods, jint nMethods) {
    std::string class_name = get_class_name(env, clazz);
    
    // 只监控特定类
    if (class_name.find("CryptoHelper") != std::string::npos) {
        // 处理逻辑
    }
    
    // 只监控特定方法

            // 处理逻辑
        }
    }

3. 动态修改注册信息

jint hook_RegisterNatives(JNIEnv *env, jclass clazz, 
                          const JNINativeMethod *methods, jint nMethods) {
    // 复制方法数组
    JNINativeMethod *new_methods = new JNINativeMethod[nMethods];
    memcpy(new_methods, methods, sizeof(JNINativeMethod) * nMethods);
    
    // 修改特定方法的实现
    for (int i = 0; i < nMethods; ++i) {
        if (std::string(new_methods[i].name) == "encrypt") {
            new_methods[i].fnPtr = (void *)my_encrypt_impl;  // 替换实现
        }
    }
    
    // 使用修改后的数组进行注册
    jint result = original_RegisterNatives(env, clazz, new_methods, nMethods);
    delete[] new_methods;
    return result;
}

总结

通过 Hook RegisterNatives 函数，我们可以：

  1. 监控所有动态注册的 Native 方法，突破静态分析的限制
  2. 获取函数的精确地址和模块偏移，为后续 Hook 提供目标
  3. 理解 Java 方法和 Native 实现的对应关系，加速逆向分析

这个技术是 Native 层逆向的重要基础，结合之前的 JNI Hook 和 Dobby Hook 技术，可以构建完整的 Native 层分析和 Hook 方案。
