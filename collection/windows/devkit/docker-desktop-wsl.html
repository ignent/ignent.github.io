Docker Desktop + WSL

ZIP2026/7/3...大约 3 分钟

一、适用场景

目标环境：

  • Windows 安装 Docker Desktop

  • Docker Desktop 使用 WSL 2 backend

  • WSL 发行版使用 Debian

  • Windows 侧执行 docker.exe

  • WSL 侧执行 docker

  • 两边都连接到 Docker Desktop 这一套引擎

  • WSL 里不要再安装发行版自带的 Docker Engine / Docker CLI 套件

二、Windows 安装

1. 开启 WSL2

管理员 PowerShell 执行：

dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
wsl --update
wsl --set-default-version 2

如果系统提示重启，先重启。

2. 安装 Debian

如果还没有 Debian：

wsl --install -d Debian

如果已经装好了多个发行版，建议把 Debian 设成默认：

wsl --set-default Debian

3. 安装 Docker Desktop

推荐直接用 winget ：

winget install -e --id Docker.DockerDesktop

也可以手动下载 Docker Desktop 安装包后双击安装。

安装完成后启动 Docker Desktop，等待初始化完成。

4. 配置 Docker Desktop

打开 Docker Desktop，确认下面几项：

  • Settings -> General -> Use the WSL 2 based engine
  • Settings -> Resources -> WSL Integration -> Enable integration with my default WSL distro
  • Settings -> Resources -> WSL Integration -> Debian

如果你希望 Windows 开机后自动可用，再打开：

  • Settings -> General -> Start Docker Desktop when you sign in

5. 让 Desktop 接管 WSL

Windows PowerShell 执行：

wsl --shutdown

然后重新打开 Docker Desktop，再重新进入 Debian。

三、WSL 安装

1. 首次进入 Debian

在 Windows Terminal、PowerShell 或 CMD 执行：

wsl -d Debian

首次进入时按提示创建 Linux 用户名和密码。

2. 不要在 Debian 里安装 Docker

当前方案里，WSL 侧不要执行下面这类安装命令：

sudo apt install docker.io
sudo apt install docker-cli
sudo apt install containerd
sudo apt install docker-compose

原因：

  • docker.io 、 containerd 会在 Debian 里装出一套本地引擎
  • docker-cli 也是发行版自己的客户端
  • 这和 Docker Desktop 的 WSL 集成是两套方案，混用后很容易出现双引擎冲突

在 Docker Desktop 的 WSL 集成方案里， docker 命令应由 Docker Desktop 提供，而不是由 Debian 包管理器再装一份。

3. 如果以前装过本地 Docker，先卸掉

如果这台 Debian 以前装过 Docker 相关包，先清理掉。WSL 内执行：

sudo apt purge -y docker.io docker-cli docker-buildx docker-compose containerd
sudo apt autoremove -y

如果 purge 前本地服务还在运行，再执行一次：

sudo systemctl stop docker docker.socket containerd
sudo systemctl disable docker docker.socket containerd

然后回到 Windows PowerShell：

wsl --shutdown

再重新启动 Docker Desktop，并重新进入 Debian。

4. 让当前用户具备访问 Docker socket 的权限

如果进入 Debian 后执行 docker 出现 permission denied ，在 WSL 里执行：

getent group docker >/dev/null || sudo groupadd docker
sudo usermod -aG docker $USER
newgrp docker

如果当前 shell 没生效，就退出终端后重新进入一次 WSL。

5. WSL 侧状态

  • Debian 里没有常驻的本地 dockerd
  • Debian 里不再通过 apt 维护 Docker Engine/CLI 套件
  • 进入 Debian 后， docker 命令直接连到 Docker Desktop

四、最终状态

装完以后，环境应当是这样：

  • Windows 上的 Docker Engine 来自 Docker Desktop
  • WSL Debian 里只有 docker 命令行客户端
  • Windows 和 WSL 共用一套容器、镜像、网络、volume

关系如下：

Windows docker.exe  --->  Docker Desktop
WSL Debian docker   --->  Docker Desktop

五、安装顺序

如果按顺序做，步骤应该是：

  1. 在 Windows 开启 WSL2
  2. 在 Windows 安装 Debian
  3. 在 Windows 安装 Docker Desktop
  4. 在 Docker Desktop 打开 WSL 2 based engine 和 Debian 集成
  5. 在 WSL 里清理旧的 docker.io / docker-cli / containerd
  6. 在 Windows 执行 wsl --shutdown
  7. 重新打开 Docker Desktop
  8. 重新进入 Debian，必要时把用户加入 docker 组

六、检查命令

Windows

docker.exe version
docker.exe context ls
wsl -l -v

WSL

docker version
docker info
docker ps

只要 WSL 里 docker version 的 Server 显示 Docker Desktop ，说明安装方向是对的。
