LSPlant Hook与UnHook状态管理

ZIP2026/6/25...大约 33 分钟XposedLSPlantARTJNIHookUnHook

LSPlant 源码阅读：Hook 执行、状态管理与 UnHook 恢复

概述

前两篇已经读过 LSPlant 的工程构建、 InitConfig 、 InitJNI 和 InitNative 。本文继续往下走，只关注真正改变 Java 方法行为的这一条链路：

Hook 前期准备与验证
  -> Hook 执行与状态管理
  -> UnHook 验证与状态查找
  -> 状态清理与 UnHook 执行

读完本文后，读者应该能在 LSPlant 源码里回答四个问题：

  1. Hook() 为什么要求 target_method 和 callback_method 都是 Java 反射里的 Executable ？
  2. LSPlant 为什么要动态生成一个 Dex stub，而不是直接把 target 指向用户写的 Java 方法？
  3. hooked_methods_ 、 hooked_classes_ 、 jit_movements_ 这些状态表分别解决什么问题？
  4. UnHook() 怎样找到 backup、恢复 ArtMethod ，以及为什么 UnHook 后不能继续调用 backup？

本文的可复现运行效果是：

Hook 前：目标方法返回原始结果
Hook 后：目标方法进入 Replacement，返回替换结果
Hook 后：backup.invoke(...) 仍能执行原始逻辑
UnHook 后：目标方法恢复原始结果

以 LSPlant 自带测试为例， t02_normalMethod 的行为可以概括成：

test.normalMethod("test", 114514, 1919810)

Hook 后：
  "test1145141919810replace"

backup.invoke(test, "test", 114514, 1919810)
  "test1145141919810"

UnHook 后：
  "test1145141919810"

注意

LSPlant 操作的是 ART 内部 ArtMethod 、entrypoint、JIT code cache、 libart.so 私有符号和动态生成 Dex。这些都不是 Android SDK 稳定公开接口。不同 Android 版本、厂商 ROM、ABI、编译器、JIT 策略都可能影响行为。本文适合源码阅读和实验复现，不建议把内部偏移、符号名或状态表设计直接跨版本套用到生产环境。

对外 API：Hook/UnHook 的契约

文件： lsplant/src/main/jni/include/lsplant.hpp

/// Hook 一个 Java 方法。
///
/// target_method:
///   要被 Hook 的 Java 反射对象，通常是 Method 或 Constructor。
///
/// hooker_object:
///   用户侧上下文对象。LSPlant 生成的 stub 会持有它，
///   之后每次进入 target 时，都会调用 hooker_object 上的 callback_method。
///
/// callback_method:
///   hooker_object 所属类里的回调方法。
///   签名必须是：
///     public Object callback_method(Object[] args)
///
/// 返回值:
///   返回 backup Method。通过反射调用 backup 可以执行原始逻辑。
///   返回 null 表示 Hook 失败。
///
/// 注意:
///   - 对同一个 target_method 并发 Hook 不是原子操作。
///   - backup 的 jmethodID 获取行为未定义。
///   - Hook 前必须成功调用 Init()。
[[nodiscard, maybe_unused, gnu::visibility("default")]]
jobject Hook(JNIEnv *env,
             jobject target_method,
             jobject hooker_object,
             jobject callback_method);

/// 取消 Hook。
///
/// target_method:
///   之前传给 Hook() 的同一个目标方法反射对象。
///
/// 返回值:
///   true 表示恢复成功，false 表示目标未 Hook 或恢复失败。
///
/// 注意:
///   UnHook 后继续调用 Hook() 返回的 backup 属于未定义行为。
[[nodiscard, maybe_unused, gnu::visibility("default")]]
bool UnHook(JNIEnv *env, jobject target_method);

/// 查询某个 Java 方法是否已被 LSPlant Hook。
[[nodiscard, maybe_unused, gnu::visibility("default")]]
bool IsHooked(JNIEnv *env, jobject method);

这里最重要的是 callback_method 的签名约束：它必须接收 Object[] 并返回 Object 。LSPlant 之所以这样设计，是因为动态生成的 Dex stub 会把目标方法的参数统一装箱到 Object[] ，再转发给用户的 Java 回调。

Java 层包装：保存 target、backup、replacement

文件： test/src/main/java/org/lsposed/lsplant/Hooker.java

package org.lsposed.lsplant;

import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Member;
import java.lang.reflect.Method;

public class Hooker {

    /**
     * 传给 Replacement 的上下文。
     *
     * backup:
     *   LSPlant::Hook 返回的备份 Method，用来调用原始逻辑。
     *
     * args:
     *   LSPlant 动态 stub 收集到的参数数组。
     *   对实例方法和构造器来说，args[0] 是 this；
     *   对静态方法来说，不会插入 null this 占位。
     */
    static class MethodCallback {
        Method backup;
        Object[] args;

        MethodCallback(Method backup, Object[] args) {
            this.backup = backup;
            this.args = args;
        }
    }

    // Hook 成功后由 native 返回并保存。
    // Replacement 可以通过它调用原始方法。
    public Method backup;

    // 被 Hook 的目标 Method 或 Constructor。
    private Member target;

    // 用户真正写的替换逻辑。
    private Method replacement;

    // replacement 所属对象。静态 replacement 可以为 null。
    private Object owner = null;

    private Hooker() {
    }

    // JNI 桥：最终调用 lsplant::Hook(env, original, this, callback)。
    private native Method doHook(Member original, Method callback);

    // JNI 桥：最终调用 lsplant::UnHook(env, target)。
    private native boolean doUnhook(Member target);

    /**
     * 这是传给 LSPlant 的统一回调入口。
     *
     * LSPlant 生成的 Dex stub 会调用此方法。
     * 该方法再把 backup 和 args 组装成 MethodCallback，
     * 最后反射调用用户写的 replacement。
     */
    public Object callback(Object[] args)
            throws InvocationTargetException, IllegalAccessException {
        var methodCallback = new MethodCallback(backup, args);
        return replacement.invoke(owner, methodCallback);
    }

    /**
     * 对 Java 调用者暴露的取消 Hook 方法。
     */
    public boolean unhook() {
        return doUnhook(target);
    }

    /**
     * 创建 Hooker，并完成 Hook。
     *
     * target:
     *   要 Hook 的 Method 或 Constructor。
     *
     * replacement:
     *   用户替换逻辑，签名形如：
     *     Object replacement(Hooker.MethodCallback callback)
     *
     * owner:
     *   replacement 的接收者对象；静态方法可传 null。
     */
    public static Hooker hook(Member target, Method replacement, Object owner) {
        Hooker hooker = new Hooker();
        try {
            // LSPlant 要求 callback_method 签名是 Object callback(Object[] args)。
            var callbackMethod = Hooker.class.getDeclaredMethod(
                    "callback",
                    Object[].class
            );

            // 进入 native Hook。
            var result = hooker.doHook(target, callbackMethod);
            if (result == null) return null;

            // 保存 native 返回的 backup，后续 callback 中可以调用原始逻辑。
            hooker.backup = result;
            hooker.target = target;
            hooker.replacement = replacement;
            hooker.owner = owner;
        } catch (NoSuchMethodException ignored) {
        }
        return hooker;
    }
}

这层包装看起来很薄，但它解释了 LSPlant 的典型用法：

  • Java 侧保留 Hooker 对象，避免 hooker_object 被 GC。
  • Hooker.backup 保存原始方法入口。
  • Hooker.callback() 是 LSPlant 生成 stub 的固定目标。
  • 真正的业务替换逻辑放在 Replacement 中，便于测试不同方法形态。

替换逻辑：静态方法、普通方法、构造器

文件： test/src/main/java/org/lsposed/lsplant/Replacement.java

package org.lsposed.lsplant;

import java.lang.reflect.InvocationTargetException;

public class Replacement {

    /**
     * 静态方法替换示例。
     *
     * 原始 LSPTest.staticMethod() 返回 false；
     * Hook 后这里直接返回 true。
     */
    static boolean staticMethodReplacement(Hooker.MethodCallback callback) {
        return true;
    }

    /**
     * 普通实例方法替换示例。
     *
     * normalMethod(String a, int b, long c) 是实例方法，
     * 因此 args[0] 是 this，真实参数从 args[1] 开始。
     */
    String normalMethodReplacement(Hooker.MethodCallback callback) {
        var a = (String) callback.args[1];
        var b = (int) callback.args[2];
        var c = (long) callback.args[3];
        return a + b + c + "replace";
    }

    /**
     * intrinsic 方法替换示例。
     *
     * 这里先调用 backup 获取 StringBuilder.toString() 原始结果，
     * 再按条件改写返回值。
     */
    String intrinsicMethodReplacement(Hooker.MethodCallback callback)
            throws InvocationTargetException, IllegalAccessException {
        var sb = (StringBuilder) callback.args[0];
        var out = (String) callback.backup.invoke(sb);
        if (out.equals("test")) {
            return "testreplace";
        }
        return out;
    }

    /**
     * 构造器替换示例。
     *
     * 构造器没有普通返回值，但仍可以通过 args[0] 拿到正在初始化的对象。
     * 先调用 backup 执行原构造逻辑，再改写 field。
     */
    void constructorReplacement(Hooker.MethodCallback callback)
            throws InvocationTargetException, IllegalAccessException {
        var test = (LSPTest) callback.args[0];
        callback.backup.invoke(test);
        test.field = true;
    }

    /**
     * 多参数替换示例。
     *
     * 主要用于验证 LSPlant 生成的 stub 能正确处理：
     * - 引用类型
     * - boolean / byte / short / int
     * - long / double 这类宽类型
     * - 装箱参数
     */
    String manyParametersReplacement(Hooker.MethodCallback callback) {
        var a = (String) callback.args[1];
        var b = (boolean) callback.args[2];
        var c = (byte) callback.args[3];
        var d = (short) callback.args[4];
        var e = (int) callback.args[5];
        var f = (long) callback.args[6];
        var g = (float) callback.args[7];
        var h = (double) callback.args[8];
        var i = (Integer) callback.args[9];
        var j = (Long) callback.args[10];
        return a + b + c + d + e + f + g + h + i + j + "replace";
    }
}

这里要特别注意实例方法的参数顺序。LSPlant 的 API 文档也说明：非静态方法会把 this 放到 args[0] ，静态方法不会放一个空的 this 占位。

import lsplant;

// 把地址按页对齐，并修改目标页权限。
// Dobby 要改写函数入口指令，因此测试工程先把目标地址所在页设为 RWX。
#define _uintval(p) reinterpret_cast<uintptr_t>(p)
#define _ptr(p) reinterpret_cast<void *>(p)
#define _align_up(x, n) (((x) + ((n) - 1)) & ~((n) - 1))
#define _align_down(x, n) ((x) & -(n))
#define _page_size 4096
#define _page_align(n) _align_up(static_cast<uintptr_t>(n), _page_size)
#define _ptr_align(x) _ptr(_align_down(reinterpret_cast<uintptr_t>(x), _page_size))
#define _make_rwx(p, n) \
    ::mprotect( \
        _ptr_align(p), \
        _page_align(_uintval(p) + n) != _page_align(_uintval(p)) \
            ? _page_align(n) + _page_size \
            : _page_align(n), \
        PROT_READ | PROT_WRITE | PROT_EXEC)

// Java 的 LSPTest.initHooker() 会读取这个结果，
// 用来确认 JNI_OnLoad 里 lsplant::Init 是否成功。
bool init_result;

/**
 * 解析 libart.so 符号。
 *
 * xdl_sym:
 *   先查动态符号表。
 *
 * xdl_dsym:
 *   动态符号查不到时，再查调试符号。
 *
 * LSPlant 初始化时既需要普通符号解析，也需要前缀符号解析。
 */
void *find_symbol(void *handle, const char *sys_name) {
    void *addr = xdl_sym(handle, sys_name, nullptr);
    if (nullptr == addr) {
        addr = xdl_dsym(handle, sys_name, nullptr);
    }
    return addr;
}

/**
 * 提供给 LSPlant 的 inline hooker。
 *
 * target:
 *   ART 内部函数地址。
 *
 * hooker:
 *   LSPlant 提供的替换函数地址。
 *
 * 返回值:
 *   Dobby 生成的 origin_call。LSPlant 之后可以通过它调用原始 ART 函数。
 */
void *InlineHooker(void *target, void *hooker) {
    _make_rwx(target, _page_size);
    void *origin_call;
    if (DobbyHook(target, hooker, &origin_call) == RS_SUCCESS) {
        return origin_call;
    } else {
        return nullptr;
    }
}

/**
 * 提供给 LSPlant 的 inline unhooker。
 */
bool InlineUnhooker(void *func) {
    return DobbyDestroy(func) == RT_SUCCESS;
}

Hook 前期准备与验证

文件： lsplant/src/main/jni/lsplant.cc

下面是 Hook() 开头部分，主要做四件事：

  1. 验证 target_method 是反射方法对象。
  2. 验证 callback_method 是反射方法对象。
  3. 从反射对象转换到 ART 内部 ArtMethod* 。
  4. 检查是否已经 Hook，避免重复 Hook。
[[maybe_unused]] jobject Hook(JNIEnv *env,
                              jobject target_method,
                              jobject hooker_object,
                              jobject callback_method) {
    // target_method 必须是 Method 或 Constructor。
    // Android 8.0+ 统一基类是 java.lang.reflect.Executable；
    // 老版本 LSPlant 初始化时会退回 AbstractMethod。
    if (!target_method || !JNI_IsInstanceOf(env, target_method, executable)) {
        LOGE("target method is not an executable");
        return nullptr;
    }

    // callback_method 也必须是可执行的反射对象。
    // 后面会检查 callback_method 是否属于 hooker_object 的类。
    if (!callback_method || !JNI_IsInstanceOf(env, callback_method, executable)) {
        LOGE("callback method is not an executable");
        return nullptr;
    }

    jmethodID hook_method = nullptr;
    jmethodID backup_method = nullptr;
    jfieldID hooker_field = nullptr;

    // 拿到 target 所属类，用于判断是否是 Proxy 类。
    auto target_class =
        JNI_Cast<jclass>(JNI_CallObjectMethod(env,
                                              target_method,
                                              method_get_declaring_class));

    // ART 里 Class.accessFlags 的 proxy 标记。
    constexpr static uint32_t kAccClassIsProxy = 0x00040000;
    bool is_proxy = JNI_GetIntField(env, target_class, class_access_flags) & kAccClassIsProxy;

    // 从 Java 反射对象拿到底层 ArtMethod*。
    // 后续真正修改的是 ArtMethod 里的 entrypoint、access flags、data 等字段。
    auto *target = ArtMethod::FromReflectedMethod(env, target_method);

    // 判断目标是否为静态方法。
    // 动态生成 stub 时，静态方法和实例方法的参数布局不同。
    bool is_static = target->IsStatic();

    // 避免重复 Hook。
    // including_backup = true 表示 target 或 backup 任意一侧已被记录都算已 Hook。
    if (IsHooked(target, true)) {
        LOGW("Skip duplicate hook");
        return nullptr;
    }

    // 后续进入动态 Dex 生成和 DoHook。
}

这里的 executable 来自 InitJNI() 的缓存。Android 8.0 之后反射方法和构造器共同继承自 java.lang.reflect.Executable ；更老平台使用 AbstractMethod 。这就是版本差异会影响初始化的第一个点。

生成 Hook stub：把任意签名统一转成 Object [] 回调

仍在 Hook() 中。为了让 callback 固定成 Object callback(Object[] args) ，LSPlant 会根据目标方法 shorty 动态生成一个类：

  • 一个静态字段：保存 hooker_object 。
  • 一个 hook 方法：签名模拟目标方法，负责收集参数并调用 hooker_object.callback(Object[]) 。
  • 一个 backup 方法：签名模拟目标方法，初始只返回默认值，稍后会被 target->BackupTo(backup) 改写成原始逻辑备份。

                 is_static,
                 target->IsConstructor()

                 class_name.get(),

BuildDex() 很长，下面保留主干逻辑，省略 DexFile 加载细节中不同 Android 版本的分支。省略部分主要处理：

  • Android Q+ 的 DexFile(ByteBuffer[], ClassLoader, Element[]) 构造方式。
  • Android O/P 的 DexFile(ByteBuffer) 构造方式。
  • 更老平台的 DexFile::OpenMemory() 和 Java DexFile 包装方式。
std::tuple<jclass, jfieldID, jmethodID, jmethodID>
BuildDex(JNIEnv *env,
         jobject class_loader,
         std::string_view shorty,
         bool is_static,
         std::string_view method_name,
         std::string_view hooker_class,
         std::string_view callback_name) {
    using namespace startop::dex;

    if (shorty.empty()) {
        LOGE("Invalid shorty");
        return {nullptr, nullptr, nullptr, nullptr};
    }

    DexBuilder dex_file;

    // shorty[0] 是返回值，shorty[1..] 是参数。
    // 对象统一按 Object 处理，基本类型按对应描述符处理。
    auto parameter_types = std::vector<TypeDescriptor>();
    parameter_types.reserve(shorty.size() - 1);

    auto return_type =
        shorty[0] == 'L'
            ? TypeDescriptor::Object
            : TypeDescriptor::FromDescriptor(shorty[0]);

    // 实例方法和构造器需要把 this 放进参数列表。
    // 静态方法没有 this。
    if (!is_static) {
        parameter_types.push_back(TypeDescriptor::Object);
    }

    for (const char &param : shorty.substr(1)) {
        parameter_types.push_back(
            param == 'L'
                ? TypeDescriptor::Object
                : TypeDescriptor::FromDescriptor(static_cast<char>(param)));
    }

    // 创建动态类，类名由 InitInfo.generated_class_name 控制，默认 LSPHooker_。
    ClassBuilder cbuilder{dex_file.MakeClass(generated_class_name)};
    if (!generated_source_name.empty()) {
        cbuilder.set_source_file(generated_source_name);
    }

    // hooker_type 是 Hooker 类。
    // 动态类会持有一个 static Hooker hooker 字段。
    auto hooker_type = TypeDescriptor::FromClassname(hooker_class.data());

    auto *hooker_field = cbuilder.CreateField(generated_field_name, hooker_type)
                             .access_flags(dex::kAccStatic)
                             .Encode();

    // 创建真正接管 target 的 hook 方法。
    // 它的签名模拟 target，所以能被 ART 当成目标方法入口。
    auto hook_builder{cbuilder.CreateMethod(
        generated_method_name == "{target}"sv
            ? method_name.data()
            : generated_method_name,
        Prototype{return_type, parameter_types})};

    // 创建 Object[]，长度等于参数数量。
    auto tmp{hook_builder.AllocRegister()};
    hook_builder.BuildConst(tmp, static_cast<int>(parameter_types.size()));

    auto hook_params_array{hook_builder.AllocRegister()};
    hook_builder.BuildNewArray(hook_params_array, TypeDescriptor::Object, tmp);

    // 遍历每个参数：
    // - 基本类型先装箱
    // - 再写入 Object[]
    // - long/double 这类 wide 类型在寄存器上多占一个位置
    for (size_t i = 0U, j = 0U; i < parameter_types.size(); ++i, ++j) {
        hook_builder.BuildBoxIfPrimitive(Value::Parameter(j),
                                         parameter_types[i],
                                         Value::Parameter(j));
        hook_builder.BuildConst(tmp, static_cast<int>(i));
        hook_builder.BuildAput(Instruction::Op::kAputObject,
                               hook_params_array,
                               Value::Parameter(j),
                               tmp);
        if (parameter_types[i].is_wide()) {
            ++j;
        }
    }

    // 生成调用：
    //   hooker.callback(Object[] args)
    auto handle_hook_method{dex_file.GetOrDeclareMethod(
        hooker_type,
        callback_name.data(),
        Prototype{TypeDescriptor::Object, TypeDescriptor::Object.ToArray()})};

    hook_builder.AddInstruction(
        Instruction::GetStaticObjectField(hooker_field->decl->orig_index, tmp));
    hook_builder.AddInstruction(
        Instruction::InvokeVirtualObject(handle_hook_method.id,
                                         tmp,
                                         tmp,
                                         hook_params_array));

    // 根据 target 返回类型，把 callback 返回的 Object 转回目标返回类型。
    if (return_type == TypeDescriptor::Void) {
        hook_builder.BuildReturn();
    } else if (return_type.is_primitive()) {
        auto box_type{return_type.ToBoxType()};
        const ir::Type *type_def = dex_file.GetOrAddType(box_type);
        hook_builder.AddInstruction(
            Instruction::Cast(tmp, Value::Type(type_def->orig_index)));
        hook_builder.BuildUnBoxIfPrimitive(tmp, box_type, tmp);
        hook_builder.BuildReturn(tmp, false, return_type.is_wide());
    } else {
        const ir::Type *type_def = dex_file.GetOrAddType(return_type);
        hook_builder.AddInstruction(
            Instruction::Cast(tmp, Value::Type(type_def->orig_index)));
        hook_builder.BuildReturn(tmp, true);
    }

    auto *hook_method = hook_builder.Encode();

    // 创建 backup 方法，签名同 target。
    // 初始实现只是返回默认值；真正的原始逻辑稍后由 target->BackupTo(backup) 写入。
    auto backup_builder{cbuilder.CreateMethod("backup",
                                              Prototype{return_type, parameter_types})};
    if (return_type == TypeDescriptor::Void) {
        backup_builder.BuildReturn();
    } else if (return_type.is_wide()) {
        LiveRegister zero = backup_builder.AllocRegister();
        LiveRegister zero_wide = backup_builder.AllocRegister();
        backup_builder.BuildConstWide(zero, 0);
        backup_builder.BuildReturn(zero, false, true);
    } else {
        LiveRegister zero = backup_builder.AllocRegister();
        backup_builder.BuildConst(zero, 0);
        backup_builder.BuildReturn(zero, !return_type.is_primitive(), false);
    }
    auto *backup_method = backup_builder.Encode();

    // 省略：把 dex_file.CreateImage() 得到的内存 Dex 加载进 ClassLoader。
    // 成功后返回：
    //   target_class: 生成类
    //   hooker_field: 静态 hooker 字段
    //   hook_method:  接管 target 的 hook 方法
    //   backup_method: 备份原始逻辑的 backup 方法
}

这个设计把 “任意 Java 方法签名” 统一成 “固定 callback 签名”。用户只需要处理 Object[] args ，不需要为每个目标方法手写同签名代理类。

Hook 执行：反射方法转 ArtMethod，并写入 hooker 对象

动态 Dex 加载成功后， Hook() 继续把生成的 hook_method 和 backup_method 转成反射对象，再回到 ArtMethod* 。

文件： lsplant/src/main/jni/lsplant.cc

// 把动态生成类里的 hook 方法转成 Java Method。

    JNI_ToReflectedMethod(env, built_class, hook_method, JNI_TRUE);

    JNI_ToReflectedMethod(env, built_class, backup_method, JNI_TRUE);

JNI_CallVoidMethod(env, reflected_backup, set_accessible, JNI_TRUE);

// hook 是接管 target 的动态方法；
// backup 是保存原始逻辑的动态方法。

auto *backup = ArtMethod::FromReflectedMethod(env, reflected_backup.get());

// 把 Java 层 Hooker 对象写入动态类静态字段。
// 之后动态 stub 执行时，会从这个字段取 Hooker 并调用 Hooker.callback(Object[])。
JNI_SetStaticObjectField(env, built_class, hooker_field, hooker_object);

if (DoHook(target, hook, backup)) {
    // Hook 成功后才进入状态记录。
}

JNI_SetStaticObjectField() 这一句是 Java 层 Hooker 对象能够在回调时被找到的关键。它也意味着 Java 侧不要过早丢掉业务上下文，否则你很难管理后续 UnHook 和 replacement 状态。

DoHook：暂停运行时，备份 target，改写 entrypoint

真正修改 ART 方法结构的是 DoHook() 。

文件： lsplant/src/main/jni/lsplant.cc

bool DoHook(ArtMethod *target,
            ArtMethod *hook,
            ArtMethod *backup) {
    // 进入 GC critical section，避免 Hook 过程中被 GC 干扰。
    ScopedGCCriticalSection section(art::Thread::Current(),
                                    art::gc::kGcCauseDebugger,
                                    art::gc::kCollectorTypeDebugger);

    // 暂停所有线程，避免其他线程正在执行或修改相关 ART 状态。
    ScopedSuspendAll suspend("LSPlant Hook", false);

    LOGV("Hooking: target = %s(%p), hook = %s(%p), backup = %s(%p)",
         target->PrettyMethod().c_str(),
         target,
         hook->PrettyMethod().c_str(),
         hook,
         backup->PrettyMethod().c_str(),
         backup);

    // 为 hook 方法生成一段可执行 trampoline。
    // target 的 entrypoint 最终会指向这个 trampoline。
    if (auto *entrypoint = GenerateTrampolineFor(hook); !entrypoint) {
        LOGE("Failed to generate trampoline");
        return false;
    } else {
        LOGV("Generated trampoline %p", entrypoint);

        // intrinsic 方法可能被 ART 用特殊路径处理。
        // Hook 前先取消 intrinsic 标记，避免绕过 entrypoint。
        target->SetNonIntrinsic();

        // 把 target 当前的 ArtMethod 内容备份到 backup。
        // 这样 backup.invoke(...) 可以走原始逻辑。
        target->BackupTo(backup);

        // 阻止 target 再被 JIT 编译成新的优化代码。
        target->SetNonCompilable();

        // 最关键的一步：
        // 把 target 的 quick entrypoint 改成 LSPlant 生成的 trampoline。
        target->SetEntryPoint(entrypoint);

        LOGV("Done hook: target(%p:0x%x) -> %p; "
             "backup(%p:0x%x) -> %p; hook(%p:0x%x) -> %p",
             target,
             target->GetAccessFlags(),
             target->GetEntryPoint(),
             backup,
             backup->GetAccessFlags(),
             backup->GetEntryPoint(),
             hook,
             hook->GetAccessFlags(),
             hook->GetEntryPoint());

        return true;
    }
}

GenerateTrampolineFor() 会把 hook 的 ArtMethod* 写到模板的指定偏移，再复制到可执行内存：

void *GenerateTrampolineFor(art::ArtMethod *hook) {
    // 拷贝当前架构的 trampoline 模板。
    auto data = trampoline;

    // 把 hook ArtMethod* 写进模板中。
    // 运行时进入 trampoline 后，会根据这段数据跳到 hook 的 entrypoint。
    *reinterpret_cast<ArtMethod **>(data.data() + art_method_offset) = hook;

    // 如果用户通过 InitInfo 提供了自定义可执行内存分配器，优先使用。
    if (executable_memory_allocator) {
        if (auto *memory =
                static_cast<char *>(executable_memory_allocator(data))) [[likely]] {
            __builtin___clear_cache(memory, memory + data.size());
            LOGV("memory allocated from user: %p", memory);
            return memory;
        }
    }

    // 省略：从 trampoline_pool 中按页分配一小块空间。
    // LSPlant 优先用 memfd / ashmem 做双映射，失败时退回 RWX mmap。

    auto *address_ptr = reinterpret_cast<char *>(address);

    // 双映射场景：
    //   executable_memory: RX
    //   writable_memory:   RW
    // 通过同一块底层内存的 RW 映射写入指令，再从 RX 映射执行。
    if (dual_regions.contains(__builtin_align_down(address_ptr, kPageSize))) [[likely]] {
        std::memcpy(address_ptr + kPageSize, data.data(), data.size());
    } else {
        std::memcpy(address_ptr, data.data(), data.size());
    }

    // 清理指令缓存，确保 CPU 执行到最新写入的 trampoline。
    __builtin___clear_cache(address_ptr,
                            reinterpret_cast<char *>(address + data.size()));

    return address_ptr;
}

这里的版本差异主要体现在两处：

  • ABI 不同，trampoline 指令模板不同。
  • 系统能力不同，可执行内存分配策略不同。Android Q+ 且内核满足条件时优先 memfd ，否则尝试 ashmem，最后才退回匿名 RWX mmap 。

状态查询和记录函数：

inline art::ArtMethod *IsHooked(art::ArtMethod *art_method,
                                bool including_backup = false) {
    art::ArtMethod *backup = nullptr;

    hooked_methods_.if_contains(
        art_method,
        [&backup, &including_backup](const auto &it) {
            // target 记录的 first 是 reflected_backup；
            // backup 反向记录的 first 是 nullptr。
            //
            // including_backup = false:
            //   只把 target 视为 hooked。
            //
            // including_backup = true:
            //   target 和 backup 都视为已记录，常用于阻止重复 Hook。
            if (including_backup || it.second.first) {
                backup = it.second.second;
            }
        });

    return backup;
}

inline art::ArtMethod *IsBackup(art::ArtMethod *art_method) {
    art::ArtMethod *backup = nullptr;

    hooked_methods_.if_contains(art_method, [&backup](const auto &it) {
        // backup 反向记录的 first 是 nullptr。
        // 命中时 it.second.second 实际是 target。
        if (!it.second.first) {
            backup = it.second.second;
        }
    });

    return backup;
}

inline void RecordHooked(art::ArtMethod *target,
                         const art::dex::ClassDef *class_def,
                         jobject reflected_backup,
                         art::ArtMethod *backup) {
    // 记录 class_def -> target 集合。
    hooked_classes_.lazy_emplace_l(
        class_def,
        [&target](auto &it) {
            it.second.emplace(target);
        },
        [&class_def, &target](const auto &ctor) {
            ctor(class_def, phmap::flat_hash_set<art::ArtMethod *>{target});
        });

    // 双向记录：
    //   target -> backup
    //   backup -> target
    hooked_methods_.insert({
        std::make_pair(target, std::make_pair(reflected_backup, backup)),
        std::make_pair(backup, std::make_pair(nullptr, target))
    });
}

inline void RecordDeoptimized(const art::dex::ClassDef *class_def,
                              art::ArtMethod *art_method) {
    deoptimized_classes_[class_def].emplace(art_method);
    deoptimized_methods_set_.insert(art_method);
}

inline void RecordJitMovement(art::ArtMethod *target,
                              art::ArtMethod *backup) {
    std::unique_lock lk(jit_movements_lock_);
    jit_movements_.emplace_back(target, backup);
}

Hook() 成功后的状态记录主干如下：

if (DoHook(target, hook, backup)) {
    // LSPlant 初始化时缓存了一些内部 jmethodID。
    // 如果其中某个 jmethodID 指向了当前 target，
    // Hook 后要把它替换为 backup_method，避免内部调用也绕进 hook。
    std::apply(
        [backup_method,
         target_method_id = env->FromReflectedMethod(target_method)](auto... v) {
            ((*v == target_method_id &&
              (LOGD("Propagate internal used method because of hook"),
               *v = backup_method)) || ...);
        },
        kInternalMethods);

    // backup Method 需要跨出当前 JNI 局部引用作用域，
    // 因此转成 global ref 交给状态表管理。
    jobject global_backup = JNI_NewGlobalRef(env, reflected_backup);

    // 记录 target -> backup 和 backup -> target。
    RecordHooked(target,
                 target->GetDeclaringClass()->GetClassDef(),
                 global_backup,
                 backup);

    if (!is_proxy) [[likely]] {
        // 普通方法需要记录 JIT movement。
        // JIT code cache 回收时会用它迁移 obsolete method 关系。
        RecordJitMovement(target, backup);
    } else {
        // Proxy 方法单独记录 backup。
        proxied_backup_methods_.emplace(backup);
    }

    // backup 也要记录为 deoptimized。
    // 原因是 hooker class 被 FixupStaticTrampolines 时，
    // 不希望 ART 更新 backup 的 entrypoint。
    RecordDeoptimized(hook->GetDeclaringClass()->GetClassDef(), backup);

    return global_backup;
}

状态表记录完成后， Hook() 返回 global_backup 给 Java 层。此时 Java 层 Hooker.backup = result ，后续 replacement 就可以通过 backup.invoke(...) 调回原始逻辑。

IsHooked：从 Java Method 查询 Hook 状态

文件： lsplant/src/main/jni/lsplant.cc

[[maybe_unused]] bool IsHooked(JNIEnv *env, jobject method) {
    // 仍然先检查 Java 反射对象类型。
    if (!method || !JNI_IsInstanceOf(env, method, executable)) {
        LOGE("method is not an executable");
        return false;
    }

    // Java Method/Constructor -> ArtMethod*。
    auto *art_method = ArtMethod::FromReflectedMethod(env, method);

    // 查询 hooked_methods_。
    return IsHooked(art_method);
}

注意这里调用的是 IsHooked(art_method) ，默认 including_backup = false 。也就是说：

  • 查询 target：返回 true。
  • 查询 backup：不会被当成普通 “已 Hook 方法” 返回 true。

这是一个很细的语义区分：backup 是状态表的一部分，但对外 API 不应把 backup 当作被 Hook 的目标方法。

UnHook 验证与状态查找

UnHook() 首先也做 Executable 校验，然后从 hooked_methods_ 找到 target 对应的 backup。

文件： lsplant/src/main/jni/lsplant.cc

[[maybe_unused]] bool UnHook(JNIEnv *env, jobject target_method) {
    // target_method 必须是 Method 或 Constructor。
    if (!target_method || !JNI_IsInstanceOf(env, target_method, executable)) {
        LOGE("target method is not an executable");
        return false;
    }

    auto *target = ArtMethod::FromReflectedMethod(env, target_method);

    jobject reflected_backup = nullptr;
    art::ArtMethod *backup = nullptr;

    // 从 hooked_methods_ 删除 target 记录，并取出 reflected_backup 和 backup。
    //
    // erase_if 返回 false 表示：
    //   - target 不在状态表里
    //   - 或命中的是 backup 反向记录，因为 backup 记录的 reflected_backup 是 nullptr
    if (!hooked_methods_.erase_if(
            target,
            [&reflected_backup, &backup](const auto &it) {
                std::tie(reflected_backup, backup) = it.second;
                return reflected_backup != nullptr;
            })) {
        LOGE("Unable to unhook a method that is not hooked");
        return false;
    }

    // 后续进入状态清理和 DoUnHook。
}

这个查找逻辑依赖 RecordHooked() 的双向记录：

Hook 成功后：

hooked_methods_
  target -> { reflected_backup_global_ref, backup }
  backup -> { nullptr, target }

UnHook(target) 时：
  只允许删除 first != nullptr 的 target 记录
  不允许把 backup 当作 target 来 UnHook

所以如果你把 Hook() 返回的 backup 再传给 UnHook() ，通常会失败，因为 backup 不是对外意义上的 target。

状态清理与 UnHook 执行

找到 backup 后， UnHook() 会先清理状态，再调用 DoUnHook() 恢复 ArtMethod 。

文件： lsplant/src/main/jni/lsplant.cc

// FIXME: not atomic, but should be fine
// 删除 backup -> target 的反向记录。

              (LOGD("Propagate internal used method because of unhook"),
               *v = target_method_id)) || ...);

DoUnHook() 的恢复动作比 Hook 更短：

bool DoUnHook(ArtMethod *target, ArtMethod *backup) {
    // 和 Hook 一样，恢复时也进入 GC critical section 并暂停线程。
    ScopedGCCriticalSection section(art::Thread::Current(),
                                    art::gc::kGcCauseDebugger,
                                    art::gc::kCollectorTypeDebugger);
    ScopedSuspendAll suspend("LSPlant Hook", false);

    LOGV("Unhooking: target = %p, backup = %p", target, backup);

    // 保存 target 当前 access_flags 和 entrypoint。
    // entry_point 用于后面判断是否需要回收用户自定义 trampoline 内存。
    auto access_flags = target->GetAccessFlags();
    auto *entry_point = target->GetEntryPoint();

    // 用 backup 的 ArtMethod 内容覆盖回 target。
    // 这一步恢复了原始入口、data、dex 信息等关键字段。
    target->CopyFrom(backup);

    // 恢复 Hook 期间保留的 access_flags。
    // LSPlant 在 Hook 中可能设置了 non-compilable 等 flags，
    // 这里避免把某些运行时标记直接从 backup 覆盖回来造成状态不一致。
    target->SetAccessFlags(access_flags);

    // 如果 trampoline 内存来自用户自定义 allocator，
    // 并且不属于 LSPlant 内部 mmap / dual mapping 区域，
    // 则调用用户提供的 recycler 回收。
    if (auto *start = __builtin_align_down(entry_point, kPageSize);
        executable_memory_recycler &&
        !mmap_regions.contains(start) &&
        !dual_regions.contains(start)) {
        executable_memory_recycler(entry_point);
    }

    LOGV("Done unhook: target(%p:0x%x) -> %p; backup(%p:0x%x) -> %p;",
         target,
         target->GetAccessFlags(),
         target->GetEntryPoint(),
         backup,
         backup->GetAccessFlags(),
         backup->GetEntryPoint());

    return true;
}

原理分析

为什么要动态生成 Dex stub

用户传入的 Java callback 固定是：

public Object callback(Object[] args)

但被 Hook 的目标方法可能是：

static boolean staticMethod()

String normalMethod(String a, int b, long c)

LSPTest()

StringBuilder.toString()

ART 调用一个方法时，期望 entrypoint 对应的方法签名、参数寄存器布局和返回类型都与目标方法一致。直接把目标方法 entrypoint 指向 Hooker.callback(Object[]) 并不满足这个要求。

所以 LSPlant 动态生成一个 “同签名方法” 作为中间层：

target 原签名
  -> generated hook method 同签名
  -> generated hook method 内部把参数装箱成 Object[]
  -> Hooker.callback(Object[])
  -> callback 返回 Object
  -> generated hook method 按 target 返回类型拆箱/强转
  -> 返回给调用方

这样做的好处是：

  • target 的调用约定不变。
  • 用户 callback 签名固定。
  • 基本类型、引用类型、宽类型都在生成 stub 内统一处理。
  • backup 也能生成同签名方法，便于反射调用原始逻辑。

为什么要双向记录 target 和 backup

hooked_methods_ 存两条记录：

target -> { reflected_backup, backup }
backup -> { nullptr, target }

这不是冗余，而是为了支持两类查询：

查询场景需要结果使用方式
IsHooked(target)target 是否已 Hook，若已 Hook 找到 backup对外查询、重复 Hook 检查
IsBackup(backup)backup 是否是某个 target 的备份JIT 编译传播、内部修正

例如 jit.cxx 中的 JIT 编译传播会用到这层关系：

inline static auto AddCompileTask_ =
    "_ZN3art3jit3Jit14AddCompileTaskEPNS_6ThreadEPNS_9ArtMethodENS_15CompilationKindEb"_sym
        .hook->*[]
    <MemBackup auto backup>
    (Jit *thiz,
     Thread *self,
     ArtMethod *method,
     CompilationKind compilation_kind,
     bool precompile) static -> void {
        // 如果 ART 准备优化编译的是已 Hook 的 target，
        // LSPlant 把编译请求传播到 backup，
        // 避免 target 被新的 JIT 入口覆盖 Hook entrypoint。
        if (compilation_kind == kOptimized && !precompile) {
            if (auto b = IsHooked(method); b) [[unlikely]] {
                LOGD("Propagate compile task: %p -> %p", method, b);
                method = b;
            }
        }
        return backup(thiz, self, method, compilation_kind, precompile);
    };

而另一个方向，ART 如果试图编译 backup，LSPlant 可以识别出它其实对应某个 target：

inline static auto EnqueueOptimizedCompilation_ =
    "_ZN3art3jit3Jit27EnqueueOptimizedCompilationEPNS_9ArtMethodEPNS_6ThreadE"_sym
        .hook->*[]
    <MemBackup auto backup>
    (Jit *thiz, ArtMethod *method, Thread *self) static -> void {
        // 如果 method 是 backup，就把编译请求传播回 target。
        // 这样可以保持 target/backup 的编译状态关系可控。
        if (auto target = IsBackup(method); target) [[unlikely]] {
            LOGD("Propagate enqueue compilation: %p -> %p", method, target);
            method = target;
        }
        return backup(thiz, method, self);
    };

注

JIT 传播策略是 LSPlant 为了适配 ART 运行时优化做的工程设计。它依赖 ART 私有函数符号和版本分支，不是 Android SDK 保证的稳定行为。

为什么 UnHook 后 backup 不能继续用

LSPlant API 文档明确提醒：UnHook 后继续调用 backup 是未定义行为。源码层面至少有三层原因：

  1. UnHook() 会删除 reflected_backup 的全局引用：
env->DeleteGlobalRef(reflected_backup);
  1. DoUnHook() 会用 backup 覆盖回 target ，backup 本身不再是稳定的 “原始逻辑入口所有者”。
target->CopyFrom(backup);
  1. 状态表会删除 target/backup 双向记录，JIT、deoptimize、类修复等内部逻辑也不再维护这个 backup。

因此正确用法是：

Hook 生命周期内：
  可以通过 backup.invoke(...) 调用原始逻辑

UnHook 之后：
  丢弃旧 backup
  如需再次 Hook，应重新调用 Hook() 并使用新的 backup

为什么 Hook 和 UnHook 都要暂停线程

ArtMethod 是运行时核心结构。Hook/UnHook 会修改 entrypoint、access flags、data 等字段。如果其他线程同时执行目标方法、触发 JIT、类初始化或 GC，可能读到中间态。

因此 DoHook() 和 DoUnHook() 都使用：

ScopedGCCriticalSection section(...);
ScopedSuspendAll suspend("LSPlant Hook", false);

它们的目标不是提升性能，而是减少并发修改 ART 内部状态时的竞态风险。不过 LSPlant API 文档仍然提醒：对同一个 target_method 并发 Hook/UnHook 不是原子操作，业务层仍应避免并发操作同一个目标。

常见错误与排查

LSPTest.initHooker() 返回 false

可能原因：

  • InitInfo.inline_hooker 、 inline_unhooker 、 art_symbol_resolver 或 art_symbol_prefix_resolver 为空。
  • xdl_open("libart.so") 失败。
  • libart.so 私有符号解析失败。
  • Dobby hook ART 内部函数失败。
  • Android 版本、ABI 或厂商 ROM 与当前源码适配不一致。

排查方式：

adb logcat -s LSPlant:D LSPlant-test:D '*:S'

重点搜索：

Failed to init art method
Failed to init runtime
Failed to init class linker
Failed to init jit
Failed to init dex file
Failed to find ...

target method is not an executable

可能原因：

  • 传给 Hook() 的不是 Method 或 Constructor 。
  • Java 层把 Member 、 Field 或其他对象误传给 native。
  • 初始化阶段 executable 缓存失败。

排查方式：

  • 确认 Java 侧使用的是 Class.getDeclaredMethod() 或 Class.getDeclaredConstructor() 的返回值。
  • 不要把 Field 传给 Hook() 。
  • 确认 t00_init 先通过。

callback_method is not a method of hooker_object

可能原因：

  • callback_method 来自 A 类，但 hooker_object 是 B 类实例。
  • 自己改造 Java 包装时，把 replacement 方法误当成 LSPlant callback 传入。

正确结构应该是：

hooker_object:
  Hooker 实例

callback_method:
  Hooker.class.getDeclaredMethod("callback", Object[].class)

replacement:
  Replacement 中的业务替换方法，不直接传给 native Hook()

Failed to generate hooker

可能原因：

  • 目标方法 shorty 解析失败。
  • 动态 Dex 构造或加载失败。
  • InitInfo.generated_class_name 、 generated_field_name 、 generated_method_name 配置为空或非法。
  • 目标 ClassLoader 不适合加载生成 Dex。
  • Android 版本对应的 DexFile 构造方式不匹配。

排查方式：

  • 先用自带测试工程确认环境可用。
  • 不要把 generated_class_name 配成 Java 源码形式，例如 com.example.Hook ；LSPlant 这里需要 Dex 类型名风格。
  • 查看 logcat 中 DexFile 相关错误。

Hook 成功但 callback 没执行

可能原因：

  • 调用方已经内联了被 Hook 方法。
  • 目标方法是 intrinsic 或被特殊优化路径处理。
  • Hook 的不是实际运行时调用的那个方法，例如类加载器不同、重载方法选错。
  • target 被 JIT 或 instrumentation 路径覆盖 entrypoint。

排查方式：

  • 确认 Hook() 返回非 null。
  • 调用 IsHooked() 检查 target 状态。
  • 对调用方尝试 Deoptimize() ，或改 Hook 更上层、更稳定的调用点。
  • 确认反射获取的方法参数列表完全匹配。

Unable to unhook a method that is not hooked

可能原因：

  • 传给 UnHook() 的不是原始 target，而是 backup。
  • Hook 失败后仍调用 UnHook。
  • 同一个 target 已经 UnHook 过。
  • 并发 Hook/UnHook 同一 target 导致状态被提前清理。

排查方式：

  • 保存并传回最初的 target Method / Constructor 。
  • 不要把 hooker.backup 传给 unhook() 。
  • 业务层对同一 target 加锁，避免重复操作。

UnHook 后调用 backup 崩溃或结果异常

原因：

  • 这是 API 明确标注的未定义行为。
  • UnHook 会删除 backup 全局引用，并清理状态表。
  • target->CopyFrom(backup) 后，backup 不再适合作为原始逻辑入口使用。

正确做法：

UnHook 后丢弃旧 backup。
再次 Hook 时使用新返回的 backup。

构建阶段找不到 NDK、CMake 或 AGP 不兼容

排查方式：

./gradlew --version
./gradlew :lsplant:assembleRelease --stacktrace

确认本地安装：

  • Android SDK Platform 35。
  • Build Tools 35.0.0。
  • NDK 29.0.14206865 。
  • CMake 3.28.0+ 。
  • JDK 17 或 AGP 8.9.x 支持的 JDK。

总结

LSPlant 的 Hook/UnHook 主线可以浓缩成一句话：

动态生成一个同签名 stub，让 target 的 ArtMethod entrypoint 跳到 stub；
同时把原 target 复制到 backup，并用状态表维护 target、backup、JIT、类初始化和 deoptimize 之间的关系；
UnHook 时再从状态表找到 backup，把 backup 的 ArtMethod 内容恢复回 target。

本文重点不是 “Hook 是替换方法” 这个概念，而是 LSPlant 为了让替换在 ART 里稳定运行做的工程处理：

  • 用 Executable 校验确保输入是方法或构造器。
  • 用 shorty 和 DexBuilder 生成同签名 stub。
  • 用 trampoline 改写 target quick entrypoint。
  • 用 hooked_methods_ 做 target/backup 双向索引。
  • 用 hooked_classes_ 、 deoptimized_classes_ 、 jit_movements_ 对抗类初始化、JIT 和 code cache 回收。
  • 用 DoUnHook() 在暂停线程和 GC critical section 中恢复 ArtMethod 。

如果要把它扩展到自己的 Hook 框架，建议先复用这套测试思路：每个 Hook 点都至少验证 Hook 前、Hook 后、backup 调用、UnHook 后四个状态。这样比只看 “Hook 返回非 null” 可靠得多。
