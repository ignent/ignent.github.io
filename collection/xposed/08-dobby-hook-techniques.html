Dobby技巧

ZIP2026/6/14...大约 9 分钟XposedDobbyNative Hook指令插桩

方案概述

Dobby 是一个轻量级的 Hook 框架，支持 ARM/ARM64/x86/x64 架构。在 Android Native Hook 场景中，Dobby 提供了三种不同层次的 Hook 技术，适用于不同的逆向需求。

本文将详细介绍 Dobby 的三种核心技术：

  1. DobbyHook（函数替换）：完全替换函数逻辑，可调用原函数
  2. DobbyInstrument（指令插桩）：在目标地址插入回调，修改寄存器和执行流
  3. DobbyCodePatch（代码补丁）：直接修改机器码字节，最底层的修改方式

技术对比

技术适用场景灵活性复杂度风险
DobbyHook替换完整函数逻辑高低低
DobbyInstrument修改寄存器、监控执行中中中
DobbyCodePatch修改指令、绕过检测低高高

2. DobbyHook - 函数替换技术

2.1 API 签名

int DobbyHook(void *address, dobby_dummy_func_t replace_func, dobby_dummy_func_t *origin_func);

参数说明：

  • address ：目标函数地址
  • replace_func ：替换函数指针
  • origin_func ：保存原函数地址的指针（可为 NULL）
  • 返回值： 0 表示成功

2.2 实现示例

#include "include/dobby.h"
#include <android/log.h>

// 备份原始 JNI 函数
jboolean (*backup_check)(JNIEnv *env, jclass clazz);

// 替换函数实现
jboolean replace_check(JNIEnv *env, jclass clazz) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "replace_check called");
    
    // 调用原函数
    jboolean result = backup_check(env, clazz);
    __android_log_print(ANDROID_LOG_INFO, "0X->", "Original result: %d", result);
    
    // 修改返回值
    return JNI_TRUE;  // 强制返回成功
}

void hook_jni_function() {
    // 1. 解析符号获取函数地址
    void *target = DobbySymbolResolver(
        "libexercise15.so",
        "Java_com_challenge_exercise_Exercise15Lib_check2"
    );
    
    if (target) {
        // 2. Hook 函数
        int ret = DobbyHook(target, (void *)replace_check, (void **)&backup_check);
        __android_log_print(ANDROID_LOG_INFO, "0X->", "DobbyHook ret: %d", ret);
    }
}

2.3 工作原理

  1. 跳转指令注入：

    原函数入口：
0x1000: mov x0, x1        →  0x1000: b trampoline
0x1004: add x0, x0, #1    →  0x1004: [被覆盖]

  2. Trampoline 跳板：

    trampoline:
    保存寄存器
    跳转到 replace_check
    恢复寄存器
    跳转回原函数（如果调用 backup_check）

  3. 调用流程：

    App 调用 → 原函数入口 → Trampoline → replace_check
                                           ↓
                                       backup_check
                                           ↓
                                       原函数逻辑

3. DobbyInstrument - 指令插桩技术

3.1 API 签名

typedef void (*dobby_instrument_callback_t)(void *address, DobbyRegisterContext *ctx);
int DobbyInstrument(void *address, dobby_instrument_callback_t pre_handler);

参数说明：

  • address ：插桩地址
  • pre_handler ：回调函数，在目标指令执行前调用
  • 返回值： 0 表示成功

3.2 寄存器上下文结构

// ARM64 架构的寄存器上下文
typedef struct {
    uint64_t dummy_0;
    uint64_t sp;                  // 栈指针
    
    uint64_t dummy_1;
    union {
        uint64_t x[29];           // 通用寄存器数组
        struct {
            uint64_t x0, x1, x2, x3, x4, x5, x6, x7, x8, x9, 
                     x10, x11, x12, x13, x14, x15, x16, x17, 
                     x18, x19, x20, x21, x22, x23, x24, x25, 
                     x26, x27, x28;
        } regs;
    } general;
    
    uint64_t fp;                  // 帧指针
    uint64_t lr;                  // 链接寄存器
    
    // 浮点寄存器（本文不涉及）
    union {
        FPReg q[32];
        struct {
            FPReg q0, q1, q2, q3, q4, q5, q6, q7;
            // ...
        } regs;
    } floating;
} DobbyRegisterContext;

3.3 实现示例：修改函数返回值

假设 IDA 分析发现某函数在 base + 0xE2C 处执行关键检测，我们通过修改 x0 寄存器（ARM64 的返回值寄存器）来绕过检测。

// 插桩回调函数
void bypass_check_callback(void *address, DobbyRegisterContext *ctx) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", 
        "Instrument at %p, original x0: 0x%llx", address, ctx->general.regs.x0);
    
    // 修改 x0 寄存器的值（ARM64 函数返回值）
#if defined(__arm64__) || defined(__aarch64__)
    ctx->general.regs.x0 = 0;  // 强制返回 0
#endif
    
    __android_log_print(ANDROID_LOG_INFO, "0X->", "Modified x0 to: 0");
}

void instrument_check_function(void *base_addr) {
    // 计算目标地址（IDA 中的偏移）
    void *target_addr = (void *)((uintptr_t)base_addr + 0xE2C);
    
    // 插桩
    int ret = DobbyInstrument(target_addr, bypass_check_callback);
    __android_log_print(ANDROID_LOG_INFO, "0X->", "DobbyInstrument ret: %d", ret);
}

3.4 工作原理

  1. 插入跳转：

    原指令：
0x1E2C: cmp x0, #1        →  0x1E2C: b callback_wrapper
0x1E30: b.ne fail         →  0x1E30: [原指令备份]

  2. 执行流程：

    程序执行到 0x1E2C
    ↓
跳转到 callback_wrapper
    ↓
保存寄存器上下文 → 调用 bypass_check_callback → 修改 ctx->general.regs.x0
    ↓
恢复修改后的寄存器
    ↓
执行原指令（cmp 使用修改后的 x0）
    ↓
继续执行 0x1E30

  3. 关键点：

    • 回调函数在原指令执行前调用
    • 修改的寄存器值会影响原指令的执行结果
    • 不需要知道完整函数逻辑，只需定位关键指令

4. DobbyCodePatch - 代码补丁技术

4.1 API 签名

int DobbyCodePatch(void *address, uint8_t *buffer, uint32_t buffer_size);

参数说明：

  • address ：目标地址
  • buffer ：要写入的字节码
  • buffer_size ：字节码长度
  • 返回值： 0 表示成功

4.2 实现示例：修改机器码

假设 IDA 分析发现以下汇编代码：

0x680: mov w0, #1          ; 设置返回值为 1
0x684: ret                 ; 返回

机器码： 20 00 80 52 C0 03 5F D6

我们希望改为：

0x680: mov w0, #0          ; 设置返回值为 0
0x684: ret

新机器码： 00 00 80 52 C0 03 5F D6

void patch_return_value(void *base_addr) {
    void *target_addr = (void *)((uintptr_t)base_addr + 0x680);
    
    // 新的机器码（ARM64：mov w0, #0; ret）
    uint8_t patch_code[] = {
        0x00, 0x00, 0x80, 0x52,  // mov w0, #0
        0xC0, 0x03, 0x5F, 0xD6   // ret
    };
    
    // 写入补丁
    int ret = DobbyCodePatch(target_addr, patch_code, sizeof(patch_code));
    __android_log_print(ANDROID_LOG_INFO, "0X->", "DobbyCodePatch ret: %d", ret);
}

4.3 工作原理

  1. 内存保护修改：

    mprotect(page_addr, page_size, PROT_READ | PROT_WRITE | PROT_EXEC);

  2. 直接写入：

    memcpy(address, buffer, buffer_size);

  3. 刷新缓存：

    __builtin___clear_cache(start, end);  // 清除指令缓存

  4. 恢复保护：

    mprotect(page_addr, page_size, PROT_READ | PROT_EXEC);

4.4 注意事项

危险操作

直接修改机器码需要：

  1. 精确的汇编知识（指令长度、编码格式）
  2. 确保不破坏代码对齐
  3. 理解指令间的依赖关系
  4. 修改错误可能导致崩溃

5. 完整实现案例

5.1 动态库加载监听

#include <jni.h>
#include <string>
#include <android/log.h>
#include "hook.h"
#include "include/dobby.h"

// 获取模块基址
void *get_module_base(const char *module_name) {
    FILE *fp = fopen("/proc/self/maps", "r");
    if (fp == nullptr) {
        return nullptr;
    }
    
    char line[512];
    void *base = nullptr;
    while (fgets(line, sizeof(line), fp)) {
        if (strstr(line, module_name)) {
            char *start_str = strtok(line, "-");
            if (start_str) {
                base = (void *)strtoul(start_str, nullptr, 16);
                break;
            }
        }
    }
    fclose(fp);
    return base;
}

// 动态库加载回调
void on_library_loaded(const char *name, void *handle) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "on_library_loaded: %s", name);
    
    if (std::string(name).ends_with("libexercise15.so")) {
        // 方法一：Hook JNI 函数
        void *jni_func = DobbySymbolResolver(
            "libexercise15.so",
            "Java_com_challenge_exercise_Exercise15Lib_check2"
        );
        
        if (jni_func) {
            __android_log_print(ANDROID_LOG_INFO, "0X->", "JNI function at: %p", jni_func);
            
            // 计算基址（JNI 函数地址 - IDA 中的偏移）
            void *base_addr = (void *)((uintptr_t)jni_func - 0xE28);
            __android_log_print(ANDROID_LOG_INFO, "0X->", "Base address: %p", base_addr);
            
            // 方法二：指令插桩（修改检测逻辑）
            void *check_addr = (void *)((uintptr_t)base_addr + 0xE2C);
            int ret = DobbyInstrument(check_addr, [](void *addr, DobbyRegisterContext *ctx) {
                // 强制检测通过
                ctx->general.regs.x0 = 0;
                __android_log_print(ANDROID_LOG_INFO, "0X->", "Modified x0 at %p", addr);
            });
            __android_log_print(ANDROID_LOG_INFO, "0X->", "DobbyInstrument ret: %d", ret);
            
            // 方法三：代码补丁
            void *patch_addr = (void *)((uintptr_t)base_addr + 0x680);
            uint8_t nop_code[] = {
                0x1F, 0x20, 0x03, 0xD5,  // nop (ARM64)
                0x1F, 0x20, 0x03, 0xD5,  // nop
            };
            ret = DobbyCodePatch(patch_addr, nop_code, sizeof(nop_code));
            __android_log_print(ANDROID_LOG_INFO, "0X->", "DobbyCodePatch ret: %d", ret);
        }
    }
}

// LSPosed Native API 初始化
extern "C" [[gnu::visibility("default")]] [[gnu::used]]
NativeOnModuleLoaded native_init(const NativeAPIEntries *entries) {
    __android_log_print(ANDROID_LOG_INFO, "0X->", "native_init called");
    return on_library_loaded;
}

6. 技巧

6.1 选择合适的 Hook 技术

场景推荐技术原因
修改函数完整逻辑DobbyHook可访问参数和返回值
修改单个寄存器值DobbyInstrument无需理解完整函数
绕过单条检测指令DobbyCodePatch直接修改，最快
监控函数调用流程DobbyInstrument不影响原逻辑

6.2 调试技巧

日志输出：

__android_log_print(ANDROID_LOG_INFO, "TAG", "Message: %p", ptr);

查看日志：

adb logcat -s "0X->"

查看内存地址：

adb shell cat /proc/<pid>/maps | grep libexercise

6.3 常见问题

问题 1：Hook 失败（返回 -1）

解决方案：

  1. 检查地址是否正确（使用 DobbySymbolResolver 或手动计算）
  2. 确认目标地址是指令起始位置（ARM64 必须 4 字节对齐）
  3. 查看 logcat 中 Dobby 的错误信息

问题 2：修改寄存器后崩溃

解决方案：

  1. 确认寄存器用途（不要修改 sp 、 fp 、 lr ）
  2. 检查目标指令是否依赖该寄存器
  3. 使用 IDA 分析寄存器生命周期

问题 3：代码补丁后程序异常

解决方案：

  1. 确认机器码正确（使用在线汇编器验证）
  2. 检查指令长度是否匹配（ARM64 固定 4 字节）
  3. 避免破坏跳转指令的目标地址

7. 进阶应用

7.1 组合使用多种技术

void comprehensive_hook(void *base_addr) {
    // 1. Hook 函数入口，记录调用
    void *entry = (void *)((uintptr_t)base_addr + 0x1000);
    DobbyHook(entry, (void *)log_entry, (void **)&orig_entry);
    
    // 2. 在关键检测点插桩，修改寄存器
    void *check_point = (void *)((uintptr_t)base_addr + 0x1050);
    DobbyInstrument(check_point, bypass_callback);
    
    // 3. 对反调试代码打补丁，直接 nop
    void *anti_debug = (void *)((uintptr_t)base_addr + 0x1100);
    uint8_t nop[] = {0x1F, 0x20, 0x03, 0xD5};
    DobbyCodePatch(anti_debug, nop, sizeof(nop));
}

7.2 动态切换 Hook 状态

// 保存 Hook 地址，用于后续移除
void *hooked_addr = nullptr;

void enable_hook() {
    hooked_addr = DobbySymbolResolver("libtarget.so", "sensitive_func");
    DobbyHook(hooked_addr, (void *)fake_func, (void **)&orig_func);
}

void disable_hook() {
    if (hooked_addr) {
        DobbyDestroy(hooked_addr);  // 恢复原始代码
        hooked_addr = nullptr;
    }
}

8. 安全与检测对抗

8.1 常见检测手段

  1. 内存完整性检查：计算代码段 CRC/MD5
  2. 指令完整性检查：读取关键函数的前几个字节
  3. Dobby 特征检测：扫描内存中的 Trampoline 特征

8.2 对抗方法

// 延迟 Hook，避开初始化时的完整性检查
void delayed_hook() {
    sleep(3);  // 等待完整性检查完成
    void *target = DobbySymbolResolver("libtarget.so", "check");
    DobbyHook(target, (void *)fake_check, nullptr);
}

// 使用代码补丁替代函数 Hook（更隐蔽）
void stealth_patch(void *addr) {
    uint8_t ret_zero[] = {
        0x00, 0x00, 0x80, 0x52,  // mov w0, #0
        0xC0, 0x03, 0x5F, 0xD6   // ret
    };
    DobbyCodePatch(addr, ret_zero, sizeof(ret_zero));
}

总结

技术优点缺点典型场景
DobbyHook代码清晰、可调用原函数特征明显、易被检测加密算法替换、参数监控
DobbyInstrument灵活、不破坏原逻辑性能开销大寄存器修改、执行流监控
DobbyCodePatch最隐蔽、性能最好风险高、难以维护绕过单条检测、修改返回值

最佳实践

  1. 优先使用 DobbyHook：代码可维护性最好
  2. 精确定位使用 DobbyInstrument：避免理解复杂逻辑
  3. 慎用 DobbyCodePatch：仅在必须隐蔽时使用
  4. 组合使用：根据不同场景选择最优方案
