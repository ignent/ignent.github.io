LSPlant初始化与源码构建

LSPlant 源码阅读：项目架构、InitConfig/InitJNI 与编译期字符串

概述

上一篇已经顺着 ArtMethod quick entry 解释了 LSPlant 怎样把 Java 方法调用导向 callback。本文换一个入口：从源码工程、测试样例和初始化流程开始，回答三个更适合复现的问题：

  1. 怎样从源码构建 LSPlant 和自带测试 APK？
  2. JNI_OnLoad -> lsplant::Init -> InitConfig/InitJNI/InitNative 分别做了什么？
  3. LSPlant 为什么大量使用 "_ZN...Ev"_sym 、 .as<签名> 、 .hook->*[] 这种 C++20 风格的编译期字符串写法？

本文最终希望读者能完成两件事：

源码构建：
  :lsplant:assembleRelease 能构建 LSPlant AAR
  :test:assembleDebugAndroidTest 能构建测试 APK

源码理解：
  JNI_OnLoad 提供 inline hooker 和 libart 符号解析器
  InitConfig 保存生成 Dex stub 所需配置
  InitJNI 缓存 Java 反射、DexFile、ClassLoader 相关 jclass/jmethodID/jfieldID
  InitNative 解析并 hook ART 内部函数
  Hook() 再基于这些缓存生成 stub、复制 ArtMethod、设置 trampoline

注意

LSPlant 操作的是 ART 内部结构和 libart.so 私有符号，不是 Android SDK 稳定公开接口。不同 Android 版本、厂商 ROM、ABI、NDK/CMake 版本都可能改变符号、字段偏移、JIT 行为和 trampoline 规则。本文适合做源码阅读和实验复现，不建议把内部偏移或私有符号跨版本硬套到生产环境。

最新提交做了什么

最新提交的主要变化集中在测试样例能否跑起来：

gradle/libs.versions.toml
  新增 xDL 2.4.0 版本和依赖坐标

test/build.gradle.kts
  测试模块新增 implementation(libs.xdl)

test/src/main/jni/CMakeLists.txt
  移除本地 lsparself 子目录
  改为 find_package(xdl REQUIRED CONFIG)
  链接 xdl::xdl

test/src/main/jni/test.cpp
  使用 xdl_open("libart.so", XDL_DEFAULT)
  使用 xdl_sym + xdl_dsym 解析 ART 符号

test/src/main/java/.../LSPTest.java
  initHooker() 改成 public native static

这次变化的核心是把测试模块的 ART 符号解析实现换成 xDL。LSPlant 本体并不内置 Dobby 或 xDL，它要求调用方通过 InitInfo 提供：

  • inline hook 函数；
  • inline unhook 函数；
  • libart.so 符号解析函数；
  • 可选的 prefix symbol resolver；
  • 可选的 executable memory allocator/recycler。

这也是为什么 JNI_OnLoad 是读懂测试样例的第一站。

#include <jni.h>
#include <dobby.h>
#include <sys/mman.h>
#include <string_view>
#include <xdl.h>

#include "logging.h"

// 使用 C++ module 导入 LSPlant 对外 API。
import lsplant;

// 将地址向页边界对齐，方便修改目标函数所在页的权限。
#define _uintval(p) reinterpret_cast<uintptr_t>(p)
#define _ptr(p) reinterpret_cast<void *>(p)
#define _align_up(x, n) (((x) + ((n) - 1)) & ~((n) - 1))
#define _align_down(x, n) ((x) & -(n))
#define _page_size 4096
#define _page_align(n) _align_up(static_cast<uintptr_t>(n), _page_size)
#define _ptr_align(x) _ptr(_align_down(reinterpret_cast<uintptr_t>(x), _page_size))

// Dobby 修改函数入口前，需要让目标页可读、可写、可执行。
// 真实项目里要谨慎处理 RWX 页面，风险见后文。
#define _make_rwx(p, n) \
    ::mprotect( \
        _ptr_align(p), \
        _page_align(_uintval(p) + n) != _page_align(_uintval(p)) \
            ? _page_align(n) + _page_size \
            : _page_align(n), \
        PROT_READ | PROT_WRITE | PROT_EXEC)

// Java 层 t00_init 会读取这个结果，确认 lsplant::Init 是否成功。
bool init_result;

// xDL 先查 .dynsym，再查 .symtab。
// LSPlant 需要解析的 ART 内部符号不保证都在动态符号表里。
void *find_symbol(void *handle, const char *symbol_name) {
    void *addr = xdl_sym(handle, symbol_name, nullptr);
    if (addr == nullptr) {
        addr = xdl_dsym(handle, symbol_name, nullptr);
    }
    return addr;
}

// InitInfo.inline_hooker：把 target 替换为 hooker，并返回原始调用入口。
void *InlineHooker(void *target, void *hooker) {
    _make_rwx(target, _page_size);

    void *origin_call = nullptr;
    if (DobbyHook(target, hooker, &origin_call) == RS_SUCCESS) {
        return origin_call;
    }
    return nullptr;
}

// InitInfo.inline_unhooker：撤销 Dobby hook。
bool InlineUnhooker(void *func) {
    return DobbyDestroy(func) == RT_SUCCESS;
}

extern "C"
JNIEXPORT jboolean JNICALL
Java_org_lsposed_lsplant_LSPTest_initHooker(JNIEnv *, jclass) {
    return init_result;
}

extern "C"
JNIEXPORT jobject JNICALL
Java_org_lsposed_lsplant_Hooker_doHook(
    JNIEnv *env,
    jobject thiz,
    jobject target,
    jobject callback

Java_org_lsposed_lsplant_Hooker_doUnhook(JNIEnv *env, jobject, jobject target) {

JNIEXPORT jint JNICALL
JNI_OnLoad(JavaVM *vm, void *) {
    JNIEnv *env = nullptr;
    if (vm->GetEnv(reinterpret_cast<void **>(&env), JNI_VERSION_1_6) != JNI_OK) {
        return JNI_ERR;
    }

    // 打开 libart.so。XDL_DEFAULT 表示使用 xDL 默认行为查找已经加载的 ELF。
    static void *handle = xdl_open("libart.so", XDL_DEFAULT);

    // 这是 LSPlant 初始化最关键的配置对象。
    lsplant::InitInfo initInfo{
        .inline_hooker = InlineHooker,
        .inline_unhooker = InlineUnhooker,

        // 精确符号解析：用于 "_ZN3art..." 这类完整 mangled name。
        .art_symbol_resolver = [](std::string_view symbol) -> void * {
            return find_symbol(handle, symbol.data());
        },

        // 前缀符号解析：部分 Android 版本上同一函数签名会有细微差异。
        .art_symbol_prefix_resolver = [](std::string_view symbol) -> void * {
            return find_symbol(handle, symbol.data());
        },
    };

    init_result = lsplant::Init(env, initInfo);
    return JNI_VERSION_1_6;
}

这段代码说明了 LSPlant 的定位：它不是一个自带所有底层能力的 “黑盒 Hook 框架”，而是把关键能力抽象成 InitInfo ，由接入方决定用 Dobby、xHook、ByteHook 或其他方案来做 inline hook，也由接入方决定怎样解析 libart.so 。

InitInfo 对外配置

文件： lsplant/src/main/jni/include/lsplant.hpp

namespace lsplant {
inline namespace v2 {

struct InitInfo {
    // inline hook 函数类型：
    // target 是要被 hook 的 ART 内部函数；
    // hooker 是 LSPlant 提供的替换函数；
    // 返回值是原始函数入口，用作 backup。
    using InlineHookFunType = std::function<void *(void *target, void *hooker)>;

    // inline unhook 函数类型：
    // func 是之前被 hook 的目标函数。
    using InlineUnhookFunType = std::function<bool(void *func)>;

    // 精确解析 libart.so 符号。
    using ArtSymbolResolver = std::function<void *(std::string_view symbol_name)>;

    // 按前缀解析 libart.so 符号。
    // 某些 ART 内部函数在不同版本上 mangled name 只差参数类型。
    using ArtSymbolPrefixResolver = std::function<void *(std::string_view symbol_prefix)>;

    // 可选：由调用方分配可执行内存，用于 trampoline。
    using MemoryAllocator = std::function<void *(std::span<const uint8_t> data)>;

    // 可选：回收调用方分配的可执行内存。
    using MemoryRecycler = std::function<void(void *memory)>;

    InlineHookFunType inline_hooker;
    InlineUnhookFunType inline_unhooker;
    ArtSymbolResolver art_symbol_resolver;
    ArtSymbolPrefixResolver art_symbol_prefix_resolver;

    // Hook 时生成的 stub class 默认名前缀。
    std::string_view generated_class_name = "LSPHooker_";

    // 生成 Dex 的 source file name，可为空。
    std::string_view generated_source_name = "LSP";

    // 生成类里用于保存 hooker_object 的静态字段名。
    std::string_view generated_field_name = "hooker";

    // 生成方法名。"{target}" 表示跟随目标方法名。
    std::string_view generated_method_name = "{target}";

    MemoryAllocator executable_memory_allocator;
    MemoryRecycler executable_memory_recycler;
};

这里有三个容易忽略的点：

  1. InitInfo 的 hooker/resolver 都是 std::function ，接入方可以用 lambda，但 executable memory allocator 注释要求不能依赖捕获状态。
  2. art_symbol_prefix_resolver 在当前 Init() 实现里也被要求非空，否则直接返回 false。
  3. generated_* 不只是调试用名字，它们会影响运行时生成的 Dex stub 类、字段和方法。

Init 的三段式初始化

文件： lsplant/src/main/jni/lsplant.cc

inline namespace v2 {
extern "C++" {

bool Init(JNIEnv *env, const InitInfo &info) {
    // 四个基础能力必须存在：
    // 1. inline hook
    // 2. inline unhook
    // 3. 精确 ART 符号解析
    // 4. 前缀 ART 符号解析
    if (!info.inline_hooker ||
        !info.inline_unhooker ||
        !info.art_symbol_resolver ||
        !info.art_symbol_prefix_resolver) {
        return false;
    }

    // static 局部变量保证 Init 主体只执行一次。
    // 如果第一次初始化失败，后续调用也会返回这个失败结果。
    bool static kInit =
        InitConfig(info) &&
        InitJNI(env) &&
        InitNative(env, info);

    return kInit;
}

}  // extern "C++"
}  // namespace v2

Init() 的顺序很重要：

InitConfig(info)
  -> 校验并保存 LSPlant 自身配置

InitJNI(env)
  -> 解析 Java 反射、ClassLoader、DexFile、AccessibleObject 等 JNI ID

InitNative(env, info)
  -> 使用 HookHandler 解析/Hook ART 内部函数，初始化 ArtMethod、Runtime、ClassLinker、JIT 等模块

如果 InitConfig 没保存生成类名，后面的 BuildDex() 不知道 stub 要叫什么；如果 InitJNI 没缓存 Executable.getName() 、 Class.getClassLoader() 等 ID， Hook() 生成 stub 时拿不到目标方法信息；如果 InitNative 没完成， ArtMethod::FromReflectedMethod() 、 SetEntryPoint() 、 ClassLinker::SetEntryPointsToInterpreter() 等操作都没有可靠基础。

InitConfig：保存生成 stub 和 trampoline 配置

文件： lsplant/src/main/jni/lsplant.cc

bool InitConfig(const InitInfo &info) {
    // 生成类名不能为空，否则 DexBuilder 无法创建合法 class descriptor。
    if (info.generated_class_name.empty()) {
        LOGE("generated class name cannot be empty");
        return false;
    }

    // 生成字段名不能为空。Hook 时会把 hooker_object 存到这个 static field。
    if (info.generated_field_name.empty()) {
        LOGE("generated field name cannot be empty");
        return false;
    }

    // 生成方法名不能为空。"{target}" 会在 BuildDex 阶段替换为目标方法名。
    if (info.generated_method_name.empty()) {
        LOGE("generated method name cannot be empty");
        return false;
    }

    // 如果接入方自定义可执行内存分配器，也必须提供回收器。
    if (info.executable_memory_allocator && !info.executable_memory_recycler) {
        LOGE("executable memory recycler cannot be null");
        return false;
    }

    // 保存到 lsplant.cc 的匿名命名空间全局变量，供 Hook()/BuildDex() 使用。
    generated_class_name = info.generated_class_name;
    generated_field_name = info.generated_field_name;
    generated_method_name = info.generated_method_name;
    generated_source_name = info.generated_source_name;
    executable_memory_allocator = info.executable_memory_allocator;
    executable_memory_recycler = info.executable_memory_recycler;

    return true;
}

InitConfig 不访问 ART，也不访问 Java class。它只保存 LSPlant 自身运行所需的配置：

  • generated_class_name ：生成 hook stub 类名前缀；
  • generated_field_name ：生成类里保存 hooker_object 的静态字段；
  • generated_method_name ：生成 hook/backup 方法名；
  • generated_source_name ：生成 Dex 的 source name；
  • executable_memory_allocator/recycler ：自定义 trampoline 内存管理。

如果你只是阅读 Hook 主流程，很容易忽略这一步。但 Hook() 里 BuildDex() 能动态生成和目标方法签名兼容的 stub，正是依赖这些配置。

InitJNI：缓存 Java 反射和 Dex 加载入口

bool InitJNI(JNIEnv *env) {
    int sdk_int = GetAndroidApiLevel();

    // Android 8.0 起 Method/Constructor 共同父类是 Executable；
    // 更老版本走 AbstractMethod。
    if (sdk_int >= kSdkOreo) {
        executable = JNI_NewGlobalRef(
            env,
            JNI_FindClass(env, "java/lang/reflect/Executable")
        );
    } else {
        executable = JNI_NewGlobalRef(
            env,
            JNI_FindClass(env, "java/lang/reflect/AbstractMethod")
        );
    }
    if (!executable) {
        LOGE("Failed to find Executable/AbstractMethod");
        return false;
    }

    // 后续 Hook() 需要读取目标方法名、声明类、参数类型、返回类型。
    method_get_name =
        JNI_GetMethodID(env, executable, "getName", "()Ljava/lang/String;");
    method_get_declaring_class =
        JNI_GetMethodID(env, executable, "getDeclaringClass", "()Ljava/lang/Class;");
    method_get_parameter_types =
        JNI_GetMethodID(env, executable, "getParameterTypes", "()[Ljava/lang/Class;");

    // getReturnType 在 java.lang.reflect.Method 上，不在 Constructor 上。
    method_get_return_type =
        JNI_GetMethodID(
            env,
            JNI_FindClass(env, "java/lang/reflect/Method"),
            "getReturnType",
            "()Ljava/lang/Class;"
        );

    auto clazz = JNI_FindClass(env, "java/lang/Class");

    // 获取 callback class loader，用它加载运行时生成的 stub Dex。
    class_get_class_loader =
        JNI_GetMethodID(env, clazz, "getClassLoader", "()Ljava/lang/ClassLoader;");

    // MakeClassInheritable() 需要遍历构造器并调整 access flags。
    class_get_declared_constructors =
        JNI_GetMethodID(
            env,
            clazz,
            "getDeclaredConstructors",
            "()[Ljava/lang/reflect/Constructor;"
        );

    class_get_name = JNI_GetMethodID(env, clazz, "getName", "()Ljava/lang/String;");

    // 注意：Class.accessFlags 不是稳定公开 API。
    class_access_flags = JNI_GetFieldID(env, clazz, "accessFlags", "I");

    // 老版本 Dex 加载 fallback 需要 PathClassLoader。
    auto path_class_loader = JNI_FindClass(env, "dalvik/system/PathClassLoader");
    path_class_loader_init =
        JNI_GetMethodID(
            env,
            path_class_loader,
            "<init>",
            "(Ljava/lang/String;Ljava/lang/ClassLoader;)V"
        );

    auto dex_file_class = JNI_FindClass(env, "dalvik/system/DexFile");

    // Android 10+ DexFile 构造函数可以接收 ByteBuffer[]、ClassLoader 和 Element[]。
    if (sdk_int >= kSdkQ) {
        dex_file_init_with_cl =
            JNI_GetMethodID(
                env,
                dex_file_class,
                "<init>",
                "([Ljava/nio/ByteBuffer;Ljava/lang/ClassLoader;[Ldalvik/system/DexPathList$Element;)V"
            );
    } else if (sdk_int >= kSdkOreo) {
        dex_file_init =
            JNI_GetMethodID(env, dex_file_class, "<init>", "(Ljava/nio/ByteBuffer;)V");
    }

    // 运行时生成的 Dex 最终通过 DexFile.loadClass 变成 Class。
    load_class =
        JNI_GetMethodID(
            env,
            dex_file_class,
            "loadClass",
            "(Ljava/lang/String;Ljava/lang/ClassLoader;)Ljava/lang/Class;"
        );

    // backup Method 需要 setAccessible(true)，否则反射调用可能失败。
    auto accessible_object = JNI_FindClass(env, "java/lang/reflect/AccessibleObject");
    set_accessible =
        JNI_GetMethodID(env, accessible_object, "setAccessible", "(Z)V");

    // 原源码每一步都会检查空指针并打印具体错误；
    // 这里为了阅读省略重复的 if (!id) return false。
    return true;
}

InitJNI 做的是 “Java 世界的准备工作”。它关心的不是 quick entry，而是后续 Hook() 需要怎样从 Method/Constructor 拿元信息、怎样加载生成的 Dex、怎样让 backup 可反射调用。

InitNative：把 ART 模块逐个接起来

文件： lsplant/src/main/jni/lsplant.cc

bool InitNative(JNIEnv *env, const HookHandler &handler) {
    // 解析 ArtMethod 布局：大小、entrypoint offset、access flags offset 等。
    if (!ArtMethod::Init(env, handler)) {
        LOGE("Failed to init art method");
        return false;
    }

    // trampoline 机器码模板里有一个“entrypoint 偏移”的占位位段；
    // ArtMethod::Init 算出真实偏移后，这里把模板补上。
    UpdateTrampoline(ArtMethod::GetEntryPointOffset());

    // 解析当前线程相关符号。
    if (!Thread::Init(handler)) return false;

    // mirror::Class 适配，用于 ClassDef、类状态、静态 trampoline 修复。
    if (!Class::Init(handler)) return false;

    // Runtime::instance_ 和 debuggable state。
    if (!Runtime::Init(handler)) return false;

    // ClassLinker、解释器入口、native 注册传播、FixupStaticTrampolines。
    if (!ClassLinker::Init(env, handler)) return false;

    // Stop-the-world 和 GC critical section，Hook/UnHook 时保护 ArtMethod 修改。
    if (!ScopedSuspendAll::Init(handler)) return false;
    if (!ScopedGCCriticalSection::Init(handler)) return false;

    // JIT 相关模块，处理编译、代码缓存和 obsolete method 迁移。
    if (!JitCodeCache::Init(handler)) return false;
    if (!Jit::Init(handler)) return false;

    // DexFile trusted 标记和动态 Dex 相关能力。
    if (!DexFile::Init(env, handler)) return false;

    // Java debuggable 或 instrumentation 场景下，防止 ART 重写 hooked method code。
    if (!Instrumentation::Init(env, handler)) return false;

    // Android 新版本 jmethodID 编码管理。
    if (!JniIdManager::Init(env, handler)) return false;

    // 如果当前运行时是 Java debuggable，LSPlant 会临时改为 non-debuggable，
    // 用于规避某些 ShouldUseInterpreterEntrypoint 内联后的行为。
    if (IsJavaDebuggable(env)) {
        Runtime::Current()->SetJavaDebuggable(
            Runtime::RuntimeDebugState::kNonJavaDebuggable
        );
    }

    return true;
}

InitNative 是 LSPlant 架构图里 “Android 运行时 ART” 那一层的集中入口。每个 xxx::Init(handler) 的风格都差不多：

用 "_ZN...Ev"_sym 描述一个 ART 内部符号
  -> handler 通过 art_symbol_resolver 找地址
  -> 如果是普通函数/字段，保存成可调用对象
  -> 如果是需要拦截的函数，调用 inline_hooker，保存 backup

C++20 编译期字符串： "_sym" 怎样变成符号对象

文件： lsplant/src/main/jni/include/utils/hook_helper.hpp

template <size_t N, char... Cs>
struct FixedString {
    // 在编译期把字符包变成 std::string_view。
    // N 是不含额外 '\0' 的长度，Cs 是字符串字面量里的每个字符。
    static constexpr auto data = [] consteval {
        static constexpr auto kString = std::array{Cs...};
        return std::string_view{kString.data(), N};
    }();
};

template <FixedString Sym, typename Ret, typename... Args>
struct Function<Sym, Ret(Args...)> {
    // 调用时转发到解析出的函数指针。
    static Ret operator()(Args... args) {
        return inner_.function_(std::forward<Args>(args)...);
    }

    // 判断符号是否解析成功。
    operator bool() const {
        return inner_.raw_function_ != nullptr;
    }

    // handler 解析出 void* 后，通过赋值写入 union。
    auto &operator=(void *function) const {
        inner_.raw_function_ = function;
        return *this;
    }

private:
    inline static union {
        Ret (*function_)(Args...);
        void *raw_function_ = nullptr;
    } inner_;
};

template <FixedString S>
struct Symbol {
    template <typename T>
    inline static decltype([] {
        if constexpr (FuncType<T>) {
            // 函数符号：Symbol<"...">.as<Ret(Args...)>
            return Function<S, T>{};
        } else {
            // 字段符号：Symbol<"...">.as<FieldType>
            return Field<S, T>{};
        }
    }()) as{};

    // .hook 用于生成 Hooker，后面配合 ->* lambda 使用。
    [[no_unique_address]] struct Hook {
        template <typename F>
        consteval auto operator->*(F &&) const {
            // 原源码这里会从 lambda 模板参数中推导 backup 签名，
            // 再构造 Hooker<S, Signature>。
        }
    } hook;
};

template <typename T, T... Cs>
    requires(std::is_same_v<T, char>)
consteval auto operator""_sym() {
    // 让 "_ZN3art..."_sym 在编译期变成 Symbol<FixedString<...>>。
    // 这不是运行时字符串 map，而是类型级符号描述。
    return Symbol<FixedString<sizeof...(Cs), Cs..., T{}>{}>{};
}

template <FixedString S, FixedString P>
consteval auto operator|(Symbol<S>, Symbol<P>) {
    // 同一个 ART 函数在 32 位和 64 位上可能 mangled name 不同。
    // 用 "|" 在编译期选择当前 ABI 对应的符号。
    if constexpr (is_arch_v<Arch::kLP64>) {
        return Symbol<P>{};
    } else {
        return Symbol<S>{};
    }
}

这段代码的目标不是 “炫技”，而是解决三个工程问题：

  1. ART 私有符号很多，写成运行时字符串表容易把签名、类型和 hook 逻辑分散。
  2. 同一符号需要绑定具体 C++ 函数签名，否则调用时全是 reinterpret_cast 。
  3. 某些符号需要 inline hook，替换函数还要拿到类型正确的 backup。

有了这个 DSL，ART 模块里就可以写成下面这样。

template <FixedString Sym, typename... Us, template <FixedString, typename...> typename T>
bool handle(const T<Sym, Us...> &hooker, bool match_prefix) const {
    // 1. 解析 ART 原函数地址。
    void *original = dlsym<Sym>(match_prefix);

    // 2. 调用 InitInfo.inline_hooker(original, replacement)。
    // 3. 返回的 backup 地址写回 hooker。
    return hooker = hook(hooker.address_ = original,
                         reinterpret_cast<void *>(hooker.replace_));
}

}

生成 trampoline 时，LSPlant 会把 hook 方法的 ArtMethod* 写进模板，再把整段字节复制到可执行内存：

void *GenerateTrampolineFor(art::ArtMethod *hook) {
    // 拷贝当前 ABI 的 trampoline 模板。
    auto data = trampoline;

    // 把 hook ArtMethod* 写入模板占位位置。
    *reinterpret_cast<ArtMethod **>(data.data() + art_method_offset) = hook;

    // 如果接入方提供了可执行内存分配器，优先使用接入方实现。
    if (executable_memory_allocator) {
        if (auto *memory = static_cast<char *>(executable_memory_allocator(data))) {
            __builtin___clear_cache(memory, memory + data.size());
            return memory;
        }
    }

    // 否则 LSPlant 自己 mmap 一页可执行内存，并在页内切分多个 trampoline。
    // 原源码包含 4K/16K page size、dual mapping、cache flush 等细节。
    void *memory = AllocateMemory();
    std::memcpy(memory, data.data(), data.size());
    __builtin___clear_cache(
        static_cast<char *>(memory),
        static_cast<char *>(memory) + data.size()
    );
    return memory;
}

"_uarr" 的价值和 "_sym" 类似：把运行时容易出错的字节长度、数组类型、ABI 分支提前到编译期处理。这样 GetTrampoline() 返回的就是 “当前 ABI 的机器码模板 + 两个偏移值”，后续逻辑不需要再判断字符串长度。

Hook 主流程怎样使用初始化结果

文件： lsplant/src/main/jni/lsplant.cc

jobject Hook(
    JNIEnv *env,
    jobject target_method,
    jobject hooker_object,
    jobject callback_method
) {
    // target_method 和 callback_method 必须是 Method/Constructor。
    if (!target_method || !JNI_IsInstanceOf(env, target_method, executable)) {
        return nullptr;
    }
    if (!callback_method || !JNI_IsInstanceOf(env, callback_method, executable)) {
        return nullptr;
    }

    // 从反射 Method/Constructor 转成 ART 内部 ArtMethod*。
    auto *target = ArtMethod::FromReflectedMethod(env, target_method);
    bool is_static = target->IsStatic();

    if (IsHooked(target, true)) {
        return nullptr;
    }

    // 读取 callback 方法名、目标方法名、callback 声明类、class loader。
    // 这些 jmethodID 都是在 InitJNI 中缓存的。
    auto callback_name =
        JNI_Cast<jstring>(JNI_CallObjectMethod(env, callback_method, method_get_name));
    JUTFString callback_method_name(callback_name);

    auto target_name =
        JNI_Cast<jstring>(JNI_CallObjectMethod(env, target_method, method_get_name));
    JUTFString target_method_name(target_name);

    auto callback_class =
        JNI_Cast<jclass>(JNI_CallObjectMethod(env, callback_method, method_get_declaring_class));
    auto callback_class_loader =
        JNI_CallObjectMethod(env, callback_class, class_get_class_loader);

    // BuildDex 会生成一个类：
    // - static field 保存 hooker_object
    // - hook method 调用 hooker_object.callback(Object[] args)
    // - backup method 保存原始 ArtMethod 副本
    auto [built_class, hooker_field, hook_method, backup_method] =
        BuildDex(
            env,
            callback_class_loader.get(),
            ArtMethod::GetMethodShorty(env, target_method),
            is_static,
            target->IsConstructor() ? "constructor" : target_method_name.get(),
            /* hooker_class */ "...",
            callback_method_name.get()
        );

    auto reflected_hook =
        JNI_ToReflectedMethod(env, built_class, hook_method, JNI_TRUE);
    auto reflected_backup =
        JNI_ToReflectedMethod(env, built_class, backup_method, JNI_TRUE);

    // backup 需要允许 Java 反射调用。
    JNI_CallVoidMethod(env, reflected_backup, set_accessible, JNI_TRUE);

    auto *hook = ArtMethod::FromReflectedMethod(env, reflected_hook.get());
    auto *backup = ArtMethod::FromReflectedMethod(env, reflected_backup.get());

    // 生成类的 static hooker 字段指向 Java 层 Hooker 对象。
    JNI_SetStaticObjectField(env, built_class, hooker_field, hooker_object);

    if (DoHook(target, hook, backup)) {
        jobject global_backup = JNI_NewGlobalRef(env, reflected_backup);
        RecordHooked(target, target->GetDeclaringClass()->GetClassDef(), global_backup, backup);
        return global_backup;
    }

    return nullptr;
}

Hook() 自己并不解析 Executable.getName() ，也不现场查 DexFile.loadClass() ，更不现场寻找 Runtime::instance_ 。这些昂贵且容易失败的准备工作都已经在 InitJNI 和 InitNative 里完成。

真正修改入口的是 DoHook() ：

bool DoHook(ArtMethod *target, ArtMethod *hook, ArtMethod *backup) {
    // 暂停线程并进入 GC critical section，降低修改 ArtMethod 时的并发风险。
    ScopedGCCriticalSection section(
        art::Thread::Current(),
        art::gc::kGcCauseDebugger,
        art::gc::kCollectorTypeDebugger
    );
    ScopedSuspendAll suspend("LSPlant Hook", false);

    // 为 hook ArtMethod 生成 quick entry trampoline。
    auto *entrypoint = GenerateTrampolineFor(hook);
    if (!entrypoint) {
        return false;
    }

    // intrinsic 方法需要先清理 intrinsic 标记，否则 ART 可能走特殊内联路径。
    target->SetNonIntrinsic();

    // 把 target 当前内容复制到 backup，让 backup 保留原始逻辑。
    target->BackupTo(backup);

    // 阻止目标方法继续被编译器优化。
    target->SetNonCompilable();

    // 把 target quick entry 改成 LSPlant trampoline。
    target->SetEntryPoint(entrypoint);

    return true;
}

这就是 “初始化” 和 “Hook” 之间的关系：

InitConfig
  -> 决定生成 stub 的类名/字段名/方法名，以及 trampoline 内存策略

InitJNI
  -> 提供 Hook() 读取反射信息、加载 stub Dex、设置 accessible 所需的 JNI ID

InitNative
  -> 提供 ArtMethod 布局、Runtime、ClassLinker、JIT、Instrumentation 等底层能力

Hook
  -> 生成 stub Dex
  -> reflected Method 转 ArtMethod*
  -> 生成 trampoline
  -> 复制 target 到 backup
  -> target->SetEntryPoint(trampoline)

文件： test/src/main/java/org/lsposed/lsplant/Hooker.java

public class Hooker {
    // callback 收到的上下文：backup 和参数数组。
    // 注意：当前源码里这个类是包可见的 static class；
    // instrumentation test 跨 APK/classloader 访问时可能触发 IllegalAccessError。
    static class MethodCallback {
        Method backup;
        Object[] args;

        MethodCallback(Method backup, Object[] args) {
            this.backup = backup;
            this.args = args;
        }
    }

    // LSPlant Hook() 返回的 backup Method。
    public Method backup;

    private Member target;
    private Method replacement;
    private Object owner = null;

    private native Method doHook(Member original, Method callback);
    private native boolean doUnhook(Member target);

    public Object callback(Object[] args)
            throws InvocationTargetException, IllegalAccessException {
        // 把 backup 和本次调用参数包装后交给 replacement。
        var methodCallback = new MethodCallback(backup, args);
        return replacement.invoke(owner, methodCallback);
    }

    public boolean unhook() {
        return doUnhook(target);
    }

    public static Hooker hook(Member target, Method replacement, Object owner) {
        Hooker hooker = new Hooker();
        try {
            // Native 层要求 callback 形态是 Object callback(Object[] args)。
            var callbackMethod = Hooker.class.getDeclaredMethod("callback", Object[].class);
            var result = hooker.doHook(target, callbackMethod);
            if (result == null) return null;

            hooker.backup = result;
            hooker.target = target;
            hooker.replacement = replacement;
            hooker.owner = owner;
        } catch (NoSuchMethodException ignored) {
        }
        return hooker;
    }
}

原理分析

为什么 InitJNI 要在 JNI_OnLoad 做

LSPlant 的头文件注释里明确提示： Init() 的 JNIEnv* 不应受到 hidden API 访问限制，通常可以在 JNI_OnLoad() 中获得。

原因是 InitJNI 会访问一些非 SDK 或版本敏感成员，例如：

  • java.lang.Class.accessFlags ；
  • dalvik.system.DexFile 的非公开构造形态；
  • 反射对象里的 artMethod 字段；
  • ART 内部符号对应的 native 函数。

如果你晚到普通业务线程再初始化，可能遇到 hidden API 策略、类加载时机、ClassLoader 选择、异常未清理等问题。放在 JNI_OnLoad 能尽早拿到稳定的 JNIEnv* ，也能在 Java 层调用 Hooker.hook() 前完成所有缓存。

为什么要动态生成 Dex stub

LSPlant 的 callback 统一要求形态类似：

Object callback(Object[] args)

但目标 Java 方法可能是：

static boolean staticMethod()
String normalMethod(String a, int b, long c)
void <init>()
String interfaceProxyMethod(String a, boolean b, ...)

这些方法的参数、返回值、是否 static、是否 constructor 都不同。直接把所有目标方法都跳到同一个 Java callback，ART 调用约定和 Java 方法签名对不上。

所以 LSPlant 用 DexBuilder 运行时生成一个签名兼容的 stub：

目标方法签名：
  boolean staticMethod()

生成 hook stub：
  boolean staticMethod() {
      return ((Boolean) hooker.callback(new Object[]{})).booleanValue();
  }

生成 backup stub：
  boolean staticMethod() {
      // ArtMethod 内容会被替换为 target 原始副本
  }

真实生成代码不是 Java 源码，而是 DexBuilder 直接构造 Dex。这样做的好处是：

  • Java 层 callback 形态统一；
  • ART 看到的 hook method 签名和 target 兼容；
  • backup 可以作为反射 Method 返回给调用方；
  • 不需要用户为每个被 Hook 方法手写 JNI bridge。

为什么要解析 ArtMethod 布局

ArtMethod 是 ART 内部结构，不同 Android 版本布局不同。LSPlant 没法用稳定 SDK API 修改 quick entry，所以 ArtMethod::Init() 会用一组运行时探测策略：

// 文件：lsplant/src/main/jni/art/runtime/art_method.cxx

auto first_ctor = constructors[0];
auto second_ctor = constructors[1];

// 同一个类的两个构造器在内存中通常连续排列，
// 两个 ArtMethod* 的差值可用于估算 ArtMethod 大小。
auto *first = FromReflectedMethod(env, first_ctor.get());
auto *second = FromReflectedMethod(env, second_ctor.get());
art_method_size =
    reinterpret_cast<uintptr_t>(second) -
    reinterpret_cast<uintptr_t>(first);

// 新版本通常把 quick entry 放在 ArtMethod 尾部。
entry_point_offset = art_method_size - kPointerSize;
data_offset = entry_point_offset - kPointerSize;

这不是公开协议，只是对 ART 当前实现的适配策略。文章开头强调 “不要跨版本硬套” 主要就是因为这些地方。

为什么需要 ClassLinker 和 JIT 适配

只改 target->SetEntryPoint(trampoline) 并不够。ART 可能在这些时机重新影响入口：

  • 类初始化后 ClassLinker::FixupStaticTrampolines 修复静态方法入口；
  • JIT 编译后 quick code 入口变化；
  • instrumentation/debuggable 场景让方法走解释器；
  • native 方法注册 / 反注册时 ArtMethod::data 或 entrypoint 改变；
  • 某些方法被 inline，调用方根本不再调用目标方法入口。

所以 InitNative 会初始化 ClassLinker 、 Jit 、 JitCodeCache 、 Instrumentation 等模块。LSPlant 的思路不是 “一次写 entrypoint 就结束”，而是在 ART 可能移动或重写入口的地方记录并传播 target/backup 关系。

C++20 编译期字符串的设计收益

以 Runtime::instance_ 为例，传统写法可能是：

auto addr = resolver("_ZN3art7Runtime9instance_E");
auto instance = reinterpret_cast<Runtime **>(addr);

LSPlant 写成：

inline static auto instance_ =
    "_ZN3art7Runtime9instance_E"_sym.as<Runtime *>;

handler(instance_);

收益是：

  • 符号名和类型绑定在同一个声明上；
  • 字段、函数、成员函数、hooker 都复用同一套 Symbol ；
  • 32 位 / 64 位符号差异可以用编译期 operator| 选择；
  • hook replacement 的 backup 签名能由模板约束推导出来；
  • InitNative 读起来像 “声明我需要哪些 ART 能力”，而不是散落一堆字符串和强转。

代价也很明确：

  • 模板错误信息更难读；
  • 对编译器、CMake、NDK 版本要求更高；
  • 新同学需要先理解 FixedString 、NTTP、 consteval 、C++ modules。

常见错误与排查

IllegalAccessError: UnitTest attempting to access Hooker$MethodCallback

现象：

UnitTest > t01_staticMethod FAILED
java.lang.IllegalAccessError:
  Illegal class access: UnitTest attempting to access Hooker$MethodCallback

原因：

Hooker.MethodCallback 在当前源码中是包可见嵌套类。 UnitTest 位于 androidTest APK，被测类位于 app APK。即使 Java 包名相同，运行时也可能因为不同 APK/classloader 不属于同一个 runtime package，从而不能访问包可见类型。

修复方式一：把测试里对 Hooker.MethodCallback.class 的直接引用改成反射加载，避免 verifier 对包可见类型做直接访问检查。

// 文件：test/src/androidTest/java/org/lsposed/lsplant/UnitTest.java

private static Class<?> methodCallbackClass() throws ClassNotFoundException {
    // 使用被测 APK 的 classloader 加载 Hooker$MethodCallback。
    return Class.forName(
            "org.lsposed.lsplant.Hooker$MethodCallback",
            false,
            LSPTest.class.getClassLoader()
    );
}

  • 先确认是否确实需要 x86 设备或模拟器；如果只在 arm64 真机复现，可以先限定 ABI。
  • 检查 test/src/main/jni/CMakeLists.txt 是否正确链接 lsplant::lsplant 。
  • 检查 Prefab imported target 在该 ABI 下是否包含实际 native library，而不只是 headers/module interface。
  • 清理 .cxx 和 Gradle 构建缓存后重新构建，避免 C++ module 扫描缓存导致 target 属性异常。

Init() 返回 false

常见原因：

  • inline_hooker 、 inline_unhooker 、 art_symbol_resolver 、 art_symbol_prefix_resolver 有任意一个为空。
  • xDL 没有打开 libart.so ，或符号解析函数只查 .dynsym ，没有查 .symtab 。
  • 当前 Android 版本的 ART mangled name 和源码里的符号不一致。
  • InitJNI 访问隐藏字段或构造函数失败，例如 Class.accessFlags 、 DexFile.<init> 。
  • 当前进程 hidden API 策略、ClassLoader、ROM 裁剪影响了反射 / JNI 查找。

建议排查：

adb logcat -s LSPlant:D LSPlant-test:D '*:S'

重点看：

Failed to find Executable/AbstractMethod
Failed to find Class.accessFlags
Failed to find DexFile.<init>
Failed to init art method
Failed to init class linker
Failed to init jni id manager

Hook 成功但目标方法没变化

可能原因：

  • 调用方已经 inline 了目标方法，后续不再经过目标方法 entrypoint。
  • 目标方法是 intrinsic，ART 走了特殊优化路径。
  • 类还没初始化，后续 FixupStaticTrampolines 改写了入口。
  • JIT 编译或代码缓存回收移动了入口。
  • Hook 了 proxy/native/constructor 等特殊方法，需要走对应适配分支。

对应思路：

  • 对调用方使用 Deoptimize() ，而不只是对被 Hook 方法操作。
  • 确认 target->SetNonIntrinsic() 执行成功。
  • 看 ClassLinker 、 JitCodeCache 、 Instrumentation 初始化是否成功。
  • 对未初始化类的静态方法，参考 t05_uninitializedStaticMethod 的测试形态。

DobbyHook 失败或进程崩溃

常见原因：

  • 目标页没有成功改成可写可执行；
  • SELinux、内核策略或 ROM 加固限制 RWX；
  • inline hook 目标函数太短或指令形态不被当前 Dobby 版本支持；
  • ABI 不匹配；
  • hook 了 ART 过早或过晚的时机。

排查方向：

  • 检查 _make_rwx() 返回值，不要忽略 mprotect 错误。
  • 先只跑 t00_init ，确认初始化成功。
  • 再跑单个测试，例如静态方法 Hook。
  • 用 adb logcat 看 native crash backtrace。
  • 换 arm64 真机复现，减少 x86 模拟器 ABI 差异。

C++ modules 相关构建错误

可能现象：

module 'lsplant' not found

IMPORTED_CXX_MODULES_COMPILE_FEATURES

排查方向：

  • 确认 CMake 版本满足 3.28.0+ 。
  • 确认 NDK 版本为 29.0.14206865 或兼容版本。
  • 确认 test/src/main/jni/CMakeLists.txt 已把 LSPlant 的 .ixx 文件加入 imported target 的 FILE_SET CXX_MODULES 。
  • 清理 .cxx 目录后重建。

总结

LSPlant 的源码可以按这条主线理解：

InitInfo
  -> 接入方提供 inline hook、unhook、ART 符号解析和可选内存分配

InitConfig
  -> 保存生成 Dex stub 和 trampoline 内存策略

InitJNI
  -> 缓存 Java 反射、ClassLoader、DexFile、AccessibleObject 入口

InitNative
  -> 解析/Hook ART 内部模块：ArtMethod、Runtime、ClassLinker、JIT、Instrumentation

Hook
  -> 生成签名兼容的 Dex stub
  -> 拿到 target/hook/backup ArtMethod
  -> 生成 trampoline
  -> 复制 target 到 backup
  -> 改写 target quick entry

本文还重点拆了两类 C++20 编译期字符串技术：

  • "_sym" ：把 ART 符号名变成类型级 Symbol<FixedString<...>> ，再通过 .as<签名> 或 .hook->*lambda 绑定字段、函数和 inline hook。
  • "_uarr" ：把机器码字面量变成 std::array<uint8_t, N> ，按 ABI 在编译期选择 trampoline 模板。
