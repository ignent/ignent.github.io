环境搭建

ZIP2026/6/11...大约 2 分钟XposedLSPosedAndroid

从 Native C++ 开始做一个可被 Xposed/LSPosed 识别的模板

1. 新建项目

在 Android Studio 里选择 Native C++ 模板。

  • Name 项目名。通常也会影响默认应用名和项目目录名。

  • Package name Java 包名，也是后面 namespace / applicationId 的基础。

  • Save location 项目保存路径。 只是决定工程放在哪，不影响模块功能。

  • Language 生成的 Android 入口代码语言。

  • Minimum SDK 应用最低支持的 Android 版本。 API 24 ，对应 minSdk = 24 。

  • Build configuration language Gradle 脚本用什么语法。 Kotlin DSL (build.gradle.kts) ，所以构建文件是 .kts 。

创建完成后，Native C++ 模板会生成这些基础文件：

  • app/src/main/java/com/xposed/MainActivity.java
  • app/src/main/cpp/native-lib.cpp
  • app/src/main/cpp/CMakeLists.txt

说明：

  • Native C++ 只是项目起点
  • 如果后面要写 so、JNI、native hook，这个模板更顺手

2. 接入 Xposed API

settings.gradle.kts

加上 Xposed 仓库：

dependencyResolutionManagement {
    repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
    repositories {
        google()
        mavenCentral()
        maven(url = "https://api.xposed.info/")
    }
}

gradle/libs.versions.toml

增加版本和依赖：

[versions]
api = "82"

[libraries]
api = { module = "de.robv.android.xposed:api", version.ref = "api" }

app/build.gradle.kts

只需要编译期依赖：

dependencies {
    compileOnly(libs.api)
}

compileOnly 的作用：

  • 编译时能找到 Xposed API
  • 打包时不会把 Xposed API 塞进 APK

项目对应位置：

  • settings.gradle.kts
  • gradle/libs.versions.toml
  • app/build.gradle.kts

3. 声明成 Xposed 模块

app/src/main/AndroidManifest.xml

在 <application> 里加入：

<meta-data
    android:name="xposedmodule"
    android:value="true" />
<meta-data
    android:name="xposeddescription"
    android:value="插件描述" />
<meta-data
    android:name="xposedminversion"
    android:value="82" />
<meta-data
    android:name="xposedscope"
    android:resource="@array/xposedscope" />

这些项的作用：

  • xposedmodule 告诉框架 “这是模块”。

  • xposeddescription 模块说明，会显示在管理器里。

  • xposedminversion 模块声明的最低 Xposed API 版本。

  • xposedscope 给 LSPosed 一个默认推荐作用域。

app/src/main/res/values/arrays.xml

创建作用域数组：

<resources>
    <string-array name="xposedscope">
        <item>com.name.app</item>
    </string-array>
</resources>

作用：

  • 告诉 LSPosed 这个模块默认打算作用到哪个包
  • 可以写多个 <item>

app/src/main/assets/xposed_init

创建 assets 目录，再创建一个没有后缀名的文件 xposed_init ：

com.xposed.HookEntry

作用：

  • 告诉 Xposed / LSPosed 入口类是谁

app/src/main/java/com/xposed/HookEntry.java

创建一个最小入口类：


import de.robv.android.xposed.IXposedHookLoadPackage;
import de.robv.android.xposed.callbacks.XC_LoadPackage;

public class HookEntry implements IXposedHookLoadPackage {
    @Override
    public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) {
        // 先留空，做到能被识别即可
    }
}

作用：

  • 这是模块真正的 Java 入口

4. 做到这里就够了

最小识别链路已经完整了：

  1. compileOnly(libs.api) 让项目能编译 Xposed 代码
  2. AndroidManifest.xml 让框架知道这是模块
  3. xposed_init 让框架知道入口类是谁
  4. HookEntry.java 让入口类真实存在
  5. arrays.xml 给 LSPosed 提供默认作用域

5. 当前模板里已经有的对应文件

项目里已经配好的关键文件是：

  • app/build.gradle.kts
  • settings.gradle.kts
  • gradle/libs.versions.toml
  • app/src/main/AndroidManifest.xml
  • app/src/main/res/values/arrays.xml
  • app/src/main/assets/xposed_init
  • app/src/main/java/com/xposed/HookEntry.java
