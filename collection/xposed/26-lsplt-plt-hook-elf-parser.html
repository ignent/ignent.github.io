PLT Hook 之 LSPlt讲解

PLT Hook 之 LSPlt 讲解：项目架构、公共 API 与 ELF 解析器初始化

概述

本文分析的是 LSPlt：一个面向 Android 的轻量 PLT Hook 库。它不像 LSPlant 那样修改 ART 的 Java 方法入口，而是从 Native ELF 的动态链接信息入手，找到目标符号对应的 PLT/GOT 重定位槽位，再把槽位里的函数指针替换成我们自己的 callback。

读完并复现本文后，你应该能完成三件事：

  1. 在自己的 Native 模块中接入 LSPlt。
  2. 通过 MapInfo::Scan() 找到目标 so 在 /proc/self/maps 里的 dev 、 inode 、 offset 。
  3. 调用 RegisterHook() 和 CommitHook() 替换目标 ELF 的 PLT 入口，并用 backup 调回原函数。

最小运行效果可以理解为：

Hook 前：
  native 调用目标导入函数 -> 进入原始实现

RegisterHook + CommitHook 后：
  native 调用目标导入函数 -> 进入 my_callback
  my_callback 内部可以通过 backup 调用原始实现

恢复时：
  再次 RegisterHook，callback 传入上一次得到的 backup
  CommitHook 后目标 PLT 入口恢复为原始函数指针

注意

PLT Hook 操作的是 ELF 动态链接结构和进程内存页权限，不是 Android SDK 稳定公开接口。不同 Android 版本、ABI、链接器策略、打包方式、RELRO、符号可见性和编译优化都会影响结果。本文适合作为源码阅读和实验复现指南，不建议把内部实现细节不加验证地跨版本套用。

核心代码

公共 API： lsplt.hpp

LSPlt 对外暴露的 API 很少，入口集中在 lsplt.hpp 。

#pragma once

#include <sys/types.h>

#include <string>
#include <string_view>
#include <vector>

namespace lsplt {
inline namespace v2 {

// MapInfo 对应 /proc/<pid>/maps 中的一行。
// LSPlt 用它描述某段进程内存映射属于哪个文件、权限是什么、起止地址在哪里。
struct MapInfo {
    // 当前映射在进程虚拟地址空间里的起始地址。
    uintptr_t start;

    // 当前映射在进程虚拟地址空间里的结束地址。
    uintptr_t end;

    // 页面权限，按位组合 PROT_READ / PROT_WRITE / PROT_EXEC。
    uint8_t perms;

    // true 表示 private mapping，对应 maps 权限字段里的 p。
    bool is_private;

    // 当前映射对应文件内偏移。
    // offset == 0 的只读映射通常可以看到 ELF Header。
    uintptr_t offset;

    // 设备号。和 inode 一起用于识别“同一个文件”。
    dev_t dev;

    // inode。只用路径匹配 so 容易受符号链接、匿名路径、APK 内加载影响。
    ino_t inode;

    // maps 行尾路径，例如 /data/app/.../lib/arm64/libdemo.so。
    std::string path;

    // 扫描 /proc/<pid>/maps，默认扫描当前进程。
    static std::vector<MapInfo> Scan(std::string_view pid = "self");
};

// 按 dev + inode 注册一个符号 Hook。
// symbol 是被 Hook 的导入符号名，例如 "clock_gettime"、"strlen"。
// callback 是替换函数指针。
// backup 用于接收原始函数指针，但只有 CommitHook 成功后才会写入。
bool RegisterHook(dev_t dev, ino_t inode, std::string_view symbol,
                  void *callback, void **backup);

// 按 dev + inode + 文件 offset 范围注册 Hook。
// 这个重载主要用于 so 直接从 APK/zip 中加载的场景。
bool RegisterHook(dev_t dev, ino_t inode, uintptr_t offset, size_t size,
                  std::string_view symbol, void *callback, void **backup);

// 提交所有已注册 Hook。
// RegisterHook 只保存意图，真正扫描 ELF、查找 PLT、写入 callback 都发生在这里。
bool CommitHook();

// 使备份映射失效，恢复到直接修改原映射的状态。
// 析构时也会自动调用，用于尽量还原内存映射。
bool InvalidateBackup();

}  // namespace v2
}  // namespace lsplt

这里有两个设计点需要先记住：

  1. RegisterHook() 不立即改内存，只把 RegisterInfo 放进待处理队列。
  2. backup 在 CommitHook() 之后才可用；如果某个符号没找到， backup 会保持为空。

最小示例：Hook 当前 so 的 clock_gettime

下面代码假设：

  • 你的 so 名为 liblsplt_demo.so 。
  • Java 层会加载 System.loadLibrary("lsplt_demo") 。
  • 该 so 内部确实通过 PLT 调用了 clock_gettime 。
  • 编译器没有把目标调用优化成静态或内联实现。
#include <android/log.h>
#include <jni.h>
#include <time.h>

#include <cstring>
#include <string_view>

#include "lsplt.hpp"

#define LOG_TAG "LSPltDemo"
#define LOGI(...) __android_log_print(ANDROID_LOG_INFO, LOG_TAG, __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, LOG_TAG, __VA_ARGS__)

namespace {

// 保存原始 clock_gettime 函数指针。
// 注意：RegisterHook 调用后它仍然是 nullptr，CommitHook 成功后才会被写入。
using clock_gettime_t = int (*)(clockid_t, struct timespec *);
clock_gettime_t g_origin_clock_gettime = nullptr;

// 替换函数。签名必须和被 Hook 的函数完全一致。
// 如果签名不一致，轻则参数错乱，重则直接崩溃。
int my_clock_gettime(clockid_t clock_id, struct timespec *ts) {
    LOGI("my_clock_gettime called, clock_id=%d", static_cast<int>(clock_id));

    // 可以选择调用原始函数，也可以完全伪造返回值。
    int ret = 0;
    if (g_origin_clock_gettime != nullptr) {
        ret = g_origin_clock_gettime(clock_id, ts);
    }

    // 为了让效果明显，把秒数改成固定值。
    if (ts != nullptr) {
        ts->tv_sec = 123456789;
    }
    return ret;
}

// 从 maps 中找当前业务 so 的 dev/inode。
// 真实项目里建议把 so 名称作为参数传入，避免硬编码。
bool FindSelfLibrary(dev_t *out_dev, ino_t *out_inode) {
    for (const auto &map : lsplt::MapInfo::Scan()) {
        // 只关心有路径的私有映射。
        if (!map.is_private || map.path.empty()) {
            continue;
        }

        // 找到当前 demo so。请替换成你自己的 so 名称。
        if (map.path.find("liblsplt_demo.so") == std::string::npos) {
            continue;
        }

        // offset == 0 的映射通常包含 ELF Header，适合作为目标 ELF 的入口。
        if (map.offset != 0) {
            continue;
        }

        *out_dev = map.dev;
        *out_inode = map.inode;
        LOGI("target map: %s dev=%lu inode=%lu",
             map.path.c_str(),
             static_cast<unsigned long>(map.dev),
             static_cast<unsigned long>(map.inode));
        return true;
    }
    return false;
}

// 触发一次 clock_gettime 调用，用来验证 Hook 前后的行为。
void PrintClock(const char *stage) {
    timespec ts{};
    int ret = clock_gettime(CLOCK_MONOTONIC, &ts);
    LOGI("%s: ret=%d sec=%lld nsec=%lld",
         stage,
         ret,
         static_cast<long long>(ts.tv_sec),
         static_cast<long long>(ts.tv_nsec));
}

}  // namespace

extern "C"
JNIEXPORT void JNICALL
Java_org_example_lspltdemo_MainActivity_runLspltDemo(JNIEnv *, jobject) {
    PrintClock("before hook");

    dev_t dev = 0;
    ino_t inode = 0;
    if (!FindSelfLibrary(&dev, &inode)) {
        LOGE("failed to find target library in /proc/self/maps");
        return;
    }

    // 注册 Hook 意图。此时不会立即写 PLT。
    bool registered = lsplt::RegisterHook(
        dev,
        inode,
        "clock_gettime",
        reinterpret_cast<void *>(my_clock_gettime),
        reinterpret_cast<void **>(&g_origin_clock_gettime));
    LOGI("RegisterHook clock_gettime => %s", registered ? "true" : "false");

    // 提交 Hook。成功后 g_origin_clock_gettime 才应该可用。
    bool committed = lsplt::CommitHook();
    LOGI("CommitHook => %s, backup=%p",
         committed ? "true" : "false",
         reinterpret_cast<void *>(g_origin_clock_gettime));

    PrintClock("after hook");

    // 恢复方式：用 backup 作为 callback 再注册一次。
    // LSPlt 会把目标槽位改回原始函数指针。
    if (g_origin_clock_gettime != nullptr) {
        void *unused_backup = nullptr;
        bool restore_registered = lsplt::RegisterHook(
            dev,
            inode,
            "clock_gettime",
            reinterpret_cast<void *>(g_origin_clock_gettime),
            &unused_backup);
        bool restored = restore_registered && lsplt::CommitHook();
        LOGI("restore => %s", restored ? "true" : "false");
    }

    PrintClock("after restore");
}

LSPlt 公共 API 接口设计

MapInfo::Scan() ：为什么不直接用 so 路径

PLT Hook 的目标不是 “某个名字”，而是 “当前进程里某个 ELF 映射的某个重定位槽位”。所以 LSPlt 用 dev + inode + offset 描述目标文件，而不是只依赖路径。

MapInfo::Scan() 的实现如下：

std::vector<MapInfo> MapInfo::Scan(std::string_view pid) {
    constexpr static auto kPermLength = 5;
    constexpr static auto kMapEntry = 7;
    std::vector<MapInfo> info;

    // 默认读取 /proc/self/maps，也可以传入其他 pid。
    auto path = "/proc/" + std::string{pid} + "/maps";
    auto maps = std::unique_ptr<FILE, decltype(&fclose)>{fopen(path.c_str(), "r"), &fclose};

    if (maps) {
        char *line = nullptr;
        size_t len = 0;
        ssize_t read;

        while ((read = getline(&line, &len, maps.get())) > 0) {
            line[read - 1] = '\0';

            uintptr_t start = 0;
            uintptr_t end = 0;
            uintptr_t off = 0;
            ino_t inode = 0;
            unsigned int dev_major = 0;
            unsigned int dev_minor = 0;
            std::array<char, kPermLength> perm{'\0'};
            int path_off;

            // 解析 maps 行：
            // start-end perms offset major:minor inode path
            if (sscanf(line, "%" PRIxPTR "-%" PRIxPTR " %4s %" PRIxPTR " %x:%x %lu %n%*s",
                       &start,
                       &end,
                       perm.data(),
                       &off,
                       &dev_major,
                       &dev_minor,
                       &inode,
                       &path_off) != kMapEntry) {
                continue;
            }

            // 跳过路径前面的空白字符。
            while (path_off < read && isspace(line[path_off])) {
                path_off++;
            }

            // 把 maps 行转换成 MapInfo。
            auto &ref = info.emplace_back(
                start,
                end,
                0,
                perm[3] == 'p',
                off,
                static_cast<dev_t>(makedev(dev_major, dev_minor)),
                inode,
                line + path_off);

            // 把 r/w/x 转成 PROT_* 位。
            if (perm[0] == 'r') ref.perms |= PROT_READ;
            if (perm[1] == 'w') ref.perms |= PROT_WRITE;
            if (perm[2] == 'x') ref.perms |= PROT_EXEC;
        }
        free(line);
    }
    return info;
}

设计重点：

字段Hook 中的作用
start/end判断某个 PLT/GOT 地址属于哪段映射
perms后续备份、重映射、写入时需要知道原始权限
is_privateLSPlt 只处理私有映射，避免污染共享文件映射
offset区分 ELF Header 映射和后续 segment 映射
dev/inode稳定识别同一个底层文件
path辅助人工定位和日志输出

RegisterHook() ：只登记，不落地

LSPlt 内部把每次注册保存为 RegisterInfo ：

struct RegisterInfo {
    // 目标 ELF 所属设备号。
    dev_t dev;

    // 目标 ELF 所属 inode。
    ino_t inode;

    // 文件 offset 范围。普通 so Hook 使用全范围；
    // APK/zip 内直接加载的 so 使用精确 offset 和 size。
    std::pair<uintptr_t, uintptr_t> offset_range;

    // 被 Hook 的导入符号名。
    std::string symbol;

    // 替换函数。
    void *callback;

    // 用于接收原始函数指针。
    void **backup;
};

普通重载：

bool RegisterHook(dev_t dev, ino_t inode, std::string_view symbol,
                  void *callback, void **backup) {
    // 参数检查：必须能定位文件，必须有符号名，必须有 callback。
    if (dev == 0 || inode == 0 || symbol.empty() || !callback) {
        return false;
    }

    const std::unique_lock lock(hook_mutex);

    // 普通 so 不限制文件 offset 范围。
    const auto &info = register_info.emplace_back(
        dev,
        inode,
        std::pair{std::numeric_limits<uintptr_t>::min(),
                  std::numeric_limits<uintptr_t>::max()},
        std::string{symbol},
        callback,
        backup);

    LOGV("RegisterHook %lu %s", info.inode, info.symbol.data());
    return true;
}

带 offset 的重载：

bool RegisterHook(dev_t dev, ino_t inode, uintptr_t offset, size_t size,
                  std::string_view symbol, void *callback, void **backup) {
    if (dev == 0 || inode == 0 || symbol.empty() || !callback) {
        return false;
    }

    const std::unique_lock lock(hook_mutex);

    // offset_range 用于定位 APK/zip 中的某个 so 条目。
    const auto &info = register_info.emplace_back(
        dev,
        inode,
        std::pair{offset, offset + size},
        std::string{symbol},
        callback,
        backup);

    LOGV("RegisterHook %lu %" PRIxPTR "-%" PRIxPTR " %s",
         info.inode,
         info.offset_range.first,
         info.offset_range.second,
         info.symbol.data());
    return true;
}

这个重载与 Android 打包方式有关。Android linker 文档说明，直接从 APK 加载的 .so 需要在 zip 中按页面对齐并以未压缩方式存储。此时 maps 中看到的底层文件可能是 APK 本身，必须用 offset 范围定位 APK 内的具体 so。

CommitHook() ：真正执行 Hook

CommitHook() 是真正的执行入口：

bool CommitHook() {
    const std::unique_lock lock(hook_mutex);

    // 没有待提交 Hook 时直接成功。
    if (register_info.empty()) {
        return true;
    }

    // 重新扫描当前进程 maps，得到最新映射状态。
    auto new_hook_info = HookInfos::ScanHookInfo();
    if (new_hook_info.empty()) {
        return false;
    }

    // 只保留和 RegisterInfo 匹配的映射。
    new_hook_info.Filter(register_info);

    // 合并已有 Hook 状态，避免重复提交时丢失 backup 和 hooks。
    new_hook_info.Merge(hook_info);
    hook_info = std::move(new_hook_info);

    // 解析 ELF，查找 PLT/GOT 槽位，写入 callback。
    return hook_info.DoHook(register_info);
}

这里体现出一个批处理设计：调用方可以连续注册多个 Hook，最后统一 CommitHook() 。这样 LSPlt 只需要集中扫描一次 maps，并且能在同一把锁里维护状态。

ELF 解析器数据结构设计

Elf 类只保存运行时 Hook 需要的信息，不做完整 ELF 反汇编，也不关心 Section Header。原因是动态链接器运行时主要依赖 Program Header 和 Dynamic Section；PLT Hook 只需要 .dynstr 、 .dynsym 、hash 表和 relocation 表。

class Elf {
    // 当前 ELF 在进程内的基地址。
    ElfW(Addr) base_addr_ = 0;

    // 装载偏移。运行时地址 = bias_addr_ + ELF 虚拟地址。
    ElfW(Addr) bias_addr_ = 0;

    // ELF Header。
    ElfW(Ehdr) *header_ = nullptr;

    // Program Header Table。
    ElfW(Phdr) *program_header_ = nullptr;

    // Dynamic Section，对应 PT_DYNAMIC。
    ElfW(Dyn) *dynamic_ = nullptr;
    ElfW(Word) dynamic_size_ = 0;

    // .dynstr：动态字符串表。
    const char *dyn_str_ = nullptr;

    // .dynsym：动态符号表。
    ElfW(Sym) *dyn_sym_ = nullptr;

    // .rel.plt 或 .rela.plt，由 DT_JMPREL / DT_PLTRELSZ 描述。
    ElfW(Addr) rel_plt_ = 0;
    ElfW(Word) rel_plt_size_ = 0;

    // .rel.dyn 或 .rela.dyn，由 DT_REL/DT_RELA 和 size 描述。
    ElfW(Addr) rel_dyn_ = 0;
    ElfW(Word) rel_dyn_size_ = 0;

    // Android 压缩 relocation，由 DT_ANDROID_REL/RELA 描述。
    ElfW(Addr) rel_android_ = 0;
    ElfW(Word) rel_android_size_ = 0;

    // SysV ELF hash。
    uint32_t *bucket_ = nullptr;
    uint32_t bucket_count_ = 0;
    uint32_t *chain_ = nullptr;

    // GNU hash 额外字段。
    uint32_t sym_offset_ = 0;
    ElfW(Addr) *bloom_ = nullptr;
    uint32_t bloom_size_ = 0;
    uint32_t bloom_shift_ = 0;

    // true 表示 PLT relocation 使用 Rela；false 表示使用 Rel。
    bool is_use_rela_ = false;

    // 构造和校验全部通过后才置 true。
    bool valid_ = false;

    uint32_t GnuLookup(std::string_view name) const;
    uint32_t ElfLookup(std::string_view name) const;
    uint32_t LinearLookup(std::string_view name) const;

public:
    // 返回符号对应的 PLT/GOT 槽位地址，注意不是函数实现地址。
    std::vector<uintptr_t> FindPltAddr(std::string_view name) const;

    // base_addr 指向 ELF Header 所在的映射起始地址。
    explicit Elf(uintptr_t base_addr);

    bool Valid() const { return valid_; }
};

几个关键字段的关系如下：

ELF Header
  -> Program Header Table
      -> PT_DYNAMIC
          -> DT_STRTAB      -> dyn_str_
          -> DT_SYMTAB      -> dyn_sym_
          -> DT_GNU_HASH    -> bloom_ / bucket_ / chain_
          -> DT_HASH        -> bucket_ / chain_
          -> DT_JMPREL      -> rel_plt_
          -> DT_PLTRELSZ    -> rel_plt_size_
          -> DT_PLTREL      -> is_use_rela_
          -> DT_REL/RELA    -> rel_dyn_
          -> DT_ANDROID_REL -> rel_android_

System V ABI 对 Dynamic Section 的定义中， DT_STRTAB 指向字符串表， DT_SYMTAB 指向符号表； DT_JMPREL 指向和 PLT 相关的 relocation 表，并且需要配套 DT_PLTRELSZ 和 DT_PLTREL 。LSPlt 的字段基本就是围绕这些动态段条目展开。

ELF 解析器构造与初始化

1. 校验 ELF Header

Elf::Elf(uintptr_t base_addr) 的第一步是把 base_addr 当作 ELF Header：

Elf::Elf(uintptr_t base_addr) : base_addr_(base_addr) {
    header_ = reinterpret_cast<decltype(header_)>(base_addr);

    // 校验 ELF 魔数：0x7f 'E' 'L' 'F'。
    if (0 != memcmp(header_->e_ident, ELFMAG, SELFMAG)) {
        return;
    }

#if defined(__LP64__)
    // 64 位进程只接受 ELFCLASS64。
    if (ELFCLASS64 != header_->e_ident[EI_CLASS]) {
        return;
    }
#else
    // 32 位进程只接受 ELFCLASS32。
    if (ELFCLASS32 != header_->e_ident[EI_CLASS]) {
        return;
    }
#endif

    // Android 主流 ABI 使用小端。
    if (ELFDATA2LSB != header_->e_ident[EI_DATA]) {
        return;
    }

    if (EV_CURRENT != header_->e_ident[EI_VERSION]) {
        return;
    }

    // 只处理可执行文件和共享对象。
    if (ET_EXEC != header_->e_type && ET_DYN != header_->e_type) {
        return;
    }

继续校验机器架构：

#if defined(__arm__)
    if (EM_ARM != header_->e_machine) return;
#elif defined(__aarch64__)
    if (EM_AARCH64 != header_->e_machine) return;
#elif defined(__i386__)
    if (EM_386 != header_->e_machine) return;
#elif defined(__x86_64__)
    if (EM_X86_64 != header_->e_machine) return;
#elif defined(__riscv)
    if (EM_RISCV != header_->e_machine) return;
#else
    return;
#endif

    if (EV_CURRENT != header_->e_version) {
        return;
    }

这里的校验非常保守：当前进程是什么 ABI，就只解析同 ABI 的 ELF。Hook 发生在本进程内，这样做可以避免把 32/64 位结构体按错格式解释。

2. 遍历 Program Header，计算 bias

ELF 文件中的很多地址是虚拟地址，不是当前进程里的绝对地址。LSPlt 需要先算出 bias_addr_ ：

    // e_phoff 是 Program Header Table 相对 ELF Header 的文件偏移。
    program_header_ = OffsetOf<decltype(program_header_)>(header_, header_->e_phoff);

    auto ph_off = reinterpret_cast<uintptr_t>(program_header_);
    for (int i = 0; i < header_->e_phnum; i++, ph_off += header_->e_phentsize) {
        auto *program_header = reinterpret_cast<ElfW(Phdr) *>(ph_off);

        if (program_header->p_type == PT_LOAD && program_header->p_offset == 0) {
            // 第一个 offset 为 0 的 LOAD 段通常包含 ELF Header。
            // base_addr_ 是它在内存里的地址，p_vaddr 是它声明的虚拟地址。
            // 两者差值就是运行时地址修正量。
            if (base_addr_ >= program_header->p_vaddr) {
                bias_addr_ = base_addr_ - program_header->p_vaddr;
            }
        } else if (program_header->p_type == PT_DYNAMIC) {
            // 找到 Dynamic Section。
            dynamic_ = reinterpret_cast<decltype(dynamic_)>(program_header->p_vaddr);
            dynamic_size_ = program_header->p_memsz;
        }
    }

    // 必须同时找到 Dynamic Section 和 bias。
    if (!dynamic_ || !bias_addr_) {
        return;
    }

    // 把 Dynamic Section 的虚拟地址转换成进程内真实地址。
    dynamic_ = reinterpret_cast<decltype(dynamic_)>(
        bias_addr_ + reinterpret_cast<uintptr_t>(dynamic_));

这个过程可以概括成：

运行时地址 = bias_addr_ + ELF 中记录的虚拟地址
bias_addr_ = ELF Header 所在映射地址 - 第一个 PT_LOAD 的 p_vaddr

3. 解析 Dynamic Section

接下来遍历 ElfW(Dyn) 数组：

    for (auto *dynamic = dynamic_,
              *dynamic_end = dynamic_ + (dynamic_size_ / sizeof(dynamic[0]));
         dynamic < dynamic_end;
         ++dynamic) {
        switch (dynamic->d_tag) {
        case DT_NULL:
            // DT_NULL 表示 Dynamic Section 结束。
            dynamic = dynamic_end;
            break;

        case DT_STRTAB:
            // 动态字符串表，符号名最终都要从这里取。
            if (!SetByOffset(dyn_str_, base_addr_, bias_addr_, dynamic->d_un.d_ptr)) {
                return;
            }
            break;

        case DT_SYMTAB:
            // 动态符号表，符号索引对应 ElfW(Sym)。
            if (!SetByOffset(dyn_sym_, base_addr_, bias_addr_, dynamic->d_un.d_ptr)) {
                return;
            }
            break;

        case DT_PLTREL:
            // PLT relocation 使用 Rel 还是 Rela。
            is_use_rela_ = dynamic->d_un.d_val == DT_RELA;
            break;

        case DT_JMPREL:
            // PLT relocation 表地址。
            if (!SetByOffset(rel_plt_, base_addr_, bias_addr_, dynamic->d_un.d_ptr)) {
                return;
            }
            break;

        case DT_PLTRELSZ:
            rel_plt_size_ = dynamic->d_un.d_val;
            break;

        case DT_REL:
        case DT_RELA:
            // 非 PLT relocation 表。
            if (!SetByOffset(rel_dyn_, base_addr_, bias_addr_, dynamic->d_un.d_ptr)) {
                return;
            }
            break;

        case DT_RELSZ:
        case DT_RELASZ:
            rel_dyn_size_ = dynamic->d_un.d_val;
            break;

        case DT_ANDROID_REL:
        case DT_ANDROID_RELA:
            // Android 压缩 relocation。
            if (!SetByOffset(rel_android_, base_addr_, bias_addr_, dynamic->d_un.d_ptr)) {
                return;
            }
            break;

        case DT_ANDROID_RELSZ:
        case DT_ANDROID_RELASZ:
            rel_android_size_ = dynamic->d_un.d_val;
            break;

        case DT_HASH:
            // SysV hash。若已经有 GNU hash，则忽略 DT_HASH。
            if (bloom_) continue;
            {
                auto *raw = reinterpret_cast<ElfW(Word) *>(bias_addr_ + dynamic->d_un.d_ptr);
                bucket_count_ = raw[0];
                bucket_ = raw + 2;
                chain_ = bucket_ + bucket_count_;
            }
            break;

        case DT_GNU_HASH:
            // GNU hash，包含 bloom filter，用于快速判断符号是否可能存在。
            {
                auto *raw = reinterpret_cast<ElfW(Word) *>(bias_addr_ + dynamic->d_un.d_ptr);
                bucket_count_ = raw[0];
                sym_offset_ = raw[1];
                bloom_size_ = raw[2];
                bloom_shift_ = raw[3];
                bloom_ = reinterpret_cast<decltype(bloom_)>(raw + 4);
                bucket_ = reinterpret_cast<decltype(bucket_)>(bloom_ + bloom_size_);
                chain_ = bucket_ + bucket_count_ - sym_offset_;
            }
            break;

        default:
            break;
        }
    }

SetByOffset() 是一个小工具，用来把 ELF 虚拟地址转换成运行时地址：

template <typename T>
inline constexpr auto SetByOffset(T &ptr, ElfW(Addr) base, ElfW(Addr) bias, ElfW(Addr) off) {
    if (auto val = bias + off; val > base) {
        ptr = reinterpret_cast<T>(val);
        return true;
    }
    ptr = 0;
    return false;
}

val > base 是一个基础防御：解析出来的地址至少应该落在 ELF 基址之后。它不是完整的越界校验，但可以过滤明显异常的动态段地址。

4. 校验 Android 压缩 relocation

Android 有压缩 relocation 格式，LSPlt 只做了头部识别：

    if (0 != rel_android_) {
        const auto *rel = reinterpret_cast<const char *>(rel_android_);

        // Android packed relocation 以 "APS2" 开头。
        if (rel_android_size_ < 4 ||
            rel[0] != 'A' ||
            rel[1] != 'P' ||
            rel[2] != 'S' ||
            rel[3] != '2') {
            return;
        }

        // 跳过 APS2 头。
        rel_android_ += 4;
        rel_android_size_ -= 4;
    }

    valid_ = true;
}

注意

当前源码在 FindPltAddr() 中会把 rel_android_ 当作普通 ElfW(Rel) 或 ElfW(Rela) 数组遍历。Android packed relocation 实际是压缩编码格式，不能简单等同普通 relocation 表。读者在分析不同 Android 版本或不同链接参数生成的 so 时，应重点验证这一点，不要假设所有压缩 relocation 都能按普通表处理。

流程拆解

1. maps 扫描与目标映射筛选

HookInfos::ScanHookInfo() 先扫描所有 maps，再只保留可读、私有、有路径、非匿名的映射：

static auto ScanHookInfo() {
    static ino_t kSelfInode = 0;
    static dev_t kSelfDev = 0;
    HookInfos info;
    auto maps = lsplt::MapInfo::Scan();

    // 找到 LSPlt 自己所在的 so，用于处理 self hook。
    if (kSelfInode == 0) {
        auto self = reinterpret_cast<uintptr_t>(__builtin_return_address(0));
        for (auto &map : maps) {
            if (self >= map.start && self < map.end) {
                kSelfInode = map.inode;
                kSelfDev = map.dev;
                break;
            }
        }
    }

    for (auto &map : maps) {
        // 只关心 readable private mapping。
        // offset == 0 的映射通常包含 ELF Header；
        // offset != 0 的映射可能是后续 segment，后续用于判断待写地址归属。
        if (!map.is_private ||
            !(map.perms & PROT_READ) ||
            map.path.empty() ||
            map.path[0] == '[') {
            continue;
        }

        auto start = map.start;
        const bool self = map.inode == kSelfInode && map.dev == kSelfDev;
        info.emplace(start, HookInfo{{std::move(map)}, {}, 0, nullptr, self});
    }
    return info;
}

然后根据 RegisterInfo 做筛选：

void Filter(const std::list<RegisterInfo> &register_info) {
    for (auto iter = begin(); iter != end();) {
        const auto &info = iter->second;
        bool matched = false;

        // 只要某个注册请求匹配当前映射，就保留。
        for (const auto &reg : register_info) {
            if (info.Match(reg)) {
                matched = true;
                break;
            }
        }

        if (matched) {
            ++iter;
        } else {
            iter = erase(iter);
        }
    }
}

匹配条件是：

bool Match(const RegisterInfo &info) const {
    return info.dev == dev &&
           info.inode == inode &&
           offset >= info.offset_range.first &&
           offset < info.offset_range.second;
}

这解释了为什么 dev/inode/offset 比路径更重要：同一个 APK、同一个 so、同一个进程里可能出现多个路径形态，但内核映射层面的身份最终要看设备号、inode 和偏移。

2. 找到符号索引

FindPltAddr() 第一件事是把符号名变成动态符号表索引：

std::vector<uintptr_t> Elf::FindPltAddr(std::string_view name) const {
    std::vector<uintptr_t> res;

    // 优先 GNU hash，其次 SysV ELF hash，最后线性扫描。
    uint32_t idx = GnuLookup(name);
    if (!idx) idx = ElfLookup(name);
    if (!idx) idx = LinearLookup(name);
    if (!idx) return res;

    // 下面继续查 relocation 表。
}

GNU hash 查找的核心逻辑：

uint32_t Elf::GnuLookup(std::string_view name) const {
    static constexpr auto kBloomMaskBits = sizeof(ElfW(Addr)) * 8;
    static constexpr uint32_t kInitialHash = 5381;
    static constexpr uint32_t kHashShift = 5;

    if (!bucket_ || !bloom_) {
        return 0;
    }

    // 计算 GNU hash。
    uint32_t hash = kInitialHash;
    for (unsigned char chr : name) {
        hash += (hash << kHashShift) + chr;
    }

    // bloom filter 快速判断“不可能存在”。
    auto bloom_word = bloom_[(hash / kBloomMaskBits) % bloom_size_];
    uintptr_t mask = 0 |
        uintptr_t{1} << (hash % kBloomMaskBits) |
        uintptr_t{1} << ((hash >> bloom_shift_) % kBloomMaskBits);

    if ((mask & bloom_word) == mask) {
        auto idx = bucket_[hash % bucket_count_];
        if (idx >= sym_offset_) {
            const char *strings = dyn_str_;
            do {
                auto *sym = dyn_sym_ + idx;

                // chain_ 里保存 hash 链。低位为 1 表示链结束。
                if (((chain_[idx] ^ hash) >> 1) == 0 &&
                    name == strings + sym->st_name) {
                    return idx;
                }
            } while ((chain_[idx++] & 1) == 0);
        }
    }
    return 0;
}

SysV ELF hash 查找：

uint32_t Elf::ElfLookup(std::string_view name) const {
    static constexpr uint32_t kHashMask = 0xf0000000;
    static constexpr uint32_t kHashShift = 24;
    uint32_t hash = 0;
    uint32_t tmp;

    // 有 GNU hash 时不使用 SysV hash。
    if (!bucket_ || bloom_) {
        return 0;
    }

    for (unsigned char chr : name) {
        hash = (hash << 4) + chr;
        tmp = hash & kHashMask;
        hash ^= tmp;
        hash ^= tmp >> kHashShift;
    }

    const char *strings = dyn_str_;
    for (auto idx = bucket_[hash % bucket_count_]; idx != 0; idx = chain_[idx]) {
        auto *sym = dyn_sym_ + idx;
        if (name == strings + sym->st_name) {
            return idx;
        }
    }
    return 0;
}

线性扫描用于兜底：

uint32_t Elf::LinearLookup(std::string_view name) const {
    // 当前实现依赖 sym_offset_。
    // sym_offset_ 来自 GNU hash，因此没有 GNU hash 时可能无法线性扫描。
    if (!dyn_sym_ || !sym_offset_) {
        return 0;
    }

    for (uint32_t idx = 0; idx < sym_offset_; idx++) {
        auto *sym = dyn_sym_ + idx;
        if (name == dyn_str_ + sym->st_name) {
            return idx;
        }
    }
    return 0;
}

注意

LinearLookup() 不是完整符号表扫描。ELF 动态符号表没有直接记录 “符号数量” 的字段，当前实现借用了 GNU hash 的 sym_offset_ 。因此它更像针对 GNU hash 前缀符号的兜底逻辑，而不是通用查找器。

3. 从 relocation 表找到 PLT/GOT 槽位

不同 ABI 的 relocation 类型不一样，LSPlt 先用宏统一：

#if defined(__arm__)
#define ELF_R_GENERIC_JUMP_SLOT R_ARM_JUMP_SLOT

#elif defined(__aarch64__)
#define ELF_R_GENERIC_JUMP_SLOT R_AARCH64_JUMP_SLOT

#define ELF_R_GENERIC_ABS R_AARCH64_ABS64
#elif defined(__i386__)
#define ELF_R_GENERIC_JUMP_SLOT R_386_JMP_SLOT
#define ELF_R_GENERIC_GLOB_DAT R_386_GLOB_DAT
#define ELF_R_GENERIC_ABS R_386_32
#elif defined(__x86_64__)
#define ELF_R_GENERIC_JUMP_SLOT R_X86_64_JUMP_SLOT
#define ELF_R_GENERIC_GLOB_DAT R_X86_64_GLOB_DAT
#define ELF_R_GENERIC_ABS R_X86_64_64
#elif defined(__riscv)
#define ELF_R_GENERIC_JUMP_SLOT R_RISCV_JUMP_SLOT
#define ELF_R_GENERIC_GLOB_DAT R_RISCV_64

找到符号索引后，遍历 relocation：

auto looper = [&]<typename T>(auto begin, auto size, bool is_plt) -> void {
    const auto *rel_end = reinterpret_cast<const T *>(begin + size);

    for (const auto *rel = reinterpret_cast<const T *>(begin);
         rel < rel_end;
         ++rel) {
        auto r_info = rel->r_info;
        auto r_offset = rel->r_offset;
        auto r_sym = ELF_R_SYM(r_info);
        auto r_type = ELF_R_TYPE(r_info);

        // 只关心目标符号对应的 relocation。
        if (r_sym != idx) {
            continue;
        }

        // PLT relocation 必须是 JUMP_SLOT。
        if (is_plt && r_type != ELF_R_GENERIC_JUMP_SLOT) {
            continue;
        }

        // 非 PLT relocation 只接受 ABS/GLOB_DAT。
        if (!is_plt &&
            r_type != ELF_R_GENERIC_ABS &&
            r_type != ELF_R_GENERIC_GLOB_DAT) {
            continue;
        }

        // r_offset 是 ELF 虚拟地址，转换成进程内槽位地址。
        auto addr = bias_addr_ + r_offset;
        if (addr > base_addr_) {
            res.emplace_back(addr);
        }

        // PLT 一般只需要第一个 JUMP_SLOT。
        if (is_plt) {
            break;
        }
    }
};

遍历的表包括：

for (const auto &[rel, rel_size, is_plt] :
     {std::make_tuple(rel_plt_, rel_plt_size_, true),
      std::make_tuple(rel_dyn_, rel_dyn_size_, false),
      std::make_tuple(rel_android_, rel_android_size_, false)}) {
    if (!rel) {
        continue;
    }

    if (is_use_rela_) {
        looper.template operator()<ElfW(Rela)>(rel, rel_size, is_plt);
    } else {
        looper.template operator()<ElfW(Rel)>(rel, rel_size, is_plt);
    }
}

注意： FindPltAddr() 返回的不是 clock_gettime 真实实现地址，而是 “保存函数指针的槽位地址”。PLT Hook 的本质就是改这个槽位：

调用点 -> PLT stub -> GOT/PLT slot -> 原始函数
                           |
                           v
                    改成 callback

4. 写入 Hook 与 backup

当 HookInfos::DoHook(register_info) 找到目标 ELF 后，会构造 Elf 并查找地址：

bool DoHook(std::list<RegisterInfo> &register_info) {
    bool res = true;

    for (auto info_iter = rbegin(); info_iter != rend(); ++info_iter) {
        auto &info = info_iter->second;

        for (auto iter = register_info.begin(); iter != register_info.end();) {
            const auto &reg = *iter;

            // 只在 ELF Header 对应的 offset 映射上解析 ELF。
            if (info.offset != iter->offset_range.first || !info.Match(reg)) {
                ++iter;
                continue;
            }

            if (!info.elf) {
                info.elf = std::make_unique<Elf>(info.start);
            }

            if (info.elf && info.elf->Valid()) {
                for (auto addr : info.elf->FindPltAddr(reg.symbol)) {
                    res = DoHook(addr,
                                 reinterpret_cast<uintptr_t>(reg.callback),
                                 reinterpret_cast<uintptr_t *>(reg.backup)) &&
                          res;
                }
            }

            // 无论成功与否，该注册项都会从待处理队列移除。
            iter = register_info.erase(iter);
        }
    }
    return res;
}

真正写入发生在 DoHook(addr, callback, backup) ：

bool DoHook(uintptr_t addr, uintptr_t callback, uintptr_t *backup) {
    // 根据目标槽位地址，找到它所属的 maps 映射。
    auto iter = lower_bound(addr);
    if (iter == end()) return false;

    auto &info = iter->second;
    if (info.end <= addr) return false;

    const auto len = info.end - info.start;

    // 非 self hook 时，先备份原映射，再创建一份可写匿名映射承载修改。
    if (!info.backup && !info.self) {
        auto *backup_addr = sys_mmap(nullptr, len, PROT_NONE, MAP_PRIVATE | MAP_ANON, -1, 0);
        if (backup_addr == MAP_FAILED) return false;

        // 优先使用 MREMAP_DONTUNMAP 复制映射。
        if (auto *new_addr = sys_mremap(reinterpret_cast<void *>(info.start),
                                        len,
                                        len,
                                        MREMAP_FIXED | MREMAP_MAYMOVE | MREMAP_DONTUNMAP,
                                        backup_addr);
            new_addr == MAP_FAILED || new_addr != backup_addr) {
            // 不支持 MREMAP_DONTUNMAP 时退回普通 mremap。
            new_addr = sys_mremap(reinterpret_cast<void *>(info.start),
                                  len,
                                  len,
                                  MREMAP_FIXED | MREMAP_MAYMOVE,
                                  backup_addr);
            if (new_addr == MAP_FAILED || new_addr != backup_addr) {
                return false;
            }
        }

        // 在原地址重新映射一段匿名内存，权限临时加 PROT_WRITE。
        if (auto *new_addr = sys_mmap(reinterpret_cast<void *>(info.start),
                                      len,
                                      PROT_READ | PROT_WRITE | info.perms,
                                      MAP_PRIVATE | MAP_FIXED | MAP_ANON,
                                      -1,
                                      0);
            new_addr == MAP_FAILED) {
            return false;
        }

        // 把备份内容按页复制回原地址的新匿名映射。
        for (uintptr_t src = reinterpret_cast<uintptr_t>(backup_addr),
                       dest = info.start,
                       end = info.start + len;
             dest < end;
             src += kPageSize, dest += kPageSize) {
            memcpy(reinterpret_cast<void *>(dest), reinterpret_cast<void *>(src), kPageSize);
        }

        info.backup = reinterpret_cast<uintptr_t>(backup_addr);
    }

    // self hook 表示目标就是 LSPlt 自己所在映射。
    // 此时无需额外备份，直接确保可写。
    if (info.self) {
        if (!(info.perms & PROT_WRITE)) {
            info.perms |= PROT_WRITE;
            mprotect(reinterpret_cast<void *>(info.start), len, info.perms);
        }
    }

    auto *the_addr = reinterpret_cast<uintptr_t *>(addr);
    auto the_backup = *the_addr;

    // 把槽位里的原始函数指针改成 callback。
    if (*the_addr != callback) {
        *the_addr = callback;
        if (backup) {
            *backup = the_backup;
        }
        __builtin___clear_cache(PageStart(addr), PageEnd(addr));
    }

    // 记录当前 Hook 状态，用于重复 Hook 和恢复。
    if (auto hook_iter = info.hooks.find(addr); hook_iter != info.hooks.end()) {
        if (hook_iter->second == callback) {
            info.hooks.erase(hook_iter);
        }
    } else {
        info.hooks.emplace(addr, the_backup);
    }

    // 如果所有 Hook 都恢复了，就把备份映射搬回原地址，尽量消除脏页。
    if (info.hooks.empty() && !info.self) {
        if (auto *new_addr = sys_mremap(reinterpret_cast<void *>(info.backup),
                                        len,
                                        len,
                                        MREMAP_FIXED | MREMAP_MAYMOVE,
                                        reinterpret_cast<void *>(info.start));
            new_addr == MAP_FAILED || reinterpret_cast<uintptr_t>(new_addr) != info.start) {
            return false;
        }
        info.backup = 0;
    }

    return true;
}

这段代码解释了 LSPlt README/API 注释中的一个重点：默认情况下，LSPlt 不直接污染原始文件映射，而是把原映射备份走，再在原地址放一份匿名可写副本进行 Hook。恢复后再尽量把原映射搬回去，从而减少脏页痕迹。

Linux mremap() 的 MREMAP_DONTUNMAP 标志从 Linux 5.7 开始支持，它允许移动映射时不取消旧地址映射。LSPlt 对它做了降级处理：如果该标志不可用，就退回不带 MREMAP_DONTUNMAP 的 mremap() 。

原理分析

PLT Hook 改的是 “调用入口表”，不是函数代码

当一个 so 调用外部函数时，编译链接阶段通常不会把真实地址写死，而是生成一个重定位槽位：

libdemo.so
  call clock_gettime@plt
      -> 读取 GOT/PLT slot
          -> libc.so!clock_gettime

动态链接器加载 so 后，根据 relocation 表把 slot 填成真实函数地址。LSPlt 做的事情是：

原始：
  slot = libc.so!clock_gettime

Hook 后：
  slot = my_clock_gettime
  backup = libc.so!clock_gettime

因此它和 inline hook 的区别很明显：

方式修改位置优点限制
PLT Hook调用方 ELF 的 GOT/PLT 槽位不改目标函数机器码，恢复相对清晰只影响经过该调用方 PLT 的调用
Inline Hook被调用函数入口机器码可影响更多调用路径需要处理指令改写、跳板、架构差异和代码页权限

如果目标代码直接调用函数地址、静态链接、内联、或者通过 dlsym() 后缓存函数指针，PLT Hook 可能拦不到。

为什么要按 dev + inode 定位

Android 上同一个 so 的路径可能出现多种形式：

/data/app/.../lib/arm64/libfoo.so
/data/app/.../base.apk!/lib/arm64-v8a/libfoo.so
/apex/com.android.runtime/lib64/bionic/libc.so

路径还可能受安装目录、split APK、命名空间和厂商 ROM 影响。 dev + inode 来自内核文件系统视角，配合 offset 范围能更稳定地描述 “当前进程实际映射的是哪个文件的哪一段”。

为什么 RegisterHook() 和 CommitHook() 分离

分离设计有三个好处：

  1. 可以批量注册多个符号，最后统一扫描 maps。
  2. backup 的生命周期更明确：只有提交成功后才可用。
  3. 恢复时仍然复用同一套注册机制，把 callback 设置成 backup 即可。

为什么需要 InvalidateBackup()

InvalidateBackup() 会把当前备份映射恢复到原地址，并清理 Hook 状态。它适用于库卸载或调用方想主动放弃 “匿名副本 Hook” 策略的场景。

源码中它被标记为析构函数：

[[gnu::destructor]] [[maybe_unused]] bool InvalidateBackup() {
    const std::unique_lock lock(hook_mutex);
    return hook_info.InvalidateBackup();
}

也就是说，库卸载时 LSPlt 会尽量恢复映射状态。但析构阶段进程状态可能已经复杂，不应把它当成业务逻辑里唯一可靠的恢复点。需要明确恢复时，建议主动用 backup 注册恢复。

版本差异和 ABI 差异

需要重点注意这些差异：

差异点影响
Rel vs Rela32 位 ARM 常见 Rel ，AArch64 常见 Rela ；解析结构不同
relocation 类型各 ABI 的 JUMP_SLOT 、 GLOB_DAT 、 ABS 常量不同
Android packed relocation压缩格式不能简单当普通 relocation 表处理，需要验证
APK 内直接加载 so需要 offset/size 重载，offset 必须页对齐
页面大小Android 15 以后 16 KB page size 设备增多，直接从 APK 加载 so 时对齐要求更敏感
编译优化-fno-plt 、LTO、内联、静态链接可能让目标调用不经过 PLT
RELROGOT 可能只读；LSPlt 通过重映射副本解决写入问题，但不同系统策略仍要实测

常见错误与排查

现象常见原因排查方法
RegisterHook() 返回 falsedev/inode 为 0、符号名为空、callback 为空打印 MapInfo::Scan() 结果，确认目标 so 存在
CommitHook() 返回 falsemaps 扫描不到目标、ELF 校验失败、内存映射操作失败打印目标 maps 行，确认 offset、权限、路径

callback 没有被调用调用没有经过目标 so 的 PLT确认 Hook 的是 “调用方 so”，不是 “被调用函数所在 so”
callback 一调用就崩溃函数签名不一致、调用约定不匹配确认返回值、参数类型、结构体指针完全一致
backup 调用崩溃backup 尚未初始化或类型转换错误只在 CommitHook() 后且 backup != nullptr 时调用

常用检查命令：

# 查看动态符号表，确认符号是否存在。
readelf -Ws liblsplt_demo.so | grep clock_gettime

# 查看 relocation，确认调用方是否有 JUMP_SLOT/GLOB_DAT 槽位。
readelf -r liblsplt_demo.so | grep clock_gettime

# 查看 so 动态段，确认 DT_JMPREL、DT_PLTRELSZ、DT_PLTREL。
readelf -d liblsplt_demo.so

# 查看设备上进程 maps。
adb shell cat /proc/<pid>/maps | grep liblsplt_demo

提示

PLT Hook 的排查顺序建议是：先确认符号存在，再确认 relocation 存在，再确认 maps 匹配，最后看内存写入和 callback 签名。不要一开始就怀疑 LSPlt 写内存失败，很多问题其实是目标调用根本没有经过 PLT。

总结

LSPlt 的主线很清楚：公共 API 收集 Hook 意图， CommitHook() 扫描进程 maps， Elf 解析器从 Dynamic Section 找到符号表、字符串表、hash 表和 relocation 表，最后把目标符号对应的 PLT/GOT 槽位改成 callback，并把原始函数指针写入 backup。

如果你想把它用在自己的工程里，最关键的不是背概念，而是验证三件事：

  1. 目标调用方 so 里确实存在目标符号的动态 relocation。
  2. MapInfo::Scan() 找到的是调用方 so 的 dev/inode/offset 。
  3. callback 签名与原函数完全一致，并且只在 CommitHook() 后使用 backup。

后续可以继续沿着两个方向扩展：一是补充更完整的 Android packed relocation 解析；二是把 maps 选择、符号验证、readelf 检查和 Hook 结果日志封装成工程化调试工具，降低在复杂 App 中定位失败原因的成本。
