Xposed 使用 DexKit 精准查找混淆代码

概述

在 Xposed Hook 开发中，我们经常遇到以下痛点：

传统反射的局限性

// 传统方式：硬编码类名和方法名
XposedHelpers.findClass("com.example.app.LoginActivity", lpparam.classLoader)
XposedHelpers.findAndHookMethod("com.example.app.utils.Crypto", "encrypt", String::class.java)

问题：

  • 代码混淆后类名变化： LoginActivity → a.b.c.d
  • 应用版本更新：类结构调整导致路径失效
  • 多渠道包差异：不同版本的类名不一致

DexKit 解决方案

DexKit 是一个基于 DEX 文件分析 的高性能查找库，通过以下特征定位目标类：

查找维度适用场景稳定性
字符串特征类中包含特定的日志、错误提示、URL⭐⭐⭐⭐⭐
方法签名参数类型、返回类型的组合特征⭐⭐⭐⭐
注解信息Spring、XPage 等框架的注解标记⭐⭐⭐⭐⭐
继承关系实现特定接口或继承特定类⭐⭐⭐
字段类型包含特定类型的成员变量⭐⭐⭐

技术原理

DexKit 工作流程

APK 安装包
    ↓
DexKitBridge.create(apkPath)
    ↓
解析 DEX 文件结构
    ↓
构建类/方法/字段索引
    ↓
定义查找规则 (Matcher)
    ↓
快速匹配并返回结果
    ↓
反射调用或 Hook 目标

核心优势

  1. Native 层实现：C++ 直接解析 DEX 文件，速度快于 Java 反射
  2. 多条件组合：支持 AND / OR 逻辑的复杂查询
  3. 模糊匹配：不依赖精确类名，适配混淆环境
  4. 批量查找：一次扫描可返回多个匹配结果

环境配置

1. 添加依赖

// gradle/libs.versions.toml
[versions]
dexkit = "2.2.0"

[libraries]
dexkit = { module = "org.luckypray:dexkit", version.ref = "dexkit" }
// app/build.gradle.kts
dependencies {
    compileOnly(libs.api)
    implementation(libs.dexkit)  // 添加 DexKit 依赖
}

2. 加载 Native 库

class KotlinHookEntry : IXposedHookLoadPackage {
    
    companion object {
        init {
            System.loadLibrary("dexkit")  // 加载 DexKit 的 Native 库
        }
    }
}

注意事项：

  • DexKit 依赖 Native 库 libdexkit.so ，需要在类加载时初始化
  • 如果加载失败，检查 libs/ 目录是否包含对应 ABI 的 .so 文件

案例 1：通过字符串特征查找 OkHttp

场景描述

目标应用使用了 OkHttp 网络库，但我们不确定具体版本和类结构。传统方式直接反射 okhttp3.OkHttpClient 可能失败（因为可能被重新打包或混淆）。

查找策略

通过 OkHttp 源码中的 特征字符串 定位核心类：

private fun findOkhttp(bridge: DexKitBridge) {
    // 步骤 1：查找 OkHttpClient.Builder 类
    val classData = bridge.findClass {
        searchPackages("okhttp3")  // 限定搜索范围
        matcher {
            // OkHttpClient.Builder 的 build() 方法中有这个错误提示
            usingStrings("protocols must contain h2_prior_knowledge or http/1.1: ")
        }
    }.singleOrNull() ?: error("This returned result is null or not unique")
    
    Log.d(TAG, "findOkhttp: ${classData.name}")
    // 输出: okhttp3.OkHttpClient$Builder
    
    // 步骤 2：查找 Builder 的 build() 方法
    val findMethod = classData.findMethod {
        matcher {
            returnType = classData.name.split("$")[0]  // 返回类型是 OkHttpClient
            paramTypes()  // 无参方法
        }
    }.singleOrNull() ?: error("This returned result is null or not unique")
    
    Log.d(TAG, "findOkhttp: (method) ${findMethod.name}")
    // 输出: build
    
    // 步骤 3：查找 Interceptor 接口
    val interfaceImplClass = bridge.findClass {
        matcher {
            // CallServerInterceptor 类中的日志字符串
            usingStrings(" had non-zero Content-Length: ")
        }
    }.singleOrNull() ?: error("This returned result is null or not unique")
    
    val interfaces = interfaceImplClass.interfaces
    if (interfaces.isNotEmpty()) {
        val interceptorInterfaceClass = interfaces[0]
        Log.d(TAG, "findOkhttp: (interface) ${interceptorInterfaceClass.name}")
        // 输出: okhttp3.Interceptor
    }
}

代码解析

1. searchPackages() - 包名过滤

searchPackages("okhttp3")
  • 作用：只搜索 okhttp3 包下的类，减少扫描范围
  • 性能优化：避免扫描系统类和第三方库

2. usingStrings() - 字符串特征匹配

matcher {
    usingStrings("protocols must contain h2_prior_knowledge or http/1.1: ")
}
  • 原理：DexKit 会扫描类中的所有字符串常量池
  • 优势：字符串特征在混淆后仍然保留（除非开启字符串加密）
  • 来源：通过反编译 OkHttp 源码找到唯一特征字符串

3. findMethod() - 查找方法

classData.findMethod {
    matcher {
        returnType = classData.name.split("$")[0]  // OkHttpClient
        paramTypes()  // 空参数列表
    }
}
  • returnType：指定返回类型为 OkHttpClient （去掉内部类标记 $Builder ）
  • paramTypes()：无参方法
  • 匹配目标： public OkHttpClient build()

4. 接口查找

val interfaces = interfaceImplClass.interfaces
  • 作用：获取类实现的所有接口
  • 场景：找到 Interceptor 接口后，可以动态代理创建拦截器

案例 2：通过方法签名查找混淆类

场景描述

某 App 的加密算法类被混淆成 a.b.c.d ，但我们知道它有以下特征方法：

// 混淆前的签名特征
public class CryptoUtil {
    public String encrypt(int key1, int key2);                          // 2 个 int 参数
    public String hash(int a, int b, int c);                           // 3 个 int 参数
    public byte[] sign(int p1, int p2, int p3, int p4, int p5, int p6); // 6 个 int 参数
}

查找代码

fun findTargetFragment(bridge: DexKitBridge) {
    val classData = bridge.findClass {
        // 排除无关的系统库和第三方库
        excludePackages(
            "androidx.constraintlayout",
            "com.google.common.primitives",
            "org.bouncycastle.crypto"
        )
        
        matcher {
            methods {
                // 匹配：至少包含这三个方法签名
                add {
                    paramTypes("int", "int")  // 方法 1
                }
                add {
                    paramTypes("int", "int", "int")  // 方法 2
                }
                add {
                    paramTypes("int", "int", "int", "int", "int", "int")  // 方法 3
                }
            }
        }
    }.singleOrNull() ?: error("This returned result is null or not unique")
    
    Log.d(TAG, "findTargetFragment: ${classData.name}")
    // 输出: com.example.challenge.fragment.Challenge16Fragment (或混淆后的类名)
}

代码解析

1. excludePackages() - 排除干扰

excludePackages(
    "androidx.constraintlayout",
    "com.google.common.primitives",
    "org.bouncycastle.crypto"
)
  • 作用：避免误匹配系统库中的类
  • 建议：通过反编译工具（jadx）先观察 APK 的包结构，排除明显无关的包

2. methods.add{} - 方法签名匹配

methods {
    add {
        paramTypes("int", "int")
    }
}
  • 逻辑：查找 同时包含 这些方法签名的类（ AND 关系）
  • 参数类型：支持基本类型（ int , boolean ）和对象类型（ java.lang.String ）

3. singleOrNull() - 结果校验

}.singleOrNull() ?: error("This returned result is null or not unique")
  • singleOrNull()：确保只有一个匹配结果
  • 如果返回多个结果：说明查找条件不够精确，需要添加更多限制条件
  • 如果返回 null：说明没有找到匹配的类

高级技巧：注解查找（已注释的示例）

代码示例

fun findTargetFragment(bridge: DexKitBridge) {
    val classData = bridge.findClass {
        searchPackages("com.example.challenge")  // 限定业务包
        
        matcher {
            // 方法 1：通过字符串特征
            usingStrings("%02x%02x%02x%02x")
            
            // 方法 2：通过注解（适用于 XPage 框架）
            annotations {
                add {
                    type = "com.xuexiang.xpage.annotation.Page"
                    addElement {
                        name = "name"
                        stringValue("练习16")  // 注解的 name 属性值
                    }
                }
            }
        }
    }.singleOrNull() ?: error("This returned result is null or not unique")
}

适用场景

框架注解示例查找条件
XPage@Page(name = "练习16")type = "Page" , name = "练习16"
Retrofit@GET("/api/user")type = "GET" , value = "/api/user"
EventBus@Subscribe(threadMode = MAIN)type = "Subscribe"

优势： 注解在混淆时通常会保留（因为框架依赖反射解析），查找稳定性极高。

完整实现流程

主入口代码

package com.xposed

import android.util.Log
import de.robv.android.xposed.IXposedHookLoadPackage
import de.robv.android.xposed.callbacks.XC_LoadPackage
import org.luckypray.dexkit.DexKitBridge

class KotlinHookEntry : IXposedHookLoadPackage {

    private val TAG: String = "0X->"

    companion object {
        init {
            System.loadLibrary("dexkit")  // 加载 Native 库
        }
    }

    private lateinit var hostClassLoader: ClassLoader

    override fun handleLoadPackage(lpparam: XC_LoadPackage.LoadPackageParam?) {
        Log.d(TAG, "handleLoadPackage: ${lpparam?.packageName}")
        
        if (lpparam != null) {
            hostClassLoader = lpparam.classLoader
            
            // 使用 use 自动释放资源
            DexKitBridge.create(lpparam.appInfo.sourceDir).use { bridge ->
                Log.d(TAG, "DexKitBridge.create: $bridge")
                
                // 执行查找任务
                // findTargetFragment(bridge)
                findOkhttp(bridge)
            }
        }
    }
}

关键要点

1. 资源管理

DexKitBridge.create(lpparam.appInfo.sourceDir).use { bridge ->
    // 查找逻辑
}
  • use 块：Kotlin 的 Closeable 自动管理，退出时自动调用 bridge.close()
  • appInfo.sourceDir：指向目标应用的 APK 文件路径

2. ClassLoader 保存

private lateinit var hostClassLoader: ClassLoader

override fun handleLoadPackage(lpparam: XC_LoadPackage.LoadPackageParam?) {
    hostClassLoader = lpparam.classLoader
}
  • 作用：后续 Hook 时需要使用目标应用的 ClassLoader 加载类
  • 跨 ClassLoader 问题：不能直接使用 Class.forName() ，需要用 lpparam.classLoader.loadClass()

日志输出

D/0X->: handleLoadPackage: com.example.targetapp
D/0X->: DexKitBridge.create: DexKitBridge@a3f4b2c
D/0X->: findOkhttp: okhttp3.OkHttpClient$Builder

后续操作

找到目标类后，可以进行 Hook 操作：

// 将 DexKit 查找结果转为可 Hook 的 Class
val okHttpClientBuilderClass = hostClassLoader.loadClass(classData.name)

XposedHelpers.findAndHookMethod(
    okHttpClientBuilderClass,
    findMethod.name,  // "build"
    object : XC_MethodHook() {
        override fun afterHookedMethod(param: MethodHookParam) {
            val client = param.result  // OkHttpClient 实例
            // 注入拦截器...
        }
    }
)

性能优化建议

1. 缩小搜索范围

// ❌ 不推荐：全局搜索
bridge.findClass {
    matcher { usingStrings("login") }
}

// ✅ 推荐：限定包名
bridge.findClass {
    searchPackages("com.example.app")  // 只搜索业务代码
    excludePackages("androidx", "com.google")  // 排除系统库
    matcher { usingStrings("login") }
}

2. 使用精确的特征字符串

// ❌ 不推荐：通用字符串
usingStrings("error")  // 可能匹配几百个类

// ✅ 推荐：唯一的业务字符串
usingStrings("Login failed: Invalid token signature")  // 只会匹配一个类

3. 避免在主线程执行

override fun handleLoadPackage(lpparam: XC_LoadPackage.LoadPackageParam?) {
    // DexKit 扫描是耗时操作，建议异步执行
    Thread {
        DexKitBridge.create(lpparam.appInfo.sourceDir).use { bridge ->
            findOkhttp(bridge)
        }
    }.start()
}

常见问题

Q1: 报错 "UnsatisfiedLinkError: dlopen failed"

原因： Native 库加载失败

解决方案：

companion object {
    init {
        try {
            System.loadLibrary("dexkit")
        } catch (e: UnsatisfiedLinkError) {
            Log.e(TAG, "Failed to load dexkit library", e)
        }
    }
}

Q2: 查找返回多个结果

原因： 查找条件不够精确

解决方案：

val results = bridge.findClass {
    matcher {
        usingStrings("login")
        methods {
            add { paramTypes("java.lang.String", "java.lang.String") }
        }
    }
}
// 打印所有结果，分析差异
results.forEach { Log.d(TAG, "Found: ${it.name}") }

Q3: 字符串加密怎么办？

方案 1： 使用方法签名 + 注解组合查找

方案 2： 运行时 Hook 字符串解密函数，获取明文后再查找

总结

技术对比

方案抗混淆能力抗版本更新性能学习成本
硬编码类名❌ 低❌ 低⭐⭐⭐⭐⭐⭐
反射遍历⚠️ 中⚠️ 中⭐⭐⭐⭐
DexKit✅ 高✅ 高⭐⭐⭐⭐⭐⭐⭐

最佳实践

  1. 优先使用注解查找：稳定性最高
  2. 字符串特征作为辅助：选择业务逻辑中的唯一字符串
  3. 方法签名用于加密类：加密算法的参数组合通常不会变化
  4. 缓存查找结果：避免每次启动都重复扫描

适用场景

  • ✅ 目标应用开启了混淆
  • ✅ 需要适配多个版本的 APK
  • ✅ 需要查找的类有明显的特征（字符串 / 方法签名 / 注解）
  • ❌ 类完全动态生成（如 DexClassLoader 加载的类）

通过 DexKit，我们可以在混淆环境下精准定位目标类，极大提升 Xposed 模块的兼容性和鲁棒性。
