Xposed, Kotlin 实现 OkHttp 网络拦截

概述

本文介绍如何使用 Kotlin 语言结合 Xposed 框架，地实现对目标应用 OkHttp 网络库的请求拦截。相比传统 Java 实现，Kotlin 版本代码更简洁、类型安全性更高，并充分利用了 Kotlin 的扩展函数、高阶函数、lazy 初始化等特性。

技术要点

  • Kotlin 扩展函数：为系统类添加自定义功能
  • 高阶函数封装：简化 XposedBridge Hook 代码
  • 动态代理技术：注入 OkHttp 拦截器
  • 反射 API 调用：跨 ClassLoader 操作对象
  • 进程过滤：避免多进程重复 Hook

应用场景

  • 抓取加密的 HTTPS 请求和响应
  • 分析 App 的网络通信协议
  • 修改请求参数或响应内容
  • 监控敏感数据传输

核心代码架构

一、Hook 辅助函数封装

HookUtil.kt

package com.xposed

import de.robv.android.xposed.XC_MethodHook

fun beforeHook(beforeHookMethod: (XC_MethodHook.MethodHookParam) -> Unit) =
    object : XC_MethodHook() {
        override fun beforeHookedMethod(param: MethodHookParam?) {
            super.beforeHookedMethod(param)
            param?.let(beforeHookMethod)
        }
    }

fun afterHook(afterHookMethod: (XC_MethodHook.MethodHookParam) -> Unit) =
    object : XC_MethodHook() {
        override fun afterHookedMethod(param: MethodHookParam?) {
            super.afterHookedMethod(param)
            param?.let(afterHookMethod)
        }
    }

实现原理

这两个函数是 Kotlin 的高阶函数，用于简化 Xposed Hook 代码。

传统 Java 写法

XposedHelpers.findAndHookMethod(
    SomeClass.class,
    "someMethod",
    new XC_MethodHook() {
        @Override
        protected void afterHookedMethod(MethodHookParam param) {
            // 处理逻辑
        }
    }
);

Kotlin 写法

XposedHelpers.findAndHookMethod(
    SomeClass::class.java,
    "someMethod",
    afterHook { param ->
        // 处理逻辑
    }
)

技术细节

  1. 高阶函数：接收 lambda 表达式作为参数
  2. 空安全处理： param?.let 避免空指针异常
  3. 类型推断：自动推断 MethodHookParam 类型
  4. 匿名对象：返回 XC_MethodHook 匿名实现

代码作用

  • 减少样板代码，提高可读性
  • 统一异常处理机制
  • 方便后续扩展（如日志、性能监控）

二、Kotlin 扩展函数工具集

ExtentionUtil.kt

package com.xposed.extension

import android.app.ActivityManager
import android.content.Context
import android.os.Process
import de.robv.android.xposed.XposedHelpers
import de.robv.android.xposed.callbacks.XC_LoadPackage

// 扩展函数 1：检测 OkHttp 库
fun XC_LoadPackage.LoadPackageParam.hasOkhttp(): Boolean {
    return runCatching {
        XposedHelpers.findClass("okhttp3.OkHttpClient", classLoader)
    }.isSuccess
}

// 扩展函数 2：判断是否系统包
fun XC_LoadPackage.LoadPackageParam.isSystemPackage(): Boolean {
    return this.packageName.equals("system")
}

// 扩展函数 3：获取当前进程名
fun Context.getCurrentProcessName(): String? {
    val pid = Process.myPid()
    val activityManager = getSystemService(Context.ACTIVITY_SERVICE) as ActivityManager
    for (process in activityManager.runningAppProcesses) {
        if (process.pid == pid) {
            return process.processName
        }
    }
    return null
}

// 扩展函数 4：判断是否主进程
fun Context.isCurrentProcessMain(): Boolean {
    val name = this.getCurrentProcessName()
    return name != null && name == this.packageName
}

实现原理详解

1. hasOkhttp () - OkHttp 库检测

核心逻辑：

runCatching {
    XposedHelpers.findClass("okhttp3.OkHttpClient", classLoader)
}.isSuccess

工作流程：

  • 尝试通过目标应用的 ClassLoader 加载 okhttp3.OkHttpClient 类
  • 使用 Kotlin 的 runCatching 包装异常处理
  • 如果加载成功返回 true ，失败返回 false

为什么需要这个检测？

  • 避免 Hook 不使用 OkHttp 的应用
  • 防止因类不存在导致的崩溃
  • 提高模块运行效率

2. isCurrentProcessMain () - 主进程判断

多进程问题： Android 应用可以配置多个进程，例如：

<service android:name=".PushService" android:process=":push" />

这会创建一个名为 com.example.app:push 的子进程。

判断逻辑：

fun Context.isCurrentProcessMain(): Boolean {
    val name = this.getCurrentProcessName()  // 获取当前进程名
    return name != null && name == this.packageName  // 比较是否等于包名
}

为什么只在主进程 Hook？

  • 避免重复初始化（每个进程都会触发 Xposed 回调）
  • 主进程通常负责网络请求
  • 减少资源消耗和日志干扰

3. getCurrentProcessName () - 进程名获取

实现方式：

val pid = Process.myPid()  // 获取当前进程 ID
val activityManager = getSystemService(Context.ACTIVITY_SERVICE) as ActivityManager
for (process in activityManager.runningAppProcesses) {
    if (process.pid == pid) {
        return process.processName  // 找到匹配的进程名
    }
}

注意事项：

  • 需要在 Application.onCreate 之后调用（此时 Context 可用）
  • runningAppProcesses 可能返回 null（权限受限或系统异常）

三、Xposed 入口类

KotlinHookEntry.kt

package com.xposed

import android.app.Application
import android.content.Context
import android.util.Log
import com.xposed.extension.hasOkhttp
import com.xposed.extension.isCurrentProcessMain
import com.xposed.hook.OkHttpHook
import de.robv.android.xposed.IXposedHookLoadPackage
import de.robv.android.xposed.XposedHelpers
import de.robv.android.xposed.callbacks.XC_LoadPackage

class KotlinHookEntry : IXposedHookLoadPackage {

    private val TAG: String = "0X->"

    override fun handleLoadPackage(lpparam: XC_LoadPackage.LoadPackageParam?) {
        Log.d(TAG, "handleLoadPackage: " + lpparam?.packageName)
        
        // 步骤 1：检测 OkHttp 库
        if (lpparam?.hasOkhttp() != true) {
            Log.d(TAG, "handleLoadPackage: can not find okhttp")
            return
        }
        
        // 步骤 2：Hook Application.onCreate()
        XposedHelpers.findAndHookMethod(
            Application::class.java,
            Application::onCreate.name,
            afterHook {
                Log.d(TAG, "afterHookedMethod: Application::onCreate.name: " + Application::onCreate.name)
                val context = it.thisObject as Context
                
                // 步骤 3：主进程判断
                if (!context.isCurrentProcessMain()) {
                    Log.d(TAG, "handleLoadPackage: not in main process")
                    return@afterHook
                }
                
                // 步骤 4：初始化 OkHttp 拦截器
                OkHttpHook(lpparam).init()
            }
        )
    }
}

实现原理剖析

为什么 Hook Application.onCreate ()？

时机选择分析：

Hook 时机优点缺点
handleLoadPackage()最早执行Context 不可用，无法判断进程
Application.attachBaseContext()较早执行部分 Context 功能未初始化
Application.onCreate() ✅Context 完全可用，在 OkHttpClient 创建前略晚于前两者
Activity.onCreate()过晚，OkHttpClient 可能已创建❌

代码流程：

XposedHelpers.findAndHookMethod(
    Application::class.java,           // Hook 目标类
    Application::onCreate.name,        // Hook 方法名（Kotlin 反射获取）
    afterHook {                        // 在 onCreate 执行后回调
        val context = it.thisObject as Context  // 获取 Application 实例
        // ...
    }
)

Kotlin 语法亮点

  1. Application::onCreate.name

    • Kotlin 函数引用语法
    • 等价于 Java 的 "onCreate"
    • 优点：编译时检查，重构安全

  2. it.thisObject as Context

    • it 是 lambda 的隐式参数（MethodHookParam）
    • thisObject 是被 Hook 方法的实例（Application 对象）
    • 强制类型转换为 Context

  3. return@afterHook

    • 标签化返回，只退出 lambda
    • 非标签返回会退出整个函数

四、OkHttp 拦截核心逻辑

OkHttpHook.kt

package com.xposed.hook

import android.util.Log
import com.xposed.beforeHook
import de.robv.android.xposed.XposedHelpers
import de.robv.android.xposed.callbacks.XC_LoadPackage
import java.lang.reflect.InvocationHandler
import java.lang.reflect.Method
import java.lang.reflect.Proxy.newProxyInstance

class OkHttpHook(val lpparam: XC_LoadPackage.LoadPackageParam) : InvocationHandler {
    private val TAG: String = "0X->"
    private val classLoader: ClassLoader get() = lpparam.classLoader
    
    // 延迟初始化 Builder 类
    private val _builderClass by lazy {
        runCatching {
            classLoader.loadClass("okhttp3.OkHttpClient\$Builder")
        }.onFailure {
            Log.d(TAG, ": $it")
        }.getOrNull()
    }
    private val builderClass get() = requireNotNull(_builderClass)
    
    // 延迟初始化 ResponseBody 类
    private val responseBodyClass by lazy {
        XposedHelpers.findClass("okhttp3.ResponseBody", classLoader)
    }

    // 初始化方法：注入拦截器
    fun init() {
        XposedHelpers.findAndHookMethod(
            builderClass,
            "build",
            beforeHook {
                val interceptorClass =
                    classLoader.loadClass("okhttp3.Interceptor") ?: return@beforeHook
                val method = builderClass.getMethod("addInterceptor", interceptorClass)
                val interceptor =
                    newProxyInstance(classLoader, arrayOf(interceptorClass), this)
                method.invoke(it.thisObject, interceptor)
            }
        )
    }

    // 拦截器核心逻辑
    private fun onInvoke(chain: Any): Any? {
        val request = XposedHelpers.callMethod(chain, "request")
        val response = XposedHelpers.callMethod(chain, "proceed", request)
        val body = XposedHelpers.callMethod(response, "body") ?: return response
        val contentType = XposedHelpers.callMethod(body, "contentType")
        val isOkhttpResponseBody = responseBodyClass.isInstance(body)
        
        if (isOkhttpResponseBody) {
            val bodyStr = XposedHelpers.callMethod(body, "string") ?: return response
            return runCatching {
                makeNewResponse(contentType, response, body, bodyStr)
            }.onFailure { 
                Log.d(TAG, "onInvoke: $it")
            }.onSuccess {
                val httpUrl = XposedHelpers.callMethod(request, "url")
                val method = XposedHelpers.callMethod(request, "method") as String
                Log.d(TAG, "onInvoke: $httpUrl")
                Log.d(TAG, "onInvoke: $method")
            }.getOrDefault(response)
        }
        return response
    }

    // 重新构造响应对象
    private fun makeNewResponse(contentType: Any, response: Any, body: Any, bodyStr: Any): Any {
        val newBody = XposedHelpers.callMethod(body, "create", contentType, bodyStr)
        val newResponseBuilder = XposedHelpers.callMethod(response, "newBuilder")
        XposedHelpers.callMethod(newResponseBuilder, "body", newBody)
        return XposedHelpers.callMethod(newResponseBuilder, "build")
    }

    // 动态代理实现
    override fun invoke(proxy: Any?, method: Method?, args: Array<out Any>?): Any? {
        return when (method?.name) {
            "intercept" -> {
                onInvoke(args!!.first())
            }
            else -> null
        } ?: Any()
    }
}

核心原理深度解析

1. 动态代理注入拦截器

OkHttp 拦截器机制：

// 正常使用方式
val client = OkHttpClient.Builder()
    .addInterceptor { chain ->
        val request = chain.request()
        val response = chain.proceed(request)
        // 处理响应
        response
    }
    .build()

Hook 注入流程：

fun init() {
    // 步骤 1：Hook OkHttpClient.Builder.build() 方法
    XposedHelpers.findAndHookMethod(
        builderClass,
        "build",
        beforeHook {
            // 步骤 2：加载 Interceptor 接口
            val interceptorClass = classLoader.loadClass("okhttp3.Interceptor")
            
            // 步骤 3：创建动态代理对象
            val interceptor = newProxyInstance(
                classLoader,                    // 目标 ClassLoader
                arrayOf(interceptorClass),      // 实现的接口
                this                            // InvocationHandler（当前类）
            )
            
            // 步骤 4：反射调用 addInterceptor
            val method = builderClass.getMethod("addInterceptor", interceptorClass)
            method.invoke(it.thisObject, interceptor)  // it.thisObject 是 Builder 实例
        }
    )
}

为什么用动态代理？

  • 跨 ClassLoader 问题：我们的模块类和目标应用的 OkHttp 类不在同一个 ClassLoader
  • 接口实现限制：无法直接 implements okhttp3.Interceptor （类不可见）
  • 动态代理优势：运行时创建代理对象，可以实现目标 ClassLoader 中的接口

2. InvocationHandler 接口实现

动态代理回调：

override fun invoke(proxy: Any?, method: Method?, args: Array<out Any>?): Any? {
    return when (method?.name) {
        "intercept" -> {
            onInvoke(args!!.first())  // args[0] 是 Interceptor.Chain 对象
        }
        else -> null
    } ?: Any()
}

调用时机：

  • 每次 OkHttp 发起网络请求时，会遍历所有 Interceptor
  • 调用 interceptor.intercept(chain) 方法
  • 由于我们的 interceptor 是动态代理，会触发 invoke() 回调

3. 网络请求拦截处理

完整流程分解：

private fun onInvoke(chain: Any): Any? {
    // 步骤 1：获取原始请求对象
    val request = XposedHelpers.callMethod(chain, "request")
    
    // 步骤 2：继续执行请求（获取响应）
    val response = XposedHelpers.callMethod(chain, "proceed", request)
    
    // 步骤 3：提取响应体
    val body = XposedHelpers.callMethod(response, "body") ?: return response
    
    // 步骤 4：获取内容类型
    val contentType = XposedHelpers.callMethod(body, "contentType")
    
    // 步骤 5：类型检查（确保是 ResponseBody）
    val isOkhttpResponseBody = responseBodyClass.isInstance(body)
    
    if (isOkhttpResponseBody) {
        // 步骤 6：读取响应体字符串
        val bodyStr = XposedHelpers.callMethod(body, "string") ?: return response
        
        // 步骤 7：重新构造响应（因为 body.string() 只能调用一次）
        return runCatching {
            makeNewResponse(contentType, response, body, bodyStr)
        }.onSuccess {
            // 步骤 8：打印请求信息
            val httpUrl = XposedHelpers.callMethod(request, "url")
            val method = XposedHelpers.callMethod(request, "method") as String
            Log.d(TAG, "onInvoke: $httpUrl")
            Log.d(TAG, "onInvoke: $method")
        }.getOrDefault(response)
    }
    return response
}

关键技术点：

a. ResponseBody 只能读取一次

OkHttp 的 ResponseBody.string() 内部会消耗流，只能调用一次：

// 第一次调用
val bodyStr = body.string()  // ✅ 成功

// 第二次调用
val bodyStr2 = body.string()  // ❌ 抛出 IllegalStateException: closed

解决方案：读取后重新创建 ResponseBody

private fun makeNewResponse(contentType: Any, response: Any, body: Any, bodyStr: Any): Any {
    // 1. 创建新的 ResponseBody（使用已读取的字符串）
    val newBody = XposedHelpers.callMethod(body, "create", contentType, bodyStr)
    
    // 2. 创建新的 Response 构建器
    val newResponseBuilder = XposedHelpers.callMethod(response, "newBuilder")
    
    // 3. 替换 body
    XposedHelpers.callMethod(newResponseBuilder, "body", newBody)
    
    // 4. 构建新的 Response 对象
    return XposedHelpers.callMethod(newResponseBuilder, "build")
}
b. 反射调用的必要性

为什么不能直接调用 response.body().string() ？

// ❌ 错误：编译器找不到 Response 类
val response: Response = ...  // 类型不可见

// ✅ 正确：通过反射调用
val body = XposedHelpers.callMethod(response, "body")
val bodyStr = XposedHelpers.callMethod(body, "string")

原因：

  • response 的类型是目标应用 ClassLoader 加载的 okhttp3.Response
  • 我们的模块无法直接访问该类
  • 必须使用反射 API

4. Lazy 延迟初始化

Kotlin 委托属性：

private val _builderClass by lazy {
    runCatching {
        classLoader.loadClass("okhttp3.OkHttpClient\$Builder")
    }.onFailure {
        Log.d(TAG, ": $it")
    }.getOrNull()
}
private val builderClass get() = requireNotNull(_builderClass)

工作原理：

  • by lazy 只在第一次访问时初始化
  • runCatching 捕获异常，避免崩溃
  • requireNotNull 在获取时强制非空断言

优势：

  • 延迟加载，提高启动速度
  • 避免在 handleLoadPackage 阶段加载类（可能失败）
  • 异常安全处理

private fun makeNewResponse(contentType: Any, response: Any, body: Any, bodyStr: Any): Any {
    // 修改 JSON 响应
    var modifiedBody = bodyStr.toString()
    if (modifiedBody.contains("\"vip\":false")) {
        modifiedBody = modifiedBody.replace("\"vip\":false", "\"vip\":true")
        Log.d(TAG, "Modified VIP status to true")
    }
    
    val newBody = XposedHelpers.callMethod(body, "create", contentType, modifiedBody)
    val newResponseBuilder = XposedHelpers.callMethod(response, "newBuilder")
    XposedHelpers.callMethod(newResponseBuilder, "body", newBody)
    return XposedHelpers.callMethod(newResponseBuilder, "build")
}

九、常见问题与解决方案

1. 模块未生效

可能原因：

  • LSPosed 未激活模块
  • 未选择作用域（目标应用）
  • 目标应用未重启

解决方法：

# 检查模块是否激活
adb shell ls /data/adb/modules/

# 强制停止并重启应用
adb shell am force-stop com.example.app
adb shell am start -n com.example.app/.MainActivity

2. 日志无输出

检查清单：

调试方法：

// 在关键位置添加日志
Log.d(TAG, "Step 1: handleLoadPackage")
Log.d(TAG, "Step 2: hasOkhttp = ${lpparam?.hasOkhttp()}")
Log.d(TAG, "Step 3: onCreate triggered")
Log.d(TAG, "Step 4: isMainProcess = ${context.isCurrentProcessMain()}")

3. ClassNotFoundException

错误示例：

java.lang.ClassNotFoundException: okhttp3.OkHttpClient

原因分析：

  • 目标应用使用的是其他网络库（Retrofit、Volley、HttpURLConnection）
  • OkHttp 被混淆或重新打包

解决方法：

// 使用通配符查找混淆后的类
fun findOkHttpClass(classLoader: ClassLoader): Class<*>? {
    val possibleNames = listOf(
        "okhttp3.OkHttpClient",
        "com.android.okhttp.OkHttpClient",
        "a.b.c"  // 混淆后的名称
    )
    for (name in possibleNames) {
        runCatching {
            return XposedHelpers.findClass(name, classLoader)
        }
    }
    return null
}

4. ResponseBody.string () 崩溃

错误信息：

java.lang.IllegalStateException: closed

原因：多次调用 string() 方法

解决方案：使用 makeNewResponse() 重新构造响应对象（代码中已实现）

5. 多进程重复 Hook

现象：日志重复输出多次

原因：应用使用了多进程架构

解决方法：使用 isCurrentProcessMain() 过滤（代码中已实现）

请求流程完整追踪

目标应用代码
    ↓
OkHttpClient.Builder().build()  ← Xposed Hook 注入拦截器
    ↓
OkHttpClient 实例创建完成（包含我们的拦截器）
    ↓
应用发起请求: client.newCall(request).execute()
    ↓
OkHttp 内部遍历拦截器链
    ↓
调用我们的拦截器: interceptor.intercept(chain)
    ↓
动态代理触发: invoke(proxy, method, args)
    ↓
执行我们的逻辑: onInvoke(chain)
    ↓
chain.proceed(request)  ← 继续执行请求
    ↓
获取 Response 对象
    ↓
读取 ResponseBody.string()
    ↓
打印日志 + 处理数据
    ↓
重新构造 Response（避免 stream 关闭）
    ↓
返回给应用（应用无感知）

  • 需要递归 Hook RealCall 的执行方法
