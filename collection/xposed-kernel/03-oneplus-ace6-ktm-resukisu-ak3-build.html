OnePlus ACE 6 基于 6.6.139 编译 ReSukiSU / KernelSU 系列内核并打包 AK3

OnePlus ACE 6 基于 6.6.139 编译 ReSukiSU / KernelSU 系列内核并打包 AK3

注意

刷内核有变砖和无限重启风险。本文只负责构建和打包流程，刷入前请确保手上有同系统版本的 boot.img 、能进 fastboot，并知道当前活动 slot。

一、项目目录

创建项目根目录：

mkdir -p Ace-6-Infinity-X
cd Ace-6-Infinity-X

mkdir -p src prebuilts/clang/host patches tools out

本文后面所有命令都默认从下面这个目录执行：

Ace-6-Infinity-X

核心路径含义：

路径作用
src/kernel主内核源码，ReSukiSU / KernelSU 系列 Root 驱动和补丁都接入这里
src/sm8750-modulessm8750 相关模块源码，作为源码参考和依赖来源
prebuilts/clang/host/linux-x86AOSP 预编译 Clang 工具链
out内核编译输出目录，最终 Image 会在这里生成
patches保存 SusFS、NTSync、DroidSpaces、BBRv3、Unicode Fix 补丁

tools/KernelPatchKernelPatch 的 kptools / kpimg 源码，仅 APatch 方案需要
ak3从官方 AnyKernel3 仓库拉取的 AK3 模板目录

二、下载内核源码和工具链

下载主内核源码。这里使用 Ace6-Development/android_kernel_oneplus_sm8750 的 dc4c44f3ecc0 提交；Linux 版本字符串里的 gdc4c44f3ecc0 去掉前缀 g 后，对应的 Git 短 SHA 就是 dc4c44f3ecc0 。

curl -L \
  https://codeload.github.com/Ace6-Development/android_kernel_oneplus_sm8750/tar.gz/dc4c44f3ecc041f550d9c1986ab4d4a8f70312d5 \
  -o /tmp/ktm-kernel-6.6.139-dc4c44f.tar.gz

mkdir -p src/kernel
tar --strip-components=1 -xzf /tmp/ktm-kernel-6.6.139-dc4c44f.tar.gz -C src/kernel

确认主内核版本：

sed -n '1,6p' src/kernel/Makefile

期望看到：

VERSION = 6
PATCHLEVEL = 6
SUBLEVEL = 139

下载 sm8750 modules。 /proc/version 只能精确到主内核 commit，看不出 modules commit；这里使用同组织 lineage-23.2 分支上已经用于 ktm 的 modules 提交。

curl -L \
  https://codeload.github.com/Ace6-Development/android_kernel_oneplus_sm8750-modules/tar.gz/694285bd56d8f299816fae50e6aee18d492da37d \
  -o /tmp/ktm-modules-6.6.139.tar.gz

mkdir -p src/sm8750-modules
tar --strip-components=1 -xzf /tmp/ktm-modules-6.6.139.tar.gz -C src/sm8750-modules

下载 AOSP Clang 预编译工具链：

git clone --depth 1 --branch android-16.0.0_r4 \
  https://android.googlesource.com/platform/prebuilts/clang/host/linux-x86 \
  prebuilts/clang/host/linux-x86

ReSukiSU 编译版本

下载 ReSukiSU。这里不指定分支和提交，直接使用仓库当前默认分支的最新代码：

git clone https://github.com/ReSukiSU/ReSukiSU.git src/kernel/ReSukiSU

确认本次 clone 到的提交和编译版本码：

git -C src/kernel/ReSukiSU log -1 --oneline

ReSukiSU 的内核编译版本码由 kernel/Kbuild 动态计算，公式是：

30000 + ReSukiSU git commit count + 700

可以用下面的命令提前算出来：

printf 'ReSukiSU version code = %s\n' \
  "$(expr 30000 + $(git -C src/kernel/ReSukiSU rev-list --count HEAD) + 700)"

输出的数字就是本次 AK3 包名里建议填写的 ReSukiSU 编译版本。

KernelSU 编译版本

如果只想编译官方 KernelSU 版本，可以把上面的 ReSukiSU 下载步骤替换为：

git clone https://github.com/tiann/KernelSU.git src/kernel/KernelSU

官方 KernelSU 的内核编译版本码由它自己的 kernel/Kbuild 动态计算，公式是：

30000 + KernelSU git commit count

提前查看版本码：

printf 'KernelSU version code = %s\n' \
  "$(expr 30000 + $(git -C src/kernel/KernelSU rev-list --count HEAD))"

官方 KernelSU 版本只替换 root 实现，不等同于 ReSukiSU 的 SusFS inline hook 路线。后面如果继续走 SusFS 全功能包，仍然使用 ReSukiSU；如果改用官方 KernelSU，就不要启用 KSU_SUSFS 相关配置，也不要套 ReSukiSU 专用的 SusFS 兼容逻辑。

KernelSU-Next 编译版本

如果要编译 KernelSU-Next 版本，可以把 ReSukiSU 下载步骤替换为：

git clone https://github.com/KernelSU-Next/KernelSU-Next.git src/kernel/KernelSU-Next

KernelSU-Next 的 kernel/Kbuild 会从它自己的 Git 仓库计算版本码，当前公式是：

30000 + KernelSU-Next git commit count

提前查看版本码：

printf 'KernelSU-Next version code = %s\n' \
  "$(expr 30000 + $(git -C src/kernel/KernelSU-Next rev-list --count HEAD))"

KernelSU-Next 的管理器包名按当前源码命名空间使用：

com.rifsxd.ksunext

SukiSU Ultra 编译版本

如果要编译 SukiSU Ultra 版本，可以把 ReSukiSU 下载步骤替换为：

git clone https://github.com/SukiSU-Ultra/SukiSU-Ultra.git src/kernel/SukiSU-Ultra

SukiSU Ultra 的 kernel/Kbuild 会按它自己的版本基线动态计算版本码，当前公式是：

40000 + SukiSU-Ultra main commit count - 2815

提前查看版本码：

printf 'SukiSU Ultra version code = %s\n' \
  "$(expr 40000 + $(git -C src/kernel/SukiSU-Ultra rev-list --count main) - 2815)"

SukiSU Ultra 的管理器包名按当前源码默认值使用：

com.sukisu.ultra

SukiSU Ultra 还有 CONFIG_KPM 。它不是普通 root 必需项；只有你明确要 SukiSU 的 KPM 内核模块能力时再打开，因为它会扩大内核侧 hook 能力，也更考验稳定性。

APatch / KernelPatch 方案

APatch 不是 drivers/kernelsu 这类 “编译期内置 Root 驱动”。它依赖 KernelPatch，典型流程是先得到一个可开机的 Image 或 boot.img ，再用 APatch 管理器或 KernelPatch 的 kptools / kpimg 去 patch。也就是说：

  • 做 ReSukiSU / KernelSU / KernelSU-Next / SukiSU Ultra 版本：走后面的 drivers/kernelsu 接入流程。
  • 做 APatch 版本：不要接入 drivers/kernelsu ，不要启用 CONFIG_KSU ，而是保留你需要的网络、DroidSpaces、NTSync、BBG 等普通内核特性，再额外保证 KernelPatch 需要的 kallsyms 配置。

下载 APatch 和 KernelPatch 源码：

mkdir -p tools

git clone https://github.com/bmax121/APatch.git tools/APatch
git clone https://github.com/bmax121/KernelPatch.git tools/KernelPatch

APatch / KernelPatch 对内核配置的核心要求是：

CONFIG_KALLSYMS=y
CONFIG_KALLSYMS_ALL=y

其中 CONFIG_KALLSYMS_ALL=y 对符号解析更友好。只开 CONFIG_KALLSYMS=y 也有初步支持，但可用性更依赖目标内核符号情况。

三、准备 AK3 模板

AK3 模板从官方 AnyKernel3 仓库拉取最新代码，不再解包旧内核包复用模板：

git clone --depth 1 https://github.com/osm0sis/AnyKernel3.git ak3
git -C ak3 log -1 --oneline

官方模板里的 anykernel.sh 是示例设备配置，不能原样用于 OnePlus ACE 6。ACE 6 这里按 GKI / Image-only 方式刷 boot：只替换 kernel image，不解包和回包 ramdisk，这样可以避开无 ramdisk boot 上的 No ramdisk found to unpack.Aborting... 。

把 anykernel.sh 改成下面这个 ktm 专用脚本：

cat > ak3/anykernel.sh <<'EOF'
### AnyKernel3 Ramdisk Mod Script
## osm0sis @ xda-developers

### AnyKernel setup
# global properties
properties() { '
kernel.string=OnePlus ACE 6
do.devicecheck=1
do.modules=0
do.systemless=1
do.cleanup=1
do.cleanuponabort=0
device.name1=ktm
device.name2=PLQ110
device.name3=OP6113L1
device.name4=
device.name5=
supported.versions=16
supported.patchlevels=
supported.vendorpatchlevels=
'; } # end properties


### AnyKernel install
## boot files attributes
boot_attributes() {
set_perm_recursive 0 0 755 644 $RAMDISK/*;
set_perm_recursive 0 0 750 750 $RAMDISK/init* $RAMDISK/sbin;
} # end attributes

# boot shell variables
BLOCK=boot;
IS_SLOT_DEVICE=1;
RAMDISK_COMPRESSION=auto;
PATCH_VBMETA_FLAG=auto;

# import functions/variables and setup patching - see for reference (DO NOT REMOVE)
. tools/ak3-core.sh;

# boot install
split_boot;
flash_boot;
## end boot install
EOF

如果刷入时提示设备名不匹配，先在系统里确认实际 device codename，再补进 device.name2 之类的位置：

adb shell getprop ro.product.device
adb shell getprop ro.build.product
adb shell getprop ro.product.vendor.device

后续只替换：

ak3/Image

这样可以使用最新 AnyKernel3 的 tools/magiskboot 、 tools/ak3-core.sh 和刷入逻辑，同时避免旧包模板里残留的设备私货。

四、接入 ReSukiSU / KernelSU 系列

进入项目根目录：

cd Ace-6-Infinity-X

默认把 ReSukiSU 接到内核 drivers 下。 ROOT_IMPL 只选一个，取值可以是 ReSukiSU 、 KernelSU 、 KernelSU-Next 、 SukiSU-Ultra ：

ROOT_IMPL=ReSukiSU
ln -s "../${ROOT_IMPL}/kernel" src/kernel/drivers/kernelsu

然后把 drivers/kernelsu 加入内核构建系统：

printf '\nobj-$(CONFIG_KSU) += kernelsu/\n' \
  >> src/kernel/drivers/Makefile

sed -i '$i source "drivers/kernelsu/Kconfig"' \
  src/kernel/drivers/Kconfig

修复当前编译链路里的兼容点：

sed -i '/ccflags-y += -Wno-int-to-pointer-cast/a ccflags-y += -I$(objtree)/security/selinux' \
  src/kernel/ReSukiSU/kernel/Kbuild

第二条 Kbuild 修改只针对 ReSukiSU。官方 KernelSU、KernelSU-Next、SukiSU Ultra 当前 kernel/Kbuild 已经包含 $(objtree)/security/selinux ，不需要再改。

ReSukiSU 安装脚本，在内核的根目录执行以下命令：：

curl -LSs "https://raw.githubusercontent.com/ReSukiSU/ReSukiSU/main/kernel/setup.sh" | bash

如果走 APatch 方案，跳过本节所有 drivers/kernelsu 相关操作。APatch 不需要 CONFIG_KSU ，后面只保留普通内核功能补丁和 CONFIG_KALLSYMS / CONFIG_KALLSYMS_ALL 。

这些修改的作用：

修改原因
drivers/kernelsu symlink让内核源码能找到 ReSukiSU / KernelSU / KernelSU-Next / SukiSU Ultra 的 kernel 部分
drivers/Makefile让 CONFIG_KSU=y 时编译 KSU 实现
drivers/Kconfig让 KSU 配置项进入内核配置系统
libbpf.c 类型调整修复当前 Clang 下的类型不匹配编译问题
Kbuild 增加 $(objtree)/security/selinux让 ReSukiSU 能找到 prepare 阶段生成的 SELinux 头文件

六、接入 BBG

下载 Baseband Guard：

git clone https://github.com/vc-teahouse/Baseband-guard.git \
  src/kernel/Baseband-guard

git -C src/kernel/Baseband-guard checkout a54e0dc6cf0aff4dd87fec49644a02d2eb612905

接入 security 子系统：

ln -s ../Baseband-guard src/kernel/security/baseband-guard

printf '\nobj-$(CONFIG_BBG) += baseband-guard/\n' \
  >> src/kernel/security/Makefile

sed -i '/source "security\/selinux\/Kconfig"/a source "security/baseband-guard/Kconfig"' \
  src/kernel/security/Kconfig

sed -i 's/selinux,smack/selinux,baseband_guard,smack/' \
  src/kernel/security/Kconfig

这里不打开 BBG_BLOCK_BOOT 和 BBG_BLOCK_RECOVERY ，避免影响后续刷入 boot/recovery 相关分区。

七、提取内核配置

准备同系统版本的原厂 boot.img ，然后解包：

magiskboot unpack /path/to/boot.img

解包后当前目录会出现 kernel ，从里面提取当前 ROM 的内核配置：

mkdir -p out

src/kernel/scripts/extract-ikconfig kernel > out/.config

这一步很关键。不要凭空使用 defconfig，直接用当前 ROM 可开机的 boot 配置当底子，稳定性会好很多。

八、写入最终配置

src/kernel/scripts/config --file out/.config \
  --enable KSU \
  --disable KSU_TRACEPOINT_HOOK \
  --enable KSU_SUSFS \
  --enable KSU_SUSFS_ENABLE_LOG \
  --enable KSU_SUSFS_SUS_PATH \
  --enable KSU_SUSFS_SUS_MOUNT \
  --enable KSU_SUSFS_SUS_KSTAT \
  --enable KSU_SUSFS_SPOOF_UNAME \
  --enable KSU_SUSFS_HIDE_KSU_SUSFS_SYMBOLS \
  --enable KSU_SUSFS_SPOOF_CMDLINE_OR_BOOTCONFIG \
  --enable KSU_SUSFS_OPEN_REDIRECT \
  --enable KSU_SUSFS_SUS_MAP \
  --enable NTSYNC \
  --enable BBG \
  --disable BBG_BLOCK_BOOT \
  --disable BBG_BLOCK_RECOVERY \
  --enable TCP_CONG_ADVANCED \
  --enable TCP_CONG_BBR \
  --enable TCP_CONG_BBR3 \
  --enable IP_SET \
  --enable IP_SET_HASH_IP \
  --enable IP_SET_HASH_NET \
  --enable NETFILTER_XT_SET \
  --enable NETFILTER_XT_MATCH_ADDRTYPE \
  --enable IP_NF_MANGLE \
  --enable IP_NF_TARGET_TTL \
  --enable IP6_NF_MANGLE \
  --enable IP6_NF_MATCH_HL \
  --enable IP6_NF_TARGET_HL \
  --enable IP6_NF_NAT \
  --enable IP6_NF_TARGET_MASQUERADE \
  --enable SYSVIPC \
  --enable IPC_NS \
  --enable DEVTMPFS \
  --enable PID_NS \
  --enable POSIX_MQUEUE \
  --enable USER_NS \
  --enable NETFILTER_XT_TARGET_REJECT \
  --enable NETFILTER_XT_TARGET_LOG \
  --enable NETFILTER_XT_MATCH_RECENT \
  --enable TMPFS_XATTR \
  --enable TMPFS_POSIX_ACL \
  --enable SECURITY_NETWORK \
  --enable SECURITY_SELINUX \
  --enable SECURITY_SELINUX_DEVELOP \
  --enable SECURITY_SELINUX_AVC_STATS \
  --enable DEFAULT_SECURITY_SELINUX \
  --set-val SECURITY_SELINUX_SIDTAB_HASH_BITS 9 \
  --set-val SECURITY_SELINUX_SID2STR_CACHE_SIZE 256 \
  --set-val SECURITY_SELINUX_AVC_HASH_BITS 9 \
  --set-str LSM "landlock,lockdown,yama,loadpin,safesetid,selinux,baseband_guard,smack,tomoyo,apparmor,bpf" \
  --set-str LOCALVERSION "-4k-gdc4c44f3ecc0-dirty"

这里手动带上 -dirty 只是为了让本机编译出的版本字符串对齐当前系统显示的 6.6.139-4k-gdc4c44f3ecc0-dirty 。 dirty 不是 commit SHA 的一部分；公开源码能精确对应到 dc4c44f3ecc0 ，系统包里的 -dirty 部分只能说明维护者构建时树上还有未提交修改。如果不想手动伪装这个状态，可以把这一项改成 -4k-gdc4c44f3ecc0 。

如果这次选择官方 KernelSU 或普通 KernelSU-Next 版本，不要启用 ReSukiSU 的 SusFS inline hook 选项。也就是从上面的配置命令里删除这些行：

  --disable KSU_TRACEPOINT_HOOK \
  --enable KSU_SUSFS \
  --enable KSU_SUSFS_ENABLE_LOG \
  --enable KSU_SUSFS_SUS_PATH \
  --enable KSU_SUSFS_SUS_MOUNT \
  --enable KSU_SUSFS_SUS_KSTAT \
  --enable KSU_SUSFS_SPOOF_UNAME \
  --enable KSU_SUSFS_HIDE_KSU_SUSFS_SYMBOLS \
  --enable KSU_SUSFS_SPOOF_CMDLINE_OR_BOOTCONFIG \
  --enable KSU_SUSFS_OPEN_REDIRECT \
  --enable KSU_SUSFS_SUS_MAP \

如果这次选择 SukiSU Ultra，基础 root 可以和官方 KernelSU 一样不启用 KSU_SUSFS ；只有你已经额外套了适配 SukiSU / KernelSU-Next 路线的 SusFS 兼容补丁，并确认 drivers/kernelsu/Kconfig 暴露这些 KSU_SUSFS 配置项时，才保留上面的 SusFS 配置。需要 SukiSU KPM 时，再额外打开：

src/kernel/scripts/config --file out/.config \
  --enable KPM \
  --enable KALLSYMS \
  --enable KALLSYMS_ALL

如果这次选择 APatch 方案，跳过所有 KSU / KSU_SUSFS 配置，改成只打开 APatch / KernelPatch 需要的 kallsyms：

src/kernel/scripts/config --file out/.config \
  --disable KSU \
  --disable KSU_SUSFS \
  --enable KALLSYMS \
  --enable KALLSYMS_ALL

几个关键点：

配置说明
KSU=y启用 ReSukiSU / KernelSU / KernelSU-Next / SukiSU Ultra
KSU_TRACEPOINT_HOOK=nSusFS 模式下不走 tracepoint hook
KSU_SUSFS=y启用 SusFS inline hook 路线
NTSYNC=y启用 NTSync
BBG=y启用 Baseband Guard
TCP_CONG_BBR=y / TCP_CONG_BBR3=y同时编入 BBR 和 BBRv3
IP_NF_TARGET_TTL=y / IP6_NF_TARGET_HL=y支持 IPv4 TTL 和 IPv6 HL 修改
IP_SET=y支持 ipset
IP6_NF_NAT=y支持 IPv6 NAT
SYSVIPC / POSIX_MQUEUEDroidSpaces 需要的 IPC 基础能力
IPC_NS / PID_NS / USER_NSDroidSpaces 需要的 namespace 能力
KALLSYMS / KALLSYMS_ALLAPatch / KernelPatch 解析和 patch kernel image 时需要的符号信息

IPC_NS 是 IPC namespace。它让 System V IPC、POSIX 消息队列这类 IPC 对象可以按 namespace 隔离。DroidSpaces 这类容器 / Android 子空间需要它来给容器自己的共享内存、信号量、消息队列做隔离；否则容器可能只能共用宿主 Android 的 IPC 空间，轻则隔离不完整，重则运行时直接报 “不支持 IPC namespace” 之类的问题。

不要在 ReSukiSU 路线上额外套 WildKernels 里的 ksu/next/susfs_fix_patches 。那一组是给 KernelSU-Next / SukiSU 方向准备的，ReSukiSU 这里走自己的兼容逻辑。

九、生成配置并编译 Image

先让 Kconfig 处理依赖关系：

make -C src/kernel \
  O=$(pwd)/out \
  ARCH=arm64 \
  LLVM=$(pwd)/prebuilts/clang/host/linux-x86/clang-r563880c/bin/ \
  LLVM_IAS=1 \
  olddefconfig

生成 SELinux 头文件：

mkdir -p out/security/selinux

make -C src/kernel \
  O=$(pwd)/out \
  ARCH=arm64 \
  LLVM=$(pwd)/prebuilts/clang/host/linux-x86/clang-r563880c/bin/ \
  LLVM_IAS=1 \
  PAHOLE=/usr/bin/pahole \
  HOSTPKG_CONFIG=/usr/bin/pkg-config \
  prepare

out/scripts/selinux/genheaders/genheaders \
  out/security/selinux/flask.h \
  out/security/selinux/av_permissions.h

编译 Image ：

CCACHE_BASEDIR=$(pwd) \
CCACHE_NOHASHDIR=1 \
CCACHE_COMPILERCHECK=mtime \
make -C src/kernel \
  O=$(pwd)/out \
  ARCH=arm64 \
  LLVM=$(pwd)/prebuilts/clang/host/linux-x86/clang-r563880c/bin/ \
  LLVM_IAS=1 \
  CC="ccache $(pwd)/prebuilts/clang/host/linux-x86/clang-r563880c/bin/clang" \
  HOSTCC="ccache gcc" \
  HOSTCXX="ccache g++" \
  PAHOLE=/usr/bin/pahole \
  HOSTPKG_CONFIG=/usr/bin/pkg-config \
  KSU_MANAGER_PACKAGE=com.resukisu.resukisu \
  -j16 Image

如果这次编译的是官方 KernelSU 版本，把最后的 manager package 改成官方包名：

  KSU_MANAGER_PACKAGE=me.weishu.kernelsu \

KernelSU-Next 版本改成：

  KSU_MANAGER_PACKAGE=com.rifsxd.ksunext \

SukiSU Ultra 版本改成：

  KSU_MANAGER_PACKAGE=com.sukisu.ultra \

APatch 方案没有 KSU_MANAGER_PACKAGE 。如果你是在编译 “等待 APatch 后处理” 的普通内核，直接删掉 KSU_MANAGER_PACKAGE=... 这一行。

编译成功后，目标文件在：

out/arch/arm64/boot/Image

如果只是改源码后重新编译，不要删除 out ，这样 ccache 和增量构建才有意义。

十、打包 AK3

把新编译出的 Image 放入 AK3 模板：

cd Ace-6-Infinity-X

install -m 0644 \
  out/arch/arm64/boot/Image \
  ak3/Image

如果你做的是 APatch 完整方案，不建议只把 raw Image 塞进 AK3 就当成完整 APatch 包。APatch 管理器通常 patch 的是 boot.img ，除了 kernel image 以外还会处理 APatch 自己的用户态组件和启动逻辑；单纯 AK3 Image-only 模板只替换 Image ，不等同于 APatch 管理器生成的 patched boot。

如果你只想得到 KernelPatch core patched Image 用于实验，可以先按 KernelPatch 文档编出 kpimg 和 kptools ，再把 patched Image 放进 ak3/Image ：

export TARGET_COMPILE=aarch64-none-elf-
export ANDROID=1

make -C tools/KernelPatch/kernel
make -C tools/KernelPatch/tools

APATCH_SUPERKEY='换成你自己的强口令'

tools/KernelPatch/tools/kptools -p \
  -i out/arch/arm64/boot/Image \
  -k tools/KernelPatch/kernel/kpimg \
  -S "$APATCH_SUPERKEY" \
  -o ak3/Image

这条 APatch/KernelPatch 路线要求前面的内核配置至少有 CONFIG_KALLSYMS=y ，推荐同时有 CONFIG_KALLSYMS_ALL=y 。

打包：

十二、刷入后的基础验证

刷入并成功重启后，可以用下面的命令确认几个核心功能。

确认 BBR / BBRv3 已注册：

adb shell su -c 'cat /proc/sys/net/ipv4/tcp_available_congestion_control; cat /proc/sys/net/ipv4/tcp_congestion_control'

能看到 bbr 和 bbr3 即可。默认拥塞控制仍然是 cubic 也正常，是否改默认值是另一个行为选择。

确认 BBG 初始化：

adb shell su -c 'dmesg | grep -i baseband'

如果能看到 baseband_guard 相关日志，说明 BBG 已经进入内核运行路径。

确认 ReSukiSU / KernelSU / KernelSU-Next / SukiSU Ultra：

adb shell su -c id

能返回 uid=0(root) 说明 root 链路正常。SusFS 的具体功能还需要在对应管理器里按需启用，不建议刚刷完就一次性打开所有隐藏规则。

APatch 版本以 APatch 管理器识别状态和 SuperKey 授权为准。如果你只是用 KernelPatch core patched Image 做实验，它不等同于完整 APatch 管理器安装状态。

十三、常见注意点

boot.img 必须来自同设备、同系统版本。混用 ROM 版本会让问题变得很难排查。

ak3 来自官方 AnyKernel3 最新仓库后，必须检查 anykernel.sh 是否已经改成 ktm 的最小刷入逻辑。AK3 失败时，问题经常不在 Image ，而在 anykernel.sh 、slot 处理、boot 解包 / 回写逻辑。

如果只改普通源码，直接重新运行 make ... Image 。如果改了 SELinux 相关头生成路径，才重新跑 prepare 和 genheaders 。

SusFS 模式下不要再启用 KSU_TRACEPOINT_HOOK 。最终期望状态是：

# CONFIG_KSU_TRACEPOINT_HOOK is not set
CONFIG_KSU_SUSFS=y
