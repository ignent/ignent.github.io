变量

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的变量写法。

在汇编里，变量不是高级语言里那种带类型、作用域和自动初始化规则的 “盒子”。更接近真实情况的是：

变量 = 一个标签名 + 一段内存字节 + 选择的读写宽度

例如：

counter:
    .quad 41

counter 是地址名字， .quad 41 表示从这个地址开始放 8 字节整数。CPU 只看到地址和字节；“变量名”、 long 、 uint64_t 、指针这些含义，都由使用什么指令读写来决定。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的变量读写指令很像，但段名、入口、链接方式和全局符号取地址写法不同。

初学阶段先记住三类变量：

  • 已初始化全局变量：放在 .data 或 __DATA,__data ，文件里保存初始值，运行时可读写。
  • 未初始化全局变量：放在 .bss 或 __DATA,__bss ，文件里通常不保存大量 0，运行时由加载器清零。
  • 局部变量：通常放在栈上，由函数进入时分配，返回前释放。

2. 变量声明：标签和伪指令

汇编里的变量通常长这样：

name:
    .quad 123

其中：

  • name: 是标签，代表当前地址。
  • .quad 123 是伪指令，告诉汇编器在当前位置放入一个 8 字节整数。
  • CPU 运行时不会执行 .quad ；CPU 只会看到这 8 个字节已经在内存里。

常见数据定义伪指令：

伪指令常见大小示例含义
.byte1 字节.byte 65一个字节，65 是 ASCII A
.short2 字节.short 10002 字节整数
.word目标相关，很多环境中是 2 或 4 字节.word 1000容易跨平台混淆，初学少依赖
.long4 字节.long 1000004 字节整数
.quad8 字节.quad 1000008 字节整数
.ascii字符串长度.ascii "hi\n"原样写入字节，不自动追加 \0
.asciz字符串长度 + 1.asciz "hi"写入字符串并追加 \0
.space nn 字节.space 64预留 n 字节，通常填 0
.zero nn 字节.zero 64写入 n 个 0

为了少踩坑，本系列会优先使用：

.byte   # 1 字节
.short  # 2 字节
.long   # 4 字节
.quad   # 8 字节

在 AArch64 文档和代码里也常看到 .hword 、 .word 、 .xword 、 .8byte 等写法。这些值能工作，但跨平台教程里保持少量固定写法更清爽。

3. .data 、 .bss 、 .rodata 分别放什么

3.1 .data ：有初始值、可修改

.section .data
counter:
    .quad 41

counter 有初始值 41 。可执行文件里会保存这个初始值，程序运行时这块内存通常可读写。

适合放：

  • 需要修改的全局整数。
  • 需要修改的字符串缓冲区。
  • 有初始值的全局数组。

3.2 .bss ：没写初始值、启动时清零

.section .bss
buffer:
    .space 128

.bss 里的空间运行时会被清零。可执行文件里通常只记录 “需要 128 字节”，不会真的保存 128 个 0。

适合放：

  • 大缓冲区。
  • 未初始化全局数组。
  • 程序运行时才写入的结果。

3.3 .rodata ：只读数据

.section .rodata
msg:
    .ascii "hello\n"
msg_len = . - msg

.rodata 通常映射为只读。适合放不会修改的字符串、查表数据、常量数组。

不要写入 .rodata 。现代系统通常会让程序崩溃，或者返回内存保护错误。

3.4 macOS 的段名

macOS arm64 使用 Mach-O。常见写法是：

.section __DATA,__data
counter:
    .quad 41

.zerofill __DATA,__bss,buffer,128,4

.section __TEXT,__const
msg:
    .ascii "hello\n"

这里 __DATA 、 __TEXT 是 Mach-O segment 名， __data 、 __bss 、 __const 是 section 名。

4. x86-64 Linux：读写全局变量

这个例子做三件事：

  1. 从 .data 里的 counter 读取初始值 41 。
  2. 加 1 得到 42 。
  3. 写入 .bss 里的 answer ，再读出来作为退出码。

文件名： var-x86-64.s

.section .data
.balign 8
counter:
    .quad 41                                # 已初始化全局变量，占 8 字节

.section .bss
.balign 8
answer:
    .space 8                                # 未初始化全局变量，运行时清零，占 8 字节

.section .text
.global _start
_start:
    # 1. 读取 counter。
    #    counter(%rip) 表示 counter 这个地址里的 8 字节内容。
    mov counter(%rip), %rax                 # rax = counter = 41

    # 2. 修改寄存器里的值。
    add $1, %rax                            # rax = 42

    # 3. 写入 answer。
    #    answer 是 .bss 中的全局变量，运行时可写。
    mov %rax, answer(%rip)                  # answer = 42

    # 4. 再从 answer 读出来，作为退出码。
    mov answer(%rip), %rdi                  # rdi = answer = 42

    # 5. exit(rdi)
    mov $60, %rax                           # rax = 60，Linux x86-64 exit 系统调用号
    syscall

编译运行：

as --64 var-x86-64.s -o var-x86-64.o
ld var-x86-64.o -o var-x86-64
./var-x86-64
echo $?

预期输出：

42

注意这两条的差别：

lea counter(%rip), %rax     # rax = counter 的地址
mov counter(%rip), %rax     # rax = counter 地址里的值

变量读写里最常见的错误，就是把 “地址” 和 “地址里的值” 搞反。

5. AArch64 Linux：读写全局变量

文件名： var-aarch64.s

.section .data
.balign 8
counter:
    .quad 41                                // 已初始化全局变量，占 8 字节

.section .bss
.balign 8
answer:
    .space 8                                // 未初始化全局变量，运行时清零，占 8 字节

.section .text
.global _start
_start:
    // 1. 取 counter 的地址到 x9。
    //    Linux AArch64/ELF 常用 adrp + add :lo12: 取全局地址。
    adrp x9, counter                         // x9 = counter 所在 4KB 页地址
    add x9, x9, :lo12:counter                // x9 = counter 的完整地址

    // 2. 读取 counter。
    ldr x0, [x9]                             // x0 = counter = 41

    // 3. 修改寄存器里的值。
    add x0, x0, #1                           // x0 = 42

    // 4. 取 answer 的地址到 x10。
    adrp x10, answer                         // x10 = answer 所在页地址
    add x10, x10, :lo12:answer               // x10 = answer 的完整地址

    // 5. 写入 answer，再读出来。
    str x0, [x10]                            // answer = 42
    ldr x0, [x10]                            // x0 = answer = 42

    // 6. exit(x0)
    mov x8, #93                              // x8 = 93，Linux AArch64 exit 系统调用号
    svc #0

编译运行：

as var-aarch64.s -o var-aarch64.o
ld var-aarch64.o -o var-aarch64
./var-aarch64
echo $?

预期输出：

42

AArch64 没有 x86-64 那种 counter(%rip) 直接读全局变量的写法。通常先把变量地址放进寄存器，再用 ldr 或 str 访问。

6. macOS arm64：读写全局变量

文件名： var-macos-arm64.s

.section __DATA,__data
.p2align 3
counter:
    .quad 41                                // 已初始化全局变量，占 8 字节

// Mach-O 的零填充变量常用 .zerofill：
//   __DATA   segment 名
//   __bss    section 名
//   answer   符号名
//   8        预留 8 字节
//   3        2^3 = 8 字节对齐
.zerofill __DATA,__bss,answer,8,3

.text
.globl _main
.p2align 2
_main:
    // 1. 取 counter 的地址。
    //    macOS arm64/Mach-O 常用 @PAGE + @PAGEOFF 重定位。
    adrp x9, counter@PAGE                    // x9 = counter 所在 4KB 页地址
    add x9, x9, counter@PAGEOFF              // x9 = counter 的完整地址

    // 2. 读取 counter。
    ldr x0, [x9]                             // x0 = counter = 41

    // 3. 修改寄存器里的值。
    add x0, x0, #1                           // x0 = 42

    // 4. 取 answer 的地址。
    adrp x10, answer@PAGE                    // x10 = answer 所在页地址
    add x10, x10, answer@PAGEOFF             // x10 = answer 的完整地址

    // 5. 写入 answer，再读出来。
    str x0, [x10]                            // answer = 42
    ldr x0, [x10]                            // x0 = answer = 42

    // 6. main 的返回值放在 w0/x0。
    //    C 运行时会把低 8 位作为进程退出码，所以 echo $? 会看到 42。
    ret

编译运行：

clang var-macos-arm64.s -o var-macos-arm64
./var-macos-arm64
echo $?

预期输出：

42

这段代码没有调用其他函数，所以 _main 是叶子函数，不需要保存 x29/x30 。

7. 变量宽度：同一个地址可以按不同大小读

变量到底是 1 字节、4 字节还是 8 字节，取决于两件事：

  1. 在数据区放了多少字节。
  2. 使用多宽的指令去读写。

例如：

value:
    .quad 0x1122334455667788

在常见的 x86-64 和 AArch64 小端环境里，内存低地址先放最低有效字节，所以内存大致是：

地址偏移   字节
+0         0x88
+1         0x77
+2         0x66
+3         0x55
+4         0x44
+5         0x33
+6         0x22
+7         0x11

如果按 1 字节读，得到 0x88 ；按 8 字节读，得到完整的 0x1122334455667788 。

x86-64：

movzbq value(%rip), %rax      # 读 1 字节，零扩展到 64 位
mov value(%rip), %rax         # 读 8 字节

AArch64/macOS arm64：

ldrb w0, [x9]                 // 读 1 字节，零扩展到 w0
ldr x0, [x9]                  // 读 8 字节

所以，“变量类型” 不是写在标签上的魔法。需要让数据定义伪指令、读写指令和意图保持一致。

8. 可修改字符串变量

字符串如果放在可写数据段，就可以修改。下面三个程序都会把字符串开头的小写 h 改成大写 H ，然后打印出来。

8.1 x86-64 Linux

文件名： mutable-string-x86-64.s

.section .data
msg:
    .ascii "hello from mutable .data\n"       # 放在 .data，运行时可修改
msg_len = . - msg

.section .text
.global _start
_start:
    # 把 msg[0] 从 'h' 改成 'H'。
    # ASCII 'H' = 72。
    movb $72, msg(%rip)                       # *(uint8_t *)msg = 72

    # write(1, msg, msg_len)
    mov $1, %rax                              # rax = write 系统调用号
    mov $1, %rdi                              # rdi = fd = 1，标准输出
    lea msg(%rip), %rsi                       # rsi = msg 的地址
    mov $msg_len, %rdx                        # rdx = 字符串长度
    syscall

    # exit(0)
    mov $60, %rax
    xor %rdi, %rdi
    syscall

运行：

as --64 mutable-string-x86-64.s -o mutable-string-x86-64.o
ld mutable-string-x86-64.o -o mutable-string-x86-64
./mutable-string-x86-64

预期输出：

Hello from mutable .data

8.2 AArch64 Linux

文件名： mutable-string-aarch64.s

.section .data
msg:
    .ascii "hello from mutable .data\n"       // 放在 .data，运行时可修改
msg_len = . - msg

.section .text
.global _start
_start:
    // 取 msg 地址。
    adrp x9, msg
    add x9, x9, :lo12:msg

    // 把 msg[0] 从 'h' 改成 'H'。
    // ASCII 'H' = 72。
    mov w10, #72                              // w10 = 72
    strb w10, [x9]                            // *(uint8_t *)msg = 72

    // write(1, msg, msg_len)
    mov x8, #64                               // x8 = write 系统调用号
    mov x0, #1                                // x0 = fd = 1，标准输出
    mov x1, x9                                // x1 = msg 的地址
    mov x2, #msg_len                          // x2 = 字符串长度
    svc #0

    // exit(0)
    mov x8, #93
    mov x0, #0
    svc #0

运行：

as mutable-string-aarch64.s -o mutable-string-aarch64.o
ld mutable-string-aarch64.o -o mutable-string-aarch64
./mutable-string-aarch64

预期输出：

Hello from mutable .data

8.3 macOS arm64

文件名： mutable-string-macos-arm64.s

.section __DATA,__data
msg:
    .ascii "hello from mutable __DATA,__data\n"  // 放在可写数据段
msg_len = . - msg

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _write，所以先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    // 取 msg 地址。
    adrp x9, msg@PAGE
    add x9, x9, msg@PAGEOFF

    // 把 msg[0] 从 'h' 改成 'H'。
    // ASCII 'H' = 72。
    mov w10, #72                              // w10 = 72
    strb w10, [x9]                            // *(uint8_t *)msg = 72

    // write(1, msg, msg_len)
    mov x0, #1                                // x0 = fd = 1，标准输出
    mov x1, x9                                // x1 = msg 的地址
    mov x2, #msg_len                          // x2 = 字符串长度
    bl _write                                 // 调用 libSystem 的 write()

    mov w0, #0                                // main 返回 0
    ldp x29, x30, [sp], #16
    ret

运行：

clang mutable-string-macos-arm64.s -o mutable-string-macos-arm64
./mutable-string-macos-arm64
echo $?

预期输出：

Hello from mutable __DATA,__data
0

如果把这些字符串放进 .rodata 或 __TEXT,__const 再尝试写入，程序通常会因为内存保护而失败。只读段适合放不会改的内容。

9. 栈上的局部变量

全局变量放在可执行文件的数据段里。局部变量通常放在栈上。

x86-64 Linux 示例片段：

sub $16, %rsp                    # 分配 16 字节栈空间
movq $7, 8(%rsp)                 # 栈上 offset 8 的位置保存局部变量 7
mov 8(%rsp), %rax                # 读取这个局部变量
add $16, %rsp                    # 释放栈空间

AArch64/macOS arm64 示例片段：

sub sp, sp, #16                  // 分配 16 字节栈空间
mov x0, #7
str x0, [sp, #8]                 // 栈上 offset 8 的位置保存局部变量 7
ldr x1, [sp, #8]                 // 读取这个局部变量
add sp, sp, #16                  // 释放栈空间

栈变量的特点：

  • 函数进入时分配，函数返回前释放。
  • 常用 sp / rsp 加偏移访问。
  • 生命周期短，适合临时数据。
  • 函数调用前后要遵守 ABI 的栈对齐要求，AArch64/macOS arm64 尤其要保持 sp 16 字节对齐。

如果一个函数调用了其他函数，还要考虑保存返回地址和 callee-saved 寄存器。这个主题会在 “过程” 和 “递归” 章节继续展开。

10. 符号可见性：局部符号和外部符号

默认情况下，标签可以被汇编器和链接器记录为符号，但不一定适合被其他文件引用。想让某个符号对链接器全局可见，常用 .global 或 .globl 。

x86-64/Linux：

.section .data
.global shared_counter
shared_counter:
    .quad 0

macOS arm64 中，如果这个符号要按 C 语言名字 shared_counter 暴露给外部，汇编里通常要写前导下划线：

.section __DATA,__data
.globl _shared_counter
_shared_counter:
    .quad 0

多数变量只在同一个 .s 文件内部使用，所以没有给这些值加 .global 。入口点 _start 、 _main 必须导出给链接器，所以需要 .global _start 或 .globl _main 。

11. 对齐：让变量站在合适的地址上

多字节变量最好按大小对齐：

数据建议对齐
.byte1 字节
.short2 字节
.long4 字节
.quad8 字节

Linux/GAS 常见：

.balign 8
value:
    .quad 123

macOS 也常见 .p2align ：

.p2align 3        // 2^3 = 8
value:
    .quad 123

为什么要对齐：

  • CPU 读取对齐数据通常更快。
  • 某些指令或平台对未对齐访问有限制。
  • 结构体、数组和 ABI 常常要求特定对齐。

入门时可以简单记：放 .quad 前加 8 字节对齐，放函数入口前常见 .p2align 2 。

12. 用工具观察变量

Linux ELF 查看 section：

readelf -S var-x86-64 | egrep 'Name|\\.data|\\.bss|\\.rodata'
objdump -s -j .data var-x86-64

AArch64 交叉工具链：

aarch64-linux-gnu-readelf -S var-aarch64 | egrep 'Name|\\.data|\\.bss|\\.rodata'
aarch64-linux-gnu-objdump -s -j .data var-aarch64

macOS Mach-O：

size -m var-macos-arm64
otool -l var-macos-arm64 | egrep 'segname|sectname|__DATA|__TEXT|__bss|__data'

想看符号表：

nm var-x86-64 | grep 'counter\\|answer'
nm var-macos-arm64 | grep 'counter\\|answer'

注意：如果符号没有导出，或者链接器做了优化，符号显示方式可能不同。学习阶段先观察 section 和输出结果即可。

13. 常见坑

13.1 把变量名当成变量值

x86-64：

lea counter(%rip), %rax      # rax = counter 的地址
mov counter(%rip), %rax      # rax = counter 的值

AArch64：

adrp x9, counter
add x9, x9, :lo12:counter    // x9 = counter 的地址
ldr x0, [x9]                 // x0 = counter 的值

标签是地址名字。要拿值，必须读内存。

13.2 写入只读段

.section .rodata
msg:
    .ascii "hello\n"

这种内容不应该修改。想要可变字符串，放 .data 或 __DATA,__data 。

13.3 .ascii 不自动追加 \0

.ascii "hi"     # 只有两个字节：h i
.asciz "hi"     # 三个字节：h i \0

write 不需要 \0 ，因为 write 靠长度参数。C 字符串函数通常需要 \0 。

13.4 .bss 不是随机垃圾

.bss 里的静态存储运行时会被清零。该指令不是未定义随机内容。下面这样的缓冲区启动时全是 0：

.section .bss
buf:
    .space 128

13.5 宽度不匹配

如果声明了 8 字节变量，却只写 1 字节，只会改最低地址那个字节：

value:
    .quad 0

movb $1, value(%rip)     # 只写 1 字节，不是写完整 8 字节

有时这是需要要的，有时是 bug。写变量时要想清楚读写宽度。

14. 小练习

  1. 把 counter 从 41 改成 99 ，让程序退出码变成 100 。
  2. 把 answer 从 .space 8 改成 .space 1 ，再思考为什么 8 字节 str / mov 会越界写。
  3. 把 mutable string 示例中的 movb $72 或 mov w10, #72 改成 ASCII 65 ，观察首字母变成什么。
  4. 把字符串从 .ascii 改成 .asciz ，再把 msg_len 计算放在 .asciz 后面，观察输出是否多写了一个不可见的 \0 。
  5. 用 objdump -s -j .data 或 otool 观察 .data 里 41 的字节顺序。
