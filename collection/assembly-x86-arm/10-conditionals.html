条件判断

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的条件判断。

高级语言里的条件判断通常写成：

if (age >= 18) {
    result = 1;
} else {
    result = 0;
}

汇编里没有 if 这个关键字。CPU 通常按下面几步完成条件判断：

1. 比较两个值，或者测试某些 bit
2. 设置条件标志位
3. 根据标志位决定跳不跳转
4. 或者根据标志位选择一个值

重点建立三个直觉：

  • cmp 只比较，不保存减法结果。
  • 条件跳转看的不是 “变量名”，而是上一条比较 / 测试指令留下的标志位。
  • 同一组二进制位，用 “有符号” 和 “无符号” 条件判断，结果可能完全不同。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的条件判断指令基本相同；差异主要在入口、链接方式和系统调用 / 退出方式。

两个最重要的写法差异：

# x86-64 AT&T：比较 rax 和 18
# cmp $18, %rax 的含义是“计算 rax - 18，只更新标志位，不保存结果”
cmp $18, %rax
jge adult
// AArch64/macOS arm64：比较 x0 和 18
// cmp x0, #18 的含义是“计算 x0 - 18，只更新 NZCV，不保存结果”
cmp x0, #18
b.ge adult

x86-64 AT&T 语法通常是 源操作数在前，目标操作数在后；AArch64 通常把主要输入寄存器写在前面，条件后缀写成 b.eq 、 b.lt 这种形式。

2. 条件判断的核心：标志位

2.1 x86-64 的 RFLAGS

x86-64 的比较和测试会更新 RFLAGS 中的状态位。入门阶段先记这几个：

标志位名称直觉
ZFZero Flag结果是否为 0
SFSign Flag结果最高位是否为 1，常用于有符号数
CFCarry Flag无符号加法进位，或无符号减法借位
OFOverflow Flag有符号运算是否溢出

cmp $18, %rax 可以理解成：

临时计算：rax - 18
保存结果：不保存
更新标志：更新 ZF/CF/SF/OF 等标志位

如果 %rax 是 18 ，临时结果是 0 ，所以 ZF=1 ，后面的 je 或 jz 会跳转。

2.2 AArch64 的 NZCV

AArch64 把常见条件标志称为 NZCV ：

标志位名称直觉
NNegative结果最高位是否为 1
ZZero结果是否为 0
CCarry加法进位；减法时表示没有借位
VOverflow有符号运算是否溢出

cmp x0, #18 是 subs xzr, x0, #18 的别名，可以理解成：

临时计算：x0 - 18
保存结果：丢到零寄存器 xzr，所以看起来就是“不保存”
更新标志：更新 N/Z/C/V

如果 x0 是 18 ，临时结果是 0 ，所以 Z=1 ，后面的 b.eq 会跳转。

3. cmp ：比较但不保存结果

3.1 x86-64

mov $20, %rax       # rax = 20
cmp $18, %rax       # 临时计算 rax - 18，也就是 20 - 18
jge adult           # 如果 rax >= 18，跳到 adult

注意 cmp $18, %rax 的顺序。AT&T 语法中源操作数在前、目标操作数在后，比较的是：

%rax - 18

不是：

18 - %rax

3.2 AArch64/macOS arm64

mov x0, #20         // x0 = 20
cmp x0, #18         // 临时计算 x0 - 18，也就是 20 - 18
b.ge adult          // 如果 x0 >= 18，跳到 adult

AArch64 的顺序更接近高级语言里的 x0 >= 18 ，所以初学时通常更直观。

4. 三个平台示例：if/else

目标逻辑：

age = 20;

if (age >= 18) {
    result = 1;
} else {
    result = 0;
}

return result;

因为 20 >= 18 成立，所以预期退出码是 1 。

4.1 x86-64 Linux

文件名： cond-x86-64.s

.section .text
.global _start
_start:
    # 目标：
    # if (age >= 18) result = 1; else result = 0;
    #
    # 本例中 age = 20，所以 result 应该是 1。

    mov $20, %rax                            # rax = age = 20

    # cmp $18, %rax 不保存计算结果。
    # 该指令只临时计算 %rax - 18，并据此更新 RFLAGS。
    #
    # 如果 %rax >= 18，后面的 jge 会跳到 adult。
    # jge 是 signed greater or equal，也就是“有符号大于等于”。
    cmp $18, %rax                            # 比较 age 和 18
    jge adult                                # 如果 age >= 18，跳到 adult

underage:
    # 能执行到这里，说明 jge 没有跳转。
    # 也就是 age < 18。
    mov $0, %rdi                             # rdi = 0，作为退出码
    jmp done                                 # 跳过 adult 分支，进入统一退出位置

adult:
    # 能执行到这里，说明 age >= 18。
    mov $1, %rdi                             # rdi = 1，作为退出码

done:
    # Linux x86-64 syscall 约定：
    # rax = 系统调用号，exit 是 60
    # rdi = 第 1 个参数，这里是退出码
    mov $60, %rax                            # rax = 60，Linux x86-64 exit
    syscall

编译运行：

as --64 cond-x86-64.s -o cond-x86-64.o
ld cond-x86-64.o -o cond-x86-64
./cond-x86-64
echo $?

预期输出：

1

文件名： cond-macos-arm64.s

5. 条件码对照

5.1 等于和不等于

含义x86-64AArch64/macOS arm64判断依据
等于je / jzb.eq结果为 0， ZF=1 / Z=1
不等于jne / jnzb.ne结果不为 0， ZF=0 / Z=0

je 和 jz 在 x86-64 中是同一个条件的两种名字：

cmp $10, %rax
je equal            # 如果 rax == 10，跳转

cmp $10, %rax
jz equal            # 同样表示“如果相等就跳转”

AArch64 写成：

cmp x0, #10
b.eq equal          // 如果 x0 == 10，跳转

5.2 有符号比较

有符号数会把最高位当作符号位，所以 -1 、 0 、 1 这种大小关系要用 signed 条件。

含义x86-64AArch64/macOS arm64
小于jlb.lt
小于等于jleb.le
大于jgb.gt
大于等于jgeb.ge

例子：

# x86-64：如果 rax < 0，跳到 negative
cmp $0, %rax
jl negative
// AArch64：如果 x0 < 0，跳到 negative
cmp x0, #0
b.lt negative

5.3 无符号比较

无符号数不看正负，只把所有 bit 当作非负整数。

含义x86-64AArch64/macOS arm64
低于jb / jcb.lo / b.cc
低于等于jbeb.ls
高于jab.hi
高于等于jae / jncb.hs / b.cs

AArch64 里 hs 是 higher or same， lo 是 lower。这些值是无符号比较条件。

一个容易记的规则：

signed   用 lt/le/gt/ge
unsigned 用 lo/ls/hi/hs

x86-64 也类似：

signed   用 l/le/g/ge
unsigned 用 b/be/a/ae

5.4 其他常见条件

含义x86-64AArch64/macOS arm64
负数jsb.mi
非负数jnsb.pl
溢出job.vs
未溢出jnob.vc
无条件跳转jmp labelb label

mi 是 minus， pl 是 plus。这些值看的是结果最高位对应的 N 标志。

6. test/tst ：只测试 bit，不保存结果

cmp 常用于大小比较， test/tst 常用于 bit 判断。

例如判断最低位是否为 1 ：

value & 1

结果为 0 表示偶数，结果不为 0 表示奇数。

6.1 x86-64

mov $42, %rax       # rax = 42，二进制最低位是 0

# test $1, %rax 会临时计算 rax & 1。
# 该指令不保存 AND 的结果，只更新 RFLAGS。
test $1, %rax
jz even             # 如果结果为 0，ZF=1，说明是偶数

6.2 AArch64/macOS arm64

mov x0, #42         // x0 = 42，二进制最低位是 0

// tst x0, #1 会临时计算 x0 & 1。
// 该指令不保存 AND 的结果，只更新 NZCV。
tst x0, #1
b.eq even           // 如果结果为 0，Z=1，说明是偶数

AArch64 还可以用专门的 bit 测试跳转：

tbz x0, #0, even    // test bit zero：如果 x0 的第 0 位是 0，跳到 even
tbnz x0, #0, odd    // test bit non-zero：如果 x0 的第 0 位是 1，跳到 odd

tbz/tbnz 不需要先写 tst ，适合判断某一个固定 bit。

7. 判断寄存器是否为 0

判断一个值是否为 0 很常见。

7.1 x86-64：常用 test reg, reg

test %rax, %rax     # 临时计算 rax & rax，只更新标志位
jz is_zero          # 如果 rax == 0，跳转
jnz not_zero        # 如果 rax != 0，跳转

也可以写：

cmp $0, %rax
je is_zero

但 test %rax, %rax 很常见，因为不需要编码立即数 0 ，也是典型的 “判断是否为 0” 写法。

7.2 AArch64/macOS arm64： cbz/cbnz

AArch64 有专门的 compare and branch zero 指令：

cbz x0, is_zero     // 如果 x0 == 0，跳到 is_zero
cbnz x0, not_zero   // 如果 x0 != 0，跳到 not_zero

cbz/cbnz 不更新 NZCV 。如果后续还想保留之前 cmp 的标志位，这些值会比 cmp x0, #0 更方便。

当然，也可以写成普通比较：

cmp x0, #0
b.eq is_zero

8. 有符号和无符号：同一组 bit，两种结果

这部分是条件判断最容易踩坑的地方。

假设一个 64 位寄存器里放的是：

0xffffffffffffffff

如果按有符号数理解，这是 -1 。

如果按无符号数理解，这是：

18446744073709551615

所以这个值和 1 比较时：

有符号：-1 < 1
无符号：18446744073709551615 > 1

8.1 x86-64

mov $-1, %rax       # rax = 0xffffffffffffffff

cmp $1, %rax        # 比较 rax 和 1，本质是临时计算 rax - 1
jl signed_less      # 有符号判断：-1 < 1，成立

cmp $1, %rax        # 再比较一次，重新设置标志位
jb unsigned_less    # 无符号判断：最大无符号数 < 1，不成立

同一个 cmp 产生同一组标志位，但选择 jl 还是 jb ，含义完全不同。

8.2 AArch64/macOS arm64

mov x0, #-1         // x0 = 0xffffffffffffffff

cmp x0, #1          // 比较 x0 和 1，本质是临时计算 x0 - 1
b.lt signed_less    // 有符号判断：-1 < 1，成立

cmp x0, #1          // 再比较一次，重新设置标志位
b.lo unsigned_less  // 无符号判断：最大无符号数 < 1，不成立

只要在判断 “大小”，就先确认：

这个值应该当 signed 还是 unsigned？

然后再选条件码。

9. 组合条件：&& 和 ||

高级语言里的组合条件通常靠多次比较和多次跳转实现。

9.1 && ：两个条件都要满足

目标逻辑：

if (x >= 10 && x <= 20) {
    result = 1;
} else {
    result = 0;
}

x86-64：

mov $15, %rax       # x = 15

cmp $10, %rax       # 比较 x 和 10
jl no               # 如果 x < 10，第一个条件失败

cmp $20, %rax       # 比较 x 和 20
jg no               # 如果 x > 20，第二个条件失败

yes:
    mov $1, %rdi    # 两个条件都满足
    jmp done

no:
    mov $0, %rdi    # 至少一个条件失败

AArch64/macOS arm64：

mov x0, #15         // x = 15

cmp x0, #10         // 比较 x 和 10
b.lt no             // 如果 x < 10，第一个条件失败

cmp x0, #20         // 比较 x 和 20
b.gt no             // 如果 x > 20，第二个条件失败

yes:
    mov x0, #1      // 两个条件都满足
    b done

no:
    mov x0, #0      // 至少一个条件失败

上面用的是有符号比较。如果 x 是无符号数，应该把 jl/jg 换成 jb/ja ，把 b.lt/b.gt 换成 b.lo/b.hi 。

9.2 || ：任意一个条件满足

目标逻辑：

if (x < 10 || x > 20) {
    result = 1;
} else {
    result = 0;
}

x86-64：

mov $25, %rax       # x = 25

cmp $10, %rax       # 比较 x 和 10
jl yes              # 如果 x < 10，整个 || 已经成立

cmp $20, %rax       # 比较 x 和 20
jg yes              # 如果 x > 20，整个 || 成立

no:
    mov $0, %rdi    # 两个条件都失败
    jmp done

yes:
    mov $1, %rdi    # 至少一个条件成立

AArch64/macOS arm64：

mov x0, #25         // x = 25

cmp x0, #10         // 比较 x 和 10
b.lt yes            // 如果 x < 10，整个 || 已经成立

cmp x0, #20         // 比较 x 和 20
b.gt yes            // 如果 x > 20，整个 || 成立

no:
    mov x0, #0      // 两个条件都失败
    b done

yes:
    mov x0, #1      // 至少一个条件成立

这里体现了短路求值的思想：只要已经知道最终结果，就不用继续判断剩下的条件。

10. 不跳转也能判断：条件移动和条件选择

有时只需要在两个值中选一个，不一定要写完整的 if/else 跳转结构。

目标逻辑：

a = 42;
b = 77;

if (a < b) {
    max = b;
} else {
    max = a;
}

return max;

预期结果是 77 。

10.1 x86-64： cmovcc

mov $42, %rax       # rax = a = 42，先假设最大值是 a
mov $77, %rbx       # rbx = b = 77

# cmp %rbx, %rax 临时计算 rax - rbx。
# 如果 rax < rbx，说明 a < b。
cmp %rbx, %rax

# cmovl 是 conditional move if less。
# 如果上一条 cmp 得出的有符号“小于”条件成立，就把 rbx 复制到 rax。
# 如果条件不成立，rax 保持原值。
cmovl %rbx, %rax    # if (a < b) rax = b

cmovcc 不会改变控制流，所以没有分支预测失败的成本。但这种写法也不是永远更好：如果分支非常容易预测，普通跳转也可能很快。入门阶段先理解为 “根据条件复制寄存器” 即可。

10.2 AArch64/macOS arm64： csel

mov x0, #42         // x0 = a = 42，先假设最大值是 a
mov x1, #77         // x1 = b = 77

cmp x0, x1          // 比较 a 和 b，也就是临时计算 x0 - x1

// csel x0, x1, x0, lt 的含义：
// 如果 lt 条件成立，也就是 a < b，则 x0 = x1
// 否则 x0 = x0
csel x0, x1, x0, lt // x0 = (a < b) ? b : a

csel 的格式很像三元表达式：

csel dst, true_value, false_value, condition

也就是：

dst = condition ? true_value : false_value

11. 把条件变成 0 或 1

高级语言里经常需要布尔值：

is_adult = age >= 18;

在汇编里可以把条件结果变成整数 0 或 1 。

11.1 x86-64： setcc

mov $20, %rax       # rax = age = 20
cmp $18, %rax       # 比较 age 和 18

# setge 会根据上一条 cmp 的结果设置一个 8 位目标。
# 条件成立时写入 1，不成立时写入 0。
setge %al           # al = (age >= 18) ? 1 : 0

# setcc 只写 8 位寄存器。
# 如果后面要把结果当作完整整数使用，通常要做零扩展。
movzbq %al, %rax    # rax = zero_extend(al)

如果要把结果作为 Linux 退出码：

mov %rax, %rdi      # rdi = 0 或 1
mov $60, %rax
syscall

11.2 AArch64/macOS arm64： cset

mov x0, #20         // x0 = age = 20
cmp x0, #18         // 比较 age 和 18

// cset 会根据条件生成 0 或 1。
// 条件成立时 x0 = 1，不成立时 x0 = 0。
cset x0, ge         // x0 = (age >= 18) ? 1 : 0

cset 实际上是 csinc 的别名，但初学时不需要先展开该别名。把该指令当作 “根据条件设置 0/1” 即可。

12. 三个平台示例：max (a, b)

这一节给出 cmovcc/csel 的完整可运行版本。

目标逻辑：

a = 42;
b = 77;
return max(a, b);

预期退出码是 77 。

12.1 x86-64 Linux

文件名： max-x86-64.s

.section .text
.global _start
_start:
    # 目标：计算 max(42, 77)，返回 77。
    #
    # rax 保存当前候选最大值。
    # rbx 保存另一个待比较的值。

    mov $42, %rax                            # rax = a = 42
    mov $77, %rbx                            # rbx = b = 77

    # 比较 a 和 b。
    # AT&T 语法下 cmp %rbx, %rax 表示临时计算 %rax - %rbx。
    cmp %rbx, %rax                           # 比较 rax 和 rbx

    # 如果 rax < rbx，就把 rbx 移到 rax。
    # 如果 rax >= rbx，就什么都不做，rax 仍然是 a。
    cmovl %rbx, %rax                         # rax = (rax < rbx) ? rbx : rax

    # exit(rax)
    mov %rax, %rdi                           # rdi = 77，退出码
    mov $60, %rax                            # rax = 60，Linux x86-64 exit
    syscall

编译运行：

as --64 max-x86-64.s -o max-x86-64.o
ld max-x86-64.o -o max-x86-64
./max-x86-64
echo $?

预期输出：

77

12.2 AArch64 Linux

文件名： max-aarch64.s

.section .text
.global _start
_start:
    // 目标：计算 max(42, 77)，返回 77。
    //
    // x0 保存 a，也作为最终返回值。
    // x1 保存 b。

    mov x0, #42                              // x0 = a = 42
    mov x1, #77                              // x1 = b = 77

    // 比较 a 和 b。
    // cmp x0, x1 表示临时计算 x0 - x1，并更新 NZCV。
    cmp x0, x1                               // 比较 x0 和 x1

    // 如果 lt 条件成立，也就是 x0 < x1，则 x0 = x1。
    // 否则 x0 = x0，保持原来的 a。
    csel x0, x1, x0, lt                      // x0 = (x0 < x1) ? x1 : x0

    // exit(x0)
    mov x8, #93                              // x8 = 93，Linux AArch64 exit
    svc #0

编译运行：

as max-aarch64.s -o max-aarch64.o
ld max-aarch64.o -o max-aarch64
./max-aarch64
echo $?

预期输出：

77

12.3 macOS arm64

文件名： max-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 目标：计算 max(42, 77)，main 返回 77。

    mov x0, #42                              // x0 = a = 42
    mov x1, #77                              // x1 = b = 77

    cmp x0, x1                               // 比较 a 和 b
    csel x0, x1, x0, lt                      // x0 = (a < b) ? b : a

77

13. 常见模式速查

13.1 if (x == y)

x86-64：

cmp %rbx, %rax      # 比较 x 和 y：临时计算 rax - rbx
je equal            # 如果相等，跳转

AArch64/macOS arm64：

cmp x0, x1          // 比较 x 和 y：临时计算 x0 - x1
b.eq equal          // 如果相等，跳转

13.2 if (x != 0)

x86-64：

test %rax, %rax     # 判断 rax 是否为 0
jnz not_zero        # 如果不为 0，跳转

AArch64/macOS arm64：

cbnz x0, not_zero   // 如果 x0 不为 0，跳转

13.3 if ((flags & 4) != 0)

x86-64：

test $4, %rax       # 临时计算 flags & 4
jnz has_flag        # 如果结果不为 0，说明这个 flag 存在

AArch64/macOS arm64：

tst x0, #4          // 临时计算 flags & 4
b.ne has_flag       // 如果结果不为 0，说明这个 flag 存在

如果判断的是固定某一位，AArch64 也可以写：

tbnz x0, #2, has_flag   // 第 2 位是 1 就跳转；4 == 1 << 2

13.4 if (x < y) ，有符号

x86-64：

cmp %rbx, %rax      # 临时计算 x - y
jl less             # signed x < y

AArch64/macOS arm64：

cmp x0, x1          // 临时计算 x - y
b.lt less           // signed x < y

13.5 if (x < y) ，无符号

x86-64：

cmp %rbx, %rax      # 临时计算 x - y
jb less             # unsigned x < y

AArch64/macOS arm64：

cmp x0, x1          // 临时计算 x - y
b.lo less           // unsigned x < y

14. 常见错误

14.1 把 cmp 的操作数顺序看反

x86-64 AT&T 语法：

cmp $18, %rax

意思是：

临时计算 %rax - 18

如果想判断 %rax < 18 ，可以写：

cmp $18, %rax
jl less_than_18

不要把理解成 18 - %rax 。

14.2 用错 signed/unsigned 条件码

判断有符号整数：

jl/jle/jg/jge       # x86-64
b.lt/b.le/b.gt/b.ge // AArch64

判断无符号整数：

jb/jbe/ja/jae       # x86-64
b.lo/b.ls/b.hi/b.hs // AArch64

如果值可能是负数，或者最高位可能为 1 ，这个区别非常重要。

14.3 比较之后又改了标志位

x86-64 很多算术和逻辑指令会更新 RFLAGS ：

cmp $18, %rax
add $1, %rbx        # add 会更新 RFLAGS
jge adult           # 这里看的已经不是 cmp 的结果

更稳妥的写法是让比较和条件跳转靠近：

add $1, %rbx
cmp $18, %rax
jge adult

AArch64 普通 add/sub 不更新 NZCV ，但 adds/subs/tst/cmp 会更新。为了减少误读，也建议把 cmp 和 b.cond 放近一点。

14.4 以为 test/tst 会保存 AND 结果

test $1, %rax       # x86-64：不保存 rax & 1
tst x0, #1          // AArch64：不保存 x0 & 1

这些值只更新条件标志。如果如果需要保存 AND 结果，要用：

and $1, %rax        # x86-64
and x0, x0, #1      // AArch64

14.5 忘记 setcc 只写 8 位

x86-64 的 setcc 写的是 8 位目标：

setge %al

如果后面要把结果当作完整 64 位整数，通常要零扩展：

movzbq %al, %rax

AArch64 的 cset x0, ge 会直接把 x0 设置成 0 或 1 ，不需要额外零扩展。

14.6 在 macOS arm64 入门示例里照搬 Linux syscall

Linux AArch64 裸程序常写：

mov x8, #93
svc #0

macOS arm64 入门示例更推荐从 _main 开始，用 clang 链接，让 C 运行时接管启动和退出：

.globl _main
_main:
    mov x0, #1
    ret

这样最容易运行，也和前面章节的 macOS 示例保持一致。

  1. 把 cond-* 示例里的 age 从 20 改成 17 ，确认退出码从 1 变成 0 。
  2. 写一个程序判断 x 是否为偶数。 x = 42 时返回 1 ， x = 43 时返回 0 。
  3. 把 max-* 示例改成 min(42, 77) ，让退出码变成 42 。
  4. 用有符号比较判断 -1 < 1 ，返回 1 ；再改成无符号比较，观察结果变化。
