宏

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的汇编宏。

宏是汇编期的文本 / 指令模板。该指令不是运行时函数调用，而是在汇编时展开成真实指令。

例如写：

EXIT 0

汇编器可能把宏展开成：

mov $60, %rax
mov $0, %rdi
syscall

宏适合减少重复样板代码，但也容易隐藏细节。入门阶段要同时理解 “宏调用” 和 “宏展开后实际执行的指令”。

说明：以下主要使用 GNU as / Apple Clang 汇编器都支持的 .macro 风格。不同汇编器的宏语法可能不同，NASM、MASM、LLVM integrated assembler、GNU as 的细节并不完全一致。

一个简单宏：

.macro LOAD_IMM reg, value
    mov \value, \reg
.endm

调用：

LOAD_IMM %rax, $42

展开后类似：

mov $42, %rax

2. 宏和函数的区别

函数调用：

call add3        # x86-64
bl add3          // AArch64

会在运行时跳转，保存返回地址，执行函数，再返回。

宏调用：

EXIT 0

会在汇编时展开，最终机器码里没有 “调用宏” 这个动作。

对比：

维度宏函数
展开 / 执行时间汇编期展开运行时执行
是否有调用开销没有 call/ret有 call/ret 或 bl/ret
代码大小每次展开都复制一份函数体通常只有一份
是否有独立作用域弱，容易名字冲突有独立调用栈和 ABI
适合场景短小样板代码可复用逻辑、复杂代码

3. 三个平台示例：用宏封装退出

目标逻辑：

return 42;

预期退出码是 42 。

3.1 x86-64 Linux

文件名： macro-x86-64.s

.macro EXIT code
    # Linux x86-64 exit(code)
    mov $60, %rax                            # rax = exit 系统调用号
    mov \code, %rdi                          # rdi = 退出码
    syscall
.endm

.section .text
.global _start
_start:
    EXIT $42                                 # 展开成 mov/mov/syscall

编译运行：

as --64 macro-x86-64.s -o macro-x86-64.o
ld macro-x86-64.o -o macro-x86-64
./macro-x86-64
echo $?

预期输出：

42

3.2 AArch64 Linux

文件名： macro-aarch64.s

.macro EXIT code
    // Linux AArch64 exit(code)
    mov x0, #\code                           // x0 = 退出码
    mov x8, #93                              // x8 = exit 系统调用号
    svc #0
.endm

.section .text
.global _start
_start:
    EXIT 42                                  // 展开成 mov/mov/svc

编译运行：

as macro-aarch64.s -o macro-aarch64.o
ld macro-aarch64.o -o macro-aarch64
./macro-aarch64
echo $?

预期输出：

42

3.3 macOS arm64

macOS arm64 的入门示例通常从 _main 返回，所以宏可以封装函数序言和尾声。

文件名： macro-macos-arm64.s

.macro PROLOGUE
    stp x29, x30, [sp, #-16]!
    mov x29, sp
.endm

.macro EPILOGUE
    ldp x29, x30, [sp], #16
    ret
.endm

.text
.globl _main
.p2align 2
_main:
    PROLOGUE

    // 这里没有调用其他函数，严格说不需要栈帧。
    // 本例只是演示宏展开。
    mov x0, #42                              // main 返回 42

    EPILOGUE

编译运行：

clang macro-macos-arm64.s -o macro-macos-arm64
./macro-macos-arm64
echo $?

预期输出：

42

4. 带参数的宏

宏参数用反斜杠引用：

.macro ADD3 dst, a, b, c
    mov \a, \dst
    add \b, \dst
    add \c, \dst
.endm

x86-64 调用：

ADD3 %rax, %rdi, %rsi, %rdx

展开后类似：

mov %rdi, %rax
add %rsi, %rax
add %rdx, %rax

AArch64 更适合写成：

.macro ADD3 dst, a, b, c
    add \dst, \a, \b
    add \dst, \dst, \c
.endm

ADD3 x0, x0, x1, x2

宏参数只是文本替换的一部分。传参时要符合目标架构的操作数语法。

5. 默认参数

GNU as 支持宏参数默认值：

.macro FILL_ZERO reg=x0
    mov \reg, #0
.endm

调用：

FILL_ZERO          // 使用默认 x0
FILL_ZERO x1       // 使用 x1

x86-64 也可以：

.macro ZERO reg=%rax
    xor \reg, \reg
.endm

注意：不同汇编器对默认参数、关键字参数的支持细节可能不同。跨平台文章里，尽量保持宏简单。

6. 宏里的标签和局部标签

宏每展开一次，里面的普通标签也会出现一次。如果标签名重复，汇编器会报错。

错误示例：

.macro COUNTDOWN reg
loop:
    sub $1, \reg
    jnz loop
.endm

COUNTDOWN %rax
COUNTDOWN %rbx     # 第二次展开又定义 loop，冲突

GNU as 可以用 \@ 生成每次展开唯一的编号：

.macro COUNTDOWN reg
loop_\@:
    sub $1, \reg
    jnz loop_\@
.endm

每次展开时， \@ 会变成不同数字，从而避免标签冲突。

7. 用宏封装 write

x86-64 Linux：

.macro WRITE fd, buf, len
    mov $1, %rax
    mov \fd, %rdi
    lea \buf(%rip), %rsi
    mov \len, %rdx
    syscall
.endm

调用：

WRITE $1, msg, $msg_len

AArch64 Linux：

.macro WRITE buf, len
    mov x0, #1
    adrp x1, \buf
    add x1, x1, :lo12:\buf
    mov x2, #\len
    mov x8, #64
    svc #0
.endm

macOS arm64：

.macro WRITE buf, len
    mov x0, #1
    adrp x1, \buf@PAGE
    add x1, x1, \buf@PAGEOFF
    mov x2, #\len
    bl _write
.endm

macOS 这个宏内部有 bl _write ，调用包含该宏的函数必须保存 x30 。

8. 宏的优点和代价

优点：

  • 减少重复样板代码。
  • 让 syscall、函数序言、寄存器保存更统一。
  • 对短小代码没有函数调用开销。

代价：

  • 每次展开都会复制代码，可能增大文件。
  • 调试时看到的是展开后的指令，不是宏调用本身。
  • 宏没有真正的类型检查。
  • 宏里使用寄存器可能偷偷破坏调用者状态。

经验规则：

短小、固定、重复的样板代码适合宏。
复杂逻辑、需要调试、需要控制 ABI 的代码更适合函数。

9. 查看宏展开

GNU as 可以通过预处理 / 列表文件观察展开结果，实际命令因工具链不同而不同。

常用思路：

as --64 -alh macro-x86-64.s > macro-x86-64.lst

或者汇编后反汇编：

objdump -d macro-x86-64

macOS 上可以用：

llvm-objdump -d macro-macos-arm64

观察时重点看：宏调用最终变成了哪些真实指令。

10. 常见错误

10.1 忘记参数前的反斜杠

mov code, %rdi      # 错误：code 会被当成符号名
mov \code, %rdi     # 正确：使用宏参数

10.2 宏里标签重复

宏会展开多次，普通标签会冲突。需要唯一标签时用 \@ 。

10.3 宏偷偷改了寄存器

如果宏内部使用 %rax 、 x0 这类寄存器，要在注释里说明。调用者不能假设宏不破坏寄存器。

10.4 把宏当函数

宏没有运行时调用栈，也没有自动返回。只是展开成一段指令。

10.5 在 macOS 宏里调用 _write 却不保存 x30

如果宏内部有：

bl _write

外层 _main 或函数必须保存返回地址，否则 ret 可能回不去。

11. 小练习

  1. 写一个 x86-64 Linux 的 EXIT code 宏，并用该宏返回 7 。
  2. 写一个 AArch64 Linux 的 WRITE msg, len 宏，输出一行文本。
  3. 写一个 ZERO reg 宏，分别清零两个寄存器。
  4. 写一个带局部标签的倒计数宏，并调用两次，确认不会标签冲突。
  5. 把第 15 章 macOS 示例的函数序言和尾声改成宏。
