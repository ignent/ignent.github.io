常量

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的常量写法。

在汇编里，“常量” 这个词容易混淆。至少有两类完全不同的东西：

汇编期常量：名字代表一个数值，不分配内存，例如 .equ EXIT, 60
只读数据：真的放在内存里的字节，只是运行时不应该修改，例如 .ascii "hello\n"

如果写：

.equ ANSWER, 42

ANSWER 只是汇编器记录的数字 42 ，不占 .data ，也没有地址。

如果写：

answer:
    .quad 42

answer 是一个地址，从这个地址开始真的有 8 个字节。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的常量表达式很像，但全局符号重定位、入口符号和链接方式不同。

初学阶段先记住：

  • .equ 定义的是数字别名，不是变量。
  • .rodata / __TEXT,__const 是只读数据，真实占内存。
  • msg_len = . - msg 是汇编期计算，常用来得到字符串长度。
  • 立即数能不能直接编码进指令，取决于指令集规则；不是所有 64 位数字都能一条 mov 搞定。

2. .equ 、 .set 、 .equiv

常见写法：

.equ NAME, value
.set NAME, value
.equiv NAME, value

这些值都能给表达式起名字，但语义有区别：

写法含义适合场景
.equ NAME, value定义一个符号常量最常见，系统调用号、缓冲区大小
.set NAME, value设置符号值，后续可以重新设置少量需要重设的汇编技巧
.equiv NAME, value定义一次；如果已定义过会报错防止重复定义，适合重要常量

入门建议：

  • 默认用 .equ 。
  • 想避免重复定义时用 .equiv 。
  • 没有明确需要重设时少用 .set 。

示例：

.equ STDOUT, 1
.equ SYS_write, 1
.equ SYS_exit, 60
.equ EXIT_SUCCESS, 0

之后代码里就可以写：

mov $SYS_write, %rax
mov $STDOUT, %rdi
mov $SYS_exit, %rax

读起来比裸数字舒服很多。

3. 表达式常量

常量可以来自表达式：

.equ BUFFER_SIZE, 64
.equ DOUBLE_SIZE, BUFFER_SIZE * 2
.equ FLAG_READ,  1 << 0
.equ FLAG_WRITE, 1 << 1
.equ FLAG_EXEC,  1 << 2
.equ DEFAULT_FLAGS, FLAG_READ | FLAG_EXEC

常用运算：

运算示例含义
+BASE + 8加法
-. - msg减法，常用于长度
*COUNT * 8乘法
/SIZE / 2除法
<<1 << 3左移，常用于位掩码
|A | B按位或，组合 flag
&MASK & VALUE按位与

表达式通常在汇编期计算。也就是说，最终机器码里不会保留 “ BUFFER_SIZE * 2 ” 这个算式，只会出现计算后的数字。

4. 当前地址 . 和字符串长度

. 表示汇编器当前位置。最常见用法是计算字符串长度：

msg:
    .ascii "hello\n"
msg_len = . - msg

解释：

  • 汇编到 msg: 时， msg 记录当前地址。
  • .ascii "hello\n" 写入 6 个字节。
  • 写完后， . 变成字符串末尾后面的地址。
  • . - msg 就是字符串长度。

这比手写 6 更安全。以后把字符串改成更长或更短， msg_len 会自动跟着变。

注意 .ascii 和 .asciz ：

msg1:
    .ascii "hi"
msg1_len = . - msg1      # 长度是 2

msg2:
    .asciz "hi"
msg2_len = . - msg2      # 长度是 3，包括结尾的 \0

write 只需要字节数，不需要 \0 。C 字符串函数通常需要 \0 。

5. x86-64 Linux：用常量写 hello

文件名： const-x86-64.s

.equ SYS_write, 1
.equ SYS_exit, 60
.equ STDOUT, 1
.equ EXIT_SUCCESS, 0

.section .rodata
msg:
    .ascii "x86-64 constants\n"
msg_len = . - msg                         # 汇编期常量，不分配内存

.section .text
.global _start
_start:
    # write(STDOUT, msg, msg_len)
    mov $SYS_write, %rax                   # rax = 1，write 系统调用号
    mov $STDOUT, %rdi                      # rdi = 1，标准输出
    lea msg(%rip), %rsi                    # rsi = msg 的地址
    mov $msg_len, %rdx                     # rdx = 字符串长度
    syscall

    # exit(EXIT_SUCCESS)
    mov $SYS_exit, %rax                    # rax = 60，exit 系统调用号
    mov $EXIT_SUCCESS, %rdi                # rdi = 0，退出码
    syscall

编译运行：

as --64 const-x86-64.s -o const-x86-64.o
ld const-x86-64.o -o const-x86-64
./const-x86-64
echo $?

预期输出：

x86-64 constants
0

这里 SYS_write 、 STDOUT 、 msg_len 都是汇编期常量。这些值让代码更可读，但不会像变量那样生成可修改的存储空间。

6. AArch64 Linux：用常量写 hello

文件名： const-aarch64.s

.equ SYS_write, 64
.equ SYS_exit, 93
.equ STDOUT, 1
.equ EXIT_SUCCESS, 0

.section .rodata
msg:
    .ascii "AArch64 constants\n"
msg_len = . - msg                         // 汇编期常量，不分配内存

.section .text
.global _start
_start:
    // write(STDOUT, msg, msg_len)
    mov x8, #SYS_write                     // x8 = 64，write 系统调用号
    mov x0, #STDOUT                        // x0 = 1，标准输出
    adrp x1, msg                           // x1 = msg 所在页地址
    add x1, x1, :lo12:msg                  // x1 = msg 完整地址
    mov x2, #msg_len                       // x2 = 字符串长度
    svc #0

    // exit(EXIT_SUCCESS)
    mov x8, #SYS_exit                      // x8 = 93，exit 系统调用号
    mov x0, #EXIT_SUCCESS                  // x0 = 0，退出码
    svc #0

编译运行：

as const-aarch64.s -o const-aarch64.o
ld const-aarch64.o -o const-aarch64
./const-aarch64
echo $?

预期输出：

AArch64 constants
0

AArch64 立即数前面用 # ，所以是 mov x8, #SYS_write ，不是 x86-64 的 $SYS_write 。

7. macOS arm64：常量配合 libSystem

文件名： const-macos-arm64.s

.equ STDOUT, 1
.equ EXIT_SUCCESS, 0

.section __TEXT,__const
msg:
    .ascii "macOS arm64 constants\n"
msg_len = . - msg                         // 汇编期常量，不分配内存

.text
.globl _main
.p2align 2
_main:
    // _main 要调用 _write，所以先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    // write(STDOUT, msg, msg_len)
    mov x0, #STDOUT                        // x0 = 1，标准输出
    adrp x1, msg@PAGE                      // x1 = msg 所在页地址
    add x1, x1, msg@PAGEOFF                // x1 = msg 完整地址
    mov x2, #msg_len                       // x2 = 字符串长度
    bl _write                              // 调用 libSystem 的 write()

    mov w0, #EXIT_SUCCESS                  // main 返回 0
    ldp x29, x30, [sp], #16
    ret

编译运行：

clang const-macos-arm64.s -o const-macos-arm64
./const-macos-arm64
echo $?

预期输出：

macOS arm64 constants
0

macOS arm64 这里没有定义 SYS_write ，因为入门阶段推荐调用 libSystem 的 _write ，不是裸 svc #0x80 。如果写裸 syscall，Darwin 的 SYS_write 是 4 ，调用号寄存器是 x16 ，不要照搬 Linux AArch64 的 x8 = 64 。

8. 常量不占内存，只读数据占内存

下面这段：

.equ ANSWER, 42

不会生成一个叫 ANSWER 的内存单元。只是告诉汇编器：以后看到 ANSWER 就当成 42 。

下面这段：

.section .rodata
answer_value:
    .quad 42

会在只读数据段里放 8 个字节。 answer_value 有地址，可以被 lea 、 adrp 、 ldr 访问。

对比：

mov $ANSWER, %rax                 # x86-64：rax = 42
lea answer_value(%rip), %rax      # x86-64：rax = answer_value 的地址
mov answer_value(%rip), %rax      # x86-64：rax = answer_value 地址里的 8 字节值

AArch64/macOS arm64 同理：

mov x0, #42                       // x0 = 42
ldr x0, [x9]                      // x0 = x9 指向的内存里的值

是否占内存，关键看是否用 .byte/.long/.quad/.ascii 这类数据定义伪指令真正写入字节。

9. 常量用于缓冲区大小

汇编期常量很适合统一管理缓冲区大小：

Linux ELF：

.equ BUFFER_SIZE, 128

.section .bss
.balign 16
buffer:
    .space BUFFER_SIZE

macOS Mach-O：

.equ BUFFER_SIZE, 128
.zerofill __DATA,__bss,buffer,BUFFER_SIZE,4

这样以后想把缓冲区从 128 字节改成 256 字节，只需要改一处。

也可以配合数组：

.equ ITEM_SIZE, 8
.equ ITEM_COUNT, 4
.equ ARRAY_SIZE, ITEM_SIZE * ITEM_COUNT

array:
    .space ARRAY_SIZE

这里 ARRAY_SIZE 在汇编期会被算成 32 。

10. 位掩码常量

很多系统接口和底层代码喜欢用 bit flag：

.equ FLAG_READ,  1 << 0      # 0b001
.equ FLAG_WRITE, 1 << 1      # 0b010
.equ FLAG_EXEC,  1 << 2      # 0b100
.equ FLAG_RW, FLAG_READ | FLAG_WRITE

这样比直接写 3 可读很多：

mov $FLAG_RW, %rax           # x86-64，rax = 3
mov x0, #FLAG_RW             // AArch64，x0 = 3

文件权限、页权限、状态位、CPU 标志相关代码里经常会看到这种写法。

11. 立即数限制：不是所有常量都能直接塞进一条指令

常量可以很大，但指令编码空间有限。很多指令只能放下某些形状的立即数。

11.1 x86-64

小整数通常很自然：

mov $42, %rax
add $8, %rax

64 位大常量常见写法：

movabs $0x1122334455667788, %rax

movabs 是 GNU 汇编器在 x86-64 上常见的写法，用于明确装入 64 位立即数。

11.2 AArch64/macOS arm64

AArch64 的 mov 是伪指令。汇编器会尝试把翻译成合适的机器指令。小数值通常没问题：

mov x0, #42

大常量常用 movz + movk 分段拼起来：

movz x0, #0x7788
movk x0, #0x5566, lsl #16
movk x0, #0x3344, lsl #32
movk x0, #0x1122, lsl #48

执行后：

x0 = 0x1122334455667788

解释：

  • movz 把一个 16 位片段放进寄存器，并把其他位清零。
  • movk 保留其他位，只替换指定的 16 位片段。
  • lsl #16/#32/#48 表示这个 16 位片段放到哪一段。

有时也可以把大常量放进只读数据段，再从内存 ldr 读出来。哪种更好取决于上下文，入门阶段先认识两种方式即可。

12. 字符常量和转义字符

字符最终也是数字。常见 ASCII：

字符十进制十六进制
'A'650x41
'H'720x48
'a'970x61
'\n'100x0a
'\0'00x00

很多汇编器允许字符常量：

movb $'A', msg(%rip)      # x86-64：写入 ASCII A
mov w0, #'A'              // AArch64：w0 = 65

如果遇到汇编器不接受某种字符写法，直接写数字最稳：

movb $65, msg(%rip)
mov w0, #65

字符串里的转义字符也会变成字节：

.ascii "A\n"              # 两个字节：0x41 0x0a
.asciz "A"                # 两个字节：0x41 0x00

13. 用工具观察常量

汇编期常量不一定会出现在最终符号表里；只读数据会出现在文件内容里。

Linux x86-64：

readelf -S const-x86-64 | egrep 'Name|\\.text|\\.rodata'
objdump -s -j .rodata const-x86-64
nm const-x86-64 | grep 'SYS_write\\|msg_len\\|msg'

AArch64 Linux：

aarch64-linux-gnu-readelf -S const-aarch64 | egrep 'Name|\\.text|\\.rodata'
aarch64-linux-gnu-objdump -s -j .rodata const-aarch64

macOS arm64：

size -m const-macos-arm64
otool -s __TEXT __const const-macos-arm64
nm const-macos-arm64 | grep 'msg\\|msg_len'

可能会看到 msg 这样的标签，但不一定看到 .equ SYS_write 。因为 .equ 更像汇编期替换，不一定需要作为运行时符号保留下来。

14. 常见坑

14.1 把 .equ 当变量

.equ COUNT, 4

COUNT 没有地址，不能当成内存变量写：

mov %rax, COUNT(%rip)     # 错误思路：COUNT 不是变量地址

想要可写变量，要放数据：

.section .data
count:
    .quad 4

14.2 把只读数据当 “纯常量”

.section .rodata
value:
    .quad 42

value 是只读数据，有地址，占文件空间和运行时映射。该指令不是 .equ 那种纯数字别名。

14.3 硬编码魔法数字

下面能跑，但不好读：

mov $1, %rax
mov $1, %rdi
mov $60, %rax

加上常量名更清楚：

.equ SYS_write, 1
.equ STDOUT, 1
.equ SYS_exit, 60

读代码的人不用一直回忆 60 是不是 exit 。

14.4 AArch64 大常量一条 mov 不一定行

小常量：

mov x0, #42

大常量可能需要：

movz x0, #0x7788
movk x0, #0x5566, lsl #16
movk x0, #0x3344, lsl #32
movk x0, #0x1122, lsl #48

如果汇编器报 immediate cannot be moved by a single instruction 之类错误，就要换成 movz/movk 或从内存加载。

14.5 .asciz 长度包含 \0

msg:
    .asciz "hi"
msg_len = . - msg       # 3，不是 2

如果把 msg_len 传给 write ，会多写一个 NUL 字节。通常不可见，但确实被写出去了。

15. 小练习

  1. 把 STDOUT 改成 2 ，观察输出走 stderr。
  2. 把 msg 改长，不手动改长度，确认 msg_len 自动正确。
  3. 给 x86-64 示例加 .equ EXIT_STATUS, 7 ，让程序打印后退出码变成 7 。
  4. 定义 FLAG_READ 、 FLAG_WRITE 、 FLAG_EXEC ，让程序退出码返回 FLAG_READ | FLAG_EXEC ，应该看到 5 。
  5. 在 AArch64/macOS arm64 中用 movz/movk 拼出 0x1122334455667788 ，再尝试把最低 8 位作为退出码。
