文件管理

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的文件管理。

文件操作的核心流程通常是：

open  打开文件，得到文件描述符 fd
read  从 fd 读取数据
write 向 fd 写入数据
close 关闭 fd

文件描述符是一个小整数：

fd含义
0stdin
1stdout
2stderr
>= 3程序打开的文件

说明：Linux 示例使用裸系统调用，便于理解内核接口。macOS arm64 入门示例使用 libSystem 的 _creat 、 _write 、 _close ，避免直接依赖 Darwin 裸 syscall 细节。

1. 一张表先建立全局印象

操作x86-64 LinuxAArch64 LinuxmacOS arm64
打开 / 创建文件open syscall 号 2常用 openat syscall 号 56入门示例调用 _creat
写文件write syscall 号 1write syscall 号 64调用 _write
读文件read syscall 号 0read syscall 号 63调用 _read
关闭文件close syscall 号 3close syscall 号 57调用 _close
返回值非负表示成功，负数表示错误非负表示成功，负数表示错误C 函数返回 -1 表示错误
路径字符串以 \0 结尾以 \0 结尾以 \0 结尾

Linux AArch64 上常用 openat ，因为现代 Linux 更推荐 openat ：

openat(AT_FDCWD, path, flags, mode)

AT_FDCWD = -100 ，表示路径相对于当前工作目录解释。

2. flags 和 mode

打开文件时常见参数：

open(path, flags, mode)

常用 flags：

常量常见值含义
O_WRONLY1只写
O_CREATLinux/macOS 常见 0x40 / 0x200不存在就创建
O_TRUNCLinux/macOS 常见 0x200 / 0x400已存在就清空

mode 是新建文件的权限，例如：

0644 = 所有者可读写，组和其他用户可读

注意： O_CREAT 、 O_TRUNC 的具体数值是操作系统 ABI 的一部分，Linux 和 macOS 不完全一样。示例分别写各自平台的常量。

3. 三个平台示例：创建文件并写入一行文本

目标逻辑：

fd = open("asm-output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
write(fd, "hello from asm\n", 15);
close(fd);
return 0;

运行后会在当前目录生成或覆盖 asm-output.txt 。

macOS arm64 示例用 _creat(path, 0644) 表达同一件事。 creat(path, mode) 可以理解成：

open(path, O_WRONLY | O_CREAT | O_TRUNC, mode)

3.1 x86-64 Linux

文件名： file-x86-64.s

.equ SYS_read,   0
.equ SYS_write,  1
.equ SYS_open,   2
.equ SYS_close,  3
.equ SYS_exit,   60

.equ O_WRONLY,   1
.equ O_CREAT,    64
.equ O_TRUNC,    512
.equ FLAGS,      O_WRONLY | O_CREAT | O_TRUNC
.equ MODE_0644,  0644

.section .rodata
path:
    .asciz "asm-output.txt"                  # open 需要 C 字符串路径
msg:
    .ascii "hello from asm\n"
msg_len = . - msg

.section .text
.global _start
_start:
    # fd = open(path, FLAGS, 0644)
    mov $SYS_open, %rax                      # rax = open
    lea path(%rip), %rdi                     # rdi = path
    mov $FLAGS, %rsi                         # rsi = flags
    mov $MODE_0644, %rdx                     # rdx = mode
    syscall

    # 简化处理：如果 open 失败，直接 exit(1)。
    test %rax, %rax
    js open_failed

    mov %rax, %r12                           # r12 = fd，保存文件描述符

    # write(fd, msg, msg_len)
    mov $SYS_write, %rax
    mov %r12, %rdi                           # rdi = fd
    lea msg(%rip), %rsi                      # rsi = msg
    mov $msg_len, %rdx                       # rdx = len
    syscall

    # close(fd)
    mov $SYS_close, %rax
    mov %r12, %rdi
    syscall

    # exit(0)
    mov $SYS_exit, %rax
    xor %rdi, %rdi
    syscall

open_failed:
    mov $SYS_exit, %rax
    mov $1, %rdi
    syscall

编译运行：

as --64 file-x86-64.s -o file-x86-64.o
ld file-x86-64.o -o file-x86-64
./file-x86-64
cat asm-output.txt
echo $?

预期文件内容：

hello from asm

3.2 AArch64 Linux

文件名： file-aarch64.s

.equ SYS_write,  64
.equ SYS_openat, 56
.equ SYS_close,  57
.equ SYS_exit,   93

.equ AT_FDCWD,   -100
.equ O_WRONLY,   1
.equ O_CREAT,    64
.equ O_TRUNC,    512
.equ FLAGS,      O_WRONLY | O_CREAT | O_TRUNC
.equ MODE_0644,  0644

.section .rodata
path:
    .asciz "asm-output.txt"
msg:
    .ascii "hello from asm\n"
msg_len = . - msg

.section .text
.global _start
_start:
    // fd = openat(AT_FDCWD, path, FLAGS, 0644)
    mov x0, #AT_FDCWD                        // x0 = dirfd
    adrp x1, path
    add x1, x1, :lo12:path                   // x1 = path
    mov x2, #FLAGS                           // x2 = flags
    mov x3, #MODE_0644                       // x3 = mode
    mov x8, #SYS_openat                      // x8 = openat
    svc #0

    // 如果返回值是负数，说明失败。
    cmp x0, #0
    b.lt open_failed

    mov x19, x0                              // x19 = fd

    // write(fd, msg, msg_len)
    mov x0, x19                              // x0 = fd
    adrp x1, msg
    add x1, x1, :lo12:msg                    // x1 = msg
    mov x2, #msg_len                         // x2 = len
    mov x8, #SYS_write
    svc #0

    // close(fd)
    mov x0, x19
    mov x8, #SYS_close
    svc #0

    // exit(0)
    mov x0, #0
    mov x8, #SYS_exit
    svc #0

open_failed:
    mov x0, #1
    mov x8, #SYS_exit
    svc #0

编译运行：

as file-aarch64.s -o file-aarch64.o
ld file-aarch64.o -o file-aarch64
./file-aarch64
cat asm-output.txt
echo $?

预期文件内容：

hello from asm

3.3 macOS arm64

文件名： file-macos-arm64.s

.equ MODE_0644,  0644

.section __TEXT,__cstring
path:
    .asciz "asm-output.txt"
msg:
    .ascii "hello from asm\n"
msg_len = . - msg

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _creat/_write/_close，所以保存 x29/x30。
    stp x29, x30, [sp, #-32]!
    mov x29, sp

    // fd = creat(path, 0644)
    // creat 等价于 open(path, O_WRONLY | O_CREAT | O_TRUNC, mode)。
    // 这里不用 _open，是为了避开 Apple arm64 下 C 可变参数函数的入门噪音。
    adrp x0, path@PAGE
    add x0, x0, path@PAGEOFF                 // x0 = path
    mov x1, #MODE_0644                       // x1 = mode
    bl _creat

    cmp x0, #0
    b.lt open_failed

    str x0, [sp, #16]                        // 保存 fd

    // write(fd, msg, msg_len)
    ldr x0, [sp, #16]                        // x0 = fd
    adrp x1, msg@PAGE
    add x1, x1, msg@PAGEOFF                  // x1 = msg
    mov x2, #msg_len                         // x2 = len
    bl _write

    // close(fd)
    ldr x0, [sp, #16]
    bl _close

    mov x0, #0                               // main 返回 0
    ldp x29, x30, [sp], #32
    ret

open_failed:
    mov x0, #1
    ldp x29, x30, [sp], #32
    ret

编译运行：

clang file-macos-arm64.s -o file-macos-arm64
./file-macos-arm64
cat asm-output.txt
echo $?

预期文件内容：

hello from asm

4. 读取文件

读取流程：

open(path, O_RDONLY)
read(fd, buf, buf_size)
write(1, buf, bytes_read)
close(fd)

关键点： read 的返回值是实际读到的字节数，可能小于缓冲区大小，也可能是 0 表示文件结束。

x86-64 Linux 的参数：

read(fd, buf, count)
rax = 0
rdi = fd
rsi = buf
rdx = count

AArch64 Linux：

x8 = 63
x0 = fd
x1 = buf
x2 = count

macOS arm64 调用 _read(fd, buf, count) ，参数仍然放在 x0 、 x1 、 x2 。

5. 错误处理

Linux 裸 syscall 返回负数表示错误，通常是 -errno ：

test %rax, %rax
js failed
cmp x0, #0
b.lt failed

C 库函数通常返回 -1 ，并设置 errno 。macOS 示例只检查返回值是否小于 0，不展开 errno 。

真实程序应该检查每一步：

  • open / creat 是否成功。
  • write 写入的字节数是否等于期望长度。
  • read 是否返回错误。
  • close 是否成功。

6. 文件偏移和追加

每个打开的文件描述符都有一个文件偏移。写入后偏移会前进。

如果使用 O_TRUNC ，打开时清空文件：

旧内容被截断为 0 字节

如果想追加到文件末尾，通常用 O_APPEND ：

open(path, O_WRONLY | O_CREAT | O_APPEND, 0644)

不同操作系统上 O_APPEND 的数值也可能不同，写汇编时要用对应平台的常量。

7. 路径字符串必须以 0 结尾

系统调用和 C 库 open 都需要 C 字符串路径：

path:
    .asciz "asm-output.txt"

不要写成：

path:
    .ascii "asm-output.txt"

否则内核 / 库函数会继续读后面的内存，直到碰到某个 0 字节。

8. 权限和 umask

示例里传了 0644 ，但最终文件权限还会受到 shell 进程的 umask 影响。

例如 umask 是 022 时：

0644 & ~0022 = 0644

如果传 0666 ，最终常见会变成 0644 。

学习阶段只需要知道： mode 是 “希望创建的权限”，最终结果可能被 umask 收窄。

9. 常见错误

9.1 路径没有 \0

文件路径必须是 C 字符串：

.asciz "file.txt"

不是普通固定长度字节串。

9.2 Linux AArch64 用了 x86-64 的 syscall 号

x86-64 Linux write = 1 ，AArch64 Linux write = 64 。不要混用。

9.3 Linux AArch64 忘记 openat 的第一个参数

openat 参数是：

dirfd, path, flags, mode

不是从 path 开始。当前目录常用 AT_FDCWD = -100 。

9.4 macOS 照搬 Linux 裸 syscall

入门阶段 macOS arm64 推荐调用 libSystem：

bl _creat
bl _write
bl _close

这样更贴近日常 Mach-O 程序。

如果直接调用带 O_CREAT 的 _open ，要注意 _open 是 C 可变参数函数；Apple arm64 对可变参数有额外 ABI 规则。入门阶段用 _creat 创建 / 截断文件更容易验证。

9.5 忘记保存 fd

write 、 close 都需要 fd。 open / openat / creat 返回后，如果马上复用返回值寄存器，就会丢掉 fd。

保存到寄存器或栈：

mov %rax, %r12      # x86-64
mov x19, x0         // AArch64
str x0, [sp, #16]   // macOS 示例

10. 小练习

  1. 把输出文件名改成 hello.txt 。
  2. 把写入内容改成两行文本。
  3. 写一个读取示例：读取 asm-output.txt 并输出到 stdout。
  4. 故意去掉 O_TRUNC ，观察旧内容是否残留。
  5. 在 Linux 示例里检查 write 返回值，如果小于 msg_len 就返回 2 。
