递归

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的递归。

递归就是函数自调用：

long fact(long n) {
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}

汇编写递归时，重点不是 “语法”，而是保存状态：

每一层调用都有独立的 n
每一层调用都有独立的返回地址
每一层调用结束后要回到上一层

这些信息通常放在栈上。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的递归写法非常相似；差异主要在入口、符号命名和退出方式。

递归函数必须有：

  • 基准条件：什么时候不再自调用。
  • 递归步骤：把问题变小。
  • 状态保存：递归调用回来后，还能继续用当前层的数据。

2. 阶乘递归的执行过程

计算 5! ：

fact(5)
  5 * fact(4)
      4 * fact(3)
          3 * fact(2)
              2 * fact(1)
                  1

返回时再一层层乘回来：

fact(1) = 1
fact(2) = 2 * 1 = 2
fact(3) = 3 * 2 = 6
fact(4) = 4 * 6 = 24
fact(5) = 5 * 24 = 120

关键是：调用 fact(n - 1) 之前，要保存当前层的 n ，否则递归回来后就不知道要乘多少。

3. 三个平台示例：递归计算 5!

目标逻辑：

return fact(5);

预期退出码：

120

3.1 x86-64 Linux

文件名： recursion-x86-64.s

.section .text
.global _start
_start:
    mov $5, %rdi                             # 第 1 个参数 n = 5
    call fact                                # rax = fact(5)

    # exit(rax)
    mov %rax, %rdi                           # rdi = 120
    mov $60, %rax                            # Linux x86-64 exit
    syscall

fact:
    # long fact(long n)
    #
    # 参数：
    # rdi = n
    #
    # 返回：
    # rax = fact(n)

    cmp $1, %rdi
    jg recursive_case                        # 如果 n > 1，进入递归分支

base_case:
    mov $1, %rax                             # fact(0) 和 fact(1) 都返回 1
    ret

recursive_case:
    # 递归调用会复用 rdi，所以先保存当前 n。
    # push 会把栈向下移动 8 字节，并保存 rdi。
    push %rdi                                # 保存当前层 n

    sub $1, %rdi                             # 参数变成 n - 1
    call fact                                # rax = fact(n - 1)

    # 递归回来后，恢复当前层 n。
    pop %rcx                                 # rcx = 当前层 n

    imul %rcx, %rax                          # rax = n * fact(n - 1)
    ret

编译运行：

as --64 recursion-x86-64.s -o recursion-x86-64.o
ld recursion-x86-64.o -o recursion-x86-64
./recursion-x86-64
echo $?

预期输出：

120

3.2 AArch64 Linux

文件名： recursion-aarch64.s

.section .text
.global _start
_start:
    mov x0, #5                               // 第 1 个参数 n = 5
    bl fact                                  // x0 = fact(5)

    // exit(x0)
    mov x8, #93                              // Linux AArch64 exit
    svc #0

fact:
    // long fact(long n)
    //
    // 参数：
    // x0 = n
    //
    // 返回：
    // x0 = fact(n)

    cmp x0, #1
    b.gt recursive_case                      // 如果 n > 1，进入递归分支

base_case:
    mov x0, #1                               // fact(0) 和 fact(1) 都返回 1
    ret

recursive_case:
    // 这个函数会自调用，bl 会覆盖 x30。
    // 同时递归回来后还需要当前层 n。
    // 所以保存 x29/x30 和 n。
    stp x29, x30, [sp, #-32]!                // 分配 32 字节，保存 fp/lr
    mov x29, sp
    str x0, [sp, #16]                        // 保存当前层 n

    sub x0, x0, #1                           // 参数变成 n - 1
    bl fact                                  // x0 = fact(n - 1)

    ldr x1, [sp, #16]                        // x1 = 当前层 n
    mul x0, x0, x1                           // x0 = fact(n - 1) * n

    ldp x29, x30, [sp], #32                  // 恢复 fp/lr，释放栈空间
    ret

编译运行：

as recursion-aarch64.s -o recursion-aarch64.o
ld recursion-aarch64.o -o recursion-aarch64
./recursion-aarch64
echo $?

预期输出：

120

3.3 macOS arm64

文件名： recursion-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _fact，所以先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    mov x0, #5                               // 第 1 个参数 n = 5
    bl _fact                                 // x0 = _fact(5)

    // main 返回值已经在 x0 中。
    ldp x29, x30, [sp], #16
    ret

.globl _fact
.p2align 2
_fact:
    cmp x0, #1
    b.gt recursive_case

base_case:
    mov x0, #1
    ret

recursive_case:
    // 保存当前层返回地址和 n。
    stp x29, x30, [sp, #-32]!
    mov x29, sp
    str x0, [sp, #16]                        // 保存 n

    sub x0, x0, #1                           // n - 1
    bl _fact                                 // x0 = _fact(n - 1)

    ldr x1, [sp, #16]                        // x1 = n
    mul x0, x0, x1                           // x0 = n * _fact(n - 1)

    ldp x29, x30, [sp], #32
    ret

编译运行：

clang recursion-macos-arm64.s -o recursion-macos-arm64
./recursion-macos-arm64
echo $?

预期输出：

120

4. 递归和栈

每次递归调用都需要保存一部分状态。以 fact(5) 为例，栈上会陆续保存：

n = 5
n = 4
n = 3
n = 2

到 fact(1) 时遇到基准条件，开始返回。每返回一层，就取回那一层保存的 n ，完成乘法。

如果没有栈，递归就很难知道 “回到哪一层” 和 “当前层原来的值是多少”。

5. 为什么 AArch64 必须保存 x30

AArch64 的返回地址放在 x30 。递归函数里再次执行：

bl fact

会覆盖 x30 。如果不保存， ret 就会跳错位置。

错误写法：

fact:
    sub x0, x0, #1
    bl fact
    ret                 // x30 已经被覆盖

正确思路：

stp x29, x30, [sp, #-16]!
...
bl fact
...
ldp x29, x30, [sp], #16
ret

x86-64 的 call 会把返回地址压入栈，所以返回地址天然每层不同。但仍然需要由调用者保存当前层的 n 。

6. 递归的基准条件

递归必须有基准条件：

cmp $1, %rdi
jg recursive_case
mov $1, %rax
ret
cmp x0, #1
b.gt recursive_case
mov x0, #1
ret

如果没有基准条件，函数会一直自调用，栈会不断增长，最后栈溢出。

7. 尾递归和循环

有些递归可以改写成循环。比如：

long fact_tail(long n, long acc) {
    if (n <= 1) return acc;
    return fact_tail(n - 1, acc * n);
}

这个函数的递归调用是最后一步，叫尾递归。编译器有时能把这种形式优化成循环。

手写汇编时，通常直接写循环更清楚：

acc = 1
while (n > 1) {
    acc *= n
    n--
}
return acc

递归适合表达树、图、分治等结构；简单计数循环通常直接写循环更省栈。

8. 递归深度和栈溢出

每递归一层都会消耗栈空间。 fact(5) 很安全， fact(1000000) 就不现实。

栈溢出的表现可能是：

  • 程序崩溃。
  • 触发段错误。
  • 覆盖不该覆盖的内存。

写递归时要估计最大深度，并考虑是否能改成循环。

9. 常见错误

9.1 没有基准条件

fact:
    sub x0, x0, #1
    bl fact

这会无限递归，直到栈耗尽。

9.2 递归前没有保存当前参数

sub x0, x0, #1
bl fact
mul x0, x0, x0      // 错误：当前层 n 已经丢了

递归回来后， x0 是返回值，不再是原来的 n 。

9.3 AArch64 没保存 x30

递归函数一定会再次 bl ，所以要保存返回地址。

9.4 栈分配和释放不匹配

stp x29, x30, [sp, #-32]!
...
ldp x29, x30, [sp], #16    // 错误：只释放了 16

分配多少，释放多少。

9.5 返回值超过退出码范围

5! = 120 可以用退出码观察。 6! = 720 的退出码会显示：

720 mod 256 = 208

如果要观察大结果，应该把数字转字符串输出。

10. 小练习

  1. 把 fact(5) 改成 fact(4) ，确认退出码是 24 。
  2. 写递归计算 sum(n) = n + sum(n - 1) ， sum(10) 应返回 55 。
  3. 故意删掉 AArch64 示例里的保存 x30 ，观察程序行为，再恢复。
  4. 把阶乘递归改成循环版本，对比栈使用。
  5. 思考为什么 fact(0) 应该返回 1 。
