寻址方式

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的寻址方式。

寻址方式回答的是一个非常朴素的问题：

CPU 要读写内存时，内存地址从哪里来？

先把三个概念分清：

  • 地址：内存中的位置，例如字符串 msg 的位置、数组 numbers 的起始位置。
  • 值：地址里保存的内容，例如 numbers[2] 的值是 30 。
  • 有效地址：CPU 根据 “基址 + 偏移 + 下标 * 比例” 等规则算出来的最终地址。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的很多寻址指令相似，但全局符号取地址的重定位写法不同：Linux ELF 常见 :lo12:symbol ，macOS Mach-O 常见 symbol@PAGEOFF 。

初学阶段可以先这样记：

  • x86-64 的内存操作数很强，常把 “基址、下标、比例、偏移” 写在一个括号里。
  • AArch64 是典型 load/store 架构，绝大多数算术指令只操作寄存器；访问内存主要靠 ldr 和 str 。
  • macOS arm64 的普通内存寻址像 AArch64，但全局符号重定位写法跟 Linux 不一样。

2. 地址和值：最容易混的一组概念

看下面这段数据：

numbers:
    .quad 10, 20, 30, 40

numbers 是一个标签。该标签代表数组第一个元素的地址，不是 10 本身。

可以理解为：

地址              内容
numbers + 0       10
numbers + 8       20
numbers + 16      30
numbers + 24      40

为什么每次加 8 ？因为 .quad 是 8 字节整数。

所以：

numbers           是地址
[numbers]         是地址里的值，也就是 10
numbers + 16      是第 3 个元素的地址
[numbers + 16]    是第 3 个元素的值，也就是 30

汇编里经常要在 “取地址” 和 “取值” 之间切换：

目的x86-64 LinuxAArch64 LinuxmacOS arm64
取 numbers 地址lea numbers(%rip), %rbxadrp x9, numbers + add x9, x9, :lo12:numbersadrp x9, numbers@PAGE + add x9, x9, numbers@PAGEOFF
取 numbers[0] 的值mov numbers(%rip), %raxldr x0, [x9]ldr x0, [x9]
取 numbers[2] 的值mov 16(%rbx), %raxldr x0, [x9, #16]ldr x0, [x9, #16]

3. x86-64： disp(base,index,scale)

GAS AT&T 语法里，x86-64 内存操作数的一般形式是：

disp(base, index, scale)

该指令计算有效地址的规则是：

有效地址 = disp + base + index * scale

其中：

  • disp 是常量偏移，可以省略。
  • base 是基址寄存器，可以省略。
  • index 是下标寄存器，可以省略。
  • scale 只能是 1 、 2 、 4 、 8 ，适合 byte、word、int、long 这类数组元素大小。

常见写法：

写法有效地址常见用途
(%rbx)%rbx指针指向的位置
8(%rbx)%rbx + 8结构体字段、数组下一个 8 字节元素
(%rbx,%rcx,8)%rbx + %rcx * 8long 数组下标访问
16(%rbx,%rcx,8)%rbx + %rcx * 8 + 16带固定头部偏移的数组
numbers(%rip)RIP + relocation(numbers)位置无关访问全局变量
numbers(,%rcx,8)numbers + %rcx * 8直接按标签访问数组元素

注意 AT&T 语法的源、目标顺序是 “源在前，目标在后”：

mov 8(%rbx), %rax       # rax = *(rbx + 8)
mov %rax, 8(%rbx)       # *(rbx + 8) = rax

4. x86-64 示例：读取数组第 3 个元素

文件名： addr-x86-64.s

.section .data
.balign 8
numbers:
    .quad 10, 20, 30, 40                    # 4 个 64 位整数，每个元素 8 字节

.section .text
.global _start
_start:
    # 目标：读取 numbers[2]，也就是 30，并把作为进程退出码。
    #
    # x86-64 AT&T 内存寻址：
    # disp(base,index,scale)
    # 有效地址 = disp + base + index * scale

    lea numbers(%rip), %rbx                 # rbx = numbers 的起始地址
    mov $2, %rcx                            # rcx = 下标 2
    mov (%rbx,%rcx,8), %rax                 # rax = *(rbx + rcx * 8) = numbers[2]

    # exit(rax)
    # Linux x86-64 syscall：
    # rax = 系统调用号
    # rdi = 第 1 参数
    mov %rax, %rdi                          # rdi = 30，作为退出码
    mov $60, %rax                           # rax = 60，exit 系统调用号
    syscall

编译运行：

as --64 addr-x86-64.s -o addr-x86-64.o
ld addr-x86-64.o -o addr-x86-64
./addr-x86-64
echo $?

预期输出：

30

这条指令最值得反复看：

mov (%rbx,%rcx,8), %rax

该指令不是把地址放进 %rax ，而是读取这个地址里的 8 字节值。这里 %rbx 是数组起点， %rcx 是下标， 8 是每个 .quad 元素的大小。

5. x86-64： lea 是算地址，不是读内存

lea 的全名是 load effective address。名字里有 load，但该指令不读内存，只计算地址。

文件名： lea-x86-64.s

.section .text
.global _start
_start:
    # 目标：计算 100 + 3 * 8 + 5 = 129。
    # lea 可以复用 x86 的地址计算硬件，做一些简单整数计算。

    mov $100, %rbx                           # rbx = 100，假装这是 base
    mov $3, %rcx                             # rcx = 3，假装这是 index
    lea 5(%rbx,%rcx,8), %rax                 # rax = 5 + rbx + rcx * 8 = 129

    mov %rax, %rdi                           # exit status = 129
    mov $60, %rax
    syscall

运行：

as --64 lea-x86-64.s -o lea-x86-64.o
ld lea-x86-64.o -o lea-x86-64
./lea-x86-64
echo $?

预期输出：

129

对比：

lea 5(%rbx,%rcx,8), %rax     # rax = 地址表达式本身
mov 5(%rbx,%rcx,8), %rax     # rax = 地址表达式指向的内存内容

一个算地址，一个读内存，差别巨大。

6. AArch64：load/store 架构

AArch64 的算术指令通常不能直接对内存做运算。通常要先 ldr 到寄存器，算完再 str 回内存。

ldr x0, [x1]          // x0 = *(uint64_t *)x1
add x0, x0, #1        // x0 = x0 + 1
str x0, [x1]          // *(uint64_t *)x1 = x0

常见寻址方式：

写法含义备注
[x1]地址是 x1基址寄存器
[x1, #8]地址是 x1 + 8立即数偏移
[x1, x2]地址是 x1 + x2寄存器偏移
[x1, x2, lsl #3]地址是 x1 + (x2 << 3)访问 8 字节元素数组
[x1, #8]!先 x1 = x1 + 8 ，再访问预索引，更新基址
[x1], #8先访问，再 x1 = x1 + 8后索引，更新基址

不同指令对偏移范围有限制。例如 ldr x0, [x1, #8] 的立即数偏移会按访问大小缩放，适合访问结构体字段或数组元素； ldrb 是按字节访问，偏移就按字节理解。

7. AArch64 示例：读取数组第 3 个元素

文件名： addr-aarch64.s

.section .data
.balign 8
numbers:
    .quad 10, 20, 30, 40                    // 4 个 64 位整数，每个元素 8 字节

.section .text
.global _start
_start:
    // 目标：读取 numbers[2]，也就是 30，并把作为进程退出码。

    // 取全局符号 numbers 的地址。
    // adrp 取 numbers 所在页的地址。
    // add 加上 numbers 在页内的低 12 位偏移。
    adrp x9, numbers                         // x9 = numbers 所在 4KB 页的页地址
    add x9, x9, :lo12:numbers                // x9 = numbers 的完整地址

    mov x10, #2                              // x10 = 下标 2
    ldr x0, [x9, x10, lsl #3]                // x0 = *(x9 + (x10 << 3)) = numbers[2]

    // exit(x0)
    // Linux AArch64 syscall：
    // x8 = 系统调用号
    // x0 = 第 1 参数
    mov x8, #93                              // x8 = 93，exit 系统调用号
    svc #0

编译运行：

as addr-aarch64.s -o addr-aarch64.o
ld addr-aarch64.o -o addr-aarch64
./addr-aarch64
echo $?

预期输出：

30

核心是：

ldr x0, [x9, x10, lsl #3]

lsl #3 表示左移 3 位，也就是乘以 8。因为 numbers 里每个 .quad 元素都是 8 字节，所以 numbers[2] 的地址是：

numbers + 2 * 8

8. macOS arm64：Mach-O 全局地址写法

macOS arm64 的普通 ldr/str 寻址方式和 AArch64 Linux 很像，但取全局符号地址时写法不同。

Linux AArch64：

adrp x9, numbers
add x9, x9, :lo12:numbers

macOS arm64：

adrp x9, numbers@PAGE
add x9, x9, numbers@PAGEOFF

文件名： addr-macos-arm64.s

.section __DATA,__data
.p2align 3
numbers:
    .quad 10, 20, 30, 40                    // 4 个 64 位整数，每个元素 8 字节

.text
.globl _main
.p2align 2
_main:
    // 目标：读取 numbers[2]，也就是 30，并把作为 main 返回值。
    //
    // main 的返回值放在 x0/w0。
    // 退出码通常只观察低 8 位，30 能直接看出来。

    adrp x9, numbers@PAGE                   // x9 = numbers 所在 4KB 页的页地址
    add x9, x9, numbers@PAGEOFF             // x9 = numbers 的完整地址

    mov x10, #2                             // x10 = 下标 2
    ldr x0, [x9, x10, lsl #3]               // x0 = numbers[2] = 30

    ret                                     // 返回给 C 运行时，进程退出码为 30

编译运行：

clang addr-macos-arm64.s -o addr-macos-arm64
./addr-macos-arm64
echo $?

预期输出：

30

这段代码没有调用其他函数，所以 _main 是叶子函数，不需要保存 x29/x30 。

9. 预索引和后索引：适合移动指针

AArch64 有两种很实用的 “访问内存并更新指针” 的形式：

ldr x0, [x1, #8]!     // 先 x1 += 8，再从新地址读取
ldr x0, [x1], #8      // 先从旧地址读取，再 x1 += 8

字节拷贝时，后索引特别直观：

ldrb w4, [x1], #1     // w4 = *x1; x1 += 1
strb w4, [x2], #1     // *x2 = w4; x2 += 1

x86-64 没有这种通用的 ldr [base], #imm 写法。通常分成两步：

movzbq (%rsi), %rax   # 读取 *rsi
add $1, %rsi          # rsi += 1

或者使用字符串指令，例如 lodsb 、 stosb 、 rep movsb 。不过入门阶段，先写显式 mov + add 更容易理解。

10. AArch64 示例：用后索引复制字符串

这个程序把 src 中的字符串逐字节复制到 dst ，再把 dst 写到标准输出。

文件名： copy-aarch64.s

.section .rodata
src:
    .ascii "AArch64 addressing modes\n"
src_len = . - src

.section .bss
.balign 16
dst:
    .space src_len                            // 预留和 src 一样长的缓冲区

.section .text
.global _start
_start:
    // x1 = src 当前读指针
    adrp x1, src
    add x1, x1, :lo12:src

    // x2 = dst 当前写指针
    adrp x2, dst
    add x2, x2, :lo12:dst

    mov x3, #src_len                          // x3 = 剩余要复制的字节数

copy_loop:
    cbz x3, write_out                         // 如果 x3 == 0，复制结束

    ldrb w4, [x1], #1                         // w4 = *x1; 然后 x1 += 1
    strb w4, [x2], #1                         // *x2 = w4; 然后 x2 += 1
    sub x3, x3, #1                            // 剩余字节数减 1
    b copy_loop

write_out:
    // write(1, dst, src_len)
    mov x8, #64                               // x8 = write 系统调用号
    mov x0, #1                                // x0 = fd = 1，标准输出
    adrp x1, dst                              // x1 = dst 所在页
    add x1, x1, :lo12:dst                     // x1 = dst 的完整地址
    mov x2, #src_len                          // x2 = 写出的字节数
    svc #0

    // exit(0)
    mov x8, #93                               // x8 = exit 系统调用号
    mov x0, #0
    svc #0

运行：

as copy-aarch64.s -o copy-aarch64.o
ld copy-aarch64.o -o copy-aarch64
./copy-aarch64

预期输出：

AArch64 addressing modes

这两行是本节主角：

ldrb w4, [x1], #1
strb w4, [x2], #1

这些值都使用后索引寻址。先访问旧地址，再让指针自动加 1，非常适合顺序处理字符串或字节数组。

11. macOS arm64 示例：同样用后索引复制字符串

文件名： copy-macos-arm64.s

.section __TEXT,__const
src:
    .ascii "macOS arm64 addressing modes\n"
src_len = . - src

.zerofill __DATA,__bss,dst,src_len,0

.text
.globl _main
.p2align 2
_main:
    // 下面会调用 _write，所以 _main 是非叶子函数。
    // 先保存 x29/x30，避免 bl _write 覆盖返回地址。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    // x1 = src 当前读指针
    adrp x1, src@PAGE
    add x1, x1, src@PAGEOFF

    // x2 = dst 当前写指针
    adrp x2, dst@PAGE
    add x2, x2, dst@PAGEOFF

    mov x3, #src_len                          // x3 = 剩余要复制的字节数

copy_loop:
    cbz x3, write_out                         // 如果 x3 == 0，复制结束

    ldrb w4, [x1], #1                         // w4 = *x1; 然后 x1 += 1
    strb w4, [x2], #1                         // *x2 = w4; 然后 x2 += 1
    sub x3, x3, #1                            // 剩余字节数减 1
    b copy_loop

write_out:
    // write(1, dst, src_len)
    // macOS 入门阶段推荐调用 libSystem 的 _write。
    mov x0, #1                                // x0 = fd = 1，标准输出
    adrp x1, dst@PAGE                         // x1 = dst 所在页
    add x1, x1, dst@PAGEOFF                   // x1 = dst 的完整地址
    mov x2, #src_len                          // x2 = 写出的字节数
    bl _write

    mov w0, #0                                // main 返回 0
    ldp x29, x30, [sp], #16                   // 恢复 x29/x30
    ret

运行：

clang copy-macos-arm64.s -o copy-macos-arm64
./copy-macos-arm64
echo $?

预期输出：

macOS arm64 addressing modes
0

Mach-O 的 .zerofill 参数含义是：

.zerofill segment, section, symbol, size, align

这里的 align 是 2 的指数。 0 表示 1 字节对齐，足够保存字节缓冲区；如果保存 8 字节整数数组，通常会用 .p2align 3 或 .zerofill ... ,3 做 8 字节对齐。

12. 栈寻址

栈也是内存，所以栈同样通过地址访问。栈指针是：

平台栈指针
x86-64%rsp
AArch64 Linuxsp
macOS arm64sp

x86-64 常见写法：

sub $16, %rsp             # 分配 16 字节栈空间
movq $42, 8(%rsp)         # *(rsp + 8) = 42
mov 8(%rsp), %rax         # rax = *(rsp + 8)
add $16, %rsp             # 释放栈空间

AArch64/macOS arm64 常见写法：

sub sp, sp, #16           // 分配 16 字节栈空间
mov x0, #42
str x0, [sp, #8]          // *(sp + 8) = 42
ldr x1, [sp, #8]          // x1 = *(sp + 8)
add sp, sp, #16           // 释放栈空间

注意：x86-64 和 AArch64 的 ABI 都要求函数调用边界附近保持栈对齐。AArch64 对 sp 的 16 字节对齐尤其严格，手写函数时不要随便让 sp 变成奇怪的地址。

13. 符号地址： rip 、 adr 、 adrp

现代 64 位程序通常会启用位置无关代码和 ASLR，程序每次运行的加载地址可能不同。所以汇编里常使用 “相对当前指令” 的方式取全局地址。

13.1 x86-64 的 RIP-relative

lea msg(%rip), %rsi       # rsi = msg 的运行时地址
mov msg(%rip), %rax       # rax = msg 地址里的 8 字节值

%rip 是当前指令指针附近的地址。 msg(%rip) 让链接器生成相对当前指令的重定位，适合位置无关代码。

13.2 AArch64 的 adr 和 adrp

adr x0, msg               // 适合距离较近的标签
adrp x0, msg              // 取 msg 所在页
add x0, x0, :lo12:msg     // 加上页内偏移

adr 简短，但范围有限。 adrp + add 更常见，尤其是访问全局变量、字符串、外部符号时。

13.3 macOS arm64 的 @PAGE/@PAGEOFF

adrp x0, msg@PAGE
add x0, x0, msg@PAGEOFF

这和 Linux AArch64 的 adrp + :lo12: 思路一样，都是 “页地址 + 页内偏移”。不同的是 Mach-O 使用 Apple 的重定位后缀。

14. 数据宽度会影响寻址结果

同一个地址，可以按 1、2、4、8 字节读取。读多宽由指令决定，不由标签决定。

x86-64：

movzbq (%rsi), %rax       # 读取 1 字节，零扩展到 64 位
movzwq (%rsi), %rax       # 读取 2 字节，零扩展到 64 位
movl (%rsi), %eax         # 读取 4 字节；写 eax 会清空 rax 高 32 位
movq (%rsi), %rax         # 读取 8 字节

AArch64/macOS arm64：

ldrb w0, [x1]             // 读取 1 字节，零扩展到 w0
ldrh w0, [x1]             // 读取 2 字节，零扩展到 w0
ldr w0, [x1]              // 读取 4 字节；写 w0 会清空 x0 高 32 位
ldr x0, [x1]              // 读取 8 字节

数组下标也要配合数据宽度：

元素类型字节数x86-64 scaleAArch64 shift
byte11 或省略lsl #0 或省略
short22lsl #1
int44lsl #2
long / pointer88lsl #3

15. 常见坑

15.1 把地址和值写反

x86-64：

lea msg(%rip), %rsi       # rsi = msg 的地址
mov msg(%rip), %rsi       # rsi = msg 开头 8 字节内容

AArch64：

adrp x1, msg
add x1, x1, :lo12:msg     // x1 = msg 的地址
ldr x1, [x1]              // x1 = msg 地址里的 8 字节内容

如果 write 需要缓冲区地址，却传了字符串开头 8 字节内容，程序通常会因为地址无效而返回 EFAULT 或崩溃。

15.2 x86-64 scale 只能是 1、2、4、8

下面是合法的：

mov (%rbx,%rcx,8), %rax

下面不是合法的 x86-64 寻址比例：

mov (%rbx,%rcx,3), %rax

如果要乘 3，通常先用 lea 算出 rcx * 3 ，或者换成其他指令组合。

15.3 AArch64 不能随便 “内存加内存”

这类想法在 AArch64 里不成立：

add [x1], [x2], [x3]      // 错误示意

要写成：

ldr x4, [x2]
ldr x5, [x3]
add x4, x4, x5
str x4, [x1]

先从内存加载到寄存器，再计算，再写回内存。

15.4 macOS 把 Linux 的 :lo12: 照搬过来

Linux AArch64：

adrp x0, msg
add x0, x0, :lo12:msg

macOS arm64：

adrp x0, msg@PAGE
add x0, x0, msg@PAGEOFF

这不是指令集差异，而是目标文件格式和汇编器重定位语法差异。

15.5 忘记对齐

很多现代 CPU 可以处理未对齐访问，但可能更慢，某些指令或平台还可能要求对齐。写 .quad 数组时保持 8 字节对齐是好习惯：

.balign 8       # Linux/GAS 常见
.p2align 3      # 2^3 = 8，macOS 也常见

16. 小练习

  1. 把 numbers[2] 改成 numbers[3] ，让退出码变成 40 。
  2. 在 x86-64 示例中，把 (%rbx,%rcx,8) 改成 8(%rbx,%rcx,8) ，观察访问的是哪个元素。
  3. 在 AArch64 示例中，把 lsl #3 改成 lsl #2 ，观察退出码为什么会变得不符合预期。
  4. 在字符串复制示例中，把后索引版本拆成普通 [x1] 加 add x1, x1, #1 ，确认输出不变。
  5. 写一个 4 字节整数数组，把 x86-64 scale 改成 4 ，把 AArch64 shift 改成 lsl #2 。
