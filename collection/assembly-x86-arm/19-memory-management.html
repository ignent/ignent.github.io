内存管理

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的内存管理。

汇编程序能使用的内存大致来自这些地方：

.text   代码
.rodata 只读数据
.data   已初始化的可写全局数据
.bss    未初始化的可写全局数据
stack   栈，保存返回地址、局部变量、临时数据
heap    堆，运行时动态分配
mmap    向操作系统申请一段虚拟内存映射

重点建立一个实用直觉：

小而固定的数据：放 .data/.bss
函数临时数据：放栈上
运行时才知道大小的数据：用堆或 mmap

说明：Linux 示例会展示裸 syscall，包括 brk 和 mmap 。macOS arm64 入门示例更推荐调用 libSystem 的 _malloc 、 _free 、 _write ，避免直接依赖 Darwin VM syscall 细节。

内存管理最容易出错的地方不是 “申请”，而是：

  • 写越界。
  • 用错权限。
  • 忘记释放。
  • 释放后继续使用。
  • 栈指针没有恢复。

2. .data 和 .bss

.data 适合有初始值的可写数据：

.section .data
counter:
    .quad 42

.bss 适合未初始化或初始化为 0 的空间：

.section .bss
buffer:
    .skip 128

程序加载时， .bss 会被初始化为 0。不会在可执行文件里存满 128 个零字节，而是由加载器创建零填充内存。

3. 栈上临时分配

函数里临时需要 32 字节，可以在栈上分配。

x86-64：

sub $32, %rsp       # 分配 32 字节
movq $123, (%rsp)   # 使用这块空间
add $32, %rsp       # 释放 32 字节

AArch64/macOS arm64：

sub sp, sp, #32     // 分配 32 字节
mov x0, #123
str x0, [sp]        // 使用这块空间
add sp, sp, #32     // 释放 32 字节

栈分配必须成对出现：分配多少，释放多少。AArch64/macOS arm64 要特别注意 sp 保持 16 字节对齐。

4. 三个平台示例：栈上数组求和

目标逻辑：

long tmp[4];
tmp[0] = 10;
tmp[1] = 20;
tmp[2] = 30;
tmp[3] = 40;
return tmp[0] + tmp[1] + tmp[2] + tmp[3];

预期退出码是 100 。

4.1 x86-64 Linux

文件名： memory-x86-64.s

.section .text
.global _start
_start:
    # 在栈上分配 32 字节，放 4 个 8 字节整数。
    sub $32, %rsp

    movq $10, 0(%rsp)                        # tmp[0] = 10
    movq $20, 8(%rsp)                        # tmp[1] = 20
    movq $30, 16(%rsp)                       # tmp[2] = 30
    movq $40, 24(%rsp)                       # tmp[3] = 40

    mov 0(%rsp), %rax                        # rax = tmp[0]
    add 8(%rsp), %rax                        # rax += tmp[1]
    add 16(%rsp), %rax                       # rax += tmp[2]
    add 24(%rsp), %rax                       # rax += tmp[3]

    add $32, %rsp                            # 释放栈空间

    # exit(rax)
    mov %rax, %rdi                           # rdi = 100
    mov $60, %rax                            # Linux x86-64 exit
    syscall

编译运行：

as --64 memory-x86-64.s -o memory-x86-64.o
ld memory-x86-64.o -o memory-x86-64
./memory-x86-64
echo $?

预期输出：

100

4.2 AArch64 Linux

文件名： memory-aarch64.s

.section .text
.global _start
_start:
    // 在栈上分配 32 字节，放 4 个 8 字节整数。
    sub sp, sp, #32

    mov x1, #10
    str x1, [sp, #0]                         // tmp[0] = 10

    mov x1, #20
    str x1, [sp, #8]                         // tmp[1] = 20

    mov x1, #30
    str x1, [sp, #16]                        // tmp[2] = 30

    mov x1, #40
    str x1, [sp, #24]                        // tmp[3] = 40

    ldr x0, [sp, #0]                         // x0 = tmp[0]
    ldr x1, [sp, #8]
    add x0, x0, x1                           // x0 += tmp[1]
    ldr x1, [sp, #16]
    add x0, x0, x1                           // x0 += tmp[2]
    ldr x1, [sp, #24]
    add x0, x0, x1                           // x0 += tmp[3]

    add sp, sp, #32                          // 释放栈空间

    // exit(x0)
    mov x8, #93                              // Linux AArch64 exit
    svc #0

编译运行：

as memory-aarch64.s -o memory-aarch64.o
ld memory-aarch64.o -o memory-aarch64
./memory-aarch64
echo $?

预期输出：

100

4.3 macOS arm64

文件名： memory-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // 在栈上分配 32 字节，放 4 个 8 字节整数。
    sub sp, sp, #32

    mov x1, #10
    str x1, [sp, #0]

    mov x1, #20
    str x1, [sp, #8]

    mov x1, #30
    str x1, [sp, #16]

    mov x1, #40
    str x1, [sp, #24]

    ldr x0, [sp, #0]
    ldr x1, [sp, #8]
    add x0, x0, x1
    ldr x1, [sp, #16]
    add x0, x0, x1
    ldr x1, [sp, #24]
    add x0, x0, x1                           // x0 = 100

    add sp, sp, #32                          // 释放栈空间
    ret

编译运行：

clang memory-macos-arm64.s -o memory-macos-arm64
./memory-macos-arm64
echo $?

预期输出：

100

5. Linux brk ：移动堆边界

brk 控制进程数据段末尾，也就是传统意义上的堆顶。

常见流程：

old = brk(0)          获取当前堆顶
brk(old + size)       扩大堆
使用 old..old+size
brk(old)              缩回堆

x86-64 Linux syscall：

rax = 12
rdi = new_brk

AArch64 Linux syscall：

x8 = 214
x0 = new_brk

brk 比较底层，现代程序通常通过 malloc 间接使用堆。手写汇编学习时，了解有助于理解 “堆顶” 概念。

6. Linux mmap ：申请独立内存映射

mmap 更通用，可以申请匿名内存：

ptr = mmap(NULL, 4096,
           PROT_READ | PROT_WRITE,
           MAP_PRIVATE | MAP_ANONYMOUS,
           -1, 0);

常用常量：

常量Linux 常见值含义
PROT_READ1可读
PROT_WRITE2可写
MAP_PRIVATE2私有映射
MAP_ANONYMOUS32匿名映射，不来自文件

用完后：

munmap(ptr, 4096);

如果 mmap 失败，Linux 通常返回负数错误码。真实程序要检查返回值。

7. Linux x86-64 mmap 片段

.equ SYS_mmap, 9
.equ SYS_munmap, 11
.equ PROT_READ, 1
.equ PROT_WRITE, 2
.equ MAP_PRIVATE, 2
.equ MAP_ANONYMOUS, 32

    mov $SYS_mmap, %rax
    xor %rdi, %rdi                           # addr = NULL
    mov $4096, %rsi                          # length = 4096
    mov $(PROT_READ | PROT_WRITE), %rdx      # prot
    mov $(MAP_PRIVATE | MAP_ANONYMOUS), %r10 # flags，第 4 参数是 r10
    mov $-1, %r8                             # fd = -1
    xor %r9, %r9                             # offset = 0
    syscall                                  # rax = ptr 或负数错误码

    test %rax, %rax
    js mmap_failed

    movb $42, (%rax)                         # 使用这块内存

    mov %rax, %rdi                           # addr
    mov $4096, %rsi                          # length
    mov $SYS_munmap, %rax
    syscall

注意：Linux x86-64 syscall 第 4 个参数放在 %r10 ，不是 %rcx 。

8. Linux AArch64 mmap 片段

.equ SYS_mmap, 222
.equ SYS_munmap, 215
.equ PROT_READ, 1
.equ PROT_WRITE, 2
.equ MAP_PRIVATE, 2
.equ MAP_ANONYMOUS, 32

    mov x0, #0                               // addr = NULL
    mov x1, #4096                            // length = 4096
    mov x2, #(PROT_READ | PROT_WRITE)        // prot
    mov x3, #(MAP_PRIVATE | MAP_ANONYMOUS)   // flags
    mov x4, #-1                              // fd = -1
    mov x5, #0                               // offset = 0
    mov x8, #SYS_mmap
    svc #0                                   // x0 = ptr 或负数错误码

    cmp x0, #0
    b.lt mmap_failed

    mov w1, #42
    strb w1, [x0]                            // 使用这块内存

    mov x1, #4096                            // length
    mov x8, #SYS_munmap
    svc #0

AArch64 Linux syscall 参数按 x0 到 x5 顺序传，比较直观。

9. macOS arm64：用 malloc/free

macOS 入门阶段最稳妥的是调用 libSystem：

ptr = malloc(32);
ptr[0] = 42;
free(ptr);

汇编轮廓：

.globl _main
_main:
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    mov x0, #32
    bl _malloc              // x0 = ptr

    cbz x0, failed

    mov w1, #42
    strb w1, [x0]

    bl _free                // free(ptr)，ptr 仍在 x0

    mov x0, #0
    ldp x29, x30, [sp], #16
    ret

failed:
    mov x0, #1
    ldp x29, x30, [sp], #16
    ret

如果调用 _free 前还要调用别的函数，就要先保存 ptr ，因为 x0 是 caller-saved。

10. 权限：可读、可写、可执行

内存页通常有权限：

R  可读
W  可写
X  可执行

.text 通常是 R-X ，不能写。

.data / .bss 通常是 RW- ，不能执行。

mmap 可以指定权限，例如：

PROT_READ | PROT_WRITE

现代系统通常启用 W^X 思想：同一段内存尽量不要同时可写又可执行。写 JIT 或加载器时才会更深入处理执行权限。

11. 对齐

很多数据类型有自然对齐：

类型常见大小常见对齐
byte11
int3244
int6488
栈指针平台 ABI 要求16

AArch64 对 sp 的对齐要求更严格。不要这样：

sub sp, sp, #8      // 风险：sp 不再 16 字节对齐

更稳妥：

sub sp, sp, #16
...
add sp, sp, #16

12. 常见错误

12.1 栈空间释放不匹配

sub sp, sp, #32
...
add sp, sp, #16     // 错误：只释放了一半

分配多少，释放多少。

12.2 栈指针不对齐

AArch64/macOS arm64 的 sp 应保持 16 字节对齐。调用函数前尤其重要。

12.3 写越界

申请 32 字节，却写第 40 字节：

str x0, [sp, #40]

这会覆盖别的数据，可能立刻崩溃，也可能埋下很难查的 bug。

12.4 释放后继续使用

free(ptr);
ptr[0] = 1;         // use-after-free

汇编里不会自动检查。释放后最好不要再使用这个地址。

12.5 忘记检查分配失败

malloc 可能返回 NULL ， mmap 可能返回错误。真实程序必须检查。

12.6 Linux x86-64 mmap 第 4 参数放错

syscall 第 4 参数是 %r10 ：

mov flags, %r10

不是 %rcx 。

13. 小练习

  1. 把栈上数组示例改成 8 个元素，求和结果控制在 255 以内。
  2. 用 .bss 定义 64 字节缓冲区，写入 4 个字节再输出。
  3. 在 Linux 上用 mmap 申请 4096 字节，写入一个字节后释放。
  4. 在 macOS 上调用 _malloc 申请 32 字节，写入后 _free 。
  5. 故意把 AArch64 栈分配改成 8 字节，思考为什么这违反 ABI 对齐要求。
