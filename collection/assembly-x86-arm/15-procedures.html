过程

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的过程，也就是函数。

过程过程用于把一段代码封装起来：

long add3(long a, long b, long c) {
    return a + b + c;
}

汇编里的函数调用主要关心这些问题：

参数放在哪里？
返回值放在哪里？
如何跳到函数？
如何返回调用者？
哪些寄存器调用后还要保持不变？
函数要不要使用栈？

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 都遵循 AAPCS64 的核心调用规则；macOS 还会有 Mach-O 符号命名和平台约定差异。

# x86-64：rax = rdi + rsi + rdx
add3:
    mov %rdi, %rax
    add %rsi, %rax
    add %rdx, %rax
    ret
// AArch64/macOS arm64：x0 = x0 + x1 + x2
add3:
    add x0, x0, x1
    add x0, x0, x2
    ret

2. 调用和返回

2.1 x86-64： call 和 ret

call add3

call 会做两件事：

1. 把下一条指令的地址压入栈
2. 跳到 add3

函数里的：

ret

会从栈顶弹出返回地址，并跳回去。

2.2 AArch64/macOS arm64： bl 和 ret

bl add3

bl 是 branch with link，会做两件事：

1. 把下一条指令的地址放进 x30/lr
2. 跳到 add3

函数里的：

ret

默认跳回 x30 保存的地址。

所以 AArch64 函数如果还要调用别的函数，必须先保存 x30 ，否则返回地址会被新的 bl 覆盖。

3. 三个平台示例：add3 (10, 20, 30)

目标逻辑：

long add3(long a, long b, long c) {
    return a + b + c;
}

return add3(10, 20, 30);

预期退出码：

10 + 20 + 30 = 60

3.1 x86-64 Linux

文件名： proc-x86-64.s

.section .text
.global _start
_start:
    # System V AMD64 ABI 中，前三个整数参数放在：
    # rdi, rsi, rdx。

    mov $10, %rdi                            # 第 1 个参数 a = 10
    mov $20, %rsi                            # 第 2 个参数 b = 20
    mov $30, %rdx                            # 第 3 个参数 c = 30
    call add3                                # rax = add3(a, b, c)

    # exit(rax)
    mov %rax, %rdi                           # rdi = 返回值 60，作为退出码
    mov $60, %rax                            # Linux x86-64 exit
    syscall

add3:
    # 参数：
    # rdi = a
    # rsi = b
    # rdx = c
    #
    # 返回值：
    # rax = a + b + c

    mov %rdi, %rax                           # rax = a
    add %rsi, %rax                           # rax += b
    add %rdx, %rax                           # rax += c
    ret

编译运行：

as --64 proc-x86-64.s -o proc-x86-64.o
ld proc-x86-64.o -o proc-x86-64
./proc-x86-64
echo $?

预期输出：

60

3.2 AArch64 Linux

文件名： proc-aarch64.s

.section .text
.global _start
_start:
    // AAPCS64 中，前 8 个整数参数放在 x0-x7。

    mov x0, #10                              // 第 1 个参数 a = 10
    mov x1, #20                              // 第 2 个参数 b = 20
    mov x2, #30                              // 第 3 个参数 c = 30
    bl add3                                  // x0 = add3(a, b, c)

    // exit(x0)
    mov x8, #93                              // Linux AArch64 exit
    svc #0

add3:
    // 参数：
    // x0 = a
    // x1 = b
    // x2 = c
    //
    // 返回值：
    // x0 = a + b + c

    add x0, x0, x1                           // x0 = a + b
    add x0, x0, x2                           // x0 = a + b + c
    ret

编译运行：

as proc-aarch64.s -o proc-aarch64.o
ld proc-aarch64.o -o proc-aarch64
./proc-aarch64
echo $?

预期输出：

60

3.3 macOS arm64

文件名： proc-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _add3，所以这是非叶子函数。
    // bl 会覆盖 x30，因此先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    mov x0, #10                              // 第 1 个参数 a = 10
    mov x1, #20                              // 第 2 个参数 b = 20
    mov x2, #30                              // 第 3 个参数 c = 30
    bl _add3                                 // x0 = _add3(a, b, c)

    // main 返回值已经在 x0 中。
    ldp x29, x30, [sp], #16
    ret

.globl _add3
.p2align 2
_add3:
    // macOS C 符号名前通常有下划线，所以函数名写 _add3。
    add x0, x0, x1                           // x0 = a + b
    add x0, x0, x2                           // x0 = a + b + c
    ret

编译运行：

clang proc-macos-arm64.s -o proc-macos-arm64
./proc-macos-arm64
echo $?

预期输出：

60

4. 参数寄存器

4.1 x86-64 Linux：System V AMD64 ABI

整数 / 指针参数通常按顺序放入：

参数序号寄存器
1%rdi
2%rsi
3%rdx
4%rcx
5%r8
6%r9

更多参数通常走栈。

4.2 AArch64 Linux/macOS arm64：AAPCS64

整数 / 指针参数通常按顺序放入：

参数序号寄存器
1x0
2x1
3x2
4x3
5x4
6x5
7x6
8x7

返回值通常放在 x0 。

5. caller-saved 和 callee-saved

调用函数时，不是所有寄存器都会自动保持原值。ABI 会规定两类寄存器。

5.1 caller-saved

caller-saved 的意思是：调用者如果还想在函数调用后继续使用这些寄存器，调用前由调用者保存。

常见例子：

平台caller-saved 举例
x86-64 System V%rax %rcx %rdx %rsi %rdi %r8 - %r11
AArch64x0 - x17

参数和返回值寄存器通常都属于 caller-saved。

5.2 callee-saved

callee-saved 的意思是：被调用函数如果要使用这些寄存器，必须在返回前恢复原值。

常见例子：

平台callee-saved 举例
x86-64 System V%rbx %rbp %r12 - %r15
AArch64x19 - x28 、 x29 、 x30

如果函数临时使用 x19 ，应该保存：

stp x19, x20, [sp, #-16]!
...
ldp x19, x20, [sp], #16
ret

6. 栈帧

简单叶子函数不一定需要栈帧：

add3:
    add x0, x0, x1
    add x0, x0, x2
    ret

但下面情况通常需要栈：

  • 函数会调用其他函数，需要保存返回地址。
  • 局部变量放不下寄存器。
  • 需要保存 callee-saved 寄存器。
  • 需要为调试器 / 回溯建立标准帧。

AArch64/macOS arm64 常见函数序言：

stp x29, x30, [sp, #-16]!
mov x29, sp

函数结尾：

ldp x29, x30, [sp], #16
ret

x86-64 常见函数序言：

push %rbp
mov %rsp, %rbp

函数结尾：

pop %rbp
ret

入门阶段先记住：栈指针通常要保持 16 字节对齐，尤其是在调用其他函数之前。

7. 局部变量示例

如果需要在栈上放一个 8 字节局部变量，x86-64 可以这样：

push %rbp
mov %rsp, %rbp
sub $16, %rsp       # 分配 16 字节，保持对齐

movq $42, -8(%rbp)  # local = 42
mov -8(%rbp), %rax  # rax = local

leave               # 等价于 mov %rbp,%rsp; pop %rbp
ret

AArch64：

stp x29, x30, [sp, #-32]!
mov x29, sp

mov x0, #42
str x0, [sp, #16]   // local = 42
ldr x0, [sp, #16]   // x0 = local

ldp x29, x30, [sp], #32
ret

这里分配 32 字节，是为了同时保存帧指针 / 返回地址并留出局部变量空间，同时保持 sp 16 字节对齐。

8. 调用 C 库函数

macOS 示例已经调用过 _write 。如果在 Linux 上用 gcc 或 clang 链接 libc，也可以调用 printf 、 puts 等 C 函数。

但这和裸 _start 程序不同：

  • 需要按 C ABI 准备参数。
  • 需要通过 C 编译器 / 链接器链接 libc。
  • 程序入口通常是 main ，不是 _start 。
  • 栈对齐必须正确。

x86-64 Linux 调用 puts 的轮廓：

.global main
main:
    lea msg(%rip), %rdi
    call puts
    mov $0, %eax
    ret

编译时用：

gcc puts.s -o puts-demo

本系列前半部分更多使用裸 syscall，是为了把操作系统接口讲清楚；调用 C 库会在真实项目里更常见。

9. 常见错误

9.1 AArch64 函数里调用别的函数却不保存 x30

错误写法：

foo:
    bl bar
    ret

bl bar 会覆盖 x30 ，导致 foo 可能回不到原调用者。修正：

foo:
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    bl bar

    ldp x29, x30, [sp], #16
    ret

9.2 使用 callee-saved 寄存器却不恢复

如果 x86-64 函数修改 %rbx ，返回前要恢复。如果 AArch64 函数修改 x19 ，返回前也要恢复。

9.3 以为参数寄存器调用后还保留

x0 、 x1 、 %rdi 、 %rsi 这类参数寄存器通常是 caller-saved。调用函数后，不要默认这些值还保存旧参数。

9.4 栈没有保持 16 字节对齐

很多 ABI 要求调用函数前栈保持 16 字节对齐。随便 push 或 sub 一个不是 16 的倍数，可能让被调用函数在保存向量寄存器或访问栈时出问题。

9.5 macOS 符号名忘记下划线

macOS Mach-O 里 C 符号名前通常有下划线：

.globl _main
_main:

自定义给 C / 链接器看的函数也常写成 _add3 。Linux ELF 通常不用这个前导下划线。

10. 小练习

  1. 把 add3 改成 mul_add(a, b, c) = a * b + c ，用退出码验证。
  2. 写一个 max2(a, b) 函数，返回较大的值。
  3. 在 AArch64 里写一个会调用 add3 的 add6 ，注意保存 x30 。
  4. 在 x86-64 函数里使用 %rbx ，先故意不保存，再改成 push %rbx / pop %rbx 。
  5. 用 objdump -d 或 llvm-objdump -d 观察 call 、 bl 、 ret 的机器码。
