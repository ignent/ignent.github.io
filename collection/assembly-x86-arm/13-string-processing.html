字符串处理

以下对比 x86-64 Linux、AArch64 Linux、macOS arm64 三种环境里的字符串处理。

汇编里没有 “字符串类型”。字符串通常就是一段连续字节：

地址 + 长度

或者：

地址 + 末尾的 0 字节

C 风格字符串以 \0 结束；Linux/macOS 的 write 系统调用或库函数不需要 \0 ，只需要明确的字节长度。

说明：AArch64 和 ARM64 在这里都指 64 位 Arm 架构。Linux AArch64 和 macOS arm64 的字符串遍历指令基本相同；差异主要在全局地址重定位、入口、链接方式和输出方式。

1. 一张表先建立全局印象

操作x86-64 LinuxAArch64 LinuxmacOS arm64

读取 1 字节movzbq (%rsi), %raxldrb wN, [xM]同 AArch64
写入 1 字节mov %al, (%rdi)strb wN, [xM]同 AArch64
指针后移inc %rsi / add $1, %rsiadd xN, xN, #1 或后索引同 AArch64
判断 \0test %al, %alcbz wN, label同 AArch64

常见字符串段.rodata / .data.rodata / .data.cstring / .data

两个重要观念：

  • .ascii "abc" 不会自动追加 \0 。
  • .asciz "abc" 会追加 \0 ，也就是字节序列 a b c 0 。

2. 字符串的两种常见表示

2.1 长度已知的字节串

msg:
    .ascii "hello\n"
msg_len = . - msg

这种写法适合 write(fd, msg, msg_len) ，因为 write 本来就要求长度。

优点：

  • 可以包含任意字节，包括 0 。
  • 不需要遍历查找结尾。
  • 输出长度由汇编器计算，稳定可靠。

2.2 以 0 结尾的 C 字符串

msg:
    .asciz "hello"

内存里实际是：

'h' 'e' 'l' 'l' 'o' 0

这种写法适合调用 C 库函数，例如 puts 、 strlen 。如果手动调用 write ，仍然需要先知道长度。

3. 三个平台示例：把字符串转成大写并输出

目标逻辑：

src = "hello, arm64 and x86-64!\n";

for each byte in src:
    if ('a' <= byte && byte <= 'z') {
        byte -= 32;
    }
    dst[i] = byte;

write(dst);

预期输出：

HELLO, ARM64 AND X86-64!

3.1 x86-64 Linux

文件名： string-x86-64.s

.section .rodata
src:
    .ascii "hello, arm64 and x86-64!\n"
src_len = . - src

.section .bss
.lcomm dst, src_len

.section .text
.global _start
_start:
    # rsi = src 当前指针
    # rdi = dst 当前指针
    # rcx = 剩余字节数

    lea src(%rip), %rsi                      # rsi = src 地址
    lea dst(%rip), %rdi                      # rdi = dst 地址
    mov $src_len, %rcx                       # rcx = 要处理的字节数

copy_loop:
    movzbq (%rsi), %rax                      # rax = 当前字节，零扩展

    # 判断是否在 'a'..'z' 之间。
    cmp $'a', %al
    jb store_char                            # 小于 'a'，不是小写字母

    cmp $'z', %al
    ja store_char                            # 大于 'z'，不是小写字母

    sub $32, %al                             # 小写转大写：'a' - 'A' = 32

store_char:
    mov %al, (%rdi)                          # 保存到 dst
    inc %rsi                                 # src++
    inc %rdi                                 # dst++
    dec %rcx                                 # 剩余字节数--
    jnz copy_loop                            # 还没处理完就继续

    # write(1, dst, src_len)
    mov $1, %rax                             # Linux x86-64 write
    mov $1, %rdi                             # stdout
    lea dst(%rip), %rsi                      # 缓冲区地址
    mov $src_len, %rdx                       # 输出长度
    syscall

    # exit(0)
    mov $60, %rax                            # Linux x86-64 exit
    xor %rdi, %rdi
    syscall

编译运行：

as --64 string-x86-64.s -o string-x86-64.o
ld string-x86-64.o -o string-x86-64
./string-x86-64

预期输出：

HELLO, ARM64 AND X86-64!

3.2 AArch64 Linux

文件名： string-aarch64.s

.section .rodata
src:
    .ascii "hello, arm64 and x86-64!\n"
src_len = . - src

.section .bss
.balign 8
dst:
    .skip src_len

.section .text
.global _start
_start:
    // x1 = src 当前指针
    // x2 = dst 当前指针
    // x3 = 剩余字节数

    adrp x1, src                             // x1 = src 所在页
    add x1, x1, :lo12:src                    // x1 = src 地址

    adrp x2, dst                             // x2 = dst 所在页
    add x2, x2, :lo12:dst                    // x2 = dst 地址

    mov x3, #src_len                         // x3 = 要处理的字节数

copy_loop:
    ldrb w4, [x1], #1                        // w4 = *src，然后 src++

    cmp w4, #'a'
    b.lo store_char                          // 小于 'a'，不是小写字母

    cmp w4, #'z'
    b.hi store_char                          // 大于 'z'，不是小写字母

    sub w4, w4, #32                          // 小写转大写

store_char:
    strb w4, [x2], #1                        // *dst = w4，然后 dst++
    subs x3, x3, #1                          // 剩余字节数--
    b.ne copy_loop                           // 未处理完就继续

    // write(1, dst, src_len)
    mov x0, #1                               // stdout
    adrp x1, dst                             // x1 = dst 所在页
    add x1, x1, :lo12:dst                    // x1 = dst 地址
    mov x2, #src_len                         // x2 = 输出长度
    mov x8, #64                              // Linux AArch64 write
    svc #0

    // exit(0)
    mov x0, #0
    mov x8, #93                              // Linux AArch64 exit
    svc #0

编译运行：

as string-aarch64.s -o string-aarch64.o
ld string-aarch64.o -o string-aarch64
./string-aarch64

预期输出：

HELLO, ARM64 AND X86-64!

3.3 macOS arm64

文件名： string-macos-arm64.s

.section __TEXT,__cstring
src:
    .ascii "hello, arm64 and x86-64!\n"
src_len = . - src

.data
.balign 8
dst:
    .space src_len

.text
.globl _main
.p2align 2
_main:
    // _main 会调用 _write，所以先保存 x29/x30。
    stp x29, x30, [sp, #-16]!
    mov x29, sp

    adrp x1, src@PAGE
    add x1, x1, src@PAGEOFF                  // x1 = src 地址

    adrp x2, dst@PAGE
    add x2, x2, dst@PAGEOFF                  // x2 = dst 地址

    mov x3, #src_len                         // x3 = 要处理的字节数

copy_loop:
    ldrb w4, [x1], #1                        // w4 = *src，然后 src++

    cmp w4, #'a'
    b.lo store_char

    cmp w4, #'z'
    b.hi store_char

    sub w4, w4, #32                          // 小写转大写

store_char:
    strb w4, [x2], #1                        // *dst = w4，然后 dst++
    subs x3, x3, #1
    b.ne copy_loop

    // write(1, dst, src_len)
    mov x0, #1                               // stdout
    adrp x1, dst@PAGE
    add x1, x1, dst@PAGEOFF                  // x1 = dst 地址
    mov x2, #src_len                         // x2 = 输出长度
    bl _write

    mov x0, #0                               // main 返回 0
    ldp x29, x30, [sp], #16
    ret

编译运行：

clang string-macos-arm64.s -o string-macos-arm64
./string-macos-arm64

预期输出：

HELLO, ARM64 AND X86-64!

4. 计算 C 字符串长度

目标逻辑：

len = 0;
while (s[len] != '\0') {
    len++;
}

4.1 x86-64

lea msg(%rip), %rsi     # rsi = 字符串地址
xor %rax, %rax          # rax = len = 0

strlen_loop:
    movzbq (%rsi, %rax), %rbx
    test %bl, %bl       # 当前字节是否为 0？
    jz strlen_done

    inc %rax            # len++
    jmp strlen_loop

strlen_done:

循环结束后， %rax 就是长度。

4.2 AArch64/macOS arm64

// 假设 x1 = 字符串地址。
mov x0, #0              // x0 = len = 0

strlen_loop:
    ldrb w2, [x1, x0]   // w2 = s[len]
    cbz w2, strlen_done // 如果是 0，结束

    add x0, x0, #1      // len++
    b strlen_loop

strlen_done:

循环结束后， x0 就是长度。

5. 查找某个字符

目标逻辑：

while (*p != '\0') {
    if (*p == 'x') found = 1;
    p++;
}

x86-64：

lea msg(%rip), %rsi
xor %rax, %rax          # rax = found = 0

find_loop:
    movzbq (%rsi), %rbx
    test %bl, %bl
    jz find_done

    cmp $'x', %bl
    je found

    inc %rsi
    jmp find_loop

found:
    mov $1, %rax

find_done:

AArch64/macOS arm64：

// 假设 x1 = 字符串地址。
mov x0, #0              // x0 = found = 0

find_loop:
    ldrb w2, [x1], #1
    cbz w2, find_done

    cmp w2, #'x'
    b.eq found

    b find_loop

found:
    mov x0, #1

find_done:

这里 found 分支没有继续扫描后面的字符，因为已经找到目标了。

6. 固定长度字符串和 C 字符串的区别

下面两个字符串看起来都像 "abc" ：

a:
    .ascii "abc"

b:
    .asciz "abc"

但这些值占用的字节不同：

a: 61 62 63
b: 61 62 63 00

如果用 C 字符串方式遍历 .ascii "abc" ，循环会继续读后面的内存，直到碰巧遇到 0 。这是 bug。

如果用 write 输出 .asciz "abc" 并把长度写成 4 ，那个 0 字节也会被传给 write 。终端通常看不见这个字节，但确实被输出了。

7. 字符串复制

固定长度复制：

for (i = 0; i < len; i++) {
    dst[i] = src[i];
}

x86-64：

mov $len, %rcx
lea src(%rip), %rsi
lea dst(%rip), %rdi

copy_loop:
    movb (%rsi), %al
    movb %al, (%rdi)
    inc %rsi
    inc %rdi
    dec %rcx
    jnz copy_loop

AArch64/macOS arm64：

// x1 = src, x2 = dst, x3 = len
copy_loop:
    ldrb w4, [x1], #1
    strb w4, [x2], #1
    subs x3, x3, #1
    b.ne copy_loop

复制 C 字符串时，要把结尾的 0 也复制过去：

读取一个字节
写入一个字节
如果这个字节是 0，结束
否则继续

8. 常见字符处理技巧

8.1 小写转大写

ASCII 小写字母和大写字母相差 32 ：

'a' - 'A' = 32

所以：

sub $32, %al        # x86-64
sub w0, w0, #32     // AArch64

但必须先确认字符在 'a'..'z' 之间，否则会把标点符号也改坏。

8.2 大写转小写

add $32, %al        # x86-64
add w0, w0, #32     // AArch64

同样要先确认字符在 'A'..'Z' 之间。

8.3 判断 ASCII 数字

cmp $'0', %al
jb not_digit
cmp $'9', %al
ja not_digit
cmp w0, #'0'
b.lo not_digit
cmp w0, #'9'
b.hi not_digit

9. 常见错误

9.1 忘记 .ascii 不加 \0

msg:
    .ascii "hello"

如果把该字节串当作 C 字符串扫描，可能越界。需要 C 字符串时写：

msg:
    .asciz "hello"

9.2 用 write 时忘记长度

write 不会自动查找 \0 ：

write(fd, buf, len)

第三个参数必须是准确字节数。

9.3 读取字节后没有零扩展

x86-64 读取一个字节到 64 位寄存器时，常用：

movzbq (%rsi), %rax

不要让寄存器高位保留旧值后再参与比较或运算。

AArch64 的 ldrb w0, [x1] 会自动零扩展到 w0 ，写 w0 也会清掉 x0 高 32 位。

9.4 在 macOS 里照搬 Linux 的 :lo12:

Linux AArch64：

adrp x1, msg
add x1, x1, :lo12:msg

macOS arm64：

adrp x1, msg@PAGE
add x1, x1, msg@PAGEOFF

Mach-O 和 ELF 的重定位写法不同。

9.5 调用 _write 前忘记保存 x30

macOS arm64 的 _main 如果调用 _write ：

bl _write

bl 会覆盖返回地址寄存器 x30 。所以非叶子函数要保存并恢复 x29/x30 ：

stp x29, x30, [sp, #-16]!
mov x29, sp

bl _write

ldp x29, x30, [sp], #16
ret
