基础语法

x86-64 Linux、AArch64 Linux、macOS arm64 三种环境对比汇编基础语法。

AArch64/ARM64 是指令集架构，不等于某一个操作系统的可执行文件格式和系统调用约定。Linux AArch64 示例使用 ELF、GNU 工具链和 Linux 系统调用；macOS arm64 示例使用 Mach-O、Apple Clang 和 macOS 的 C 运行时 /libSystem。两边寄存器和基础指令很像，但入口符号、段名、链接方式、系统调用方式都不一样。

两种架构在写法上的核心差异：

  • x86-64 常见两种语法：Intel 和 AT&T。为了能直接用 GNU 工具链复现，示例默认使用 AT&T 语法。
  • ARM64/AArch64 的 GNU 汇编语法更接近官方文档写法，操作数通常是 目标寄存器在前，源操作数在后。
  • x86-64 的很多指令会隐式影响标志位；AArch64 则通常把 “是否更新标志位” 写进指令名，例如 adds 、 subs 、 cmp 。
  • Linux x86-64 与 Linux AArch64 的系统调用号、参数寄存器、调用指令完全不同，但 “把参数放进约定寄存器，然后触发内核” 这个思路是一样的。
  • macOS arm64 建议先通过 _main 调用 C 库函数，例如 _puts ，不要一开始就写裸系统调用；macOS 的底层 syscall 接口不适合作为入门示例直接硬编码。

1. 先准备复现环境

如果在 x86-64 Linux 上，可以直接汇编并运行 x86-64 示例：

as --64 hello-x86-64.s -o hello-x86-64.o
ld hello-x86-64.o -o hello-x86-64
./hello-x86-64
echo $?

如果在 ARM64 Linux 上，可以直接汇编并运行 AArch64 示例：

as hello-aarch64.s -o hello-aarch64.o
ld hello-aarch64.o -o hello-aarch64
./hello-aarch64
echo $?

如果在 x86-64 Linux 上想交叉编译 AArch64 示例，通常需要安装交叉工具链和 QEMU：

sudo apt install binutils-aarch64-linux-gnu gcc-aarch64-linux-gnu qemu-user
aarch64-linux-gnu-as hello-aarch64.s -o hello-aarch64.o
aarch64-linux-gnu-ld hello-aarch64.o -o hello-aarch64
qemu-aarch64 ./hello-aarch64
echo $?

如果在 Apple Silicon Mac 上学习，先安装 Xcode Command Line Tools：

xcode-select --install

然后直接用 clang 汇编、链接、运行 macOS arm64 示例：

clang hello-macos-arm64.s -o hello-macos-arm64
./hello-macos-arm64

clang return5-macos-arm64.s -o return5-macos-arm64
./return5-macos-arm64
echo $?

如果需要在 macOS 上复现 Linux x86-64 或 Linux AArch64 示例，建议使用 Docker、虚拟机、远程 Linux 或 QEMU，因为 macOS 的 Mach-O 文件格式和系统调用 ABI 与 Linux 不同，Linux 示例不能原样运行。

2. 汇编程序的基本结构

  1. 段（section）：把代码、只读数据、可写数据放到不同区域。
  2. 符号（symbol）：给地址起名字，例如入口点 _start 、字符串 msg 。
  3. 指令（instruction）：真正让 CPU 执行的操作，例如移动数据、加法、跳转、系统调用。

常见段如下：

作用Linux ELF 常见段名macOS Mach-O 常见段名常见内容
代码段.text.text 或 __TEXT,__text指令、函数、入口点
只读数据段.rodata__TEXT,__const 或 __TEXT,__cstring字符串常量、查表数据
已初始化的可写数据段.data__DATA,__data全局变量
未初始化的可写数据段.bss__DATA,__bss缓冲区、数组

GAS 中的伪指令以 . 开头，例如：

.section .text       # 切换到代码段
.global _start       # 把 _start 导出给链接器
_start:              # 定义标签，表示当前地址

伪指令不是 CPU 指令，这些值是给汇编器和链接器看的。CPU 最终执行的是 mov 、 add 、 syscall 、 svc 这类机器指令。

macOS 的 Mach-O 段名看起来更长，例如：

.section __TEXT,__const     // macOS 只读常量区
.text                       // macOS 代码区的简写
.globl _main                // 导出 _main 给 C 运行时

Apple 平台上 C 符号通常带前导下划线：C 里的 main 在汇编里写成 _main ，C 里的 write 在汇编里写成 _write 。

3. 第一份 x86-64 程序：打印 Hello

文件名： hello-x86-64.s

.section .rodata
msg:
    .ascii "Hello from x86-64\n"   # 原样写入字符串，不自动追加 \0
msg_len = . - msg                  # 当前地址 . 减去 msg 地址，得到字符串长度

.section .text
.global _start
_start:
    # Linux x86-64 系统调用约定：
    # rax = 系统调用号
    # rdi = 第 1 个参数
    # rsi = 第 2 个参数
    # rdx = 第 3 个参数
    #
    # write(fd, buf, count)
    # 系统调用号：write = 1
    # fd = 1 表示标准输出 stdout
    mov $1, %rax                   # rax = 1，选择 write 系统调用
    mov $1, %rdi                   # rdi = 1，第 1 参数 fd
    lea msg(%rip), %rsi            # rsi = msg 的地址，第 2 参数 buf
    mov $msg_len, %rdx             # rdx = 字符串长度，第 3 参数 count
    syscall                        # 进入内核，执行 write

    # exit(status)
    # 系统调用号：exit = 60
    mov $60, %rax                  # rax = 60，选择 exit 系统调用
    xor %rdi, %rdi                 # rdi = 0，退出码 status = 0
    syscall                        # 进入内核，结束进程

编译运行：

as --64 hello-x86-64.s -o hello-x86-64.o
ld hello-x86-64.o -o hello-x86-64
./hello-x86-64

预期输出：

Hello from x86-64

这段代码里最容易看错的是 lea msg(%rip), %rsi 。该指令不是读取 msg 位置上的字符串内容，而是把 msg 的地址算出来放进 %rsi 。系统调用 write 需要的是缓冲区地址，所以这里用 lea 。

4. 第一份 Linux AArch64 程序：打印 Hello

文件名： hello-aarch64.s

.section .rodata
msg:
    .ascii "Hello from AArch64\n"  // 原样写入字符串，不自动追加 \0
msg_len = . - msg                  // 当前地址 . 减去 msg 地址，得到字符串长度

.section .text
.global _start
_start:
    // Linux AArch64 系统调用约定：
    // x8 = 系统调用号
    // x0 = 第 1 个参数
    // x1 = 第 2 个参数
    // x2 = 第 3 个参数
    //
    // write(fd, buf, count)
    // 系统调用号：write = 64
    // fd = 1 表示标准输出 stdout
    mov x8, #64                    // x8 = 64，选择 write 系统调用
    mov x0, #1                     // x0 = 1，第 1 参数 fd
    adr x1, msg                    // x1 = msg 的地址，第 2 参数 buf
    mov x2, #msg_len               // x2 = 字符串长度，第 3 参数 count
    svc #0                         // 进入内核，执行 write

    // exit(status)
    // 系统调用号：exit = 93
    mov x8, #93                    // x8 = 93，选择 exit 系统调用
    mov x0, #0                     // x0 = 0，退出码 status = 0
    svc #0                         // 进入内核，结束进程

编译运行：

as hello-aarch64.s -o hello-aarch64.o
ld hello-aarch64.o -o hello-aarch64
./hello-aarch64

预期输出：

Hello from AArch64

Linux AArch64 示例中的 adr x1, msg 与 x86-64 示例中的 lea msg(%rip), %rsi 作用类似：把标签 msg 对应的地址放入寄存器，而不是取出字符串内容。

5. 第一份 macOS arm64 程序：打印 Hello

文件名： hello-macos-arm64.s

.section __TEXT,__const
msg:
    .ascii "Hello from macOS arm64\n"  // 原样写入字符串，不自动追加 \0
msg_len = . - msg                      // 当前地址 . 减去 msg 地址，得到字符串长度

.text
.globl _main
.p2align 2
_main:
    // macOS arm64 使用 Mach-O 格式。
    // C 可见的符号名前面通常要加下划线，所以入口是 _main，函数是 _write。
    //
    // 这里不直接写 macOS 裸系统调用，而是调用 libSystem 提供的 write()：
    // ssize_t write(int fd, const void *buf, size_t count)
    //
    // AArch64 C 调用约定：
    // x0 = 第 1 个参数
    // x1 = 第 2 个参数
    // x2 = 第 3 个参数
    // x0 = 返回值

    stp x29, x30, [sp, #-16]!          // 建立 16 字节栈帧，同时保存帧指针 x29 和返回地址 x30
    mov x29, sp                        // x29 = 当前栈顶，作为本函数的帧指针

    mov x0, #1                         // x0 = 1，第 1 参数 fd，标准输出 stdout
    adrp x1, msg@PAGE                  // x1 = msg 所在 4KB 页的页地址
    add x1, x1, msg@PAGEOFF            // x1 = x1 + msg 在页内的偏移，得到 msg 的完整地址
    mov x2, #msg_len                   // x2 = 字符串长度，第 3 参数 count
    bl _write                          // 调用 macOS libSystem 的 write()

    mov w0, #0                         // main 返回 0，表示程序成功
    ldp x29, x30, [sp], #16            // 恢复 x29、x30，并释放 16 字节栈帧
    ret                                // 返回给 C 运行时，由运行时负责退出进程

编译运行：

clang hello-macos-arm64.s -o hello-macos-arm64
./hello-macos-arm64

预期输出：

Hello from macOS arm64

这一版看起来比 Linux AArch64 多了几行，原因主要有三个：

  1. macOS 上默认从 C 运行时调用 _main ，不是直接从 _start 裸入口开始。
  2. _main 调用了 _write ，所以这是非叶子函数，必须在调用前保存返回地址寄存器 x30 ，否则最后 ret 会跳错位置。
  3. Mach-O 下取全局地址常用 adrp + add 配合 @PAGE / @PAGEOFF 重定位，而不是直接照搬 Linux 示例里的 adr x1, msg 。

如果只是写一个不调用其他函数的极小函数，macOS arm64 也可以很短；但一旦 bl _write 、 bl _printf 、 bl _puts ，就要认真保存 x30 。

6. 语法对照：指令、寄存器、立即数

6.1 操作数顺序

这是初学者最容易混淆的一点。

架构这里使用语法常见格式含义
x86-64GAS AT&T指令 源, 目标右边被改写
AArch64GAS/Arm 风格指令 目标, 源1, 源2左边被改写

例如把 1 放入寄存器：

# x86-64 AT&T
mov $1, %rax       # rax = 1

// AArch64
mov x0, #1         // x0 = 1

再看加法：

# x86-64 AT&T
mov $2, %rax       # rax = 2
add $3, %rax       # rax = rax + 3，也就是 5

// AArch64
mov x0, #2         // x0 = 2
add x0, x0, #3     // x0 = x0 + 3，也就是 5

x86-64 的 add $3, %rax 只有两个显式操作数，目标寄存器 %rax 同时也是输入。AArch64 的 add x0, x0, #3 有三个操作数，左侧 x0 是目标，后面的 x0 和 #3 是输入。

6.2 寄存器写法

用途x86-64AArch64
通用 64 位寄存器%rax 、 %rbx 、 %rdi 、 %rsix0 - x30
通用 32 位寄存器%eax 、 %ebx 、 %edi 、 %esiw0 - w30
栈指针%rspsp
指令指针%rippc ，通常不能像普通寄存器一样直接使用
零寄存器没有专用零寄存器xzr / wzr ，读出恒为 0，写入会被丢弃

x86-64 中 %rax 、 %eax 、 %ax 、 %al 是同一组物理寄存器的不同宽度视图：

mov $0x1122334455667788, %rax  # 写入 64 位
mov $0xaabbccdd, %eax          # 写入低 32 位，并把高 32 位清零

AArch64 中 x0 是 64 位视图， w0 是同一寄存器的低 32 位视图：

mov x0, #0x1234                // 写入 64 位寄存器 x0
mov w0, #0x56                  // 写入低 32 位，同时高 32 位清零

6.3 立即数写法

立即数就是直接写在指令里的常量。

# x86-64 AT&T：立即数前面加 $
mov $42, %rax                  # rax = 42
mov $0x2a, %rax                # rax = 0x2a，也就是 42

// AArch64：立即数通常前面加 #
mov x0, #42                    // x0 = 42
mov x0, #0x2a                  // x0 = 0x2a，也就是 42

注意：AArch64 不是所有任意大小的立即数都能被一条 mov 编码进去。遇到大常量时，汇编器可能需要使用 movz 、 movk 、字面量池或从内存加载。先记住 “小整数可以直接 mov ” 就够了。

7. 注释、标签和符号

7.1 注释

GAS 在不同目标架构上支持的注释风格略有差异。为了少踩坑：

# x86-64 示例建议用 #
mov $1, %rax       # 行尾注释

// AArch64 示例建议用 //
mov x0, #1         // 行尾注释

块状解释建议写在 Markdown 文档里，汇编文件中只保留必要注释。真实项目里注释应该解释 “为什么这样做”，而不是机械重复 “把 1 放到寄存器”。

7.2 标签

标签本质上是地址的名字。

.global _start
_start:
    mov $60, %rax
    xor %rdi, %rdi
    syscall

这里 _start 是程序入口地址。链接器默认会从 _start 开始执行。标签后面跟冒号，表示 “当前位置的地址叫这个名字”。

标签也可以用来表示数据地址：

.section .rodata
msg:
    .ascii "hello\n"

此时 msg 表示字符串第一个字节的地址。

7.3 全局符号和局部符号

.global 会把符号导出给链接器：

.global _start     # 链接器能看到 _start
_start:

没有 .global 的标签通常只在当前目标文件内部使用，例如循环标签：

loop_begin:
    # ...
    # 跳回 loop_begin

8. 数据定义伪指令

GAS 常用数据定义伪指令如下：

伪指令大小说明
.byte1 字节定义字节
.short2 字节定义 16 位整数
.long4 字节定义 32 位整数
.quad8 字节定义 64 位整数
.ascii按字符串长度写入字符串，不自动追加 \0
.asciz字符串长度 + 1写入字符串，并自动追加 \0
.space nn 字节预留 n 个字节

示例：

.section .data
counter:
    .quad 100                    # 8 字节整数，初始值 100

.section .rodata
name:
    .asciz "codex"               # 字符串末尾自动追加 0 字节

.section .bss
buffer:
    .space 128                   # 预留 128 字节，通常会被加载器清零

.ascii 和 .asciz 的区别很重要：

.ascii "abc"     # 内存中是 61 62 63
.asciz "abc"     # 内存中是 61 62 63 00

Linux 的 write 系统调用不需要 \0 结尾，因为接收明确的长度参数；C 字符串函数通常需要 \0 结尾。

9. 内存访问基础

9.1 x86-64：括号在 AT&T 里写成 (...)

AT&T 语法的内存操作数格式常见如下：

偏移量(基址寄存器, 索引寄存器, 比例)

例如：

.section .data
value:
    .quad 123

.section .text
.global _start
_start:
    lea value(%rip), %rbx         # rbx = value 的地址
    mov (%rbx), %rax              # rax = 内存[rbx]，读取 value 的 8 字节内容
    movq $456, (%rbx)             # 内存[rbx] = 456，明确写入 8 字节

几个常见写法：

mov (%rbx), %rax                  # 读取 rbx 指向的 8 字节
mov 8(%rbx), %rax                 # 读取 rbx + 8 指向的 8 字节
mov (%rbx,%rcx,8), %rax           # 读取 rbx + rcx * 8 指向的 8 字节
mov 16(%rbx,%rcx,8), %rax         # 读取 rbx + rcx * 8 + 16 指向的 8 字节

这里 “读取多少字节” 通常由目标寄存器或指令后缀决定。例如 %rax 是 64 位，所以 mov (%rbx), %rax 读取 8 字节。

9.2 AArch64：内存地址放在 [...] 中

AArch64 常见内存操作数写法：

[基址寄存器]
[基址寄存器, #偏移量]

例如：

.section .data
value:
    .quad 123

.section .text
.global _start
_start:
    adr x1, value                 // x1 = value 的地址
    ldr x0, [x1]                  // x0 = 内存[x1]，读取 value 的 8 字节内容
    mov x2, #456                  // x2 = 456
    str x2, [x1]                  // 内存[x1] = x2，写回 value

几个常见写法：

ldr x0, [x1]                      // 读取 x1 指向的 8 字节
ldr x0, [x1, #8]                  // 读取 x1 + 8 指向的 8 字节
str x0, [x1, #16]                 // 写入 x1 + 16 指向的 8 字节
ldr w0, [x1]                      // 读取 x1 指向的 4 字节到 w0

x86-64 常用一条 mov 同时表达读写内存；AArch64 通常用 ldr 读内存、 str 写内存，语义更直白。

10. 指令宽度与后缀

10.1 x86-64：后缀或寄存器决定宽度

GAS AT&T 语法中，很多指令可以带宽度后缀：

后缀大小示例
b1 字节movb $1, (%rbx)
w2 字节movw $1, (%rbx)
l4 字节movl $1, (%rbx)
q8 字节movq $1, (%rbx)

如果寄存器已经能说明宽度，后缀可以省略：

mov $1, %rax       # 目标是 rax，汇编器知道是 64 位
mov $1, %eax       # 目标是 eax，汇编器知道是 32 位

但写内存时如果没有寄存器参与，建议显式写后缀：

movq $1, (%rbx)    # 明确写入 8 字节
movl $1, (%rbx)    # 明确写入 4 字节

10.2 AArch64：寄存器名决定宽度

AArch64 通常通过 x / w 寄存器名表达宽度：

mov x0, #1         // 64 位
mov w0, #1         // 32 位
ldr x0, [x1]       // 读取 8 字节
ldr w0, [x1]       // 读取 4 字节

读取更小宽度时，AArch64 有专门指令：

ldrb w0, [x1]      // 读取 1 字节，零扩展到 w0
ldrh w0, [x1]      // 读取 2 字节，零扩展到 w0
strb w0, [x1]      // 写入 w0 的低 1 字节
strh w0, [x1]      // 写入 w0 的低 2 字节

11. 分支和条件判断入门

11.1 x86-64：比较后跳转

x86-64 常见套路是 cmp 设置标志位，然后 jcc 根据标志位跳转。

mov $5, %rax                     # rax = 5
cmp $5, %rax                     # 比较 rax 和 5，本质上计算 rax - 5 并设置标志位
je equal                         # 如果相等，跳转到 equal

not_equal:
    mov $1, %rdi                 # 不相等时，退出码 = 1
    jmp done                     # 跳过 equal 分支

equal:
    mov $0, %rdi                 # 相等时，退出码 = 0

done:
    mov $60, %rax                # exit
    syscall

AT&T 语法的 cmp $5, %rax 要读成 “比较 %rax 和 $5 ”。对等于 / 不等于来说顺序不容易出问题；对大于 / 小于来说要格外小心，因为 AT&T 是源在前、目标在后。

11.2 AArch64：比较后跳转

AArch64 常见套路也是 cmp 设置条件标志，然后 b.cond 跳转。

mov x0, #5                       // x0 = 5
cmp x0, #5                       // 比较 x0 和 5，本质上计算 x0 - 5 并设置条件标志
b.eq equal                       // 如果相等，跳转到 equal

not_equal:
    mov x0, #1                   // 不相等时，退出码 = 1
    b done                       // 跳过 equal 分支

equal:
    mov x0, #0                   // 相等时，退出码 = 0

done:
    mov x8, #93                  // exit
    svc #0

常见条件码对照：

含义x86-64AArch64
相等je / jzb.eq
不相等jne / jnzb.ne
有符号大于jgb.gt
有符号大于等于jgeb.ge
有符号小于jlb.lt
有符号小于等于jleb.le
无符号高于jab.hi
无符号高于等于jaeb.hs / b.cs
无符号低于jbb.lo / b.cc
无符号低于等于jbeb.ls

有符号和无符号不是数据本身的属性，而是选择哪一种条件跳转来解释标志位。

12. 函数调用初步

先不深入栈帧，只看 “调用函数” 和 “返回” 的基础写法。

12.1 x86-64

.section .text
.global _start
_start:
    mov $2, %rdi                 # 第 1 个参数 a = 2
    mov $3, %rsi                 # 第 2 个参数 b = 3
    call add2                    # 调用 add2，返回值放在 rax

    mov %rax, %rdi               # exit 的参数 status = rax
    mov $60, %rax                # exit 系统调用号
    syscall

add2:
    mov %rdi, %rax               # rax = a
    add %rsi, %rax               # rax = a + b
    ret                          # 返回调用者

Linux x86-64 的 C 函数调用约定中，前几个整数或指针参数通常放在 %rdi 、 %rsi 、 %rdx 、 %rcx 、 %r8 、 %r9 ，返回值放在 %rax 。注意这和系统调用约定相似但不完全相同，系统调用第 4 个参数用 %r10 。

12.2 Linux AArch64

.section .text
.global _start
_start:
    mov x0, #2                   // 第 1 个参数 a = 2
    mov x1, #3                   // 第 2 个参数 b = 3
    bl add2                      // 调用 add2，返回值放在 x0

    // x0 已经是 exit 的第 1 个参数 status
    mov x8, #93                  // exit 系统调用号
    svc #0

add2:
    add x0, x0, x1               // x0 = a + b
    ret                          // 返回调用者

AArch64 的 C 函数调用约定中，前几个整数或指针参数通常放在 x0 - x7 ，返回值放在 x0 。 bl 会把返回地址保存到 x30 ， ret 默认跳回 x30 指向的位置。

12.3 macOS arm64

.text
.globl _main
.p2align 2
_main:
    stp x29, x30, [sp, #-16]!    // main 里要调用 add2，先保存帧指针和返回地址
    mov x29, sp                  // 建立当前函数的帧指针

    mov x0, #2                   // 第 1 个参数 a = 2
    mov x1, #3                   // 第 2 个参数 b = 3
    bl add2                      // 调用 add2，返回值放在 x0

    ldp x29, x30, [sp], #16      // 恢复 C 运行时传给 main 的返回地址
    ret                          // 返回给 C 运行时，进程退出码就是 w0 的低 8 位

add2:
    add x0, x0, x1               // x0 = a + b
    ret                          // add2 没有再调用别的函数，所以不需要保存 x30

macOS arm64 和 Linux AArch64 的普通函数调用规则都来自 AAPCS64：参数放在 x0 - x7 ，返回值放在 x0 。区别在于 macOS 示例通过 C 运行时进入 _main ，所以 _main 返回时要回到运行时；只要 _main 内部执行了 bl ， x30 就会被新的返回地址覆盖，因此必须先保存。

13. 最小可运行练习：返回 5

下面三个程序都不打印内容，只通过退出码返回 2 + 3 = 5 。运行后用 echo $? 查看。

13.1 x86-64 版本

文件名： return5-x86-64.s

.section .text
.global _start
_start:
    mov $2, %rax                 # rax = 2
    add $3, %rax                 # rax = rax + 3 = 5

    mov %rax, %rdi               # exit(status) 的 status = 5
    mov $60, %rax                # Linux x86-64 exit 系统调用号 = 60
    syscall                      # 结束进程

运行：

as --64 return5-x86-64.s -o return5-x86-64.o
ld return5-x86-64.o -o return5-x86-64
./return5-x86-64
echo $?

预期输出：

5

13.2 Linux AArch64 版本

文件名： return5-aarch64.s

.section .text
.global _start
_start:
    mov x0, #2                   // x0 = 2
    add x0, x0, #3               // x0 = x0 + 3 = 5

    // exit(status) 的第 1 个参数正好使用 x0
    mov x8, #93                  // Linux AArch64 exit 系统调用号 = 93
    svc #0                       // 结束进程

运行：

as return5-aarch64.s -o return5-aarch64.o
ld return5-aarch64.o -o return5-aarch64
./return5-aarch64
echo $?

预期输出：

5

13.3 macOS arm64 版本

文件名： return5-macos-arm64.s

.text
.globl _main
.p2align 2
_main:
    mov w0, #2                   // w0 = 2
    add w0, w0, #3               // w0 = w0 + 3 = 5
    ret                          // 从 main 返回，C 运行时把返回值作为进程退出码

运行：

clang return5-macos-arm64.s -o return5-macos-arm64
./return5-macos-arm64
echo $?

预期输出：

5

这个版本没有调用别的函数，所以不需要保存 x30 。C 运行时调用 _main 时已经把返回地址放进了 x30 ；代码没有执行 bl 覆盖 x30 ，最后 ret 能直接回到运行时。

14. 常见坑

14.1 把 “地址” 和 “地址里的值” 混在一起

# x86-64
lea msg(%rip), %rsi              # rsi = msg 的地址
mov msg(%rip), %rsi              # rsi = msg 地址处的前 8 字节内容
// AArch64
adr x1, msg                      // x1 = msg 的地址
ldr x1, [x1]                     // x1 = x1 指向内存里的 8 字节内容

打印字符串时， write 要的是字符串地址，所以应该传地址，不是传字符串前 8 字节内容。

14.2 x86-64 的 AT&T 顺序和 Intel 顺序相反

很多资料使用 Intel 语法：

mov rax, 1       ; Intel：目标在前，源在后

这里使用 GAS AT&T 语法：

mov $1, %rax     # AT&T：源在前，目标在后

看到 x86-64 示例时，先确认使用的是 Intel 还是 AT&T。两者混着看，很容易把赋值方向看反。

14.3 系统调用号不是跨架构通用的

同样是 Linux：

系统调用x86-64AArch64
write164
exit6093

所以不要把 mov $60, %rax 机械翻译成 mov x8, #60 。AArch64 的 exit 是 93 。

14.4 _start 不是 main

这里的 Linux 示例直接从 _start 进入，没有经过 C 运行时初始化，也不能直接 ret 返回。

在 _start 里结束程序应该调用 exit 系统调用：

# x86-64
mov $60, %rax
xor %rdi, %rdi
syscall
// AArch64
mov x8, #93
mov x0, #0
svc #0

如果目标是被 C 调用的函数，才会按 C ABI 写函数标签、保存必要寄存器，并用 ret 返回。

14.5 macOS arm64 不能直接照搬 Linux AArch64

下面这些差异都足够让代码无法运行：

项目Linux AArch64macOS arm64
文件格式ELFMach-O
常见入口_start_main
C 符号名main 、 write_main 、 _write
只读数据段.section .rodata.section __TEXT,__const
退出方式x8=93 后 svc #0从 _main ret ，让 C 运行时退出
常见链接命令as + ldclang

所以 Linux AArch64 里的这段：

mov x8, #93
svc #0

不要直接放到 macOS 入门示例里。更推荐在 macOS 上从 _main 开始，用 clang 链接，并优先调用 _write 、 _puts 、 _printf 这类 C 库函数。
