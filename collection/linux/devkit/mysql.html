MySQL 安装

ZIP2026/6/24...大约 4 分钟

提示

这篇默认以 Debian 上常见的 MariaDB / default-mysql-server 为主线，同时补充 Oracle MySQL 的差异。真正上线前，先确认项目到底要的是 “兼容 MySQL 协议”，还是 “必须 Oracle MySQL 8”。

一、适用场景

这篇文档适合这些场景：

  • Debian 系服务器上的 MySQL / MariaDB 安装和运维
  • 单机应用、本机数据库、内网数据库
  • 需要建库、建用户、备份、恢复、日志排查的生产环境

二、机器初始化

先把系统更新到最新状态：

sudo apt update
sudo apt full-upgrade -y
sudo apt autoremove -y
sudo apt install -y \
  curl wget vim tmux htop lsof jq rsync \
  ca-certificates gnupg ufw

如果数据库只给本机或内网使用，先不要急着开放公网端口。

三、环境安装

在 Debian 上，最省事的主线安装方式通常是：

sudo apt install -y default-mysql-server default-mysql-client

这条线路大概率装下来的是 MariaDB 。安装完成后先确认版本：

mysql --version

如果项目明确要求 Oracle MySQL 8，不要和 MariaDB 混装。那种场景应该改走官方 APT 仓库，再安装 mysql-server ，后面的建库、建用户、备份思路基本一致，但服务名和配置文件路径会有所不同。

四、目录规划

MySQL 这类数据库服务，一般不用自己造目录结构，但你要知道几个关键路径：

/etc/mysql/
/var/lib/mysql/
/var/log/mysql/

MariaDB 常见配置文件路径：

  • /etc/mysql/mariadb.conf.d/50-server.cnf

Oracle MySQL 常见配置文件路径：

  • /etc/mysql/mysql.conf.d/mysqld.cnf

五、部署流程

安装完成后先把服务拉起来：

sudo systemctl enable --now mariadb
sudo systemctl status mariadb

第一次安装完建议立刻跑安全初始化：

sudo mariadb-secure-installation

有些环境里可能是这个命令：

sudo mysql_secure_installation

先登录数据库：

sudo mysql

初始化一个业务库和业务账号：

CREATE DATABASE appdb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'appuser'@'127.0.0.1' IDENTIFIED BY 'change-this-password';
GRANT ALL PRIVILEGES ON appdb.* TO 'appuser'@'127.0.0.1';
FLUSH PRIVILEGES;

如果要导入已有 SQL 文件：

mysql -u appuser -p appdb < appdb.sql

查看当前库和账号：

SHOW DATABASES;
SELECT user, host FROM mysql.user;

六、服务守护与开机自启

数据库进程一般直接由系统包自带的 systemd 服务管理：

sudo systemctl enable mariadb
sudo systemctl start mariadb
sudo systemctl status mariadb

重启和重载：

sudo systemctl restart mariadb
sudo systemctl reload mariadb

如果你走的是 Oracle MySQL 路线，服务名通常是 mysql ：

sudo systemctl status mysql

七、网络访问与对外暴露

大多数业务数据库不应该直接暴露到公网。先看它到底监听在哪：

sudo ss -lntp | grep 3306

如果只是本机应用使用，优先保持 127.0.0.1 或内网地址即可。

如果确实要改监听地址，MariaDB 常见配置项在：

/etc/mysql/mariadb.conf.d/50-server.cnf

常见配置项：

[mysqld]
bind-address = 127.0.0.1
port = 3306

改完以后重启：

sudo systemctl restart mariadb

如果是内网机器互联，再按需放行来源网段，而不是直接全放：

sudo ufw allow from 10.0.0.0/24 to any port 3306 proto tcp

八、日志与监控

先看服务状态：

sudo systemctl status mariadb
journalctl -u mariadb -f
mysqladmin ping

数据库里常用的排查语句：

SHOW VARIABLES LIKE 'port';
SHOW VARIABLES LIKE 'bind_address';
SHOW PROCESSLIST;
SHOW DATABASES;

如果要观察连接数和并发：

SHOW STATUS LIKE 'Threads_connected';
SHOW STATUS LIKE 'Max_used_connections';

九、备份与回滚

逻辑备份命令：

mysqldump --single-transaction --routines --triggers appdb > appdb.sql

压缩：

mysqldump --single-transaction --routines --triggers appdb | gzip > appdb.sql.gz

恢复数据：

gunzip -c appdb.sql.gz | mysql -u appuser -p appdb

导回未压缩 SQL：

mysql -u appuser -p appdb < appdb.sql

数据库回滚很少像代码那样 “一条软链切回去”，所以真正的重点是：

  • 备份先于上线
  • 变更前先导出
  • 高风险 DDL 先在测试库验证

十、安全加固

  • 不要让应用直接使用 root
  • 新项目默认使用 utf8mb4
  • 不要把 3306 直接暴露到公网
  • 业务账号优先限制到 127.0.0.1 或内网 IP

常用防火墙策略：

sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

如果数据库只本机使用，通常不需要额外开放 3306 。

十一、常见故障排查

1. Can't connect to MySQL server

先看服务是否启动、端口是否监听：

sudo systemctl status mariadb
sudo ss -lntp | grep 3306
journalctl -u mariadb -n 100

2. 账号能登录但业务连不上

大多数时候是 user@host 不匹配：

SELECT user, host FROM mysql.user;

如果你把用户建成 'appuser'@'127.0.0.1' ，那应用也应该用 TCP 连 127.0.0.1 ，而不是随手换成其他主机名。

3. Access denied

优先检查密码、权限和登录来源：

SHOW GRANTS FOR 'appuser'@'127.0.0.1';

4. 连接数不够

先看当前使用情况：

SHOW STATUS LIKE 'Threads_connected';
SHOW VARIABLES LIKE 'max_connections';

5. 磁盘满了

数据库对磁盘空间非常敏感，先看空间再做别的：

df -h
du -sh /var/lib/mysql

6. MariaDB 和 MySQL 兼容性问题

如果项目明确依赖 MySQL 8 的函数、驱动、认证方式或运维规范，就不要继续在 MariaDB 上硬顶，直接切回 Oracle MySQL 正线。

十二、上线检查清单

  • 已确认当前路线是 MariaDB 还是 Oracle MySQL
  • systemctl status mariadb 或 systemctl status mysql 正常
  • 已跑安全初始化脚本
  • 已创建业务库和独立业务账号
  • 已确认监听地址和端口
  • 已验证备份和恢复命令
  • 3306 没有被错误暴露到公网
